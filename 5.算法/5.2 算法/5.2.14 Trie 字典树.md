# 5.2.14 Trie 字典树

> Trie 把字符串拆成一条从根节点出发的字符路径。路径存在表示某个前缀存在，节点上的 `isEnd` 表示这个前缀是否正好是一个完整单词。

---

## Trie 解决什么问题

普通哈希表适合判断“完整字符串是否出现过”，但不擅长反复处理前缀关系。例如：

- 是否存在以 `app` 开头的单词
- 找到某个单词的最短词根
- 对输入前缀返回搜索建议
- 在网格中同时搜索一批单词

Trie 的优势是把公共前缀只存一份。比如 `cat` 和 `car` 共享路径 `c -> a`，只在最后一个字符处分叉。

和 [[5.算法/5.2 算法/5.2.8 哈希表与计数|哈希表与计数]] 相比：

| 结构 | 更适合的问题 | 核心能力 |
|------|--------------|----------|
| `unordered_set<string>` | 完整字符串存在性 | 平均 `O(1)` 查整个 key |
| 排序数组 | 批量前缀查询、搜索建议 | 二分定位前缀区间 |
| Trie | 大量前缀匹配、词根搜索、多词搜索 | 沿字符路径逐层剪枝 |

> [!tip]
> 看到“前缀”“词根”“字典”“自动补全”“一批单词同时搜索”，就应该想到 Trie。

---

## Trie 结构总览

![[图片/5.算法/5.2 算法/5_2_2_14_1.svg]]

Trie 节点通常保存两类信息：

1. `child`：从当前节点出发，某个字符能走到哪个子节点。
2. `isEnd`：当前路径是否组成一个完整单词。

默认题目字符范围是小写英文字母 `a-z` 时，可以用固定数组：

```cpp
#include <array>

struct TrieNode {
    std::array<TrieNode*, 26> child{};
    bool isEnd = false;
};
```

如果题目字符集不是固定的 `a-z`，例如包含大写、路径字符、任意 ASCII 或 Unicode，应该把 `array<TrieNode*, 26>` 换成 `std::unordered_map<char, TrieNode*>`。固定数组速度快、写法短；哈希表更通用，但常数更大。

> [!warning]
> LeetCode 手写模板常省略释放节点；工程代码要补析构、对象池，或用智能指针管理内存。

---

## 基础操作

Trie 的基础接口通常只有三个：

- `insert(word)`：插入一个单词。
- `search(word)`：判断完整单词是否存在。
- `startsWith(prefix)`：判断某个前缀是否存在。

```cpp
#include <array>
#include <string>

struct TrieNode {
    std::array<TrieNode*, 26> child{};
    bool isEnd = false;
};

class Trie {
public:
    Trie() : root(new TrieNode()) {}

    void insert(const std::string& word) {
        TrieNode* node = root;
        for (char ch : word) {
            int index = ch - 'a';
            if (node->child[index] == nullptr) {
                node->child[index] = new TrieNode();
            }
            node = node->child[index];
        }
        node->isEnd = true;
    }

    bool search(const std::string& word) const {
        TrieNode* node = findNode(word);
        return node != nullptr && node->isEnd;
    }

    bool startsWith(const std::string& prefix) const {
        return findNode(prefix) != nullptr;
    }

private:
    TrieNode* root = nullptr;

    TrieNode* findNode(const std::string& text) const {
        TrieNode* node = root;
        for (char ch : text) {
            int index = ch - 'a';
            if (index < 0 || index >= 26 || node->child[index] == nullptr) {
                return nullptr;
            }
            node = node->child[index];
        }
        return node;
    }
};
```

**关键点**：

- 插入时，路径不存在就创建节点。
- 完整匹配必须看 `isEnd`，不能只看路径存在。
- 前缀匹配只要求路径存在，不要求最后节点是单词结尾。
- 空字符串如果被插入，可以让 `root->isEnd = true`；大多数题不会使用空单词。

## 前缀匹配

`startsWith` 的本质是沿着前缀字符一路向下走。只要中途不断，说明这个前缀存在。

```cpp
bool startsWith(const std::string& prefix) const {
    return findNode(prefix) != nullptr;
}
```

如果题目要求统计某个前缀出现过多少次，可以给节点增加 `passCount`：

```cpp
struct CountTrieNode {
    std::array<CountTrieNode*, 26> child{};
    bool isEnd = false;
    int passCount = 0;
};
```

插入单词时，每走到一个节点就 `++passCount`。查询前缀时，先找到前缀最后一个节点，再返回它的 `passCount`。

| 需求 | 推荐结构 |
|------|----------|
| 完整单词查找 | 哈希表或 Trie |
| 前缀是否存在 | Trie |
| 前缀数量统计 | Trie + `passCount` |
| 静态词典搜索建议 | 排序数组 + 二分也可行 |
| 动态插入并查询前缀 | Trie 更自然 |

---

## 单词搜索

单个单词的网格搜索属于 DFS/回溯，基础写法可以回看 [[5.算法/5.2 算法/5.2.18 回溯算法|回溯算法]] 中的“单词搜索”。Trie 更有价值的场景是：**在同一张网格里搜索一批单词**。

如果对每个单词都单独 DFS，很多前缀会被反复搜索。Trie 可以把所有单词放进一棵树，DFS 时只要当前路径不在 Trie 中，就立刻剪枝。

常见做法：

1. 把所有单词插入 Trie。
2. 从每个格子出发做 DFS。
3. 当前字符在 Trie 子节点中不存在时，直接返回。
4. 走到 `isEnd` 节点时，记录一个答案。
5. 标记当前格子已访问，递归返回后恢复现场。

```cpp
#include <array>
#include <string>
#include <vector>

struct WordTrieNode {
    std::array<WordTrieNode*, 26> child{};
    int wordIndex = -1;
};

void dfsBoard(std::vector<std::vector<char>>& board,
              int row,
              int col,
              WordTrieNode* node,
              const std::vector<std::string>& words,
              std::vector<std::string>& result) {
    int rows = static_cast<int>(board.size());
    int cols = static_cast<int>(board[0].size());
    if (row < 0 || row >= rows || col < 0 || col >= cols) return;

    char ch = board[row][col];
    if (ch == '#') return;

    int index = ch - 'a';
    if (index < 0 || index >= 26 || node->child[index] == nullptr) return;

    node = node->child[index];
    if (node->wordIndex != -1) {
        result.push_back(words[node->wordIndex]);
        node->wordIndex = -1;
    }

    board[row][col] = '#';
    dfsBoard(board, row + 1, col, node, words, result);
    dfsBoard(board, row - 1, col, node, words, result);
    dfsBoard(board, row, col + 1, node, words, result);
    dfsBoard(board, row, col - 1, node, words, result);
    board[row][col] = ch;
}
```

这里用 `wordIndex` 代替 `isEnd`，是为了找到单词后能直接拿到原字符串。找到后把 `wordIndex` 改成 `-1`，可以避免同一个单词重复加入答案。

> [!warning]
> 网格 DFS 必须恢复现场。把格子改成 `'#'` 后，递归结束要改回原字符，否则其他路径会被错误影响。

## 替换单词

替换单词的典型题意是：给一组词根和一个句子，把句子中的单词替换成字典里最短的词根。

Trie 的做法：

1. 把所有词根插入 Trie。
2. 扫描句子里的每个单词。
3. 从单词开头沿 Trie 向下走。
4. 第一次遇到 `isEnd == true`，说明找到最短词根，立即停止。
5. 如果中途走不下去，就保留原单词。

```cpp
std::string findShortestRoot(TrieNode* root, const std::string& word) {
    TrieNode* node = root;
    std::string prefix;

    for (char ch : word) {
        int index = ch - 'a';
        if (index < 0 || index >= 26 || node->child[index] == nullptr) {
            return word;
        }

        prefix.push_back(ch);
        node = node->child[index];
        if (node->isEnd) {
            return prefix;
        }
    }

    return word;
}
```

**为什么遇到 `isEnd` 就停**：

- 题目要求最短词根。
- 从左到右走 Trie，第一次遇到完整词根时长度最短。
- 继续往下找只会得到更长的词根，不符合优先级。

## 搜索建议系统

搜索建议系统通常要求：输入 `searchWord` 的每个前缀后，返回最多 3 个字典序最小的商品名。

Trie 版思路：

1. 把所有商品名插入 Trie。
2. 对 `searchWord` 的每个前缀，先走到前缀节点。
3. 从前缀节点开始按 `a` 到 `z` 做 DFS。
4. 收集到 3 个结果就停止。

```cpp
void collectSuggestions(TrieNode* node,
                        std::string& path,
                        std::vector<std::string>& result) {
    if (node == nullptr || result.size() == 3) return;

    if (node->isEnd) {
        result.push_back(path);
        if (result.size() == 3) return;
    }

    for (int i = 0; i < 26; ++i) {
        if (node->child[i] == nullptr) continue;

        path.push_back(static_cast<char>('a' + i));
        collectSuggestions(node->child[i], path, result);
        path.pop_back();

        if (result.size() == 3) return;
    }
}
```

按 `a` 到 `z` 遍历子节点，可以自然得到字典序结果。候选不足 3 个时，返回实际找到的数量即可。

这道题也可以用“排序 + 二分”做：先把商品名排序，再对每个前缀定位可能区间，取前三个匹配项。静态数据时排序方案很简洁；如果词典需要动态插入或频繁做前缀查询，Trie 更贴近问题结构。

---

## Trie 和其他结构的选择

| 场景 | 推荐 |
|------|------|
| 只查完整单词是否存在 | `unordered_set<string>` |
| 查前缀是否存在 | Trie |
| 查某前缀下有多少单词 | Trie + `passCount` |
| 静态搜索建议 | 排序数组 + 二分 或 Trie |
| 动态搜索建议 | Trie |
| 多单词网格搜索 | Trie + DFS |
| 字符集很大且稀疏 | `unordered_map<char, TrieNode*>` 子节点 |

Trie 的代价是节点数量多、内存占用大。如果只是少量字符串完整匹配，哈希表更简单。

---

## 复杂度总结

设单词长度为 `L`，字典总字符数为 `S`。

| 操作 | 时间复杂度 | 空间复杂度 |
|------|------------|------------|
| 插入单词 | `O(L)` | 新增节点最多 `O(L)` |
| 完整查找 | `O(L)` | `O(1)` |
| 前缀查找 | `O(L)` | `O(1)` |
| 构建 Trie | `O(S)` | `O(S * 字符集大小)` 或 `O(S)` 级节点 |
| 替换单词 | 每个单词最多走到自身长度 | Trie 节点空间 |
| 搜索建议 | 前缀定位 `O(L)`，DFS 最多收集 3 个 | Trie 节点空间 |
| 多单词网格搜索 | 由网格 DFS 和 Trie 剪枝共同决定 | Trie + 递归栈 |

固定数组版本每个节点都有 26 个指针，查询快但占内存；哈希表版本只存存在的边，空间更省但常数更大。

## 常见误区

### 1. 把路径存在当成完整单词存在

插入 `apple` 后，`app` 的路径存在，但如果 `app` 没有被单独插入，`search("app")` 应该返回 `false`。完整匹配必须检查 `isEnd`。

### 2. 前缀匹配错误检查 `isEnd`

`startsWith("app")` 只关心路径是否存在，不要求最后节点是单词结尾。

### 3. 字符集假设不匹配

`ch - 'a'` 只适用于小写英文字母。题目如果包含其他字符，必须换子节点结构或先做字符映射。

### 4. Word Search II 找到单词后重复加入答案

可以把 `wordIndex` 置为 `-1`，或用集合去重。直接 `push_back` 可能重复记录同一个单词。

### 5. DFS 标记后忘记恢复

网格搜索的访问标记是当前路径的临时状态，递归返回后必须恢复。

### 6. 搜索建议没有按字典序遍历

Trie 方案要按 `a` 到 `z` 遍历子节点，才能自然得到字典序最小的候选。

## 关键要点

1. Trie 用路径表示字符串，共享公共前缀。
2. `isEnd` 区分“前缀存在”和“完整单词存在”。
3. 小写字符集用 `array<TrieNode*, 26>`，复杂字符集用哈希表子节点。
4. 前缀匹配、替换词根、搜索建议都依赖快速定位前缀节点。
5. 多单词搜索常用 Trie + 网格 DFS，让不存在的前缀尽早剪枝。
6. Trie 查询快，但可能用更多内存；只查完整字符串时哈希表通常更简单。

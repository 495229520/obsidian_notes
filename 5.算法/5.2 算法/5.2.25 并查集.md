# 5.2.25 并查集

> 并查集用于维护“元素属于哪个集合”。它不关心具体路径，只关心两个元素是否已经连通，以及动态加入关系后集合如何合并。

---

## 并查集解决什么问题

并查集（Union-Find / Disjoint Set Union, DSU）适合处理一类动态连通性问题：

| 题目信号 | 并查集做什么 |
|----------|--------------|
| 两个点是否属于同一组 | 查询根节点是否相同 |
| 不断加入边或关系 | 合并两个集合 |
| 求连通分量数量 | 成功合并时分量数减一 |
| 判断新增边是否成环 | 两端点原本已连通则成环 |
| 网格中相邻陆地连成岛 | 把二维格子映射成一维节点后合并 |

它常出现在图题、社交关系、网络连通性、账号合并、最小生成树 Kruskal 等场景。和 [[5.算法/5.2 算法/5.2.26 图与图算法|图与图算法]]、[[5.算法/5.2 算法/5.2.24 图论基础|图论基础]] 的关系是：DFS / BFS 更像“现场遍历整张图”，并查集更像“边到来时持续维护连通状态”。

> [!tip]
> 如果题目反复出现“合并集合”“是否连通”“有几组”“新加一条边会不会形成环”，优先考虑并查集。

---

## 基础模型

并查集用一个 `parent` 数组表示森林：

- `parent[x] == x`：`x` 是当前集合的根节点。
- `parent[x] != x`：`x` 的父节点是 `parent[x]`。
- 两个元素的根节点相同，说明它们属于同一个集合。

```text
parent[0] = 0
parent[1] = 0
parent[2] = 1

2 -> 1 -> 0
根节点是 0，所以 2 属于以 0 为代表的集合
```

最基础的查询是 `find(x)`：不断沿着父节点向上走，直到根节点。

```cpp
int findRoot(int x, const std::vector<int>& parent) {
    while (parent[x] != x) {
        x = parent[x];
    }
    return x;
}
```

但只写成这样还不够。如果合并顺序很差，树可能退化成链，查询会变慢。因此并查集通常配合两个优化：**路径压缩**和**按秩合并**。

---

## 路径压缩

路径压缩发生在 `find` 过程中：既然已经找到根节点，就把沿途节点直接挂到根节点下面。后续再查这些节点时，就能一步到根。

![[图片/5.算法/5.2 算法/5_2_2_25_1.svg]]

递归写法最常见：

```cpp
int find(int x) {
    if (parent_[x] != x) {
        parent_[x] = find(parent_[x]);
    }
    return parent_[x];
}
```

**关键点**：

- `find(x)` 返回的是集合代表元，也就是根节点。
- `parent_[x] = find(parent_[x])` 会把 `x` 直接挂到根节点。
- 路径压缩不改变集合划分，只改变树的形状。

> [!note]
> 路径压缩后的树不一定严格保持原来的高度含义，所以 `rank_` 通常只作为合并时的近似高度，而不是精确高度。

---

## 按秩合并

合并两个集合时，不能随便让一个根挂到另一个根下面。按秩合并的原则是：**让矮树挂到高树下面**，避免树越来越深。

```cpp
bool unite(int x, int y) {
    int rx = find(x);
    int ry = find(y);
    if (rx == ry) return false;

    if (rank_[rx] < rank_[ry]) {
        std::swap(rx, ry);
    }

    parent_[ry] = rx;
    if (rank_[rx] == rank_[ry]) {
        ++rank_[rx];
    }
    --count_;
    return true;
}
```

**为什么相同秩时才加一**：

- 矮树挂到高树下，高树高度不变。
- 两棵同高的树合并，新的树高度才可能增加一层。
- `count_` 只在两个不同集合成功合并时减少。

路径压缩 + 按秩合并后，并查集单次操作的均摊复杂度接近 `O(1)`，更准确地说是 `O(α(n))`，其中 `α` 是反阿克曼函数，在常见数据规模下可以近似看成常数。

---

## 通用 C++ 模板

```cpp
#include <numeric>
#include <utility>
#include <vector>

class UnionFind {
public:
    explicit UnionFind(int n) : parent_(n), rank_(n, 0), count_(n) {
        std::iota(parent_.begin(), parent_.end(), 0);
    }

    int find(int x) {
        if (parent_[x] != x) {
            parent_[x] = find(parent_[x]);
        }
        return parent_[x];
    }

    bool unite(int x, int y) {
        int rx = find(x);
        int ry = find(y);
        if (rx == ry) return false;

        if (rank_[rx] < rank_[ry]) {
            std::swap(rx, ry);
        }

        parent_[ry] = rx;
        if (rank_[rx] == rank_[ry]) {
            ++rank_[rx];
        }
        --count_;
        return true;
    }

    bool connected(int x, int y) {
        return find(x) == find(y);
    }

    int count() const {
        return count_;
    }

private:
    std::vector<int> parent_;
    std::vector<int> rank_;
    int count_;
};
```

这个模板适合节点编号为 `[0, n)` 的题目。如果题目编号是 `[1, n]`，通常创建 `UnionFind uf(n + 1)`，下标 `0` 不使用。

## 连通分量：省份数量

[[547. 省份数量|547. 省份数量]] 的本质是无向图连通分量计数。

思路：

1. 初始时每个城市都是一个独立省份，`count_ = n`。
2. 遍历邻接矩阵上三角，遇到 `isConnected[i][j] == 1` 就合并城市 `i` 和 `j`。
3. 每次成功合并，连通分量数减一。
4. 最终 `uf.count()` 就是省份数量。

```cpp
#include <numeric>
#include <vector>

int findCircleNum(const std::vector<std::vector<int>>& isConnected) {
    int n = static_cast<int>(isConnected.size());
    UnionFind uf(n);

    for (int i = 0; i < n; ++i) {
        for (int j = i + 1; j < n; ++j) {
            if (isConnected[i][j] == 1) {
                uf.unite(i, j);
            }
        }
    }

    return uf.count();
}
```

只遍历上三角，是因为矩阵对称；`i == j` 表示城市和自己相连，也没有合并意义。

## 冗余连接：加边判环

冗余连接类问题通常给出一条条无向边，要求找出第一条或最后一条让图成环的边。

并查集判断方式非常直接：

- 如果 `u` 和 `v` 原本不连通，加入这条边只是合并两个分量。
- 如果 `u` 和 `v` 原本已经连通，再加入这条边就形成环。

![[图片/5.算法/5.2 算法/5_2_2_25_2.svg]]

```cpp
#include <vector>

std::vector<int> findRedundantConnection(const std::vector<std::vector<int>>& edges) {
    UnionFind uf(static_cast<int>(edges.size()) + 1);

    for (const auto& edge : edges) {
        int u = edge[0];
        int v = edge[1];
        if (!uf.unite(u, v)) {
            return edge;
        }
    }

    return {};
}
```

> [!warning]
> 这类题经常使用 1-based 编号，所以并查集大小通常要开到 `n + 1`。

## 岛屿数量变体

[[200. 岛屿数量|200. 岛屿数量]] 的主解通常是 DFS / BFS；但如果题目变成“动态加陆地”“多次查询岛屿数量”，并查集会更自然。

并查集处理网格的关键是把二维坐标映射成一维编号：

```cpp
int id(int row, int col, int cols) {
    return row * cols + col;
}
```

静态岛屿数量也可以用并查集写：

```cpp
#include <numeric>
#include <vector>

int numIslandsByUnionFind(const std::vector<std::vector<char>>& grid) {
    if (grid.empty() || grid[0].empty()) return 0;

    int rows = static_cast<int>(grid.size());
    int cols = static_cast<int>(grid[0].size());
    UnionFind uf(rows * cols);
    int water = 0;

    const int dirs[2][2] = {{1, 0}, {0, 1}};

    for (int r = 0; r < rows; ++r) {
        for (int c = 0; c < cols; ++c) {
            if (grid[r][c] == '0') {
                ++water;
                continue;
            }

            int cur = r * cols + c;
            for (const auto& dir : dirs) {
                int nr = r + dir[0];
                int nc = c + dir[1];
                if (nr < rows && nc < cols && grid[nr][nc] == '1') {
                    uf.unite(cur, nr * cols + nc);
                }
            }
        }
    }

    return uf.count() - water;
}
```

**为什么最后要减去 `water`**：

- `UnionFind uf(rows * cols)` 会把每个格子都当成一个初始集合。
- 水格子不应该算作岛屿分量。
- 因此最终连通分量数需要减去水格子的数量。

> [!tip]
> 如果是“动态加陆地”问题，通常不要一开始把所有格子都算进集合，而是用 `active` 数组记录哪些格子已经变成陆地；每加入一个新陆地，岛屿数先加一，再和相邻陆地合并。

## 如何识别题型

| 题目特征 | 优先考虑 | 写法要点 |
|----------|----------|----------|
| 给定关系，问有几个组 | 并查集 / DFS | 并查集用 `count_` 维护分量数 |
| 连续加入边，问是否成环 | 并查集 | `unite` 返回 `false` 表示原本已连通 |
| 查询两点是否属于同一集合 | 并查集 | 比较 `find(x)` 和 `find(y)` |
| 网格相邻格合并 | 并查集 | 二维坐标映射为 `r * cols + c` |
| 需要具体路径或遍历顺序 | DFS / BFS | 并查集不记录路径细节 |

---

## 复杂度总结

| 操作 | 时间复杂度 | 说明 |
|------|------------|------|
| `find` | `O(α(n))` 均摊 | 路径压缩后接近常数 |
| `unite` | `O(α(n))` 均摊 | 两次 `find` 加一次挂接 |
| `connected` | `O(α(n))` 均摊 | 比较两个根节点 |
| 初始化 | `O(n)` | 初始化 `parent_` 和 `rank_` |
| 空间 | `O(n)` | 主要是 `parent_`、`rank_` |

## 常见误区

### 1. 合并时直接改 `parent_[x]`

合并的是两个集合的根节点，不是随便把 `x` 挂到 `y` 上。正确流程是先 `find(x)`、`find(y)`，再合并根节点。

### 2. `count_` 每次调用 `unite` 都减一

只有两个元素原本不属于同一集合时，合并才会减少连通分量。`rx == ry` 时不能减少。

### 3. 忘记编号范围

节点编号是 `[0, n)` 还是 `[1, n]` 要先看题目。1-based 题目通常需要 `UnionFind uf(n + 1)`。

### 4. 在网格题中重复合并四个方向

静态网格可以只检查右、下两个方向，避免重复合并。重复合并不影响正确性，但会多做无意义查询。

### 5. 用并查集寻找具体路径

并查集只能回答“是否连通”和“属于哪个集合”，不能恢复从 `u` 到 `v` 的具体路径。需要路径时应使用 DFS / BFS。

---

## 关键要点

1. 并查集维护的是集合关系，不维护具体路径。
2. `find` 找根节点，路径压缩让后续查询更快。
3. `unite` 合并两个根节点，按秩合并避免树退化。
4. `unite` 返回 `false` 可以直接用于加边判环。
5. `count_` 适合维护连通分量数量，成功合并时减一。
6. 网格题需要先把二维坐标映射成一维编号。
7. 路径压缩 + 按秩合并后，并查集操作可以近似看成常数时间。

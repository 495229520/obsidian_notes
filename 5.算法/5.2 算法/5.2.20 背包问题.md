# 5.2.20 背包问题

> 背包问题的核心是：在有限容量或有限目标下，逐个处理物品，决定“选不选、选几次、顺序是否重要”。LeetCode 高频题里，零钱兑换、分割等价子集、组合总和计数都可以归到背包模型。

---

## 背包问题解决什么问题

背包 DP 常见于“从一批数里凑出某个目标”的题目：

| 题目信号 | 背包模型 |
|----------|----------|
| 每个数最多用一次 | 0-1 背包 |
| 每个数可以无限用 | 完全背包 |
| 能不能凑出 target | 可行性背包 |
| 有多少种凑法 | 计数背包 |
| 凑出 target 的最少/最大数量 | 最值背包 |

和 [[5.算法/5.2 算法/5.2.19 动态规划|动态规划]] 总纲相比，本篇只关注背包类题的状态压缩和遍历顺序。背包题最难的不是转移式，而是**容量循环到底正序还是倒序**。

## 0-1 背包

0-1 背包的限制是：每个物品最多选一次。

二维状态最直观：

```text
dp[i][j] = 只看前 i 个物品，容量为 j 时能获得的最大价值
```

转移：

```text
不选第 i 个物品：dp[i][j] = dp[i - 1][j]
选第 i 个物品：dp[i][j] = dp[i - 1][j - weight[i]] + value[i]
```

空间压缩后只保留一维 `dp[j]`：

```cpp
#include <algorithm>
#include <vector>

int zeroOneKnapsack(const std::vector<int>& weight,
                    const std::vector<int>& value,
                    int capacity) {
    std::vector<int> dp(capacity + 1, 0);

    for (int i = 0; i < static_cast<int>(weight.size()); ++i) {
        for (int j = capacity; j >= weight[i]; --j) {
            dp[j] = std::max(dp[j], dp[j - weight[i]] + value[i]);
        }
    }

    return dp[capacity];
}
```

**为什么容量要倒序**：

- 0-1 背包要求每个物品最多用一次。
- 倒序遍历时，`dp[j - weight[i]]` 仍然是处理当前物品之前的结果。
- 如果正序遍历，当前物品刚更新过的小容量状态可能又被大容量使用，相当于同一个物品被选了多次。

## 完全背包

完全背包的限制是：每个物品可以选无限次。

一维模板和 0-1 背包非常像，但容量要正序：

```cpp
#include <algorithm>
#include <vector>

int completeKnapsack(const std::vector<int>& weight,
                     const std::vector<int>& value,
                     int capacity) {
    std::vector<int> dp(capacity + 1, 0);

    for (int i = 0; i < static_cast<int>(weight.size()); ++i) {
        for (int j = weight[i]; j <= capacity; ++j) {
            dp[j] = std::max(dp[j], dp[j - weight[i]] + value[i]);
        }
    }

    return dp[capacity];
}
```

**为什么容量要正序**：

- 完全背包允许当前物品重复使用。
- 正序遍历时，`dp[j - weight[i]]` 可能已经包含当前物品。
- 这正好表达“当前物品可以再选一次”。

> [!warning]
> 0-1 背包和完全背包的转移式看起来一样，真正区别在容量遍历方向。

## 可行性背包：分割等和子集

分割等和子集可以转化为：能否从数组中选一些数，使和为 `sum / 2`。每个数最多用一次，所以是 0-1 背包。

```cpp
#include <numeric>
#include <vector>

bool canPartition(const std::vector<int>& nums) {
    int sum = std::accumulate(nums.begin(), nums.end(), 0);
    if (sum % 2 != 0) return false;

    int target = sum / 2;
    std::vector<bool> dp(target + 1, false);
    dp[0] = true;

    for (int num : nums) {
        for (int j = target; j >= num; --j) {
            dp[j] = dp[j] || dp[j - num];
        }
    }

    return dp[target];
}
```

状态含义：

```text
dp[j] = 处理过的数字中，能否选出若干个，使它们的和恰好为 j
```

初始化 `dp[0] = true` 表示什么都不选时，可以凑出和 0。

## 最值背包：零钱兑换

零钱兑换问的是：用无限枚硬币凑出 `amount`，最少需要几枚。硬币可以重复使用，所以是完全背包的最小值版本。

```cpp
#include <algorithm>
#include <vector>

int coinChange(const std::vector<int>& coins, int amount) {
    const int inf = amount + 1;
    std::vector<int> dp(amount + 1, inf);
    dp[0] = 0;

    for (int coin : coins) {
        for (int j = coin; j <= amount; ++j) {
            dp[j] = std::min(dp[j], dp[j - coin] + 1);
        }
    }

    return dp[amount] == inf ? -1 : dp[amount];
}
```

**为什么 `inf = amount + 1` 足够大**：

- 如果硬币面额都为正，凑出 `amount` 最多使用 `amount` 枚面额为 1 的硬币。
- 因此 `amount + 1` 可以作为不可达标记。

## 计数背包：组合还是排列

计数背包最容易混淆的是：题目问的是组合数还是排列数。

| 目标 | 循环顺序 | 含义 |
|------|----------|------|
| 组合数 | 先物品，后容量 | 不关心顺序，`1+2` 和 `2+1` 算一种 |
| 排列数 | 先容量，后物品 | 关心顺序，`1+2` 和 `2+1` 算两种 |

### 组合数：零钱兑换 II

```cpp
#include <vector>

int changeCombinations(int amount, const std::vector<int>& coins) {
    std::vector<int> dp(amount + 1, 0);
    dp[0] = 1;

    for (int coin : coins) {
        for (int j = coin; j <= amount; ++j) {
            dp[j] += dp[j - coin];
        }
    }

    return dp[amount];
}
```

### 排列数：组合总和 IV

```cpp
#include <vector>

int combinationSumCount(const std::vector<int>& nums, int target) {
    std::vector<int> dp(target + 1, 0);
    dp[0] = 1;

    for (int j = 1; j <= target; ++j) {
        for (int num : nums) {
            if (j >= num) {
                dp[j] += dp[j - num];
            }
        }
    }

    return dp[target];
}
```

> [!tip]
> 如果题目说“不同顺序视为不同方案”，通常是排列数；否则多半是组合数。

## 如何识别题型

| 题目描述 | 模型 | 遍历方向 |
|----------|------|----------|
| 每个数字只能用一次 | 0-1 背包 | 容量倒序 |
| 数字可以无限重复使用 | 完全背包 | 容量正序 |
| 问能否凑出 target | 可行性背包 | `bool dp` |
| 问凑法数量 | 计数背包 | 看组合/排列决定外层循环 |
| 问最少硬币/最大价值 | 最值背包 | `min` / `max` 转移 |

---

## 复杂度总结

| 模型 | 时间复杂度 | 空间复杂度 |
|------|------------|------------|
| 0-1 背包 | `O(n * capacity)` | `O(capacity)` |
| 完全背包 | `O(n * capacity)` | `O(capacity)` |
| 可行性背包 | `O(n * target)` | `O(target)` |
| 计数背包 | `O(n * target)` | `O(target)` |

## 常见误区

### 1. 0-1 背包容量正序

这样会让同一个物品在同一轮被重复使用，变成完全背包。

### 2. `dp[0]` 初始化错误

可行性和计数题里，`dp[0]` 往往表示“空方案”。可行性设为 `true`，计数设为 `1`。

### 3. 组合数和排列数循环顺序写反

组合数先遍历物品，排列数先遍历容量。循环顺序不同，语义就不同。

### 4. 不可达状态没有保护

最小值背包中，如果 `dp[j - coin]` 还是 `inf`，加一后仍然应该保持不可达语义。用 `amount + 1` 这类安全哨兵能减少溢出风险。

---

## 关键要点

1. 背包题先判断每个物品能用几次。
2. 0-1 背包容量倒序，完全背包容量正序。
3. `dp[j]` 通常表示容量或目标为 `j` 时的最优值、可行性或方案数。
4. 计数题必须先分清组合数和排列数。
5. 分割等和子集是 0-1 可行性背包。
6. 零钱兑换是完全背包的最小值版本。

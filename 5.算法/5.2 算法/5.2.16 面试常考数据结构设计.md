# 5.2.16 面试常考数据结构设计

> 设计类数据结构题通常不是考“会不会某个 STL”，而是考能否把哈希表、链表、堆、栈、队列、Trie 等结构组合起来，并守住接口复杂度。

---

## 设计类题目考什么

面试里的数据结构设计题通常会给出固定接口，并要求每个接口达到特定复杂度。

| 考点 | 典型问题 |
|------|----------|
| 接口语义 | `get` 是否也算一次访问 |
| 复杂度约束 | 是否真的平均 `O(1)` 或 `O(log n)` |
| 组合数据结构 | 哈希表负责查找，链表负责顺序 |
| 迭代器失效 | 删除、移动节点后是否更新映射 |
| 边界条件 | 容量为 0、空结构、重复 key |

> [!tip]
> 设计题先写接口语义，再选底层结构。不要先堆 STL，再回头解释复杂度。

---

## 总览

| 题型 | 核心结构 | 目标复杂度 |
|------|----------|------------|
| LRU Cache | `unordered_map + list` | `get/put` 平均 `O(1)` |
| LFU Cache | `keyMap + freqMap + minFreq` | `get/put` 平均 `O(1)` |
| MinStack | 主栈 + 最小值栈 | `push/pop/top/getMin` `O(1)` |
| MonotonicQueue | `deque<int>` 保存候选下标 | 均摊 `O(1)` |
| RandomizedSet | `vector + unordered_map` | 插入/删除/随机 `O(1)` |
| Trie | 字符路径树 | 单词长度 `O(L)` |
| MedianFinder | 大根堆 + 小根堆 | 插入 `O(log n)`，查询 `O(1)` |

## LRU：哈希表 + 双向链表

[[146. LRU 缓存|146. LRU 缓存]] 的核心结构是：

```cpp
std::list<std::pair<int, int>> cache;
std::unordered_map<int, std::list<std::pair<int, int>>::iterator> pos;
```

约定：

- 链表头部是最近使用。
- 链表尾部是最久未使用。
- `pos[key]` 指向 key 所在的链表节点。

关键操作：

| 操作 | 做什么 |
|------|--------|
| `get(key)` 命中 | 读取 value，并把节点移动到头部 |
| `put(key, value)` 已存在 | 更新 value，并移动到头部 |
| `put(key, value)` 新 key | 头部插入，超容量时删除尾部 |

> [!warning]
> `get` 命中也是一次访问，必须更新最近使用顺序。

在 C++ 中，`std::list::splice` 可以把节点移动到头部，并保持迭代器有效：

```cpp
cache.splice(cache.begin(), cache, it);
```

如果使用 `erase + push_front`，一定要同步更新哈希表里的迭代器。

## LFU：频次表 + 频次链表

LFU（Least Frequently Used）淘汰访问频次最低的 key；如果频次相同，淘汰最久未使用的 key。

常用结构：

```text
keyMap:  key -> {value, freq, iterator}
freqMap: freq -> list<key>
minFreq: 当前最小频次
```

流程：

1. `get(key)` 命中后，key 的频次加一。
2. 从旧频次链表删除 key。
3. 插入到新频次链表头部。
4. 如果旧频次是 `minFreq` 且链表变空，`minFreq++`。
5. 淘汰时，从 `freqMap[minFreq]` 的尾部删除最旧 key。

```cpp
#include <list>
#include <unordered_map>

struct LFUNode {
    int value = 0;
    int freq = 0;
    std::list<int>::iterator it;
};
```

> [!note]
> LFU 比 LRU 多了一个维度：频次。每个频次内部仍然要维护 LRU 顺序。

## 最小栈

最小栈要求普通栈操作之外，还能 `O(1)` 查询当前最小值。

结构：

```text
data 栈：保存所有元素
mins 栈：保存历史最小值
```

关键点：

- 入栈时，如果 `x <= mins.top()`，也把 `x` 压入最小值栈。
- 出栈时，如果弹出的值等于 `mins.top()`，同步弹出最小值栈。
- 使用 `<=` 是为了处理重复最小值。

细节可回看 [[5.算法/5.2 算法/5.2.10 栈与单调结构|栈与单调结构]]。

## 单调队列

单调队列常用于滑动窗口最大值或最小值。

结构：

```cpp
std::deque<int> dq;  // 保存下标，不直接保存值
```

维护最大值时：

- 队头过期就弹出。
- 入队前，从队尾弹出所有小于等于当前值的下标。
- 队头下标对应的值就是当前窗口最大值。

这类题的核心不是 `queue` 接口，而是候选下标的有效性和单调性。

## 随机集合

随机集合要求：

- `insert(val)` 平均 `O(1)`。
- `remove(val)` 平均 `O(1)`。
- `getRandom()` 平均 `O(1)` 等概率返回一个元素。

核心结构：

```cpp
#include <random>
#include <unordered_map>
#include <vector>

class RandomizedSet {
public:
    bool insert(int val) {
        if (index_.count(val) > 0) return false;
        index_[val] = static_cast<int>(nums_.size());
        nums_.push_back(val);
        return true;
    }

    bool remove(int val) {
        auto it = index_.find(val);
        if (it == index_.end()) return false;

        int idx = it->second;
        int last = nums_.back();
        nums_[idx] = last;
        index_[last] = idx;

        nums_.pop_back();
        index_.erase(it);
        return true;
    }

    int getRandom() {
        std::uniform_int_distribution<int> dist(0, static_cast<int>(nums_.size()) - 1);
        return nums_[dist(rng_)];
    }

private:
    std::vector<int> nums_;
    std::unordered_map<int, int> index_;
    std::mt19937 rng_{std::random_device{}()};
};
```

**为什么删除时用末尾覆盖**：

- `vector` 中间删除是 `O(n)`。
- 把最后一个元素搬到待删位置，再 `pop_back()`，就能保持 `O(1)`。
- 搬动后必须更新最后一个元素的新下标。

## 双堆中位数

数据流中位数常用两个堆：

| 堆 | 保存什么 |
|----|----------|
| 大根堆 `left` | 较小的一半 |
| 小根堆 `right` | 较大的一半 |

不变量：

- `left.size()` 等于 `right.size()`，或比 `right` 多 1。
- `left.top() <= right.top()`。
- 中位数来自两个堆顶。

```cpp
#include <functional>
#include <queue>
#include <vector>

class MedianFinder {
public:
    void addNum(int num) {
        if (left_.empty() || num <= left_.top()) {
            left_.push(num);
        } else {
            right_.push(num);
        }
        rebalance();
    }

    double findMedian() const {
        if (left_.size() == right_.size()) {
            return (left_.top() + right_.top()) / 2.0;
        }
        return left_.top();
    }

private:
    std::priority_queue<int> left_;
    std::priority_queue<int, std::vector<int>, std::greater<int>> right_;

    void rebalance() {
        if (left_.size() > right_.size() + 1) {
            right_.push(left_.top());
            left_.pop();
        } else if (right_.size() > left_.size()) {
            left_.push(right_.top());
            right_.pop();
        }
    }
};
```

堆接口和比较器细节可回看 [[5.算法/5.2 算法/5.2.11 堆与优先队列|堆与优先队列]]。

## 如何识别题型

| 接口要求 | 常用组合 |
|----------|----------|
| `O(1)` 查找 + 维护顺序 | 哈希表 + 双向链表 |
| 淘汰最少频次，频次相同按时间 | LFU 频次链表 |
| `O(1)` 最小值 | 辅助栈 |
| 滑动窗口最值 | 单调队列 |
| `O(1)` 随机返回 | `vector + unordered_map` |
| 前缀查询 | Trie |
| 动态中位数 | 双堆 |

---

## 常见误区

### 1. 只用哈希表实现 LRU

哈希表能快速查找，但不能维护最近使用顺序。

### 2. 链表节点移动后不更新迭代器

如果使用 `erase + push_front`，旧迭代器会失效，哈希表必须更新。使用 `splice` 可以减少这个问题。

### 3. LFU 忘记维护 `minFreq`

淘汰时必须知道当前最低频次，否则会退化成扫描所有 key。

### 4. 随机集合删除时忘记更新末尾元素下标

末尾元素覆盖到中间位置后，哈希表里的下标必须同步修改。

### 5. 双堆没有保持平衡

堆大小差超过 1 时，中位数就不能直接从堆顶得到。

---

## 关键要点

1. 设计题要先锁定接口语义和复杂度。
2. `unordered_map` 经常负责定位，`list` / `deque` / `heap` 负责维护顺序或优先级。
3. LRU 是哈希表 + 双向链表。
4. LFU 是 key 表 + freq 表 + `minFreq`。
5. 随机集合用 `vector` 保证随机访问，用哈希表保证定位。
6. 双堆中位数要维护大小平衡和左右有序。

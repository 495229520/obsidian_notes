# 5.2.7 双指针与滑动窗口

> 双指针通过有规则地移动两个下标或链表指针，减少重复枚举；滑动窗口是同向双指针在连续区间问题中的特化。

---

## 双指针与滑动窗口解决什么问题

很多数组、字符串、链表题的暴力写法都是多重枚举：

```text
for 每个起点 left:
    for 每个终点 right:
        检查区间 [left, right]
```

如果每次都重新扫描，复杂度很容易变成 `O(n²)` 甚至更高。双指针的核心是：**让每个元素只被访问常数次，用指针移动规则替代重复枚举**。

常见模式可以分成五类：

| 类型 | 指针方向 | 常见场景 | 核心条件 |
|------|----------|----------|----------|
| 对撞指针 | 两端向中间 | 有序数组、回文、两数和、三数和 | 排序或单调性 |
| 快慢指针 | 同起点不同速度 | 链表环、中点、倒数第 k 个节点 | 速度差或固定间距 |
| 同向双指针 | 同方向扫描 | 去重、覆盖、合并、压缩 | 每个元素最多访问常数次 |
| 固定窗口 | 同向维护固定长度区间 | 长度为 k 的子数组 / 子串 | 窗口长度固定 |
| 可变窗口 | 同向维护可变长度区间 | 最长 / 最短满足条件的连续区间 | 窗口合法性可维护 |

> [!tip] 双指针的关键
> 不是“用了两个变量”就叫双指针，而是每次移动都依赖明确的不变量：为什么移动左指针、为什么移动右指针、移动后仍然不会漏解。

---

## 对撞指针

对撞指针通常把 `left` 放在左端，`right` 放在右端，然后根据当前状态决定移动哪一侧。

它最常见的前提是：**序列有序，或者两端结构具有对称性**。

### 适用场景

| 场景 | 为什么能用对撞指针 |
|------|--------------------|
| 有序数组两数和 | 和太小就增大 `left`，和太大就减小 `right` |
| 三数之和 | 固定一个数后，在右侧有序区间做两数和 |
| 回文判断 | 左右字符必须配对相等 |
| 盛水容器类问题 | 两端边界决定当前状态，移动较弱一侧 |

[[15. 三数之和|15. 三数之和]] 就是典型的“排序 + 对撞指针”：先通过 [[5.算法/5.2 算法/5.2.5 常见排序算法与STL排序|常见排序算法与 STL 排序]] 建立单调性，再用左右夹逼降低枚举成本。

### 有序数组两数和模板

这个模板解决的是：在已经升序的数组中，找两个数使它们的和等于 `target`。

```cpp
#include <vector>

std::vector<int> twoSumSorted(const std::vector<int>& nums, int target) {
    if (nums.size() < 2) return {};

    int left = 0;
    int right = static_cast<int>(nums.size()) - 1;

    while (left < right) {
        int sum = nums[left] + nums[right];
        if (sum == target) {
            return {left, right};
        }
        if (sum < target) {
            ++left;
        } else {
            --right;
        }
    }

    return {};
}
```

**关键点**：

- `sum < target` 时移动 `left`，因为数组有序，右端不变时只能通过增大左端让和变大。
- `sum > target` 时移动 `right`，因为左端不变时只能通过减小右端让和变小。
- 这类写法依赖“有序”这个不变量；无序数组不能直接这样移动。
- `right` 使用 `int` 前先判断 `nums.size() < 2`，避免空数组下 `size() - 1` 的边界问题。

### 三数之和中的去重

三数之和除了左右夹逼，还必须处理重复答案：

```cpp
while (left < right && nums[left] == nums[left + 1]) ++left;
while (left < right && nums[right] == nums[right - 1]) --right;
++left;
--right;
```

**为什么命中答案后再去重**：

- 排序后相同值相邻，重复的 `left` 或 `right` 会产生相同三元组。
- 只在找到答案后跳过重复左右端，可以避免漏掉还没检查过的组合。
- 固定数 `nums[i]` 也需要去重，否则同一个三元组可能从不同 `i` 开始产生。

> [!warning]
> 对撞指针不是“左右一起动”。每次移动哪一侧，必须由当前不变量决定；否则容易漏解。

## 快慢指针

快慢指针常用于链表，因为链表不能像 [[5.算法/5.1 STL/5.1.1 vector|vector]] 那样随机访问下标。通过让两个指针保持速度差或固定距离，可以在一次遍历中得到结构信息。

链表指针操作可以参考 [[206. 反转链表|206. 反转链表]]、[[25. K 个一组翻转链表|25. K 个一组翻转链表]] 和 [[1.C++基础/6. 指针/6.1基本指针|基本指针]]。

### 链表环检测

如果链表有环，快指针每次走两步，慢指针每次走一步，最终会在环内相遇。

```cpp
struct ListNode {
    int val = 0;
    ListNode* next = nullptr;
};

bool hasCycle(ListNode* head) {
    ListNode* slow = head;
    ListNode* fast = head;

    while (fast != nullptr && fast->next != nullptr) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) {
            return true;
        }
    }

    return false;
}
```

**关键点**：

- `fast != nullptr && fast->next != nullptr` 是空指针保护，保证 `fast->next->next` 安全。
- 如果没有环，`fast` 会先到达链表末尾。
- 如果有环，`fast` 会在环内不断追赶 `slow`，最终相遇。

### 链表中点

快慢指针也可以找链表中点：快指针走两步，慢指针走一步；快指针到末尾时，慢指针在中间。

```cpp
ListNode* middleNode(ListNode* head) {
    ListNode* slow = head;
    ListNode* fast = head;

    while (fast != nullptr && fast->next != nullptr) {
        slow = slow->next;
        fast = fast->next->next;
    }

    return slow;
}
```

**关键点**：

- 奇数长度时，`slow` 指向唯一中点。
- 偶数长度时，这种写法返回第二个中点。
- 如果题目要求第一个中点，需要调整循环条件或初始化方式。

### 倒数第 k 个节点

倒数第 k 个节点使用的是“固定间距”：先让 `fast` 领先 `slow` k 步，再一起移动。

```cpp
ListNode* kthFromEnd(ListNode* head, int k) {
    if (k <= 0) return nullptr;

    ListNode* slow = head;
    ListNode* fast = head;

    for (int i = 0; i < k; ++i) {
        if (fast == nullptr) return nullptr;
        fast = fast->next;
    }

    while (fast != nullptr) {
        slow = slow->next;
        fast = fast->next;
    }

    return slow;
}
```

**为什么这样写**：

- `fast` 先走 k 步后，`slow` 和 `fast` 之间保持 k 个节点的距离。
- 当 `fast` 到达空位置时，`slow` 正好停在倒数第 k 个节点。
- 如果 k 超过链表长度，提前返回 `nullptr`。

> [!note] 快慢指针的本质
> 快慢指针不是只能“一个走一步、一个走两步”。它的本质是让两个指针保持速度差或距离差，从而在一次遍历中推导位置关系。

## 同向双指针

同向双指针通常让两个指针都从左向右移动：

- `fast` 负责扫描输入。
- `slow` 负责维护有效区域的边界。

它常用于原地去重、移动元素、数组压缩、字符串压缩等题型。

### 有序数组原地去重

有序数组中，相同元素相邻。`slow` 指向当前最后一个不重复元素，`fast` 向右寻找新值。

```cpp
#include <vector>

int removeDuplicates(std::vector<int>& nums) {
    if (nums.empty()) return 0;

    int slow = 0;
    for (int fast = 1; fast < static_cast<int>(nums.size()); ++fast) {
        if (nums[fast] != nums[slow]) {
            ++slow;
            nums[slow] = nums[fast];
        }
    }

    return slow + 1;
}
```

**关键点**：

- `[0, slow]` 始终是已经处理出的不重复区域。
- `fast` 负责扫描每个元素。
- 发现新值时，先 `++slow`，再把新值写到有效区域末尾。
- 返回值是长度，所以是 `slow + 1`，不是 `slow`。

### 同向双指针的常见不变量

| 场景 | `slow` 含义 | `fast` 含义 |
|------|-------------|-------------|
| 原地去重 | 最后一个有效元素位置 | 当前扫描位置 |
| 移动零 | 下一个非零元素应写入的位置 | 当前扫描位置 |
| 字符串压缩 | 下一个写入位置 | 当前读取位置 |
| 分区过滤 | 合法区域边界 | 当前检查元素 |

> [!warning]
> 同向双指针最容易混淆的是 `slow` 表示“最后一个有效下标”还是“有效长度”。写代码前先定义清楚，边界才不容易错。

## 滑动窗口总览

滑动窗口是同向双指针在连续区间问题中的特化。通常用 `left` 和 `right` 表示当前窗口 `[left, right]`。

```text
s = a b c a b c b b
        left   right
窗口 = [left, right]
```

窗口题的关键不是移动两个指针本身，而是维护窗口状态：

| 状态 | 典型结构 |
|------|----------|
| 窗口和 | `int` / `long long` |
| 字符是否出现 | `std::unordered_set<char>` |
| 出现次数 | `std::unordered_map<char, int>` 或计数数组 |
| 不同元素个数 | 哈希表 + distinct 计数 |
| 当前非法程度 | duplicate 数量、missing 数量等 |

窗口状态常会用到 [[5.算法/5.2 算法/5.2.8 哈希表与计数|哈希表与计数]] 中的集合、频率表思想；字符串窗口可以结合 [[5.算法/5.1 STL/5.1.6 string|string]] 理解。

### 固定窗口 vs 可变窗口

| 窗口类型 | 窗口长度 | 典型目标 |
|----------|----------|----------|
| 固定窗口 | 始终等于 k | 长度为 k 的最大和、平均值、字符统计 |
| 可变窗口 | 根据条件变化 | 最长合法窗口、最短满足窗口 |

---

## 固定窗口

固定窗口适合题目明确给出窗口长度 `k` 的场景：

- 长度为 `k` 的连续子数组最大和
- 长度为 `k` 的子串中元音数量
- 每个长度为 `k` 的窗口统计某种状态

### 长度为 k 的最大子数组和

固定窗口不需要反复重新求和。右边加入一个元素，左边移出一个元素，窗口和就能 `O(1)` 更新。

```cpp
#include <algorithm>
#include <vector>

int maxSumOfFixedWindow(const std::vector<int>& nums, int k) {
    if (k <= 0 || k > static_cast<int>(nums.size())) return 0;

    int windowSum = 0;
    for (int i = 0; i < k; ++i) {
        windowSum += nums[i];
    }

    int best = windowSum;
    for (int right = k; right < static_cast<int>(nums.size()); ++right) {
        windowSum += nums[right];
        windowSum -= nums[right - k];
        best = std::max(best, windowSum);
    }

    return best;
}
```

**关键点**：

- 先初始化前 `k` 个元素，保证窗口一开始就是合法长度。
- 从 `right = k` 开始，每轮加入 `nums[right]`。
- 被移出的左端正好是 `nums[right - k]`。
- 每次移动后窗口长度仍然是 `k`。

> [!warning]
> 固定窗口最常见错误是窗口还没达到长度 `k` 就更新答案，或者移出元素下标写成 `right - k + 1`。

## 可变窗口

可变窗口适合“连续区间长度不固定，但必须满足某个条件”的问题。

常见关键词：

- 最长无重复子串
- 至多 k 个不同字符
- 最短满足条件子数组
- 乘积小于 k 的子数组
- 和至少为 target 的最短子数组

### 最长合法窗口模板

最长合法窗口的思路是：右边界不断扩张；一旦窗口非法，就移动左边界直到重新合法；合法后更新最大值。

[[3. 无重复字符的最长子串|3. 无重复字符的最长子串]] 就是这个模板的典型例子。

```cpp
#include <algorithm>
#include <string>
#include <unordered_set>

int lengthOfLongestUniqueSubstring(const std::string& s) {
    std::unordered_set<char> window;
    int left = 0;
    int best = 0;

    for (int right = 0; right < static_cast<int>(s.size()); ++right) {
        while (window.count(s[right]) > 0) {
            window.erase(s[left]);
            ++left;
        }

        window.insert(s[right]);
        best = std::max(best, right - left + 1);
    }

    return best;
}
```

**关键点**：

- `window` 保存当前窗口里的字符。
- `s[right]` 如果重复，窗口非法，需要不断移出左侧字符。
- 窗口恢复合法后，再加入 `s[right]` 并更新答案。
- 每个字符最多进入窗口一次、离开窗口一次，所以时间复杂度是 `O(n)`。

### 最短满足窗口模板

最短满足窗口的思路相反：右边界扩张直到满足条件；只要满足，就尽量收缩左边界，并在收缩过程中更新最小值。

下面示例求“非负数组中，和至少为 target 的最短连续子数组长度”。

```cpp
#include <algorithm>
#include <limits>
#include <vector>

int minSubarrayLen(int target, const std::vector<int>& nums) {
    int left = 0;
    int sum = 0;
    int best = std::numeric_limits<int>::max();

    for (int right = 0; right < static_cast<int>(nums.size()); ++right) {
        sum += nums[right];

        while (sum >= target) {
            best = std::min(best, right - left + 1);
            sum -= nums[left];
            ++left;
        }
    }

    return best == std::numeric_limits<int>::max() ? 0 : best;
}
```

**关键点**：

- `sum >= target` 时，当前窗口已经满足条件，可以尝试缩短。
- 缩短前先更新答案，因为当前窗口是一个合法候选。
- 移动 `left` 前必须先把 `nums[left]` 从 `sum` 中移除。
- 这个模板依赖数组元素非负；如果有负数，窗口和不再随右扩张单调变大，简单滑动窗口可能失效。

> [!warning] 滑动窗口的前提
> 对于和、积这类条件，可变窗口通常依赖元素非负带来的单调性；如果包含负数，可能需要前缀和、单调队列或哈希表。

## 如何识别题型

| 题目关键词 | 优先考虑 | 典型结构 |
|------------|----------|----------|
| 有序数组、两数和、三数和、回文 | 对撞指针 | `left` 从左，`right` 从右 |
| 链表是否有环、链表中点、倒数第 k 个 | 快慢指针 | `slow` / `fast` |
| 原地删除、去重、压缩、移动元素 | 同向双指针 | `slow` 写入，`fast` 扫描 |
| 长度为 k 的连续子数组 / 子串 | 固定窗口 | 加右端，删左端 |
| 最长 / 最短连续区间、无重复、至多 k 个 | 可变窗口 | 扩张 + 收缩 |

---

## 复杂度总结

| 模式 | 时间复杂度 | 空间复杂度 | 说明 |
|------|------------|------------|------|
| 对撞指针 | `O(n)`；若需要排序则 `O(nlogn)` | 通常 `O(1)` | 排序成本可能占主导 |
| 快慢指针 | `O(n)` | `O(1)` | 适合链表一次遍历 |
| 同向双指针 | `O(n)` | 通常 `O(1)` | 每个元素最多被读写常数次 |
| 固定窗口 | `O(n)` | 取决于窗口状态 | 维护一个长度为 k 的状态 |
| 可变窗口 | 通常 `O(n)` | 取决于窗口状态 | `left` 和 `right` 都只单调移动 |

## 常见误区

### 1. 没有不变量，只是机械移动指针

双指针每次移动都要回答一个问题：**为什么移动这个指针不会漏掉答案？**

- 对撞指针依赖有序性或对称性。
- 同向双指针依赖有效区域边界。
- 滑动窗口依赖窗口合法性。

### 2. 滑动窗口更新答案时机错误

| 目标 | 更新答案的时机 |
|------|----------------|
| 最长合法窗口 | 窗口恢复合法后更新最大值 |
| 最短满足窗口 | 窗口满足条件时更新最小值，并继续收缩 |
| 固定窗口 | 窗口长度达到 k 后更新 |

### 3. 收缩窗口时忘记同步状态

如果窗口状态用了集合、哈希表或计数数组，移动 `left` 前必须把左端元素从状态中移除或计数减一。

### 4. 对负数数组误用可变窗口

对于“窗口和至少为 target”这类题，如果数组含负数，右边界扩张不一定让和变大，左边界收缩也不一定让和变小。此时简单滑动窗口不再可靠。

### 5. 链表快慢指针缺少空指针保护

访问 `fast->next->next` 前，必须确认 `fast` 和 `fast->next` 都不是 `nullptr`。

---

## 最佳实践

| 推荐 | 避免 | 原因 |
|------|------|------|
| 先写清楚窗口或指针不变量 | 直接套模板 | 不变量决定移动方向 |
| 统一窗口定义 `[left, right]` | 一会儿闭区间一会儿半开区间 | 避免 off-by-one |
| 链表代码先写空指针条件 | 先移动再判断 | 防止空指针访问 |
| 固定窗口先初始化首个窗口 | 每轮重新计算窗口 | 保持 `O(n)` |
| 可变窗口同步维护状态 | 只移动指针不更新计数 | 状态会和窗口不一致 |

---

## 关键要点

1. 双指针的本质是“有规则地减少枚举”，不是简单声明两个变量。
2. 对撞指针通常依赖排序或对称结构，常见于两数和、三数和、回文判断。
3. 快慢指针适合链表问题，用速度差或距离差在一次遍历中获得结构信息。
4. 同向双指针常用于原地去重、覆盖、压缩，`slow` 和 `fast` 的含义要先定义清楚。
5. 固定窗口长度不变，核心是右端加入、左端移出。
6. 可变窗口长度随条件变化，核心是维护窗口合法性。
7. 滑动窗口处理和、积条件时要注意单调性；含负数时不能盲目套模板。

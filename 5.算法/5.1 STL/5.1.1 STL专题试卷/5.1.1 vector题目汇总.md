## 一、选择题（概念基础）

**1.** `vector` 的底层数据结构是：
- A. 链表　　B. 动态数组（连续内存）　　C. 红黑树　　D. 哈希表

**2.** 关于 `size()` 和 `capacity()`，正确的是：
- A. 两者永远相等
- B. `size` 是已有元素个数，`capacity` 是当前分配内存能容纳的元素个数，`size ≤ capacity`
- C. `capacity` 是元素个数，`size` 是内存字节数
- D. `capacity` 总是 `size` 的 2 倍

**3.** 主流实现（libstdc++/libc++）中，vector 扩容时新容量通常为原容量的：
- A. 1 倍（不变）　　B. 1.5 倍（MSVC）或 2 倍（GCC/Clang）　　C. 固定 +1　　D. 固定 +10

**4.** `vec.reserve(20)` 的作用是：
- A. 把 size 改成 20　　B. 只改变 capacity，不改变 size，也不构造元素
- C. 构造 20 个默认元素　　D. 把已有元素清空

**5.** `push_back` 的时间复杂度是：
- A. 恒定 O(1)　　B. 均摊（摊还）O(1)，单次最坏 O(n)　　C. 恒定 O(n)　　D. O(log n)

**6.** 关于 `vec[5]` 和 `vec.at(5)`，正确的是：
- A. 完全等价
- B. `operator[]` 不做越界检查（越界是 UB），`at()` 越界抛 `std::out_of_range`
- C. `at()` 更快，因为不检查
- D. 两者越界都抛异常

**7.** vector 内部三指针中，`size()` 等于：
- A. `_end - _first`　　B. `_last - _first`　　C. `_end - _last`　　D. `_last - _end`

**8.** 下列哪种操作**一定**使 vector 的**所有**迭代器失效：
- A. `operator[]` 访问　　B. `pop_back()`
- C. 触发扩容（重新分配内存）的 `push_back`/`insert`　　D. `size()`

**9.** `emplace_back(1, 2)` 相比 `push_back(Point(1, 2))` 的优势是：
- A. 线程安全　　B. 在容器内**原地构造**，省去临时对象的构造与移动/拷贝
- C. 自动去重　　D. 不会扩容

**10.** `vec.shrink_to_fit()` 的语义是：
- A. 强制让 `capacity == size`
- B. 一个**非强制**请求，实现可以忽略；通常会尽量把 capacity 收缩到接近 size
- C. 把 size 收缩到 0
- D. 释放整个 vector

> [!success]- 参考答案（第一节）
> 1. **B**。vector = 动态数组，内存连续，故支持 O(1) 随机访问；这也是它区别于 list（链表）的根本。
> 2. **B**。`size` = 有效元素数，`capacity` = 已分配内存可容纳数，恒有 `size ≤ capacity`。二者不相等正是扩容留下的"预留空间"。
> 3. **B**。GCC/Clang 常见 2 倍，MSVC 为 1.5 倍。倍增（而非固定增量）是均摊 O(1) 的关键。
> 4. **B**。`reserve` 只动 capacity，不动 size、不构造元素——这是它和 `resize` 的核心区别。若参数 ≤ 当前 capacity 则什么都不做（不会收缩）。
> 5. **B**。多数 `push_back` 是 O(1)，偶尔扩容那次是 O(n)（要搬迁全部元素）；因倍增使扩容次数呈对数级，均摊下来仍是 O(1)。
> 6. **B**。`operator[]` 为性能不做检查，越界是未定义行为；`at()` 做检查、越界抛 `std::out_of_range`。
> 7. **B**。`size() = _last - _first`（有效元素）；`capacity() = _end - _first`（总容量）。
> 8. **C**。只有"重新分配内存"才使全部迭代器/指针/引用失效；不扩容的 `push_back` 只让 `end()` 相关失效，`pop_back` 只让被删元素和 `end()` 失效。
> 9. **B**。`emplace_back` 用参数在容器末尾**直接构造**，避免先建临时对象再移动/拷贝进去。
> 10. **B**。标准规定 `shrink_to_fit` 是 non-binding request，实现可不理会；不能依赖它精确释放。

## 二、概念辨析（判断对错并说明理由）

**11.** `vec.reserve(100)` 之后，`vec.size()` 变为 100。

**12.** 只要调用 `push_back`，之前保存的迭代器就一定失效。

**13.** `resize(n)` 当 `n < size()` 时会缩小 size 并析构多余元素，同时立即把 capacity 也降下来释放内存。

**14.** 对一个空 vector 写 `v[0] = 1;`（未 reserve/resize）是安全的，会自动扩容。

**15.** `capacity()` 只会增大，永远不会自动变小（除非 `shrink_to_fit` 或 swap 技巧）。

**16.** `emplace_back` 一定比 `push_back` 快。

**17.** vector 内存连续，所以可以把 `&vec[0]` 当作 C 数组首地址传给需要 `int*` 的 C 接口（vector 非空时）。

**18.** `std::vector<bool>` 就是元素为 bool 的普通 vector，`&v[0]` 能取到 `bool*`。

> [!success]- 参考答案（第二节）
> 11. **错**。`reserve` 只增大 capacity，`size` 不变（仍是 0）。要改变 size 用 `resize`。
> 12. **错**。只有**触发扩容**（size 将超过 capacity）的 `push_back` 才使所有迭代器失效；若 capacity 足够，未搬迁内存，`end()` 之前的迭代器仍有效（但指向 `end()` 的迭代器要重新取）。
> 13. **错**。缩小 size 会析构多余元素，但 **capacity 不变**、内存不释放。要释放得再 `shrink_to_fit` 或用 `swap` 技巧。
> 14. **错**。空 vector 没有分配元素，`v[0]` 越界访问是**未定义行为**，不会自动扩容。要么先 `resize(1)`/`reserve`+`push_back`，要么用 `push_back`。
> 15. **对**。capacity 单调不减，除非显式 `shrink_to_fit` 或 `vector<int>(v).swap(v)`。
> 16. **错**。当传入的是已构造好的**右值对象**时，`push_back` 也是移动，二者相当；`emplace_back` 的优势主要在"用零散参数原地构造"。此外 emplace 在某些重载歧义/隐式转换场景下语义还更危险。
> 17. **对**。C++03 起标准保证 vector 元素连续，`&vec[0]`（或 `vec.data()`）可作连续缓冲区首地址；但**空 vector 不能这样取**，且一旦扩容指针失效。
> 18. **错**。`vector<bool>` 是**特化**，按位压缩存储，`operator[]` 返回代理对象而非 `bool&`，不能取 `bool*`。需要真正 bool 数组时用 `vector<char>`/`std::array<bool>`。

## 三、代码输出预测

**19.**
```cpp
std::vector<int> v;
v.reserve(20);
std::cout << v.empty() << " " << v.size() << " " << (v.capacity() >= 20);
```

```cpp
std::vector<int> v;
int prev = -1;
for (int i = 0; i < 9; ++i) {
    v.push_back(i);

```

**21.**
```cpp
std::vector<int> v{1, 2, 3, 4, 5};
v.resize(3);
std::cout << v.size() << " " << (v.capacity() >= 5);
```

**22.**
```cpp
std::vector<int> v(3, 7);      // {7,7,7}
v.resize(5);                    // 扩到 5
std::cout << v[3] << " " << v.size();
```

**23.**
```cpp
std::vector<int> v{10, 20, 30};
auto it = v.begin();
v.push_back(40);               // 若发生扩容
std::cout << *it;              // 使用旧迭代器
```

**24.**
```cpp
std::vector<int> v{1, 2, 3, 4};
v.erase(v.begin() + 1);
for (int x : v) std::cout << x << " ";
```

**25.**
```cpp
std::vector<int> v{1, 2, 3};
std::cout << v.size() << " " << v.max_size() > 0;   // 注意运算符优先级
```

> [!success]- 参考答案（第三节）
> 19. 输出 `1 0 1`。`reserve` 后仍为空（size=0、empty=1），但 capacity 已 ≥ 20。
> 20. 输出 `1 2 4 8 16`。libstdc++ 2 倍增长：容量在 1→2→4→8→16 处各跳一次（size 达 9 时 capacity 已到 16）。MSVC（1.5 倍）序列不同。
> 21. 输出 `3 1`。`resize(3)` 把 size 降到 3、析构后两个元素，但 **capacity 仍 ≥ 5 不变**，故 `capacity()>=5` 为真（1）。
> 22. 输出 `0 5`。`resize(5)` 新增的元素做**值初始化**，`int` 被初始化为 0，故 `v[3]==0`，size=5。
> 23. **未定义行为**。若 `push_back(40)` 触发扩容，`it` 指向的旧内存已被释放，解引用是悬空访问。正确做法：push 后重新 `it = v.begin()`。
> 24. 输出 `1 3 4 `。删掉下标 1 的元素（值 2），其后元素前移。
> 25. **陷阱**：`<<` 优先级高于 `>`，等价于 `(std::cout << v.size() << " " << v.max_size()) > 0`,即先打印 `3` 和一个很大的 max_size 值，再把 `ostream>0` —— 现代标准下 `ostream` 无到 bool 的隐式转换用于 `>`，**编译错误**。教训：比较要加括号。

## 四、找错与修复（指出 bug 并改正）

**26.**
```cpp
std::vector<int> v{1, 2, 3, 4, 5, 6};
for (auto it = v.begin(); it != v.end(); ++it)
    if (*it % 2 == 0) v.erase(it);      // 删除所有偶数
```

**27.**
```cpp
std::vector<int> v;
for (int i = 0; i < 100; ++i)
    v[i] = i;                            // 填入 0..99
```

**28.**
```cpp
std::vector<int> build() {
    std::vector<int> v{1, 2, 3};
    auto it = v.begin();
    v.reserve(1000);                     // 预留
    return *it;                          // 想返回首元素
}
```

**29.**
```cpp
// 在所有奇数前插入一个"比它小 1 的偶数"
std::vector<int> v{1, 3, 5};
for (auto it = v.begin(); it != v.end(); ++it)
    if (*it % 2) v.insert(it, *it - 1);  // 插入后继续用 it
```

**30.**
```cpp
// C 风格：手动 malloc 一段 int，填值后返回，调用方负责 free
int* makeBuf(int n) {
    int* p = (int*)malloc(n * sizeof(int));
    for (int i = 0; i < n; i++) p[i] = i;
    return p;
}
```
要求：用 Modern C++ 重写，杜绝裸内存管理。

**31.**
```cpp
std::vector<int> v{5, 3, 8, 1};
int& r = v[0];
for (int i = 0; i < 1000; ++i) v.push_back(i);
std::cout << r;                          // 打印原首元素
```

> [!success]- 参考答案（第四节）
> 26. **迭代器失效**：`erase(it)` 使 `it` 及其后失效，`++it` 越过或悬空 → UB，还漏删相邻偶数。修复：用 erase 返回值
> ```cpp
> for (auto it = v.begin(); it != v.end(); )
>     if (*it % 2 == 0) it = v.erase(it); else ++it;
> // 或 C++20：std::erase_if(v, [](int x){ return x % 2 == 0; });
> ```
> 27. **越界/UB**：空 vector 未分配内存，`v[i]` 越界写。修复：`std::vector<int> v(100);`（或 `resize(100)`）再下标赋值，或用 `push_back`/`v.reserve(100)`+`push_back`。也可 `std::vector<int> v(100); std::iota(v.begin(), v.end(), 0);`。
> 28. **两个 bug**：① `reserve(1000)` 触发重新分配，`it` 悬空；② 返回类型是 `vector<int>` 却 `return *it`（`int`）类型不符。修复：去掉多余 reserve，或在 reserve 后重新取迭代器；若想返回首元素应把返回类型改 `int` 并 `return v.front();`。
> 29. **插入使迭代器失效**：`insert` 可能扩容使 `it` 失效，且插入后不跳过新元素会**死循环**。修复：用返回值并前移
> ```cpp
> for (auto it = v.begin(); it != v.end(); ++it) {
>     if (*it % 2) { it = v.insert(it, *it - 1); ++it; }  // it 指向新偶数，++ 跳回原奇数
> }
> ```
> 30. **Modern C++ 重写**：返回值容器，RVO/移动，调用方无需 free。
> ```cpp
> #include <vector>
> #include <numeric>
> std::vector<int> makeBuf(int n) {
>     std::vector<int> v(n);
>     std::iota(v.begin(), v.end(), 0);   // 0,1,2,...
>     return v;
> }
> ```
> 31. **悬空引用**：多次 `push_back` 必然扩容，`r` 绑定的旧内存被释放，`std::cout << r` 是悬空访问 UB。教训：**保存到 vector 元素的引用/指针/迭代器在扩容后全部失效**；需要长期持有就存下标或先 `reserve` 足够容量。

## 五、简答题

**32.** 用一句话说清 `size` 与 `capacity` 的区别，并说明为什么需要 capacity 这个概念。

**33.** vector 为什么用"成倍扩容"而不是"每次 +1"？

**34.** `reserve` 和 `resize` 有什么区别？各自适用什么场景？

**35.** vector 内部三个指针 `_first`/`_last`/`_end` 各指向哪里？`size()`/`capacity()` 如何用它们表示？

**36.** 什么情况下 vector 的迭代器/指针/引用会失效？分插入和删除两种情况说。

**37.** 遍历中删除满足条件的元素，正确写法是什么？为什么不能 `for(...;++it) if(cond) v.erase(it);`？

> [!success]- 参考答案（第五节）
> 32. `size` 是"现在装了几个元素"，`capacity` 是"不重新分配内存最多能装几个"。有了 capacity（预留空间），连续 `push_back` 才能大多数是 O(1)，不必每次都搬家。
> 33. 成倍扩容让扩容次数随元素数呈**对数级**减少，n 次 push_back 的总搬迁代价是 O(n)，**均摊 O(1)**；每次 +1 则每次都搬，总代价 O(n²)。
> 34. `reserve(n)` 只增大 capacity、不改 size、不构造元素，适合"已知大概要装多少，先预留避免多次扩容"；`resize(n)` 改变 size、会构造/析构元素，适合"就是要 n 个元素好用下标访问"。
> 35. `_first` 指数组起点，`_last` 指最后一个有效元素的**后一个**位置，`_end` 指分配空间的**后一个**位置。`size() = _last - _first`，`capacity() = _end - _first`。
> 36. **插入**（push_back/insert/emplace）：若触发扩容，所有迭代器/指针/引用失效；若不扩容，插入点及其后失效。**删除**（erase/pop_back）：被删元素及其后的失效。经验：任何可能改变 size 的操作后，别再用旧迭代器/引用。
> 37. 正确：`for(auto it=v.begin(); it!=v.end();) if(cond) it=v.erase(it); else ++it;`（或 C++20 `std::erase_if`）。因为 `erase(it)` 使 `it` 失效，再 `++it` 是对失效迭代器操作 → UB，还会漏删。

## 六、综合设计与手写代码

**38.** 实现一个函数 `void removeEvens(std::vector<int>& v)`，删除所有偶数，要求安全处理迭代器（给出两种写法：经典循环 + C++20）。

**39.** 实现 `std::vector<int> readN(int n)`：读入（这里用 `i*i` 模拟）n 个数存进 vector 并返回，要求**避免中途扩容**。

**40.**（Modern C++ 重构）把下面这段代码改成 Modern C++：
```cpp
int* arr = new int[n];
for (int i = 0; i < n; i++) arr[i] = i * 2;
process(arr, n);
delete[] arr;
```

**41.** 写一个"真正释放 vector 多余内存"的函数 `void trim(std::vector<int>& v)`，并说明为什么单靠 `clear()` 不行。

> [!success]- 参考答案（第六节）
> **38.**
> ```cpp
> void removeEvens(std::vector<int>& v) {
>     for (auto it = v.begin(); it != v.end(); )
>         if (*it % 2 == 0) it = v.erase(it); else ++it;
> }
> // C++20：
> void removeEvens20(std::vector<int>& v) { std::erase_if(v, [](int x){ return x % 2 == 0; }); }
> ```
> 要点：erase 返回下一个有效迭代器；`erase_if` 内部是 erase-remove 惯用法，一趟 O(n)。
> **39.**
> ```cpp
> std::vector<int> readN(int n) {
>     std::vector<int> v;
>     v.reserve(n);                       // 一次预留，杜绝中途扩容
>     for (int i = 0; i < n; ++i) v.push_back(i * i);
>     return v;                           // RVO / 移动
> }
> ```
> **40.**
> ```cpp
> std::vector<int> arr(n);
> for (int i = 0; i < n; ++i) arr[i] = i * 2;   // 或 std::generate
> process(arr.data(), static_cast<int>(arr.size()));  // 若 process 要 int*+长度
> // 无需 delete，作用域结束自动释放
> ```
> 要点：`vector` 管理生命周期（RAII），`data()` 提供连续缓冲区首地址兼容 C 接口。
> **41.**
> ```cpp
> void trim(std::vector<int>& v) { v.shrink_to_fit(); }
> // 更强保证（不依赖实现是否响应 shrink_to_fit）：
> void trimStrong(std::vector<int>& v) { std::vector<int>(v).swap(v); }
> ```
> `clear()` 只把 size 清零、析构元素，**capacity 不变**、内存不还；要收缩容量需 `shrink_to_fit`（非强制）或 `swap` 一个刚好合身的临时副本。

## 七、简答深化题

**42.** 详细解释"均摊 O(1)"：为什么单次最坏是 O(n)，但平均是 O(1)？给出累计代价的估算。

**43.** 扩容时元素是被**拷贝**还是**移动**到新内存？这和元素类型的移动构造 `noexcept` 有什么关系？（串联移动语义章）

**44.** `emplace_back` 一定优于 `push_back` 吗？举一个 `emplace_back` 反而有坑的例子。

**45.** vector 保证元素内存连续，这个"连续性"在哪些场景下是刚需？扩容会怎样破坏依赖它的指针？

**46.**（跨章综合）结合 [[1.3 进程的虚拟地址空间|虚拟地址空间]]：一个局部 `std::vector<int> v` 的"三指针对象本身"和"它管理的元素数组"分别位于进程内存的哪个区域？

**47.** 为什么说"持有 vector 元素的引用/指针/迭代器"是危险的？工程上有哪些替代持有方式？

> [!success]- 参考答案（第七节）
> 42. 设倍增因子 2、从容量 1 起。插入第 1、2、4、8…、2^k 个元素时各搬 1、2、4…2^(k-1) 次，累计搬迁 ≈ 2n。故 n 次 push_back 总代价 O(n)，**每次均摊 O(1)**。单次落在扩容点时要搬全部旧元素，是 O(n)。
> 43. 优先**移动**，但有前提：只有当元素的移动构造是 `noexcept`（或类型不可拷贝）时，vector 扩容才用移动，否则为保证**强异常安全**会退回**拷贝**。所以自定义类型务必给移动构造/赋值加 `noexcept`,否则扩容悄悄变慢。
> 44. 不一定。当实参已是构造好的右值对象时二者等价。坑例：`v.emplace_back(10)` 对 `vector<std::vector<int>>` 会调用 `vector(size_t)` 构造出**10 个 0**的子 vector，而 `push_back({10})` 得到的是**含一个 10** 的子 vector——emplace 直接透传参数，语义可能出乎意料。
> 45. 刚需场景：传给 C API（`int*`+len）、`memcpy` 批量拷贝、SIMD/缓存友好遍历、`data()` 给 GPU/IO。扩容会重新分配并搬迁，之前 `data()`/`&v[i]` 得到的指针全部悬空——必须扩容后重新取。
> 46. 局部 `v` 这个对象（含三个指针，约 24 字节）在**栈**上；它 `new`/allocator 出来的**元素数组在堆**上。所以 vector 是"栈上小对象 + 堆上大数组"的组合，这也是它可移动且开销小的原因。
> 47. 因为任何扩容/插入/删除都可能使它们失效，留下悬空访问的 UB。替代：持有**下标**（不受扩容影响，只要不删前面的元素）、持有容器本身 + 索引、或改用 `std::deque`/`std::list`（元素地址稳定）等地址稳定的容器。

## 八、概念辨析进阶

**48.** 辨析 `reserve` / `resize` / `shrink_to_fit`。

**49.** 辨析 `size()` / `capacity()` / `max_size()`。

**50.** 辨析 `push_back` / `emplace_back` / `insert`。

**51.** 辨析 `clear()` / `erase(begin,end)` / `= {}` / `swap 空容器` 对 size 和 capacity 的影响。

**52.** 辨析 `operator[]` / `at()` / `front()` / `data()` 的越界与安全性。

> [!success]- 参考答案（第八节）
> 48. `reserve(n)`：只增 capacity；`resize(n)`：改 size（构造/析构元素）；`shrink_to_fit()`：请求收缩 capacity 到接近 size（非强制）。口诀：**reserve 管容量、resize 管个数、shrink 还内存**。
> 49. `size` 现有元素数；`capacity` 当前不扩容能装多少；`max_size` 理论上限（受 allocator/地址空间限制，极大，实际用不到）。
> 50. `push_back` 末尾加一个已有对象（拷贝/移动）；`emplace_back` 末尾用参数原地构造；`insert(pos,...)` 任意位置插入（O(n) 搬移）。末尾加元素优先 emplace/push_back，中间插入才用 insert。
> 51. `clear()`/`erase(begin,end)`/`= {}` 都把 size 归零但 **capacity 通常不变**；只有 `std::vector<int>().swap(v)`（和空容器交换）能同时把 capacity 也清零、释放内存。
> 52. `operator[]` 不查越界（UB，最快）；`at()` 查越界抛异常；`front()`/`back()` 对**空容器**调用是 UB；`data()` 返回连续首地址，空容器时不应解引用。口诀：**性能用 `[]`、安全用 `at`、空容器都别碰 front/back/data**。

## 九、大厂面试场景题 / 八股常考

**53.** 面试官：往一个 vector 里 `push_back` 一亿次，性能瓶颈在哪？怎么优化？

**54.** 面试官：我保存了 `int* p = &v[0]`，之后往 v 里加了很多元素，再用 `*p` 就崩了/读到脏数据，为什么？

**55.** 面试官：`std::vector<MyClass>` 扩容很慢，怎么排查和优化？

**56.** 面试官：为什么 `std::vector<bool>` 被称为"STL 的败笔"？该用什么替代？

**57.** 面试官：如何在不改变元素顺序的前提下，一趟删除 vector 中所有等于某值的元素？说说 erase-remove 惯用法。

**58.** 面试官：`v.clear()` 之后内存还占着，怎么真正把内存还给系统？生产中要注意什么？

> [!success]- 参考答案（第九节）
> 53. **现象**：大量 push_back 慢。**原因**：反复扩容（每次搬迁全部旧元素）+ 可能的 malloc。**解决**：已知规模先 `reserve(1e8)` 一次到位；元素是重对象时给移动构造加 `noexcept`；必要时改用 `deque` 避免大块连续内存搬迁。**延伸**：reserve 后 capacity 单调，避免了 log n 次搬家。
> 54. **现象**：`*p` 悬空。**原因**：`push_back` 触发扩容 → 重新分配 + 搬迁 → 旧数组释放，`p` 指向已释放内存。**解决**：不要长期持有元素地址；需要则存下标，或先 `reserve` 足够容量保证不扩容。**延伸**:引用、迭代器同理都会失效。
> 55. **现象**：扩容慢。**原因**：MyClass 移动构造不是 `noexcept`,vector 为强异常安全退回**拷贝**搬迁。**解决**：给 MyClass 加 `noexcept` 的移动构造/赋值；或存 `vector<std::unique_ptr<MyClass>>`/`vector<MyClass*>` 让搬的只是指针。**延伸**：`std::is_nothrow_move_constructible` 可自测。
> 56. **现象/原因**：`vector<bool>` 是按位压缩的**特化**，`operator[]` 返回代理对象不是 `bool&`，不能取 `bool*`、不满足普通容器语义，泛型代码里常出坑。**替代**：`std::vector<char>`、`std::array<bool,N>`、`std::bitset`（大小固定、需要位运算时）。
> 57. `v.erase(std::remove(v.begin(), v.end(), val), v.end());`。`remove` 把不等于 val 的元素**稳定前移**并返回新逻辑尾，`erase` 再一次性删尾部残留。整体一趟 O(n)、只搬移不逐个删。C++20 可直接 `std::erase(v, val)`。
> 58. `std::vector<T>().swap(v);` 或 `v.shrink_to_fit()`（clear 后）。**注意**：`clear()` 只清 size 不还 capacity；频繁 clear+复用其实是想**保留** capacity 复用内存（快），真要还内存才 shrink/swap。生产中权衡"复用内存的速度"与"及时归还的占用"。

## 十、补充加分题

**59.**（复杂度分析）分别给出 vector 的 `push_back`、`insert(begin)`、`erase(begin)`、`operator[]`、`pop_back` 的时间复杂度，并说明缓存局部性对遍历性能的影响。

**60.** libstdc++（2 倍）与 MSVC（1.5 倍）扩容因子各有什么权衡？为什么 1.5 倍在"复用被释放内存"上理论上更优？

**61.** 手写一个极简 `MyVector<int>`,实现 `push_back`（含倍增扩容）、`operator[]`、`size`、`capacity`,用三指针模型，元素搬迁优先移动。

**62.** `std::move(v)` 之后源 vector 处于什么状态？还能安全使用吗？`v.clear()` 后能继续 push_back 吗？

> [!success]- 参考答案（第十节）
> 59. `push_back` 均摊 O(1)；`insert(begin)`/`erase(begin)` O(n)（要搬移后续元素）；`operator[]`/`pop_back` O(1)。vector 连续内存**缓存局部性极好**，顺序遍历比 list 快数倍——即使复杂度相同，常数差距巨大。
> 60. 2 倍：扩容次数更少但内存峰值更高，且每次新容量 > 之前所有已释放容量之和，**无法复用**前面释放的块。1.5 倍：增长慢些、扩容更频繁，但增长率 < 2 使得若干次扩容后新申请量可能 ≤ 之前释放的总量，**理论上更利于分配器复用旧内存**、峰值更低。是"时间 vs 空间"的权衡。
> 61.
> ```cpp
> template <class T>
> class MyVector {
>     T* first_ = nullptr; T* last_ = nullptr; T* end_ = nullptr;
> public:
>     std::size_t size() const { return last_ - first_; }
>     std::size_t capacity() const { return end_ - first_; }
>     T& operator[](std::size_t i) { return first_[i]; }
>     void push_back(const T& x) {
>         if (last_ == end_) grow();
>         *last_++ = x;
>     }
> private:
>     void grow() {
>         std::size_t cap = capacity() ? capacity() * 2 : 1;
>         T* nf = static_cast<T*>(::operator new(cap * sizeof(T)));
>         std::size_t n = size();
>         for (std::size_t i = 0; i < n; ++i) new (nf + i) T(std::move(first_[i]));
>         // 省略：析构旧元素、释放旧内存（教学简化）
>         first_ = nf; last_ = nf + n; end_ = nf + cap;
>     }
> };
> ```
> 要点：三指针 + 倍增 + 搬迁用 `std::move`；工业实现还要处理异常安全、allocator、`noexcept` 判定。
> 62. 被 move 后源 vector 处于**有效但未指定**状态（通常为空）；**不能假设其内容**，但可以安全地重新赋值、`clear()`、`push_back`。`clear()` 只清空元素，容器仍完全可用，可继续 `push_back`（还可能复用原 capacity）。

## 十一、STL 专项（迭代器失效 / 容器选型 / 复杂度）

**63.**（迭代器失效）下面代码想在遍历中给每个奇数后面插一个 0，指出问题并给正确写法。
```cpp
std::vector<int> v{1, 2, 3};
for (auto it = v.begin(); it != v.end(); ++it)
    if (*it % 2) it = v.insert(it + 1, 0);
```

**64.**（容器选型）以下需求分别应选 `vector` / `list` / `deque` / `set` / `unordered_map` 中的哪个，简述理由：
（a）频繁在**头部**插入删除；（b）需要**随机下标**访问且尾部追加为主；（c）需要元素**始终有序去重**；（d）需要 **O(1) 键值查找**；（e）持有元素的**指针要长期稳定**不能失效。

**65.**（复杂度）在有序 vector 上用 `std::lower_bound` 查找是 O(?)；在 list 上对同一算法是 O(?)？为什么？

**66.**（迭代器失效对照）填表：对 vector，下列操作后哪些迭代器失效——`push_back`（扩容 / 不扩容）、`insert(mid)`、`erase(mid)`、`pop_back`、`clear`。

**67.**（选型 + 复杂度综合）要维护一个"最近 N 条日志"的滑动窗口，频繁在尾部加、头部删，且偶尔按下标读中间某条。vector 和 deque 各自开销如何？你选哪个？

> [!success]- 参考答案（第十一节）
> 63. `insert` 可能扩容使 `it` 失效；且 `it = v.insert(...)` 后 `it` 指向新插入的 0，`++it` 到原奇数之后，逻辑还算能走，但若扩容则 `it+1` 已基于失效迭代器计算 → UB。稳妥写法用**下标**避免迭代器失效：
> ```cpp
> for (std::size_t i = 0; i < v.size(); ++i)
>     if (v[i] % 2) { v.insert(v.begin() + i + 1, 0); ++i; }  // 跳过新插入的 0
> ```
> 64. （a）`list` 或 `deque`（头部 O(1)；deque 还支持下标）；（b）`vector`（下标 O(1)、尾部均摊 O(1)）；（c）`set`（自动有序去重）；（d）`unordered_map`（均摊 O(1) 查找）；（e）`list` 或 `deque`（元素地址稳定，插入不使其他元素失效）——vector 扩容会全失效，不适合。
> 65. vector 上 O(log n)：连续内存支持随机访问迭代器，二分能真正跳转。list 上退化为 O(n)：list 是双向迭代器，`lower_bound` 虽仍做"对数次比较"，但每次前进要线性走，总移动 O(n)。这说明**算法复杂度依赖迭代器类别**。
> 66.
> | 操作 | 失效范围 |
> |---|---|
> | push_back 扩容 | 所有迭代器/指针/引用 |
> | push_back 不扩容 | 仅原 `end()`（其余有效） |
> | insert(mid) | 插入点及其后（扩容则全部） |
> | erase(mid) | 被删元素及其后 |
> | pop_back | 被删元素（末元素）与 `end()` |
> | clear | 全部（size→0） |
> 67. vector 头部删是 O(n)（要整体前移），不适合频繁头删；deque 两端插删都是 O(1) 且支持 O(1) 下标随机访问，正是"两端操作 + 偶尔下标读"的理想选择。**选 deque**。若只追尾不头删，才用 vector。

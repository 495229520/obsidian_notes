# 43. 字符串相乘

给定两个用字符串表示的非负整数 `num1` 和 `num2`，要求在**不使用任何内置大整数库、也不能直接把字符串转成整数**的前提下，返回它们乘积的字符串形式。这是「高精度乘法」中**大数 × 大数**的标准题型。

---

## 1. 题目概览

### 1.1 题目描述

`num1` 和 `num2` 都是只含数字 `0-9` 的字符串，长度可能很大（远超 `long long` 范围），因此必须像竖式乘法一样**逐位相乘并处理进位**，全程用字符串/数组模拟。

### 1.2 输入输出与约束

| 项目 | 内容 |
|------|------|
| 输入 | 字符串 `num1`、`num2` |
| 输出 | 表示二者乘积的字符串 |
| 长度 | `1 <= num1.length, num2.length <= 200` |
| 字符范围 | 仅含 `0-9` |
| 前导零 | 除数字 `0` 本身外，**不含前导零** |
| 限制 | 不能把输入直接转为整数，也不能使用内置大整数库 |

> [!important]
> 两个长度各为 `200` 的数相乘，结果最多有 `400` 位，远超 64 位整数范围，所以**只能用数组模拟**。

### 1.3 示例

```text
输入：num1 = "2", num2 = "3"
输出："6"
```

```text
输入：num1 = "123", num2 = "456"
输出："56088"
```

```text
输入：num1 = "0", num2 = "123"
输出："0"
```

---

## 2. 高精度乘法简介

> [!note]
> 本题对应的通用高精度加 / 减 / 乘 / 除模板出处见 [[5.2.3 高精度]]。

### 2.1 与「大数 × 小数」的区别

[[5.2.3 高精度]] 中的乘法模板是 **大数 × 小整数**（把整个大数乘以一个 `int`）。而本题是 **大数 × 大数**，两个乘数都可能很长，套不上那个模板，需要换一种「按位错位相乘 + 累加」的思路——也就是手算竖式的数组化实现。

### 2.2 核心思想

把结果放进一个长度为 `n + m` 的数组 `res`（`n`、`m` 为两数长度），**按正常顺序存放**（高位在前，全部初始化为 `0`）。关键在于一条位置映射规律：

> [!important]
> `num1[i]` 与 `num2[j]` 的乘积是个**两位数**，它恰好落在结果的两个**相邻位置**：
> - 个位写入 `res[i + j + 1]`
> - 十位（进位）累加到 `res[i + j]`

### 2.3 为什么是 `i + j` 和 `i + j + 1`

按字符串下标，`num1[i]` 的位权是 `10^(n-1-i)`，`num2[j]` 的位权是 `10^(m-1-j)`，二者乘积的位权为：

```text
10^(n-1-i) × 10^(m-1-j) = 10^(n+m-2-i-j)
```

而长度为 `n+m` 的数组里，下标 `k` 代表位权 `10^(n+m-1-k)`。令 `n+m-1-k = n+m-2-i-j`，解得 **`k = i + j + 1`**（存乘积个位），其上一位 `k = i + j` 则用来接收进位。

> [!tip]
> 判断信号：输入是两个数字字符串、长度上限较大（如 `200`、`10^4`），要求做乘法 —— 套「大数 × 大数」的下标错位累加。

## 3. 解题思路

### 3.1 步骤分解

1. **特判 0**：若任一乘数是 `"0"`，乘积必为 `"0"`，直接返回，避免最后输出 `"000"` 之类。
2. **开数组**：`vector<int> res(n + m, 0)`，长度取上界 `n + m`。
3. **双层循环**：`i` 从 `n-1`、`j` 从 `m-1` 倒着遍历每一对数字。
   - `mul = (num1[i]-'0') * (num2[j]-'0')`；
   - `sum = mul + res[i+j+1]`（**先加上该位已累计的值**）；
   - `res[i+j+1] = sum % 10`（写回个位）；
   - `res[i+j] += sum / 10`（进位累加到高一位）。
4. **跳过前导零**：从下标 `0` 起跳过开头连续的 `0`（最高位可能没用上而留 `0`）。
5. **拼接结果**：把剩余每一位 `+ '0'` 转成字符接到答案字符串。

> [!tip]
> 第 3 步里 `sum = mul + res[i+j+1]` 的「先累加再取模进位」是精髓：同一个 `res[k]` 会被多对 `(i,j)` 写到，把旧值一起算进去就能把所有部分积自然叠加，无需单独再做一遍竖式求和。

### 3.2 图解

以 `num1 = "12"`、`num2 = "34"` 为例（结果 `408`，包含一次进位与前导零，覆盖关键点）：

![[图片/5.算法/5.3 力扣/5.3.3 高精度/5_1_43_1.svg|860]]

数组 `res` 初始为 `[0,0,0,0]`，四对乘积依次累加：`2×4` 落到 `res[3]`，`2×3` 落到 `res[2]`，`1×4` 再落到 `res[2]`（此时 `4+6=10` 产生进位，`res[2]=0`、`res[1]+=1`），`1×3` 落到 `res[1]`。最终 `res = [0,4,0,8]`，跳过开头前导零 `res[0]=0`，拼成 `"408"`——注意中间的 `res[2]=0` 是有效位，必须保留。

### 3.3 示例推演

| 步骤 | (i, j) | a × b | sum = a·b + res[i+j+1] | 写入 / 进位 | res 数组 |
|------|--------|-------|------------------------|-------------|----------|
| 1 | (1,1) | 2×4=8 | 8 + 0 = 8 | res[3]=8，进位 0 | `[0,0,0,8]` |
| 2 | (1,0) | 2×3=6 | 6 + 0 = 6 | res[2]=6，进位 0 | `[0,0,6,8]` |
| 3 | (0,1) | 1×4=4 | 4 + 6 = 10 | res[2]=0，进位 1 | `[0,1,0,8]` |
| 4 | (0,0) | 1×3=3 | 3 + 1 = 4 | res[1]=4，进位 0 | `[0,4,0,8]` |

## 4. 代码实现

```cpp
class Solution {
public:
    string multiply(string num1, string num2) {
        if (num1 == "0" || num2 == "0") return "0";

        int n = num1.size();
        int m = num2.size();

        vector<int> res(n + m, 0);

        for (int i = n - 1; i >= 0; i--) {
            for (int j = m - 1; j >= 0; j--) {
                int a = num1[i] - '0';
                int b = num2[j] - '0';

                int mul = a * b;
                int sum = mul + res[i + j + 1];

                res[i + j + 1] = sum % 10;
                res[i + j] += sum / 10;
            }
        }

        string ans;
        int i = 0;

        while (i < res.size() && res[i] == 0) i++;

        for (; i < res.size(); i++) {
            ans += res[i] + '0';
        }

        return ans.empty() ? "0" : ans;
    }
};
```

### 4.1 代码关键点

| 代码 | 作用 |
|------|------|
| `if (num1 == "0" \|\| num2 == "0") return "0"` | 特判，避免输出多余前导零 |
| `vector<int> res(n + m, 0)` | 结果数组，长度取上界 `n+m` |
| `num1[i] - '0'` | 字符转数字 |
| `sum = mul + res[i + j + 1]` | **先把该位已累计的值加进来**，自动叠加各部分积 |
| `res[i + j + 1] = sum % 10` | 当前位只留个位 |
| `res[i + j] += sum / 10` | 进位累加到高一位（用 `+=` 而非 `=`） |
| `while (... res[i] == 0) i++` | 跳过最高位可能多出的前导零 |
| `ans += res[i] + '0'` | 数字转字符并按高位到低位拼接 |

> [!note]
> 这里 `res` 是**正序存储**（高位在前），所以不像加 / 减法模板那样需要逆序输出，直接从下标 `0` 往后拼即可。

---

## 5. 易错点

1. **忘记特判 0**：若不特判，`"0" × "123"` 会先得到全 `0` 的数组，跳前导零后变成空串。本题用 `ans.empty() ? "0" : ans` 兜底，但开头特判更稳妥。
2. **进位用 `=` 覆盖**：`res[i + j] += sum / 10` 必须是 `+=`，因为同一位会被多对 `(i,j)` 累加，写成 `=` 会丢掉之前的部分积。
3. **下标写反**：个位是 `res[i+j+1]`、进位是 `res[i+j]`，两者不能互换；记住「个位在更低位（下标更大）」。
4. **数组长度不够**：必须开 `n + m` 长度。最高位可能进位到 `res[0]`，少开一位会越界或丢最高位。
5. **误删内部 0**：去前导零只跳**开头**连续的 `0`（`while` 一旦遇到非零就停），中间的 `0`（如本例 `res[2]=0`）是有效数字，不能删。

> [!warning]
> 最常见的两个坑：进位写成 `=` 覆盖、以及把「跳前导零」错写成「删所有 0」。前者丢部分积，后者把 `408` 变成 `48`。

---

## 6. 复杂度

- **时间复杂度**：`O(n × m)` —— 双层循环遍历每一对数字，`n`、`m` 为两字符串长度；末尾拼接只是 `O(n+m)`。
- **空间复杂度**：`O(n + m)` —— 结果数组与答案字符串规模均为 `n+m`。

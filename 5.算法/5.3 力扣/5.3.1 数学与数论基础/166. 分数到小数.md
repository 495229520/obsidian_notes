# 166. 分数到小数

> 给定两个整数 `numerator`（分子）和 `denominator`（分母），返回它们相除的结果，结果用**字符串**表示。
>
> - 如果小数部分是无限循环的，把循环节用括号 `()` 括起来。
> - 例如 `1/2 = "0.5"`，`2/1 = "2"`，`4/333 = "0.(012)"`，`1/6 = "0.1(6)"`。

这题第一眼会让人懵：明明是除法，怎么判断「循环节」？关键是把它还原成小学学过的**竖式除法（长除法）**，再加一个观察：

```text
余数一旦重复，后面的数字就会无限重复。
```

整道题就是围绕这一句话展开的。

## 一、为什么会有循环节

回忆竖式除法 `1 ÷ 6`：
![[图片/5.算法/5.3 力扣/5.3.1 数学与数论基础/ChatGPT Image Jun 2, 2026, 11_06_08 PM.png|246]]

注意每一步都是：**把余数 ×10，再除以分母，得到下一位商，并产生新的余数**。

下一位商完全由「当前余数」决定。所以一旦某个余数**第二次出现**，从那一刻起，后面的商会和上一次一模一样地重复下去——这就是循环节。

`1/6` 里余数 `4` 反复出现，对应的商 `6` 就无限重复，于是结果是 `0.1(6)`。

而如果某次余数变成 `0`（比如 `1/2`），除法就**结束**了，是有限小数。

## 二、整体框架

![[图片/5.算法/5.3 力扣/5.3.1 数学与数论基础/5_166_1.svg|820]]

把一道题拆成三步：

1. **处理符号**：分子分母「一正一负」时结果才是负数。
2. **整数部分**：直接 `a / b`，再算出余数 `a % b`。
3. **小数部分**：模拟竖式，循环「余数 ×10 取商」，并用哈希表记录每个余数出现的位置，用来检测循环节。

## 三、两个隐藏的坑

### 坑 1：符号判断用异或

只有当分子、分母**符号相反**时，结果才为负：

```cpp
if ((a < 0) ^ (b < 0)) {
    ans += "-";
}
```

`^` 是异或：两边一真一假才为真，正好对应「一正一负」。

### 坑 2：`INT_MIN` 取绝对值会溢出

`int` 的范围是 `[-2147483648, 2147483647]`，负数比正数多一个。如果直接对 `INT_MIN`（`-2147483648`）取绝对值，`2147483648` 超出了 `int` 上限，**未定义行为**。

解决办法：先转成 `long long` 再取绝对值。

```cpp
long long a = numerator;   // 先扩成 long long
long long b = denominator;
a = llabs(a);              // 再取绝对值，不会溢出
b = llabs(b);
```

## 四、核心：用哈希表记录余数位置

```cpp
unordered_map<long long, int> mp;   // 余数 -> 它在结果串中的位置
```

模拟竖式的循环体：

```cpp
while (rem != 0) {
    if (mp.count(rem)) {            // 余数重复 => 循环节
        int pos = mp[rem];
        ans.insert(pos, "(");      // 在首次出现处插入 "("
        ans += ")";                // 末尾补 ")"
        break;
    }
    mp[rem] = ans.size();          // 记录：下一位商将写在哪个下标
    rem *= 10;
    ans += to_string(rem / b);     // 商作为下一位小数
    rem %= b;                      // 更新余数
}
```

> [!important] 关键理解
> `mp[rem] = ans.size()` 记录的是「由这个余数算出来的那位数字，将被写在结果串的哪个下标」。
> 所以当余数重复时，`mp[rem]` 恰好指向**循环节的第一个数字**，`(` 插在它前面正好。

## 五、完整代码

```cpp
class Solution {
public:
    string fractionToDecimal(int numerator, int denominator) {
        if (numerator == 0) return "0";

        string ans;

        long long a = numerator;
        long long b = denominator;

        // 符号：一正一负才是负数
        if ((a < 0) ^ (b < 0)) {
            ans += "-";
        }

        // 转正，防止 INT_MIN 取绝对值溢出
        a = llabs(a);
        b = llabs(b);

        // 整数部分
        ans += to_string(a / b);

        // 余数
        long long rem = a % b;
        if (rem == 0) return ans;   // 整除，直接返回

        ans += ".";

        // 余数 -> 它对应的小数位在 ans 中的下标
        unordered_map<long long, int> mp;

        while (rem != 0) {
            if (mp.count(rem)) {        // 余数重复，找到循环节
                int pos = mp[rem];
                ans.insert(pos, "(");
                ans += ")";
                break;
            }
            mp[rem] = ans.size();       // 记录当前余数的位置
            rem *= 10;
            ans += to_string(rem / b);  // 取下一位商
            rem %= b;                   // 更新余数
        }

        return ans;
    }
};
```

## 六、过程详解：以 `1 / 6` 为例

![[图片/5.算法/5.3 力扣/5.3.1 数学与数论基础/5_166_2.svg|860]]

逐步追踪（起点 `ans = "0."`，长度为 2，余数 `rem = 1`）：

| 轮次 | rem | 见过? | 记录 / 操作 | 商 = rem×10 / 6 | ans | 新 rem |
|---|---:|---|---|---|---|---:|
| 轮 1 | 1 | 否 | `mp[1] = 2` | `10 / 6 = 1` | `"0.1"` | 4 |
| 轮 2 | 4 | 否 | `mp[4] = 3` | `40 / 6 = 6` | `"0.16"` | 4 |
| 轮 3 | 4 | **是! pos=3** | 在下标 3 插 `(`，末尾补 `)` | — | `"0.1(6)"` | 停止 |

第三轮余数又是 `4`，在 `mp` 里查到它第一次出现时记录的位置 `3`（也就是数字 `6` 所在处），于是在下标 `3` 插入 `(`，末尾补 `)`，得到 `0.1(6)`。

> 再看 `4 / 333`：余数依次是 `4 → 40 → 67 → 4`，第四次余数 `4` 重复，循环节从第一位小数开始，结果是 `0.(012)`。

## 七、容易写错的地方

### 1. 忘记特判 `numerator == 0`

如果不特判，`0` 会带上符号或者多出小数点。直接返回 `"0"` 最干净。

### 2. 用 `int` 存余数和分母

`rem *= 10` 在 `int` 下可能溢出。本题统一用 `long long` 存 `a / b / rem`，一劳永逸。

### 3. 哈希表记录的是「商之前」还是「商之后」的位置

必须**先记录 `mp[rem] = ans.size()`，再追加商**。顺序写反，插入 `(` 的位置就会偏移一位。

### 4. 漏掉整除的提前返回

`rem == 0` 时若不 `return`，会多写一个孤零零的小数点 `.`。

## 八、复杂度

```text
时间复杂度：O(b)  （b 为分母绝对值）
```

不同的余数最多只有 `b - 1` 种（余数范围 `1 ~ b-1`），每种最多出现一次就会触发循环检测，所以循环次数被 `b` 限制。

```text
空间复杂度：O(b)
```

哈希表最多存 `b - 1` 个不同的余数。

## 九、总结

这题的「数学翻译」是：

```text
小数除法 = 不断「余数 ×10 再除」的竖式过程
余数重复 = 循环节出现
```

三步走：**定符号 → 取整数 → 模拟竖式（哈希表记位置）**。再处理好 `INT_MIN` 溢出和 `numerator == 0` 两个边界，整题就稳了。

```cpp
mp[rem] = ans.size();   // 记位置
ans += to_string(rem / b);
rem %= b;               // 余数重复 => 在记录处括起循环节
```

## 说说

166. 分数到小数 ✅

完全没思路的根源，是没把它和「小学竖式除法」联系起来。一旦想到「下一位商只由当前余数决定」，循环节判定就变成了「余数有没有重复出现」，用一个哈希表 `余数 → 位置` 就解决了。

中等题里很典型的一类：算法不难，难在两个边界——`INT_MIN` 取绝对值溢出（统一升 `long long`）和先记位置再写商的顺序。把这两点踩过一遍，这题就再也不会错了。

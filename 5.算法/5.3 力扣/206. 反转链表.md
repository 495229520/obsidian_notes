# 206. 反转链表给定单链表的头节点 `head`，要求把链表中所有节点的 `next` 指针方向反过来，并返回反转后的新头节点。---## 1. 题目概览### 1.1 题目描述给你单链表的头节点 `head` ，请你反转链表，并返回反转后的链表。反转链表不是交换节点中的值，而是改变节点之间的连接方向：```text1 -> 2 -> 3 -> 4 -> 5```反转后变成：```text5 -> 4 -> 3 -> 2 -> 1```### 1.2 输入输出与约束| 项目 | 内容 ||------|------|| 输入 | 单链表头节点 `head` || 输出 | 反转后的链表头节点 || 节点数量 | `[0, 5000]` || 节点值范围 | `-5000 <= Node.val <= 5000` || 特殊要求 | 需要修改节点指针方向，而不是只交换节点值 |> [!warning]> 空链表 `head = []` 也是合法输入，此时直接返回空链表。### 1.3 示例#### 示例一```text输入：head = [1,2,3,4,5]输出：[5,4,3,2,1]```#### 示例二```text输入：head = [1,2]输出：[2,1]```#### 示例三```text输入：head = []输出：[]```### 1.4 进阶链表可以选用迭代或递归方式完成反转。你能否用两种方法解决这道题？---## 2. 可用算法与数据结构### 2.1 可选解法总览| 方案 | 核心算法 | 核心数据结构 | 是否适合本题 | 原因 ||------|----------|--------------|--------------|------|| 三指针迭代 | 逐个改变 `next` 指向 | 指针变量 | 推荐 | 思路稳定，空间复杂度 `O(1)` || 递归反转 | 先反转后半段，再回溯接回当前节点 | 递归调用栈 | 适合 | 代码短，但需要 `O(n)` 栈空间 || 辅助数组 | 先存节点再反向连接 | 数组 / vector | 不推荐 | 额外空间 `O(n)`，没有必要 |### 2.2 本题采用的算法本题主要采用：**三指针迭代法**。选择它的原因：1. 每个节点只处理一次，时间复杂度是 `O(n)`。2. 只使用常数个指针变量，空间复杂度是 `O(1)`。3. 能清楚控制每一步的 `next` 指向，适合面试手写。递归法也会给出，作为理解链表递归结构的补充。### 2.3 本题使用的数据结构| 数据结构 | 在本题中的作用 | 为什么需要它 ||----------|----------------|--------------|| `ListNode*` 指针 | 访问和修改链表节点 | 单链表只能通过指针连接节点 || `pre` | 已经反转好的部分的头节点 | 当前节点需要指回它 || `head` / `curr` | 当前正在处理的节点 | 控制遍历进度 || `last` / `next` | 当前节点原本的下一个节点 | 防止修改指针后丢失后续链表 |### 2.4 相关 STL / 算法笔记引用- 6.1指针 — 本题核心是修改指针指向- [[5.1.3 list及其与其他结构的区别]] — 辅助理解链表结构与节点连接关系---## 3. 解题步骤### 3.1 核心思路单链表只能顺着 `next` 指针往后走，因此反转时最容易出错的地方是：一旦把当前节点的 `next` 改掉，后面的链表就可能找不到了。所以每处理一个节点，都要先保存它原本的下一个节点，再把当前节点指向前一个节点。迭代过程中维护三个指针：1. `pre`：已经反转好的链表头2. `head`：当前正在处理的节点3. `last`：当前节点原本的下一个节点### 3.2 详细步骤#### 第一步：初始化指针```cppListNode* pre = nullptr;ListNode* last = nullptr;```初始时，还没有任何节点被反转，所以 `pre = nullptr`。#### 第二步：逐个反转节点当 `head != nullptr` 时，持续处理当前节点：```cpplast = head->next;head->next = pre;pre = head;head = last;```四行代码的含义：1. `last = head->next`：保存后继节点2. `head->next = pre`：让当前节点指回前一个节点3. `pre = head`：当前节点成为已反转部分的新头4. `head = last`：继续处理原链表的下一个节点#### 第三步：返回新头节点循环结束时，`head == nullptr`，说明原链表已经全部处理完。此时 `pre` 指向反转后的新头节点：```cppreturn pre;```### 3.3 示例推演以 `head = [1,2,3]` 为例：| 步骤 | 当前节点 | 保存后继 | 反转后局部状态 | `pre` ||------|----------|----------|----------------|-------|| 初始 | `1` | - | `1 -> 2 -> 3` | `nullptr` || 处理 1 | `1` | `2` | `1 -> nullptr` | `1` || 处理 2 | `2` | `3` | `2 -> 1 -> nullptr` | `2` || 处理 3 | `3` | `nullptr` | `3 -> 2 -> 1 -> nullptr` | `3` |最终返回 `pre`，也就是节点 `3`。---## 4. SVG 图解### 4.1 指针变化示意当前笔记没有单独的 SVG 资产，因此用文本流程图展示关键状态。```text原链表：1 -> 2 -> 3 -> nullptr处理 1 后：nullptr <- 1    2 -> 3 -> nullptr          pre   head处理 2 后：nullptr <- 1 <- 2    3 -> nullptr               pre   head处理 3 后：nullptr <- 1 <- 2 <- 3                    prehead = nullptr，返回 pre```### 4.2 关键状态变化1. 每次修改 `head->next` 前，必须先用 `last` 保存后继节点。2. `pre` 始终表示已经反转好的部分。3. `head` 始终表示原链表中尚未处理的当前节点。4. 当 `head` 走到 `nullptr`，整条链表就已经反转完成。---## 5. 源码实现### 5.1 写法一：三指针迭代法```cppclass Solution {public:    ListNode* reverseList(ListNode* head) {        ListNode* pre = nullptr;        ListNode* last = nullptr;        while (head != nullptr) {            last = head->next;            head->next = pre;            pre = head;            head = last;        }        return pre;    }};```### 5.2 写法二：递归法```cppclass Solution {public:    ListNode* reverseList(ListNode* head) {        if (head == nullptr || head->next == nullptr) {            return head;        }        ListNode* newHead = reverseList(head->next);        head->next->next = head;        head->next = nullptr;        return newHead;    }};```### 5.3 代码中的关键注释| 代码位置 | 解释重点 ||----------|----------|| `last = head->next` | 修改指针前先保存后继节点，防止链表断开 || `head->next = pre` | 当前节点指回前一个节点，完成局部反转 || `pre = head` | 扩大已反转部分 || `head = last` | 继续处理原链表剩余节点 || `head->next = nullptr` | 递归法中断开旧指向，避免形成环 |---## 6. 源码详解### 6.1 核心变量说明| 变量 | 含义 | 生命周期 | 为什么需要它 ||------|------|----------|--------------|| `pre` | 已反转部分的新头节点 | 整个迭代过程 | 当前节点反转后要指向它 || `head` | 当前正在处理的节点 | 整个迭代过程 | 控制遍历进度 || `last` | 当前节点原本的后继节点 | 每轮循环更新 | 防止修改 `next` 后丢失剩余链表 || `newHead` | 递归法中反转后的新头 | 每层递归返回后 | 最终答案需要从最深层一路返回 |### 6.2 主流程拆解#### 6.2.1 迭代法为什么返回 `pre`循环结束时：```texthead == nullptr```说明原链表已经没有未处理节点。此时最后一个被处理的节点就是反转后链表的头节点，它保存在 `pre` 中。因此返回：```cppreturn pre;```#### 6.2.2 递归法为什么要写 `head->next->next = head`递归法的核心语义是：> `reverseList(head)` 会反转以 `head` 为头节点的整条链表，并返回反转后的新头。当执行：```cppListNode* newHead = reverseList(head->next);```可以认为 `head` 后面的链表已经反转好了。此时原来的 `head->next` 已经变成反转后链表的尾节点，需要让它指回 `head`：```cpphead->next->next = head;```然后再断开 `head` 原本的指向：```cpphead->next = nullptr;```否则链表会形成环。### 6.3 两种写法对比| 方法 | 思想 | 优点 | 注意点 ||------|------|------|--------|| 三指针迭代 | 用指针逐个改变 `next` 方向 | 空间复杂度低，最常用 | 先保存后继节点 || 递归法 | 先反转后半段，再回溯处理当前节点 | 代码短，适合理解递归 | 注意断开原指向，避免成环 |### 6.4 易错点1. 修改 `head->next` 之前，必须先保存 `head->next`。2. 迭代法最后返回 `pre`，不是 `head`。3. 递归法必须写 `head->next = nullptr`，否则可能形成环。4. 递归出口要覆盖空链表和单节点链表。5. 翻转的是节点之间的指针，不是交换节点中的值。---## 7. 复杂度分析### 7.1 时间复杂度- 时间复杂度：`O(n)`原因：无论迭代法还是递归法，每个节点都只会被处理一次。### 7.2 空间复杂度- 迭代法空间复杂度：`O(1)`- 递归法空间复杂度：`O(n)`原因：迭代法只使用常数个指针；递归法需要递归调用栈，最深可能达到链表长度 `n`。---## 8. 相关链接- 6.1指针 — 本题核心是修改节点指针指向- [[5.1.3 list及其与其他结构的区别]] — 辅助理解链表结构与节点连接关系- [[25.

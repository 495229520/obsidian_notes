# 215. 数组中的第K个最大元素

给定整数数组 `nums` 和整数 `k`，要求返回数组排序后的第 `k` 个最大元素。注意重复元素也参与排名。

---

## 1. 题目概览

### 1.1 题目描述

给定整数数组 `nums` 和整数 `k`，请返回数组中第 `k` 个最大的元素。

请注意，你需要找的是数组排序后的第 `k` 个最大的元素，而不是第 `k` 个不同的元素。

你必须设计并实现时间复杂度为 `O(n)` 的算法解决此问题。

### 1.2 输入输出与约束

| 项目 | 内容 |
|------|------|
| 输入 | 整数数组 `nums` 和整数 `k` |
| 输出 | 数组排序后的第 `k` 个最大元素 |
| 数组长度 | `1 <= k <= nums.length <= 10^5` |
| 元素范围 | `-10^4 <= nums[i] <= 10^4` |
| 特殊说明 | 重复元素正常参与排名，不要求找第 `k` 个不同元素 |

> [!warning]
> 第 `k` 大不是“第 `k` 个不同的数”。例如 `[3,2,3,1]` 中第 2 大是 `3`，不是 `2`。

### 1.3 示例

#### 示例一

```text
输入：nums = [3,2,1,5,6,4], k = 2
输出：5
```

#### 示例二

```text
输入：nums = [3,2,3,1,2,4,5,5,6], k = 4
输出：4
```

## 2. 可用算法与数据结构

### 2.1 可选解法总览

| 方案 | 核心算法 | 核心数据结构 | 是否适合本题 | 原因 |
|------|----------|--------------|--------------|------|
| 完整排序 | 排序后取下标 `n - k` | 原数组 | 可行但不最优 | 时间复杂度 `O(nlogn)`，做了多余排序 |
| `nth_element` | 快速选择思想 | 原数组 + 迭代器 | 推荐 | 平均 `O(n)`，只定位目标排名 |
| 小根堆 | 维护最大的 `k` 个数 | `priority_queue` | 适合 | `O(nlogk)`，适合不能改原数组或数据流 |
| 快速选择手写 | partition | 原数组 | 适合进阶 | 平均 `O(n)`，但边界比 STL 写法复杂 |

### 2.2 本题采用的算法

本题主要采用：**`nth_element` / 快速选择思想**。

选择它的原因：

1. 本题只需要第 `k` 大元素，不需要完整排序。
2. `nth_element` 可以把目标排名的元素放到正确位置，平均时间复杂度是 `O(n)`。
3. 代码短，边界比手写快速选择更安全。

同时给出 **小根堆写法**，用于理解 `priority_queue` 的排名维护思路。

### 2.3 本题使用的数据结构

| 数据结构 | 在本题中的作用 | 为什么需要它 |
|----------|----------------|--------------|
| `vector<int>` | 存储输入数组 | 支持随机访问和 STL 算法 |
| 迭代器 | 指定 `nth_element` 的目标位置 | 定位排序后应该在 `target` 的元素 |
| `priority_queue` | 维护最大的 `k` 个元素 | 堆顶最终就是第 `k` 大元素 |

## 3. 解题步骤

### 3.1 核心思路

如果把数组从小到大排序，第 `k` 大元素对应的下标是：

```cpp
int target = nums.size() - k;
```

例如数组长度为 `6`：

```text
升序下标：0  1  2  3  4  5
排名：    第6大 ... 第3大 第2大 第1大
```

所以第 `k` 大可以转化成：**升序排序后下标为 `n - k` 的元素**。

完整排序能解决问题，但没有必要。因为本题只关心一个位置，而不是整个数组是否有序。

### 3.2 详细步骤

#### 第一步：计算目标下标

```cpp
int target = nums.size() - k;
```

`target` 表示答案在升序排序数组中的位置。

#### 第二步：定位目标排名

使用 `nth_element`：

```cpp
nth_element(nums.begin(), nums.begin() + target, nums.end());
```

它会保证：

1. `nums[target]` 是完整排序后应该放在 `target` 位置的元素
2. 左边元素都不大于它
3. 右边元素都不小于它

但左右两边内部不保证有序。

#### 第三步：返回答案

```cpp
return nums[target];
```

### 3.3 示例推演

以 `nums = [3,2,1,5,6,4]`，`k = 2` 为例：

| 步骤 | 当前状态 | 说明 |
|------|----------|------|
| 1 | `n = 6, k = 2` | 要找第 2 大 |
| 2 | `target = 6 - 2 = 4` | 第 2 大对应升序下标 4 |
| 3 | 升序结果为 `[1,2,3,4,5,6]` | 下标 4 的元素是 `5` |
| 4 | 返回 `5` | 答案为第 2 大元素 |

## 5. 源码实现

### 5.1 写法一：`nth_element`

```cpp
class Solution {
public:
    int findKthLargest(vector<int>& nums, int k) {
        int target = nums.size() - k;
        nth_element(nums.begin(), nums.begin() + target, nums.end());
        return nums[target];
    }
};
```

### 5.2 写法二：小根堆

```cpp
class Solution {
public:
    int findKthLargest(vector<int>& nums, int k) {
        priority_queue<int, vector<int>, greater<int>> heap;

        for (int x : nums) {
            heap.push(x);

            if (heap.size() > k) {
                heap.pop();
            }
        }

        return heap.top();
    }
};
```

### 5.3 代码中的关键注释

| 代码位置 | 解释重点 |
|----------|----------|
| `target = nums.size() - k` | 把第 `k` 大转成升序下标 |
| `nth_element(...)` | 只保证目标位置正确，不完整排序 |
| `priority_queue<int, vector<int>, greater<int>>` | 定义一个小根堆 |
| `heap.size() > k` | 堆中只保留最大的 `k` 个候选值 |
| `heap.top()` | 最大的 `k` 个数中最小的那个，就是第 `k` 大 |

## 6. 源码详解

### 6.1 核心变量说明

| 变量 / 数据结构 | 含义 | 生命周期 | 为什么需要它 |
|-----------------|------|----------|--------------|
| `target` | 第 `k` 大对应的升序下标 | `nth_element` 写法中使用 | 把排名问题转换成下标问题 |
| `nums` | 输入数组 | 整个函数过程 | `nth_element` 会在原数组中重排元素 |
| `heap` | 小根堆 | 小根堆写法中使用 | 维护当前最大的 `k` 个元素 |
| `k` | 目标排名 | 整个函数过程 | 控制目标下标和堆大小 |

### 6.2 `nth_element` 为什么有效

`nth_element(nums.begin(), nums.begin() + target, nums.end())` 执行后，`nums[target]` 一定是完整升序排序后应该位于 `target` 的元素。

它不保证数组完全有序，但本题只要求返回一个元素，所以这已经足够。

> [!warning]
> `nth_element` 会改变 `nums` 中元素的排列顺序。如果后续还需要原数组顺序，需要先拷贝一份再操作。

### 6.3 小根堆为什么有效

小根堆的堆顶是堆中最小的元素。

如果堆中始终只保留当前见过的最大的 `k` 个数，那么堆顶就是这 `k` 个数里最小的，也就是整个数组中的第 `k` 大元素。

遍历每个元素 `x` 时：

1. 先把 `x` 放入堆中
2. 如果堆大小超过 `k`，弹出堆顶
3. 弹出的总是当前候选中最小的那个
4. 最后留下来的就是最大的 `k` 个数

### 6.4 两种方法对比

| 方法 | 时间复杂度 | 空间复杂度 | 是否修改原数组 | 适合场景 |
|------|------------|------------|----------------|----------|
| `nth_element` | 平均 `O(n)` | `O(1)` | 会修改 | 只处理一个数组，追求速度 |
| 小根堆 | `O(nlogk)` | `O(k)` | 不修改 | 数据流、不能改变原数组、`k` 较小 |

### 6.5 易错点

1. 第 `k` 大对应升序下标 `nums.size() - k`，不是 `k - 1`。
2. `nth_element` 只保证目标位置正确，不保证左右两边内部有序。
3. `priority_queue` 默认是大根堆，小根堆需要写 `greater<int>`。
4. 小根堆大小超过 `k` 时要立刻 `pop`，否则堆顶不一定是第 `k` 大。
5. 题目不是找第 `k` 个不同元素，重复值要参与排名。

## 7. 复杂度分析

### 7.1 时间复杂度

- `nth_element` 写法：平均 `O(n)`
- 小根堆写法：`O(nlogk)`

原因：`nth_element` 基于快速选择思想，平均只需要线性时间；小根堆需要遍历 `n` 个元素，每次堆操作代价是 `O(logk)`。

### 7.2 空间复杂度

- `nth_element` 写法：`O(1)`
- 小根堆写法：`O(k)`

原因：`nth_element` 原地重排数组；小根堆最多保存 `k` 个元素。

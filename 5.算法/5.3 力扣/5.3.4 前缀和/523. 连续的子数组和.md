# 523. 连续的子数组和

> 判断数组中是否存在**长度 ≥ 2**、且元素和为 `k` 的倍数的连续子数组。核心是「前缀和取模 + 哈希表」：**两个前缀和对 `k` 同余 ⟺ 它们之间的子数组和是 `k` 的倍数**。

本题是 [[5.2.4 前缀和]] 中「前缀和 + 哈希」模式的代表题，与 [[560. 和为 K 的子数组]]（精确和）、`974. 和可被 K 整除的子数组`（计数版）同源，建议对照学习。

---

## 一、题目分析

### 1.1 题目描述

给定整数数组 `nums` 和整数 `k`，若存在一个**好的子数组**则返回 `true`，否则返回 `false`。「好的子数组」需满足：

- 长度**至少为 2**；
- 元素总和为 `k` 的**倍数**。

> [!note]
> - 子数组是数组中**连续**的一段。
> - `x` 是 `k` 的倍数，当且仅当存在整数 `n` 使 `x = n * k`；**`0` 始终视为 `k` 的倍数**。

### 1.2 输入输出与约束

| 项目 | 内容 |
|------|------|
| 输入 | 整数数组 `nums`、整数 `k` |
| 输出 | `bool`：是否存在长度 ≥ 2 且和为 `k` 倍数的子数组 |
| 数组长度 | `1 <= nums.length <= 10^5` |
| 元素范围 | `0 <= nums[i] <= 10^9` |
| 总和范围 | `0 <= sum(nums[i]) <= 2^31 - 1` |
| `k` 范围 | `1 <= k <= 2^31 - 1` |

> [!important]
> 约束的两个关键暗示：
> 1. **`n` 高达 `10^5`** —— `O(n^2)` 的枚举（约 `10^10`）必然超时，必须做到 `O(n)`。
> 2. **总和 ≤ `2^31 - 1` 且 `nums[i] ≥ 0`** —— 累加和不会超过 `int` 上界、也不会为负，因此本题用 `int sum` 安全，`sum % k` 也恒在 `[0, k-1]`，无需处理负余数（一般题目要写 `((x % k) + k) % k`）。

### 1.3 示例

```text
输入：nums = [23, 2, 4, 6, 7], k = 6
输出：true
解释：子数组 [2, 4] 长度为 2，和为 6 = 1 × 6。
```

```text
输入：nums = [23, 2, 6, 4, 7], k = 6
输出：true
解释：整段 [23, 2, 6, 4, 7] 长度为 5，和为 42 = 7 × 6。
```

```text
输入：nums = [23, 2, 6, 4, 7], k = 13
输出：false
解释：不存在长度 ≥ 2 且和为 13 倍数的子数组。
```

## 二、解法演进：为什么前面的解法会超时

「子数组和」类问题的标准抓手是**前缀和**：定义 `sum[i]` 为前 `i` 个元素之和（`sum[0] = 0`），则区间 `(i, j]`（即下标 `i+1 … j`）的和为：

```text
区间 (i, j] 的和 = sum[j] - sum[i]
```

下面三种解法层层递进。

### 2.1 暴力枚举 —— O(n³) / O(n²)，超时

最朴素的做法是枚举所有起点 `l` 与终点 `r`（`r - l + 1 >= 2`），求出区间和并判断是否为 `k` 的倍数。

- **不预处理前缀和**：每次区间和重新累加，时间 `O(n³)`。
- **预处理前缀和**：区间和用 `sum[r] - sum[l-1]` 在 `O(1)` 求出，但仍要枚举所有 `O(n²)` 个区间对。

```cpp
// O(n^2)：前缀和 + 枚举所有区间对（仅示意，会 TLE）
for (int i = 0; i < n; i++)
    for (int j = i + 2; j <= n; j++)          // 保证长度 >= 2
        if ((sum[j] - sum[i]) % k == 0)
            return true;
```

> [!warning]
> `n = 10^5` 时，`O(n^2) ≈ 10^10` 次运算，远超 1 秒能处理的量级（约 `10^8`），**必然超时**。前缀和只优化了「单次区间求和」，没有减少「区间对」的数量。

### 2.2 关键转化：从「枚举区间对」到「查余数」

把判定条件做一步代数变形，问题的复杂度就能被打穿：

```text
(sum[j] - sum[i]) % k == 0
⟺ sum[j] % k == sum[i] % k          （同余）
```

也就是说，**我们不再需要遍历所有 `i`**，只需在扫描到 `j` 时回答一个问题：

> 「在 `j` 之前，是否出现过一个前缀和，它对 `k` 的余数与 `sum[j]` 相同？」

这正是**哈希表**擅长的「查历史是否出现过某值」。于是每个 `j` 的查询变成 `O(1)`，总复杂度降到 `O(n)`。

### 2.3 三种解法对比

| 解法 | 区间和 | 是否枚举区间对 | 时间复杂度 | n=10⁵ |
|------|--------|----------------|------------|--------|
| 朴素暴力 | 现场累加 | 是 | `O(n³)` | 超时 |
| 前缀和 + 枚举 | `O(1)` 相减 | 是 | `O(n²)` | 超时 |
| **前缀和取模 + 哈希** | 隐式（只存余数） | **否** | **`O(n)`** | **通过** |

## 三、核心数学结论

> [!important] 两条等价结论（务必记牢）
> 1. 若 `(sum[j] - sum[i]) % k == 0`，则区间 `[i+1, j]` 的元素和为 `k` 的倍数。
> 2. 若两个前缀和**对 `k` 取模后结果相同**（同余），则它们之间的区间和**一定是 `k` 的倍数**。

### 3.1 推导

设两个前缀和对 `k` 同余，即 `sum[i] % k == sum[j] % k == r`，按带余除法写成：

```text
sum[i] = q_i · k + r
sum[j] = q_j · k + r
————————————————————————————————
sum[j] - sum[i] = (q_j - q_i) · k      ← 余数 r 相减抵消
```

差是 `k` 的整数倍，而 `sum[j] - sum[i]` 恰好是区间 `(i, j]` 的和，结论成立。反之，若区间和是 `k` 的倍数，则两端前缀和必然同余。两个方向都成立，故为**充要条件**。

### 3.2 几何直觉

把数轴按 `k` 切成等宽的「块」。一个前缀和落在某块内的**偏移**就是它的余数 `r`。当 `sum[i]` 与 `sum[j]` 落在各自块内的**相同偏移**处时，二者之间的距离必然是**整数个块** = `k` 的倍数。

![[图片/5.算法/5.3 力扣/5.3.4 前缀和/lc_523_mod_principle.svg]]

> 以 `sum[i] = 23 = 3·6 + 5`、`sum[j] = 29 = 4·6 + 5` 为例：两者余数都是 `5`，距离恰好 `29 - 23 = 6 = 1 × k`。

## 四、图解过程

### 4.1 前缀和与取模数组的构建

以示例 `nums = [23, 2, 4, 6, 7]`、`k = 6` 为例。逐列累加得到 `sum`，再对 `6` 取模得到余数行 `r`：

![[图片/5.算法/5.3 力扣/5.3.4 前缀和/lc_523_prefix_build.svg]]

| 下标 i | −1(哨兵) | 0 | 1 | 2 | 3 | 4 |
|--------|:--------:|:-:|:-:|:-:|:-:|:-:|
| `nums[i]` | ∅ | 23 | 2 | 4 | 6 | 7 |
| `sum`     | 0  | 23 | 25 | 29 | 35 | 42 |
| `r = sum%6` | 0 | **5** | 1 | **5** | **5** | 0 |

下标 `0` 与 `2` 的余数都是 `5`（最早的 `5` 在下标 `0`），它们之间的区间 `(0, 2]` = `nums[1..2]` = `[2, 4]`，和为 `29 - 23 = 6`，正是 `k` 的倍数。

### 4.2 哈希表记录余数位置的执行过程

`mp` 保存「余数 → 该余数**最早**出现的下标」。扫描 `nums = [23, 2, 4]`：

![[图片/5.算法/5.3 力扣/5.3.4 前缀和/lc_523_hashmap_trace.svg]]

| i | nums[i] | sum | r=sum%6 | 动作 | mp 状态（执行后） |
|:-:|:-------:|:---:|:-------:|------|-------------------|
| — | — | 0 | 0 | 初始化哨兵 `mp[0] = -1` | `{0:-1}` |
| 0 | 23 | 23 | 5 | `5` 不在 mp → 插入 `mp[5]=0` | `{0:-1, 5:0}` |
| 1 | 2 | 25 | 1 | `1` 不在 mp → 插入 `mp[1]=1` | `{0:-1, 5:0, 1:1}` |
| 2 | 4 | 29 | 5 | `5` 已存在 `mp[5]=0`，`i-mp[5]=2≥2` ✓ | **返回 `true`** |

## 五、代码实现（逐行注释）

```cpp
class Solution {
public:
    bool checkSubarraySum(vector<int>& nums, int k) {
        // mp: 余数 r -> 该余数第一次出现时的下标
        unordered_map<int, int> mp;

        // 哨兵：余数 0 对应"空前缀"（什么都不取，和为 0），位置记为 -1。
        // 这样若某个 sum 本身就是 k 的倍数，也能用统一公式算出长度。
        mp[0] = -1;

        int sum = 0;                       // 累计前缀和（本题总和 <= 2^31-1，int 安全）

        for (int i = 0; i < nums.size(); i++) {
            sum += nums[i];                // sum = 前缀和 sum[i+1]
            int r = sum % k;               // 当前前缀和对 k 的余数（nums[i]>=0，r 恒非负）

            if (mp.count(r)) {             // 之前出现过相同余数 => 中间区间和是 k 的倍数
                // i - mp[r] 是子数组长度；要求长度 >= 2 才算"好的子数组"
                if (i - mp[r] >= 2) {
                    return true;
                }
                // 长度不足 2 时：什么都不做，故意"不覆盖" mp[r]，
                // 保留最早下标以维持最大间隔（见 6.2）。
            } else {
                mp[r] = i;                 // 该余数第一次出现，记录下标
            }
        }

        return false;                      // 整段扫描都没找到
    }
};
```

> [!tip] 一句话抓住算法
> 边扫描边维护「余数 → 最早下标」。**当前余数若曾出现过，且与那次的下标间隔 ≥ 2，就找到了答案**。

## 六、关键实现细节

### 6.1 为什么初始化 `mp[0] = -1`

余数 `0` 意味着**该前缀和本身就是 `k` 的倍数**。它对应的子数组是从数组**最开头** `[0, i]` 的整段。

为了让「长度 = 下标之差」这套统一逻辑也覆盖这种整段情形，我们引入一个虚拟的「空前缀」：它什么元素都不取、和为 `0`、余数也是 `0`，把它的位置定义为 `-1`。

于是当某个 `sum[i] % k == 0` 时：

```text
子数组长度 = i - mp[0] = i - (-1) = i + 1   ← 正好是 [0, i] 的长度
```

只要 `i + 1 >= 2`（即 `i >= 1`）就返回 `true`。例如 `nums = [23,2,6,4,7], k = 6`，整段和 `42 = 7×6`，扫到末尾余数为 `0`，靠 `mp[0] = -1` 才能算出长度 `5` 并返回 `true`。

> [!warning]
> 若漏掉 `mp[0] = -1`，「整段恰好是 `k` 倍数」以及「从开头起的前缀就是倍数」这类情况会被漏判。这是本题最隐蔽的边界。

### 6.2 为什么只记录某余数「第一次」出现的位置

对当前下标 `j`，要让长度 `j - i >= 2` **最容易成立**，应让配对的 `i` **尽可能小**——`i` 越小，间隔 `j - i` 越大。

- 某余数**最早**出现的下标，给出与后续任意 `j` 的**最大间隔**。
- 如果连「最早出现」都满足不了长度 ≥ 2，更晚出现的下标（离 `j` 更近、间隔更小）就更不可能满足。

因此哈希表里每个余数**只保留第一次**的下标，绝不用后来的下标覆盖它——这正是代码中「`if (mp.count(r)) {…}` 命中分支里不写入、只有 `else` 分支才 `mp[r] = i`」的原因。

> [!note]
> 对比 [[560. 和为 K 的子数组]]：那道题要**统计个数**，需要累加每个前缀和出现的**次数**；本题只要判断**存在性**且带长度约束，所以只需保留**最早下标**。同一套「前缀和 + 哈希」，因目标不同而存储内容不同。

### 6.3 长度约束如何用「下标之差」表达

`mp` 里存的是**前缀和的下标**（`sum` 累加到第 `i` 个元素后记为下标 `i`）。两次相同余数的下标分别是 `mp[r]` 和 `i`，它们之间的子数组是 `nums[mp[r]+1 .. i]`，元素个数为：

```text
i - (mp[r] + 1) + 1 = i - mp[r]
```

所以 `i - mp[r] >= 2` 即「子数组长度 ≥ 2」。

## 七、复杂度

- **时间复杂度**：`O(n)`。单次遍历，哈希表的插入与查询均摊 `O(1)`。
- **空间复杂度**：`O(min(n, k))`。哈希表存放的是**不同的余数**，余数取值范围是 `[0, k-1]`，且最多记录 `n` 个，故上界为两者较小值。

## 八、对比与变体

| 题目 | 目标 | 哈希表存什么 | 关键差异 |
|------|------|--------------|----------|
| **523. 连续的子数组和** | 是否存在和为 `k` 倍数、长度 ≥ 2 的子数组 | 余数 → **最早下标** | 取模 + 长度约束 |
| [[560. 和为 K 的子数组]] | 和**恰好**为 `k` 的子数组**个数** | 前缀和 → **出现次数** | 精确和，不取模 |
| `974. 和可被 K 整除的子数组` | 和为 `k` 倍数的子数组**个数** | 余数 → **出现次数** | 取模 + 计数（需处理负余数） |
| `525. 连续数组` | 0 和 1 数量相等的**最长**子数组 | 把 0 视作 -1，前缀和 → 最早下标 | 求最长，故也存最早下标 |

> [!tip] 面试考点总结
> 1. **识别信号**：「连续子数组」+「和 / 倍数 / 整除」→ 立刻想到**前缀和**；带「倍数 / 整除」再叠加**取模**。
> 2. **同余转化**：`(sum[j]-sum[i]) % k == 0 ⟺ sum[j]%k == sum[i]%k`，把 `O(n²)` 枚举降到 `O(n)` 查表。
> 3. **哨兵 `mp[0] = -1`** 的作用，以及它如何统一处理「整段就是倍数」。
> 4. **存最早还是存次数 / 最新**：取决于求「存在性 / 最长」（最早）还是「个数」（次数）。
> 5. **负数与溢出**：一般情形前缀和可能为负，余数要写 `((x%k)+k)%k`；累加和可能溢出，应用 `long long`。本题约束恰好规避了这两点。

## 九、易错点

| 易错点 | 说明 |
|--------|------|
| 忘记 `mp[0] = -1` | 漏判「整段 / 从头的前缀本身就是 `k` 的倍数」，最典型的 WA。 |
| 命中时覆盖了 `mp[r]` | 必须保留**最早**下标。覆盖成更晚的下标会缩小间隔，导致本可满足「长度 ≥ 2」的解被漏掉。 |
| 漏掉长度 ≥ 2 约束 | 单个元素恰为 `k` 倍数也不算；务必判 `i - mp[r] >= 2`。 |
| 误把判定写成「次数」 | 本题是**存在性**，存最早下标即可；写成计数是 974 的解法。 |
| 负余数（一般情形） | `nums[i]` 可为负时，`sum % k` 可能为负，需 `((sum%k)+k)%k` 归一化。本题 `nums[i] >= 0` 才可省略。 |
| 累加和溢出（一般情形） | 题目不保证总和 ≤ `2^31-1` 时，`sum` 应用 `long long`，否则溢出导致余数错误。 |

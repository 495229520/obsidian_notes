# 14.18 贪心算法

贪心算法是一类“每一步都做当前看起来最优选择”的算法。它的难点不在代码，而在证明：为什么每一步的局部最优选择，最终一定能得到全局最优解。

---

## 1. 贪心算法概览

### 1.1 什么是贪心算法

贪心算法（Greedy Algorithm）的核心思想是：

> 在每一步选择中，都做出当前状态下最优、最有利、最不吃亏的选择，并希望这些局部最优选择能组合成全局最优解。

例如：

- 区间调度：每次选择结束最早的区间
- 跳跃游戏：每一步维护当前能到达的最远位置
- 分发糖果：先满足左邻居约束，再满足右邻居约束

贪心算法通常代码很短，但证明很重要。

### 1.2 局部最优与全局最优

| 概念 | 含义 |
|------|------|
| 局部最优 | 在当前一步做出的最优选择 |
| 全局最优 | 整个问题最终得到的最优解 |
| 贪心正确性 | 证明局部最优选择不会破坏全局最优解 |

贪心不是“看起来合理就可以”，而是必须能说明：

```text
当前这样选，不会让最终答案变差。
```

### 1.3 贪心与动态规划的区别

| 对比项 | 贪心 | 动态规划 |
|--------|------|----------|
| 决策方式 | 每一步直接做当前最优选择 | 枚举多种选择，取最优状态 |
| 是否回头 | 通常不回头 | 通过状态转移保留历史信息 |
| 证明重点 | 贪心选择性质 | 状态定义与转移正确性 |
| 常见复杂度 | 常为 `O(n)` 或 `O(nlogn)` | 常为 `O(n)`、`O(n^2)` 或更高 |
| 适合问题 | 可证明局部选择不吃亏 | 子问题重叠、需要比较多种选择 |

> [!tip]
> 如果一个问题每一步的选择会影响后续状态，而且无法证明“当前最优一定不吃亏”，就不要轻易用贪心，可能需要动态规划。

---

## 2. 如何判断能不能用贪心

### 2.1 贪心选择性质

贪心选择性质指的是：

> 全局最优解可以通过一系列局部最优选择得到。

也就是说，当前这一步做出的选择，可以安全地成为某个最优解的一部分。

例如区间调度中，选择结束时间最早的区间是安全的，因为它给后面的区间留下了最大的可选空间。

### 2.2 最优子结构

最优子结构指的是：

> 做出当前选择后，剩下的问题仍然是一个同类型的最优化问题。

区间调度中，选了一个区间后，剩下的就是在它结束时间之后继续选最多不重叠区间。

跳跃游戏中，扫描到当前可达范围内的位置后，剩下的问题就是继续扩大可达范围。

### 2.3 反例验证

设计贪心策略时，一定要尝试找反例。

例如区间调度不能按“开始时间最早”选：

```text
[1, 10], [2, 3], [3, 4], [4, 5]
```

如果先选 `[1, 10]`，只能选 1 个区间；但最优解可以选 `[2,3]`、`[3,4]`、`[4,5]`。

也不能按“区间最短”简单选择，因为最短区间可能卡在中间，阻碍两边更多区间。

### 2.4 常见证明角度

| 证明方法 | 核心问题 | 常见场景 |
|----------|----------|----------|
| 交换论证 | 把某个最优解中的选择换成贪心选择，答案不变差 | 区间调度、排序后选择 |
| 反证法 | 假设贪心不正确，推出矛盾 | 单调边界、最远覆盖 |
| 留出更多空间 | 当前选择让后续选择余地最大 | 区间调度 |
| 单调边界 | 维护一个不断扩大的最优边界 | 跳跃游戏 |
| 局部约束合并 | 分别满足局部方向约束，最终合并为全局合法 | 分发糖果 |

## 4. 区间调度

### 4.1 问题模型

给定若干区间 `[start, end]`，要求选择尽可能多的互不重叠区间。

例如：

```text
[1,3], [2,4], [3,5], [0,6], [5,7]
```

希望选出最多个互不冲突的区间。

### 4.2 贪心策略

按区间结束时间从小到大排序。

每次选择：

```text
结束时间最早，并且与上一个已选区间不冲突的区间
```

为什么选结束最早？

因为结束越早，后面剩下的时间越多，能容纳更多区间。

### 4.3 C++ 模板

```cpp
int intervalSchedule(vector<vector<int>>& intervals) {
    if (intervals.empty()) return 0;

    sort(intervals.begin(), intervals.end(),
        [](const vector<int>& a, const vector<int>& b) {
            return a[1] < b[1];
        });

    int count = 0;
    int lastEnd = INT_MIN;

    for (const auto& interval : intervals) {
        int start = interval[0];
        int end = interval[1];

        if (start >= lastEnd) {
            ++count;
            lastEnd = end;
        }
    }

    return count;
}
```

> [!note]
> 如果题目定义区间闭区间且端点相同算重叠，判断条件可能要写成 `start > lastEnd`。要根据题意调整。

### 4.4 为什么不是按开始时间排序

反例：

```text
[1,10], [2,3], [3,4], [4,5]
```

如果按开始时间选，先选 `[1,10]`，后面都不能选。

但真正更好的选择是：

```text
[2,3], [3,4], [4,5]
```

### 4.5 证明思路：交换论证

设最优解中第一个选择的区间不是结束最早的区间，而是某个更晚结束的区间。

把它替换成结束最早的区间：

1. 替换后仍然不和后续区间冲突，因为新选择结束得更早。
2. 区间数量不会减少。
3. 因此一定存在一个以“结束最早区间”为第一个选择的最优解。

这说明贪心选择是安全的。

## 5. 跳跃游戏

### 5.1 问题模型

给定数组 `nums`，`nums[i]` 表示从下标 `i` 最多可以向右跳多少步，判断是否能到达最后一个下标。

例如：

```text
nums = [2,3,1,1,4]
```

从下标 `0` 最多跳到 `2`，继续选择可以到达最后。

### 5.2 贪心策略

维护当前能到达的最远位置：

```cpp
farthest = max(farthest, i + nums[i]);
```

遍历数组时：

- 如果 `i > farthest`，说明当前位置无法到达，直接失败。
- 否则用当前位置继续更新最远可达范围。

局部最优是：

```text
在所有已经可达的位置中，不断扩展最远覆盖范围。
```

### 5.3 C++ 模板

```cpp
bool canJump(vector<int>& nums) {
    int farthest = 0;

    for (int i = 0; i < nums.size(); ++i) {
        if (i > farthest) {
            return false;
        }

        farthest = max(farthest, i + nums[i]);

        if (farthest >= nums.size() - 1) {
            return true;
        }
    }

    return true;
}
```

### 5.4 为什么这个贪心正确

在遍历过程中，`farthest` 表示：

```text
目前所有可达位置能进一步到达的最远下标
```

只要当前下标 `i <= farthest`，就说明它可达，可以用它继续扩展覆盖范围。

如果某一刻 `i > farthest`，说明前面所有可达位置都无法跳到 `i`，后面的位置更不可能被处理到，因此一定失败。

## 6. 分发糖果

### 6.1 问题模型

有一排孩子，每个孩子有一个评分 `ratings[i]`，要求分发糖果满足：

1. 每个孩子至少 1 个糖果。
2. 相邻孩子中，评分更高的孩子必须获得更多糖果。
3. 返回最少需要的糖果总数。

### 6.2 贪心策略

相邻约束有两个方向：

1. 如果 `ratings[i] > ratings[i - 1]`，那么 `i` 的糖果要比左边多。
2. 如果 `ratings[i] > ratings[i + 1]`，那么 `i` 的糖果要比右边多。

一次扫描很难同时满足两个方向，所以使用两次扫描：

- 左到右：满足右孩子比左孩子评分高的情况
- 右到左：满足左孩子比右孩子评分高的情况

最终每个位置取两个方向约束下的最大值。

### 6.3 C++ 模板

```cpp
int candy(vector<int>& ratings) {
    int n = ratings.size();
    vector<int> candies(n, 1);

    for (int i = 1; i < n; ++i) {
        if (ratings[i] > ratings[i - 1]) {
            candies[i] = candies[i - 1] + 1;
        }
    }

    for (int i = n - 2; i >= 0; --i) {
        if (ratings[i] > ratings[i + 1]) {
            candies[i] = max(candies[i], candies[i + 1] + 1);
        }
    }

    int total = 0;
    for (int x : candies) {
        total += x;
    }

    return total;
}
```

### 6.4 为什么要取 `max`

右到左扫描时，当前位置可能已经在左到右扫描中得到过一个糖果数。

如果直接覆盖，可能破坏左边方向的约束。

所以必须写：

```cpp
candies[i] = max(candies[i], candies[i + 1] + 1);
```

含义是：同时满足两个方向约束，取更大的那个。

### 6.5 局部约束如何合并成全局最优

每个相邻关系只涉及两个孩子。

左到右扫描保证所有上升边满足约束，右到左扫描保证所有下降边满足约束。每次只在必要时增加糖果，并且用 `max` 保留已有约束，因此最终得到的就是满足所有局部约束的最小总数。

## 7. 贪心常见模式

### 7.1 排序后选择

先排序，再按照某个规则依次选择。

常见排序依据：

| 排序依据 | 常见问题 |
|----------|----------|
| 结束时间 | 区间调度、无重叠区间 |
| 起点 / 终点 | 合并区间、射气球 |
| 差值 | 两地调度、收益最大化 |
| 权重 / 代价 | 背包变体、任务安排 |

关键是证明排序规则为什么不吃亏。

### 7.2 维护最远边界

维护当前能覆盖到的最远位置。

常见问题：

- 跳跃游戏
- 跳跃游戏 II
- 加油站
- 区间覆盖

这种题通常有一个单调扩张的边界变量，例如 `farthest`、`right`、`cover`。

### 7.3 两次扫描

当约束来自两个方向时，可以拆成两次扫描。

典型问题：

- 分发糖果
- 摆动序列的方向变化
- 左右前缀 / 后缀约束

### 7.4 优先队列维护当前最优

有些贪心题需要在动态候选集合中取最大或最小，可以使用优先队列。

常见问题：

- 会议室
- 课程表 III
- IPO 项目选择
- 数据流中的任务调度

可以回看 [[14.8 容器适配器]] 中的 `priority_queue`。

## 8. 贪心证明方法

### 8.1 交换论证

交换论证常用于排序后选择问题。

基本套路：

1. 假设存在一个最优解没有使用贪心选择。
2. 把最优解中的某个选择替换成贪心选择。
3. 证明替换后仍然合法，且答案不会变差。
4. 因此一定存在包含贪心选择的最优解。

区间调度中，“结束最早”的证明就是典型交换论证。

### 8.2 反证法

假设贪心策略失败，然后推出与题目状态矛盾。

跳跃游戏中，如果遍历到 `i > farthest`，说明前面所有可达位置都无法到达 `i`。此时无论后面有什么值，都不可能被访问到，因此一定失败。

### 8.3 边界单调性

如果某个边界只会向一个方向扩张，就可以用贪心维护它。

例如跳跃游戏中的：

```cpp
farthest = max(farthest, i + nums[i]);
```

`farthest` 只会变大，不会变小。

### 8.4 “不吃亏”选择

贪心证明的核心是“不吃亏”：

```text
当前这样选，至少不会比别的选择更差。
```

例如区间调度选择结束最早的区间，不会减少后续可选空间；分发糖果每次只在必要时增加糖果，不会多发。

## 9. 复杂度分析

| 问题模型 | 常见时间复杂度 | 常见空间复杂度 | 主要开销 |
|----------|----------------|----------------|----------|
| 区间调度 | `O(nlogn)` | `O(1)` 或排序栈空间 | 排序 |
| 跳跃游戏 | `O(n)` | `O(1)` | 单次扫描 |
| 分发糖果 | `O(n)` | `O(n)` | 糖果数组 |
| 优先队列贪心 | `O(nlogn)` 或 `O(nlogk)` | `O(n)` 或 `O(k)` | 堆操作 |

贪心题的复杂度通常来自：

1. 是否需要排序
2. 是否需要堆维护候选集合
3. 是否只需要一次或两次线性扫描

---

## 10. 易错点

1. 不要看到“每一步选最大 / 最小”就直接写贪心，必须能证明。
2. 排序规则选错会导致错误答案，例如区间调度不能按开始时间最早选。
3. 跳跃游戏中要先判断 `i > farthest`，否则可能用不可达位置更新答案。
4. 分发糖果右到左扫描时必须取 `max`，不能直接覆盖。
5. 贪心和动态规划都可能解决最优化问题，但贪心不保留所有状态，适用范围更窄。
6. 如果找不到可靠证明，先尝试构造反例，或者考虑 DP。

# 14.19 图与图算法

图（Graph）是算法中非常重要的一类数据结构。很多看起来完全不同的题目，例如连通块、课程依赖、最短路径、最小代价连接，本质上都可以抽象成“点与点之间的关系”，也就是图。

---

## 1. 图的概览

### 1.1 什么是图

图由两部分组成：

- **顶点**（Vertex）—— 也叫节点，用来表示对象
- **边**（Edge）—— 用来表示对象之间的关系

例如：

```text
A --- B --- C
|           |
+-----------+
```

上图中：

- `A`、`B`、`C` 是顶点
- 顶点之间的连线是边

在算法题中，顶点不一定真的是“圆点”，它也可能表示：

- 一门课程
- 一个城市
- 一个网页
- 一个网格中的格子
- 一个字符串状态

也就是说，只要题目里有“对象”和“对象之间的关系”，就有可能把它抽象成图。

### 1.2 图的常见分类

| 类型 | 含义 | 例子 |
|------|------|------|
| 无向图 | 边没有方向，`u -> v` 和 `v -> u` 等价 | 好友关系、道路互通 |
| 有向图 | 边有方向，`u -> v` 不等价于 `v -> u` | 课程先修关系、网页链接 |
| 无权图 | 每条边只表示“能到达” | 社交关系、岛屿连通 |
| 带权图 | 每条边还有代价、距离、时间 | 最短路、网络延迟 |
| 连通图 | 任意两个点之间都能通过若干边到达 | 整体互通的网络 |
| 非连通图 | 图中存在多个互不相连的部分 | 多个省份、多个岛 |

### 1.3 树和图的关系

树其实是图的一种特殊情况。

可以把树理解为：

```text
连通 + 无环
```

所以之前在 [[14.17 二叉树与遍历算法]] 中学到的 DFS / BFS 思想，到了图这里仍然成立；只是图比树更一般，因此需要额外处理：

1. 一个点可能有很多邻居，而不只是左右孩子
2. 图中可能存在环
3. 同一个点可能通过不同路径重复到达

> [!tip]
> 树上的遍历之所以相对简单，是因为树天然没有环；图上的遍历则必须考虑“是否已经访问过”。

### 1.4 算法题里什么情况下要想到图

如果题目中出现下面这些关键词，通常要考虑图建模：

- **连通 / 可达 / 是否属于同一组**
- **路径 / 最短距离 / 最少步数**
- **依赖关系 / 先后顺序**
- **扩散 / 感染 / 传播**
- **用最小代价把所有点连起来**

例如：

| 题目表述 | 图上的理解 |
|----------|------------|
| 岛屿数量 | 每个陆地格子是点，相邻陆地之间连边 |
| 课程表 | 课程是点，先修关系是有向边 |
| 网络延迟 | 节点是点，传输时间是边权 |
| 连接所有点的最小费用 | 点之间存在带权边，要找最小生成树 |

## 2. 图的存储方式

写图题前，第一步往往不是直接写 DFS / BFS，而是先想：

```text
这个图应该怎么存？
```

### 2.1 邻接表

邻接表是算法题中最常见的图存储方式。

```cpp
int n = 5;
vector<vector<int>> graph(n);

graph[0].push_back(1);
graph[0].push_back(2);
graph[1].push_back(3);
```

这段代码表示：

- `graph[0]` 存的是和顶点 `0` 相邻的所有点
- `graph[1]` 存的是和顶点 `1` 相邻的所有点

如果是带权图，常见写法是：

```cpp
vector<vector<pair<int, int>>> graph(n);
graph[0].push_back({1, 5});  // 0 -> 1，边权为 5
```

**为什么邻接表最常用**：

1. 稀疏图节省空间
2. 遍历某个点的所有邻居很方便
3. 与 DFS、BFS、拓扑排序、Dijkstra 都很搭配

**关键点**：

- 邻接表通常基于 [[14.1 vector]]
- 无向图建边时要双向加入
- 有向图只加一个方向

### 2.2 邻接矩阵

邻接矩阵适合顶点数不大、图比较稠密的情况。

```cpp
int n = 4;
vector<vector<int>> matrix(n, vector<int>(n, 0));
matrix[0][1] = 1;
matrix[1][0] = 1;
```

这里：

- `matrix[u][v] = 1` 表示 `u` 和 `v` 之间有边
- 如果是带权图，也可以把 `1` 改成具体权值

| 特点 | 说明 |
|------|------|
| 查询 `u` 到 `v` 是否有边 | `O(1)` |
| 遍历 `u` 的所有邻居 | `O(V)` |
| 空间复杂度 | `O(V^2)` |

所以：

- 点少、边多：邻接矩阵可以考虑
- 点多、边少：通常还是邻接表更好

### 2.3 边集

有些题更适合直接存边，而不是存每个点的邻居。

```cpp
vector<array<int, 3>> edges;
edges.push_back({2, 3, 5});  // u=2, v=3, w=5
```

边集最常见的用途：

1. **Kruskal 最小生成树**
2. **Bellman-Ford**
3. 题目本身直接给的是边列表

### 2.4 节点编号不连续时怎么办

有些题的节点不是 `0...n-1`，而是：

- 字符串
- 城市名
- 用户名
- 很大的离散整数

这时可以借助 [[14.5 map]] 或哈希映射把它们压缩成连续编号。

例如：

```cpp
map<string, int> id;
id["beijing"] = 0;
id["shanghai"] = 1;
```

如果题目要求有序输出、判重或维护字典序关系，也可能用到 [[14.4 set]]。

### 2.5 四种存储方式对比

| 存储方式 | 常见写法 | 适用场景 | 优点 | 缺点 |
|----------|----------|----------|------|------|
| 邻接表 | `vector<vector<int>>` | 大多数图题 | 节省空间，遍历邻居方便 | 判断两点是否直接相连不如矩阵直观 |
| 带权邻接表 | `vector<vector<pair<int,int>>>` | 最短路 | 与 Dijkstra 配合自然 | 代码稍长 |
| 邻接矩阵 | `vector<vector<int>>` | 稠密图、小规模图 | 查询边存在性快 | 空间大 |
| 边集 | `vector<array<int,3>>` | Kruskal、Bellman-Ford | 排序和全边扫描方便 | 不适合直接做 BFS / DFS |

## 3. DFS：搜索连通性与路径

### 3.1 DFS 的核心思想

深度优先搜索（DFS, Depth-First Search）的思路是：

```text
沿着一条路尽可能往深处走，走不动了再回退。
```

在树里，DFS 不需要担心回到父节点形成死循环；但在图里，**必须记录 visited**，否则可能在环里无限绕圈。

例如无向图：

```text
0 -- 1
|    |
2 -- 3
```

如果从 `0` 出发，不记录访问状态，就可能：

```text
0 -> 1 -> 3 -> 2 -> 0 -> 1 -> ...
```

### 3.2 图上的 DFS 模板

这是最常见的递归模板：

```cpp
void dfs(int u, const vector<vector<int>>& graph, vector<bool>& visited) {
    visited[u] = true;

    for (int v : graph[u]) {
        if (!visited[v]) {
            dfs(v, graph, visited);
        }
    }
}
```

**关键点**：

- `visited[u] = true` 必须在进入当前节点时就标记
- `graph[u]` 表示 `u` 的所有邻居
- 对每个没访问过的邻居继续递归

如果不想用递归，也可以显式使用栈：

```cpp
void dfsIterative(int start, const vector<vector<int>>& graph, vector<bool>& visited) {
    stack<int> st;
    st.push(start);

    while (!st.empty()) {
        int u = st.top();
        st.pop();

        if (visited[u]) continue;
        visited[u] = true;

        for (int v : graph[u]) {
            if (!visited[v]) {
                st.push(v);
            }
        }
    }
}
```

> [!note]
> 递归 DFS 代码更短，但图很深时可能有栈溢出风险；显式栈更稳，但代码略长。

### 3.3 LeetCode 200. 岛屿数量

#### 题目为什么是图

题目给的是二维网格，但本质上每个陆地格子都可以看成一个顶点。

如果两个陆地格子上下左右相邻，就认为它们之间有边。

于是问题就变成：

```text
求网格隐式图中有多少个连通块。
```

### 3.4 为什么优先想到 DFS

因为本题的核心不是最短路，也不是排序，而是：

- 发现一个还没访问过的陆地
- 把和它连通的整块陆地全部搜完
- 连通块数量加一

这正是 DFS 最擅长的“整块染色 / 连通块统计”问题。

### 3.5 C++ 实现

```cpp
class Solution {
public:
    int numIslands(vector<vector<char>>& grid) {
        int rows = static_cast<int>(grid.size());
        if (rows == 0) return 0;
        int cols = static_cast<int>(grid[0].size());

        int count = 0;

        for (int r = 0; r < rows; ++r) {
            for (int c = 0; c < cols; ++c) {
                if (grid[r][c] == '1') {
                    ++count;
                    dfs(grid, r, c, rows, cols);
                }
            }
        }

        return count;
    }

private:
    void dfs(vector<vector<char>>& grid, int r, int c, int rows, int cols) {
        if (r < 0 || r >= rows || c < 0 || c >= cols) return;
        if (grid[r][c] != '1') return;

        grid[r][c] = '0';

        dfs(grid, r + 1, c, rows, cols);
        dfs(grid, r - 1, c, rows, cols);
        dfs(grid, r, c + 1, rows, cols);
        dfs(grid, r, c - 1, rows, cols);
    }
};
```

### 3.6 代码分析

这段代码的设计思路是：

1. 外层双重循环负责“找新的岛屿起点”
2. 每当遇到一个 `'1'`，说明发现了新的连通块
3. 用 DFS 把整块岛屿全部淹没成 `'0'`
4. 之后再次扫描到这块区域时，就不会重复计数

**关键点**：

- `grid[r][c] != '1'` 直接返回，表示水域或已访问过的陆地都不再处理
- `grid[r][c] = '0'` 相当于把当前格子标记为已访问
- 四次递归分别对应上下左右四个方向

### 3.7 复杂度

- **时间复杂度**：`O(rows * cols)`
- **空间复杂度**：最坏为递归栈深度 `O(rows * cols)`

### 3.8 这一类题的识别关键词

看到下面这些词，通常就要想到 DFS / BFS：

- 岛屿数量
- 连通块个数
- 染色
- 是否可达
- 从某点开始把一整片区域全部搜掉

> [!tip]
> `547. 省份数量` 也是同一类模型：本质上仍然是在数无向图的连通分量。

## 4. BFS：层次扩散与无权最短路

### 4.1 BFS 的核心思想

广度优先搜索（BFS, Breadth-First Search）的思路是：

```text
从起点开始，一层一层向外扩展。
```

它最适合处理：

1. **最少步数**
2. **最短层数**
3. **扩散传播**
4. **无权图最短路**

BFS 通常借助 [[14.2 queue]] 完成；如果想从整体上理解 `queue` 与 `priority_queue` 在图算法中的分工，也可以一起回看 [[14.8 容器适配器]]。和 [[102. 二叉树的层序遍历]] 一样，本质都是“先入先出、按层推进”。

### 4.2 图上的 BFS 模板

```cpp
vector<int> bfs(int start, const vector<vector<int>>& graph) {
    int n = static_cast<int>(graph.size());
    vector<int> dist(n, -1);
    queue<int> que;

    dist[start] = 0;
    que.push(start);

    while (!que.empty()) {
        int u = que.front();
        que.pop();

        for (int v : graph[u]) {
            if (dist[v] != -1) continue;
            dist[v] = dist[u] + 1;
            que.push(v);
        }
    }

    return dist;
}
```

**关键点**：

- `dist[v] = -1` 表示还没访问过
- 首次到达某个点时，路径一定最短
- `dist[v] = dist[u] + 1` 就是在记录最少边数

### 4.3 LeetCode 994. 腐烂的橘子

#### 题目为什么是图

每个格子可以看成图中的一个点。

- 新鲜橘子和腐烂橘子是顶点状态
- 相邻格子之间存在边
- 腐烂会沿边扩散到上下左右的新鲜橘子

这本质上是一个**扩散问题**。

### 4.4 为什么优先想到 BFS

因为题目问的是：

```text
最少经过几分钟，所有新鲜橘子都会腐烂？
```

“最少时间”“一轮一轮传播”正是 BFS 的典型信号。

而且本题不是单源，而是：

```text
所有初始腐烂橘子同时开始扩散
```

所以这是一个典型的**多源 BFS**。

### 4.5 C++ 实现

```cpp
class Solution {
public:
    int orangesRotting(vector<vector<int>>& grid) {
        int rows = static_cast<int>(grid.size());
        int cols = static_cast<int>(grid[0].size());

        queue<pair<int, int>> que;
        int fresh = 0;

        for (int r = 0; r < rows; ++r) {
            for (int c = 0; c < cols; ++c) {
                if (grid[r][c] == 2) {
                    que.push({r, c});
                } else if (grid[r][c] == 1) {
                    ++fresh;
                }
            }
        }

        if (fresh == 0) return 0;

        int minutes = 0;
        vector<pair<int, int>> directions{{1, 0}, {-1, 0}, {0, 1}, {0, -1}};

        while (!que.empty()) {
            int size = static_cast<int>(que.size());
            bool spread = false;

            for (int i = 0; i < size; ++i) {
                auto [r, c] = que.front();
                que.pop();

                for (const auto& [dr, dc] : directions) {
                    int nr = r + dr;
                    int nc = c + dc;

                    if (nr < 0 || nr >= rows || nc < 0 || nc >= cols) continue;
                    if (grid[nr][nc] != 1) continue;

                    grid[nr][nc] = 2;
                    --fresh;
                    spread = true;
                    que.push({nr, nc});
                }
            }

            if (spread) {
                ++minutes;
            }
        }

        return fresh == 0 ? minutes : -1;
    }
};
```

### 4.6 代码分析

这段代码的关键不在“怎么遍历”，而在“怎么按分钟分层”。

**第一步：初始化队列**

```cpp
if (grid[r][c] == 2) {
    que.push({r, c});
}
```

这里把所有初始腐烂橘子都放进队列，表示它们在第 `0` 分钟同时作为起点开始扩散。

**第二步：统计新鲜橘子数量**

```cpp
else if (grid[r][c] == 1) {
    ++fresh;
}
```

这样最后可以判断是否还有无法被感染的橘子。

**第三步：按层处理**

```cpp
int size = static_cast<int>(que.size());
```

这一轮队列中的所有元素，表示“当前分钟已经腐烂、现在可以继续传播”的橘子。

和 [[102. 二叉树的层序遍历]] 中“固定当前层大小”的做法完全一致。

**第四步：传播给四邻格**

```cpp
grid[nr][nc] = 2;
--fresh;
que.push({nr, nc});
```

一旦某个新鲜橘子被感染，就立刻改成 `2`，避免重复入队。

### 4.7 复杂度

- **时间复杂度**：`O(rows * cols)`
- **空间复杂度**：`O(rows * cols)`

### 4.8 这一类题的识别关键词

看到下面这些词，通常优先考虑 BFS：

- 最少步数
- 最短路径（无权图）
- 分层
- 扩散
- 感染
- 从多个起点同时传播

## 5. 拓扑排序：处理依赖关系

### 5.1 什么是拓扑排序

拓扑排序（Topological Sort）只适用于：

```text
有向无环图（DAG）
```

它的目标是给出一种顶点顺序，使得：

```text
如果存在边 u -> v，那么 u 一定出现在 v 前面。
```

这类问题常见于：

- 课程先修关系
- 任务依赖关系
- 编译顺序
- 工作流调度

### 5.2 Kahn 算法思想

Kahn 算法的核心是：

1. 统计每个点的入度
2. 把所有入度为 `0` 的点先入队
3. 每次取出一个点，把它指向的邻居入度减一
4. 某个邻居入度减到 `0` 时，再入队

这其实是一个带入度约束的 BFS。

### 5.3 LeetCode 207. 课程表

#### 题目为什么是图

如果要学课程 `a` 之前必须先学课程 `b`，就建边：

```text
b -> a
```

含义是：

- `b` 是 `a` 的前置课程
- 学完 `b` 才能学 `a`

题目要判断能否学完全部课程，本质上就是判断：

```text
这个有向图里是否有环
```

如果有环，就意味着依赖关系互相卡住，无法完成。

### 5.4 C++ 实现

```cpp
class Solution {
public:
    bool canFinish(int numCourses, vector<vector<int>>& prerequisites) {
        vector<vector<int>> graph(numCourses);
        vector<int> indegree(numCourses, 0);

        for (const auto& edge : prerequisites) {
            int course = edge[0];
            int pre = edge[1];
            graph[pre].push_back(course);
            ++indegree[course];
        }

        queue<int> que;
        for (int i = 0; i < numCourses; ++i) {
            if (indegree[i] == 0) {
                que.push(i);
            }
        }

        int studied = 0;

        while (!que.empty()) {
            int u = que.front();
            que.pop();
            ++studied;

            for (int v : graph[u]) {
                --indegree[v];
                if (indegree[v] == 0) {
                    que.push(v);
                }
            }
        }

        return studied == numCourses;
    }
};
```

### 5.5 代码分析

**建图阶段**：

```cpp
graph[pre].push_back(course);
++indegree[course];
```

表示学完 `pre` 之后，才能解锁 `course`。

所以：

- `graph[pre]` 存的是“被它解锁的课程”
- `indegree[course]` 存的是“这门课还有多少前置条件没满足”

**初始化队列**：

```cpp
if (indegree[i] == 0) {
    que.push(i);
}
```

入度为 `0` 的课程表示没有前置依赖，可以立刻开始学。

**主循环**：

每学完一门课，就把它后继课程的入度减一；如果某门课入度减到了 `0`，说明它的所有前置条件都已经满足了。

### 5.6 为什么 `studied == numCourses` 就说明无环

如果图里没有环，课程会被一层层“解锁”，最终所有课程都能入队并被处理。

如果图里有环，例如：

```text
0 -> 1 -> 2 -> 0
```

那么环上的每个点入度都不可能减到 `0`，最后处理数量就会小于总课程数。

### 5.7 复杂度

- **时间复杂度**：`O(V + E)`
- **空间复杂度**：`O(V + E)`

### 5.8 这一类题的识别关键词

- 先修课程
- 依赖顺序
- 编译顺序
- 是否存在循环依赖
- 某些任务必须先于另一些任务完成

## 6. 并查集：动态连通性

### 6.1 什么是并查集

并查集（Union-Find / Disjoint Set Union, DSU）用于维护：

```text
若干个互不相交的集合，以及它们的合并关系。
```

它最擅长的问题不是“遍历整张图”，而是：

1. 两个点是否已经连通
2. 不断加入边后，连通关系如何变化
3. 加一条边是否会形成环

### 6.2 基本结构

并查集通常维护一个 `parent` 数组：

```cpp
class UnionFind {
public:
    explicit UnionFind(int n) : parent(n), size(n, 1) {
        iota(parent.begin(), parent.end(), 0);
    }

    int find(int x) {
        if (parent[x] != x) {
            parent[x] = find(parent[x]);
        }
        return parent[x];
    }

    bool unite(int a, int b) {
        int rootA = find(a);
        int rootB = find(b);
        if (rootA == rootB) return false;

        if (size[rootA] < size[rootB]) {
            swap(rootA, rootB);
        }

        parent[rootB] = rootA;
        size[rootA] += size[rootB];
        return true;
    }

private:
    vector<int> parent;
    vector<int> size;
};
```

**关键点**：

- `find(x)`：找 `x` 所在集合的代表元
- `path compression`：路径压缩，降低后续查找成本
- `unite(a, b)`：合并两个集合
- `size`：按集合大小合并，减少树高

### 6.3 并查集和 DFS / BFS 的区别

| 方式 | 擅长问题 |
|------|----------|
| DFS / BFS | 遍历整张图、找路径、找连通块 |
| 并查集 | 动态维护连通性、合并集合、判环 |

也就是说：

- 如果题目要求“把一整片区域都搜出来”，偏向 DFS / BFS
- 如果题目不断给边，问“这两个点是否已经连通”，偏向并查集

### 6.4 LeetCode 684. 冗余连接

#### 题目为什么适合并查集

题目逐条给出无向边，要求找出“删掉后仍能保证树结构”的那条多余边。

树的特点是：

```text
连通 + 无环
```

所以当我们按顺序加边时：

- 如果两个点原来不连通，加这条边没问题
- 如果两个点原来已经连通，再加这条边就一定形成环

这正是并查集最擅长的判断。

### 6.5 C++ 实现

```cpp
class UnionFind {
public:
    explicit UnionFind(int n) : parent(n + 1) {
        iota(parent.begin(), parent.end(), 0);
    }

    int find(int x) {
        if (parent[x] != x) {
            parent[x] = find(parent[x]);
        }
        return parent[x];
    }

    bool unite(int a, int b) {
        int rootA = find(a);
        int rootB = find(b);
        if (rootA == rootB) return false;
        parent[rootB] = rootA;
        return true;
    }

private:
    vector<int> parent;
};

class Solution {
public:
    vector<int> findRedundantConnection(vector<vector<int>>& edges) {
        UnionFind uf(static_cast<int>(edges.size()));

        for (const auto& edge : edges) {
            int u = edge[0];
            int v = edge[1];
            if (!uf.unite(u, v)) {
                return edge;
            }
        }

        return {};
    }
};
```

### 6.6 代码分析

这道题最核心的一句是：

```cpp
if (!uf.unite(u, v)) {
    return edge;
}
```

含义是：

- 如果 `u` 和 `v` 原本属于不同集合，就正常合并
- 如果 `u` 和 `v` 已经属于同一集合，再连一条边就构成了环
- 这条边就是冗余边

### 6.7 复杂度

在路径压缩 + 按秩 / 按大小合并优化下：

- 单次操作复杂度接近 `O(1)`
- 整体复杂度通常可视为 `O(n)` 或 `O(n α(n))`

这里的 `α(n)` 是反 Ackermann 函数，增长极慢，工程上几乎可以当常数。

## 7. 最短路：带权图的路径代价

### 7.1 无权图最短路与带权图最短路

先区分两个概念：

- **无权图最短路**：边权都一样，直接用 BFS
- **带权图最短路**：边权不同，通常要用 Dijkstra、Bellman-Ford 等算法

如果题目保证边权非负，最常用的是 **Dijkstra**。

### 7.2 Dijkstra 的核心思想

Dijkstra 的思路是：

```text
每次从当前还没确定的点里，选距离起点最近的那个点，
然后用它去更新邻居的最短距离。
```

这个“每次取最小”的动作通常借助 [[14.8 容器适配器]] 中的 `priority_queue` 完成。

为了得到小根堆，常见写法是：

```cpp
priority_queue<pair<int, int>, vector<pair<int, int>>, greater<pair<int, int>>> pq;
```

这里的 `greater<>` 可以结合 [[14.9 函数对象]] 一起理解。

### 7.3 LeetCode 743. 网络延迟时间

#### 题目为什么是图

题目里：

- 网络节点就是图的顶点
- `u -> v` 的信号传输时间就是边权
- 问从起点 `k` 发出信号后，多久所有点都能收到

本质上就是：

```text
求起点到所有点的最短路中的最大值。
```

### 7.4 C++ 实现

```cpp
class Solution {
public:
    int networkDelayTime(vector<vector<int>>& times, int n, int k) {
        vector<vector<pair<int, int>>> graph(n + 1);
        for (const auto& edge : times) {
            int u = edge[0];
            int v = edge[1];
            int w = edge[2];
            graph[u].push_back({v, w});
        }

        const int INF = INT_MAX / 2;
        vector<int> dist(n + 1, INF);
        dist[k] = 0;

        priority_queue<pair<int, int>, vector<pair<int, int>>, greater<pair<int, int>>> pq;
        pq.push({0, k});

        while (!pq.empty()) {
            auto [d, u] = pq.top();
            pq.pop();

            if (d > dist[u]) continue;

            for (const auto& [v, w] : graph[u]) {
                if (dist[u] + w < dist[v]) {
                    dist[v] = dist[u] + w;
                    pq.push({dist[v], v});
                }
            }
        }

        int answer = 0;
        for (int i = 1; i <= n; ++i) {
            if (dist[i] == INF) return -1;
            answer = max(answer, dist[i]);
        }

        return answer;
    }
};
```

### 7.5 代码分析

**第一步：建带权邻接表**

```cpp
graph[u].push_back({v, w});
```

表示从 `u` 到 `v` 有一条代价为 `w` 的有向边。

**第二步：初始化距离数组**

```cpp
vector<int> dist(n + 1, INF);
dist[k] = 0;
```

含义是：

- 一开始认为所有点都“很远”
- 只有起点到自己的距离是 `0`

**第三步：堆里保存当前候选最短路**

```cpp
pq.push({dist[v], v});
```

这里把“当前已知的最短距离”和“点编号”一起放进堆。

**第四步：跳过过期状态**

```cpp
if (d > dist[u]) continue;
```

因为同一个点可能多次入堆，旧的更大距离记录已经没用了。

**第五步：松弛操作**

```cpp
if (dist[u] + w < dist[v]) {
    dist[v] = dist[u] + w;
}
```

“松弛”就是尝试通过 `u` 这条路径，看能不能把 `v` 的最短距离变得更小。

### 7.6 复杂度

- **时间复杂度**：常写为 `O((V + E) log V)`
- **空间复杂度**：`O(V + E)`

### 7.7 这一类题的识别关键词

- 距离
- 代价
- 时间
- 从起点到所有点
- 边权非负

> [!warning]
> Dijkstra 不能直接用于存在负权边的最短路问题。只要题目允许负权，就要考虑 Bellman-Ford 或其他算法。

## 8. 最小生成树 MST

### 8.1 什么是最小生成树

最小生成树（Minimum Spanning Tree, MST）解决的问题是：

```text
用最小总代价，把图中所有顶点连起来。
```

要求：

1. 所有点都连通
2. 不能有环
3. 边权总和最小

### 8.2 MST 和最短路的区别

这两个概念非常容易混淆。

| 概念 | 目标 |
|------|------|
| 最短路 | 从一个起点到其他点的路径尽量短 |
| 最小生成树 | 把所有点连起来的总代价尽量小 |

也就是说：

- 最短路关注“从我出发到你最便宜”
- MST 关注“整个图连通的总成本最便宜”

### 8.3 Kruskal 思想

Kruskal 的核心步骤：

1. 把所有边按权值从小到大排序
2. 依次尝试加入答案
3. 如果加入某条边会形成环，就跳过
4. 如果不会形成环，就保留它

其中“是否形成环”就可以用并查集判断。

### 8.4 LeetCode 1584. 连接所有点的最小费用

这题要求把所有点连接起来，使总代价最小。

如果把任意两点之间的曼哈顿距离看作边权，那么问题本质上就是：

```text
在带权无向图中求最小生成树。
```

### 8.5 C++ 实现（Kruskal）

```cpp
class UnionFind {
public:
    explicit UnionFind(int n) : parent(n), size(n, 1) {
        iota(parent.begin(), parent.end(), 0);
    }

    int find(int x) {
        if (parent[x] != x) {
            parent[x] = find(parent[x]);
        }
        return parent[x];
    }

    bool unite(int a, int b) {
        int rootA = find(a);
        int rootB = find(b);
        if (rootA == rootB) return false;

        if (size[rootA] < size[rootB]) {
            swap(rootA, rootB);
        }

        parent[rootB] = rootA;
        size[rootA] += size[rootB];
        return true;
    }

private:
    vector<int> parent;
    vector<int> size;
};

class Solution {
public:
    int minCostConnectPoints(vector<vector<int>>& points) {
        int n = static_cast<int>(points.size());
        vector<array<int, 3>> edges;

        for (int i = 0; i < n; ++i) {
            for (int j = i + 1; j < n; ++j) {
                int cost = abs(points[i][0] - points[j][0])
                         + abs(points[i][1] - points[j][1]);
                edges.push_back({cost, i, j});
            }
        }

        sort(edges.begin(), edges.end(), [](const auto& a, const auto& b) {
            return a[0] < b[0];
        });

        UnionFind uf(n);
        int answer = 0;
        int used = 0;

        for (const auto& edge : edges) {
            int cost = edge[0];
            int u = edge[1];
            int v = edge[2];

            if (uf.unite(u, v)) {
                answer += cost;
                ++used;
                if (used == n - 1) break;
            }
        }

        return answer;
    }
};
```

### 8.6 代码分析

**第一步：构造边集**

```cpp
edges.push_back({cost, i, j});
```

这里的边集写法与前面“图的存储方式”一节一致，适合 Kruskal 这类先处理所有边的算法。

**第二步：按边权排序**

```cpp
sort(edges.begin(), edges.end(), ...);
```

Kruskal 的贪心策略就是：

```text
优先选当前代价最小、且不会成环的边。
```

**第三步：并查集判环**

```cpp
if (uf.unite(u, v)) {
    answer += cost;
}
```

如果 `u` 和 `v` 原本不连通，就把这条边加入生成树；如果已经连通，再加就会成环。

**第四步：为什么 `used == n - 1` 可以结束**

一棵包含 `n` 个点的树一定有：

```text
n - 1 条边
```

所以当已经选满 `n - 1` 条边时，最小生成树就构建完成了。

### 8.7 复杂度

- 构造所有边：`O(n^2)`
- 排序边集：`O(n^2 log n)`
- 并查集合并：近似线性

这题的主要开销其实在“枚举所有边 + 排序”。

> [!note]
> 最小生成树除了 Kruskal 之外，还常见 Prim。Prim 更像“从一个已连通点集不断向外扩展”，而 Kruskal 更像“全局按边权从小到大挑边”。

## 9. 图算法选型速查表

很多图题难点不在实现，而在：

```text
我到底该先想 DFS、BFS、并查集、拓扑排序，还是最短路？
```

下面这张表可以作为快速判断工具：

| 题目特征 | 优先方法 | 核心结构 |
|----------|----------|----------|
| 连通块 / 染色 / 区域搜索 | DFS / BFS | 递归 / `queue` |
| 最少步数 / 扩散轮次 / 无权最短路 | BFS | `queue` |
| 依赖顺序 / 先修课程 / 是否有环 | 拓扑排序 | 邻接表 + 入度数组 + `queue` |
| 动态合并集合 / 判环 | 并查集 | `parent` |
| 边权非负的最短路径 | Dijkstra | 邻接表 + `priority_queue` |
| 最小总代价连接所有点 | Kruskal / MST | 边集 + 并查集 |

可以进一步记成一句话：

```text
搜一整片，用 DFS/BFS；
求最少步数，用 BFS；
看依赖顺序，用拓扑排序；
边不断加入判连通，用并查集；
带权最短路，用 Dijkstra；
全图最小连接代价，用 MST。
```

## 10. 易错点

1. **忘记 `visited`**：图中可能有环，DFS / BFS 若不做访问标记，容易死循环。
2. **无向图只建了一条边**：无向图通常要 `u -> v` 和 `v -> u` 都加入。
3. **把 BFS 当普通遍历，却忘了分层**：题目如果问“最少几步 / 几分钟”，通常需要按层处理。
4. **把 Dijkstra 用到负权图上**：这是错误的适用场景。
5. **并查集下标范围写错**：有些题节点从 `1` 开始编号，有些从 `0` 开始。
6. **把最短路和最小生成树混为一谈**：前者关注“从起点到各点”，后者关注“整体连通总代价”。
7. **网格题忘记先做边界判断**：四方向扩展时，下标越界是最常见 bug 之一。
8. **拓扑排序建边方向写反**：课程表类问题里，谁指向谁一定要在建图前想清楚。

> [!warning]
> 图题真正容易出错的地方，往往不是 STL 语法，而是“建模方向”和“访问状态”的细节。

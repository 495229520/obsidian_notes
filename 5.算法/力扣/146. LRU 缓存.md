# 146. LRU 缓存

设计一个满足 LRU（最近最少使用）淘汰策略的缓存结构，使 `get` 和 `put` 操作都能以 `O(1)` 平均时间复杂度运行。

---

## 1. 题目概览

### 1.1 题目描述

请你设计并实现一个满足 **LRU（最近最少使用）缓存** 约束的数据结构。

实现 `LRUCache` 类：

- `LRUCache(int capacity)` 以**正整数**作为容量 `capacity` 初始化 LRU 缓存
- `int get(int key)` 如果关键字 `key` 存在于缓存中，则返回关键字的值，否则返回 `-1`
- `void put(int key, int value)` 如果关键字 `key` 已经存在，则变更其数据值 `value`；如果不存在，则向缓存中插入该组 `key-value`。如果插入操作导致关键字数量超过 `capacity`，则应该**逐出最久未使用的关键字**

函数 `get` 和 `put` 必须以 `O(1)` 的平均时间复杂度运行。

### 1.2 输入输出与约束

| 项目 | 内容 |
|------|------|
| 输入 | 操作序列和对应参数 |
| 输出 | 每次操作的返回值 |
| 初始化 | `LRUCache(int capacity)` |
| 查询 | `get(int key)`，命中返回值，否则返回 `-1` |
| 更新 | `put(int key, int value)`，插入或更新键值对 |
| 特殊要求 | `get` 和 `put` 平均时间复杂度必须为 `O(1)` |

> [!warning]
> `get(key)` 也是一次访问。只要命中缓存，该关键字就应该变成“最近使用”。

### 1.3 示例

```text
输入
["LRUCache", "put", "put", "get", "put", "get", "put", "get", "get", "get"]
[[2], [1, 1], [2, 2], [1], [3, 3], [2], [4, 4], [1], [3], [4]]
输出
[null, null, null, 1, null, -1, null, -1, 3, 4]

解释
LRUCache lRUCache = new LRUCache(2);
lRUCache.put(1, 1); // 缓存是 {1=1}
lRUCache.put(2, 2); // 缓存是 {1=1, 2=2}
lRUCache.get(1);    // 返回 1
lRUCache.put(3, 3); // 该操作会使得关键字 2 作废，缓存是 {1=1, 3=3}
lRUCache.get(2);    // 返回 -1 (未找到)
lRUCache.put(4, 4); // 该操作会使得关键字 1 作废，缓存是 {4=4, 3=3}
lRUCache.get(1);    // 返回 -1 (未找到)
lRUCache.get(3);    // 返回 3
lRUCache.get(4);    // 返回 4
```

## 2. 可用算法与数据结构

### 2.1 可选解法总览

| 方案 | 核心算法 | 核心数据结构 | 是否适合本题 | 原因 |
|------|----------|--------------|--------------|------|
| 只用哈希表 | 快速查找 key | `unordered_map` | 不适合 | 无法维护最近使用顺序 |
| 只用链表 | 维护访问顺序 | `list` | 不适合 | 无法 `O(1)` 查找 key |
| 哈希表 + 双向链表 | 快速查找 + 快速移动节点 | `unordered_map` + `list` | 推荐 | 同时满足 `O(1)` 查找、插入、删除、移动 |

### 2.2 本题采用的算法

本题采用：**哈希表 + 双向链表**。

选择它的原因：

1. 哈希表可以通过 `key` 在平均 `O(1)` 时间内找到缓存项。
2. 双向链表可以在已知节点位置时 `O(1)` 删除和插入节点。
3. 链表顺序可以表示最近使用顺序，头部为最近使用，尾部为最久未使用。

### 2.3 本题使用的数据结构

| 数据结构 | 在本题中的作用 | 为什么需要它 |
|----------|----------------|--------------|
| `list<pair<int, int>>` | 保存 `{key, value}`，并维护使用顺序 | 支持 `O(1)` 插入、删除和移动节点 |
| `unordered_map<int, list<pair<int, int>>::iterator>` | 映射 `key -> 链表节点位置` | 支持 `O(1)` 查找 key |
| `capacity` | 缓存容量上限 | 判断是否需要淘汰 LRU 节点 |

## 3. 解题步骤

### 3.1 核心思路

LRU 是 **Least Recently Used** 的缩写，意思是**最近最少使用**。

把缓存中的数据按“最近使用时间”排序：

- 头部：最近使用的数据，也叫 MRU
- 尾部：最久未使用的数据，也叫 LRU
- 每次访问一个数据，都把它移动到头部
- 插入新数据时，也把它放到头部
- 容量满时，删除尾部数据

单独使用一种数据结构很难同时满足 `O(1)` 查找和 `O(1)` 维护顺序，因此需要哈希表和双向链表配合。

### 3.2 详细步骤

#### 第一步：初始化结构

```cpp
int capacity;
list<pair<int, int>> cache;
unordered_map<int, list<pair<int, int>>::iterator> map;
```

链表头部表示最近使用，链表尾部表示最久未使用。

#### 第二步：实现 `get(key)`

如果 `key` 不存在，返回 `-1`。

如果 `key` 存在：

1. 通过哈希表找到链表节点
2. 取出节点中的 `value`
3. 删除原位置的节点
4. 把 `{key, value}` 插入链表头部
5. 更新哈希表中 `key` 对应的新迭代器
6. 返回 `value`

#### 第三步：实现 `put(key, value)`

如果 `key` 已经存在：

1. 删除旧节点
2. 后面统一插入新的 `{key, value}` 到头部

如果 `key` 不存在且缓存已满：

1. 找到尾部节点 `cache.back()`
2. 从哈希表中删除尾部节点的 `key`
3. 删除链表尾部节点

最后将新 `{key, value}` 插入链表头部，并更新哈希表。

### 3.3 示例推演

容量为 `2`：

| 操作 | 结果 | 缓存状态（左边是最近使用） | 说明 |
|------|------|----------------------------|------|
| `put(1, 1)` | `null` | `[1]` | 插入 1 |
| `put(2, 2)` | `null` | `[2, 1]` | 插入 2，2 最近使用 |
| `get(1)` | `1` | `[1, 2]` | 访问 1，移动到头部 |
| `put(3, 3)` | `null` | `[3, 1]` | 容量满，淘汰 2 |
| `get(2)` | `-1` | `[3, 1]` | 2 已被淘汰 |
| `put(4, 4)` | `null` | `[4, 3]` | 淘汰 1 |
| `get(3)` | `3` | `[3, 4]` | 3 移动到头部 |

## 5. 源码实现

### 5.1 完整 C++ 代码

```cpp
class LRUCache {
public:
    LRUCache(int capacity) {
        this->capacity = capacity;
    }

    int get(int key) {
        if (map.find(key) == map.end()) {
            return -1;
        }

        auto it = map[key];
        int value = it->second;

        cache.erase(it);
        cache.push_front({key, value});
        map[key] = cache.begin();

        return value;
    }

    void put(int key, int value) {
        if (map.find(key) != map.end()) {
            cache.erase(map[key]);
        } else if (cache.size() == capacity) {
            auto last = cache.back();
            map.erase(last.first);
            cache.pop_back();
        }

        cache.push_front({key, value});
        map[key] = cache.begin();
    }

private:
    int capacity;
    list<pair<int, int>> cache;
    unordered_map<int, list<pair<int, int>>::iterator> map;
};
```

### 5.2 代码中的关键注释

| 代码位置 | 解释重点 |
|----------|----------|
| `map.find(key)` | 判断 key 是否存在 |
| `cache.erase(it)` | 删除旧位置节点，为移动到头部做准备 |
| `cache.push_front(...)` | 将节点设为最近使用 |
| `map[key] = cache.begin()` | 更新 key 对应的新位置 |
| `cache.back()` | 找到最久未使用节点 |
| `map.erase(last.first)` | 淘汰节点时同步删除哈希表记录 |

## 6. 源码详解

### 6.1 核心变量说明

| 变量 / 数据结构 | 含义 | 生命周期 | 为什么需要它 |
|-----------------|------|----------|--------------|
| `capacity` | 缓存最大容量 | 对象整个生命周期 | 判断是否需要淘汰 |
| `cache` | 双向链表，保存 `{key, value}` | 对象整个生命周期 | 维护最近使用顺序 |
| `map` | 哈希表，保存 `key -> 链表迭代器` | 对象整个生命周期 | 快速定位节点 |
| `it` | 某个 key 对应的链表节点位置 | 单次 `get` / `put` | 用于 `O(1)` 删除旧节点 |

### 6.2 `get` 操作拆解

`get` 命中时不能只返回 value，还要刷新最近使用顺序。

```cpp
cache.erase(it);
cache.push_front({key, value});
map[key] = cache.begin();
```

这三步表示：删除旧位置、插入到头部、更新哈希表迭代器。

### 6.3 `put` 操作拆解

`put` 有三种情况：

1. `key` 已存在：删除旧节点，再插入新值到头部。
2. `key` 不存在且缓存未满：直接插入头部。
3. `key` 不存在且缓存已满：先淘汰尾部 LRU 节点，再插入头部。

淘汰尾部时，链表节点中必须保存 `key`：

```cpp
auto last = cache.back();
map.erase(last.first);
cache.pop_back();
```

否则只知道 value，不知道该从哈希表删除哪个 key。

### 6.4 易错点

1. `get` 命中后也要移动到链表头部。
2. `put` 更新已有 key 时，也要刷新最近使用顺序。
3. 淘汰尾部节点时，要同时从 `map` 中删除旧 key。
4. 链表里必须保存 `key`，否则删除尾部时不知道该从 `map` 删除哪个 key。
5. `map[key]` 保存的是链表迭代器，不是 value 本身。

## 7. 复杂度分析

### 7.1 时间复杂度

- `get`：平均 `O(1)`
- `put`：平均 `O(1)`

原因：哈希表查找、插入、删除平均是 `O(1)`；双向链表在已知迭代器时删除节点是 `O(1)`，头部插入和尾部删除也是 `O(1)`。

### 7.2 空间复杂度

- 空间复杂度：`O(capacity)`

原因：缓存最多保存 `capacity` 个键值对，哈希表和链表都与容量成正比。

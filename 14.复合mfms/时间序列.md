
``` mermaid
sequenceDiagram
    autonumber
    participant L as 物流系统
    participant M as 数据中台
    participant D as MySQL
    participant S as 调度系统
    participant R as 调度内部 Redis

    Note over L,R: 第一阶段：接收物流需求

    L->>M: 下发六字段任务<br/>taskCode、起点、终点、罐体编号<br/>起点是否开门、终点是否开门
    M->>M: 校验字段和类型

    alt 新任务
        M->>D: BEGIN
        M->>D: INSERT logisticsTaskRecord<br/>id=独立雪花ID A<br/>task_code=taskCode<br/>context=完整六字段JSON<br/>task_status=1 已生成<br/>arrived_storage_code=NULL<br/>door_request_id=NULL
        M->>D: INSERT logisticsTaskOutBox<br/>id=独立雪花ID B<br/>logistics_task_id=A<br/>payload=完整六字段JSON<br/>status=0 PENDING
        M->>D: COMMIT
        D-->>M: 两表统一提交成功
        M-->>L: code=200，接收成功
    else 同任务编号、相同内容的重复请求
        M->>D: 查询并核对已有 Record 和 OutBox
        D-->>M: 已存在且内容一致
        M-->>L: code=200，接收成功，不重复创建
    else 内容冲突或数据库写入失败
        M->>D: 若已开启写事务则 ROLLBACK
        M-->>L: 返回错误，message 说明原因
    end

    Note over L,R: 以下只对已经成功接收的任务执行

    Note over S,R: 第二阶段：调度接收需求

    S->>D: 轮询 logisticsTaskOutBox<br/>读取 status=0 的待处理记录
    S->>S: 按 logistics_task_id 幂等处理<br/>建立或找到已有调度任务
    S->>D: 在调度处理事务中更新 OutBox<br/>status=1 PROCESSED
    Note over D,S: OutBox=1：数据库处理完成，等待投递 Redis<br/>Record 此时仍可保持 task_status=1 已生成

    S->>R: 投递调度内部消息
    R-->>S: 投递成功
    S->>D: UPDATE logisticsTaskOutBox<br/>status=2 PUBLISHED
    Note over D,R: OutBox=2 只表示 Redis 投递成功<br/>不表示已经到点、取货或任务完成<br/>失败使用 status=3，处理与重试规则由调度确定

    Note over L,R: 第三阶段：前往起点柜台

    S->>S: 正式下发第一张运单
    S->>D: UPDATE logisticsTaskRecord<br/>task_status=2 已下发<br/>首次填写 started_at
    S->>S: 控制 AGV 前往起点
    S->>S: 确认 AGV 实际到达起点柜台
    S->>D: 同事务条件 UPDATE Record<br/>task_status=已到起点<br/>arrived_storage_code=实际到达的业务点位编号

    M->>D: 轮询 Record，读取任务状态、到达点位和 context
    D-->>M: 已到起点及 arrived_storage_code
    M->>M: 核对到达点位等于 startStorageCode

    Note over M,S: 状态或点位不匹配时不发 OPEN<br/>AGV 地图站点须由调度映射为物流系统点位编号

    alt startStorageOpenDoor=true
        M->>D: 条件 UPDATE Record<br/>仅在仍为已到起点且点位匹配时<br/>保存当前 door_request_id
        D-->>M: 请求编号持久化成功

        M->>L: 请求 OPEN<br/>requestOpenDoorId=door_request_id<br/>taskCode=任务编号<br/>storageCode=arrived_storage_code<br/>doorStatus=OPEN
        L-->>M: code=200，开门请求已接收
        Note over M,S: 接收成功不等于门已打开<br/>调度保持等待，不执行取货

        L->>L: 对接工厂，打开对应柜门
        L->>M: 门状态回传<br/>requestOpenDoorId、taskCode<br/>storageCode、doorStatus=OPENED
        M->>M: 核对任务、当前请求编号、点位<br/>及当前任务是否仍等待起点开门
        M->>D: 条件 UPDATE Record<br/>task_status=起点门已打开
        D-->>M: 提交成功
        M-->>L: code=200，门已打开

        S->>D: 读取 Record<br/>确认当前任务起点门已打开
    else startStorageOpenDoor=false
        S->>D: 读取 Record 和 context<br/>确认已到起点且无需开门
        Note over M,S: 跳过开门请求和 OPENED 等待
    end

    Note over L,R: 第四阶段：取货上车及起点关门

    S->>S: 执行取货<br/>确认气罐已经到小车上
    S->>D: 条件 UPDATE Record<br/>task_status=6 运送中
    Note over D,S: 此时不立即覆盖为后续状态<br/>等待中台完成状态 6 的反馈交接

    M->>D: 读取 task_status=6 的任务
    M->>L: 状态反馈<br/>taskCode、taskDetailStatus=6
    L-->>M: code=200，接收成功
    L->>L: 根据状态 6 自动关闭起点柜门
    M->>M: 持久保存状态 6 的成功确认
    M->>D: 条件 UPDATE Record<br/>task_status：6 → 6已反馈

    Note over M,D: 若本地已经确认 6，但数据库更新失败<br/>只重试状态更新，不重复发送已确认反馈

    S->>D: 读取到 task_status=6已反馈
    S->>D: 条件 UPDATE Record<br/>清空 arrived_storage_code<br/>清空起点 door_request_id
    S->>S: 继续运输，前往目标点

    Note over L,R: 第五阶段：到达目标点及开门

    S->>S: 确认 AGV 实际到达目标点
    S->>D: 同事务条件 UPDATE Record<br/>task_status=7 准备放下<br/>arrived_storage_code=实际到达的目标点位编号

    M->>D: 轮询 Record，读取状态、到达点位和 context
    M->>M: 核对到达点位等于 endStorageCode

    alt endStorageOpenDoor=true
        M->>D: 条件 UPDATE Record<br/>仅在仍为7且目标点位匹配时<br/>保存新的 door_request_id
        D-->>M: 新请求编号持久化成功

        M->>L: 请求 OPEN<br/>新的 requestOpenDoorId<br/>taskCode、storageCode=目标点位<br/>doorStatus=OPEN
        L-->>M: code=200，开门请求已接收
        L->>L: 对接工厂，打开目标柜门
        L->>M: 回传对应请求的 OPENED

        M->>M: 核对任务、新请求编号、目标点位<br/>及当前任务是否仍等待终点开门
        M->>D: 条件 UPDATE Record<br/>task_status=终点门已打开
        D-->>M: 提交成功
        M-->>L: code=200，门已打开
        S->>D: 读取 Record<br/>确认当前任务终点门已打开
    else endStorageOpenDoor=false
        S->>D: 读取 Record 和 context<br/>确认已到目标点且无需开门
        Note over M,S: 跳过开门请求和 OPENED 等待
    end

    Note over L,R: 第六阶段：放货及任务结束

    S->>S: 执行放货，确认气罐已放下
    S->>D: UPDATE Record<br/>task_status=8 已放下
    S->>S: 执行离开点位步骤
    S->>D: 同事务 UPDATE Record<br/>task_status=9 车离开<br/>arrived_storage_code=NULL
    S->>S: 确认整体任务完成
    S->>D: 同事务 UPDATE Record<br/>task_status=201 正常结束<br/>填写 ended_at

    M->>D: 读取 task_status=201
    M->>L: 状态反馈<br/>taskCode、taskDetailStatus=201
    L-->>M: code=200，接收成功
    M->>M: 持久保存状态 201 的成功确认

    Note over L,S: 放货后关门方式尚待确认<br/>不能根据 201 推断门已关闭<br/>当前中台不主动发送 CLOSE

    Note over L,R: 独立取消分支：可在允许取消的未完成阶段进入

    opt 调度确认人工取消
        S->>D: 同事务条件 UPDATE Record<br/>task_status=601 手动取消<br/>填写 ended_at、ended_reason
        M->>D: 读取 task_status=601
        M->>L: 状态反馈<br/>taskCode、taskDetailStatus=601
        L-->>M: code=200，接收成功
        M->>M: 持久保存状态 601 的成功确认
        Note over L,S: 取消后的门处理不包含在本轮流程中
    end
```

# MFMS 新中台 · 待确定问题清单

> [!abstract] 本文定位
> 这是 MFMS 新中台**唯一未决项登记簿**。当前结论见 [[MFMS新中台-架构构造思路]]，详细设计见 [[MFMS新中台-逐层设计工作台]]。其他文档只引用这里的编号，不复制维护问题。

> [!success] v0.3 已纠正的核心边界
> 下位机是控制权唯一权威。Q-33 已在数据中台范围内关闭；中台不再设计锁、租约、epoch、确认令牌或跨系统暂停协调。Q-31、Q-32 仍需冻结数据契约，Q-34 只保留中台消费 Adapter 运单消息所需的外部契约。

## 1. 状态规则

| 状态 | 含义 |
| --- | --- |
| **待确认** | 需要下位机、调度、Adapter 或业务方给出事实 |
| **待评审** | v0.3 已给出推荐方案，仍需联合评审后冻结 |
| **已闭** | 结论已进入当前架构与 Trellis |
| **移出范围** | 不是数据中台职责；只登记对外依赖 |
| **历史废弃** | 旧假设被 v0.3 明确推翻 |

关闭问题时必须写明：结论、权威方、日期、影响的 Trellis spec，以及是否需要迁移旧实现。

## 3. v0.3 已处理的原架构阻塞项

| ID | 结论 | 状态 |
| --- | --- | --- |
| **Q-33** | 生产与调试的真实互斥、普通申请、强制夺权和无权命令拒绝均由下位机裁决。中台只查询/展示/申请/强制申请/释放、鉴权、二次确认和审计；订单/运单状态仅作风险提示。 | **已闭（中台范围）** |
| **Q-34** | Adapter 内部状态机、ADK 编排、暂停、崩溃恢复不属于中台设计。中台只要求规范的 AGV 运单实时消息、来源和关联 ID。 | **移出范围** |
| **Q-02-rev** | 基线不要求调度系统通过 gRPC 直连中台；订单经 MySQL 交换，实时状态经 Redis Stream 输入。健康检查或管理 API 如有真实需求再单独立项。 | **已闭** |
| **Q-31-topology** | 中台不负责 Redis 实例、消费者组部署或运维拓扑；只冻结自己消费的消息契约。 | **移出范围** |

> [!warning] 不要误解“已闭”
> Q-33 关闭的是**数据中台的职责边界**，不是声称下位机控制接口已经冻结。下位机接口细节仍由 Q-35～Q-44 跟踪。

## 6. 历史废弃假设

以下表述不得再出现在活跃设计或 Trellis 约束中：

- 调度系统发布 <code>business_status</code>，中台据此关闭按钮就完成了生产/调试互斥；
- 中台通知调度系统暂停、等待 Adapter 释放、修改运单为 PAUSED 后再夺权；
- 中台维护 control epoch、确认令牌、控制租约或本地锁表；
- 中台与调度系统共同更新同一订单行；
- Redis KV 是 v0.3 的统一车辆实时状态契约；
- Adapter/下位机直接写中台的订单执行摘要表；
- Redis Stream 事件可以不保留来源而无条件覆盖另一来源；
- 调度 gRPC 是基线必选端点。

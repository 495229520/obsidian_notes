# 初版调度系统数据库结构

> [!abstract]
> 本文整理初版调度系统的数据库结构，共 11 张表。机器人实时状态通过 Redis 心跳获取；MySQL 保留机器人档案、任务、地图、库位、历史记录和任务日志，不再维护机器人当前状态快照表或独立机器人报警表。任务资源等待和资源预留状态只存储在 Redis 中，不建立对应的 MySQL 表。

> [!note]
> `robot_current_state` 已移除。调度器读取实时状态时直接访问 Redis；`t_robotstatusrecord` 保存运行、电池和报警历史，`t_robotmotionrecord` 保存位置、速度、阻挡和减速历史。

> `t_windtaskresourcewait` 不纳入 MySQL 表清单。任务资源等待、资源预留和唤醒队列属于高频调度运行态，统一由 Redis 维护。
## 1. 表清单

| 分类 | 表名 | 作用 |
|---|---|---|
| 机器人 | `t_robotitem` | 机器人档案 |
| 机器人 | `t_robotstatusrecord` | 运行、电池和报警历史 |
| 机器人 | `t_robotmotionrecord` | 位置、速度、阻挡和减速历史 |
| 地图 | `t_mapversion` | 地图版本和激活状态 |
| 地图 | `t_mapnode` | 地图节点和节点运行状态 |
| 地图 | `t_mapedge` | 地图拓扑边 |
| 库位 | `t_worksite` | 库位业务信息和占用状态 |
| 任务 | `t_windtaskdef` | 任务模板 |
| 任务 | `t_windtaskrecord` | 任务订单和根任务记录 |
| 任务 | `t_windwaybillrecord` | 运单执行记录 |
| 可观测 | `t_windtasklog` | 任务日志 |

## 2. 机器人相关表

### 2.1 `robotItem` 机器人档案表（由数据中台管理维护，我需要读取其中调度电量阈值以及robot_code）

只保存稳定的机器人主数据和调度配置，不保存心跳中的状态、位置、电池、任务、报警或速度信息。

| 字段                      | 类型             | 注释                       | 用途                                |
| ----------------------- | -------------- | ------------------------ | --------------------------------- |
| `id`                    | `bigint`       | 主键 ID                    | 雪花算法内部主键                          |
| `robot_code`            | `varchar(64)`  | 机器人唯一编码                  | 对应心跳 `robot_code`，例如 `insMes0001` |
| `robot_name`            | `varchar(255)` | 机器人名称                    | 前端展示名称                            |
| `robot_type`            | `varchar(64)`  | 机器人类型                    | 例如 `AGV`、`AMR`                    |
| `online`                | `int`          | 是否在线                     | 0-离线，1-在线                         |
| `capacity`              | `int`          | 存储容量                     | 0，1，2                             |
| ```dispatch_blocked```  | `bool`         | 指令结果不确定时禁止继续分配，核实机器人后再解除 | true = 禁止分配/false = 继续分配          |
| `battery_min_threshold` | `decimal(5,4)` | 最低调度电量阈值                 | 范围 `0~1`，例如 `0.2000` 表示 20%       |
| `battery_max_threshold` | `decimal(5,4)` | 最高调度电量阈值                 | 范围 `0~1`，例如 `0.8000` 表示 80%       |
| `created_at`            | `datetime()`   | 创建时间                     | 机器人建档时间                           |
| `updated_at`            | `datetime()`   | 更新时间                     | 最后修改时间                            |

## 3. 地图与库位相关表

### 3.1 `mapVersion` 地图版本表

每次上传 `.smap` 都创建新版本，不覆盖正在使用的地图。

| 字段               | 类型              | 注释       | 用途                                |
| ---------------- | --------------- | -------- | --------------------------------- |
| `id`             | `bigint`        | 地图版本主键   | 雪花算法内部主键                          |
| `map_name`       | `varchar(255)`  | 地图名称     | 对应 `.smap` 的 `header.mapName`     |
| `source_version` | `varchar(64)`   | 源文件版本    | 对应 `.smap` 的 `header.version`     |
| `revision`       | `bigint`        | 地图运行约束版本 | 地图运行约束版本                          |
| `map_type`       | `varchar(64)`   | 地图类型     | 例如 `2D-Map`                       |
| `resolution`     | `decimal(10,4)` | 地图分辨率    | 例如 `0.02` 米                       |
| `min_x`          | `decimal(12,4)` | 最小 X 坐标  | 地图范围                              |
| `min_y`          | `decimal(12,4)` | 最小 Y 坐标  | 地图范围                              |
| `max_x`          | `decimal(12,4)` | 最大 X 坐标  | 地图范围                              |
| `max_y`          | `decimal(12,4)` | 最大 Y 坐标  | 地图范围                              |
| `source_file`    | `varchar(512)`  | 原始文件路径   | `.smap` 原文件位置                     |
| `file_hash`      | `varchar(64)`   | 文件哈希     | SHA-256，用于判断重复上传                  |
| `node_count`     | `int`           | 节点数量     | 导入统计和诊断                           |
| `edge_count`     | `int`           | 拓扑边数量    | 导入统计和诊断                           |
| `status`         | `int`           | 地图状态     | `DRAFT=0`、`ACTIVE=1`、`ARCHIVED=2` |
| `activated_on`   | `datetime`      | 激活时间     | 开始供新任务使用的时间                       |
| `created_at`     | `datetime()`    | 创建时间     | 地图版本创建时间                          |
| `updated_at`     | `datetime()`    | 更新时间     | 最后修改时间                            |

### 3.2 `mapNode` 地图节点表

一条记录对应 `.smap` 的一个 `advancedPointList` 命名点。

| 字段               | 类型              | 注释      | 用途                                           |
| ---------------- | --------------- | ------- | -------------------------------------------- |
| `id`             | `bigint`        | 节点主键    | 雪花算法内部主键                                     |
| `map_version_id` | `bigint`        | 地图版本 ID | 对应 `t_mapversion.id`                         |
| `node_code`      | `varchar(128)`  | 节点编码    | 对应 `instanceName`                            |
| `node_type`      | `varchar(64)`   | 节点类型    | `LocationMark`、`ActionPoint`、`ChargePoint` 等 |
| `x`              | `decimal(12,4)` | X 坐标    | 地图节点坐标                                       |
| `y`              | `decimal(12,4)` | Y 坐标    | 地图节点坐标                                       |
| `ignore_dir`     | `int`           | 忽略方向标记  | `0` 不忽略，`1` 忽略（机器人到达该节点时是否必须满足朝向要求）          |
| `created_at`     | `datetime()`    | 创建时间    | 地图节点创建时间                                     |
| `updated_at`     | `datetime()`    | 更新时间    | 最后修改时间                                       |

约束：同一地图版本内 `node_code` 必须唯一，匹配时使用完整字符串，不自动转换大小写或改名。

### 3.3 `mapEdge` 地图拓扑边表

一条记录对应 `.smap` 的一条 `advancedCurveList` 有向连接。

| 字段               | 类型              | 注释      | 用途                        |
| ---------------- | --------------- | ------- | ------------------------- |
| `id`             | `bigint`        | 拓扑边主键   | 雪花算法内部主键                  |
| `map_version_id` | `bigint`        | 地图版本 ID | 对应 `t_mapversion.id`      |
| `edge_code`      | `varchar(255)`  | 拓扑边编码   | 对应曲线 `instanceName`       |
| `edge_type`      | `varchar(64)`   | 拓扑边类型   | 例如 `DegenerateBezier`     |
| `from_node_code` | `varchar(128)`  | 起点节点    | 有向边起点                     |
| `to_node_code`   | `varchar(128)`  | 终点节点    | 有向边终点                     |
| `cost`           | `decimal(19,6)` | 路径代价    | 默认使用边长度，可由策略调整            |
| `geometry`       | `longtext`      | 几何 JSON | 起点、终点和控制点（用来保存边的完整几何形状）   |
| `direction`      | `int`           | 移动方向    | 控制小车正向移动还是倒向移动（正向-0，倒向-1） |
| `created_at`     | `datetime()`    | 创建时间    | 拓扑边创建时间                   |
| `updated_at`     | `datetime()`    | 更新时间    | 最后修改时间                    |

只有地图文件明确包含反向曲线时才保存反向边，不自动推导反向路径。
`geometry`列如：
```json
{
  "start": {"x": 1.0, "y": 2.0},
  "end": {"x": 5.0, "y": 6.0},
  "controlPoints": [
    {"x": 2.5, "y": 4.0}
  ]
}
```

### 4.2 `waybillRecord` 运单执行记录表

一条记录对应一次 `TaskDispatch` 下发。既保存不可变的下发快照，也保存该运单当前执行进度；同一 `task_id` 下可以存在多条不同的 `waybill_id`。

| 字段                | 类型              | 注释         | 用途                                                                                                                                                                                                                                               |
| ----------------- | --------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `id`              | `bigint`        | 主键 ID      | '自增id'                                                                                                                                                                                                                                           |
| `task_record_id`  | `varchar(64)`   | 任务记录业务 ID  | 对应 `taskrecord.task_id`                                                                                                                                                                                                                          |
| `waybill_id`      | `varchar(64)`   | 运单唯一 ID    | 对应下发 JSON 的 `waybill_id`，用于幂等接收和回调关联 时间戳+短ID W202608180001                                                                                                                                                                                       |
| `command_id`      | `varchar(64)`   | 当前下发指令唯一ID | 对应下发指令唯一id，用于幂等验证                                                                                                                                                                                                                                |
| `robot_code`      | `varchar(64)`   | 机器人唯一编码    | 对应 `robot_code`，逻辑关联 `t_robotitem.robot_code`                                                                                                                                                                                                    |
| `map_version_id`  | `bigint`        | 地图版本 ID    | 服务接收运单时绑定当前地图版本，保证站点解析和执行期间使用同一版本                                                                                                                                                                                                                |
| `type`            | `varchar(64)`   | 下发指令任务类型   | 下发指令任务类型，pickup / arrive / charge                                                                                                                                                                                                                |
| `station`         | `json`          | 站点执行快照     | 原样保存按 `order` 排序的站点、类型、目标 ID、产品和数量                                                                                                                                                                                                               |
| `status`          | `int`           | 运单状态       | - `DISPATCHED = 0` — 已调度，并预占库位点<br>- `PENDING = 1` — 已创建，尚未下发/开始<br>- `RUNNING = 2` — 执行中<br>- `PAUSED = 3` — 暂停<br>- `WAITING = 4` — 等待库位点释放<br>- `COMPLETED = 5` — 完成<br>- `CANCELLED = 6` — 取消<br>- `FAILED = 7` — 失败<br>- `TIMEOUT = 8` — 超时 |
| `command_sent_at` | `datetime`      | 最近下发时间     | 最后下发时间                                                                                                                                                                                                                                           |
| `started_at`      | `datetime`      | 开始时间       | 运单真正开始执行的时间                                                                                                                                                                                                                                      |
| `ended_at`        | `datetime`      | 结束时间       | 运单完成、取消、失败或超时的时间                                                                                                                                                                                                                                 |
| `ended_reason`    | `varchar(1024)` | 结束原因       | 失败、取消或超时说明，正常完成时可为 `NULL`                                                                                                                                                                                                                        |
| `created_at`      | `datetime`      | 创建时间       | 运单执行记录创建时间                                                                                                                                                                                                                                       |
| `updated_at`      | `datetime`      | 更新时间       | 最后修改时间                                                                                                                                                                                                                                           |

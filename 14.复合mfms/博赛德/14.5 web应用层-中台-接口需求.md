# Web只读展示：接口需求与实现范围

> 版本：v2.1｜日期：2026-09-19｜面向前端与中台开发者。
> 本版替代v1.0交付范围，保留原接口编号。原稿已备份至工程Trellis物流桥接任务research目录。

## 1. 本期边界

应用端分为任务系统和Web。任务系统下发搬运任务、处理门控、接收6/201/601反馈；Web只展示，不创建任务，不下发调度或设备控制指令。

任务清单和有效阶段由中台根据任务需求表及调度Stream整理。设备树、机械臂和底盘状态来自现有C++中台与ROS。前端不直接读取数据库或消费调度原始Stream，不在浏览器重建调度状态机。

| 结论 | 开发含义 |
|---|---|
| 可做 | 已核实有数据来源，可以列入开发；Web接口及联调仍需中台完成 |
| 部分可做 | 仅支持明确列出的字段，其余隐藏或显示未提供 |
| 补接入后可做 | 下层已有字段，但传递或关联不完整，接入前不能作为可用功能交付 |
| 当前不做 | 超出只读范围或本期数据不足，从交付清单移除 |

现有ROS/C++接口不是浏览器API。“可做”不代表已上线；原URL、10Hz及P95目标均须在实际接口设计和测试后确认。

## 2. 前端页面怎么调整

| 页面 | 能做 | 当前不能做 |
|---|---|---|
| 首页 | 接单数、各任务状态数量、已接入设备通信状态摘要 | 上下料产品件数、完整生产效率、完整活动告警计数 |
| 任务列表 | 每个taskCode一行，气罐、起终点、开门需求、当前状态，搜索/筛选/分页 | 每台车绑定当前物流任务、合单、优先级、内部调度任务 |
| 任务详情 | 原六字段、当前阶段、已有时间、结束原因、原始错误码 | 完整运单时间线、精确阶段等待时长、路径进度百分比 |
| 设备列表/详情 | 设备分组、通信状态、已支持机械臂与底盘数据 | 将groupId直接当调度robotCode，猜测设备与物流任务关联 |
| 机械臂 | 关节、末端位姿、速度倍率；法奥运行模式、急停和IO | 点动、使能、复位、IO写入、程序运行等操作 |
| 底盘 | 仙工电量、充电、速度、位置数值、定位可信度 | 无地图版本关联的车辆叠图、剩余路径、11态导航阶段 |
| 统计页 | 任务数、状态分布、按起终点编码汇总和明细下钻 | 上下料件数、按机器人产量、整机时间分布、OEE |
| 异常展示 | 已有任务原因、设备当前错误 | 完整告警历史、解除/确认操作与生命周期 |

## 3. 原接口逐项结论

路径仅用于对照v1.0，最终Web路由、DTO、认证与推送方式待冻结。

| 编号 | 原接口或用途 | 结论 | 本期范围 |
|---|---|---|---|
| S1 | GET /api/robots | 部分可做 | 设备ID、名称、类型、groupId与分组；不承诺能力位、电量阈值及调度robotCode映射 |
| S2 | WS /api/fleet/events | 部分可做 | 任务变化与已有设备遥测；不含命令结果，不承诺全车队同步10Hz |
| S3 | GET /api/robots/:robotCode/snapshot | 部分可做 | 设备快照需以明确deviceId寻址，不能直接套用原robotCode |
| S4 | GET /api/fleet/operations | 部分可做 | 设备状态和任务清单分别展示；暂不拼接每车当前物流任务 |
| S5 | GET /api/fleet/summary | 部分可做 | 通信状态计数；在线不等于空闲、工作或可执行 |
| M1 | GET /api/maps/active | 当前不做 | 缺本期地图几何、版本与ROS坐标系完整关联 |
| M2 | GET /api/stations | 当前不做 | 起终点编码可作筛选项，不能替代完整站点/库位台账 |

| T5 | GET /api/waybills | 当前不做 | 缺已接入的任务/运单关联与完整执行数据 |
| T6 | POST /api/navigation/execute | 当前不做 | 不下发导航 |

| P2 | GET /api/production/filter-options | 部分可做 | 只提供任务数据已有的日期、状态、气罐和起终点选项 |
| P3 | GET /api/production/records | 部分可做 | 改为物流任务明细下钻，不返回虚构quantity |

| Y1 | GET /api/system/info | 可做 | 服务时间、明确配置的业务时区、服务版本 |

原地图导入/激活、路径管理、机械臂调试控制及命令闭环验收全部移出本期。“当前不做”限定本期已接数据与职责，不代表系统永远不能支持。

## 4. 任务字段与状态字典

以下字段用于Web接口设计，待中台发布DTO后冻结。主身份保留taskCode，避免把物流任务编号伪装成调度内部taskId。

| Web建议字段 | 当前来源 | 展示规则 |
|---|---|---|
| taskCode | Record.task_code | 原字符串任务编号，关联主键 |
| containerCode | context.containerCode | 气罐编号，不作为件数 |
| startStorageCode/endStorageCode | context同名字段 | 业务编码；无坐标、中文名、占用信息 |
| startStorageOpenDoor/endStorageOpenDoor | context同名字段 | 是否需要开门，不是门实时状态 |
| taskStatus | Record.task_status | 当前已应用状态，保留原整数及统一展示名称 |
| arrivedStorageCode | Record.arrived_storage_code | 当前阶段到点关联，可空；状态6/10/201/601清空，不是实时位置 |
| createdAt/updatedAt | Record.created_at/updated_at | 中台落库/更新时间，不冒充现场事件发生时间 |
| startedAt/endedAt | Record.started_at/ended_at | 可空；不能用createdAt或updatedAt补成执行时间 |
| endedReason/errorCode | Record.ended_reason/error_code | 有值才展示，错误码保留原类型；中台不编造码义 |

起终点编码可以作列表筛选项，但不能据此生成完整站点库。门请求ID可作为排查信息按需提供，不是任务主键。数据库BIGINT如需暴露，应序列化为字符串，避免浏览器数字精度丢失。

### 当前阶段名称

| taskStatus | Web展示 | 依据 |
|---|---|---|
| 1 | 已生成 | 中台受理落库 |
| 2 | 已下发 | 调度已入队并建进度；不能据此推导startedAt |
| 3 | 已分配 | 已报告分配阶段；消息没有机器人编号，不能展示分配给哪台车 |
| 4 | 已到起点 | 调度到点；需门时结合门动作显示等待，不能一律当等待 |
| 5 | 起点门已打开 | 中台核验本次OPENED；不代表门现在仍开着 |
| 6 | 运送中（气罐已上车） | 取货上车事实；任务系统收到反馈6后自动关门 |
| 7 | 到终点，准备放下 | 调度到点；需门时结合门动作判断等待 |
| 8 | 终点门已打开 | 中台核验本次OPENED |
| 9 | 已放下 | 调度事实，不等于整单完成 |
| 10 | 车离开 | 调度事实，不等于整单完成 |
| 201 | 正常结束 | 整单完成 |
| 301 | 超时结束 | 现有实现限连续三次开门超时，不泛化成所有设备故障 |
| 601 | 手动取消 | 调度报告结果；不因此给Web增加取消按钮 |

已定义名称的100/202/501/502/503/504尚未接入当前Record合法转换；例如504收件SUCCESSED仅表示消息已保存。不能把诊断中的504直接当作已应用任务状态。若需要在Web展示这类原始上报，应独立标明“上报未应用”，另行设计。

原文t_windtaskrecord.status的0–6、运单status和物流taskDetailStatus是不同枚举。不得套用原文“6=TIMEOUT”。Web展示阶段多于任务系统反馈的6/201/601，两者是不同接口。

## 5. 机械臂、底盘与设备数据

| 可增加的展示 | 字段／来源 | 当前链路与边界 |
|---|---|---|
| 设备树与机械臂/底盘分组 | CommunicationInterface.deviceTree()；DeviceTreeRobot.groupId及各设备id/name/type | 已有C++快照与信号；同group_id分组，不等于调度robotCode或mapObjectCode，需要明确外部身份映射；多臂不默认选第一台 |
| 设备通信状态与最后收件时间 | deviceStatuses()/deviceStatusUpdated；hasHeartbeat、online、lastSeenMs、dbState | 已有全量摘要；支持Fr/Aubo/Seer状态话题。区分从未收到、过期和DB生命周期，不能把心跳在线当作设备可执行 |
| 机械臂关节与末端位姿 | FrRobotState/AuboRobotState：jt_cur_pos[6]、tl_cur_pos[6] | ROS→RobotRealtimeStatus→Worker→sendARMState/sendAuboARMState已有传递；统一结构标注度、mm/度，原msg未完整标单位，实际发布源仍需核对 |
| 机械臂名称、型号、速度倍率 | robot_name、robot_type、robot_speed | 两类机械臂均有数据；速度为百分比/倍率，不是末端m/s；名称型号可为配置值，不能冒充自动硬件识别 |
| 法奥运行与安全状态 | program_state、robot_motion_done、robot_mode、robot_err_code、emergency_stop | 已有转换传递；枚举解释按对应SDK版本核对。运动完成不等于物流任务完成 |
| 法奥IO只读展示 | 控制箱/工具数字输入输出、模拟输入输出 | 已有传递；位含义、模拟量单位及量程需按现场接线确认，不能推断夹罐或门已开 |
| 奥博控制器与安全状态 | mode_type、safety_mode_type | msg有枚举，ROS monitor已读并记录变化；convertAuboMessage及Worker重建消息未保留两字段，须补传递后才能可靠展示；默认0不是现场值 |
| 仙工底盘电量、充电和速度 | SeerCtrlState.battery_level、charging、vel_x/y/ang及电池电压温度等 | 已有转换/回传；电量[0,1]转百分比。只适用于该消息类型，不推广到所有底盘 |
| 仙工位置与定位可信度 | pose_x/y、angle、confidence、current_station、last_station | 已有数据；原消息位置/朝向经转换为mm/度再转回。current_station表示最近站点，不证明停靠。数值可展示，叠加地图还缺frame/map版本关联 |
| 仙工导航状态与目标站点 | guide_state.task_status/task_type/target_station | ROS消息已定义，但当前convertSeerMessage与Worker重建消息未保留guide_state；CommunicationInterface另有queryNavigationStatus/navigationStatusUpdated，Web接入时应选择并核验数据链 |
| 当前设备错误提示 | Fr.robot_err_code；Seer.err_code/err_msg；Aubo安全模式 | 可展示已提供的当前异常；Aubo无通用错误码字段，摘要errCode=0不能证明无故障。仍不等于完整告警生命周期/历史平台 |

### 设备展示限制

- 现有全量deviceStatuses主要是心跳/错误摘要；完整机械臂状态沿当前设备订阅链传递，Worker对AGV还有已连接设备组过滤。多设备Web完整快照/并发订阅需专门聚合，不能将当前Qt单设备选择逻辑直接当车队10Hz服务。
- 状态话题按完整deviceId命名：`/<deviceId>_state`；命令service用六位prefix。Web身份应来自订阅设备，不凭robot_index或robot_name猜测对应任务。
- 本地FrAdapterPublisher把robot_index、curtask_index、curstep_index分别写为0、0、1，软件版本也写固定字符串。不能用这些字段证明真实调度任务、执行步骤或实际固件版本；最终SDK发布节点的行为需另核对。
- Fr.robot_err_code为uint8，适配器从main_code赋值；不能声称保留所有完整厂商错误码。main_code/sub_code在msg标为弃用，不能把它们作为新的稳定Web契约。
- AgvOrderState.msg定义了单号、步骤、loaded/unloaded等，但本次核对的SeerCtrlState不包含该消息；定义存在不足以证明已接入中台，暂不据此恢复子运单或取放料台账承诺。
- ROS状态消息没有统一源时间戳；lastSeenMs和转换时间为中台收件时间，不是机器人实际采样时间。机械臂/底盘/任务状态来自不同源，不承诺同一帧同步；应分别标来源和更新时间。
- 有srv控制接口不意味着Web要开放控制。点动、急停指令、IO写入、导航等仍不纳入只读界面。

## 6. 统计、刷新和缺失数据

- 每个taskCode计一单，不能按Stream消息或重投次数计数；气罐编号不能自动折算产品件数。
- 今日接单数按createdAt分日；今日完成数要求201和真实endedAt。缺少结束时间只能纳入当前状态分布，不能猜成今天完成。
- 选定创建日期的一批任务，其当前完成数应标为“该批任务已完成数”，不能叫“当日完成数”。301单列超时，未知/未完成不一律算失败。
- 列表、统计和下钻使用明确一致的筛选规则；业务时区和asOf由中台提供，不按浏览器时区自行改日界。原七维生产筛选与交付台账本期撤下。
- 任务Stream没有新事件不代表设备离线；设备质量依据ROS实际收件判定。当前心跳约3秒窗口不等于已冻结Web SLA，不照搬原Mock的1秒在线/8秒过期规则。
- 首次无数据、已过期、不支持字段和有效数据须区分。缺值显示未提供或隐藏，不填0电量/0位姿/正常；真实0或false不能被误当缺失。
- 任务、机械臂、底盘分别标识数据来源与更新时间；中台收件时间不是源采样时间，不保证同步帧。
- 5/8是某次开门完成事实，6是上车事实，不能当持续门传感器或载荷传感器。任务系统收到反馈6自动关门，无需Web操作。
- 只有开始/结束时间齐全且含义核实时才计算耗时；不以状态编号计算百分比，不用页面首次看见某状态的时间伪造等待时长。

## 7. 前后端责任与验收

中台提供只读DTO、查询/刷新接口、设备身份、单位、有效状态及数据质量；发布样例和OpenAPI或等价说明。任务状态由中台持久化、排序、去重和校验，前端展示已应用结果。设备多源汇总需在中台补齐，不能把现有Qt单设备订阅直接当车队推送服务。

前端按本文移除不支持的页面字段和控制入口；Mock仅用于开发且明确标识，不混入真实页面。最终路由、认证、推送方式、刷新频率及性能目标在接口设计时冻结。

验收项：

1. 原六字段与任务系统一致；搜索、筛选、分页和统计明细一致，同任务不重复计数。
2. 到点、OPENED、上车和终态按有效事实展示；乱序或重投不使状态倒退。
3. 无需开门、缺时间、301和601均有正确显示，不伪造完成阶段。
4. 机械臂数据与对应设备核对单位、模式、IO；奥博尚未传递字段不显示默认正常。
5. 仙工电量百分比、设备身份正确，多设备切换不串数据；没有地图关联时只显示位置数值。
6. 首帧无数据、ROS断流、Web断线和重连分别验证，任务无新事件不触发设备离线。
7. 不存在任务写操作、导航、路径修改或机械臂/IO控制入口。

本次范围确认不代表Web API、现场字段或性能已验收；物流桥接已有测试不能代替Web验收。

## 9. 逐字段数据来源（前后端对照表）

下表的Web字段是建议命名，最终以中台发布DTO为准；来源字段是当前代码中的实际名称。Web只消费中台接口，不直接连ROS、Redis或MySQL。

### 9.1 来源名称与关联键

| 标识 | 实际来源 | 如何关联 |
|---|---|---|
| 任务DB | MySQL `logisticsTaskRecord` | `task_code`对应任务系统`taskCode`；`context`保存原六字段JSON |
| 调度Stream | Redis `bosaide:scheduler:events`，消费组`middleware` | 每条只有`data`字段，其值为JSON；解析其中`taskCode`关联Record，`eventId`去重，`sequence`按任务排序 |
| 返回Stream | Redis `bosaide:middleware:results` | 给调度的收件/门结果，不作为Web任务状态来源；其中`status=SUCCESSED`不代表任务成功 |
| FR ROS | `com_interfaces/msg/FrRobotState.msg` | topic为`/<完整deviceId>_state`，设备身份取订阅上下文 |
| Aubo ROS | `com_interfaces/msg/AuboRobotState.msg` | 同上；不能依靠消息`robot_index`猜设备身份 |
| Seer ROS | `com_interfaces/msg/SeerCtrlState.msg` | 同上，含`base/AgvGuideState.msg`定义的`guide_state` |
| 设备DB | `device_state`左连接`device`，条件`device_state.id=device.id` | 属于设备管理数据库表，不是物流任务需求表 |
| 中台派生 | `DeviceRuntimeStatus`、设备树、查询聚合结果 | 明确列出计算规则；不是上游原始字段 |

现场Stream名称可通过配置覆盖，上表为当前约定名称。com_interfaces是ROS接口包；CommunicationInterface是中台C++对外接口，两者不是同一个层次。

### 9.2 任务字段：原始来源 → 落库字段 → Web

| Web字段/展示 | 原始来源 | Web读取的中台事实字段 | 转换与限制 |
|---|---|---|---|
| taskCode | 任务系统接单JSON `taskCode` | `logisticsTaskRecord.task_code` | 字符串原样保留；`context.$.taskCode`亦保留原单 |
| containerCode | 任务系统JSON `containerCode` | `logisticsTaskRecord.context.$.containerCode` | JSON路径，不是单独SQL列 |
| startStorageCode | 任务系统JSON同名字段 | `logisticsTaskRecord.context.$.startStorageCode` | 起点业务编码 |
| endStorageCode | 任务系统JSON同名字段 | `logisticsTaskRecord.context.$.endStorageCode` | 终点业务编码 |
| startStorageOpenDoor | 任务系统JSON同名字段 | `logisticsTaskRecord.context.$.startStorageOpenDoor` | JSON布尔值，是否需要开门 |
| endStorageOpenDoor | 任务系统JSON同名字段 | `logisticsTaskRecord.context.$.endStorageOpenDoor` | 同上，不是当前门状态 |
| taskStatus | 调度Stream `data`解析后的`taskStatus`；状态1由中台创建，5/8由OPENED生成 | `logisticsTaskRecord.task_status` | 只读已应用结果，不取Stream最后一条直接覆盖 |
| arrivedStorageCode | 调度Stream `storageCode`，到点状态4/7携带 | `logisticsTaskRecord.arrived_storage_code` | 当前阶段的到点关联；进入6/10/201/601会清空，不能当永久最后位置 |
| requestOpenDoorId（按需） | 中台在需门4/7时生成 | `logisticsTaskRecord.door_request_id` | 当前门请求关联；进入6/10/201/601会清空 |
| createdAt | 中台接单事务`UTC_TIMESTAMP(3)` | `logisticsTaskRecord.created_at` | 中台接单落库时间，不是任务系统生成时间 |
| updatedAt | 中台应用事件或OPENED时`UTC_TIMESTAMP(3)` | `logisticsTaskRecord.updated_at` | 中台业务记录更新时间，不是设备采样时间 |
| startedAt | 调度Stream可选`startedAt` | `logisticsTaskRecord.started_at` | 当前解析支持UTC RFC3339毫秒；未提供保留已有值/空值，不能由状态2推算 |
| endedAt | 调度Stream可选`endedAt` | `logisticsTaskRecord.ended_at` | 可空；当前解析仅允许结束类201/301/601携带 |
| endedReason | 调度Stream可选`endedReason` | `logisticsTaskRecord.ended_reason` | 未提供不编造；缺省保留已有值 |
| errorCode | 调度Stream可选`errorCode` | `logisticsTaskRecord.error_code`（JSON） | 保留JSON标量类型；不将任务错误码与机械臂错误码混用 |

`context.$.字段`表示JSON列内路径，例如 `JSON_EXTRACT(context, '$.containerCode')`；不是名称带点的数据库列。

门完成事实是例外来源：任务系统四字段回调`requestOpenDoorId/taskCode/storageCode/doorStatus=OPENED` → 中台校验 → Record.task_status写5或8。它不是调度直接上报的5/8，也不是ROS IO推测。生产回调入口仍待接入。

### 9.3 Stream与数据库中容易误用的字段

| 字段 | 实际用途 | 不能怎么用 |
|---|---|---|
| Stream `eventId` | 原始事件唯一身份 | 不能作为taskCode、设备ID |
| Stream `sequence` | 单任务调度事件顺序号 | 不能作为阶段百分比、状态码或完成步骤数 |
| `logisticsBridgeEvent.payload` / `apply_state` | 中台私有原始事件与RECEIVED/APPLIED/REJECTED | 收到不等于已应用；不直接对外开放私有表 |
| `logisticsBridgeEvent.created_at` | 中台收件持久化时间 | 不能冒充现场阶段开始/结束时间 |
| `logisticsBridgeDoor.delivery_state` | PENDING/RECEIVED/OPENED/STALE/FAILED门动作进度 | 可由中台按当前request_id整理门等待/失败；不是实时门传感器 |
| `logisticsBridgeDoor.last_error` | 门处理的最近错误记录 | 可能是暂时重试原因，不单独证明最终门失败 |
| `logisticsTaskOutBox.status` | 0/1/2/3初始任务交接状态 | 不能当taskStatus、机器人状态或任务完成率 |
| 返回Stream `taskStatus` | 对应原调度状态；门成功仍返回4/7 | 不能替代Record中已确认的5/8 |

### 9.4 机械臂逐字段来源

以下ROS字段是原始字段，不是任务数据库列。当前常规链路为ROS → MfmsRosBridge → RobotRealtimeStatus → CommunicationWorker → CommunicationInterface；Web还需适配。

| Web展示/建议字段 | com_interfaces消息及字段 | 当前中台字段/出口 | 可用性与转换 |
|---|---|---|---|
| 名称 robotName | `FrRobotState.robot_name` / `AuboRobotState.robot_name` | `RobotRealtimeStatus.robotName` → `sendARMState` / `sendAuboARMState` | 已传递，设备列表名另见设备DB |
| 型号 robotType | 两种消息`.robot_type` | `robotType`，Aubo为空时回退“奥博机器人” | 可显示，但可能是配置名称 |
| 速度倍率 speedPercent | 两种消息`.robot_speed` | `RobotRealtimeStatus.speed` | 已传递；百分比，不是m/s |
| 关节 jointPositions | 两种消息`.jt_cur_pos[0..5]` | `RobotRealtimeStatus.jointPos[0..5]` | 数值原样复制；统一结构约定度，实际发布源单位仍须核对 |
| 末端 tcpPose | 两种消息`.tl_cur_pos[0..5]` | `RobotRealtimeStatus.cartPos[0..5]` | 原样复制；统一结构约定XYZ为mm、RX/RY/RZ为度 |
| 程序状态 programState | `FrRobotState.program_state` | `programState` | 已传递；枚举按实际SDK核对 |
| 运动完成 motionDone | `FrRobotState.robot_motion_done` | `motionDone=(原值!=0)` | 已传递；不表示任务完成 |
| 手动/自动 robotMode | `FrRobotState.robot_mode` | `robotMode` | 已传递，不能套用Aubo模式枚举 |
| 急停 emergencyStop | `FrRobotState.emergency_stop` | `emergencyStop=(原值!=0)` | 已传递，只展示 |
| 错误码 errorCode | `FrRobotState.robot_err_code` | `RobotRealtimeStatus.errorCode`；摘要`errCode` | uint8；不承诺完整厂商错误码位宽 |
| 控制箱DO | `FrRobotState.cl_dgt_output_h/l` | `io.digitalOutputH/L` | 位图，高字节15–8，低字节7–0 |
| 控制箱DI | `FrRobotState.cl_dgt_input_h/l` | `io.digitalInputH/L` | 同上 |
| 模拟输入/输出 | `FrRobotState.cl_analog_input[2]` / `cl_analog_output[2]` | `io.analogInput/analogOutput` | 原始值；量程与电压换算未确认 |
| 工具DO/DI | `FrRobotState.tl_dgt_output_l` / `tl_dgt_input_l` | `io.toolDigitalOutput/toolDigitalInput` | 仅bit0/bit1，接线业务含义另定 |
| 奥博控制器模式 | `AuboRobotState.mode_type` | monitor有读取；通用转换未保留 | 补接入后可做，不能读取重建消息的默认0当真值 |
| 奥博安全模式 | `AuboRobotState.safety_mode_type` | 同上 | 补接入后可做；无通用robot_err_code |

法奥本地适配器的`curtask_index=0`、`curstep_index=1`是固定值，`robot_soft_index`也是固定字符串；不纳入可信任务进度/固件版本展示。`FrCmdInterface.srv`与`AuboCmdInterface.srv`响应有`pub_state`，但服务响应中的`err_code`表示该次调用结果，不等于持续设备错误；Web不因存在srv而新增控制能力。

### 9.6 设备台账、在线状态与统计来源

| Web字段/展示 | 精确来源 | 计算/回退规则 |
|---|---|---|
| deviceId | `device_state.id`，连接`device.id` | 原完整设备ID；ROS订阅携带此身份 |
| groupId | `device.group_id` | 当前查询COALESCE为0；无配置的0不能证明一台真实复合机器人 |
| 设备名称 | `device_state.info.$.name` | 空时回退设备ID；与ROS robot_name分开识别 |

| DB生命周期 dbState | `device_state.state` | 当前列表筛选offline/load/online/connected，非完整永久资产清单 |
| 命令前缀（中台内部） | `device.topic_prefix` | 不用它代替完整状态topic，也不作为Web设备主键 |

| online | `DeviceRuntimeStatus`派生 | hasHeartbeat且lastSeenMs>0且当前时间-lastSeenMs≤3000ms；非数据库online字段透传 |
| 各任务状态数量 | Record按`task_status`分组计数 | task_code唯一；不数Stream条数 |
| 今日接单数 | Record.created_at按明确业务时区分日 | 无需quantity |
| 今日完成数 | Record.task_status=201且ended_at落入当天 | ended_at为空排除该时间口径，不能用updated_at补齐 |
| 通信状态数量 | deviceStatuses()当前设备集合 | 无数据/不支持与在线/过期分开；不能等同工作/空闲/故障数量 |

### 9.8 实现核对位置

任务链：`src/mfms_server/tools/logistics_bridge/schema.sql`、`repository.py`、`events.py`、`stream_repository.py`。设备定义：`src/com_interfaces/msg/`。设备读取/转换：`src/mfms_server/ros_bridge/src/MfmsRosBridge.cpp`及`ros_bridge/include/ros_bridge/RobotTypes.h`。前端C++出口：`client_api/src/CommunicationWorker.cpp`、`client_api/include/mfms_server/CommunicationInterface.h`。设备树：`client_api/src/DeviceTreeBuilder.cpp`。心跳结构：`common/include/mfms_common/DeviceStatus.h`。

以上为当前本地代码核对，未替代现场ROS发布、数据库部署与Web联调。新增Web适配不得把缺字段默认值当成真实上报。

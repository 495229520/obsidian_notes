# MFMS_BASE 数据库结构

> [!abstract]
> 按项目 `src/mfms_server/MFMS_BASE.sql` 整理，共 **15张表、2个触发器**，涵盖设备配置与状态、AGV路径、机械臂点位、Lua脚本、事件、日志与用户。本文保留实际表名、字段类型、默认值和约束，不包含原SQL中的业务数据、脚本正文、设备地址或账户记录。

> [!note]
> SQL导出时间：2026-06-25 21:45:54；整理日期：2026-09-19。原文件为MySQL 8.0.46导出，不能据此声称现场数据库当前结构已核验。所有表使用InnoDB、utf8mb4、utf8mb4_0900_ai_ci及DYNAMIC行格式。
>
> 本SQL不包含 `logisticsTaskRecord`、`logisticsTaskOutBox` 和 `logisticsBridge*`。物流桥接新增表来自独立的 `tools/logistics_bridge/schema.sql`，不混入本次15张表清单。参考文档只用于排版，不把调度系统的表名或约定移植到本数据库。

## 2. 设备与设备事件

### 2.1 `device` 设备配置表

保存设备唯一标识、所属下位机控制器、连接地址及命令端点前缀。

| 字段 | 类型 | 注释 | 用途与约束 |
|---|---|---|---|
| `id` | `varchar(10)` | 设备唯一辨识符 type_3 + module_3 + id_4 | 设备唯一标识：type_3 + module_3 + id_4。 不可空。 |
| `group_id` | `int` | 设备组id，唯一标识了下位机控制器 | 设备组/下位机控制器标识；与物流任务编号无关。 不可空。 |
| `address` | `varchar(50)` | 设备地址 | 设备连接地址，语义由设备类型确定。 不可空。 |
| `create_ts` | `bigint` | 创建时间 | 设备创建时间数值；SQL仅定义bigint，单位需核对写入方。 可空；默认 NULL。 |
| `topic_prefix` | `varchar(10)` | 端点前缀(type_3+module_3) | 命令端点前缀；状态topic仍使用完整设备ID。 可空；默认 NULL。 |

约束与索引（按原DDL）：

- `PRIMARY KEY (`id`) USING BTREE`

### 2.2 `device_state` 设备状态表

保存设备生命周期状态、设备详细JSON和错误码。此表状态不等于ROS实时心跳判定。

| 字段 | 类型 | 注释 | 用途与约束 |
|---|---|---|---|
| `id` | `varchar(10)` | 设备唯一辨识符 type_3 + module_3 + id_4 | 完整设备ID，逻辑对应device.id；未声明外键。 不可空。 |
| `state` | `enum('offline','online','load','unload','connected')` | 设备状态 | 当前状态，枚举见下文。 不可空；默认 'offline'。 |
| `info` | `json` | 设备详细信息（JSON） | 设备详细信息JSON；DDL未约束内部键。 不可空。 |
| `err_code` | `int` | 错误码 | 设备错误码，可空；具体码义由设备定义。 可空；默认 NULL。 |

约束与索引（按原DDL）：

- `PRIMARY KEY (`id`) USING BTREE`

`state`：offline离线、online在线、load请求加载、unload请求卸载、connected已连接。数据库生命周期状态与ROS心跳新鲜度分开判断。`info`中的name/module/type等键由上游写入与中台解析约定，DDL没有固定JSON Schema。

### 2.3 `device_state_event` 设备请求事件表

记录进入load/unload的状态变化，供下位机侧处理设备加载、卸载请求。

| 字段 | 类型 | 注释 | 用途与约束 |
|---|---|---|---|
| `id` | `bigint` | SQL未写COMMENT | 记录主键；是否自增见约束列。 不可空；AUTO_INCREMENT。 |
| `device_id` | `varchar(10)` | SQL未写COMMENT | 所属设备的完整ID。 不可空。 |
| `from_state` | `enum('offline','online','load','unload','connected')` | SQL未写COMMENT | 变化前的状态。 不可空。 |
| `to_state` | `enum('offline','online','load','unload','connected')` | SQL未写COMMENT | 变化后的状态。 不可空。 |
| `reason` | `varchar(255)` | SQL未写COMMENT | 状态变化原因/执行说明，可空。 可空；默认 NULL。 |
| `created_at` | `timestamp` | SQL未写COMMENT | 记录创建时间；具体默认及自动更新时间见约束。 可空；默认 CURRENT_TIMESTAMP；更新行时自动刷新CURRENT_TIMESTAMP。 |

## 6. 触发器与事件流

### 6.1 `trg_device_state_event`

触发时机：`AFTER UPDATE ON device_state`，逐行执行；只有旧状态与目标状态不同时才插入对应事件。SQL未定义INSERT触发器。

| 新状态 | 写入表 | 原因来源 |
|---|---|---|
| load | device_state_event | 会话变量`@change_reason` |
| unload | device_state_event | 会话变量`@change_reason` |
| online | device_ui_event | 固定文本“设备加载完成” |
| connected | device_ui_event | 固定文本“设备连接成功” |
| offline | device_ui_event | 根据旧状态区分卸载完成、加载失败、连接断开、异常离线或普通离线 |

请求方向是上位机提出加载/卸载，反馈方向是设备侧报告状态变化。会话变量必须在执行UPDATE的同一数据库会话设置，否则可能为空或不是预期原因。

### 6.2 `trg_lua_state_event`

触发时机：`AFTER UPDATE ON lua_state`，逐行执行，仅记录进入指定新状态的变化。

| 新状态 | 写入表 | 原因来源 |
|---|---|---|
| ready / abort / pause / resume | lua_state_event | 会话变量`@change_reason_lua` |
| running / wait / paused / aborted | lua_ui_event | 更新后记录的`NEW.reason` |

四类事件表由触发器插入事件，事件消费及清理策略由程序控制；本SQL没有声明队列领取、消费确认或保留期限字段。

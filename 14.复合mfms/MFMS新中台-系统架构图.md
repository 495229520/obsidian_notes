### 1. 核心分层与组件职责
* **L5/L6 上位应用层**：MES / SCADA / Qt GUI / Web Dashboard / 开发者运维工作台。
* **L4 MFMS 数据中台**：C++ 单进程模块化单体，部署于局域网工控机。职责限于订单校验受理、只读 OrderView 组装、控制透传与审计、实时流接入及 StateManager 快照维护。
* **L3 调度系统**：多实例集群，以 `order_uid UNIQUE` 约束原子抢占认领订单，拆解工艺工单，单写 `execution` 摘要与 `binding` 映射。
* **L2 Adapter**：接收调度执行单元，调 ADK 向下位机申请生产控制权并下发路径动作，向 Stream 发布 `AgvOrderState` 进度事实。
* **L1 下位机核心**：**真实控制权唯一权威与终极裁决者**，独占存储持有者，原子裁决 `Query/Acquire/Force/Release`；收到任何动作指令前执行【持有者身份 + 硬件物理安全】双重前置校验；向 Stream 发布物理遥测与 `AgvControl` 快照。
* **L0 物理设备层**：AGV 底盘（SEER / VirtAgv）、机械臂机构（FrRobot / AuboRobot）、力觉传感器、PLC / 夹爪。

---

### 2. 四大横向解耦总线与数据流向
1. 🔵 **【订单业务通道】（MySQL 存储）**：中台 `OrderIntakeService` 单写 `mfms_order_request`，调度多实例从中扫描未认领工单。
2. 🟣 **【执行与绑定通道】（MySQL 存储）**：调度系统单写 `mfms_order_execution` 与 `mfms_order_execution_binding`，中台 `OrderQueryService` 跨表聚合读取组装只读 `OrderView`。
3. 🔴 **【控制访问与调试总线】（服务调用）**：中台与 Adapter 向下位机投递申请/指令，下位机独占接收、原子裁决并执行前置双重安全校验。
4. 🟢 **【Redis Stream 实时事实总线】（统一消息信封）**：下位机与 Adapter 发布实时事实，中台 `RedisStreamIngestor` 消费解码更新 `StateManager` 内存快照。

## 🚫 四大红线与架构铁律（v0.3）

> [!danger] 红线禁区（中台明确不拥有）
> 1. **严禁在中台实现控制权状态机与锁表**：控制权是下位机物理资产，中台仅为透传者，绝不维护 lease 租约、fencing token、control epoch 或 confirmation token。
> 2. **持久化按字段所有权单写隔离**：中台单写 request，调度单写 execution/binding，双方绝不并发改写同一行数据。
> 3. **实时事实单向广播且快照非凭据**：StateManager 快照仅供前端只读展示，过期断流置 `UNKNOWN/STALE` 禁用调试，绝不能作为持权执行凭据。
> 4. **超时属于“结果未知”**：下位机调用超时时，页面必须先通过 `QueryControl` 查询确认当前状态，严禁盲目重复发起强制夺权。

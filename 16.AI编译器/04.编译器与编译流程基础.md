# 编译器与编译流程基础

由原 `01.md` 整理，保留其中关于编译与解释、Token、语法和语义分析的问题，并修正概念混淆。

## 1. 编译器与解释器

Compiler 是编译器，Interpreter 是解释器。

| 方式 | 主要过程 | 产物 |
|---|---|---|
| 编译 | 把源程序转换为另一种程序表示 | 例如 IR、汇编、机器码或字节码 |
| 解释 | 按程序语义执行程序，并处理运行时输入 | 本次执行的结果 |

通常所说的提前编译，是先生成可执行程序，再用不同数据运行它。只换输入数据、不改程序时，通常不必重新编译。这里的“离线”表示编译与这次运行分开，不是指断开网络。

这个区别不是绝对的时间划分。JIT 在程序运行期间编译代码；一个系统也可以同时使用解释执行和 JIT。

## 2. 词法、语法与语义分析

以表达式 `a == b` 为例：

| 阶段 | 处理什么 | 示例 |
|---|---|---|
| 词法分析 | 把字符划分为 Token | 标识符 `a`、运算符 `==`、标识符 `b` |
| 语法分析 | 按语言语法识别结构 | 构成一个有左右操作数的相等比较表达式 |
| 语义分析 | 检查名称、类型及相关语言约束 | `a`、`b` 是否声明，类型是否允许比较 |

`=` 和 `==` 都可以是一个 Token。`=` 通常用于赋值，`==` 用于相等比较；Token 的数量不等于字符数。`if`、`else`、`while` 是不同关键字，`if` 和 `else` 不属于循环。

语法分析关心结构是否合法，语义分析检查该结构在语言规则下是否成立。语义分析不能简单写成“把高级语言翻译成加减运算”。生成 IR 与后续代码生成还需要各自的转换步骤。

[Clang 内部手册](https://clang.llvm.org/docs/InternalsManual.html#the-sema-library)说明，Clang 的 Parser 在解析过程中调用 Sema 完成语义分析，并为合法结构构建 AST。因此，教学上分开讲的阶段，在实现中可以交错进行。

## 3. 与 MLIR 学习的联系

先把编译过程理解为“源码结构 → 中间表示 → 变换与逐步降低抽象层次 → 目标代码”。这是一条简化路径，具体工具链还可能包含预处理、汇编和链接。

MLIR 学习主要从中间表示与变换开始。第一版 MiniNN 可以直接接收 MLIR 文本，复用解析设施；无需先完整实现一门语言的词法与语法分析器。下一步查看 [[16.AI编译器/03.MLIR学习与项目实践指南#2. 学习顺序与资料分工|学习资料与实验的对应关系]]。

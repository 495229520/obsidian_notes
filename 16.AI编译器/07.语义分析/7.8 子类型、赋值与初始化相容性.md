# 7.8 子类型、赋值与初始化相容性

COOL 中普通类的子类型关系由继承树确定。记 $A\le B$ 表示 A 符合 B 的类型要求，允许把 A 类型的结果用于需要 B 的位置。

## 1. 子类型的方向

关系具有自反性和传递性。若 Dog 继承 Animal、Animal 继承 Object，则：

$$Dog\le Animal\le Object.$$

Dog 可以初始化 Animal 变量；反方向不成立。这里是类型相容性，不是类型名称大小，也不要求将子类对象转换成一个独立的父类对象。

在有效单继承树上，检查 A ≤ B 可以从 A 开始沿父类向上找 B，遇到则成功；走到根仍找不到则失败。复杂度取决于继承树高度。SELF_TYPE 要单独处理，不能当普通类节点。

## 2. 几类检查共用同一个方向

| 位置 | 相容条件 |
|---|---|
| let 初始化 | 初值类型 ≤ 变量声明类型 |
| 属性初始化 | 初值类型 ≤ 属性声明类型 |
| 赋值 | 右侧表达式类型 ≤ 目标变量声明类型 |
| 方法实参 | 实参表达式类型 ≤ 形参声明类型 |
| 方法返回 | 正文表达式类型 ≤ 声明返回类型 |

不能将“初始化类型”与“let 正文类型”比较；两者承担不同作用。也不能因为一次初始化合法，就把变量的声明类型永久改成初值类型。

## 3. 赋值表达式自己的类型

$$\frac{O(x)=T_x\qquad O\vdash e:T_e\qquad T_e\le T_x}
{O\vdash x\leftarrow e:T_e}$$

如果 pet 声明为 Animal，那么：

| 对象 | 类型 |
|---|---|
| pet 变量引用 | Animal |
| new Cat | Cat |
| pet ← new Cat 整个赋值表达式 | Cat |

赋值结果取右侧表达式类型，变量绑定仍是 Animal。后面的 `pet` 引用不会因为刚赋了 Cat 就自动变成 Cat；本章采用 COOL 的常规规则，不做流敏感类型细化。

self 不能成为赋值目标，哪怕右侧类型看似相容也不行。类型相容是必要检查之一，不能代替名称和特殊标识符规则。

## 4. 类属性的初始化环境

属性初值在类属性环境下检查，环境包括当前类与继承来的属性以及 self。和 let 不同，当前属性声明也已登记，其他写在后面的属性也可以查到。

但“名称可见”与“运行时初值已经计算出来”是两回事。静态类型检查不执行属性初始化，也不能仅凭查到声明就断言读取到哪个运行时值。

## 5. 相容不等于所有运算都允许

Int ≤ Object 不代表可以对两个静态类型为 Object 的表达式执行加法。Add 规则仍要求操作数静态类型为 Int。

子类型相容解决“某个值能否用于这个类型位置”；具体运算和成员访问仍根据相应静态类型规则判断。分支结果如何选择公共类型见 [[7.9 LUB、if 与 case 的类型汇合]]。

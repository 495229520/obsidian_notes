# 7.6 类型推理规则、证明树与基础表达式

类型规则说明：子表达式及其他条件满足什么要求时，当前表达式可以得到什么类型。检查器根据 AST 节点选择规则，递归验证前提，再写入结论类型。

## 1. 如何读规则

$$\frac{O\vdash e_1:Int\qquad O\vdash e_2:Int}{O\vdash e_1+e_2:Int}\ [Add]$$

O 表示类型环境，`⊢` 读作“在这些假设下可推导”。横线上方是需要成立的前提，下方是结论。横线不是除法，冒号也不是运行时转换。

有些前提是递归类型判断，有些是查表或比较，例如类型是否存在、参数个数是否一致、子类型关系是否成立。不是每一个前提都需要递归调用。

## 2. 字面量与证明树

整数字面量 i 的类型为 Int，布尔字面量为 Bool，字符串字面量为 String。它们没有需要递归检查的子表达式，可作为证明的叶子。

对 `1 + 2`：

$$
\frac{
\frac{}{O\vdash1:Int}\ [Int]
\qquad
\frac{}{O\vdash2:Int}\ [Int]
}{O\vdash1+2:Int}\ [Add]
$$

先确定两个子节点为 Int，再用 Add 规则得到父节点类型。证明类型不需要把表达式求值成 3。

在这类语法制导规则中，证明与 AST 的递归结构紧密对应。但带有环境比较、子类型或额外转换规则时，不能断言所有证明树都与 AST 严格一一同构。

## 3. 基础表达式规则

| 表达式 | 主要检查 | 结果类型 |
|---|---|---|
| 整数、布尔、字符串字面量 | 字面量类别 | Int、Bool、String |
| e1 + e2 | 两个操作数均为 Int | Int |
| not e | e 为 Bool | Bool |
| new T | T 是合法可创建类型 | T |
| { e1; …; en; } | 检查所有子表达式 | 最后一个 en 的类型 |
| while c loop b pool | c 为 Bool，b 也须合法 | Object |

new SELF_TYPE 的特殊解释留到 [[7.11 SELF_TYPE 与精确返回类型]]。不能因为 new 没有子表达式，就遗漏类型名合法性检查。

COOL 的布尔取反写作 not，`~` 是整数取反。规则必须对应实际语言语法，不能照搬其他语言的运算符写法。

## 4. while 为什么不是正文类型

$$\frac{O\vdash c:Bool\qquad O\vdash b:T}{O\vdash\text{while }c\text{ loop }b\text{ pool}:Object}$$

COOL 规定循环正常结束后返回 void，整个循环的静态类型固定为 Object。即使正文最后算出 Int，也不把这个 Int 当作循环结果。

正文可能执行零次，但“执行零次”本身不能推导出必须选择 Object；最终仍是语言规范作出的规定。

## 5. 如何把公式读成检查步骤

以 Add 为例：检查左子树，检查右子树，验证两者都是 Int，给当前节点注解 Int。若有错误，记录诊断并按恢复策略返回，不能未检查就无条件写 Int。

变量节点还需要 O 查表，let 还要改变正文环境，见 [[7.7 类型环境 O 与 let 规则]]。公式中的 O 是抽象映射，不要求每次调用都复制整张表。

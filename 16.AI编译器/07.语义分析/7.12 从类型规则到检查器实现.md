# 7.12 从类型规则到检查器实现

前置阶段已经建立类表、有效继承树和方法签名后，表达式检查器递归遍历 AST：环境向下传，类型向上返回，同时记录诊断并给节点写入注解。

## 1. 接口需要表达哪些结果

可以采用接口 `check(expr, O, M, C)`，返回推导类型并将诊断写入诊断器；也可以返回包含类型和错误状态的结果对象。

如果练习中使用 bool 返回是否成功、把类型写入节点字段，也可以实现。但要明确：bool 只表示检查状态，表达式类型仍需另外保存；失败路径不能留下未初始化类型供父节点读取。

节点的 kind 由 AST 构造决定。检查器依据 kind 选择规则，不应通过检查过程把 Add 节点变成 IntLiteral；Add 的结构类别与结果类型 Int 是不同信息。

## 2. Add 的前提对应什么代码

```text
checkAdd(node, env):
    leftType ← check(node.left, env)
    rightType ← check(node.right, env)
    分别检查两个已知操作数类型是否为 Int
    若有类型错误，记录诊断并返回恢复结果
    否则注解当前节点为 Int，返回 Int
```

递归调用检查的是任意子表达式，不只是变量。例如左操作数可能是 let、方法调用或字面量，不能先拿整个 Add 去 O 中查“是否注册”。只有变量引用等需要绑定信息的节点才执行相应查表。

若一个操作数已经出错，仍可检查另一个操作数，报告独立错误。用 `check(left) && check(right)` 的短路求值可能直接跳过右侧。

## 3. Let 的顺序与返回值

```text
checkLet(node, env):
    验证声明名字和声明类型
    若存在显式初值：
        initType ← check(node.init, env)
        验证 initType 符合 node.declaredType
    inner ← 基于 env 建立局部环境
    在 inner 中绑定 node.name 到 node.declaredType
    bodyType ← check(node.body, inner)
    注解整个 let 为 bodyType
    返回 bodyType，并保留此前记录的错误状态
```

这里比较初值与声明类型，不是初值与正文类型。正文登记声明类型，不是初值类型。没有显式初值时应走单独分支，不能对空指针递归调用。

如果声明类型非法或名字是 self，应进入明确恢复路径，不能直接把错误声明按正常绑定写进环境。

## 4. 规则与实现的对应

| 数学部分 | 实现位置 |
|---|---|
| O(x) | 名称查找 |
| O[T/x] | 建立局部绑定，保留外层环境 |
| O ⊢ e:T | 递归检查并取得类型 |
| T1 ≤ T2 | 相容性函数 |
| lub(T1,T2) | 分支类型汇总函数 |
| 结论类型 | 返回值和 AST 类型注解 |

只用 Int、Bool、Object 做的小型练习，可以暂用有限分支判断相容性；扩展到任意类时，应统一调用继承树上的 subtype 操作。加入 SELF_TYPE 后再扩充这个操作，而不是在每个节点里重复写特判。

## 5. 用什么例子验证

| 测试目的 | 例子或预期 |
|---|---|
| 子节点递归 | let 的正文是 Add，Add 的操作数又含 let |
| 初始化边界 | let x 的初值引用外层 x |
| 遮蔽恢复 | 内层 x 为 Bool，退出后外层 x 仍为 Int |
| 声明与结果分离 | let x: Int in true，整个结果为 Bool |
| 子类型方向 | Dog 初始化 Animal 通过，反向拒绝 |
| 不跳过独立错误 | Add 两侧各自含未声明名字，两处都被访问 |

# 7.4 类、继承与多趟语义分析

COOL 允许类名和成员在文本上先使用后定义。检查方法正文之前，先收集全局声明和签名，可以避免把合法前向引用误报为未定义。

## 1. 为什么分阶段处理

```cool
class Foo {
    make(): Bar { new Bar };
};
class Bar { };
```

检查 Foo 时，Bar 的类定义可能还没按文本顺序访问。先收集所有类名，就能在检查 make 的返回类型和正文时找到 Bar。

多趟是清晰的实现方案，不是说任何语言、任何实现都必须恰好扫描四遍。也可以用延迟检查、工作队列等方式组织；关键是先满足信息依赖。

## 2. 一种四阶段安排

| 阶段 | 工作 | 产物 |
|---|---|---|
| 收类名 | 登记内置类与用户类，检测重名 | 类名表 |
| 查继承 | 父类存在性、禁用父类、继承环 | 有效的单继承树 |
| 收成员签名 | 属性、方法、形参和返回类型，检查重写 | 属性环境与方法环境 |
| 查表达式 | 属性初值、方法正文、局部作用域与类型规则 | 带类型 AST 和诊断 |

方法签名收集完后，方法可以调用定义在后面的其他方法。属性环境也应覆盖当前类和可继承的属性，不能只登记遍历过程中已经遇到的属性。

## 3. 继承和成员检查

COOL 中，父类必须存在，继承图不能有环；Int、Bool、String 不能作为父类，SELF_TYPE 也不能作为父类。Object、IO 可以继承，但内置类不能重新定义。

继承图可用 DFS 标记检测环：未访问、正在访问、已完成。沿父类边遇到“正在访问”的节点，说明当前路径形成环。图结构无效时，应先停止依赖它的检查或建立明确的恢复结构，避免方法查找和 LUB 沿父链无限循环。

成员方面，应区分以下情况：

- 同类不能重复定义同名属性或同名方法。
- 子类不能重定义继承来的属性。
- 方法可以重写，但 COOL 要求形参数量、各形参类型和返回类型与被重写方法一致。
- 形参名不能在同一方法中重复；self 不能被当作普通变量绑定或赋值。

声明中的类型名称及 SELF_TYPE 使用位置也必须检查，位置限制见 [[7.11 SELF_TYPE 与精确返回类型]]。

## 4. 检查成员正文

方法环境登记签名，不代表方法实现已经通过检查。进入方法时，将形参加入局部对象环境，推导正文类型，并验证它符合声明的返回类型。

属性初始化也要检查“初值类型 ≤ 属性声明类型”。属性名在初值中可见，不代表运行时所有属性初始化表达式都已经执行完；名称可见性与初始化次序应分别理解。

方法签名负责调用点与实现之间的约定。具体调用规则见 [[7.10 方法环境与动态、静态分派]]，子类型比较见 [[7.8 子类型、赋值与初始化相容性]]。

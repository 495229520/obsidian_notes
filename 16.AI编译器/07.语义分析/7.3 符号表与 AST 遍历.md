# 7.3 符号表与 AST 遍历

符号表把名字映射到声明信息，支持查找、遮蔽和退出作用域。它与 LR 分析器的状态栈不同：前者管理“x 是谁”，后者管理“当前该移进还是归约”。

## 1. 表里存什么

局部变量条目通常包含名字、类型、声明位置，也可以指向声明节点。类表和方法表还需要父类、参数类型、返回类型等信息。

变量的运行时值放在程序的存储位置中，不是类型检查符号表的必备内容。后续代码生成可能补充布局信息，但不能把类型环境当作运行时堆栈。

## 2. 分层接口

| 操作 | 含义 |
|---|---|
| enter_scope | 新增当前作用域层 |
| add_symbol(name, info) | 在当前层登记绑定 |
| lookup(name) | 从内向外查找最近绑定 |
| lookup_current(name) | 只检查当前层 |
| exit_scope | 移除当前层，恢复外层可见性 |

一种简单实现是“栈中的每层存一张映射表”。lookup 沿层向外查询；lookup_current 可检查一批形参有没有重名。查到同名后是否报错，仍由具体语言构造决定。

## 3. 遍历顺序必须匹配作用域规则

检查 `let x: Int <- init in body` 时：

1. 在旧环境中检查 init。
2. 新建一层，登记 x 的声明类型 Int。
3. 在新环境中检查 body。
4. 退出这一层，将 body 的类型作为整个 let 的类型。

不能一进入 let 节点就给所有子节点传入新绑定：init 看不到正在声明的这个 x。也不能只做“访问节点前压栈、访问节点后出栈”而忽略不同子节点使用不同环境。

case 的每个分支也要建立独立局部层；一个分支的变量不能泄漏到另一个分支。方法正文则在类属性环境之上加入形参。

## 4. 环境怎么实现

| 实现方式 | 特点 |
|---|---|
| 复制映射后更新 | 直观，适合小型练习，复制成本随环境大小增长 |
| 作用域栈 | 不复制外层；进入、退出时需成对管理 |
| 持久化环境 | 新环境共享旧结构，以不同根表示不同作用域 |

在复制环境的练习中，遮蔽应更新副本中的同名键。只尝试插入、却忽略“键已存在”，会让内层声明继续查到外层类型。原环境应保持不变。

错误退出也要清理当前作用域。可用作用域守卫保证函数正常返回或提前返回时都执行 exit_scope；否则后面的无关表达式可能错误地看到局部变量。

## 5. 两股信息的方向

环境从父节点传给子节点，说明当前位置有哪些声明；表达式类型从子节点返回父节点，供父节点验证规则并计算结果。这里的递归遍历是在处理已存在的 AST，不是在重新做递归下降语法分析。

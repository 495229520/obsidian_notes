# 4.1 从正则语言到上下文无关文法

Lexer 已经识别出标识符、数字、括号等 Token，Parser 接下来确定它们如何组成表达式和语句。单个 Token 的类别不能说明嵌套层次，也不能决定哪个表达式是谁的操作数。

## 1. 为什么有限自动机不够

考虑先出现 n 个左括号，再出现 n 个右括号的语言：

$$
L=\{\texttt{(}^{\,n}\texttt{)}^{\,n}\mid n\geq0\}.
$$

它包含空串、`()`、`(())`、`((()))`，不包含 `()()`。

假设一个 DFA 只有 k 个状态。读取 0 到 k 个左括号后有 k+1 个前缀，必有两个不同长度 i、j 的前缀使它停在同一状态。再接相同的 i 个右括号：

- i 个左括号配 i 个右括号，应当接受。
- j 个左括号配 i 个右括号，应当拒绝。

但同一状态读取同一后缀，只能得到相同结果，产生矛盾。因此，固定数量的状态无法精确记住无上限的嵌套深度。

这不意味着 DFA 不能识别无限语言：它可以用环识别任意长度的数字串。问题是这里需要区分任意多种“还欠几个右括号”的情况。

如果深度有固定上限，可以用有限状态记录深度。对于多种括号，除了深度，还需要区分种类和嵌套顺序，例如 `([])` 与 `([)]`；栈适合保存这些信息。

## 2. CFG 的四个组成部分

上下文无关文法（Context-Free Grammar，CFG）可写为 $G=(N,T,P,S)$：

| 组成 | 含义 | 本例 |
|---|---|---|
| N | 非终结符集合，表示可继续展开的结构 | S |
| T | 终结符集合，不再由产生式替换 | 左括号、右括号 |
| P | 产生式集合 | $S\to(S)\mid\varepsilon$ |
| S | 开始符号 | S |

$S\to(S)$ 每次生成一对括号，内部仍有 S 可以继续展开；$S\to\varepsilon$ 结束展开。二者恰好生成前面的单层套入式括号语言。

若需要包括 `()()` 在内的全部合法单种括号串，可以改用：

$$
S\to(S)S\mid\varepsilon.
$$

前一个 S 表示第一对括号内部，后一个 S 表示第一对括号之后的剩余部分。文法用递归描述结构，分析器用具体算法检查输入，不要把产生式本身当作已经写好的程序。

## 3. “上下文无关”指什么

CFG 的产生式左侧只能是一个非终结符，例如 $A\to\alpha$。出现 A 时，无论它前后有哪些文法符号，都可以用这条规则替换 A。

这里说的是产生式的形式，不是说程序含义与上下文无关。变量是否声明、名称对应哪个作用域、类型是否相容，仍需要另外检查。

语法文法中的终结符通常是 Token 类别：`ID`、`INT` 虽然用大写字母写出，也可以是终结符。具体拼写 `count` 或数值 42 由 Token 属性携带。`Expr`、`Stmt` 等非终结符则描述结构，不是 Lexer 额外读到的单词。

## 4. Lexer 与 Parser 的边界

| 阶段 | 输入 | 主要结果 |
|---|---|---|
| 词法分析 | 字符 | Token 序列及属性、位置 |
| 语法分析 | Token 序列 | 结构关系，常以分析树或 AST 表示 |
| 语义分析 | 语法结构及环境 | 名称绑定、类型检查等结果 |

例如，COOL 文法允许在 if 的条件位置放入一个表达式；该表达式的类型是不是 Bool，不由 CFG 单独保证。

Parser 不一定先构造完整分析树。结构可以体现在递归调用或分析栈中，也可以在分析过程中直接构造 AST，见 [[4.5 CST、AST 与语义动作]]。

词法与语法也可以合并，直接从字符解析。常见实现仍把它们分开，以简化空白、注释、数字等规则的处理。这里的分层是工程选择，不是所有语言实现都必须遵循的固定边界。

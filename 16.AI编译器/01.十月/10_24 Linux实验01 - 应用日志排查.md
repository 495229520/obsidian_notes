# Linux 实验 01：用 Shell 排查应用错误日志

对应 [[07.每日计划#2026-10-24（周六）|每日计划中的第一项 Linux 实验]]：`find`、`grep`、`sed`、`awk`、管道、重定向、退出码。计划里的 10 月 23 日是过渡日，本题按 10 月 24 日的 Linux 内容设计；[[10_23]] 中记录的 Shell 疑问可以通过这道题逐项验证。

用时 30–45 分钟。只做这一道综合题，最终留下一份命令记录和结果说明。

## 题目背景

你接手了一个小服务。有人反馈请求失败，需要你从应用日志中找出错误记录，整理成报告，并区分“没有匹配结果”和“命令执行出错”。

使用已创建的 WSL 实验目录，不需要安装工具，也不需要编译 LLVM/MLIR。

在 Windows PowerShell 中进入 Ubuntu：

```powershell
wsl -d Ubuntu-24.04
```

然后在 Ubuntu 的 Bash 中进入素材目录。后面的所有命令都从这里执行，以免相对路径指向其他位置。

```bash
cd ~/shell-lab/workspace
pwd
```

预期当前位置为 `/home/ubuntu/shell-lab/workspace`。输出文件统一放到已有的 `output/` 目录。

## 已知素材

`logs/app.log` 初始内容如下。每行用空格分隔，第四列是服务，第六列是状态码。

```text
2026-10-23 09:00:00 INFO service=api user=alice status=200 duration_ms=12
2026-10-23 09:01:00 ERROR service=api user=bob status=500 duration_ms=90
2026-10-23 09:02:00 WARN service=worker user=alice status=429 duration_ms=35
2026-10-23 09:03:00 ERROR service=db user=carol status=503 duration_ms=120
2026-10-23 09:04:00 INFO service=api user=bob status=200 duration_ms=18
2026-10-23 09:05:00 ERROR service=api user=alice status=500 duration_ms=80
```

只读取原日志；替换和筛选结果另存到 `output/`。这样可以重复运行自己的命令，并检查源数据有没有被改动。

## 操作要求

### 1. 找到日志并提取错误（约 8 分钟）

1. 用 `find` 在 `logs/` 中递归查找名字匹配 `*.log` 的普通文件。文件名模式要加引号。
2. 用 `grep` 显示 `app.log` 中包含 `ERROR` 的行及行号。
3. 再执行一次不带行号的筛选，把结果覆盖写入 `output/errors.log`。后面的文本处理使用这份文件。

验收：找到 `logs/app.log` 和 `logs/access.log` 两个文件；错误日志来自原文件第 2、4、6 行；`errors.log` 有 3 行且不带行号前缀。

### 2. 整理一份错误报告（约 12 分钟）

1. 用 `sed` 把 `errors.log` 中的 `ERROR` 替换为 `FAIL`，写入 `output/errors-normalized.log`。
2. 用 `awk` 从替换后的文件中提取第四列和第六列。
3. 用管道连接 `awk` 与 `sed`，去掉 `service=` 和 `status=` 前缀，保存到 `output/error-report.txt`。

报告应为下面的三行，顺序不变，列之间一个空格：

```text
api 500
db 503
api 500
```

检查源文件：`logs/app.log` 仍然有 3 行 `ERROR`，没有 `FAIL`。`output/errors-normalized.log` 则有 3 行 `FAIL`。

### 3. 验证覆盖、追加与错误输出（约 8 分钟）

1. 将 `error-report.txt` 的内容覆盖写入 `output/report-copy.txt`，再追加一次同样的内容。可以用 `cat` 输出文件、用 `wc -l` 数行。
2. 执行 `ls logs/app.log logs/missing.log`。其中第二个文件不存在。把标准输出保存到 `output/stdout.txt`，把标准错误保存到 `output/stderr.txt`。
3. 重新执行同一条 `ls`，将标准输出和标准错误一起保存到 `output/combined.txt`。

验收：`report-copy.txt` 有 6 行；`stdout.txt` 包含存在的日志路径；`stderr.txt` 包含文件不存在的错误；`combined.txt` 同时包含两类信息。错误文字随系统语言变化，不要求逐字一致。

### 4. 判断命令是否成功（约 7 分钟）

分别完成下面三个操作。每次操作后立即执行 `echo $?`，记录退出码，不要先运行其他命令。

| 操作 | 你的命令 | 实际退出码 | 你对结果的解释 |
| --- | --- | --- | --- |
| 用 grep 在 app.log 中查找 ERROR | 待填写 | 待填写 | 待填写 |
| 用 grep 在 app.log 中查找 XYZ_NOT_FOUND | 待填写 | 待填写 | 待填写 |
| 用 grep 在 logs/missing.log 中查找 ERROR | 待填写 | 待填写 | 待填写 |

自查：三个退出码应依次为 `0`、`1`、`2`。请说明后两种结果的区别，不能都只写成“失败”。

## 卡住时再看

> [!tip]- 命令形状提示，先尝试再展开
> - 查文件：`find 目录 -type f -name '文件名模式'`。
> - 带行号筛选：`grep -n '关键词' 文件`；写给后续处理的文件时去掉 `-n`。
> - 替换：`sed 's/旧文本/新文本/g' 文件`，多条替换可用多个 `-e 's/.../.../g'`。
> - 取列：`awk '{print $4, $6}' 文件`。
> - 管道：`命令一 | 命令二 > 输出文件`。右侧命令可以从标准输入读数据，不必再指定输入文件。
> - 分别保存：`命令 > 普通输出文件 2> 错误输出文件`。
> - 合并保存：`命令 > 合并文件 2>&1`。
> - 查看退出码：在目标命令后紧接着执行 `echo $?`。

命令选项忘记时，可查 [[1.3 cat、mv、mkdir、grep、find、kill、tar]] 中的 find 和 grep 部分。

## 素材需要恢复时

如果原日志被误改，可以运行下面的重置操作。它会先把整个旧 workspace 移到 `~/shell-lab/backups/`，再恢复初始素材，因此已有输出也会移进备份。先保存本次作答记录，再决定是否重置。

```bash
cd ~/shell-lab
python3 reset.py --reset
cd workspace
```

重置后重新进入 workspace，后续命令才会使用新生成的目录。

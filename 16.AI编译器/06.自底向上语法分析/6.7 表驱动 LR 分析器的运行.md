# 6.7 表驱动 LR 分析器的运行

分析表在构造阶段生成。运行时只根据栈顶状态和前瞻 Token 查询 ACTION，执行移进、归约、接受或报错，不再现场计算 CLOSURE 和 FOLLOW。

## 1. 状态栈保存什么

符号栈为 X1…Xm 时，状态栈保存 s0、s1…sm，其中：

$$s_i=\hat\delta(s_0,X_1\cdots X_i).$$

每个状态记录 DFA 读取对应栈前缀后的结果。因此取栈顶就能得到当前项集状态，归约弹栈后也能直接找回剩余前缀的状态，不必从栈底重跑 DFA。

本文把它们合写为 `0 int 3 * 6`：0 是初态，int 后的状态为 3，星号后的状态为 6，栈顶在右。

## 2. 四种动作

| ACTION 结果 | 运行操作 |
|---|---|
| shift j | 消费当前 Token，压入其语义值和状态 j |
| reduce A → β | 读取右部语义值，弹出长度为 β 的符号及对应状态，再查 GOTO 并压入左部结果 |
| accept | 完成分析 |
| error | 报错或进入单独的恢复流程 |

归约时查 GOTO 用的是弹栈后露出的状态。不是归约前的栈顶，也不是直接使用 DFA 完成项的状态。

若符号与状态分为两个数组，各弹 |β| 个，状态数组仍保留初态；若交替保存符号和状态，则弹 2|β| 个槽位；若存二元组，则弹 |β| 对。不要混用计数约定。空产生式不弹出任何右部项。

## 3. 输入 int * int 的完整跟踪

使用 [[6.6 SLR(1) 与分析表构造]] 的表，每行是动作执行前。

| 栈（顶在右） | 未读输入 | 查表结果与动作 |
|---|---|---|
| 0 | int * int $ | s3，移进 int |
| 0 int 3 | * int $ | s6，移进 * |
| 0 int 3 * 6 | int $ | s3，移进 int |
| 0 int 3 * 6 int 3 | $ | r4：T → int；弹一对，GOTO[6,T] 为 8 |
| 0 int 3 * 6 T 8 | $ | r3：T → int * T；弹三对，GOTO[0,T] 为 2 |
| 0 T 2 | $ | r2：E → T；弹一对，GOTO[0,E] 为 1 |
| 0 E 1 | $ | acc |

后三次归约都没有消费 `$`。前瞻可以在多次归约之间保持不变，直到发生移进或接受。

## 4. 主循环伪代码

```text
states ← [0]
values ← []
lookahead ← nextToken()

repeat:
    action ← ACTION[states.top, lookahead.kind]
    if action is shift j:
        values.push(lookahead.value)
        states.push(j)
        lookahead ← nextToken()
    else if action is reduce A → β:
        k ← length(β)
        result ← semanticAction(右部 k 个语义值)
        values.pop(k)
        states.pop(k)
        j ← GOTO[states.top, A]
        values.push(result)
        states.push(j)
    else if action is accept:
        return success
    else:
        reportSyntaxError()
        return failure
```

语义动作必须在右部值失效前读取或转移它们。这里只演示识别和构树，不包含恢复、源码位置栈及资源清理的完整实现。

## 5. 语义值与 AST

状态栈足以进行表驱动语法识别；构造 AST 还要保存整数值和子树。无需为了决策额外读取栈中的符号名称。

| 归约规则 | 示例语义动作 |
|---|---|
| T → int | Int(int.value) |
| T → int * T | Mul(Int(第一个值), 第三个值) |
| E → T | 直接传递 T 的子树 |
| E → T + E | Add(第一个值, 第三个值) |
| T → ( E ) | 直接传递 E 的子树 |

例如输入 `2 * 3`，归约后得到 `Mul(Int(2), Int(3))`，构造树不等于已经求值。语义动作的概念见 [[4.5 CST、AST 与语义动作]]。

对固定文法，右部最大长度是常数，正常确定性 LR 识别对输入长度为线性开销；任意语义动作的耗时不包括在这个结论中。若每次都重新扫描完整符号栈确定状态，重复工作则可能达到二次量级。

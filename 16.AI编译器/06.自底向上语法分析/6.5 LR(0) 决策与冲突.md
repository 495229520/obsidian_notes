# 6.5 LR(0) 决策与冲突

LR(0) 项不携带前瞻。普通完成项一旦出现在状态中，就提出在所有输入列上归约的候选；若同一表格位置还有其他动作，就发生冲突。

## 1. 从项得到动作

| 项或转移 | LR(0) 动作 |
|---|---|
| A → α · a β，a 为终结符，转移到 Ij | 在 a 列填 shift j |
| A → α ·，A 不是增广开始符号 | 在所有终结符及 `$` 列填该归约 |
| S′ → E · | 只在 `$` 列填 accept |
| 非终结符 A 的转移 | 填 GOTO，不直接消费 Token |

“0”指归约选择不使用前瞻来限制适用位置，并不是说移进时不检查当前 Token。增广完成项单独处理，不能当成普通归约填满一行。

## 2. 移进／归约冲突

沿用 [[6.4 LR(0) 项集与 DFA 构造]] 的编号：

```text
I2: E → T · + E
    E → T ·

I3: T → int · * T
    T → int ·
```

| 状态与输入 | 移进候选 | 归约候选 |
|---|---|---|
| I2，`+` | shift 5 | E → T |
| I3，`*` | shift 6 | T → int |

LR(0) 会把普通归约填入所有列，因此两处都无法唯一决策。特别是 I3：若在 `*` 上过早将 int 归约为 T，就会出现 6.1 中的错误。

这份文法不是 LR(0)，但不能由此推出它二义。冲突也可能只是该分析方法丢失了必要的上下文；下一篇会用 FOLLOW 消除这两处冲突。

## 3. 归约／归约冲突

考虑另一个文法：

```text
S → A a | B b
A → c
B → c
```

在初始状态读 c 后，项集中同时有 `A → c ·` 与 `B → c ·`。LR(0) 对每个输入列都提出两种归约，因此冲突。

但是 FOLLOW(A) 为 {a}，FOLLOW(B) 为 {b}。如果允许查看一个前瞻，就能在 a 上归约为 A，在 b 上归约为 B。这个例子也说明两个完成项不必造成 SLR 冲突；应看它们的归约列是否重叠。

## 4. 为什么没有“移进／移进冲突”

一个状态内可能有多项都等待同一终结符，但 GOTO 会把它们一起推进成同一个目标项集。DFA 已保证该符号的转移唯一，因此标准 LR 表中不产生两个不同的移进目标。

冲突发生在同一个 ACTION 单元格，不是只要一行包含多种动作就算冲突。例如 a 上移进、b 上归约完全可以共存。

## 5. 判定时应检查什么

构造全部可达项集，再按 LR(0) 规则填表。只检查一个输入走过的几个状态，不足以证明文法属于 LR(0)。填表时保留候选动作集合，发现多个动作就报告，不能用后写的动作覆盖前面的动作。

运行时强行选移进或某条归约，只是附加了裁决策略，不会使原文法自动变成 LR(0)。

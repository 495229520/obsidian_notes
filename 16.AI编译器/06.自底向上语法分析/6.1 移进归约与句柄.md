# 6.1 移进归约与句柄

自底向上分析从输入 Token 开始，把已识别的结构归约为非终结符，最终得到开始符号。移进归约分析维护已处理部分的栈与未读输入；归约序列对应最右推导的逆过程。

## 1. 本章统一文法

后续 NFA、DFA、SLR 表和运行跟踪采用以下规则编号：

```text
(0) S' → E
(1) E  → T + E
(2) E  → T
(3) T  → int * T
(4) T  → int
(5) T  → ( E )
```

规则 0 是增广规则。int 表示一个整数 Token。这份教学文法右递归，且乘号左侧限定为 int；`( int ) * int` 不属于它的语言。

## 2. 两种基本动作

用 $\alpha\mid\omega$ 表示配置，竖线左侧是符号栈，右侧是未读 Token，栈顶在右。

| 动作 | 配置变化 | 输入游标 |
|---|---|---|
| 移进 a | $\alpha\mid a\omega\to\alpha a\mid\omega$ | 前进一个 Token |
| 按 A → β 归约 | $\alpha\beta\mid\omega\to\alpha A\mid\omega$ | 不变 |

归约只替换栈顶的后缀。空产生式归约时 β 长度为零，不弹符号，直接压入 A。实际能否执行某次归约，由分析表决定。

## 3. 句柄的定义

若有最右推导：

$$S'\Rightarrow_{rm}^*\alpha A\omega
\Rightarrow_{rm}\alpha\beta\omega,$$

则产生式 A → β 及 β 在右句型 αβω 中的位置，构成这一步的句柄。将该位置的 β 换回 A，就撤销了最后一步最右推导。

ω 只含终结符，因为这一步展开的是最右边的非终结符 A。句柄包含位置和规则，不能只用字符串内容来描述。

例如：

$$E\Rightarrow T+E\Rightarrow T+T\Rightarrow T+int
\Rightarrow int*T+int\Rightarrow int*int+int.$$

逆向第一步应归约中间的 int，而不是最左或最右的 int。正确移进到句柄右端时，它才完整位于栈顶。

## 4. 为什么匹配右部仍不能立即归约

在配置 `int | * int + int` 中，栈顶确实匹配 T → int。但若立即归约，变成 `T | * int + int`，后面没有规则能把 `T * …` 组成合法项。本例需要继续移进 `*`，等待右侧 T，再把 `int * T` 整体归约。

因此，匹配产生式右部只是形式条件；句柄还要求这一步与当前完整右句型的最右推导相符。后续 LR 项集和前瞻用于确定这一决策。

## 5. 一次完整移进归约

每行是动作之前的配置：

| 符号栈 | 未读输入 | 动作 |
|---|---|---|
| 空 | int * int + int $ | 移进 int |
| int | * int + int $ | 移进 * |
| int * | int + int $ | 移进 int |
| int * int | + int $ | T → int |
| int * T | + int $ | T → int * T |
| T | + int $ | 移进 + |
| T + | int $ | 移进 int |
| T + int | $ | T → int |
| T + T | $ | E → T |
| T + E | $ | E → T + E |
| E | $ | 接受 |

输入仍然从左向右读取；“最右推导的逆过程”描述归约顺序，不是从右向左读 Token。

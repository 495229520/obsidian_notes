# 6.2 活前缀与有效项

句柄描述下一次应撤销哪一步推导；活前缀描述正确移进归约过程中，栈内允许保留哪些前缀。LR 项则用一个圆点表示某条产生式已经识别到哪里。

## 1. 活前缀的边界

活前缀是右句型的一个前缀，且没有越过该句型句柄的右端。它可以结束在句柄之前、句柄中间或句柄末尾。

对于右句型 `int * int + int`，当前句柄是中间的 int。相应前缀包括空串、`int`、`int *`、`int * int`；在这一步继续越过 `+`，就越过了当前句柄右端。

不要把活前缀简称为“句柄的前缀”：它通常还包含句柄之前的栈内容。判断也带有存在性：某个符号串只要能作为某个合法右句型中符合边界要求的前缀，就属于文法的活前缀集合。

栈保持活前缀，不表示实际剩余输入一定正确。比如 `( int *` 尚可补全，但接下来若出现 `)`，本章文法就缺少乘号后的 T。

## 2. 圆点表示已识别的部分

对 $A\to\beta\gamma$，项写作 $A\to\beta\cdot\gamma$。

| 项 | 当前进度 |
|---|---|
| T → · ( E ) | 尚未识别该右部 |
| T → ( · E ) | 已识别左括号，等待 E |
| T → ( E · ) | E 已识别，等待右括号 |
| T → ( E ) · | 右部已完整识别，产生归约候选 |

右部有 k 个文法符号就有 k+1 个项。ε 产生式只有 `A → ·` 一个项，不存在要读取的 ε Token。

圆点左侧的非终结符可能由归约得到；圆点不是源码字符偏移，也不是记录所有历史动作的指针。

## 3. 有效项的形式定义

项 $A\to\beta\cdot\gamma$ 对前缀 αβ 有效，如果存在最右推导：

$$S'\Rightarrow_{rm}^*\alpha A\omega
\Rightarrow_{rm}\alpha\beta\gamma\omega.$$

其中 α、β、γ 是文法符号串，ω 是终结符串。β 位于当前前缀末尾，γ 是该产生式尚待识别的部分。

这里的 ω 只表示 A 右边的后缀。若 γ 尚未识别，实际未读输入还需要提供 γ 的终结符展开，再接 ω；不能把 ω 单独等同于此刻全部未读输入。

例如项 `T → int · * T` 对前缀 int 有效。取 `E ⇒ T ⇒ int * T`，此时 α、ω 都为空，γ 为 `* T`。实际输入仍可能剩下 `* int`，显然并不等于空的 ω。

## 4. 一个前缀可以对应多个有效项

对前缀 int，`T → int ·` 与 `T → int · * T` 都有效。前者表示已有短规则归约候选，后者表示可能继续识别乘法。有效只说明存在相应推导上下文，不保证当前实际前瞻允许该动作。

反过来，一个项也能对多个甚至无穷多个前缀有效。`T → ( · E )` 对 `(`、`((`、`(((` 等前缀都有效。状态可以复用，但不同嵌套深度仍保存在分析栈里。

## 5. 为什么可以用有限自动机

对通常已去除无用符号的 CFG，活前缀集合可以由有限自动机识别。它的字母表是文法符号，包括终结符和非终结符。

这不意味着原语言变成正则语言。自动机处理的是经过归约后的栈符号序列，完整 LR 分析还需要栈、前瞻和归约动作。构造方法见 [[6.3 从 LR 项构造活前缀 NFA]]；DFA 状态与有效项集合的对应见 [[6.4 LR(0) 项集与 DFA 构造]]。

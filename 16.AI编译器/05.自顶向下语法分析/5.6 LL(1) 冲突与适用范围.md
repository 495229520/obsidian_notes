# 5.6 LL(1) 冲突与适用范围

LL(1) 冲突是同一个表格位置出现了不同产生式：当前非终结符和一个前瞻 Token 不足以确定选择。没有左递归、没有显眼的公共前缀，都不能代替实际填表检查。

## 1. 用 SELECT 统一检查

对 $A\to\alpha$，将预测表中可选该规则的列收集为 SELECT：

$$
SELECT(A\to\alpha)=
\begin{cases}
FIRST(\alpha)-\{\varepsilon\},&\alpha\text{ 不可空}\\
(FIRST(\alpha)-\{\varepsilon\})\cup FOLLOW(A),&\alpha\text{ 可空}.
\end{cases}
$$

同一左部的不同候选，其 SELECT 必须两两不相交。这个条件包括 FIRST/FIRST、FIRST/FOLLOW，以及两个可空候选在 FOLLOW 上的重叠。

## 2. FIRST/FIRST 冲突

```text
S → A a | B b
A → c
B → c
```

两个候选在字面上以不同非终结符开头，但都能以 c 开始，因此 M[S, c] 冲突。代入 A、B 后，可提取为 `S → c R`、`R → a | b`。

另一个例子是 `S → S a | b`：两条右部的 FIRST 都含 b。消除左递归后可得到 `S → b R`、`R → a R | ε`。原文法不是 LL(1)，不代表它生成的语言不能用 LL(1) 文法描述。

## 3. 可空分支与后继冲突

```text
S → A a
A → a | ε
```

FIRST(a) 为 {a}，FOLLOW(A) 也为 {a}。看到 a 时，分析器不能确定应由 A 消费它，还是让 A 为空并交给 S 的末尾 a，因此 M[A, a] 同时包含两条规则。

此文法并不二义：合法串 a 与 aa 各有一种分析。冲突来自一个 Token 不够决定当前分支。整体改写为 `S → a R`、`R → a | ε` 后可消除冲突。

两个可空候选也会冲突。例如 `S → A`、`A → B | C`、`B → ε`、`C → ε`，M[A, $] 同时需要两条规则；空串在这里确有两种推导。

## 4. 左因子提取的作用与限制

提取左因子能把共同前缀推迟到分支选择之前，方法统一见 [[5.2 左递归消除与左因子提取]]。但对 `S → a S a | a`，提取后得到：

```text
S → a R
R → S a | ε
```

FIRST(Sa) 含 a，FOLLOW(R) 也含 a，冲突仍在。它消除了字面的公共前缀，却没有消除前瞻信息不足。

悬空 else 也是典型例子：把共同的 `if 条件 then 语句` 提取出来后，else 分支与空分支仍会在 else 上冲突。原因和消歧方式见 [[4.4 悬空 else 与文法消歧]]。

## 5. 怎样理解适用范围

| 判断 | 能推出什么 |
|---|---|
| 标准 LL(1) 表无冲突 | 该文法可以按一符号预测分析 |
| 表有冲突 | 该文法不是 LL(1)，需改写或换方法 |
| 文法二义 | 不可能直接成为 LL(1) 文法 |
| 文法无二义 | 仍可能不是 LL(1) |

实际手写递归下降可以配合额外前瞻、表达式优先级处理或局部试探，不能将所有手写 Parser 都归为 LL(1)。LR 方法能直接处理更多文法，包括许多自然的左递归表达式文法，但也有自己的冲突判定。

# 5.2 左递归消除与左因子提取

两种变换解决不同问题：左递归可能让朴素递归下降在不消费输入的情况下反复调用；公共前缀则让分析器过早面临分支选择。改写后还需要检查预测表，不能直接断言得到 LL(1) 文法。

## 1. 直接左递归

若 $A\Rightarrow^+A\alpha$，就存在左递归。最直接的形式是：

$$A\to A\alpha\mid\beta.$$

朴素实现会在匹配 α 前先调用 A，于是回到同一输入位置。常用改写为：

$$A\to\beta A',\qquad A'\to\alpha A'\mid\varepsilon.$$

两者描述先得到 β，再接零个或多个 α。这里 α、β 可以包含非终结符，这种重复形式不证明整个语言是正则语言。

多个候选时：

$$
\begin{aligned}
A&\to A\alpha_1\mid\cdots\mid A\alpha_n\mid\beta_1\mid\cdots\mid\beta_m\\
\Longrightarrow\quad A&\to\beta_1A'\mid\cdots\mid\beta_mA'\\
A'&\to\alpha_1A'\mid\cdots\mid\alpha_nA'\mid\varepsilon.
\end{aligned}
$$

β 分支不以 A 开头，且至少有一个基准分支；空的递归尾部应先处理。若 α 可空，改写后仍可能隐藏左递归，不能机械套公式后停止检查。

## 2. 间接与隐藏左递归

间接例子：

```text
S → A a | b
A → S c | d
```

代入 A 后，S 变成 `S → S c a | d a | b`，再改为：

```text
S → d a R | b R
R → c a R | ε
A → S c | d
```

一般算法为非终结符排序：处理 Ai 时，先用已处理的 Aj 产生式替换右部开头的 Aj，再消除 Ai 的直接左递归。含空产生式或循环规则时，需要先处理这些情况或采用能处理它们的算法。

隐藏例子是 `S → A S b | c`、`A → ε | d`。A 可以消失，所以 S 能再次出现在最左端。检查时应沿可空前缀继续向后看，不能只比较右部第一个符号。

## 3. 左因子提取

对于公共前缀 α：

$$
A\to\alpha\beta_1\mid\alpha\beta_2\mid\gamma
\quad\Longrightarrow\quad
A\to\alpha A'\mid\gamma,\quad A'\to\beta_1\mid\beta_2.
$$

先识别 α，再选择剩余部分；γ 等其他候选必须保留。课件文法统一改写为：

```text
E → T X
X → + E | ε
T → int Y | ( E )
Y → * T | ε
```

后续 FIRST、FOLLOW 和 LL(1) 表都使用这份文法。它保留原文法的限制：`int * ( int )` 合法，`( int ) * int` 不合法，因为乘号左侧限定为 int。它不是通常支持任意因子相乘的完整算术文法。

X、Y 的空分支应根据 FOLLOW 选择，不能在任意失配时自动使用。若仍有公共前缀，可以继续提取；它的局限见 [[5.6 LL(1) 冲突与适用范围]]。

## 4. 树形改变后如何保留结合性

`E → E - T | T` 改为 `E → T R`、`R → - T R | ε` 后，辅助节点形成右递归链。语言中的字符串集合不变，但 AST 不能照搬辅助节点的形状。

左结合减法可按下面的伪代码构造：

```text
left ← parseTerm()
while lookahead is MINUS:
    consume MINUS
    right ← parseTerm()
    left ← Sub(left, right)
return left
```

对 `1 - 2 - 3`，依次得到 `Int(1)`、`Sub(1, 2)`、`Sub(Sub(1, 2), 3)`，求值为 −4。消除左递归不会自动把语义改成右结合；真正决定结果的是 AST 构造和语义动作。也可以通过继承属性传递累积的左子树。

코드 생성 · 단계별 시연

스택 머신 코드: 3 + (7 + 5)를 만들고 돌리기

앞쪽 단계에서 AST를 따라 템플릿을 붙여 코드를 만든다. 뒤쪽 단계에서 그 코드를 한 줄씩 실행하며 $a0와 스택을 본다.

노트 11/2 코드 생성 노트 §2

  1. 손으로 할 때
  2. 정수는 $a0에 넣는다.
  3. 덧셈은 왼쪽 값을 계산해 스택에 밀어 두고, 오른쪽 값을 계산한 뒤, 스택에서 꺼내 더한다.
  4. 어떤 식이든 끝나면 결과는 $a0에 있고 스택은 원래 높이로 돌아온다.

템플릿

  1. cgen(i): li $a0 i
  2. cgen(e₁ + e₂): ① cgen(e₁)
  3. ② sw $a0 0($sp); addiu $sp $sp -4 (e₁을 스택에)
  4. ③ cgen(e₂)
  5. ④ lw $t1 4($sp); add $a0 $t1 $a0; addiu $sp $sp 4

객체와 디스패치 · 단계별 시연

동적 디스패치: e.f()는 어느 f를 부르나

객체의 세 번째 칸이 그 클래스의 디스패치 표를 가리킨다. 메서드 이름은 컴파일할 때 표의 칸 번호로 바뀌고, 실행할 때 객체가 가리키는 표에서 그 칸을 읽는다.

노트 11/2 코드 생성 노트 §4

  1. 손으로 할 때
  2. 정적 타입(A)으로 f의 칸 번호를 정한다: A의 표에서 f는 0번째.
  3. 실행 중에 객체의 디스패치 포인터(오프셋 8)를 읽는다.
  4. 그 표의 0번째 칸에 있는 주소로 뛴다.

클래스와 배치

e.f() 실행

연산적 의미론 · 단계별 시연

연산적 의미론: 환경 E와 저장소 S로 실행하기

코드 생성이 지켜야 할 "정답"을 규칙으로 적은 것이 연산적 의미론이다. let x : Int <- 1 in { x <- x + 2; x }를 규칙대로 계산한다.

노트 11/2 연산적 의미론 노트

  1. 손으로 할 때
  2. E는 이름 → 위치, S는 위치 → 값이다.
  3. 변수를 읽을 때는 E로 위치를 찾고 S에서 값을 읽는다.
  4. 대입은 S만 바꾼다. E는 let이 새 이름을 만들 때만 바뀐다.

레지스터 할당 · 단계별 시연

k = 3: 막혔을 때 스필 후보 고르기 (슬라이드 42–48)

a를 지우고 나면 모두 차수 3 이상이라 막힌다. 스필 후보를 직접 고른다. 슬라이드는 f를 골랐다. 다른 후보를 고르면 무슨 일이 생기는지도 볼 수 있다.

노트 11/2 레지스터 할당 노트 §2.3

  1. 손으로 할 때
  2. 막히면 후보 하나를 일단 스택에 넣고 단순화를 계속한다.
  3. 두 번째로 막히면 이 페이지는 남은 노드 중 차수가 가장 큰 것을 자동으로 고른다(슬라이드 63: 간섭이 많은 것부터).
  4. 꺼낼 때 이웃이 색 3개를 다 썼으면 그 노드를 스필한다.

같은 계산, 다른 순서: 캐시 미스 세기

슬라이드 70의 루프를 작게 줄였다: 배열 길이 8, 반복 3번, 캐시 줄 4개(한 줄에 원소 2개), 가장 오래 안 쓴 줄부터 쫓아냄. 왼쪽은 원래 순서, 오른쪽은 고른 순서다.

노트 11/2 레지스터 할당 노트 §3.3

  1. 손으로 할 때
  2. 파란 칸은 지금 캐시에 들어 있는 원소다(한 줄 = 원소 2개).
  3. 이번에 읽은 원소가 초록이면 히트, 주황이면 미스다.
  4. 미스가 나면 그 줄을 가져오고, 캐시가 차 있으면 가장 오래 안 쓴 줄을 쫓아낸다.

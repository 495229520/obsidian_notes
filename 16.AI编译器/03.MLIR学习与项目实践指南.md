# AI Compiler 学习路线：从 IR 到自己的张量编译器

你的主项目是一个基于 MLIR 的小型张量编译器：输入静态二维 FP32 的 `MatMul → Add → ReLU`，经过自己实现的算子校验和转换，在 CPU 上执行，再完成一次有测试、有测量的优化。

整条主线只有五个阶段。每阶段先交出结果，再进入下一阶段；同一份项目代码持续扩展，不另开五个互不相干的项目。

## 2. 学习顺序与资料分工

### 第一阶段：读懂程序表示，算清张量结果

**这一阶段解决：编译器正在处理什么，它必须保留什么结果。**

学习内容限定在编译前端／中端／后端、AST 与 IR、SSA 的定义与使用、基本块，以及 MLIR 的 Operation、Value、Region、Block、Type、Attribute。数学只补矩阵乘法、shape/stride、逐元素 Add、ReLU 和浮点比较。

按这个顺序阅读：

1. [[16.AI编译器/04.编译器与编译流程基础|编译流程基础]]。
2. [[16.AI编译器/90.学习与实践/MLIR入门教程-第1期视频完整字幕|入门视频第1期]]的动机与 IR 部分，先跳过完整工具链构建。
3. [IR Structure](https://mlir.llvm.org/docs/Tutorials/UnderstandingTheIRStructure/) 中的嵌套结构与 def-use 关系。先识别概念，C++ 遍历实现留到第二阶段。
4. [[16.AI编译器/02.AI编译器与MLIR的数学和算法基础#2.1 矩阵乘法要能落到逐元素计算|矩阵乘法]]、[[16.AI编译器/02.AI编译器与MLIR的数学和算法基础#2.2 张量形状与内存布局需要分开理解|布局]]、[[16.AI编译器/02.AI编译器与MLIR的数学和算法基础#2.4 浮点数与误差从第一次执行验证就要使用|误差]]和该笔记 §3.1 的三个算子。

练习逐项完成：画一个小函数的 AST 与伪 IR；标注一段真实 MLIR 的结果、操作数、类型和嵌套关系；手算一个小矩阵的 `ReLU(AB+C)`；用 C++ 循环和独立 NumPy 参考核对输出。C 与 AB 同形状，初版不做广播。

留下 `ir-notes.md`、数值参考实现及测试记录。过关时应能不看答案解释每个值从哪里来、矩阵维度为何匹配、结果为何一致，以及浮点比较为什么不能一律要求完全相等。

还不要求自己写 Parser、学完龙书、掌握全部深度学习或购买加速器。进入下一阶段时，带着已经能解释的 IR 与数值参考。

### 第二阶段：搭好工程，写出第一个 Pass

**这一阶段解决：怎样用自己的 C++ 代码改变 IR。**

先固定 LLVM/MLIR 20.1.8，完成最小构建，再基于该版本的 [standalone 示例](https://github.com/llvm/llvm-project/tree/llvmorg-20.1.8/mlir/examples/standalone) 建立独立项目。工具链安装、工程构建和测试分别记录；先把上游示例的 `check-standalone` 跑通。

学习 Pass、PatternRewriter、Operation/Value 的 C++ 访问方式，以及 lit/FileCheck。主读 [Toy 第3章的 C++ 模式重写](https://mlir.llvm.org/docs/Tutorials/Toy/Ch-3/)；先理解示例中的双转置规则，再把匹配与替换机制用到自己的练习。测试写法参考 [Testing Guide](https://mlir.llvm.org/getting_started/TestingGuide/)。暂不同时学习 DRR、PDLL 等多种写法。

首个练习固定为受限整数加零消除：对普通标量 i32 的 `arith.addi x, 0` 返回 x，其他情况不改写。不将规则直接推广到浮点加法。

留下自己的 Pass、注册与运行方式，以及三类测试：应当消除的加零、不应消除的非零加法、再次运行后结果稳定。单独运行自己的 Pass，并保留能够证明其命中的记录；不能只调用上游 canonicalizer 就把结果算作自己实现。

过关标准：你能解释匹配条件、替换的值及合法性；关闭自己的 Pass 时目标变换不发生，开启时发生；测试失败时能缩小到一个最小输入。记录中要区分手写规则与上游已有优化。

这时完成第一个可独立解释的编译器改动，再进入张量算子定义。

### 第三阶段：定义自己的 MiniNN 算子

**这一阶段解决：怎样让编译器知道一次 MatMul 的含义与合法输入。**

在同一项目中增加 MiniNN Dialect。只支持 Constant、MatMul、Add、ReLU；计算数据为静态二维 FP32 张量。类型先复用 MLIR 的张量类型，不另外设计完整类型系统。

主读 [Toy 第2章的 Dialect 与 ODS 部分](https://mlir.llvm.org/docs/Tutorials/Toy/Ch-2/)，学习操作声明、操作数与结果、属性、Verifier。Toy 是机制参考，你的算子范围和计算语义由 MiniNN 项目定义。

先用 MLIR 通用文本格式手写输入，复用已有解析设施。完成操作定义、解析打印与校验，检查 MatMul 的归约维、Add 的同形状要求、ReLU 的输入输出形状以及 FP32 限制。

留下 `mininn` 操作定义、Verifier、合法示例及错误输入测试。过关标准：合法图能解析并打印；错误形状、不支持的类型与广播被清楚拒绝；你能解释每个操作的输入、输出与逐元素公式。

这个阶段先完成“能表示且能检查”。CPU 执行在下一阶段完成，不把仅打印出自定义操作当作编译器已经可运行。

### 第四阶段：让 MiniNN 在 CPU 上算对

**这一阶段解决：怎样把高层算子逐步变成可以执行的程序。**

沿同一条转换路径推进：

```text
MiniNN 张量算子
    ↓ 自己实现算子到标准方言的转换
Linalg / tensor 等标准操作
    ↓ Bufferization 与循环转换
memref / scf / arith 等表示
    ↓ 复用对应版本的转换与代码生成
LLVM Dialect → LLVM IR → CPU 执行
```

这是一张概念路径图，实际 Pass 的组合和次序要按固定版本验证。

先学 [Dialect Conversion](https://mlir.llvm.org/docs/DialectConversion/) 的合法操作集合与转换模式，再读 [Bufferization](https://mlir.llvm.org/docs/Bufferization/) 的 tensor/memref 区别、destination-passing style、复制与复用。[Toy 第5章](https://mlir.llvm.org/docs/Tutorials/Toy/Ch-5/)和[第6章](https://mlir.llvm.org/docs/Tutorials/Toy/Ch-6/)用于理解分阶段降低与 CPU 执行；Toy 的 Affine 路线与本项目的 Linalg 路线分别核对，不照抄成同一条流水线。

按 ReLU → Add → MatMul 的顺序接入，最后组合为 `ReLU(AB+C)`。保存各阶段 IR，明确 MatMul 累加值的初始化，以及缓冲区由谁分配、谁释放。One-Shot Bufferize 不自动承担完整释放职责。

留下可以从输入 IR 跑到数值结果的程序，与第一阶段的独立参考比较。测试包括小矩阵、非方阵、含负值的 ReLU 输入、错误形状和类型；浮点容差在测试中写明。

过关标准：换一组合法输入仍得到可核对的结果；转换后没有遗留预期消除的 MiniNN 操作；失败时能定位是算子语义、转换、内存还是调用约定出了问题；README 给出完整构建与执行步骤。

**到这里，项目第一版完成。** 可以整理仓库和个人贡献，不需要等量化、NPU 真机或工业 PR 都完成。

### 第五阶段：完成一项优化，解释它的收益与代价

**这一阶段解决：怎样在不破坏正确性的前提下改变执行方式。**

默认先做 MatMul 分块。复用现有变换机制，为同一项目选择和组合分块策略，理解索引、归约维、tile 大小与尾块；再有余力时考虑 Add/ReLU 融合。主读 [Transform 教程 Ch0](https://mlir.llvm.org/docs/Tutorials/transform/Ch0/) 的结构化计算，以及 [Ch1](https://mlir.llvm.org/docs/Tutorials/transform/Ch1/) 的变换组合。

学习顺序是先有第四阶段的正确基线，再回来增加优化。实际编译流水线中，张量层面的分块／融合通常放在 Bufferization 之前。

保留未优化版本作为基线，测试能整除与不能整除 tile 的输入。解释并行维与归约维的区别；ReLU 不能随意移入尚未完成的归约，也不能忽略输出被多个操作使用的情况。

留下优化配置或代码、前后 IR、正确性测试、基准脚本和结果表。测量固定设备、输入、精度、线程数、预热、重复次数与计时范围。分别说明自己设计了什么、复用了哪些上游变换。

过关标准：优化前后数值检查通过；测量可复现；能解释在哪些输入上更快、更慢或没有收益。没有加速也可形成完整实验，不能只挑一次最快结果。

整理一个真实失败案例的复现、原因、修改和回归测试，并确认他人能按 README 重现。五阶段主线至此完成。

## 3. 基础知识什么时候补

| 卡在哪一步 | 当场补什么 | 先不用展开什么 |
|---|---|---|
| 看不懂 IR | 编译流程、SSA、定义与使用、块和 Region | 完整 Parser、所有编译原理算法 |
| Pass 写不动 | 指针／引用、生命周期、RAII、基础模板、LLVM 常用容器与类型转换 | 为开工而重学全部 C++ |
| 算子结果不对 | 矩阵乘法、shape/stride、索引、浮点误差 | 微积分、训练与自动微分 |
| 内存或 Lowering 出错 | tensor/memref、别名、复制、所有权、调用约定 | 完整 NPU 内存规划器 |
| 优化没有收益 | 缓存、循环、访存、线程与测量方法 | 同时开 CUDA、Triton、TVM 多条路线 |

C++、Linux 与算法继续按 [[07.每日计划|07]] 推进，遇到具体缺口时取用已有笔记。当前项目的初版范围不要求先补完一整门数学或深度学习课程。

## 4. 主线完成后，再走向 NPU 编译优化

沿你现有的 NPU 兴趣，默认延伸顺序是：**张量生命周期 → 教学片上内存规划与独立检查 → 工业编译器的一处真实修改 → 匹配设备上的验证。** 详细实验取自 [[16.AI编译器/01.AI编译器与NPU培养方案|长期培养方案]] 的后半部分。

量化、ONNX 导入、真实 NPU 部署分别按后续任务补充。进入工业项目时先固定版本、跑基线、跟踪一个算子，再选范围明确的问题。模拟器验证与真机性能分别记录。

CUDA/Triton 属于 GPU 方向的另一项选择，等目标岗位确实需要时再安排。当前先把上述主项目完成。

## 5. 你下一次学习只做这一件事

利用下一次已有的 LLVM/MLIR 学习时段，完成“一个小函数的三种表示”。

| 用时建议 | 操作 | 留下什么 |
|---|---|---|
| 10 分钟 | 读 [[16.AI编译器/04.编译器与编译流程基础|编译流程基础]] | 用自己的话区分 AST、IR、目标代码 |
| 15 分钟 | 对返回 `(a + 0) + b` 的普通整数函数画简化 AST，再写直线伪 IR | 原始表示与加零消除后的表示 |
| 15 分钟 | 解释为什么可消除整数加零、为什么仍要保留 a+b、为什么不直接推广到浮点 | 三段简短说明 |
| 5–10 分钟 | 对照已有 Day 1 记录，标出独立答出的内容与仍需要提示的内容 | 本次结果和下一次要补的问题 |

这次先验证已有概念，不要求同时构建 LLVM 或写 C++ Pass。通过后，下一次进入真实 MLIR 的结构标注，再做矩阵参考。

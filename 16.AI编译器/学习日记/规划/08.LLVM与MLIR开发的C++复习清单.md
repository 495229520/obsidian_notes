# LLVM与MLIR开发的C++复习清单

本清单服务于[[16.AI编译器/00.学习导航|当前 LLVM／MLIR 学习主线]]：独立 LLVM Pass → MLIR 重写 → 张量到 CPU 的编译链路 → 分块优化。目标是能读懂接口、实现受限变换、定位错误，并解释正确性条件。

当前复习顺序是：内存与生命周期、容器与遍历、类型与模板、构建调试；图算法与编译器知识同步学习。进程线程先掌握基本概念与共享状态边界，网络 I/O 复用不作为当前项目的前置条件。

本文是知识范围、阅读索引和出题依据，不代表已经掌握，也不另排学习日期。实际学习任务、完成记录和实验结果继续由本目录的 Trellis 管理。既有笔记用于查概念；涉及 LLVM／MLIR API 时，以项目锁定版本的头文件、示例和测试为准。

## 2. 现在重点复习

### C01 指针、引用与 const

先读[[1.C++基础/6. 指针/6.4 引用|6.4 引用]]和[[1.C++基础/6. 指针/6.8 指针安全|6.8 指针安全]]，再用[[2.C++高级/4. const、指针和引用/4. const、指针和引用|const、指针和引用]]整理组合类型。参数设计结合[[1.C++基础/9. 函数/9.1 基础函数/9.1.2 函数参数|函数参数]]复习。

重点掌握：

- `T*`、`T&`、`const T&` 分别表达什么；指针类型本身不说明是否拥有对象。
- 指针可为空，引用要求绑定有效对象；引用后续仍可能因对象死亡而悬空。
- `const T*` 限制经该指针修改对象，`T* const` 限制指针本身重新绑定。
- 地址仍有数值、指针非空，都不能证明对象仍然存活。
- 接口是否允许空、是否保存参数、是否转移所有权，需要结合接口契约判断。

**编译器中的落点：** 拿到一个节点指针时，先问它由谁管理、能保存多久、哪些修改会让它失效。不能看到裸指针就擅自释放，也不能把所有裸指针统一改成智能指针。

达到 D2 的检查：

1. 给出 `T*`、`const T*`、`T&`、`const T&` 四种参数，分别说明能否修改对象、能否表示缺失。
2. 判断“返回局部对象的引用”和“返回调用者仍持有的对象的引用”有什么差别。
3. 设计一个只读节点查询接口，说明返回值在什么条件下有效。

出题方向：类型辨析、悬空引用找错、接口参数选择。先考一层指针；复杂二级指针资格转换按实际需要补。

### C02 构造析构、RAII 与所有权

基础来自[[1.C++基础/12. OOP/12.1 封装/12.1.6 构造函数|构造函数]]、[[1.C++基础/12. OOP/12.1 封装/12.1.7 析构函数|析构函数]]和[[1.C++基础/6. 指针/6.3 动态内存分配的风险|动态内存分配的风险]]。独占所有权重点读[[1.C++基础/6. 指针/智能指针/独享智能指针|独享智能指针]]，其中“函数设计中的所有权契约”“容器与数据结构中的所有权模式”最贴近本路线。

[[1.C++基础/6. 指针/智能指针/共享智能指针|共享智能指针]]与[[1.C++基础/6. 指针/智能指针/弱引用智能指针|弱引用智能指针]]先读所有权、控制块和循环引用，不要求复刻实现。

| 要点 | 掌握要求 | 容易犯的错误 |
|---|---|---|
| 构造与析构 | 知道基类、成员和派生对象的构造／析构顺序 | 把初始化列表的书写顺序当成成员初始化顺序 |
| RAII | 对象生命周期管理资源，提前返回时也能正确清理 | 只在正常结束路径手动清理 |
| unique_ptr | 区分 get、release、reset 和移动 | 把 get 当所有权转移，或 release 后无人接管 |
| shared_ptr | 多个所有者共享同一控制块 | 给同一裸指针创建两个独立控制块 |
| weak_ptr | 不延长对象寿命，访问前需要取得有效共享所有权 | 以为弱引用保证对象不会销毁 |
| 树和图 | 分清拥有边和观察边 | 因为使用者多，就让所有边都变成 shared_ptr |

**编译器中的落点：** 教学 AST 可以让父节点用 unique_ptr 拥有孩子；LLVM／MLIR IR 应遵守框架本身的管理方式。use-def 边描述定义与使用，不自动等于 C++ 共享所有权。

达到 D3 的检查：

- 独立设计只有常量和二元节点的小 AST，画清拥有边与观察边，解释销毁顺序。
- 在提前返回路径中验证资源会释放；验证借用指针不会擅自释放对象。
- 阅读框架创建和删除节点的接口，指出调用后哪些保存的指针或句柄不能再使用。

出题方向：析构顺序推导、所有权图设计、泄漏和重复释放定位。手写完整 shared_ptr、enable_shared_from_this 内部机制暂不作为验收项。

### C03 拷贝、移动与值语义

先用[[2.C++高级/8. 浅拷贝与深拷贝/8. 浅拷贝与深拷贝|浅拷贝与深拷贝]]理解资源复制问题，再读[[1.C++基础/13. 左值与右值/13.1 左值和右值|左值和右值]]、[[1.C++基础/13. 左值与右值/13.2 右值引用|右值引用]]和[[2.C++高级/15. C++11/15.8 移动语义与右值引用&&|移动语义]]。参数选择查[[1.C++基础/13. 左值与右值/13.4 左右值参数|左右值参数]]。

需要讲清楚的边界：

1. `std::move` 是转换，不负责搬运资源；最终调用哪种构造或赋值取决于类型和重载。
2. 移动后的源对象状态由类型契约决定，不能统一理解为“清空”。unique_ptr 移动后为空，不代表所有类型都如此。
3. 名字为右值引用的变量，在按名字使用时是左值表达式。
4. 返回对象可能发生拷贝消除，不能根据“返回了大对象”就断言一定发生拷贝或移动。
5. Rule of Zero 优先：资源交给合适的成员类型管理；确实定义资源管理行为时，再考虑特殊成员函数之间的关系。
6. 复制轻量句柄与克隆其指向的 IR 是两件事；图结构克隆还可能需要旧值到新值的映射。

**最低练习：** 用带构造日志的小类型区分拷贝构造、移动构造、拷贝赋值和移动赋值；再用 vector、unique_ptr 验证自己的解释。实际输出受拷贝消除影响时，注明语言标准和编译选项，不能把某次输出当作通用规则。

达到 D2：能判断一个参数传递是否可能复制，能正确转移 unique_ptr，能解释“为什么不对所有变量都使用 std::move”。

出题方向：重载选择、所有权转移、返回值与拷贝消除、句柄复制和对象克隆的区别。

### C04 容器选择与复杂度

以[[5.算法/5.1 STL/5.1.1 vector|vector]]为主，结合[[5.算法/5.1 STL/5.1.5 map|map 与 unordered_map]]、[[5.算法/5.1 STL/5.1.4 set|set 与 unordered_set]]、[[5.算法/5.1 STL/5.1.2 queue|queue]]复习。算法接口按需查[[5.算法/5.1 STL/5.1.11 算法|STL 算法]]；链式存储的取舍查[[5.算法/5.1 STL/5.1.3 list及其与其他结构的区别|list 与其他结构的区别]]。

| 场景 | 起步选择 | 必须能解释的取舍 |
|---|---|---|
| 保存一串节点或操作 | vector | 连续存储、随机访问、扩容、元素搬移 |
| 名字映射到符号 | unordered_map 或 map | 哈希查找与有序遍历；键的所有权与寿命 |
| 已访问节点与去重 | unordered_set 或 set | 插入、查询、顺序要求及最坏情况 |
| 待处理节点 | queue 或 vector 作为栈 | 处理顺序为什么适合当前算法 |
| 自定义排序 | 算法加比较器 | 比较器需满足严格弱序，不能用任意判定函数替代 |

重点会用 size、capacity、reserve、resize，区分“预留容量”和“创建元素”。了解 map 查询的 `operator[]` 可能插入默认值；只想查询时选不会悄悄插入的接口。

达到 D2：写一个小符号表和访问集合，处理缺失名字、重复名字、重复访问；说明预期复杂度。知道哈希表查找通常为平均常数复杂度，不能承诺所有情况下都是常数。

LLVM 中再学习 SmallVector、DenseMap、DenseSet 的接口和约束，见 [[#F01 LLVM 容器与非拥有视图|F01]]。不要把 STL 的失效规则直接套给所有 LLVM 容器。

> [!warning] 复习现有 map 笔记时先辨清
> 现有 map 笔记开头的有序性表格容易误读，“有序哈希表 map”的标题也不准确。std::map 按比较器有序，通常以红黑树实现；unordered_map 不保证键的排序。这里保留勘误提醒，不改动原笔记。

### C05 迭代器与修改中的遍历

读[[2.C++高级/12. 迭代器/12.1 迭代器基础概念|迭代器基础概念]]和[[2.C++高级/12. 迭代器/12.3 迭代器的失效问题|迭代器的失效问题]]。[[2.C++高级/12. 迭代器/12.2 vector容器的迭代器实现|vector 迭代器实现]]作为原理参考，不要求闭卷重写。

重点不是背一张表，而是能分析“当前操作改变了哪段存储、哪些元素已经不存在”：

- vector 重新分配后，原元素的指针、引用、迭代器会失效。
- 即便没有重新分配，插入或删除也可能使一部分迭代器和引用失效；预留容量不是万能修复。
- erase 后继续使用被删除元素的指针，和迭代器递增写错，是不同错误。
- list 删除当前节点与 vector 删除当前元素的规则不同；节点容器也不意味着所有操作都安全。
- 遍历结束标记是否可以缓存，需要结合容器及修改方式判断。

**迁移到 Pass：** “先递增再删除”“提前保存候选”“使用框架提供的遍历辅助接口”都可能适用，但有不同前提。提前保存原始指针也不能保证安全：后续一次重写可能连带删除其他候选。

达到 D3 的练习：先独立写对 vector 的条件删除，再分析一个删除 IR 操作的遍历。说清当前迭代器、下一个节点、保存的候选及使用关系是否仍然有效。

出题方向：边遍历边删除找错、扩容引起的悬空、一次重写影响多个候选。每题要求指出失效发生在哪一步，不接受只回答“可能崩溃”。

### C06 字符串、视图与句柄

字符串基础读[[1.C++基础/8. 字符串/8.1 string|string]]或[[5.算法/5.1 STL/5.1.6 string|STL string]]，无需重复通读。非拥有访问重点读[[2.C++高级/15. C++11/15.13 std-span|std-span]]中的第 1、3、6、7 节；RPC 编解码应用先略读。

std::span 属于 C++20，虽在当前笔记的 C++11 目录下，也不能由目录名推断它的标准版本。这里用它学习视图概念；项目未启用 C++20 时，不为学习它而擅自更改工程语言标准。

| 对象 | 需要分清的内容 |
|---|---|
| std::string／vector | 拥有元素存储，修改和扩容可能影响观察者 |
| span／ArrayRef／StringRef | 观察已有存储，不负责使底层对象继续存活 |
| const span 与 span<const T> | 前者限制视图对象，后者限制经视图访问元素；不能混同 |
| MLIR 的 Value 或类型化 Op 包装 | 复制包装值不等于复制其底层 IR；需要分别核对有效期 |

另一个容易混淆的地方是[[1.C++基础/12. OOP/12.1 封装/12.1.5 const成员函数|const 成员函数]]：const 通常限制当前对象的直接状态，不能自动递归冻结指针指向的对象。分析一个“const 句柄”时，要查看它提供的实际访问接口。

达到 D3：能找出返回局部字符串视图、保存临时容器视图、扩容后继续访问旧视图等错误；在框架中解释一个 Op 被删除后，旧包装对象为什么不能继续使用。

出题方向：拥有与非拥有类型对照、视图寿命、浅层 const、句柄复制与底层克隆。不要把所有框架值类型都归为同一种所有权模型。

### C07 类、继承与多态

重点读[[1.C++基础/12. OOP/12.3 多态/12.3.2 虚函数|虚函数]]、[[1.C++基础/12. OOP/12.3 多态/12.3.4 抽象类|抽象类]]和[[2.C++高级/6. OOP/6.2 继承/6.2.2 重载、隐藏、覆盖|重载、隐藏、覆盖]]。继承构造与析构有疑问时回查[[1.C++基础/12. OOP/12.2 继承/12.2.2 继承构造函数|继承构造函数]]、[[1.C++基础/12. OOP/12.2 继承/12.2.3 继承析构函数|继承析构函数]]。

本模块需要掌握：

- 基类接口与派生实现；public、protected、private 对访问的影响。
- override 如何帮助检查覆盖；参数、const 等不匹配可能产生隐藏或新重载。
- 对象切片为什么会丢失派生部分。
- 通过基类指针销毁派生对象时，虚析构的要求。
- 普通运行时多态和模板静态多态的基本区别；不要把框架中所有继承都理解成虚函数分发。

达到 D2：读懂自己使用的 Pass 或 Pattern 的声明，找出基类要求实现的函数，独立完成一个派生类。能说明调用经过哪个接口，以及实例由谁管理。

出题方向：覆盖失败定位、析构行为、切片、接口扩展。虚表布局、多重继承的指针调整和 ABI 细节暂时只作选读。

### C08 模板、类型推导与 CRTP

主读[[2.C++高级/10. 模版/10.1 函数模版|函数模板]]和[[2.C++高级/10. 模版/10.2 类模版|类模板]]。模板参数与推导回查[[1.C++基础/9. 函数/9.2 函数重载/9.2.6 函数模版参数|函数模板参数]]、[[1.C++基础/9. 函数/9.2 函数重载/9.2.5 auto类型推导|auto 类型推导]]；转发引用结合[[1.C++基础/13. 左值与右值/13.4 左右值参数|左右值参数]]学习。

| 内容 | 当前要达到的程度 | 后移范围 |
|---|---|---|
| 函数与类模板 | 能读写简单模板，说明实例化时类型如何确定 | 通用模板库设计 |
| 类型与非类型参数 | 能辨认参数究竟是类型、整数还是其他允许的实参 | 复杂编译期计算 |
| auto／auto&／const auto& | 能判断是否复制、是否允许修改 | 所有推导边角规则 |
| typename／template 消歧义 | 看见依赖名称时能识别，并通过局部例子验证 | 系统复刻两阶段查找规则 |
| std::forward | 知道它用于保留转发参数的值类别，区别于无条件 std::move | 多层完美转发工具库 |
| CRTP | 理解派生类型被作为基类模板参数，能追踪静态接口 | 复杂混入层级与元编程技巧 |
| traits | 能找到某项静态约束或行为由何处提供 | 实现完整 traits 框架 |

**编译器中的落点：** 读懂 OpRewritePattern 的目标操作类型、模板基类关系、生成的类型接口。MLIR 的 Op 定义使用 CRTP 与 traits，可用 [Toy 第 2 章](https://mlir.llvm.org/docs/Tutorials/Toy/Ch-2/)对照，不要求先读完整套模板专著。

达到 D2：能把框架类型名替换成一个小示例说明关系；模板报错时找到第一处涉及自己代码的类型不匹配，解释预期类型与实际类型。

出题方向：模板参数辨认、引用推导、CRTP 结构解释、编译错误定位。类模板笔记中的手写 vector 与空间配置器可以暂时略过。

### C09 lambda、回调与现代语法

重点读[[2.C++高级/15. C++11/15.4 lambda|lambda]]，结合[[2.C++高级/15. C++11/15.1 auto、foreach|auto 与范围遍历]]、[[2.C++高级/15. C++11/15.7 using、nullptr|using 与 nullptr]]、[[2.C++高级/15. C++11/15.11 default、delete、初始化列表|default、delete 与初始化列表]]。需要回顾可调用对象时读[[2.C++高级/15. C++11/15.6 仿函数|仿函数]]和[[2.C++高级/15. C++11/15.12 回调函数|回调函数]]。

先掌握：

- 值捕获与引用捕获分别保存什么；捕获 this 不会自动延长当前对象的生命周期。
- 即时调用的回调与被保存、延后执行的回调，有不同的寿命要求。
- 范围遍历中的 auto、auto&、const auto&；避免不必要复制，也不能对已失效对象引用遍历。
- using 可以声明类型别名，也可以引入基类成员或继承构造函数；根据上下文区分。
- default 与 delete 对特殊成员函数和接口的影响。
- 结构化绑定、enum class、optional 能读懂并用于简单数据和状态表达。相关基础已收录在[[2.C++高级/15. C++11/15.13 std-span|std-span 笔记第 0 节]]，无需重读整篇 RPC 应用。

达到 D2：用 lambda 统计局部遍历结果；再把回调改为延迟执行，主动指出哪些捕获方式需要调整。解释框架是否会保存回调，不能只从 lambda 语法猜测。

出题方向：捕获生命周期、遍历复制、回调保存、using 的不同用途。

### C10 类型判断与错误返回

基础阅读[[2.C++高级/13. 类型转换方式/13. 类型转换方式|类型转换方式]]和[[2.C++高级/15. C++11/15.9 枚举类|枚举类]]。可选结果的类型表达回查[[2.C++高级/15. C++11/15.13 std-span|std-span 笔记的 optional 小节]]。

对 C++ 转换先做到：能解释 static_cast 的前提，知道 dynamic_cast 的适用范围；const_cast 不会使原本的 const 对象变成可安全修改的对象，reinterpret_cast 也不能替代有效的对象生命周期和类型规则。

再迁移到 LLVM／MLIR：

- isa：判断是否满足目标类型条件。
- cast：调用者已有类型成立的依据；不能靠断言在所有构建模式下兜底。
- dyn_cast：尝试转换，按所用接口检查转换失败。
- LLVM Error／Expected：处理错误，或按接口要求向上转交。
- MLIR LogicalResult／FailureOr：区分状态和带结果的成功／失败。

LLVM 使用自己的类型判断接口，具体空值处理和可接受参数依版本及重载而定。使用前对照 [LLVM 类型转换说明](https://llvm.org/docs/ProgrammersManual.html#the-isa-cast-and-dyn-cast-templates)和项目头文件。

达到 D2：在一个“识别操作 → 检查条件 → 变换或失败”的例子中，解释每一步的类型前提与失败路径。不通过强制转换压掉编译错误，不把所有失败都当成异常。

出题方向：cast 前提缺失、失败返回值被忽略、匹配失败与整个 Pass 失败的区别。错误类型的完整内部实现后移。

### C11 编译链接、构建与调试

先读[[1.C++基础/1. 计算机基础/1.1 程序编译与链接原理|程序编译与链接原理]]，结合[[1.C++基础/9. 函数/9.1 基础函数/9.1.8 函数声明与定义|函数声明与定义]]、[[1.C++基础/9. 函数/9.1 基础函数/9.1.9 头文件|头文件]]和[[1.C++基础/11. 编译器/11.1 ODR唯一定义规则|ODR]]理解多翻译单元。[[1.C++基础/11. 编译器/11.3 inline|inline]]重点区分语言规则与优化决策。

工程部分主读[[3.Linux/14. Makefile/14.3 CMake基础|CMake 基础]]，再读[[3.Linux/14. Makefile/14.4 CMake进阶|CMake 进阶]]中的多目录项目、查找依赖和库目标。Makefile 暂时做到能读常见构建命令，不要求先手写 LLVM 的构建系统。

| 问题 | 应能定位到的层次 |
|---|---|
| 找不到头文件或类型 | 包含关系、包含目录、命名空间、版本 |
| undefined reference／重复定义 | 缺少实现、链接依赖、签名、ODR |
| 插件不能加载 | 实际加载路径、所用工具与库的版本、构建配置 |
| 程序崩溃 | 断点、调用栈、局部对象与生命周期 |
| 没有发生预期重写 | Pass 是否注册和执行、匹配条件、输入 IR |
| 运行了却输出错误 | 类型、使用关系、变换条件与运行对照 |

达到 D3 的验收：

1. 独立构建一个受限 Pass 或 standalone 工程，说明每个 target 和依赖的用途。
2. 能在自己的实现处下断点，查看节点类型、操作数与必要的状态。
3. 将失败输入缩小到能暴露问题的最小例子；保留命中、不命中和错误输入测试。
4. 区分“IR 校验通过”和“语义正确”；执行对照也不能只测一组值。
5. 记录项目实际 LLVM／MLIR 版本和复现命令，避免混用不同版本的工具与库。

出题方向：头文件与模板可见性、ODR、链接排错、CMake 依赖、失败用例定位。调试器、Sanitizer、lit／FileCheck 是实践中需要补的工具，不假定现有 C++ 笔记已完整覆盖。

### C12 整数、位运算与浮点边界

基础查[[1.C++基础/2. 基本数据类型/2.1 C++基本数据类型|C++ 基本数据类型]]、[[1.C++基础/3. 运算符/3.3 位运算|位运算]]。张量索引与数值验证接到[[16.AI编译器/02.AI编译器与MLIR的数学和算法基础|AI 编译器的数学和算法基础]]，重点是索引、布局、整除边界与浮点误差。

当前需要分清：

- 宿主 C++ 的类型宽度与目标 IR 类型不是同一件事，不能用宿主 int 表示所有 IR 整数。
- C++ 有符号整数溢出不能当作合法的自动回绕；无符号整数运算和位移也有各自的规则。
- size_t 与有符号索引混用时的转换，可能让负数变成大正数。
- shape 乘积、线性偏移、分块上界都可能溢出；“结果最终很小”不能证明中间计算安全。
- 浮点加法不保证结合律；归约重排、NaN、无穷和有符号零的影响，需要按所做变换分析。
- LLVM IR 的标志与浮点选项影响变换合法性，不能把 C++ 直觉直接套入 IR。

达到 D2：给定小矩阵手推地址偏移和尾块范围；构造一次整数边界和一次浮点归约顺序变化；能说明宿主计算、IR 语义和最终执行结果各自在哪一层。

LLVM IR 具体语义按项目版本的 [Language Reference](https://llvm.org/docs/LangRef.html)核对；APInt／APFloat 等类型遇到时再补接口，不要求在起步阶段实现任意精度运算。

出题方向：有符号与无符号比较、索引计算、溢出前提、浮点变换反例。不要用“数学上相等”直接证明程序变换合法。

先读[[5.算法/5.2 算法/5.2.12 二叉树与遍历算法|二叉树与遍历]]建立结构遍历概念，再读[[5.算法/5.2 算法/5.2.26 图与图算法|图与图算法]]中的存储、DFS、BFS。[[5.算法/5.2 算法/5.2.27 拓扑排序与有向无环图|拓扑排序与 DAG]]用于理解无环依赖；现阶段无需连带复习最短路、最小生成树全部专题。

先达到 D1，接真实执行入口时达到 D2：能解释参数与返回值、符号名、外部声明，以及缓冲区由谁分配和释放。extern "C" 不能替代完整的 ABI 匹配；数据类型、布局和调用约定仍需一致。

### B03 线程、锁与框架并行边界

先读[[3.Linux/17. 并发同步/17.1 并发同步概述：多执行流与共享可变状态|共享可变状态与并发同步概述]]，再读[[3.Linux/17. 并发同步/17.3 锁机制、死锁与故障|锁、死锁与故障]]、[[3.Linux/17. 并发同步/17.8 Modern C++ 同步设施与实战并发模式|Modern C++ 同步设施]]中的 RAII 锁管理。线程生命周期按需查[[2.C++高级/15. C++11/15.2 thread|thread]]，原子概念查[[2.C++高级/15. C++11/15.3 atomic|atomic]]。

当前达到 D1，进入并行 Pass 或运行时后达到相应 D2：

1. 区分数据竞争、逻辑竞态与死锁；知道单个原子变量不能自动保护多个变量的整体不变式。
2. 知道线程退出、join、共享对象寿命与锁作用域的关系。
3. 阅读 MLIR Pass 对跨操作访问、可变状态和并行执行的约束；先遵守框架边界，不自行给共享状态加一把锁就认为合法。
4. 区分编译器本身并行编译、生成代码并行执行、网络服务并发这三个场景。

MLIR 的具体限制见 [Pass Infrastructure](https://mlir.llvm.org/docs/PassManagement/#operation-pass)。题目应先考“是否应共享这些状态”，再考“怎样同步”。无锁结构、复杂内存序和自制任务调度器后移。

### B04 分配内存与构造对象

遇到 arena、批量节点分配或自定义存储时，再读[[1.C++基础/12. OOP/12.1 封装/12.1.8 对象放置构造|对象放置构造]]、[[1.C++基础/12. OOP/12.1 封装/12.1.13 malloc与new|malloc 与 new]]和[[2.C++高级/5. new 和 delete/5. new和delete|new 与 delete]]。

达到 D1：能区分存储分配、对象构造、对象销毁、存储回收，理解集中管理存储不自动等于正确调用所有析构行为。实际采用哪个框架分配器，再查其对齐、对象类型和清理契约。

不要求先实现 allocator 或修改全局分配行为。这个模块用于读懂现有代码，不是要求把普通练习改成手工内存管理。

## 4. 从 C++ 基础接到 LLVM／MLIR

### F01 LLVM 容器与非拥有视图

前置模块：C04、C05、C06。

在实际接口中学习 SmallVector、DenseMap、DenseSet、ArrayRef、StringRef，分别记录元素存储、所有权、适用操作和失效条件。SmallVector 的内联存储不等于永远不分配；ArrayRef／StringRef 不延长底层数据寿命。对照 [LLVM Programmer’s Manual](https://llvm.org/docs/ProgrammersManual.html)查自己当前使用的类型。

验收：把一个使用 STL 的局部数据收集例子改为框架需要的接口类型，解释选择理由。不得仅因为“LLVM 常用”就批量替换所有容器。

### F02 IR 的拥有关系与对象句柄

前置模块：C01、C02、C03、C06。

找到一个操作的创建处、所在 Block／Region、使用者和删除处；再区分 Operation 指针、类型化 Op 包装、Value 与显式拥有包装的用途。遇到 OwningOpRef 等类型时核对实际所有权契约。

验收：能回答“复制这个变量会不会创建新 IR”“删除后哪个变量失效”“为什么一个结果有多个使用者不等于需要 shared_ptr”。这里只要求读懂自己操作的对象链路。

### F03 Pattern 的类型接口与重写契约

前置模块：C05、C07、C08、C10。

结合 [MLIR Pattern Rewriter](https://mlir.llvm.org/docs/PatternRewriter/)阅读自己的模式：匹配条件、类型检查、替换结果和失败路径。模式中的 IR 修改要经过所提供的 PatternRewriter；成功匹配前不能先改一半 IR 再返回失败。

验收：对一个不应命中的输入返回失败且不改动 IR；对命中输入说明替换值的类型、使用关系与原操作的处理。能说明局部匹配失败与整个 Pass 失败不是同一件事。

### F04 Pass 状态、分析与测试

前置模块：C10、C11、B01、B03。

先会注册、构建和独立运行一个 Pass，再学习它依赖的分析和分析失效。修改 IR 后，不能无条件宣称旧分析仍有效。并行执行约束按具体 Pass 框架与锁定版本核对。

验收：能证明自己的 Pass 实际执行过，测试能区分“没运行”“没有匹配”“错误替换”。IR 校验、文本检查和执行对照各有用途，不能互相替代。测试工具按 [LLVM Testing Guide](https://llvm.org/docs/TestingGuide.html)选择与当前实验相关的部分。

### F05 宿主程序与被编译程序的语义

前置模块：C12、B02，以及[[16.AI编译器/02.AI编译器与MLIR的数学和算法基础|张量与算法基础]]。

区分 C++ 写成的编译器、内存中的 IR、IR 最终生成并执行的程序。C++ 的一个数、一个循环或一个指针，不会自动与目标 IR 中对应概念具有相同语义。

验收：解释一个常量计算、索引计算或浮点重排，分别列出宿主侧的计算条件、IR 的语义条件和执行侧的验证方法。优化成立与是否更快也要分别证明。

## 6. 项目开始前与过程中的综合验收

### 6.1 起步检查

能完成下列内容，就可以开始受限 Pass；尚未完成的 D3 要求在对应项目中练习，不必把所有模块都学完再动手。

| 检查 | 最小成果 | 不通过时回到哪里 |
|---|---|---|
| 拥有与借用 | 小 AST 的节点拥有图，能解释提前返回与销毁 | C01、C02 |
| 容器和遍历 | 名字映射、访问集合、正确的条件删除 | C04、C05 |
| 框架类型阅读 | 能解释一个模板基类、override、回调和类型判断 | C07—C10 |
| 构建运行 | 构建并执行一个小工程，区分编译错误与链接错误 | C11 |
| 算法基础 | 遍历带环图，解释去重与重新入队的区别 | B01 |

### 6.2 LLVM Pass 验收

选择导航中已限定的标量整数变换，不扩成通用优化器。必须明确匹配范围和语义条件，不能把浮点变换混进整数例子。

- 能定位目标操作、检查类型并正确替换使用关系。
- 遍历与删除安全，修改后不访问旧节点。
- 单独运行自己的 Pass 时能观察到效果，不能由其他 Pass 代替完成。
- 有命中、不命中、IR 校验和执行对照；能解释测试分别防什么错误。
- 版本、构建与运行入口可以复现。

### 6.3 MLIR 重写验收

用导航中限定的静态二维转置重写练习，结合 C06、C08、C10 和 F02—F03：说明类型与 shape 条件，正确使用重写接口，保留命中与不命中输入，检查重写后的使用关系。

重点解释“复制 Op 包装”和“创建新操作”的差别，以及失败时为什么不能留下部分修改。目标不是背诵一份完整 Toy 实现。

### 6.4 张量 CPU 与分块阶段验收

结合 C12、B02、F05：手算 MatMul 索引、连续行主序偏移与非整块边界；用外部输入和独立参考验证结果。区分编译耗时、算子执行耗时与端到端耗时。

优化前后保持输入、设备和测量条件可比较。先保证正确性，再解释局部性或访存变化；不能用“分块通常更快”替代实际结果。

## 7. 后续让 AI 出题与讲解的使用约定

### 7.1 如何指定范围

直接使用模块编号，例如“针对 C02 出题”“讲解 C06 到 F02 的联系”“检查我是否具备写第一个 Pass 的 C++ 基础”。先读取本模块及其实际链接到的笔记，避免只凭模块标题泛泛出题。

每次优先围绕一个模块展开；综合题再组合两个以上模块。没有指定难度时，从目标深度低一级做诊断，答对后提升到目标深度。不能从“已经有笔记”推断学习者已经掌握。

### 7.2 出题与反馈要求

| 题型 | 要检查什么 | 合适的任务 |
|---|---|---|
| 概念与口述 | 是否知道前提与边界 | 拥有与借用、复制与克隆、const 的作用范围 |
| 代码阅读 | 是否能逐步推导行为 | 析构顺序、拷贝／移动、捕获与失效 |
| 找错与修复 | 是否能定位根因 | 悬空视图、迭代器失效、错误类型转换 |
| 局部实现 | 是否能独立使用 | AST 所有权、符号表、工作队列、条件删除 |
| 编译器迁移 | 是否能用于真实接口 | IR 替换、Pattern 失败路径、Pass 状态 |

讲解与批改应遵循：

1. 先让我回答或写出推导，不把完整答案和实现一开始全部展示。
2. 错误要定位到具体步骤：语法、类型、生命周期、算法、IR 语义或框架契约；这些原因不能混为一谈。
3. 给出成立条件与反例。涉及未定义行为时，不要求预测固定输出；涉及实现相关行为时注明平台或版本。
4. 代码采用最小可理解示例，讲清为什么这样写。无需为单线程语法或纯计算例子强画图。
5. LLVM／MLIR 题先确认版本；可编译 API 示例与伪代码明确区分，不编造接口。
6. 改变输入、节点寿命或类型后再追问一次，检查是否只记住原答案。
7. 一次答对只证明本次题目通过。正式学习记录按现有任务体系维护，不擅自修改本清单或标记整个模块完成。


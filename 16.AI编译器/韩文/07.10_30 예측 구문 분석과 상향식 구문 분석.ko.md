# CS143 제7강: 예측 구문 분석과 좌측 인수 분해

일반적인 재귀 하강 구문 분석(Recursive-Descent Parsing)은 여러 생성 규칙을 시도하며 백트래킹할 수 있다. 이번 강의에서는 스탠퍼드 CS143의 예측 구문 분석(Predictive Parsing), LL(k)·LL(1) 문법, 그리고 예측 충돌을 해결하기 위한 좌측 인수 분해(Left Factoring)를 다룬다.

## 1. 예측 구문 분석의 개념과 스택 기반 실행 모델

### 1.1 예측 구문 분석과 LL(k) 문법

예측 구문 분석기는 재귀 하강 분석기처럼 문법을 위에서 아래로 전개한다. 차이는 다음에 사용할 생성 규칙을 미리 결정한다는 점이다.

- 앞으로 읽을 몇 개의 토큰을 확인한다. 이를 미리보기(Lookahead)라고 한다.
- 미리 본 토큰으로 생성 규칙을 선택하므로 백트래킹이 없다.
- 이러한 결정을 할 수 있는 제한된 문법, 즉 LL(k) 문법을 사용한다.

### 1.2 재귀 하강과 예측 구문 분석: 미로 탐색과 안내 표지판

백트래킹을 사용하는 재귀 하강 분석은 갈림길에서 한 경로를 시도하고, 실패하면 입력 위치를 되돌려 다른 경로를 시도하는 방식이다. 구현에서는 입력 위치를 `save`에 저장하고 실패 시 `next = save`로 복구한다. 분기가 중첩되면 같은 입력 구간을 여러 번 분석할 수 있으며, 나쁜 경우에는 시도 횟수가 지수적으로 증가한다. 단순한 구현에서는 짧은 분기가 먼저 성공한 뒤, 바깥쪽 분석에서 실패했을 때 그 선택을 다시 검토하지 못하는 문제도 생긴다.

LL(1) 예측 구문 분석은 현재 비단말 기호와 다음 토큰 하나를 보고 분석표에서 생성 규칙을 선택한다. 길을 시도한 뒤 되돌아가는 대신, 갈림길에서 표지판을 보고 경로를 결정하는 셈이다. 고정된 LL(1) 문법에서는 입력 길이 $n$에 대해 $O(n)$ 시간에 분석할 수 있다.

```text
[백트래킹을 사용하는 재귀 하강]
입력: [ a ] [ b ] [ c ] ...
위치: 앞뒤로 이동할 수 있음

분기 1 시도 -> 실패 -> 입력 위치 복원 -> 분기 2 시도 -> ...
문제: 중복 분석이 누적되며, 최악의 경우 시도 횟수가 지수적으로 증가한다.

[예측 구문 분석]
입력: [ a ] [ b ] [ c ] ...
미리보기: 현재 위치의 토큰 하나를 확인하되, 조회만으로 소비하지는 않음

(현재 비단말 기호, 미리보기 토큰) -> 분석표 조회 -> 생성 규칙 선택
특징: 백트래킹 없이 입력을 왼쪽에서 오른쪽으로 처리한다.
```

### 1.3 LL(k)의 각 문자가 뜻하는 것

- 첫 번째 L: 입력을 왼쪽에서 오른쪽으로 읽는다(Left-to-right).
- 두 번째 L: 가장 왼쪽 비단말 기호를 먼저 전개하는 최좌단 유도를 구성한다(Leftmost derivation).
- k: 생성 규칙을 결정하기 위해 미리 보는 토큰의 수다.

LL(1)은 토큰 하나만 보고 선택한다. k가 커지면 구별할 수 있는 문법의 범위는 늘어나지만, 가능한 토큰 조합과 분석표의 크기도 커진다.

### 1.4 분석 스택은 구문 트리의 미처리 프런티어를 저장한다

표 기반 예측 분석기는 다음과 같이 동작한다.

1. 스택 맨 위의 비단말 기호 $S$를 확인한다.
2. 다음 입력 토큰 $a$, 즉 `*next`를 확인한다.
3. 분석표 $M[S,a]$를 조회하여 적용할 생성 규칙을 선택한다.

구문 트리를 위에서 아래로 만들 때 아직 전개하거나 입력과 대조하지 않은 잎들을 왼쪽부터 나열하면, 앞으로 처리할 기호의 순서가 된다. 분석 스택은 이 순서를 저장한다.

스택에는 두 종류의 기호가 들어간다.

- 비단말 기호: 분석표를 조회해 생성 규칙의 우변으로 전개해야 한다.
- 단말 기호: 입력 토큰과 일치하는지 확인한 뒤 소비해야 한다.

스택 맨 위에는 가장 왼쪽의 미처리 기호가 놓인다. 이것이 최좌단 유도를 구현하는 방식이다.

#### 구문 트리의 프런티어와 스택의 대응

```text
단계 1: 시작 기호 E
트리: E
미처리 프런티어: E
스택(맨 위부터): E, $

단계 2: E -> T X
       E
      / \
     T   X
미처리 프런티어: T, X
스택(맨 위부터): T, X, $

단계 3: T -> int Y
       E
      / \
     T   X
    / \
  int  Y
미처리 프런티어: int, Y, X
스택(맨 위부터): int, Y, X, $

단계 4: 입력의 int와 일치시켜 소비
       E
      / \
     T   X
    / \
  int  Y
   ^ 이미 일치 확인
미처리 프런티어: Y, X
스택(맨 위부터): Y, X, $
```

> [!tip] 우변을 역순으로 넣는 이유
> 프런티어의 왼쪽 기호를 먼저 처리하려면 그 기호가 스택 맨 위에 있어야 한다. $E \to TX$를 적용할 때는 $X$를 먼저 넣고 $T$를 나중에 넣는다. 그러면 $T$가 맨 위에 놓인다.

분석의 종료 조건은 다음과 같다.

- 거부(Reject): 분석표의 항목이 비어 있거나, 스택의 단말 기호가 현재 입력과 일치하지 않으면 구문 오류다.
- 수락(Accept): 입력과 스택의 끝 표시 `$`까지 일치시켜 처리하면 분석이 끝난다.

재귀 하강에서는 함수 호출 스택이 앞으로 처리할 작업을 암묵적으로 저장한다. 표 기반 분석기는 이를 명시적인 자료구조로 옮겨 반복문으로 실행한다. 재귀 호출 깊이를 직접 관리할 수 있다는 장점이 있지만, 실제 메모리 사용량과 속도는 구현에 따라 달라진다.

### 1.5 표 기반 예측 분석기의 일반 알고리즘

```text
initialize stack = <S $> and next
repeat
  case stack of
    <X, rest> : if M[X, *next] = Y1 ... Yn
                then stack <- <Y1 ... Yn rest>;
                else error();
    <t, rest> : if t == *next ++
                then stack <- <rest>;
                else error();
until stack == < >
```

#### 초기화와 반복문

`initialize stack = <S $> and next`는 시작 기호 $S$와 끝 표시 `$`로 스택을 초기화한다. 여기서 스택 맨 위는 왼쪽이다. 입력 포인터 `next`는 첫 토큰을 가리키며, 입력 끝에도 `$`가 있다.

반복문은 스택 맨 위가 비단말 기호인지 단말 기호인지 구분하여 처리한다. 마지막 `$`까지 처리하여 스택이 비면 종료한다.

#### 분기 1: 비단말 기호 `<X, rest>`

`X`는 전개할 비단말 기호, `rest`는 그 아래에 남은 기호들이다.

`M[X, *next]`에서 우변 $Y_1\cdots Y_n$을 얻으면 $X$를 꺼내고 그 우변으로 대체한다. 새로운 스택은 `<Y1 ... Yn rest>`이며 $Y_1$이 맨 위다.

이때 입력 포인터는 움직이지 않는다. 생성 규칙을 전개했을 뿐 입력 토큰을 대조하지 않았기 때문이다. 우변이 $\varepsilon$이면 아무것도 넣지 않아 스택이 `<rest>`가 된다. 표 항목이 비어 있으면 오류를 보고한다.

#### 분기 2: 단말 기호 `<t, rest>`

스택의 단말 기호 $t$와 현재 입력 `*next`를 비교한다. 일치하면 $t$를 꺼내고 입력 위치를 한 칸 옮긴다. 일치하지 않으면 오류다.

위 의사 코드의 `*next ++`는 현재 토큰을 읽고 포인터를 증가시키는 축약 표기다. 오류 처리까지 구현할 때는 비교와 포인터 이동을 분리하면 동작을 더 명확하게 표현할 수 있다.

#### 종료

스택의 `$`와 입력의 `$`를 일치시켜 처리하면 스택이 빈 상태 `< >`가 된다. 입력 전체가 문법에 맞게 분석된 것이다.

## 2. 유도 상태와 세 가지 분기 선택 결과

재귀 하강에서는 여러 생성 규칙을 시도할 수 있지만, LL(1)에서는 현재 토큰에 적용할 생성 규칙이 하나로 결정되어야 한다.

유도 도중의 문장 형식을 다음과 같이 나타내자.

$$wA\beta$$

다음 입력 토큰이 `+`라면, 분석기의 질문은 “$A$의 어느 생성 규칙 $A\to\alpha$를 선택할 것인가?”다.

### 2.1 $wA\beta$는 분석기의 현재 상태다

```text
이미 일치한 부분 w | 현재 전개할 A | 나중에 처리할 β
예: 1 + 2 *       | E             | ;
```

- $w$: 이미 일치시켜 소비한 단말 기호의 접두부다.
- $A$: 현재 문장 형식에서 가장 왼쪽의 비단말 기호다. 생성 규칙 $A\to\alpha$의 좌변(LHS)이기도 하다.
- $\beta$: $A$ 뒤에서 처리를 기다리는 기호열이다.
- 다음 입력 `+`: 아직 소비하지 않은 미리보기 토큰이다.

### 2.2 분석표 조회 결과는 세 가지다

| $M[A,t]$의 내용 | 의미 | 처리 |
| --- | --- | --- |
| 생성 규칙 1개 | 현재 토큰으로 규칙을 결정할 수 있다 | 해당 규칙으로 전개 |
| 생성 규칙 0개 | 현재 위치에서 입력을 이어갈 수 없다 | 구문 오류 보고 또는 오류 복구 |
| 생성 규칙 2개 이상 | 토큰 하나로 규칙을 구별할 수 없다 | LL(1) 충돌로 판단 |

생성 규칙이 하나이면 백트래킹 없이 적용한다.

표가 비어 있으면 해당 토큰에 맞는 전개가 없다는 뜻이다. $A$가 현재 토큰으로 시작할 수 없고, $A$를 빈 문자열로 없애 뒤의 구조가 그 토큰을 처리하도록 할 수도 없는 경우다. 분석기는 오류를 보고하거나, 구현된 복구 전략에 따라 토큰을 건너뛰어 동기화한다. 패닉 모드(Panic Mode)는 그 복구 방식 중 하나다.

표 항목에 여러 규칙이 들어가면 문법이 LL(1)이 아니다. 공통 접두부, 좌재귀, 모호성 등이 원인일 수 있다. 원인에 따라 좌측 인수 분해나 문법 재작성, 다른 분석 방식이 필요하다.

## 3. 공통 접두부가 예측을 방해하는 이유

다음 산술식 문법을 보자.

$$
\begin{aligned}
E &\to T+E\mid T\\
T &\to \text{int}\mid\text{int}*T\mid(E)
\end{aligned}
$$

$T$의 두 선택지는 모두 `int`로 시작한다. 현재 토큰이 `int`라는 사실만으로는 단독 정수인지, 뒤에 곱셈이 이어지는지 알 수 없다.

$E$의 두 선택지는 모두 $T$로 시작한다. $T$는 `int` 또는 `(`로 시작할 수 있으며, 그 자체가 긴 식일 수도 있다. 토큰 하나만으로는 $T$ 뒤에 `+`가 있는지 판단할 수 없다.

```text
T의 선택:
  int
  int * T
  ( E )
  ^ 처음 두 선택지는 첫 토큰이 같다.

E의 선택:
  T + E
  T
  ^ T를 다 읽기 전에는 뒤에 +가 있는지 알기 어렵다.
```

이 문제를 해결하기 위해 공통 접두부를 먼저 처리하도록 문법을 바꾼다.

## 4. 좌측 인수 분해의 원리와 문법 재작성

### 4.1 선택을 공통 접두부 뒤로 미룬다

공통 접두부를 먼저 읽고, 그 뒤에 새 비단말 기호를 두어 나머지 선택을 맡긴다.

일반적인 변환은 다음과 같다.

$$A\to\alpha\beta_1\mid\alpha\beta_2\mid\gamma$$

공통 접두부 $\alpha$를 분리하면 다음과 같다.

$$
\begin{aligned}
A&\to\alpha A'\mid\gamma\\
A'&\to\beta_1\mid\beta_2
\end{aligned}
$$

### 4.2 $T$의 좌측 인수 분해

원래 규칙은 다음과 같다.

$$T\to\text{int}\mid\text{int}*T\mid(E)$$

두 분기의 공통 접두부는 `int`, 남은 부분은 각각 $\varepsilon$과 $*T$다.

$$
\begin{aligned}
T&\to\text{int}\ T'\mid(E)\\
T'&\to *T\mid\varepsilon
\end{aligned}
$$

`int`를 먼저 처리한 다음 $T'$가 다음 토큰을 본다.

- `*`이면 $T'\to *T$를 선택한다.
- `+`, `)`, 입력 끝이면 $T'\to\varepsilon$를 선택한다.

### 4.3 $E$의 좌측 인수 분해

$$E\to T+E\mid T$$

공통 접두부 $T$를 분리하면 다음과 같다.

$$
\begin{aligned}
E&\to TE'\\
E'&\to +E\mid\varepsilon
\end{aligned}
$$

먼저 $T$ 전체를 분석하고, $E'$에서 다음 토큰을 확인한다.

- `+`이면 $E'\to +E$를 선택한다.
- `)` 또는 입력 끝이면 $E'\to\varepsilon$를 선택한다.

### 4.4 변환한 전체 문법

새 비단말 기호 $E'$를 $X$, $T'$를 $Y$라고 쓰면 다음과 같다.

```text
E -> T X
X -> + E | ε
T -> int Y | ( E )
Y -> * T | ε
```

```text
변환 전:
T에 진입 -> int 또는 int * T 중 하나를 먼저 선택해야 함

변환 후:
T에 진입 -> int와 일치 -> Y에서 다음 토큰 확인
                          +-- *       -> * T
                          +-- +, ), $ -> ε
```

이 문법에서는 비단말 기호와 미리보기 토큰의 각 조합에 적용 가능한 생성 규칙이 최대 하나다. 이 성질은 뒤에서 분석표를 구성하여 확인한다. 좌측 인수 분해만으로 모든 문법이 LL(1)이 되는 것은 아니다.

## 5. LL(1) 예측 분석표의 구조와 사용법

### 5.1 먼저 표를 사용하고, 다음에 구성 방법을 배운다

분석표가 주어졌다고 가정하고 실행 방식을 먼저 살펴보면, FIRST와 FOLLOW 집합을 계산하는 목적을 이해하기 쉽다. 표는 다음 질문에 답한다.

“현재 전개할 비단말 기호가 $A$이고 다음 입력이 $t$일 때, 어떤 규칙을 적용할 것인가?”

### 5.2 행, 열, 항목의 의미

| 비단말 기호 / 미리보기 | `int` | `*` | `+` | `(` | `)` | `$` |
| --- | --- | --- | --- | --- | --- | --- |
| $E$ | $TX$ | 오류 | 오류 | $TX$ | 오류 | 오류 |
| $X$ | 오류 | 오류 | $+E$ | 오류 | $\varepsilon$ | $\varepsilon$ |
| $T$ | $\text{int}\ Y$ | 오류 | 오류 | $(E)$ | 오류 | 오류 |
| $Y$ | 오류 | $*T$ | $\varepsilon$ | 오류 | $\varepsilon$ | $\varepsilon$ |

- 행은 스택 맨 위의 비단말 기호다. $wA\beta$에서 $A$에 해당한다.
- 열은 현재 입력 토큰이다. `$`는 입력 끝을 나타낸다.
- 항목에는 선택한 생성 규칙의 우변(RHS)이 들어간다. 좌변은 행으로 이미 정해진다.

예를 들어 $A=E$이면 $E$ 행을, $A=X$이면 $X$ 행을 조회한다. 표에서 얻은 우변 $\alpha$로 스택 맨 위의 $A$를 대체한다.

### 5.3 빈 항목과 규칙이 있는 항목

빈 항목은 해당 조합에서 사용할 생성 규칙이 없다는 뜻이다.

- $M[E,+]$: 식이 시작되어야 하는데 `+`가 왔다. 이 예제 문법에는 단항 덧셈 규칙이 없으므로 오류다.
- $M[T,*]$: 항이 시작되어야 하는데 `*`가 왔으므로 오류다.

분석기는 이런 위치에서 오류를 보고하거나, 별도로 구현한 오류 복구 절차로 넘어간다.

내용이 있는 항목은 다음 전개를 지정한다.

| 조회 | 항목의 내용 | 적용할 생성 규칙 |
| --- | --- | --- |
| $M[E,\text{int}]$ | $TX$ | $E\to TX$ |
| $M[X,+]$ | $+E$ | $X\to +E$ |
| $M[X,\$]$ | $\varepsilon$ | $X\to\varepsilon$ |
| $M[T,\texttt{(}]$ | $(E)$ | $T\to(E)$ |
| $M[Y,+]$ | $\varepsilon$ | $Y\to\varepsilon$ |

### 5.4 `int * int $`의 전체 실행 추적

다음 표는 각 동작 직전의 상태를 나타낸다. 스택 맨 위는 왼쪽이다.

| 단계 | 스택 | 남은 입력 | 동작 | 설명 |
| --- | --- | --- | --- | --- |
| 1 | `E $` | `int * int $` | $E\to TX$ | $E$를 $TX$로 대체 |
| 2 | `T X $` | `int * int $` | $T\to\text{int}\ Y$ | $T$ 전개 |
| 3 | `int Y X $` | `int * int $` | 단말 기호 일치 | 첫 `int` 소비 |
| 4 | `Y X $` | `* int $` | $Y\to *T$ | 곱셈 후속 부분 전개 |
| 5 | `* T X $` | `* int $` | 단말 기호 일치 | `*` 소비 |
| 6 | `T X $` | `int $` | $T\to\text{int}\ Y$ | 두 번째 항 전개 |
| 7 | `int Y X $` | `int $` | 단말 기호 일치 | 두 번째 `int` 소비 |
| 8 | `Y X $` | `$` | $Y\to\varepsilon$ | 더 이상의 곱셈이 없어 $Y$ 제거 |
| 9 | `X $` | `$` | $X\to\varepsilon$ | 더 이상의 덧셈이 없어 $X$ 제거 |
| 10 | `$` | `$` | 수락 | 끝 표시 일치 |

#### 생성되는 구문 트리

```text
                 E
               /   \
              T     X
             / \    |
          int   Y   ε
               / \
              *   T
                 / \
              int   Y
                    |
                    ε
```

잎을 왼쪽에서 오른쪽으로 읽으면 `int`, `*`, `int`, $\varepsilon$, $\varepsilon$다. 빈 문자열을 제외하고 연결하면 입력 `int * int`와 같다.

$Y\to *T$가 곱셈 부분을 만들고, 덧셈이 없으므로 $X$는 빈 문자열이 된다. 이 문법의 곱셈과 덧셈은 우재귀로 표현되어 있다. 반복 연산의 구문 트리도 우결합 형태이며, 왼쪽 결합을 원한다면 AST 구성이나 문법을 별도로 설계해야 한다.

### 5.5 `int + int $`의 실행 추적

다음 표는 초기 상태와 각 동작을 수행한 뒤의 상태를 나타낸다.

| 단계 | 스택 | 남은 입력 | 수행한 동작 | 의미 |
| --- | --- | --- | --- | --- |
| 0 | `E $` | `int + int $` | 초기화 | 시작 기호 배치 |
| 1 | `T X $` | `int + int $` | $E\to TX$ | 입력 소비 없음 |
| 2 | `int Y X $` | `int + int $` | $T\to\text{int}\ Y$ | 입력 소비 없음 |
| 3 | `Y X $` | `+ int $` | `int` 일치 | 첫 정수 소비 |
| 4 | `X $` | `+ int $` | $Y\to\varepsilon$ | 현재 항의 곱셈 부분 종료 |
| 5 | `+ E $` | `+ int $` | $X\to +E$ | 덧셈 분기 선택 |
| 6 | `E $` | `int $` | `+` 일치 | 덧셈 기호 소비 |
| 7 | `T X $` | `int $` | $E\to TX$ | 오른쪽 피연산자 분석 |
| 8 | `int Y X $` | `int $` | $T\to\text{int}\ Y$ | 두 번째 항 전개 |
| 9 | `Y X $` | `$` | `int` 일치 | 두 번째 정수 소비 |
| 10 | `X $` | `$` | $Y\to\varepsilon$ | 곱셈 후속 부분 종료 |
| 11 | `$` | `$` | $X\to\varepsilon$ | 덧셈 후속 부분 종료 |
| 12 | 빈 스택 | 끝 | `$` 일치 후 수락 | 전체 입력 분석 완료 |

```text
         E
       /   \
      T     X
     / \   / \
  int   Y +   E
        |    / \
        ε   T   X
           / \  |
        int   Y ε
              |
              ε
```

### 5.6 분석표가 하는 일

행은 현재 전개할 위치, 열은 눈앞의 입력을 나타낸다. 규칙이 있으면 전개하고, 없으면 오류를 보고한다. 분석 중에 여러 경로를 시험할 필요가 없다는 점이 LL(1)의 실행 방식을 단순하게 만든다.

# 제2부: FIRST·FOLLOW 집합과 LL(1) 분석표 구성

이제 분석표를 사용하는 방법에서 한 걸음 더 나아가, 각 칸에 어떤 근거로 생성 규칙을 넣는지 살펴본다.

## 6. 분석표 작성 규칙과 FIRST·FOLLOW의 정의

### 6.1 어떤 생성 규칙을 넣을 것인가

현재 스택 맨 위가 비단말 기호 $A$, 다음 입력이 단말 기호 $t$일 때, 후보 규칙 $A\to\alpha$를 $M[A,t]$에 넣을 수 있는 근거는 두 가지다.

1. $\alpha$가 $t$로 시작하는 문자열을 유도할 수 있다. FIRST 집합을 사용한다.
2. $\alpha$가 빈 문자열이 될 수 있고, $A$ 다음에 $t$가 올 수 있다. FOLLOW 집합을 사용한다.

어느 조건도 만족하지 않으면 그 규칙은 해당 칸에 넣지 않는다. 모든 규칙을 처리한 뒤에도 비어 있는 칸은 오류 항목이다. 두 조건이 일반적으로 서로 배타적인 것은 아니며, 서로 다른 규칙이 같은 칸에 들어가면 충돌 여부를 확인해야 한다.

### 6.2 경우 1: FIRST로 첫 토큰을 맞춘다

$$
t\in\operatorname{FIRST}(\alpha)
\quad\Longleftrightarrow\quad
\alpha\Rightarrow^*t\beta
$$

여기서 $t$는 단말 기호, $\beta$는 뒤에 이어지는 기호열이며, $\Rightarrow^*$는 0회 이상의 유도다.

FIRST는 해당 기호열에서 처음 나타날 수 있는 단말 기호를 모은 집합이다. 이 문서에서는 빈 문자열을 유도할 수 있을 때 $\varepsilon$도 FIRST에 포함한다.

$t\in\operatorname{FIRST}(\alpha)$이면 $A\to\alpha$를 적용하여 현재 입력 $t$와 일치할 수 있는 전개를 시작한다.

```text
현재 입력:       t ...
                ^
A -> α 적용:    t β ... 로 유도 가능

따라서 M[A, t]에 A -> α를 넣는다.
```

예를 들어 $X\to +E\mid\varepsilon$에서 입력이 `+`이면 다음과 같다.

$$+\in\operatorname{FIRST}(+E),\qquad M[X,+]=+E$$

### 6.3 경우 2: 빈 문자열로 사라지고 뒤의 토큰을 드러낸다

FOLLOW의 정의는 다음과 같다.

$$
t\in\operatorname{FOLLOW}(A)
\quad\Longleftrightarrow\quad
S\Rightarrow^*\beta At\delta
$$

즉 시작 기호 $S$에서 유도되는 어떤 문장 형식에서 단말 기호 $t$가 $A$ 바로 뒤에 나타날 수 있다는 뜻이다. 시작 기호 뒤의 입력 끝 표시 `$`도 FOLLOW에 포함한다.

후보 규칙 $A\to\alpha$가 다음을 만족하면,

$$\alpha\Rightarrow^*\varepsilon,\qquad t\in\operatorname{FOLLOW}(A)$$

그 규칙을 $M[A,t]$에 넣는다. $A$를 빈 문자열로 유도해 없애면, 뒤에서 기다리던 구조가 현재 입력 토큰을 처리할 수 있기 때문이다.

```text
유도 가능한 배치: ... A t ...
                     |
                     +-> ε

A가 사라진 뒤:    ...   t ...
현재 입력:              t ...
```

우변 $\alpha$ 자체가 $\varepsilon$인 규칙이라면 표에는 $\varepsilon$를 넣는다. 일반적인 nullable 우변이라면 표에 넣는 것은 원래 우변 $\alpha$이며, 이를 무조건 $\varepsilon$로 바꾸는 것은 아니다.

#### 예 A: $M[X,\$]=\varepsilon$

$E\to TX$에서 $X$는 식의 끝에 놓인다. 시작 기호 $E$ 뒤에는 `$`가 올 수 있으므로 $X$ 뒤에도 `$`가 올 수 있다. $X\to\varepsilon$를 선택하면 스택의 끝 표시를 처리할 수 있다.

#### 예 B: $M[Y,+]=\varepsilon$

변환한 문법에서는 다음 유도가 가능하다.

$$E\Rightarrow TX\Rightarrow\text{int}\ YX\Rightarrow\text{int}\ Y+E$$

따라서 `+`는 $Y$ 뒤에 올 수 있다. 곱셈 부분을 다 읽은 뒤 `+`를 만나면 $Y\to\varepsilon$로 현재 항을 끝내고, 바깥의 덧셈 규칙이 `+`를 처리하게 한다.

### 6.4 산술식 분석표의 항목별 근거

| 표 항목 | 우변 | 사용하는 집합 | 근거 |
| --- | --- | --- | --- |
| $M[E,\text{int}]$ | $TX$ | FIRST | $TX$는 `int`로 시작할 수 있다 |
| $M[E,\texttt{(}]$ | $TX$ | FIRST | $TX$는 `(`로 시작할 수 있다 |
| $M[X,+]$ | $+E$ | FIRST | 우변이 `+`로 시작한다 |
| $M[T,\text{int}]$ | $\text{int}\ Y$ | FIRST | 우변이 `int`로 시작한다 |
| $M[T,\texttt{(}]$ | $(E)$ | FIRST | 우변이 `(`로 시작한다 |
| $M[Y,*]$ | $*T$ | FIRST | 우변이 `*`로 시작한다 |
| $M[X,\$]$ | $\varepsilon$ | FOLLOW | `$`가 $X$ 뒤에 올 수 있다 |
| $M[X,\texttt{)}]$ | $\varepsilon$ | FOLLOW | `)`가 $X$ 뒤에 올 수 있다 |
| $M[Y,+]$ | $\varepsilon$ | FOLLOW | `+`가 $Y$ 뒤에 올 수 있다 |
| $M[Y,\texttt{)}]$ | $\varepsilon$ | FOLLOW | `)`가 $Y$ 뒤에 올 수 있다 |
| $M[Y,\$]$ | $\varepsilon$ | FOLLOW | `$`가 $Y$ 뒤에 올 수 있다 |

> [!note] 두 규칙의 역할
> FIRST는 현재 규칙으로 시작할 수 있는 입력을 알려 준다. FOLLOW는 빈 문자열을 유도할 수 있는 규칙으로 현재 구조를 끝내도 되는 입력을 알려 준다.

## 7. FIRST 집합 계산: 산술식 문법

### 7.1 기본 규칙: 단말 기호의 FIRST는 자기 자신이다

$$\operatorname{FIRST}(t)=\{t\}$$

단말 기호는 더 전개하지 않으므로 처음 나타날 수 있는 기호도 자기 자신이다.

| 기호 또는 문자열 | FIRST |
| --- | --- |
| `+` | $\{+\}$ |
| `*` | $\{*\}$ |
| `(` | $\{\texttt{(}\}$ |
| `)` | $\{\texttt{)}\}$ |
| `int` | $\{\text{int}\}$ |
| $\varepsilon$ | $\{\varepsilon\}$ |

$\varepsilon$는 단말 토큰이 아니라 빈 문자열이다. 따라서 마지막 행은 단말 기호의 규칙과 구분한다.

### 7.2 비단말 기호의 FIRST: 후보 우변을 살핀다

#### $\operatorname{FIRST}(X)$

$$X\to +E\mid\varepsilon$$

$+E$는 `+`로 시작하고 다른 분기는 빈 문자열이다.

$$\operatorname{FIRST}(X)=\{+,\varepsilon\}$$

#### $\operatorname{FIRST}(Y)$

$$Y\to *T\mid\varepsilon$$

따라서 다음과 같다.

$$\operatorname{FIRST}(Y)=\{*,\varepsilon\}$$

#### $\operatorname{FIRST}(T)$

$$T\to(E)\mid\text{int}\ Y$$

첫 분기는 `(`로, 두 번째 분기는 `int`로 시작한다.

$$\operatorname{FIRST}(T)=\{\texttt{(},\text{int}\}$$

### 7.3 우변이 비단말 기호로 시작할 때: $\operatorname{FIRST}(E)$

$$E\to TX$$

첫 기호가 $T$이므로 $E$의 시작 토큰은 우선 $T$의 FIRST에서 얻는다.

$T$가 빈 문자열을 유도할 수 있다면 $T$를 건너뛰어 $X$의 FIRST도 살펴봐야 한다. 하지만 이 문법에서는 다음이 성립한다.

$$\varepsilon\notin\operatorname{FIRST}(T)$$

따라서 $X$까지 넘어가지 않는다.

$$\operatorname{FIRST}(E)=\operatorname{FIRST}(T)=\{\texttt{(},\text{int}\}$$

### 7.4 FIRST 집합 전체 표

| 기호 | 종류 | 계산 근거 | FIRST |
| --- | --- | --- | --- |
| `+` | 단말 | 자기 자신 | $\{+\}$ |
| `*` | 단말 | 자기 자신 | $\{*\}$ |
| `(` | 단말 | 자기 자신 | $\{\texttt{(}\}$ |
| `)` | 단말 | 자기 자신 | $\{\texttt{)}\}$ |
| `int` | 단말 | 자기 자신 | $\{\text{int}\}$ |
| $X$ | 비단말 | $X\to+E\mid\varepsilon$ | $\{+,\varepsilon\}$ |
| $Y$ | 비단말 | $Y\to*T\mid\varepsilon$ | $\{*,\varepsilon\}$ |
| $T$ | 비단말 | $T\to(E)\mid\text{int}\ Y$ | $\{\texttt{(},\text{int}\}$ |
| $E$ | 비단말 | $E\to TX$, $T$는 nullable이 아님 | $\{\texttt{(},\text{int}\}$ |

## 8. FOLLOW 집합 계산과 산술식 문법의 유도

### 8.1 FIRST와 FOLLOW는 살펴보는 위치가 다르다

$\operatorname{FIRST}(X)$를 구할 때는 $X$가 좌변인 규칙을 보고, $X$가 무엇으로 시작할 수 있는지 계산한다.

$\operatorname{FOLLOW}(X)$를 구할 때는 생성 규칙의 우변에 $X$가 나타나는 위치를 찾는다. 그 주변 문맥에서 어떤 단말 기호가 $X$ 바로 뒤에 올 수 있는지 계산한다.

### 8.2 전개할 때 기호들의 위치가 어떻게 바뀌는가

다음 규칙을 생각하자.

$$X\to AB$$

$t\in\operatorname{FOLLOW}(X)$라면 다음과 같은 문장 형식이 존재한다.

$$S\Rightarrow^*\cdots Xt\cdots$$

$X$를 전개하면 다음과 같다.

$$S\Rightarrow^*\cdots ABt\cdots$$

```text
전개 전: ... X       t ...
전개 후: ... A   B   t ...

A 뒤: B에서 처음 나오는 단말 기호
B 뒤: 원래 X 뒤에 있던 t
B가 ε이면: A 뒤에도 t가 올 수 있음
```

이 위치 관계에서 다음 규칙을 얻는다.

1. $A$ 뒤에 $B$가 있으므로:

   $$\operatorname{FIRST}(B)-\{\varepsilon\}\subseteq\operatorname{FOLLOW}(A)$$

2. $B$가 우변 끝에 있으므로:

   $$\operatorname{FOLLOW}(X)\subseteq\operatorname{FOLLOW}(B)$$

3. $B\Rightarrow^*\varepsilon$이면 $A$도 부모의 FOLLOW를 받는다.

   $$\operatorname{FOLLOW}(X)\subseteq\operatorname{FOLLOW}(A)$$

4. 시작 기호 $S$ 뒤에는 입력 끝이 올 수 있다.

   $$\$\in\operatorname{FOLLOW}(S)$$

### 8.3 FOLLOW 계산의 일반 규칙

```text
목표: 모든 비단말 기호 X에 대해 FOLLOW(X)를 구한다.

1. 시작 기호 S의 FOLLOW에 $를 넣는다.

2. A -> α X β가 있으면:
   FIRST(β) - {ε}를 FOLLOW(X)에 넣는다.

3. A -> α X β가 있고 β가 빈 문자열을 유도할 수 있으면:
   FOLLOW(A)를 FOLLOW(X)에 넣는다.
   β가 처음부터 비어 있는 경우, 즉 X가 우변 끝인 경우도 포함한다.

집합에 더 이상 새 원소가 추가되지 않을 때까지 반복한다.
```

### 8.3.1 세 번째 규칙의 포함 관계는 왜 이 방향인가

다음 관계를 증명하자.

$$\operatorname{FOLLOW}(A)\subseteq\operatorname{FOLLOW}(X)$$

전제는 $A\to\alpha X\beta$이고 $\beta\Rightarrow^*\varepsilon$라는 것이다.

#### 첫째, FOLLOW의 정의를 적용한다

임의의 $t\in\operatorname{FOLLOW}(A)$를 선택한다. 정의에 따라 다음 문장 형식이 존재한다.

$$S\Rightarrow^*\cdots At\cdots$$

#### 둘째, $A$를 우변으로 대체한다

$$S\Rightarrow^*\cdots\alpha X\beta t\cdots$$

$\beta$가 비어 있으면 곧바로 다음 형태다.

$$\cdots\alpha Xt\cdots$$

$\beta$가 비어 있지 않더라도 빈 문자열을 유도할 수 있으므로:

$$\cdots\alpha X\beta t\cdots\Rightarrow^*\cdots\alpha Xt\cdots$$

어느 경우든 $t$가 $X$ 바로 뒤에 나타날 수 있다. 따라서 $t\in\operatorname{FOLLOW}(X)$다. 임의의 $t$에 대해 성립하므로 포함 관계가 증명된다.

기억할 방향은 “좌변 부모의 FOLLOW를 우변 끝의 자식에게 전달한다”이다.

| 생성 규칙 | 포함 관계 |
| --- | --- |
| $X\to+E$ | $\operatorname{FOLLOW}(X)\subseteq\operatorname{FOLLOW}(E)$ |
| $E\to TX$ | $\operatorname{FOLLOW}(E)\subseteq\operatorname{FOLLOW}(X)$ |
| $Y\to*T$ | $\operatorname{FOLLOW}(Y)\subseteq\operatorname{FOLLOW}(T)$ |
| $T\to\text{int}\ Y$ | $\operatorname{FOLLOW}(T)\subseteq\operatorname{FOLLOW}(Y)$ |

### 8.4 산술식 문법에서 FOLLOW를 구한다

사용하는 문법은 다음과 같다.

$$
\begin{aligned}
E&\to TX\\
T&\to(E)\mid\text{int}\ Y\\
X&\to+E\mid\varepsilon\\
Y&\to*T\mid\varepsilon
\end{aligned}
$$

#### $\operatorname{FOLLOW}(E)$와 $\operatorname{FOLLOW}(X)$

$E$가 나타나는 위치를 조사한다.

- $E$는 시작 기호이므로 `$`를 FOLLOW에 넣는다.
- $T\to(E)$에서는 $E$ 바로 뒤에 `)`가 있다.
- $X\to+E$에서는 $E$가 끝에 있으므로 $X$의 FOLLOW를 받는다.

따라서 다음 관계를 얻는다.

$$\{\$,\texttt{)}\}\subseteq\operatorname{FOLLOW}(E)$$

$$\operatorname{FOLLOW}(X)\subseteq\operatorname{FOLLOW}(E)$$

한편 $E\to TX$에서 $X$는 끝에 있으므로:

$$\operatorname{FOLLOW}(E)\subseteq\operatorname{FOLLOW}(X)$$

양쪽이 서로의 부분집합이며, 전체 규칙에서 더 추가되는 원소가 없으므로 최종 결과는 다음과 같다.

$$\operatorname{FOLLOW}(E)=\operatorname{FOLLOW}(X)=\{\$,\texttt{)}\}$$

#### $\operatorname{FOLLOW}(T)$와 $\operatorname{FOLLOW}(Y)$

$E\to TX$에서 $T$ 다음에는 $X$가 있다.

$$\operatorname{FIRST}(X)-\{\varepsilon\}=\{+\}$$

따라서 `+`를 $\operatorname{FOLLOW}(T)$에 넣는다. 또한 $X$는 빈 문자열을 유도할 수 있으므로 $E$의 FOLLOW도 전달한다.

$$\operatorname{FOLLOW}(E)\subseteq\operatorname{FOLLOW}(T)$$

이를 합치면:

$$\{+,\$,\texttt{)}\}\subseteq\operatorname{FOLLOW}(T)$$

$Y\to*T$에서 $T$가 우변 끝이므로:

$$\operatorname{FOLLOW}(Y)\subseteq\operatorname{FOLLOW}(T)$$

$T\to\text{int}\ Y$에서 $Y$가 우변 끝이므로:

$$\operatorname{FOLLOW}(T)\subseteq\operatorname{FOLLOW}(Y)$$

최종 결과는 다음과 같다.

$$\operatorname{FOLLOW}(T)=\operatorname{FOLLOW}(Y)=\{+,\$,\texttt{)}\}$$

### 8.5 FOLLOW 집합 전체 표

LL(1) 분석표 구성에 사용하는 FOLLOW는 비단말 기호에 대해 계산한다.

| 비단말 기호 | 계산 근거 | FOLLOW |
| --- | --- | --- |
| $E$ | 시작 기호, $T\to(E)$, $X$와 상호 전달 | $\{\$,\texttt{)}\}$ |
| $X$ | $E\to TX$의 끝에서 $E$의 FOLLOW를 받음 | $\{\$,\texttt{)}\}$ |
| $T$ | $X$의 FIRST 및 $E$의 FOLLOW, $Y$와 상호 전달 | $\{+,\$,\texttt{)}\}$ |
| $Y$ | $T\to\text{int}\ Y$의 끝에서 $T$의 FOLLOW를 받음 | $\{+,\$,\texttt{)}\}$ |

단말 기호 다음에 올 수 있는 기호도 같은 문맥 관점에서 관찰할 수 있다. 다만 아래 표는 LL(1) 구성에 필요한 표준 FOLLOW 계산과 구분한 참고 자료다.

| 단말 기호 | 바로 뒤에 올 수 있는 토큰 또는 끝 표시 | 근거 |
| --- | --- | --- |
| `(` | $\{\texttt{(},\text{int}\}$ | 뒤의 $E$가 시작하는 토큰 |
| `)` | $\{+,\$,\texttt{)}\}$ | $(E)$ 전체 뒤에 올 수 있는 토큰 |
| `+` | $\{\texttt{(},\text{int}\}$ | 뒤의 $E$가 시작하는 토큰 |
| `*` | $\{\texttt{(},\text{int}\}$ | 뒤의 $T$가 시작하는 토큰 |
| `int` | $\{*,+,\$,\texttt{)}\}$ | $Y$의 FIRST와, $Y$가 사라질 때 $T$의 FOLLOW |

## 9. LL(1) 분석표 구성 알고리즘과 적용

### 9.1 일반 알고리즘

```text
입력: 문맥 자유 문법 G, FIRST와 FOLLOW 집합
출력: 분석표 M[A, t]

각 생성 규칙 A -> α에 대해:
  1. FIRST(α) - {ε}의 각 단말 기호 t에 대해
     M[A, t]에 A -> α를 추가한다.

  2. ε가 FIRST(α)에 포함되면
     FOLLOW(A)의 각 t에 대해($ 포함)
     M[A, t]에 A -> α를 추가한다.

같은 칸에 서로 다른 규칙이 들어가면 충돌로 기록한다.
```

표를 우변만 저장하는 형식으로 구현해도 된다. 다만 기존 규칙을 조용히 덮어쓰면 충돌을 놓치므로, 표를 만드는 동안에는 중복 여부를 검사해야 한다.

### 9.2 빈 문자열을 유도할 때 FOLLOW를 보는 이유

입력에는 $\varepsilon$라는 토큰이 없다. $A\to\varepsilon$는 토큰을 읽는 동작이 아니라 현재 구조를 끝내고 제어를 바깥쪽 구조로 넘기는 동작이다.

$X\to+E\mid\varepsilon$를 예로 들면:

- 다음 토큰이 `+`이면 덧셈을 계속한다.
- 다음 토큰이 `)` 또는 `$`이면 현재 식을 끝낸다.
- 그 밖의 토큰이라고 해서 무조건 빈 규칙을 선택할 수는 없다.

빈 규칙을 선택하려면 현재 토큰이 실제로 $X$ 뒤에 올 수 있어야 한다. 이 조건이 $t\in\operatorname{FOLLOW}(X)$다.

### 9.3 산술식 문법의 행별 작성 과정

먼저 계산한 집합을 모으면 다음과 같다.

| 비단말 기호 | FIRST | FOLLOW |
| --- | --- | --- |
| $E$ | $\{\texttt{(},\text{int}\}$ | $\{\$,\texttt{)}\}$ |
| $T$ | $\{\texttt{(},\text{int}\}$ | $\{+,\$,\texttt{)}\}$ |
| $X$ | $\{+,\varepsilon\}$ | $\{\$,\texttt{)}\}$ |
| $Y$ | $\{*,\varepsilon\}$ | $\{+,\$,\texttt{)}\}$ |

#### $E$ 행: $E\to TX$

$T$는 빈 문자열을 유도할 수 없으므로:

$$\operatorname{FIRST}(TX)=\operatorname{FIRST}(T)=\{\texttt{(},\text{int}\}$$

따라서 `(`와 `int` 열에 $TX$를 넣는다.

$$M[E,\texttt{(}]=TX,\qquad M[E,\text{int}]=TX$$

#### $T$ 행: $T\to(E)$와 $T\to\text{int}\ Y$

두 우변은 각각 `(`와 `int`로 시작한다.

$$M[T,\texttt{(}]=(E),\qquad M[T,\text{int}]=\text{int}\ Y$$

어느 우변도 빈 문자열을 유도하지 못하므로 다른 칸에는 넣지 않는다.

#### $X$ 행: $X\to+E$와 $X\to\varepsilon$

$+E$의 FIRST는 $\{+\}$다.

$$M[X,+]=+E$$

빈 규칙은 $\operatorname{FOLLOW}(X)=\{\$,\texttt{)}\}$에 대응하는 칸에 넣는다.

$$M[X,\texttt{)}]=\varepsilon,\qquad M[X,\$]=\varepsilon$$

#### $Y$ 행: $Y\to*T$와 $Y\to\varepsilon$

$*T$의 FIRST는 $\{*\}$다.

$$M[Y,*]=*T$$

빈 규칙은 $\operatorname{FOLLOW}(Y)=\{+,\$,\texttt{)}\}$에 대응하는 칸에 넣는다.

$$M[Y,+]=\varepsilon,\qquad M[Y,\texttt{)}]=\varepsilon,\qquad M[Y,\$]=\varepsilon$$

### 9.4 완성한 LL(1) 예측 분석표

| 비단말 기호 | `(` | `)` | `+` | `*` | `int` | `$` |
| --- | --- | --- | --- | --- | --- | --- |
| $E$ | $TX$ | | | | $TX$ | |
| $T$ | $(E)$ | | | | $\text{int}\ Y$ | |
| $X$ | | $\varepsilon$ | $+E$ | | | $\varepsilon$ |
| $Y$ | | $\varepsilon$ | $\varepsilon$ | $*T$ | | $\varepsilon$ |

빈 칸은 오류다. 어느 칸에도 서로 다른 생성 규칙이 둘 이상 들어가지 않았으므로, 이 문법은 LL(1)이다.

## 10. LL(1)이 아닌 문법과 중복 정의 충돌

### 10.1 하나의 칸에 여러 규칙이 들어가는 경우

LL(1) 분석표의 각 칸에는 생성 규칙이 최대 하나 있어야 한다. 서로 다른 규칙이 같은 칸에 들어가면 중복 정의(Multiply Defined), 즉 LL(1) 충돌이다.

> [!warning] LL(1) 판정
> 충돌하는 칸이 하나라도 있으면 그 문법은 LL(1)이 아니다. 현재 비단말 기호와 토큰 하나만으로 다음 규칙을 결정할 수 없기 때문이다.

### 10.2 좌재귀 문법의 충돌 예

$$S\to Sa\mid b$$

이 문법은 $b$, $ba$, $baa$, $baaa$ 등을 생성한다.

#### FIRST와 FOLLOW

$S$가 생성하는 문자열은 모두 `b`로 시작한다.

$$\operatorname{FIRST}(S)=\operatorname{FIRST}(Sa)=\{b\}$$

$S$는 시작 기호이며, $S\to Sa$에서 우변의 $S$ 뒤에 `a`가 있다.

$$\operatorname{FOLLOW}(S)=\{\$,a\}$$

#### 표 작성

- $S\to Sa$: $b\in\operatorname{FIRST}(Sa)$이므로 $M[S,b]$에 $Sa$를 넣는다.
- $S\to b$: $b\in\operatorname{FIRST}(b)$이므로 같은 칸에 $b$를 넣는다.

| 비단말 기호 | `a` | `b` | `$` |
| --- | --- | --- | --- |
| $S$ | 오류 | $Sa$ / $b$: 충돌 | 오류 |

스택 맨 위가 $S$이고 입력이 `b`일 때 어느 규칙을 적용할지 결정할 수 없다. 따라서 이 문법은 LL(1)이 아니다.

### 10.3 LL(1) 충돌의 대표적인 원인

1. 공통 접두부가 남아 있다. $A\to\alpha\beta_1\mid\alpha\beta_2$처럼 같은 부분으로 시작하면 미리보기 토큰이 겹칠 수 있다. 좌측 인수 분해가 필요한 이유다.
2. 직접 또는 간접 좌재귀가 있다. $A\to A\alpha\mid\beta$ 같은 구조는 재귀 분기와 비재귀 분기의 FIRST가 겹치는 원인이 된다.
3. 문법이 모호하다. 같은 입력에 서로 다른 구문 트리가 존재하는 모호한 문법은 LL(k) 문법일 수 없다.
4. 다른 구조적 제한이 있다. 좌재귀와 공통 접두부, 모호성을 제거해도 LL(1)이 된다는 보장은 없다. 더 긴 미리보기나 LR 계열의 분석 방식이 필요할 수 있다.

### 10.4 실제 언어 문법과 상향식 분석으로의 전환

실제 프로그래밍 언어의 자연스러운 문맥 자유 문법은 LL(1)이 아닌 경우가 많다. LL(1) 형태로 바꾸려면 좌재귀를 없애고 중간 비단말 기호를 추가해야 하며, 그 결과 문법이 길어지고 원래 구조를 읽기 어려워질 수 있다.

연산자의 우선순위와 결합 방향 역시 문법 구조 및 AST 구성 방식과 함께 설계해야 한다.

이런 제약을 살펴본 다음에는 상향식 구문 분석(Bottom-Up Parsing)으로 넘어간다. 이어서 다룰 주제는 시프트-리듀스 분석, LR(0), SLR, LR(1), LALR(1)이다.

# 제3부: 상향식 구문 분석과 시프트-리듀스

앞부분에서는 LL(1) 예측 분석을 위해 문법을 재작성하고 공통 접두부를 분리했다. 이번에는 입력 토큰에서 출발해 구문 트리의 루트를 구성하는 상향식 분석을 살펴본다. Yacc, Bison, Tree-sitter 같은 도구는 이 계열의 분석 기법을 사용한다.

## 11. 상향식 분석의 장점과 자연스러운 문법

### 11.1 상향식 분석이 널리 쓰이는 이유

- 문법 표현 범위가 넓다. 문법 클래스 관점에서 LL(1)은 LR(1)에 포함된다.
- 결정적 LR 분석은 고정된 문법에 대해 입력 길이에 선형인 시간으로 실행할 수 있다.
- 상태와 분석표를 이용하여, 생성 규칙을 역방향으로 적용할 시점을 결정한다.

### 11.2 좌측 인수 분해 없이 산술식 문법을 사용한다

상향식 분석을 위해 문법을 반드시 좌측 인수 분해할 필요는 없다. 앞에서 사용한 $X$, $Y$ 같은 보조 비단말 기호 없이 다음 규칙을 사용할 수 있다.

$$
\begin{aligned}
E&\to T+E\mid T\\
T&\to\text{int}*T\mid\text{int}\mid(E)
\end{aligned}
$$

이 문법으로 다음 입력을 분석한다.

$$\text{int}*\text{int}+\text{int}$$

## 12. 리듀스의 원리와 최우단 유도의 역과정

### 12.1 리듀스는 생성 규칙을 역방향으로 적용한다

하향식 전개에서는 비단말 기호를 우변의 기호열로 바꾼다.

$$T\to\text{int}$$

리듀스(Reduce, 축약)에서는 그 우변에 해당하는 기호열을 좌변 비단말 기호로 바꾼다.

$$\text{int}\quad\Longrightarrow_{\text{reduce}}\quad T$$

#### `int * int + int`의 전체 축약 과정

| 현재 문장 형식 | 역방향으로 적용할 생성 규칙 | 동작 |
| --- | --- | --- |
| `int * int + int` | $T\to\text{int}$ | 두 번째 `int`를 $T$로 축약 |
| `int * T + int` | $T\to\text{int}*T$ | 앞의 `int * T`를 $T$로 축약 |
| `T + int` | $T\to\text{int}$ | 마지막 `int`를 $T$로 축약 |
| `T + T` | $E\to T$ | 오른쪽 $T$를 $E$로 축약 |
| `T + E` | $E\to T+E$ | 전체를 $E$로 축약 |
| `E` | 수락 | 시작 기호에 도달 |

```text
              [ E ]
             /  |  \
          [T]  [+]  [E]
         / | \       |
    [int] [*] [T]   [T]
               |     |
             [int] [int]

트리 구성 방향: 입력 토큰인 잎에서 시작하여 루트 E로 올라간다.
```

### 12.2 핵심 사실 1: 최우단 유도를 거꾸로 추적한다

> [!important] 최우단 유도의 역과정
> 상향식 구문 분석기는 최우단 유도(Rightmost derivation)를 역순으로 추적한다.

위 축약 과정을 역순으로 읽으면 다음 유도를 얻는다.

$$
\begin{aligned}
E
&\Rightarrow T+E\\
&\Rightarrow T+T\\
&\Rightarrow T+\text{int}\\
&\Rightarrow\text{int}*T+\text{int}\\
&\Rightarrow\text{int}*\text{int}+\text{int}
\end{aligned}
$$

첫 단계에서는 유일한 $E$를 전개한다. 다음에는 오른쪽 $E$, 그다음에는 오른쪽 $T$를 전개한다. 마지막 두 단계에서는 남아 있는 유일한 비단말 기호를 전개한다. 매번 가장 오른쪽의 비단말 기호를 전개하므로 최우단 유도다.

### 12.3 다음 축약 부분의 오른쪽에는 단말 기호만 있다

최우단 유도의 역과정을 따라가는 올바른 축약 단계에서 현재 문장 형식을 $\alpha\beta\omega$라고 하자. 다음 동작이 $X\to\beta$를 역으로 적용하는 것이라면:

$$\alpha\beta\omega\quad\Longrightarrow_{\text{reduce}}\quad\alpha X\omega$$

이때 $\omega$는 단말 기호로만 이루어진 문자열이다.

#### 증명

이 단계를 정방향 유도로 읽으면 다음과 같다.

$$\alpha X\omega\Rightarrow\alpha\beta\omega$$

최우단 유도에서 전개하는 $X$는 현재 문장 형식의 가장 오른쪽 비단말 기호다. 따라서 그 오른쪽의 $\omega$에는 비단말 기호가 있을 수 없다.

```text
역방향 축약: α β ω -> α X ω
정방향 유도: α X ω -> α β ω
               ^
               현재 가장 오른쪽 비단말 기호

따라서 ω는 단말 기호열이다.
```

### 12.4 세로선으로 나누는 시프트-리듀스 모델

이 성질을 이용하면 분석 상태를 스택과 미처리 입력으로 나눌 수 있다.

```text
스택                              미처리 입력
[이미 처리한 기호들]       |       [아직 읽지 않은 토큰들]
       α X                |                  ω
단말·비단말 기호가 섞임    |       단말 토큰으로만 구성
                          ^
                        스택 맨 위
```

- 세로선 왼쪽: 이미 시프트한 토큰과 리듀스로 만든 비단말 기호를 스택에 저장한다.
- 세로선 오른쪽: 아직 읽지 않은 원래 입력 토큰이다.
- 세로선: 스택과 입력의 경계다.

기본 동작은 두 가지다.

**시프트(Shift, 이동)**: 다음 입력 토큰 하나를 읽어 스택에 넣는다.

$$\cdots\mid\mathbf{t}\cdots\quad\Longrightarrow\quad\cdots\mathbf{t}\mid\cdots$$

**리듀스(Reduce, 축약)**: 스택 끝의 기호열 $\beta$를 생성 규칙 $X\to\beta$의 좌변 $X$로 바꾼다. 입력은 소비하지 않는다.

$$\cdots\mathbf{\beta}\mid\cdots\quad\Longrightarrow\quad\cdots\mathbf{X}\mid\cdots$$

> [!note] 실행 모델
> 시프트-리듀스 분석기는 스택을 사용하며, 상태와 미리보기 토큰을 근거로 다음 이동 또는 축약을 선택한다.

## 13. 시프트-리듀스 실행 모델과 11개 상태 추적

### 13.1 두 동작의 형식적 정의

#### 시프트: 입력 하나를 스택으로 옮긴다

$$ABC\mid xyz\quad\Longrightarrow\quad ABC\mathbf{x}\mid yz$$

입력 토큰 $x$를 읽어 스택에 넣는다. 미처리 입력은 $yz$가 된다.

#### 리듀스: 스택 끝에서 생성 규칙을 역으로 적용한다

생성 규칙 $A\to xy$가 있고 현재 상태가 다음과 같다고 하자.

$$Cb\mathbf{xy}\mid ijk$$

$xy$를 꺼내고 $A$를 넣으면:

$$Cb\mathbf{A}\mid ijk$$

오른쪽 입력 $ijk$는 그대로다. 리듀스는 입력을 새로 읽는 동작이 아니다.

### 13.2 `int * int + int`의 전체 실행 추적

다시 다음 문법을 사용한다.

$$
\begin{aligned}
E&\to T+E\mid T\\
T&\to\text{int}*T\mid\text{int}\mid(E)
\end{aligned}
$$

다음 표의 동작은 각 행의 상태에서 다음 상태로 가기 위해 수행한다. 세로선 왼쪽이 스택이며, 맨 위는 오른쪽 끝이다.

| 단계 | 스택과 남은 입력 | 다음 동작 | 설명 |
| --- | --- | --- | --- |
| 0 | `\| int * int + int` | Shift | 첫 `int`를 스택에 넣음 |
| 1 | `int \| * int + int` | Shift | `*`를 스택에 넣음 |
| 2 | `int * \| int + int` | Shift | 두 번째 `int`를 스택에 넣음 |
| 3 | `int * int \| + int` | Reduce: $T\to\text{int}$ | 맨 위의 `int`를 $T$로 축약 |
| 4 | `int * T \| + int` | Reduce: $T\to\text{int}*T$ | `int * T` 전체를 $T$로 축약 |
| 5 | `T \| + int` | Shift | `+`를 스택에 넣음 |
| 6 | `T + \| int` | Shift | 마지막 `int`를 스택에 넣음 |
| 7 | `T + int \|` | Reduce: $T\to\text{int}$ | 마지막 `int`를 $T$로 축약 |
| 8 | `T + T \|` | Reduce: $E\to T$ | 오른쪽 $T$를 $E$로 축약 |
| 9 | `T + E \|` | Reduce: $E\to T+E$ | 전체를 시작 기호 $E$로 축약 |
| 10 | `E \|` | Accept | 입력을 모두 읽고 분석 완료 |

실제 LR 분석기의 수락은 단순히 기호 모양만으로 결정하지 않고, 시작 규칙에 대응하는 수락 상태와 입력 끝 표시를 확인한다. 위 표는 기호 스택의 변화를 보여 주기 위한 추적이다.

### 13.3 리듀스와 구문 트리의 성장

리듀스할 때마다 해당 우변에 대응하는 부분 트리 위에 부모 노드를 만든다.

```text
단계 3: 두 번째 int 위에 T를 만든다.
          [ T ]
            |
          [int]

단계 4: int * T를 하나의 T로 묶는다.
          [ T ]
         /  |  \
     [int] [*] [ T ]
                 |
               [int]

단계 7, 8: 마지막 int를 T로, 다시 E로 묶는다.
          [ E ]
            |
          [ T ]
            |
          [int]

단계 9: 두 부분을 루트 E 아래에 결합한다.
                 [ E ]
               /   |   \
            [ T ] [+] [ E ]
           / | \        |
       [int][*][ T ]   [ T ]
                 |       |
               [int]   [int]
```

시프트는 입력을 읽어 스택에 재료를 쌓는 동작이다. 리듀스는 스택 끝의 재료를 부분 트리로 묶는 동작이다. 두 동작을 반복하여 토큰열에서 전체 구문 트리를 만든다.

### 13.4 스택으로 구현하는 방법

세로선 왼쪽의 기호열을 스택으로 구현하면 다음과 같다.

1. 시프트: 다음 토큰을 읽고 `stack.push(token)`을 수행한다.
2. 리듀스 $A\to\beta$: 우변 길이만큼의 기호를 꺼내고, 좌변 $A$를 넣는다.

```text
리듀스 A -> α β

이전 스택(맨 위부터): β, α, ...
동작: β와 α를 꺼냄 -> A를 넣음
이후 스택(맨 위부터): A, ...
```

실제 LR 구현에서는 상태도 함께 저장한다. 리듀스 후에는 남은 상태와 좌변 비단말 기호에 대한 GOTO를 계산한다. 여기서는 기호의 이동과 축약에 초점을 맞춘다.

## 14. 시프트-리듀스 분석의 두 가지 충돌

특정 상태와 미리보기 토큰에 대해 분석표가 하나의 동작을 지정하지 못하면 충돌이 발생한다.

| 충돌 | 의미 |
| --- | --- |
| Shift-Reduce Conflict | 시프트와 리듀스가 모두 후보가 됨 |
| Reduce-Reduce Conflict | 서로 다른 리듀스가 둘 이상 후보가 됨 |

### 14.1 시프트-리듀스 충돌

현재 토큰을 더 읽어야 할지, 스택에 있는 부분을 먼저 축약해야 할지 결정할 수 없는 경우다.

#### 예 A: 연산자 우선순위

모호한 산술식 문법으로 `1 + 2 * 3`을 분석한다고 하자. 스택에 `1 + 2`에 해당하는 부분이 있고 다음 토큰이 `*`라면 두 선택이 생길 수 있다.

- 리듀스: 덧셈을 먼저 묶어 `(1 + 2) * 3`에 해당하는 구조를 만든다.
- 시프트: `*`를 읽고 곱셈을 먼저 구성하여 `1 + (2 * 3)`에 해당하는 구조를 만든다.

이는 우선순위가 문법 또는 별도 선언으로 정해지지 않았을 때의 예다. 앞에서 사용한 계층화된 산술식 문법 자체가 이 모호성을 가진다는 뜻은 아니다.

#### 예 B: 댕글링 else(Dangling Else)

```text
if E1 then if E2 then S1 else S2
```

`else`를 만난 시점의 선택은 다음과 같다.

- 시프트: `else`를 읽어 가장 가까운 안쪽 `if`와 결합한다.
- 리듀스: 안쪽 `if E2 then S1`을 먼저 완성하고, `else`를 바깥쪽 `if`와 결합한다.

일반적인 언어 규칙은 `else`를 가장 가까운 미완성 `if`에 연결한다.

### 14.2 리듀스-리듀스 충돌

같은 상태와 미리보기에서 서로 다른 생성 규칙으로 축약할 수 있는 경우다. 스택의 같은 부분을 $A$로 묶을지 $B$로 묶을지 결정할 수 없다.

시프트-리듀스 충돌 중 연산자 우선순위나 댕글링 else에 해당하는 경우는 우선순위·결합 방향 선언 또는 언어 규칙으로 의도를 지정할 수 있다.

리듀스-리듀스 충돌은 서로 겹치는 문법 범주나 모호한 빈 규칙 등에서 생길 수 있다. 예를 들어 같은 식별자에 대해 `type_name`과 `variable_name` 중 어느 범주인지 결정하지 못하는 상황이다. 다만 이 구별에는 문법 외에 이름 해석이나 렉서와의 협력이 필요한 경우도 있다.

규칙의 순서만으로 충돌을 덮으면 어느 의미 동작이 실행되는지 달라질 수 있으므로, 문법과 분석 방식이 의도에 맞는지 검토해야 한다.

### 14.3 Yacc·Bison의 기본 충돌 처리

명시적인 우선순위 등으로 해결되지 않은 충돌에 대해 전통적인 결정적 분석기의 기본 선택은 다음과 같다.

| 충돌 유형 | 기본 선택 | 의미와 주의점 |
| --- | --- | --- |
| Shift-Reduce | 시프트 선택 | 댕글링 else를 안쪽 `if`에 연결하는 결과를 낳는다. 다른 문법에서도 항상 의도한 결과라는 보장은 없다. |
| Reduce-Reduce | 문법 파일에서 먼저 나온 규칙 선택 | 순서에 따라 축약과 의미 동작이 달라질 수 있으므로 충돌 원인을 수정해야 한다. |

도구는 충돌을 진단한다. 기본 선택이 존재한다는 사실과 문법의 충돌이 해결되었다는 것은 구분해야 한다.

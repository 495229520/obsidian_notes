# AI 컴파일러와 MLIR을 위한 수학 및 알고리즘 기초

AI 컴파일러 입문에서는 구체적인 실험과 함께 행렬·텐서 연산, 인덱스·루프 경계, 부동소수점 오차를 익히고 이를 연산 표현, 로워링(lowering), 정확성 검증에 적용한다. 미적분과 확률·통계는 학습, 양자화, 성능 측정 등 해당 과제에 필요할 때 보완한다. 첫날부터 모두 이수해야 하는 선수 과목은 아니다.

이 문서는 MLIR로 AI 컴파일러를 구현할 때 필요한 지식을 다룬다. MLIR은 범용 컴파일러 인프라이므로 MLIR을 쓴다고 반드시 신경망을 다루는 것은 아니다. 알고리즘 기초는 머신러닝 연산의 계산 의미와 컴파일러가 사용하는 자료구조·알고리즘으로 나눈다.

> [!note] 현재 프로젝트와의 관계
> 학습 계획의 프로젝트 A는 정적 형상의 2차원 f32 텐서에 대한 MatMul, Add, ReLU에서 시작한다. 초기 Add의 두 입력은 형상이 같아야 하며 브로드캐스팅을 지원하지 않는다. 이에 필요한 내용을 입문 필수로, 연산 확장·학습·양자화·심화 최적화를 후속 과제로 구분한다. 이 문서는 지식 참고 자료이며 실제 일정과 완료 상태는 기존 Trellis 작업에서 관리한다.

## 1. 학습 깊이 구분

입문 필수는 소형 텐서 컴파일러의 해당 실습에서 사용할 지식을 뜻한다. 첫날 모두 숙지할 필요는 없다. 심화는 관련 과제를 수행할 때 추가할 내용이다. 현재 프로젝트에 필요한 학습 범위를 기준으로 구분했다. 단계별 적용은 학습 계획의 단계별 참고표에서 확인한다. 완료 여부는 Trellis 작업에만 기록한다.

| 분야 | 입문 필수 | 방향별 심화 |
|---|---|---|
| 선형대수 | 벡터, 내적, 행렬 곱, 전치, 차원 확인 | 배치 행렬 곱, 텐서 축약, 희소 표현. 행렬 분해·스펙트럼 분석은 연산에 따라 학습 |
| 인덱스·정수 연산 | 합, 올림·내림, 정수 나눗셈, 나머지, 구간, 스트라이드, 선형 오프셋 | 아핀 집합, 의존성 분석, 다면체 변환, 동적 형상 제약 |
| 수치 계산 | 부동소수점 표현, 반올림, 오버플로, 절대·상대 오차, 리덕션 순서 | 혼합 정밀도, 양자화 오차, 함수 근사, 오차 전파·민감도 |
| 이산수학·그래프 이론 | 집합, 관계, 유향 그래프, 의존성, 기본 순회 | 지배 관계, 데이터 흐름 분석, 격자·고정점, 스케줄링·메모리 계획 |
| 미적분·초등함수 | 초기 MatMul/Add/ReLU에는 미적분 선수 지식이 필요하지 않음. 지수·로그·제곱근은 연산 추가 시 학습 | 학습 컴파일러에서는 도함수, 편미분, 연쇄 법칙, 행렬 미분, 자동 미분, 옵티마이저 |
| 확률·통계 | 성능 반복 측정의 변동 이해. 평균·분산은 실제 실험에 맞춰 보완 | 양자화 캘리브레이션, 분포·이상치, 표본 추출·통계 추정 |

## 2. 입문 필수: 수학 기초

### 2.1 행렬 곱을 원소 단위 계산으로 설명하기

다음과 같이 정의한다.

$$
A\in\mathbb{R}^{M\times K},\qquad
B\in\mathbb{R}^{K\times N},\qquad
C=AB\in\mathbb{R}^{M\times N}
$$

원소 단위 정의는 다음과 같다.

$$
C_{ij}=\sum_{k=0}^{K-1}A_{ik}B_{kj}
$$

$i,j$는 출력 위치를 결정하고 $k$는 리덕션 차원이다. 서로 다른 출력 원소는 각각 계산할 수 있다. 하나의 출력 원소에 대해 $k$를 따라 계산한 부분합은 올바르게 합쳐야 한다.

입문 단계에서는 다음 질문에 답할 수 있어야 한다.

- A의 열 수와 B의 행 수가 같아야 하는 이유는 무엇인가? 출력 형상이 $[M,N]$인 이유는 무엇인가?
- $C_{ij}$가 읽는 입력 원소는 무엇인가? 여러 출력에서 재사용하는 입력은 무엇인가?
- 일반적으로 행렬 곱의 순서를 바꾸면 결과가 달라지는 이유는 무엇인가?
- 기본 구현의 산술 연산량이 $O(MNK)$인 이유는 무엇인가?

기존 선형대수 자료에서는 행렬 곱의 성립 조건, 출력 형상, 원소별 전개부터 복습한다. 역행렬 계산법은 MatMul 로워링의 전제 조건이 아니다.

### 2.2 텐서 형상과 메모리 레이아웃 구분

형상(shape)은 논리적인 원소 수와 차원 구성을 나타내고, 스트라이드(stride)는 인덱스가 변할 때 저장 위치가 얼마나 이동하는지 나타낸다.

연속적인 행 우선 저장 방식의 $[M,N]$ 행렬에서는 원소 오프셋이 다음과 같다.

$$
\operatorname{offset}(i,j)=iN+j
$$

일반적인 2차원 스트라이드 레이아웃에서는 다음과 같다.

$$
\operatorname{offset}(i,j)=o+i\,s_0+j\,s_1
$$

$o$는 시작 오프셋이고 $s_0,s_1$은 각 차원의 스트라이드다. 모두 원소 단위이며 바이트 주소로 변환하려면 원소 크기를 곱해야 한다.

같은 논리 연산도 메모리 접근 방식이 다를 수 있다. 전치 뷰를 행 방향으로 읽더라도 실제 저장 위치는 연속적이지 않을 수 있다. Transpose, Reshape, Slice가 데이터 이동을 요구하는지는 레이아웃, 후속 소비 연산, 타깃 표현을 함께 확인해야 한다. 연산 이름만으로 결정하지 않는다.

입문 단계에서는 2차원 행렬의 오프셋을 손으로 계산하고 연속 레이아웃과 스트라이드 뷰를 구분한다. 블록 레이아웃, 벡터 레이아웃, 장치 전용 레이아웃은 후속 최적화에서 학습한다.

### 2.3 정수 나눗셈·나머지·경계와 타일링

길이 $N$을 크기 $T>0$인 타일로 나누면 타일 수는 다음과 같다.

$$
n_{\text{tiles}}=\left\lceil\frac{N}{T}\right\rceil
$$

$p$번째 타일의 유효 구간은 다음과 같다.

$$
[pT,\ \min((p+1)T,N))
$$

$N=10,T=4$라면 세 타일의 실제 길이는 $4,4,2$다. 마지막 타일에도 유효 원소가 네 개 있다고 가정하면 안 된다.

음이 아닌 인덱스 $i$는 다음과 같이 분해할 수 있다.

$$
i=T\left\lfloor\frac{i}{T}\right\rfloor+(i\bmod T)
$$

몫은 타일 번호이고 나머지는 타일 내부 위치다. 이 관계를 이해하면 루프 경계, 마지막 불완전 타일, 마스크를 설명할 수 있다. 실제 구현에서는 정수 오버플로와 사용 연산의 부호 처리 의미도 확인한다.

### 2.4 첫 실행부터 부동소수점 오차 확인

실수 덧셈에는 결합법칙이 성립하지만 유한 정밀도의 부동소수점 덧셈에는 일반적으로 성립하지 않는다. 타일링, 병렬 리덕션, 융합 곱셈-덧셈, 정밀도 축소는 반올림 위치나 계산 순서를 바꿀 수 있다.

| 개념 | 컴파일러 실험에서의 용도 |
|---|---|
| 절대 오차 | 출력 편차의 크기 확인. 특히 참조값이 0에 가까운 경우 |
| 상대 오차 | 참조값의 크기에 비례한 편차 판단 |
| 반올림·유효 정밀도 | 덧셈에서 작은 값이 사라지는 이유 이해 |
| 오버플로·언더플로·NaN·Inf | 극단적인 입력에서 나타나는 결과 설명 |
| 수치 안정성 | 계산 과정이 오차를 확대하는지 판단 |

수치해석 자료에서는 절대·상대 오차, 반올림 오차, 유효 숫자를 복습한다. 정방향·역방향 점화식 예제는 같은 수학 문제라도 알고리즘에 따라 안정성이 달라질 수 있음을 이해하는 데 활용한다.

실무에서는 원소별로 다음과 같은 허용 오차 판정을 자주 사용한다.

$$
|y_i-y_i^{\mathrm{ref}}|
\le \mathrm{atol}+\mathrm{rtol}\,|y_i^{\mathrm{ref}}|
$$

$y^{\mathrm{ref}}$는 선택한 참조 결과다. 허용 오차는 자료형, 리덕션 길이, 입력 범위, 정밀도 요구에 맞춰 정한다. 허용 오차를 늘리는 것으로 인덱스 오류 분석을 대신하지 않는다. NaN·Inf는 검증 정책에 따라 별도로 처리한다.

FP16과 BF16은 모두 16비트지만 지수 범위와 유효 정밀도 배분이 다르다. 입력 자료형, 곱셈 정밀도, 누산 자료형, 출력 자료형도 서로 다른 선택 사항이다. 먼저 이 구분을 이해하고 실제 구현 시 연산과 하드웨어 사양을 확인한다.

수학적으로 동등하더라도 부동소수점 연산 순서를 임의로 바꿀 수 있는 것은 아니다. IR의 연산 의미, 부동소수점 속성, 허용되는 정밀도 변화를 함께 확인한다. [PyTorch 수치 정확도 문서](https://docs.pytorch.org/docs/2.14/notes/numerical_accuracy.html)는 비결합성과 계산 경로에 따른 결과 차이를 설명한다.

### 2.5 그래프와 의존성

계산 그래프에서는 값을 만드는 연산과 사용하는 연산이 간선으로 연결된다. 현재 다루는 분기와 순환이 없는 텐서 계산은 의존 관계에 따라 순서대로 실행할 수 있다. 제어 흐름과 루프가 있으면 전체 IR을 DAG라고 가정할 수 없다.

노드, 간선, 진입 차수, 도달 가능성, DFS, BFS, 위상 정렬부터 익힌다. 위상 정렬은 선행 의존성을 먼저 처리하는 순서를 이해하는 데 유용하지만 MLIR의 Region·Block·SSA·제어 흐름 의미를 대신하지 않는다.

## 3. 입문 필수: AI 연산의 알고리즘 기초

### 3.1 현재 프로젝트에서 사용하는 연산부터 학습

| 내용 | 최소 이해 수준 | 프로젝트에서의 용도 |
|---|---|---|
| 텐서 메타데이터 | rank·shape·dtype 구분, 정적·동적 차원 이해 | 입출력 표현과 타입 검사 |
| MatMul | 원소별 공식, 병렬·리덕션 차원 식별 | Verifier, 로워링, 행렬 참조 구현 |
| 동일 형상 Add | 같은 위치끼리 더하며 입출력 형상이 같음 | 잔차 또는 덧셈 항 |
| ReLU | 일반 실수에서는 $\max(0,x)$. 구현은 NaN·부호 있는 0 등의 의미 확인 | 원소별 로워링과 융합 |
| Sum·Max 개념 | 리덕션 축, 초기값, 출력 형상의 관계 | MatMul 누산과 후속 확장 이해 |
| 계산 그래프·의존성 | 생산자·소비자·중간 결과 구분 | 실행 순서, 융합 위치, 버퍼 생존 기간 판단 |

연산을 이해했다는 기준은 입출력, 원소별 계산 규칙, 리덕션 축, 자료형, 경계 동작을 설명하고 작은 입력을 손으로 계산할 수 있는지다.

### 3.2 MatMul → Add → ReLU로 수학과 MLIR 연결

프로젝트 A의 초기 범위에 맞춰 다음을 고려한다.

$$
Y=\operatorname{ReLU}(AB+R)
$$

$$
A:[M,K],\quad B:[K,N],\quad R:[M,N],\quad Y:[M,N]
$$

$R$은 행렬 곱 결과와 형상이 같은 덧셈 입력이다. 이 예제에는 편향의 브로드캐스팅을 사용하지 않는다.

$$
Y_{ij}=\max\left(0,\ \sum_{k=0}^{K-1}A_{ik}B_{kj}+R_{ij}\right)
$$

행렬 곱의 접근 매핑은 다음처럼 표현할 수 있다. 각 반복에서 읽거나 갱신하는 위치를 설명하는 표기이며, 실행 가능한 MLIR 코드는 아니다.

```text
반복 변수: (i, j, k)
A 접근:    (i, j, k) → (i, k)
B 접근:    (i, j, k) → (k, j)
C 접근:    (i, j, k) → (i, j)
반복 유형: parallel, parallel, reduction
```

$C$는 행렬 곱의 중간 결과다. 서로 다른 $(i,j)$는 서로 다른 출력에 대응하고, $k$ 방향 계산은 같은 $C_{ij}$를 계속 갱신한다. 리덕션 차원을 분할할 때는 부분 누산과 병합을 설계해야 한다. 여러 실행 주체가 동기화 없이 같은 위치를 갱신하면 안 된다.

융합 시에는 출력 원소의 행렬 곱 누산이 끝난 뒤 Add와 ReLU를 수행해 중간 결과의 저장·읽기를 줄일 수 있다. ReLU를 매 누산 단계 뒤로 옮길 수는 없다.

$$
\operatorname{ReLU}(a+b)
\ne \operatorname{ReLU}(\operatorname{ReLU}(a)+b)
$$

$a=-2,b=3$이면 왼쪽은 $1$, 오른쪽은 $3$이다. 덧셈 항을 넣는 순서만 바꾸더라도 부동소수점 반올림과 타깃 IR의 의미를 고려한다.

융합이 실제로 데이터 이동을 줄이는지, 중복 계산을 추가하는지, 임시 저장 공간이 용량을 초과하는지도 확인한다. 수학적으로 허용되는 융합이라도 더 빠른지는 측정해야 한다.

[Linalg 구조화 연산 튜토리얼](https://mlir.llvm.org/docs/Tutorials/transform/Ch0/)은 인덱스 매핑, 병렬·리덕션 차원으로 행렬 곱을 표현하고 타일링·융합을 설명한다. MLIR 입문 영상의 MatMul·ReLU 예제와 함께 읽는다.

## 4. 심화: 연산과 업무 방향에 따라 보완

### 4.1 브로드캐스팅·배치 행렬 곱·형상 변환

연산을 확장하기 전에 다음을 학습한다.

- 브로드캐스팅: 타깃 프레임워크 규칙으로 차원을 정렬하고 확장 가능한 차원을 판단한다.
- Batch MatMul: 배치 차원, 출력 차원, 축약 차원을 구분하고 배치 브로드캐스팅 규칙을 확인한다.
- Reshape·Transpose·Slice·Concat: 원소 대응 관계와 데이터 이동 필요성을 도출한다.
- 동적 형상: 컴파일 시 증명 가능한 제약과 런타임 검사가 필요한 조건을 구분한다.

완전 연결 계층은 $Y=XW+b$로 쓸 수 있지만 가중치 저장 방향은 연산 정의에 따라 다르다. 편향 브로드캐스팅도 명확히 정의해야 한다. 이는 초기 동일 형상 Add를 확장하는 과제다.

### 4.2 Softmax와 정규화

유한하고 비어 있지 않은 실수 입력 집합에 대해 수치적으로 안정적인 Softmax는 보통 다음과 같이 쓴다.

$$
m=\max_j x_j,\qquad
y_i=\frac{e^{x_i-m}}{\sum_j e^{x_j-m}}
$$

최댓값을 빼면 지수 함수의 입력이 0 이하가 되어 큰 양수에 대한 지수 계산의 오버플로를 피한다. 반올림 오차는 여전히 존재한다. Inf·NaN이 포함되거나 행 전체가 마스킹된 경우는 타깃 연산 정의에 따라 별도로 처리한다.

최댓값과 합의 리덕션 축을 설명할 수 있어야 한다. 병렬 구현에서는 타일별 통계량을 합치는 방법을 추가로 학습한다.

원소가 $n$개인 정규화 그룹의 일반적인 LayerNorm은 다음과 같다.

$$
\mu=\frac{1}{n}\sum_i x_i,\qquad
v=\frac{1}{n}\sum_i(x_i-\mu)^2,\qquad
y_i=\gamma_i\frac{x_i-\mu}{\sqrt{v+\epsilon}}+\beta_i
$$

일반적인 RMSNorm은 다음과 같다.

$$
y_i=\gamma_i\frac{x_i}{\sqrt{\frac{1}{n}\sum_j x_j^2+\epsilon}}
$$

RMSNorm은 평균을 빼지 않는다. 두 연산 모두 정규화 축, 파라미터 브로드캐스팅, epsilon 위치, 계산 정밀도를 확인한다.

노름·조건수 자료는 벡터 크기와 섭동에 대한 민감도 이해에, 내적 자료는 제곱합 복습에 활용한다. LayerNorm의 평균·분산과 RMSNorm의 제곱평균제곱근은 각각의 정의가 있으며 벡터의 2-노름과 그대로 동일시할 수 없다. 기존 GPU 수치 정확성 자료는 Softmax·저정밀도·허용 오차 검증의 참고로 사용하되 이전 주차 계획은 현재 일정에 적용하지 않는다.

### 4.3 LLM: Attention·KV cache·모델 구조

단순화한 단일 헤드 Attention부터 이해한다.

$$
O=\operatorname{softmax}\left(\frac{QK^{\mathsf T}}{\sqrt d}+\text{mask}\right)V
$$

$$
Q:[L_q,d],\quad K:[L_k,d],\quad V:[L_k,d_v]
$$

점수 행렬은 $[L_q,L_k]$이고 Softmax는 key 차원을 따라 계산한다. 출력은 $[L_q,d_v]$다.

LLM 연산 컴파일에서는 다음을 설명할 수 있어야 한다.

- $L_q\times L_k$ 중간 결과가 생기는 이유와 저장 공간.
- causal mask, 스케일링, Softmax가 적용되는 위치.
- 멀티헤드, GQA, KV cache에 따른 형상과 읽기 패턴 변화.
- prefill과 decode의 입력 규모·데이터 재사용 차이.

이후 FlashAttention의 타일링·온라인 Softmax, RoPE, MoE를 학습한다. 입력 레이아웃, 마스크 종류, 정밀도 요구는 [ONNX Attention 정의](https://onnx.ai/onnx/operators/onnx__Attention.html)에서 확인할 수 있다.

### 4.4 비전 모델: 합성곱과 풀링

커널 이동, 입력·출력 채널, stride, padding, dilation, groups를 이해한다. 일반적인 2차원 합성곱의 출력 높이는 다음과 같다.

$$
H_{\mathrm{out}}=
\left\lfloor
\frac{H_{\mathrm{in}}+P_{\mathrm{top}}+P_{\mathrm{bottom}}-D_h(K_h-1)-1}{S_h}
\right\rfloor+1
$$

너비도 같은 방식으로 계산한다. 자동 padding 등의 모드는 연산 정의에 따라 별도로 계산한다.

다음으로 직접 합성곱, im2col, 행렬 곱 기반 구현의 계산량·저장 공간을 비교한다. 풀링에서는 최댓값과 평균을 구분하고 경계 padding이 평균의 분모에 포함되는지 확인한다.

### 4.5 저정밀도와 양자화

균일 아핀 양자화의 기본 관계는 다음과 같다.

$$
x\approx s(q-z)
$$

일반적인 양자화 과정은 다음처럼 요약할 수 있다.

$$
q=\operatorname{clip}\left(\operatorname{round}(x/s)+z,\ q_{\min},q_{\max}\right)
$$

$s>0$은 스케일, $z$는 영점(zero-point)이다. 반올림 규칙과 범위는 연산 정의에 따른다.

per-tensor·per-channel 등의 파라미터 단위, 캘리브레이션 범위, 이상치, 누산 비트 폭, 재양자화(requantization)를 순차적으로 학습한다. 양자화의 적용 가능성은 연산 오차와 배포 요구에 따른 모델 품질을 함께 검증한다. 개별 연산이 허용 오차를 통과했다고 모델 평가를 생략할 수는 없다. [MLIR 양자화 문서](https://mlir.llvm.org/docs/Quantization/)에서 수치 표현을 확인한다.

### 4.6 학습 컴파일러와 자동 미분

편미분, 기울기, Jacobian, 연쇄 법칙, 역방향 자동 미분을 추가로 학습한다. 특히 행렬 곱·브로드캐스팅·리덕션의 역방향 계산을 유도할 수 있어야 한다.

실수에서 미분 가능한 적절한 조건하에 $Y=XW$이고 상위 기울기 $G=\partial L/\partial Y$가 주어지면 다음과 같다.

$$
\frac{\partial L}{\partial X}=GW^{\mathsf T},\qquad
\frac{\partial L}{\partial W}=X^{\mathsf T}G
$$

여러 위치로 브로드캐스팅한 파라미터의 기울기는 확장된 차원을 따라 합산한다. 이후 손실 함수, SGD/Adam 상태 갱신, 혼합 정밀도 학습, 중간 활성값 저장·재계산을 다룬다.

미적분 자료로 도함수, 편미분, 연쇄 법칙, Taylor 전개를 복습한다. 행렬 미분과 자동 미분은 별도 학습이 필요하다. 초기 추론 컴파일러는 역전파 없이 완성할 수 있다.

### 4.7 함수 근사와 민감도 분석

exp·log·tanh·GELU 등의 근사 구현을 다룰 때 다항식·유리함수 근사, 구간 분할, 오차 한계를 보완한다. 함수 근사·곡선 적합 자료에서는 기저 함수 선택, 오차 정의, 최소제곱법을 복습한다.

제곱 오차가 작다고 최대 오차 요구까지 충족되는 것은 아니다. 함수 구현을 교체할 때는 유효 구간, 최대 편차, 단조성, 특수값 동작도 확인한다.

전체 출력 차이는 벡터·행렬 노름으로 측정할 수 있다. 입력 섭동의 영향은 해당 문제의 조건수로 판단한다. 선형 연립방정식의 조건수 공식을 임의의 신경망 연산에 그대로 적용하지 않는다.

### 4.8 컴파일 최적화: 아핀 분석·데이터 흐름·자원 계획

루프 변환을 심화할 때 정수 집합, 아핀 제약, 의존 방향, 다면체 모델을 학습한다. [Affine 공식 문서](https://mlir.llvm.org/docs/Dialects/Affine/)에서 표현을 확인한다. 입문에서는 인덱스 매핑 읽기부터 익히고 이후 구체적인 변환의 적법성을 분석한다.

분석 Pass에는 격자, 상태 병합, 전달 함수, 단조성, 고정점 반복이 필요하다. 여기서 고정점은 추상 분석 상태가 더 이상 변하지 않는 상태다. 수치적인 근 찾기의 고정점 반복과는 구체적인 문제 설정이 다르다. [MLIR 데이터 흐름 분석 튜토리얼](https://mlir.llvm.org/docs/Tutorials/DataFlowAnalysis/)을 개념 입문으로 활용하고 실제 API는 프로젝트의 고정 버전을 따른다.

온칩 메모리 계획과 스케줄링에서는 생존 기간, 구간 중첩, 정렬, 용량 제약, 탐욕적 전략, 탐색을 학습한다. 성능 평가에는 캐시·대역폭·병렬 하드웨어·측정 방법도 필요하다. 이는 아키텍처와 엔지니어링 지식이며 수학 과목만으로 대체할 수 없다.

## 5. 자료구조·알고리즘의 최소 범위

| 내용 | 입문 용도 | 심화 용도 |
|---|---|---|
| 배열·해시 테이블·집합 | 값 저장, 매핑, 중복 제거, 검색 | 분석 결과 캐시와 복잡한 인덱스 |
| 트리·그래프·DFS/BFS | IR의 중첩·의존성과 구조 순회 | 도달 가능성·제어 흐름 분석 |
| 위상 정렬 | 비순환 데이터 의존성 처리 | 스케줄 후보 순서. 자원·부수 효과는 별도 고려 |
| 작업 목록(worklist) | 방문 대기 노드와 변경 전파 처리 | 데이터 흐름 분석·반복 재작성 |
| 복잡도 분석 | 순회·계산 규모 추정 | 분석·탐색·최적화 Pass의 컴파일 비용 판단 |
| 지배 관계·활성성 | 개념과 용도 이해 | 제어 흐름 변환, 생존 기간·버퍼 분석 |

동적 계획법, 그래프 색칠, 정수 계획법은 구체적인 최적화 문제에 맞춰 추가한다. 제한적인 Pass를 구현하면서 필요한 알고리즘을 함께 익혀도 된다.

## 6. 입문 이해도 점검

다음 질문은 이해도 확인용이며 작업 완료 상태를 기록하지 않는다.

1. $A:[3,5]$, $B:[5,2]$, $R:[3,2]$일 때 $Y=\operatorname{ReLU}(AB+R)$의 출력 형상과 임의 원소의 전체 공식을 쓸 수 있는가?
2. 행렬 곱의 세 접근 매핑과 $k$가 리덕션 차원인 이유를 설명할 수 있는가?
3. shape·offset·stride가 주어지면 원소 위치를 계산할 수 있는가?
4. 길이 10, 타일 크기 4일 때 세 타일의 유효 구간을 쓸 수 있는가?
5. ReLU를 누산 과정 안으로 옮기면 결과가 달라질 수 있음을 숫자로 설명할 수 있는가?
6. 최적화 후 참조값과 차이가 나면 인덱스 오류, 계산 순서, 정밀도, 허용 오차 문제를 구분할 수 있는가?

이 질문에 답하고 작은 입력으로 검증할 수 있으면 현재 MatMul/Add/ReLU 로워링 실습에 필요한 수학·연산 기초를 갖춘 것이다. 프로젝트 산출물은 별도로 빌드·실행·검증 기준을 충족해야 한다.

## 1. Linux IO函数

### 1.1 · 从 buf[] 到盘片

[▶ 打开动画](<../图片/HTML/3.Linux/4. Linux IO函数/4.2.1 从buf到盘片动画.html>)

五个主题：**全链路**（四层存储的持久性阶梯，数据芯片沿层真实滑动：stdio 库缓冲只是 memcpy 此刻还没有系统调用 → `write()` 陷入内核并沿 fd→file→inode 定位 → `copy_from_user` 是**整条路径唯一一次 CPU 拷贝** → 打上 `PG_dirty` 后立即返回，**返回 ≠ 落盘** → `bio`/`blk-mq`/驱动/`DMA` 逐个点亮，设备主动读物理内存所以没有第二次 CPU 拷贝 → 盘上 DRAM 回复「写完了」却是易失的 → `FLUSH`/`FUA` 才把数据推上盘片；CPU 拷贝、系统调用、数据最深三个计数器同步累加，收口"fflush 只跨 ①、write 返回只到 ②、fsync 返回才进 ④"）、**定位链与元数据**（`fd 表 → struct file → inode` 三张卡加 SVG 连线：`lseek` 改的只是 `f_pos`、`dup` 让两条线汇入同一个 `struct file` 所以偏移量共享、`f_count` 1→2、终点是唯一 inode；再点破两个误解——页缓存不是一大锅散页而是挂在 `inode->i_mapping` 按页索引组织，元数据不在别处**就是 inode 自己**；正因两者同属一个 inode，`fsync(fd)` 才能一次刷「脏数据页 + 元数据」，`fdatasync` 只保留读取必需的那部分）、**脏页回写三时机**（脏页水位条真实涨落，两条阈值虚线：周期回写看 `dirty_expire_centisecs`=3000（30s）的驻留计时、越过 `dirty_background_ratio` 后台悄悄刷而写者无感、越过 `dirty_ratio` 时**写者被直接阻塞**——这正是"平时微秒级的 write 偶尔卡几百毫秒"的成因、`fsync` 立刻提交并等待；收口"前两种由内核决定不可预测，只有第三种可控，这就是 fsync 存在的理由"）、**丢失边界**（同一张梯子换两种故障：`kill -9` 只丢 ①、②③④ 存活（内核已接手）；内核 panic / 掉电 ①② 全丢、③ 无 PLP 一并丢；再演示企业盘 **PLP 超级电容**把 ③ 变成准持久层，以及 `nobarrier` 挂载让 fsync 返回成功却不下发 FLUSH 的陷阱，末步四层 × 两故障对照）、**旁路 O_DIRECT / mmap**（`O_DIRECT` 把第 ② 层变成虚线旁路、数据芯片从 ① 直接跳到 ③，但地址/偏移/长度三处都要对齐、预读与合并一并失去，且**仍然需要 fsync**——它不保证元数据落盘也不保证盘上缓存被 flush；`mmap` 恰好相反，①② 同时点亮标注"同一张物理页"，写内存即改页缓存、零系统调用零拷贝，用 `msync(MS_SYNC)` 代替；收口"两条旁路都改变不了：第 ③ 层的 FLUSH 谁都省不掉"）。
**对应笔记**：[[4.2 重定向、同步]]。

### 1.2 · 文件锁

[▶ 打开动画](<../图片/HTML/3.Linux/4. Linux IO函数/4.3 文件锁动画.html>)

四个主题：**共享锁与排他锁**（P1、P2 两个读者共存、P3 的 `LOCK_EX` 被挡在门口，右侧兼容性矩阵单元格随每步点亮——无锁全放行、共享挡排他、排他挡一切；读者全部释放的瞬间内核把排他锁交给等待者）、**fcntl 区域锁**（字节标尺 0~300 上用 `l_start + l_len` 圈区域：不相交的两把写锁并行成立、[50,150) 撞上 [0,100) 写锁时 `F_SETLK` 立即 `EAGAIN`、`F_GETLK` 把冲突锁的 `l_pid`/`l_type` 填回结构体、解锁后读锁区域滑入生效）、**阻塞与非阻塞**（双泳道对照：A 睡在 `flock()` 系统调用里等唤醒 vs B 带 `LOCK_NB` 立即 `-1/EWOULDBLOCK` 转身做别的事；fcntl 侧对应 `F_SETLKW`/`F_SETLK`，收口固定顺序、失败重试、超时三板斧防死锁）、**建议性锁与关闭 fd**（P3 不检查锁直接 `write()` 内核照样放行——advisory 只约束自愿者；flock 锁随 `close(fd)` 释放；fcntl 陷阱红线：同进程关闭指向该文件的**任一** fd，该进程在此文件上的所有记录锁瞬间蒸发）。
**对应笔记**：[[4.3 文件锁]]。

### 1.3 · IOCP

[▶ 打开动画](<../图片/HTML/3.Linux/4. Linux IO函数/4.4.1 IOCP动画.html>)

四个主题：**请求投递**（`WSARecv` 先把 buffer+OVERLAPPED 挂进内核 → 返回 `WSA_IO_PENDING` **不是失败** → 数据到达直接写进用户 buffer（可省一次拷贝）→ 完成包携 bytes+key+ol 按 **FIFO** 入队，收口"投递(应用)→执行(内核)→入队(IOCP)→取包(worker)"四段流水）、**两层上下文**（关联时 `CreateIoCompletionPort` 绑一次 CompletionKey=连接级、每次 I/O 独立 OVERLAPPED=请求级，完成包回来 key 找连接 SVG 线、ol 找请求 SVG 线同时点亮；含官方点名高危反例：两个未完成 I/O 复用同一 OVERLAPPED 双红线警示）、**worker 取包**（GQCS 阻塞→Recv 完成包"Hello" 5B→echo 处理→PostSend→Send 完成→**再补投下一次 WSARecv**——写丢这步连接"安静死"，附 FIFO 入队/LIFO 释放线程）、**失败完成**（GQCS 四分支判定卡：ok&&bytes>0 正常 / bytes==0 对端优雅关闭 / **!ok && ol!=NULL = 失败完成包**看 GetLastError / ol==NULL 没取到包，末步 `PostQueuedCompletionStatus(iocp,0,0,nullptr)` 退出包 + closesocket 后资源清理时机）。
**对应笔记**：[[4.4 IOCP]]。

## 2. 进程控制（fork · exec · 退出 · 等待 · 进程组）

### 2.1 –5.5 · exec 家族 · 退出出口 · status 位布局 · 进程组

[▶ 打开动画](<../图片/HTML/3.Linux/11. 进程/11.2-11.6 exec·退出·status·进程组动画.html>)

五个主题：**exec 家族**（`l/v`、`p`、`e` 三个开关逐个拨亮，六个函数名跟着分组点亮——记开关不必背名字；再翻到分界线视图：代码段、数据段与堆、栈三行整个换掉，PID 和已打开的 fd 原样留下，信号处置只复位装了 handler 的那些。收口两个坑：`l` 系列末尾必须写 `(char *)NULL`（裸 `NULL` 可能展开成 `int` 的 0，`execl` 就找不到列表末尾），以及 `exec` 只有失败才返回，后面不接 `perror` + `_exit` 子进程会带着父进程的代码继续跑）、**退出出口**（`return` / `exit()` / `_exit()` / `abort()` 四个入口，令牌沿「① atexit 逆序 → ② 刷 stdio 并关流 → ③ 删 tmpfile → `_exit(2)`」滑动；`_exit` 和 `abort` 各走一条虚线绕过三格，末步内核四步全亮——四个出口的差别全在用户态，进了内核谁走都一样）、**stdio 缓冲区**（同一个程序，接终端是行缓冲、重定向到 `f.txt` 是全缓冲：后者 `fork()` 时缓冲区里还压着 `"hi\n"`，副本被父子各刷一次，文件里出现两行 hi；改成 `_exit(0)` 副本随地址空间丢掉，输出只剩一次。顺带点破 `atexit()` 注册信息同样被复制，清理逻辑会跑两遍）、**status 位布局**（16 格位条按语义着色，三种编码轮流上场：正常退出高字节放退出码、信号终止低 7 位放信号号且 bit7 是 core 标志、停止把低字节钉成 `0x7F` 当哨兵；核心一幕是对着被 `SIGKILL` 打死的 status 调 `WEXITSTATUS`——语法合法、读回 0、看着像成功，所以 `WIF*` 判类型必须在取值之前）、**进程组与会话**（一条管道三个进程共用 PGID 4712，Ctrl+C 的 SIGINT 一次打中整组，后台组 4730 毫发无伤；`tpgid` 徽章演示「谁在前台」记在终端里而不在进程里，`fg` 改的就是 `tcsetpgrp`；后台组读终端被 `SIGTTIN` 停住；末步收口 `kill` 的 pid 带符号，以及 `setsid()` 一次做三件事、要求调用者不是组长所以守护进程得先 `fork`）。
**对应笔记**：[[11.2 进程创建与程序替换]] · [[11.3 结束进程]] · [[11.6 进程组与会话]] · [[11.4 等待与回收]]。

## 4. TCP 编程

### 4.1 · TCP 原理

[▶ 打开动画](<../图片/HTML/3.Linux/8. TCP 编程/8.1.1 TCP原理动画.html>)

三个主题：**Seq/Ack 按字节推进**（字节标尺 1000~1014，报文段括号罩住发送区间、ack 徽章沿标尺滑动，核心一幕是丢包演示：`seq=1005` 段丢失后 `seq=1010` 段先到，ack **卡在 1005 不动**（累计确认卡在缺口），重传补齐后 ack 直接跳到 1015——一步看懂"Ack = 下一个期待字节"）、**SYN/FIN 占序号**（序号轴上 SYN 占住 100 号格子所以对方回 `ack=101`，正式数据从 101 开始；FIN 占住 500 所以回 `ack=501`——解开"SYN 没带数据为什么 ack 要 +1"的经典疑惑）、**连接全生命周期**（三次握手 `seq=100/300` → 数据传输 ack 推进 → 四次挥手 `500/501/900/901` → TIME_WAIT 2MSL，一条时间线串完建连→传数据→断连，socket API 面板按阶段高亮）。
**对应笔记**：[[8.1 TCP原理]]。

### 4.2 · IO 缓冲

[▶ 打开动画](<../图片/HTML/3.Linux/8. TCP 编程/8.7.1 IO缓冲动画.html>)

三个主题：**全链路数据流**（用户态 `write(40B)` → 内核发送缓冲 → 网络 → 对端接收缓冲 → 4 次 `read(10B)`，字节块沿五段泳道滑动，揭晓"剩下 30B 不在空中盘旋、在接收缓冲排队"，并点破 `write ≠ 发送`）、**缓冲为什么存在**（效率：小写合并减 40B 头开销；流控：水位驱动反压；可靠：未确认段保留、丢包后从缓冲重传）、**关闭时的命运**（`close()` 后输出缓冲遗留数据继续发送、输入缓冲未读数据直接丢弃，四条铁律对照高亮）。

### 4.3 · 流控制

[▶ 打开动画](<../图片/HTML/3.Linux/8. TCP 编程/8.8.1 流控制动画.html>)

三个主题：**发送方滑动窗口**（字节流四区着色：已确认 / 已发送未确认 / 可发送 / 窗口外，SND.UNA 与窗口右沿两条指针真实滑动——ACK 到达窗口右滑、通告缩小窗口收缩、额度用尽发送方必须停）、**rwnd 动态变化**（接收缓冲区水位涨落驱动 win 通告，数字与笔记时序完全一致：发 1000B→win=8000、发 5000B 堆积→win=3000、发 3000B 缓冲区满→win=0 暂停、应用 `read()` 读走 4000B→win=4000 恢复，看清"接收方用 win 字段反压发送方"）、**零窗口探测**（win=0 后窗口更新 ACK 在网络中丢失 → 双方互等死锁 → persist timer 倒计时到期 → 发送 1 字节零窗口探测报文 → 对方回 win=4000 解除死锁）。

### 4.5 · 拥塞控制

[▶ 打开动画](<../图片/HTML/3.Linux/8. TCP 编程/8.10.1 拥塞控制动画.html>)

**对应笔记**：[[8.10 拥塞控制]]。

### 4.6 · 非阻塞 connect 与健壮收发

[▶ 打开动画](<../图片/HTML/3.Linux/8. TCP 编程/8.12.1 非阻塞connect与健壮收发动画.html>)

三个主题：**非阻塞 connect**（`connect()` 返回 -1 + `EINPROGRESS` **不是失败**——SYN 已交内核后台握手；核心误区"可写 ≠ 成功"：成功路径 `getsockopt(SO_ERROR)`→err=0，失败路径对端回 RST 同样以"可写"唤醒、err=ECONNREFUSED，收口三步公式 EINPROGRESS→等可写/错误→查 SO_ERROR）、**短写**（业务要发 10KB 而内核缓冲只剩 4KB：`send` 返回 4096 就只发出 4096——交付进度条/内核水位条/output_buffer 三条真实增减，余量 6KB 挂应用层输出缓冲、再写撞 `-1 EAGAIN`（满≠错）、EINTR 重试、EPIPE 才关连接，腾空后续发完成；EPOLLOUT 注册舞步引用 13.6 不重演）、**反压**（对端读得慢→内核缓冲堆积→output_buffer 冲破 HIGH_WATERMARK 红线→`disableReading` 暂停读取"不读→不产生响应→堆积不再增长"→低水位 `enableReading` 恢复，附输入堆积/线程池过长/定时器踢慢连接三类兜底）。
**对应笔记**：[[8.12 非阻塞connect与健壮收发]]。

### 4.7 · TCP 内核队列

[▶ 打开动画](<../图片/HTML/3.Linux/8. TCP 编程/8.13 内核队列动画.html>)

四个主题：**两个队列**（三次握手穿过**半连接队列**（SYN_RECV）与**全连接队列**（ESTABLISHED），连接芯片在 客户端→半连接→全连接→`accept()` 四列间真实滑动，点破 `listen(fd, backlog)` 背后不是一个队列——半连接服务握手、全连接服务 accept）、**backlog 上限**（`listen` 的 backlog 被 `net.core.somaxconn` 封顶：三条容量条联动演示 有效上限 = `min(512, 128) = 128`，只改代码不改内核参数没用，放开 `somaxconn` 到 512 才真正生效）、**全连接溢出**（`accept` 太慢 → 队列填满 3/3 → 第 4 条已完成握手的连接被**丢弃**（`ListenOverflows` 增长）→ 客户端 `SYN+ACK` 重传/超时或 RST，收口 accept 后立刻交 epoll/worker、`SO_REUSEPORT` 分摊）、**SYN flood**（伪造源 SYN 占满半连接队列 → 正常客户端 SYN 被丢，开启 `tcp_syncookies` 把状态编码进 SYN+ACK 序列号、不再占队列，队列无法被耗尽、真客户端凭 cookie 建连）。
**对应笔记**：[[8.13 TCP内核队列与参数调优]]。

### 4.8 · 高性能发送（零拷贝）

[▶ 打开动画](<../图片/HTML/3.Linux/8. TCP 编程/8.14 高性能发送动画.html>)

五个主题：**read+write 基线**（数据芯片走完 磁盘→页缓存→用户 buf→socket 缓冲→网卡 五站，CPU 拷贝 / DMA / syscall 三个计数器逐步累加，收口"两次 CPU 拷贝纯属过路——数据在用户态什么都没做"）、**sendfile**（一次系统调用后数据只在内核横向移动、用户态往返消失；SG-DMA 进阶：socket 缓冲只存描述符、网卡直接从页缓存取数，CPU 拷贝归零；边界：用户态碰不到数据，只适合原样转发）、**mmap + send**（映射只改页表不搬字节，缺页 DMA 装载后用户透过映射直接读改——省掉 read 那次拷贝；send 仍要一次 CPU 拷贝，比 sendfile 多一次但保留加工能力）、**splice**（pipe 是一组页指针槽位：两次 splice 挂引用不搬字节、全程内核态；socket→socket 的代理转发 sendfile 做不了、splice 经 pipe 中转即可）、**writev 聚集写**（header/body 分居两块缓冲，反例 memcpy 拼接多一次拷贝一次分配、两次 send 双倍 syscall 还有小包风险；iovec 只是指针+长度清单，内核按序聚集一次写出）。

### 12.2 / 17.6 · 无锁编程与并发队列

[▶ 打开动画](<../图片/HTML/3.Linux/17. 并发同步/17.5-17.6 无锁编程与并发队列动画.html>)

五个主题：**CAS 重试**（Thread A 读 `expected=5`、算 `desired=6`，B 插队先提交成 6 → A 的 CAS 失败但 `expected` 被**自动刷新**为 6 → 直接重算再提交 6→7 成功，收口"A 失败恰证明 B 成功——系统总在推进"的 lock-free 语义与循环内用 `_weak` 的理由）、**ABA 问题**（无锁栈 head→A(0x100)→B→C：T1 读完快照被抢占，T2 pop A、pop B、delete 后 push D **恰好复用 0x100**，T1 恢复后 `CAS(0x100→0x200)` 竟成功——head 悬垂指向已释放内存；末步给出 tagged pointer 解法：值同版异 v1≠v3 → CAS 安全失败）、**SPSC 环形缓冲**（8 格环 + 真实滑动的 head/tail 徽章：push 两拍"①先写槽位②再 release 发布 tail"，acquire 配对保证读者绝不见半成品；tail 回绕撞 head 演示**留一格判满**，收口"一端一个写者所以零 CAS"与 `alignas(64)` 防伪共享）、**MPMC 队列**（Michael-Scott 哨兵链表：P1、P2 同时 `CAS(tail->next, null→节点)`，仅 P1 赢、P2 无阻塞重试，接节点/推 Tail 两步 CAS 与"帮忙推进"，出队 `CAS(Head)` 后 n1 变新哨兵——旧哨兵何时 delete 引出回收难题）、**内存回收**（hazard pointer 全流程：读者登记 `HP[R]=0x100` → 回收者摘节点入 retire 链 → 扫表发现被保护**推迟释放** → 读者清 HP → 再扫安全 delete，对照 RCU 宽限期，同一铁律"读者在场，绝不释放"）。
**对应笔记**：[[17.5 无锁编程：CAS、乐观锁与悲观锁]] · [[17.6 并发队列：有界队列与无锁队列]]。

### 12.3 · 进程间同步

[▶ 打开动画](<../图片/HTML/3.Linux/17. 并发同步/17.7 进程间同步动画.html>)

四个主题：**共享内存 + pshared 锁**（两进程 mmap 同一物理页、虚拟地址不同但页表汇聚；反例红线：默认 `PTHREAD_PROCESS_PRIVATE` 放进共享内存也不生效；`setpshared + setrobust` 后像两个线程一样真实竞争、unlock 唤醒交接）、**持锁进程崩溃**（转账改到一半 A 扣了 B 没加，P1 死于临界区——普通锁被永久锁死、P2 blocked forever，收口"线程同归于尽 vs 进程独立存亡"的失败单元差异）、**EOWNERDEAD 修复**（robust 锁善后四步逐行点亮：lock 返回 `EOWNERDEAD` 拿到锁+得知真相 → `repair_invariants` 修复中间态 → `pthread_mutex_consistent` 声明恢复 → 正常 unlock 后续进程无感；反例：跳过 consistent 直接 unlock → `ENOTRECOVERABLE` 锁报废）、**OFD 锁**（传统记录锁挂在「进程+inode」名下：库代码 close 无关 fd7，fd3 的锁瞬间蒸发；`F_OFD_SETLK` 把归属改到打开文件描述、无关 close 免疫，dup/fork 共享同一把锁）。

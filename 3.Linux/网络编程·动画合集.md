### 7.5 · TCP 连接建立与释放

[▶ 打开动画](<file:///Users/melene/Documents/C++/obsidian_notes-main/3.Linux/7. 网络编程基础/7.5.1 TCP连接建立与释放动画.html>)

## 8. TCP 编程

### 8.1 · TCP 原理

[▶ 打开动画](<file:///Users/melene/Documents/C++/obsidian_notes-main/3.Linux/8. TCP 编程/8.1.1 TCP原理动画.html>)

三个主题：**Seq/Ack 按字节推进**（字节标尺 1000~1014，报文段括号罩住发送区间、ack 徽章沿标尺滑动，核心一幕是丢包演示：`seq=1005` 段丢失后 `seq=1010` 段先到，ack **卡在 1005 不动**（累计确认卡在缺口），重传补齐后 ack 直接跳到 1015——一步看懂"Ack = 下一个期待字节"）、**SYN/FIN 占序号**（序号轴上 SYN 占住 100 号格子所以对方回 `ack=101`，正式数据从 101 开始；FIN 占住 500 所以回 `ack=501`——解开"SYN 没带数据为什么 ack 要 +1"的经典疑惑）、**连接全生命周期**（三次握手 `seq=100/300` → 数据传输 ack 推进 → 四次挥手 `500/501/900/901` → TIME_WAIT 2MSL，一条时间线串完建连→传数据→断连，socket API 面板按阶段高亮）。
**对应笔记**：[[8.1 TCP原理]]。

### 8.7 · IO 缓冲

[▶ 打开动画](<file:///Users/melene/Documents/C++/obsidian_notes-main/3.Linux/8. TCP 编程/8.7.1 IO缓冲动画.html>)

三个主题：**全链路数据流**（用户态 `write(40B)` → 内核发送缓冲 → 网络 → 对端接收缓冲 → 4 次 `read(10B)`，字节块沿五段泳道滑动，揭晓"剩下 30B 不在空中盘旋、在接收缓冲排队"，并点破 `write ≠ 发送`）、**缓冲为什么存在**（效率：小写合并减 40B 头开销；流控：水位驱动反压；可靠：未确认段保留、丢包后从缓冲重传）、**关闭时的命运**（`close()` 后输出缓冲遗留数据继续发送、输入缓冲未读数据直接丢弃，四条铁律对照高亮）。
**对应笔记**：[[8.7 IO缓冲]]。

### 8.8 · 流控制

[▶ 打开动画](<file:///Users/melene/Documents/C++/obsidian_notes-main/3.Linux/8. TCP 编程/8.8.1 流控制动画.html>)

三个主题：**发送方滑动窗口**（字节流四区着色：已确认 / 已发送未确认 / 可发送 / 窗口外，SND.UNA 与窗口右沿两条指针真实滑动——ACK 到达窗口右滑、通告缩小窗口收缩、额度用尽发送方必须停）、**rwnd 动态变化**（接收缓冲区水位涨落驱动 win 通告，数字与笔记时序完全一致：发 1000B→win=8000、发 5000B 堆积→win=3000、发 3000B 缓冲区满→win=0 暂停、应用 `read()` 读走 4000B→win=4000 恢复，看清"接收方用 win 字段反压发送方"）、**零窗口探测**（win=0 后窗口更新 ACK 在网络中丢失 → 双方互等死锁 → persist timer 倒计时到期 → 发送 1 字节零窗口探测报文 → 对方回 win=4000 解除死锁）。
**对应笔记**：[[8.8 流控制]]。

### 8.9 · TCP 粘包与拆包

[▶ 打开动画](<file:///Users/melene/Documents/C++/obsidian_notes-main/3.Linux/8. TCP 编程/8.9.1 TCP粘包与拆包动画.html>)

### 8.10 · 拥塞控制

[▶ 打开动画](<file:///Users/melene/Documents/C++/obsidian_notes-main/3.Linux/8. TCP 编程/8.10.1 拥塞控制动画.html>)

四个主题：**慢启动**（柱状图 cwnd 1→2→4→8 指数翻倍，在途报文段与 ACK 小芯片同步亮灭，触达 ssthresh=8 改色提示切阶段）、**拥塞避免**（过门限后每 RTT 只 +1 MSS：8→9→10→11 线性爬坡，公式 `cwnd += MSS×MSS/cwnd` 与 AIMD 加性增大对照）、**快重传·快恢复**（双生命线：情形 A 丢段 3 后累计 3 个重复 ACK=3 → 立刻重传、ssthresh=cwnd/2、进入快恢复；情形 B 超时 → cwnd 直接打回 1、重回慢启动，底部对照卡收口两种降速力度）、**完整曲线**（RTT1–12 的 cwnd/ssthresh 全程锯齿：慢启动→拥塞避免→3 dup ACK 减半→再避免→超时打回 1，阶段色带与事件竖线同步点亮）。

## 13. IO 复用

### 13.2 / 13.4 · select 与 epoll 对比

[▶ 打开动画](<file:///Users/melene/Documents/C++/obsidian_notes-main/3.Linux/13. IO复用/13.2.1 select与epoll对比动画.html>)

三个主题：**select 工作流**（`FD_ZERO/FD_SET` 组装位图 → 整份 `fd_set` 每次拷入内核 → 内核线性扫全部监控 fd → 用户态再 `FD_ISSET` 扫 maxfd 找就绪 → 返回后集合被破坏须重建，三道线性成本叠加；`FD_SETSIZE≈1024` 硬上限）、**epoll 工作流**（`epoll_create1` 建实例 → `epoll_ctl` 把 fd 挂进内核红黑树常驻 → 数据到达回调挂就绪链表 → `epoll_wait` 只返回就绪数组、用户无二次全量扫描 → 下轮无需重建监控集）、**对照总结**（集合传递 / 事件检测 / 返回形态 / 上限与成本四条差异；代价主要 ∝ 就绪数而非总连接数——勿机械背「永远 O(1)」；Linux 高并发首选 epoll，它发现「谁就绪」，Reactor 负责「分发给谁」）。
**对应笔记**：[[13.2 select模型]] · [[13.4 epoll模型]]。

### 13.4 · epoll LT 与 ET

[▶ 打开动画](<file:///Users/melene/Documents/C++/obsidian_notes-main/3.Linux/13. IO复用/13.4.1 epoll LT与ET动画.html>)

四个主题：**LT 水平触发**（接收缓冲有数据就反复通知，读一部分后只要还有剩余，下轮 `epoll_wait` 仍会再报——默认模式、编程简单）、**ET 边缘触发**（状态变化边沿只通知一次；读不干净就可能再无通知，必须配合非阻塞 fd）、**非阻塞读到 EAGAIN**（ET 下循环 `recv` 直到 `EAGAIN`/`EWOULDBLOCK` 才算本轮读完；阻塞 fd + ET 会卡死 EventLoop）、**LT vs ET 对照**（通知条件、读策略、常见坑并排收口）。
**对应笔记**：[[13.4 epoll模型]]。

### 13.6 · Reactor 与 EventLoop

[▶ 打开动画](<file:///Users/melene/Documents/C++/obsidian_notes-main/3.Linux/13. IO复用/13.6.2 Reactor EventLoop动画.html>)

四个主题：**角色映射**（epoll 只发现就绪 → Handle/fd → Demultiplexer/`epoll_wait` → EventLoop 分发 → Channel 绑 fd+回调 → Acceptor/TcpConnection 做真实 IO；「epoll 面向 fd，Reactor 面向对象」）、**事件循环**（`poller.poll` → `channel.handleEvent` → `doPendingFunctors` 三步骨架，activeChannels 就绪列表与跨线程任务点亮，铁律：勿阻塞 EventLoop）、**读写路径**（accept 循环 `accept4`、read 填 input buffer 再协议解析、写路径最易错：常驻 `EPOLLOUT` 空转 → 正确做法是有待发且未发完才 `enableWriting`，发完 `disableWriting`）、**one loop per thread**（main loop 专职 accept → 轮询分配 sub loop → 连接读写归属固定 → worker 池做重活后回投所属 loop；Reactor 与线程池正交互补）。

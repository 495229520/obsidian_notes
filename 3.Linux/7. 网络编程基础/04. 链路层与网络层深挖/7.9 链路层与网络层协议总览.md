# 7.9 链路层与网络层协议总览

> [!abstract] 本组笔记的定位
> 本组笔记沿着「一个 IP 数据报如何离开本机、跨越网络并反馈差错」的主线，补充链路层和网络层协议。分层模型的整体介绍见 [[7.1 网络分层模型]]，地址、子网与 CIDR 的计算见 [[7.2 IP地址与CIDR]]。这一篇是总览：先把四个协议串成一条完整链路，字段级的细节留给 7.9 到 7.13。

## 1. 为什么这四个协议要放在一起讲

[[7.1 网络分层模型|分层模型]]说清了每层负责什么，[[7.2 IP地址与CIDR|IP 地址]]说清了地址怎么算，但两者都没回答一个具体问题：程序里 `write()` 出去的一段数据，怎么变成网线上的信号，又怎么找到地球另一端那台机器。

回答这个问题需要四个协议合起来：

- **Ethernet** 管一条链路上相邻两个节点之间怎么传一帧；
- **IP** 管数据报跨越多条链路、经过多台路由器到达目标；
- **ARP** 管把 IP 层算出的「下一跳 IP」翻译成链路层能用的 MAC 地址；
- **ICMP** 管上面任何一步出错时，把消息送回源主机。

前三个是数据平面，最后一个是控制平面。少了 ARP，IP 数据报封不成帧，包发不出去；少了 ICMP，包丢在哪一跳你永远查不出来。

## 2. 一次跨网段通信：包在路上被改了什么

假设主机 A（`192.168.1.10`）要访问 `203.0.113.20`，中间隔着一台交换机和两台路由器。

![[图片/SVG/3_7_7_9_1.svg|900]]

按发送顺序拆开，内核做的事是这样的：

1. **判断目标是不是同网段。** 用目的 IP 和本机的子网掩码做与运算，结果不等于本网段，说明要出网关。
2. **查路由表定下一跳。** 目的地不在任何直连网段，走默认路由，下一跳是网关 `192.168.1.1`。注意下一跳的 IP 和最终目的 IP 是两个不同的东西，前者只用来找 MAC，不会写进 IP 头。
3. **把下一跳 IP 换成 MAC。** 查邻居表，命中就直接用；没命中就发 ARP 请求，这是图 B 的四步。
4. **封 Ethernet 帧交给网卡。** 目的 MAC 填网关的，源 MAC 填本机网卡的，EtherType 填 `0x0800` 表示载荷是 IPv4。
5. **交换机按 MAC 转发。** 它查自己的 MAC 地址表决定从哪个口发出去，帧头一个字节都不改，IP 头对它是不透明的载荷。
6. **路由器换帧头再转发。** R1 剥掉旧帧头，读 IP 头查路由表，TTL 减 1，重算 IPv4 首部校验和，再用下一跳的 MAC 封一个全新的帧。R2 重复一遍。
7. **出错时回 ICMP。** TTL 耗尽、无路可达、包超过链路 MTU 又置了 DF，这三种情况下卡住的那台设备会生成一个 ICMP 差错报文，按源 IP 送回 A。

图 A 的表格是这一路的结果：**MAC 每跳重写，IP 端到端不变，TTL 每跳减 1**。这条规则是后面所有抓包分析的基准线。本机抓包看到目的 MAC 是网关、目的 IP 是某个公网地址，这是正常现象，说明包要出本网段。

> [!note] 同网段的情况少两步
> 如果目标就在本网段，第 2 步选出的下一跳就是目标自己，ARP 直接问目标要 MAC，整条路上没有路由器，TTL 也不减。区别只在下一跳选谁，ARP 那一步的机制完全一样。

## 3. 四个协议的分工

| 协议 | 所在位置 | 回答的问题 | 主要标识 | 作用范围 |
|---|---|---|---|---|
| Ethernet | 数据链路层 | 相邻两个节点之间怎样传一帧 | MAC 地址、EtherType | 单条链路 |
| IPv4 / IPv6 | 网络层 | 数据报怎样跨网段到达目标 | IP 地址、路由前缀 | 端到端 |
| ARP | 夹在 IPv4 和链路层之间 | 下一跳 IPv4 对应哪个 MAC | IP 与 MAC 的映射 | 单个广播域 |
| ICMP / ICMPv6 | 网络层的控制协议 | 怎样报告差错、怎样诊断 | Type、Code | 从出错点回到源主机 |

三个协议的封装关系值得单独记一下，它决定了抓包时该按什么条件过滤：

| 谁装在谁里面 | 标识字段 | 抓包过滤 |
|---|---|---|
| IPv4 装在 Ethernet 帧里 | EtherType `0x0800` | `tcpdump ip` |
| IPv6 装在 Ethernet 帧里 | EtherType `0x86DD` | `tcpdump ip6` |
| ARP 装在 Ethernet 帧里 | EtherType `0x0806` | `tcpdump arp` |
| ICMP 装在 IPv4 数据报里 | IP 首部协议号 `1` | `tcpdump icmp` |
| ICMPv6 装在 IPv6 数据报里 | 下一个首部 `58` | `tcpdump icmp6` |

> [!warning] ARP 不在 IP 之上
> 很多图把 ARP 画在网络层，容易让人以为 ARP 报文外面套着 IP 头。实际上 ARP 报文直接装在 Ethernet 帧里，走的是自己的 EtherType `0x0806`，整个过程不经过 IP 层。ARP 里出现的 IP 地址只是被查询的数据，不是路由用的地址。

## 4. IPv4 走 ARP，IPv6 走 NDP

ARP 只服务于 IPv4。IPv6 把邻居解析这件事收进了 ICMPv6，叫 NDP（Neighbor Discovery Protocol，邻居发现协议）。

| | IPv4 | IPv6 |
|---|---|---|
| 邻居解析协议 | ARP，独立的 EtherType | NDP，是 ICMPv6 的一组报文 |
| 询问方式 | 广播到 `ff:ff:ff:ff:ff:ff` | 组播到被请求节点组播地址 |
| 报文 | Request / Reply | NS（135）/ NA（136） |
| 路由器发现 | 靠 DHCP 或手工配置 | RS（133）/ RA（134），协议自带 |
| 缓存位置 | `ip neigh` | 同样是 `ip neigh` |

差别不只是换个名字。ARP 用广播，同一广播域里每台机器的网卡都要收下这个帧、交给内核判断是不是问自己，网段一大就是纯粹的浪费。NDP 用组播，目标地址由被查询 IPv6 地址的低 24 位算出来，落到不相干主机上的概率很低，网卡在硬件层面就过滤掉了。

另一个后果是：IPv6 的邻居发现依赖 ICMPv6，所以**在 IPv6 网络上无脑封禁 ICMP 会直接让网络瘫痪**。IPv4 里封掉 ICMP 只是让 `ping` 不通，IPv6 里封掉 ICMPv6 连邻居的 MAC 都解析不出来。

## 5. ICMP：网络层唯一会回话的协议

IP 本身是尽力而为的：包送不到就丢掉，不解释也不重试。ICMP 补上的正是这个解释。

图 C 列了四种最常遇到的差错。它们的共同点是：**差错报文由中途的设备生成，源 IP 是那台设备的地址，报文体里附上原包的 IP 首部加前 8 字节**。附这 8 字节是为了让源主机能对号入座。TCP 和 UDP 的源端口、目的端口正好落在这 8 字节里，源主机据此知道是哪个连接出的问题。

两个日常工具就建立在这上面：

- `ping` 发 Echo Request（ICMPv4 Type 8），等 Echo Reply（Type 0）。ICMPv6 里对应 128 和 129。
- `traceroute` 把 TTL 从 1 开始逐次加一。TTL 减到 0 的那台路由器回一个超时报文，报文的源 IP 就暴露了这一跳是谁。Linux 上它默认发 UDP 到 33434 起的高端口，到达终点后靠「端口不可达」判断走到头了；加 `-I` 则改用 ICMP Echo。

> [!warning] ping 不通不代表主机不在
> 防火墙丢弃 ICMP Echo 是常见配置，此时主机活得好好的，TCP 端口也通，只是不回 ping。反过来 ping 通也不代表服务可用，那只说明三层可达。判断服务是否在，用 `telnet 主机 端口` 或 `nc -vz` 探四层。

## 6. 常见误区

- **MAC 地址不会端到端保持不变。** 每经过一台路由器就被完整重写一次。只有在同一个广播域内它才是稳定的。
- **Ethernet 帧长和 IP 数据报长度不是一回事。** 帧比数据报多 14 字节帧头和 4 字节 FCS，加了 802.1Q VLAN 标签再多 4 字节。MTU 1500 说的是载荷上限，不含这些。
- **交换机不读 IP 头。** 它只认 MAC 地址表。能按 IP 转发的是三层交换机，那已经在做路由器的活。
- **FCS 通常不出现在抓包结果里。** 校验由网卡硬件完成，校验通过后 FCS 就被剥掉了，抓包工具拿到的一般是不含 FCS 的帧。
- **ICMP 不是传输层协议。** 它装在 IP 里，但没有端口号，所以防火墙规则里不能按端口匹配 ICMP，只能按 Type 和 Code。
- **下一跳 IP 不会写进 IP 头。** 它只用来查 ARP，查完就没它的事了。IP 头里始终是最终目的地址。

## 7. 动手验证

先看内核的决策结果，再看链路上的实际字节，两边能对上就说明这条链路理解对了。

```bash
ip -br addr                    # 网卡、IP 与状态，一行一个接口
ip link show eth0              # MAC 地址和 MTU
ip route get 203.0.113.20      # 内核对这个目的地选了哪个下一跳、走哪张网卡、用哪个源 IP
ip neigh                       # 邻居表，IPv4 的 ARP 缓存和 IPv6 的 NDP 缓存都在这里
```

`ip route get` 是这几条里最有用的。它不打印整张路由表，而是直接给出内核对某个具体地址的决策：`via` 后面是下一跳，`dev` 是出接口，`src` 是会填进 IP 头的源地址。上面第 1 到第 3 步的结果，这一条命令就能全部确认。

观察 ARP 首包需要先把缓存清掉，否则第一个包就直接命中了：

```bash
sudo ip neigh flush all
sudo tcpdump -i eth0 -n 'arp or icmp' &
ping -c 1 192.168.1.1
```

正常会看到四行：ARP 请求（广播）、ARP 应答（单播）、ICMP Echo Request、ICMP Echo Reply。这个顺序印证了图 B：解析不出 MAC 就封不出帧，ping 包只能排队等着。

探测路径 MTU 用置 DF 位的大包：

```bash
ping -M do -s 1472 -c 1 203.0.113.20     # 1472 + 8(ICMP) + 20(IP) = 1500
```

`-M do` 让内核置上 DF 位，禁止沿途分片。如果中间某段链路的 MTU 小于 1500，就会收到 `Frag needed and DF set`，也就是图 C 第三行的 ICMP Type 3 Code 4，报文里还会带上那一跳的 MTU 值。逐步减小 `-s` 直到能通，就测出了路径 MTU。

> [!note] `-M do` 是 Linux 的写法
> macOS 的 `ping` 用 `-D` 置 DF 位，参数含义不通用。本组笔记的命令都以 Linux 为准。

## 10. 关键要点

1. **四个协议是一条流水线**：IP 定目标和下一跳，ARP/NDP 把下一跳换成 MAC，Ethernet 把帧送到对面，ICMP 在出错时把消息带回来。
2. **MAC 逐跳重写，IP 端到端不变，TTL 每跳减 1**。抓包时先核对这三条，不符合就说明拓扑理解错了。
3. **下一跳 IP 只用来查 MAC**，从不写进 IP 头。区分不开这两个地址，跨网段的包为什么发得出去就想不通。
4. **ARP 直接装在 Ethernet 帧里**，EtherType `0x0806`，不经过 IP 层；ICMP 装在 IP 里，协议号 `1`，但没有端口。
5. **IPv6 把邻居解析并进了 ICMPv6**。IPv4 里封 ICMP 只是 ping 不通，IPv6 里封 ICMPv6 会让网络直接不可用。

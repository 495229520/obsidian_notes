## 1. IPv4 承诺了什么，没承诺什么

IPv4 提供的是**无连接、尽力而为的数据报服务**。这两个词的具体含义是：

- **无连接**：每个数据报独立处理，路由器不为你保存任何状态。同一个 TCP 连接的两个包走不同的路径是允许的，到达顺序颠倒也是允许的。
- **尽力而为**：送不到就丢掉。IP 不重传、不确认、不排序、不去重、不做流控。

所以 IPv4 只承诺一件事：**尽量把这个数据报送到目的地址，并且保证首部在传输中没有损坏**。校验和只覆盖首部，负载坏了 IP 层不管。

需要可靠、需要顺序、需要不重复，全部由传输层补上，这正是 [[7.5 TCP协议基础|TCP]] 存在的理由。UDP 不补，所以 UDP 程序要自己面对丢包和乱序。

封装关系：IPv4 数据报装在 [[7.8.1 Ethernet以太网|Ethernet]] 帧里（EtherType `0x0800`），TCP 段、UDP 数据报、[[7.8.5 ICMP与ICMPv6|ICMP]] 报文装在 IPv4 数据报里（靠 Protocol 字段区分）。

## 2. 首部：20 字节里装了什么

![[图片/SVG/3_7_7_8_2_1.svg|900]]

| 字段 | 宽度 | 作用 | 谁会改它 |
|---|---|---|---|
| Version | 4 位 | 固定填 4 | 源主机 |
| IHL | 4 位 | 首部长度，**单位是 4 字节**，最小 5，最大 15 | 源主机 |
| DSCP / ECN | 6 + 2 位 | 服务等级与拥塞标记，由 RFC 2474 和 3168 重新划分原来的 TOS 字节 | 源主机、支持 ECN 的路由器 |
| Total Length | 16 位 | 首部加负载的总字节数，**单位是 1 字节**，上限 65535 | 分片时会改 |
| Identification | 16 位 | 同一个原始数据报的所有分片填同一个值 | 源主机 |
| Flags | 3 位 | 保留位、DF（禁止分片）、MF（后面还有片） | 分片时会改 |
| Fragment Offset | 13 位 | 本片数据在原负载中的位置，**单位是 8 字节** | 分片时会改 |
| TTL | 8 位 | 每经过一台路由器减 1，减到 0 丢弃 | **每跳都改** |
| Protocol | 8 位 | 负载交给谁：1 ICMP，6 TCP，17 UDP | 源主机 |
| Header Checksum | 16 位 | 只覆盖首部的反码和 | **每跳都改** |
| Source / Destination | 各 32 位 | 源、目的 IP 地址 | 端到端不变（NAT 除外） |
| Options + Padding | 可变 | 只有 IHL > 5 时存在 | 极少用到 |

三个容易记混的点：

**IHL 和 Total Length 的单位不一样。** IHL 以 4 字节为单位，Total Length 以 1 字节为单位。最常见的首字节 `0x45` 就是版本 4 加 IHL 5，也就是 20 字节首部。看到 `0x46` 以上说明带了 Options。

**校验和只覆盖首部。** 计算方式是把首部按 16 位分组求反码和，计算时把校验和字段本身当作 0。负载损坏 IP 层察觉不到，那是 TCP 校验和的职责；UDP 在 IPv4 下校验和是可选的，填 0 表示不校验。

**TTL 是跳数不是时间。** 名字里的 Time 是历史遗留，实际语义就是「还能经过多少台路由器」。上限 255，Linux 出发时填 64。对端回包的 TTL 和 64、128、255 的差值，能大致反推中间隔了几跳。

## 3. 逐跳转发：路由表怎么选下一跳

主机要发一个包，先做一次判断：目的 IP 和本机地址按子网掩码做与运算，结果相同就是同网段，直接问对方要 MAC；不同就得交给路由器。

这个判断在 Linux 里体现为路由表的匹配。一张典型的主机路由表：

```
$ ip route
default via 192.168.1.1 dev eth0 proto dhcp metric 100
192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.10 metric 100
```

两条规则的区别在于有没有 `via`：

- 第二条**没有** `via`，叫直连路由。它说的是「`192.168.1.0/24` 这个网段就挂在 eth0 上」，下一跳就是目标本身。
- 第一条**有** `via`，下一跳是 `192.168.1.1`。`default` 等价于 `0.0.0.0/0`，前缀长度 0，能匹配任何地址。

匹配规则是**最长前缀匹配**：所有能匹配的条目里，前缀最长的那条胜出。`192.168.1.20` 同时匹配 `/24` 和 `/0`，`/24` 更长所以走直连；`8.8.8.8` 只匹配 `/0`，走默认路由。这条规则和表里的书写顺序无关。

> [!note] 下一跳 IP 从来不写进 IP 首部
> 路由表选出的 `via 192.168.1.1` 只有一个用途：拿去问 [[7.8.4 ARP|ARP]] 要 MAC 地址。IP 首部里的目的地址始终是最终目标。分不清这两个地址，跨网段的包为什么发得出去就永远想不通。

路由器收到一个不是发给自己的数据报，做四件事：

1. 剥掉链路层帧头。
2. 查路由表，按最长前缀匹配选出出接口和下一跳。
3. **TTL 减 1**。减完是 0 就丢弃，并回一个 ICMP 超时报文（Type 11）。
4. **重算首部校验和**，因为 TTL 变了。实现上不必从头算一遍，RFC 1624 给了增量更新的做法：只根据变化的那 16 位调整校验和。

然后用下一跳的 MAC 封一个全新的帧发出去。**源、目的 IP 一个字节都不动**，改的只有 TTL 和校验和。

## 4. 分片：切开容易，丢一片就全废

数据报比出口链路的 MTU 大，又没置 DF 位，IP 层就把它切开。

![[图片/SVG/3_7_7_8_2_2.svg|900]]

切法有三条硬规则：

1. **每片都要带一份完整的 IP 首部**，所以每片能装的数据是 `MTU − 20`。
2. **除最后一片外，每片的数据长度必须是 8 的倍数**，因为 Fragment Offset 的单位是 8 字节，13 位的字段才够表示 65535 字节的范围。
3. **同一批分片的 Identification 填同一个值**，接收方靠它把散落的片认成一家。

图里 4000 字节的数据报过 MTU 1500 的链路，`1500 − 20 = 1480` 是每片的数据上限，正好是 8 的倍数。切出 1480、1480、1020 三片，Offset 分别是 0、185（`1480 ÷ 8`）、370（`2960 ÷ 8`），前两片 MF 置 1，最后一片 MF 置 0。

> [!warning] 只有片 1 里有传输层首部
> UDP 首部只有 8 字节，跟在 IP 首部后面，所以它整个落在片 1 里。片 2 和片 3 单独拿出来看不到源端口和目的端口，这就是防火墙和负载均衡常常直接丢弃非首片的原因——它们按端口做策略，读不到端口就没法判断。

重组只在**目的主机**做一次，中途的路由器不攒片。这带来一系列代价：

- 丢任何一片，整个原始数据报都拼不起来，4000 字节全部白传，且 IP 层不会只重传那一片。
- 重组有超时。Linux 的 `net.ipv4.ipfrag_time` 默认 30 秒，超时就丢掉已收到的片，并回一个 ICMP Type 11 Code 1（分片重组超时）。
- 分片放大了丢包的影响。三片各有 1% 的丢包率，整报的成功率就掉到 97% 左右。

TCP 基本不会走到这一步。它在三次握手时协商 MSS，以太网上通常是 `1500 − 20 − 20 = 1460`，超过就由 TCP 自己切段。**切段和分片是两回事**：切段发生在传输层，每段各自封成一个完整的 IP 数据报，丢了只补这一段；分片发生在 IP 层，一片丢了整报作废。名字像，后果差得远。

真正会遇到分片的是 UDP：一次 `sendto()` 写了 4000 字节，IP 层就得动手切。所以 UDP 应用通常自己把消息控制在 1400 字节以内。

分片的这些麻烦，[[7.8.3 IPv6]] 的做法是直接取消路由器分片：包太大就丢掉并回一个 ICMPv6 报文，由源主机自己解决。

## 5. 路径 MTU 发现与黑洞

沿途各段链路的 MTU 未必相同，最小的那个决定了端到端能过多大的包，叫路径 MTU（PMTU）。发现它的办法是：**置上 DF 位发大包，被卡住时听 ICMP 的回复**。

```bash
ping -M do -s 1472 -c 1 8.8.8.8     # 1472 + 8 ICMP 首部 + 20 IP 首部 = 1500
```

`-M do` 让内核置 DF。如果中途某段 MTU 小于 1500，那台设备不能分片也不能转发，只好丢包并回一个 ICMP Type 3 Code 4（需要分片但设置了 DF），报文里带上自己那一跳的 MTU 值。源主机收到后把这个值记进路由缓存，之后发往这个目的地的包就按新 MTU 来。

```bash
ip route get 8.8.8.8      # 学到更小的 PMTU 后，输出里会多出一个 mtu 字段
```

> [!warning] PMTU 黑洞
> 有些网络为了「安全」把所有 ICMP 都丢掉，包括 Type 3 Code 4。这时源主机发的大包被中途丢弃，却收不到任何解释，表现是：小包能通、`ping` 正常、TCP 握手成功，但一传大数据就卡死。这类故障很难查，因为所有常规探测都是小包。
>
> Linux 的缓解手段是 `net.ipv4.tcp_mtu_probing`，置 1 表示检测到疑似黑洞时主动向下探测 MSS。

## 6. 协议分用

Protocol 字段决定负载交给内核的哪个模块。常见取值：

| 值 | 协议 | 说明 |
|---|---|---|
| 1 | ICMP | 差错与诊断，见 [[7.8.5 ICMP与ICMPv6]] |
| 2 | IGMP | 组播组管理 |
| 6 | TCP | |
| 17 | UDP | |
| 41 | IPv6 | IPv6 over IPv4 隧道 |
| 47 | GRE | 通用路由封装 |
| 50 / 51 | ESP / AH | IPsec |

完整列表在 `/etc/protocols`。这个字段就是网络层的分用（demultiplexing）依据，和 Ethernet 用 EtherType 分用、TCP/UDP 用端口号分用是同一个套路，只是分用的粒度一层比一层细。

## 7. Linux 观察与抓包

看内核的决策：

```bash
ip -br addr                  # 每个接口的地址
ip route                     # 完整路由表
ip route get 8.8.8.8         # 对这个目标的决策：下一跳、出接口、源地址、PMTU
ip link show eth0            # MAC 与 MTU
sysctl net.ipv4.ip_forward   # 本机是否在做转发
```

看链路上的实际字节：

```bash
sudo tcpdump -i eth0 -n -v icmp
```

`-v` 会把 IP 首部展开，输出形如：

```
IP (tos 0x0, ttl 64, id 12345, offset 0, flags [DF], proto ICMP (1), length 84)
    192.168.1.10 > 8.8.8.8: ICMP echo request, id 3, seq 1, length 64
```

对照第 2 节的表逐个核：`ttl 64` 是出发初值，`flags [DF]` 是禁止分片，`proto ICMP (1)` 是 Protocol 字段，`length 84` 是 Total Length（20 首部 + 8 ICMP 首部 + 56 默认负载）。

制造并观察分片：

```bash
ping -s 4000 -c 1 <同网段主机>          # 不置 DF，会被切片
sudo tcpdump -i eth0 -n 'ip[6:2] & 0x3fff != 0'   # 只抓 MF 置位或 Offset 非零的片
nstat -az | grep -i reasm               # 重组相关计数器
```

过滤表达式里 `ip[6:2]` 取的是首部第 6、7 字节（Flags + Fragment Offset），掩掉高 2 位的保留位和 DF 位，剩下的非零就说明这是一个分片。

## 8. 常见误区

- **IP 地址属于网络接口，不属于主机。** 一台主机可以有多个接口、每个接口多个地址，它们在路由上互相独立。`ip addr` 把地址列在接口下面，正是这个道理。
- **路由器不改源、目的 IP。** 它只改 TTL 和校验和。NAT 设备确实会改，但那是地址转换，已经超出 IP 转发的定义。
- **首部校验和不覆盖负载。** 负载的完整性归传输层管。IP 层不会因为数据坏了而丢包。
- **分片不是 TCP 做的。** TCP 切段，IP 分片，两者层次和后果都不同。
- **DF 置位不等于不会分片，而是宁可丢包也不分片。** 丢包时会回 ICMP 3/4，路径 MTU 发现就建立在这个行为上。
- **TTL 不是秒。** 它是跳数计数器。

## 9. 自测问题

1. 目标 IP 不在本地网段时，ARP 查询的是谁的 MAC 地址？
2. 路由器转发 IPv4 数据报时至少要修改哪些字段？
3. 为什么 TCP 通常通过 MSS 避免触发 IP 分片？
4. 一个 3000 字节的 IPv4 数据报过 MTU 1500 的链路，会切成几片？每片的 Offset 是多少？

> [!success]- 参考答案
> 1. 默认网关的 MAC。ARP 问的永远是下一跳，跨网段时下一跳是网关，不是最终目标。
> 2. TTL 减 1、重算首部校验和。链路层帧头也会整个换掉，但那不是 IP 首部的字段。
> 3. 分片丢一片就整报作废，重传代价大；很多中间设备直接丢非首片；重组只在终点做还有超时。TCP 用 MSS 把数据切到不超过 MTU，从源头绕开这些问题。
> 4. 三片。负载 2980 字节，每片最多装 1480：片 1 装 1480（Offset 0，MF=1，Total Length 1500），片 2 装 1480（Offset 185，MF=1，Total Length 1500），片 3 只剩 20 字节（Offset 370，MF=0，Total Length 40）。容易答错成两片，但第二片装 1500 字节的话总长会变成 1520，超过 MTU。

## 关键要点

1. **IPv4 只承诺尽力送达和首部完整。** 可靠、有序、不重复全部由传输层补。
2. **IHL 单位 4 字节，Total Length 单位 1 字节，Fragment Offset 单位 8 字节。** 三个单位不一样，看抓包时最容易栽在这里。
3. **转发只改 TTL 和首部校验和。** 源、目的 IP 端到端不变，改的是链路层帧头。
4. **最长前缀匹配和书写顺序无关**，`default` 就是前缀长度为 0 的兜底条目。
5. **分片的代价是非线性的。** 丢一片整报作废，重组只在终点做，还有 30 秒超时。TCP 用 MSS 绕开，UDP 得自己控制消息大小。
6. **DF 加 ICMP 3/4 构成路径 MTU 发现。** 把 ICMP 全封掉就得到一个 PMTU 黑洞：小包通、大包死。

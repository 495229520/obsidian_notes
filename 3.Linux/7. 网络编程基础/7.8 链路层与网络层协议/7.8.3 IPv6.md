## 1. 为什么需要 IPv6

直接原因是地址不够。IPv4 的 32 位地址空间理论上有 43 亿个，IANA 的顶级地址池在 2011 年 2 月分配完毕，之后新增的地址只能靠回收和交易。

NAT 把这件事拖了很多年，代价是打破了端到端可达：内网主机没有公网地址，外面主动连不进来。P2P、IP 电话、点对点游戏都得靠打洞或中转服务器绕开，一层 NAT 还能对付，运营商级 NAT 叠上去就基本没法做。

IPv6 用 128 位地址解决容量问题，但顺手做了另一件事：**把 IPv4 二十多年积累的历史包袱清掉**。首部字段从 13 个减到 8 个，长度写死，校验和删掉，路由器不再分片，广播换成组播。下面几节讲的就是这些改动各自换来了什么。

## 2. IPv6 地址

128 位，写成 8 组、每组 4 位十六进制数，冒号分隔：

```
2001:0db8:0000:0000:0000:0000:a1b2:c3d4
```

两条压缩规则：

1. **每组的前导零可以省略**：`0db8` → `db8`，`0000` → `0`。
2. **连续的全零组可以压成 `::`**，但整个地址里 `::` 只能出现一次。

上面那个地址压完是 `2001:db8::a1b2:c3d4`。

> [!warning] `::` 只能用一次
> `2001:0:0:1:0:0:0:2` 写成 `2001::1::2` 是非法的：解析器无法判断左边的 `::` 该补几组零、右边该补几组。合法写法是压缩最长的那串，`2001:0:0:1::2`。

前缀长度和 CIDR 一样写在斜杠后面，`2001:db8::/32` 表示前 32 位是网络前缀。和 IPv4 不同的是，**IPv6 的子网基本统一用 /64**，因为无状态地址自动配置要求后 64 位留给接口 ID。

### 常见地址段

| 地址段 | 名字 | 作用 |
|---|---|---|
| `2000::/3` | 全局单播 | 公网地址，相当于 IPv4 的公网 IP |
| `fe80::/10` | 链路本地 | 每个接口自动生成一个，只在本链路有效，不可路由 |
| `fc00::/7` | 唯一本地 | 相当于 IPv4 的私有地址，实践中用 `fd00::/8` |
| `ff00::/8` | 组播 | 取代了 IPv4 的广播 |
| `::1/128` | 回环 | 相当于 `127.0.0.1` |
| `::/128` | 未指定 | 还没配好地址时用，DAD 会用到 |
| `::ffff:0:0/96` | IPv4 映射 | 在 IPv6 socket 上表示一个 IPv4 对端 |

### 三种通信方式，没有广播

IPv4 有单播、广播、组播。IPv6 去掉了广播，换成单播、任播、组播：

- **单播**：一对一。
- **组播**：一对一组。`ff02::1` 是所有节点，`ff02::2` 是所有路由器。想让全网段都听见，发到 `ff02::1` 就行，效果和广播类似但目标明确。
- **任播**：地址形式和单播一样，但配在多台设备上，路由把包送到路由意义上最近的那台。DNS 根服务器就是这么部署的。

去掉广播的收益在下一节的 NDP 里体现：广播会强制同网段每张网卡都收下这个帧、交给内核判断，组播则可以在网卡硬件层就过滤掉。

## 3. 基本首部：固定 40 字节

![[图片/SVG/3_7_7_8_3_1.svg|900]]

| 字段 | 宽度 | 说明 |
|---|---|---|
| Version | 4 位 | 固定填 6 |
| Traffic Class | 8 位 | 对应 IPv4 的 DSCP + ECN |
| Flow Label | 20 位 | IPv4 没有。标记同一条流，让路径上的设备把它们按同一策略处理 |
| Payload Length | 16 位 | **不含**这 40 字节基本首部，但**含**所有扩展首部 |
| Next Header | 8 位 | 下一个首部是什么，兼作扩展首部链的指针 |
| Hop Limit | 8 位 | 就是改了名的 TTL，每跳减 1 |
| Source / Destination | 各 128 位 | 源、目的地址 |

三个删掉的字段值得单独说：

**IHL 没了**，因为长度固定 40 字节，不需要再说明。可变的部分全部挪进扩展首部。

**Header Checksum 没了**。IPv4 每跳都要重算校验和，是转发路径上一笔实打实的开销。IPv6 认为这层校验是冗余的：下面链路层的 FCS 会校验整个帧，上面 TCP 和 UDP 的校验和会覆盖负载，中间再算一遍收益不大。代价是 IPv6 下 **UDP 的校验和从可选变成必填**，因为没有别的东西兜底了。

**分片三件套没了**（Identification、Flags、Fragment Offset）。它们搬进了 Fragment 扩展首部，而且只有源主机能用。

> [!warning] Payload Length 的口径和 IPv4 不一样
> IPv4 的 Total Length 是首部加负载的总长；IPv6 的 Payload Length 不包含基本首部。抓包算长度时容易差 40 字节。

## 4. 扩展首部：把可变部分挂成一条链

IPv4 的 Options 长在首部里，导致首部长度可变，每台路由器都得解析 IHL 才知道首部到哪结束。IPv6 把这些东西全部挪出去，串成一条链：

```
IPv6 基本首部          Next Header = 44
  └─ Fragment 首部     Next Header = 6
       └─ TCP 首部     ...
```

每个首部的 Next Header 字段说明紧跟在它后面的是什么。链的末端是传输层首部，此时 Next Header 填的就是传输层的协议号。

| Next Header 值 | 内容 |
|---|---|
| 0 | Hop-by-Hop Options，沿途每个节点都可能要看 |
| 43 | Routing，指定途经的节点 |
| 44 | Fragment，源主机分片时用 |
| 50 / 51 | ESP / AH，IPsec |
| 60 | Destination Options，只有目的主机看 |
| 6 / 17 / 58 | TCP / UDP / ICMPv6，链到这里就结束了 |
| 59 | 后面没有首部了，也没有负载 |

这个编号空间和 IPv4 的 Protocol 字段是同一套（IANA 维护的 Protocol Numbers），所以 TCP 在两边都是 6。

设计上的好处是：路由器只关心 Hop-by-Hop Options，其余扩展首部一眼扫过去就能跳过，不用逐个解析。代价是链可以任意长，某些中间设备为了省事直接丢掉带扩展首部的包，实践中这类兼容性问题不少。

---

## 5. 分片：路由器不干了

IPv6 路由器**不对数据报做分片**。包比出口链路的 MTU 大，路由器就丢弃它，回一个 ICMPv6 Packet Too Big（Type 2），报文里带上自己这一跳的 MTU。

这等于把 IPv4 里可选的路径 MTU 发现变成了强制流程：源主机必须自己发现路径 MTU，然后要么把数据切小，要么用 Fragment 扩展首部自己分片。IPv6 规定链路的最小 MTU 是 **1280 字节**，所以最坏情况下按 1280 发总是能通。

好处是路由器的转发路径变简单了，不用维护分片状态。坏处和 IPv4 一样：**把 ICMPv6 全部封掉就得到一个 PMTU 黑洞**，而且比 IPv4 更严重——IPv4 至少路由器还能替你分片，IPv6 连这个后路都没有。

```bash
ping -6 -M do -s 1232 -c 1 2001:db8::1     # 1232 + 8 ICMPv6 + 40 IPv6 = 1280
```

## 6. NDP：ARP 的活它全包了

IPv6 不使用 [[7.8.4 ARP|ARP]]。邻居解析、路由器发现、地址冲突检测这一整套工作交给 NDP（Neighbor Discovery Protocol），而 NDP 的所有报文都是 [[7.8.5 ICMP与ICMPv6|ICMPv6]]。

![[图片/SVG/3_7_7_8_3_2.svg|900]]

### 五种报文

| 报文 | Type | 谁发给谁 | 用途 |
|---|---|---|---|
| Router Solicitation | 133 | 主机 → 所有路由器组播 | 我刚上线，请立刻通告 |
| Router Advertisement | 134 | 路由器 → 所有节点组播 | 前缀、默认网关、MTU、是否用 DHCPv6 |
| Neighbor Solicitation | 135 | 求解方 → 被请求节点组播 | 谁是这个地址，你的 MAC 是多少 |
| Neighbor Advertisement | 136 | 被问方 → 单播回去 | 是我，MAC 在这 |
| Redirect | 137 | 路由器 → 主机单播 | 你该走另一个下一跳，它离目标更近 |

对比 ARP 就能看出差距：ARP 只做地址解析一件事，默认网关得靠 DHCP 或手工配；NDP 把路由器发现、地址自动配置、地址冲突检测、邻居可达性检测全都包了。

### 目的地址是算出来的

ARP 请求发广播，同网段每张网卡都得收下这个帧交给内核判断。NDP 的 NS 发组播，目的地址由被查询的 IPv6 地址算出来：

1. 取目标地址的**最低 24 位**；
2. 拼在固定前缀 `ff02::1:ff00:0/104` 后面，得到**被请求节点组播地址**；
3. 映射成链路层组播 MAC：前 16 位固定 `33:33`，后 32 位照抄组播地址的末 32 位。

图 C 里 `2001:db8::a1b2:c3d4` 的低 24 位是 `b2:c3d4`，组播地址就是 `ff02::1:ffb2:c3d4`，MAC 是 `33:33:ff:b2:c3:d4`。两台主机的低 24 位撞车的概率很低，所以绝大多数情况下只有目标那张网卡会收下，其余在硬件过滤阶段就丢了。

### DAD 和 NUD

**重复地址检测（DAD）**：接口配好一个地址后，先不能用，要发一个 NS 去问「这个地址有人在用吗」，源地址填未指定地址 `::`（因为自己的地址还没生效）。等一小段时间没人回 NA，地址才转为可用。

**邻居不可达检测（NUD）**：邻居表项不是配了就永久有效。Linux 的 `ip neigh` 会显示 `REACHABLE`、`STALE`、`DELAY`、`PROBE`、`FAILED` 这些状态，长时间没通信的表项会转成 STALE，再次要用时先探测一下对方还在不在。

> [!warning] 封 ICMPv6 等于关网
> IPv4 里把 ICMP 全丢掉，后果是 `ping` 不通、路径 MTU 发现失效，但基本通信还在。IPv6 里 NDP 建立在 ICMPv6 上，全丢掉的后果是：解析不出邻居的 MAC、收不到 RA 因此拿不到前缀和默认网关、做不了 DAD。网络直接不可用。防火墙规则必须放行 133–137 这几个类型。

## 7. 地址配置与迁移

### SLAAC：不需要 DHCP 服务器

主机上线后发一个 RS，路由器回 RA。RA 里带着网段前缀（通常是个 /64）和自己的地址。主机把前缀和自己生成的 64 位接口 ID 一拼，就得到一个可用地址，默认网关就是发 RA 的那台路由器。整个过程不需要任何服务器。

接口 ID 的来源有两种：

- **EUI-64**：从网卡 MAC 推导。缺点是地址里嵌着 MAC，换个网络也能被追踪。
- **随机生成**：RFC 7217 的稳定隐私地址，或 RFC 4941 的临时地址。现代系统默认走这条路，所以 `ip -6 addr` 里常能看到一个稳定地址加若干个临时地址。

RA 里的 M 和 O 两个标志位决定要不要再去找 DHCPv6：M 置位表示地址也从 DHCPv6 拿，O 置位表示只从 DHCPv6 拿 DNS 之类的附加信息。

### 双栈与程序怎么写

迁移期的常规做法是双栈：同一台机器同时配 IPv4 和 IPv6，能走 IPv6 就走，不能就退回 IPv4。这对程序的要求是**不要把地址族写死**。

```cpp
addrinfo hints{};
hints.ai_family   = AF_UNSPEC;      // 关键：不指定 v4 还是 v6
hints.ai_socktype = SOCK_STREAM;

addrinfo* raw = nullptr;
if (::getaddrinfo("example.com", "80", &hints, &raw) != 0) { /* 处理错误 */ }

// getaddrinfo 分配的链表必须用 freeaddrinfo 释放，交给 unique_ptr 管
std::unique_ptr<addrinfo, decltype(&::freeaddrinfo)> res{raw, &::freeaddrinfo};

for (addrinfo* p = res.get(); p != nullptr; p = p->ai_next) {
    // 依次尝试，连上一个就停
}
```

三点解释：

- `AF_UNSPEC` 让 `getaddrinfo()` 把 IPv4 和 IPv6 的结果都返回，形成一条链表。写死 `AF_INET` 或还在用 `gethostbyname()`，程序就永远连不上纯 IPv6 的服务。
- 返回的链表是库分配的，必须 `freeaddrinfo()`。中途 `return` 或抛异常就漏了，所以套一个带自定义删除器的 `unique_ptr`，让释放跟着作用域走。
- **必须遍历整条链表**，而不是只试第一项。第一项可能是个 IPv6 地址而本机没有 IPv6 出口，此时只有回退到后面的 IPv4 项才连得上。浏览器的做法更激进，IPv4 和 IPv6 同时发起、谁先成功用谁，这套策略叫 Happy Eyeballs（RFC 8305）。

服务端这边，Linux 的 `net.ipv6.bindv6only` 默认是 0，意味着一个绑到 `::` 的 `AF_INET6` socket **同时也能接收 IPv4 连接**，对端地址会以 IPv4 映射地址的形式出现（`::ffff:192.168.1.10`）。要改这个行为就设 `IPV6_V6ONLY`：

```c
int on = 1;
setsockopt(fd, IPPROTO_IPV6, IPV6_V6ONLY, &on, sizeof(on));   // 只收 IPv6
```

两个书写上的坑：

- **地址和端口一起写要加方括号**：`[2001:db8::1]:8080`，否则冒号分不清是地址的一部分还是端口分隔符。
- **链路本地地址必须带作用域**：`fe80::1%eth0`。同一个 `fe80::1` 可以出现在多张网卡上，不指定接口内核不知道从哪发。`sockaddr_in6` 里对应的字段是 `sin6_scope_id`。

## 8. Linux 观察与抓包

```bash
ip -6 addr                     # IPv6 地址，注意每个接口都有一个 fe80:: 开头的
ip -6 route                    # IPv6 路由表
ip -6 neigh                    # 邻居表，NDP 学到的映射
ip -6 route get 2001:db8::1    # 对这个目标的决策
sysctl net.ipv6.conf.eth0.accept_ra    # 是否接受 RA
```

`ip -6 addr` 的输出里，链路本地地址后面会标 `scope link`，全局地址标 `scope global`。临时地址会额外标 `temporary`。

抓 NDP：

```bash
sudo ip -6 neigh flush all
sudo tcpdump -i eth0 -n icmp6 &
ping -6 -c 1 <同网段 IPv6 地址>
```

会看到 `neighbor solicitation` 和 `neighbor advertisement` 各一条，然后才是 echo request 和 reply，顺序和 [[7.8.0 Ethernet、IP、ARP与ICMP总览|总览]] 里 ARP 那张图完全对应。

看默认网关是怎么来的：

```bash
sudo tcpdump -i eth0 -n 'icmp6 && ip6[40] == 134'    # 只抓 RA
```

`ip6[40]` 取的是 IPv6 基本首部之后的第一个字节，也就是 ICMPv6 的 Type 字段（前提是没有扩展首部）。抓到一条 RA，里面的前缀和源地址就是这台机器 IPv6 地址与默认网关的来源。

## 9. IPv4 与 IPv6 对比

| 对比项 | IPv4 | IPv6 |
|---|---|---|
| 地址长度 | 32 位 | 128 位 |
| 基本首部 | 20–60 字节可变 | 固定 40 字节 |
| 首部字段数 | 13 | 8 |
| 首部校验和 | 有，每跳重算 | 没有，交给链路层和传输层 |
| UDP 校验和 | 可选 | 必填 |
| 路由器分片 | 会，除非置了 DF | 不会，只丢包并回 Packet Too Big |
| 最小 MTU | 68 字节，主机须能重组 576 | 1280 字节 |
| 广播 | 有 | 没有，用组播 `ff02::1` 代替 |
| 邻居解析 | ARP，独立 EtherType `0x0806` | NDP，属于 ICMPv6 |
| 地址自动配置 | 靠 DHCP | SLAAC 自带，DHCPv6 可选 |
| 跳数字段 | TTL | Hop Limit，只是改了名 |
| 长度字段口径 | Total Length 含首部 | Payload Length 不含基本首部 |
| 可选项 | 首部里的 Options | 独立的扩展首部链 |
| EtherType | `0x0800` | `0x86DD` |

## 10. 常见误区

- **`::` 只能出现一次。** 出现两次就无法唯一还原成 128 位。
- **IPv6 没有广播，但有 `ff02::1`。** 效果类似，机制不同：组播能在网卡硬件层过滤。
- **链路本地地址不可路由。** 它只在本条链路上有效，跨路由器就没意义，所以用它通信必须指定 `%接口名`。
- **Payload Length 不含基本首部但含扩展首部。** 和 IPv4 的 Total Length 口径不一样。
- **封 ICMPv6 会让 IPv6 直接不可用**，不像 IPv4 那样只是 `ping` 不通。
- **IPv6 不是「更长的 IPv4」。** 没有 A/B/C 类地址那套历史，子网基本统一 /64，地址配置方式也换了。
- **双栈主机不会自动选对协议。** 程序用 `AF_UNSPEC` 并遍历 `getaddrinfo()` 的结果，选择才真正发生。

## 11. 自测问题

1. 为什么阻断全部 ICMPv6 会让 IPv6 出现严重故障？
2. IPv6 路由器遇到过大的数据报时怎样处理？
3. NDP 相比 ARP 还承担了哪些额外职责？
4. `2001:db8::a1b2:c3d4` 对应的被请求节点组播地址和组播 MAC 分别是什么？

> [!success]- 参考答案
> 1. NDP 建立在 ICMPv6 上。封掉之后：解析不出邻居 MAC，包封不成帧；收不到 RA，拿不到前缀和默认网关；做不了 DAD；收不到 Packet Too Big，路径 MTU 发现失效。基本通信直接断掉。
> 2. 丢弃，并回一个 ICMPv6 Packet Too Big（Type 2），报文里带上自己这一跳的 MTU。IPv6 路由器不替源主机分片，分片只能由源主机用 Fragment 扩展首部做。
> 3. 路由器发现（RS / RA）、无状态地址自动配置所需的前缀通告、重复地址检测（DAD）、邻居不可达检测（NUD）、重定向（Redirect）。ARP 只做地址解析。
> 4. 取低 24 位 `b2:c3d4`，拼上前缀得到 `ff02::1:ffb2:c3d4`；MAC 是 `33:33` 加上组播地址末 32 位，即 `33:33:ff:b2:c3:d4`。

## 关键要点

1. **地址变长只是表面，真正的改动是砍掉了可变首部、校验和与路由器分片。** 三样东西都是为了让转发路径变简单。
2. **`::` 只能出现一次，子网基本统一 /64。** 前者是解析要求，后者是 SLAAC 的要求。
3. **Payload Length 不含基本首部。** 这是抓包时最容易算错 40 字节的地方。
4. **NDP 是 ICMPv6 的一部分，职责比 ARP 大得多。** 邻居解析、路由器发现、DAD、NUD 全在里面，所以 ICMPv6 不能封。
5. **NS 的目的地址是算出来的**：低 24 位拼上 `ff02::1:ff00:0/104`，再映射成 `33:33` 开头的 MAC。这就是组播能替掉广播的原因。
6. **路由器不分片，最小 MTU 1280。** PMTU 黑洞在 IPv6 下没有退路，因为没人能替你把包切小。
7. **程序里用 `AF_UNSPEC` 并遍历 `getaddrinfo()` 的返回链表。** 写死 `AF_INET` 的代码在纯 IPv6 网络里连不上。

# 7.7 套接字（Socket）

## 1. 简介

套接字的价值不在于「能上网」，而在于**把四套完全不同的通信方式收进了同一个文件描述符**。TCP 连接、UDP 数据报、本机进程间通信、原始 IP 包，拿到手都是一个 `int`，都能用 `read()` / `write()` / `close()` 操作，都能丢进 `epoll` 里等。

它位于应用层和传输层之间：向上给出一个 fd，向下根据你创建时的参数选择具体协议。

![[图片/SVG/3_7_7_7_1.svg|900]]

图的右半部分是这句话的技术含义：`socket()` 返回的 fd 在内核里指向一个 `struct file`，`struct file` 指向 `struct socket`，再往下是 `struct sock`。序号、窗口、重传队列、收发缓冲区全都挂在 `struct sock` 上。因为最外层是 `struct file`，所有基于 fd 的系统调用自然就都能用在它身上。

由此推出几条平时会用到的结论：

- `read()` / `write()` / `close()` 直接可用，`send()` / `recv()` 只是多了一个 `flags` 参数。
- `select` / `poll` / `epoll` 能监听它，因为它们监听的就是 fd。
- `fork()` 之后父子进程共享同一个 `struct file`，引用计数加一，所以两边都要 `close()` 才真正关闭连接。
- `write()` 返回只代表数据进了发送缓冲区，不代表对方收到了。

## 2. socket 函数

```c
#include <sys/types.h>
#include <sys/socket.h>

int socket(int domain, int type, int protocol);
```

| 参数 | 说明 |
|:---|:---|
| `domain` | 地址族，决定用哪一套地址格式和协议族 |
| `type` | 套接字类型，决定通信语义（字节流还是数据报） |
| `protocol` | 具体协议，通常填 0 |

- **成功**：返回一个非负整数，即套接字文件描述符
- **失败**：返回 -1，并设置 `errno`

### 2.1 domain 与 type 的组合

前面那张图的 C 区列出了常见组合。三个参数不是自由搭配的，是 `domain` + `type` 基本就确定了协议：

| domain | 含义 |
|:---|:---|
| `AF_INET` | IPv4 |
| `AF_INET6` | IPv6 |
| `AF_UNIX` / `AF_LOCAL` | 本机进程间通信，走内存不走网卡 |

| type | 含义 |
|:---|:---|
| `SOCK_STREAM` | 面向连接的字节流，配合 `AF_INET` 就是 TCP |
| `SOCK_DGRAM` | 无连接的数据报，配合 `AF_INET` 就是 UDP |
| `SOCK_RAW` | 原始套接字，自己构造 IP 载荷，需要 root |

**`protocol` 填 0 的含义是「这个组合只有一种合理选择，你来定」。** 只有 `SOCK_RAW` 这类一个 type 对应多种协议的场合才必须写明，比如 `socket(AF_INET, SOCK_RAW, IPPROTO_ICMP)`，`ping` 就是这么实现的。

> [!note] `AF_` 和 `PF_` 用哪个都行
> 历史上打算用 `PF_`（Protocol Family）表示协议族、`AF_`（Address Family）表示地址族，一个协议族可以支持多种地址格式。这个设计最终没有实现，Linux 的头文件里直接写着 `#define PF_INET AF_INET`，两组宏取值完全相同。新代码统一用 `AF_` 即可。

### 2.2 示例

```c
int sock = socket(AF_INET, SOCK_STREAM, 0);   // IPv4 上的 TCP
if (sock < 0) {
    perror("socket");
    return -1;
}
```

`perror()` 会把 `errno` 翻译成可读的错误信息。socket 系列函数失败时都要看 `errno`，光看返回值 -1 定位不了原因。

## 3. 地址结构体

### 3.1 为什么要那个丑陋的强制转换

几乎所有 socket 函数的地址参数都长这样：

```c
int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
```

而你手里拿的是 `struct sockaddr_in`，所以每次都得写 `(struct sockaddr*)&addr`。原因是 BSD socket API 定型于 1983 年，那时 C 语言还没有普及 `void*`，要表达「这里可以传多种地址结构」，只能定义一个通用结构体让大家往它上面转：

```c
struct sockaddr {
    sa_family_t  sa_family;    // 地址族，2 字节
    char         sa_data[14];  // 地址数据，具体格式由 sa_family 决定
};                             // 共 16 字节
```

内核收到指针后先读头两个字节的 `sa_family`，知道是 `AF_INET` 就按 `sockaddr_in` 解释，是 `AF_UNIX` 就按 `sockaddr_un` 解释。`addrlen` 参数则告诉内核这块内存有多大，防止越界。

如果今天重新设计这套 API，参数类型会是 `const void*`，转换就不需要了。

### 3.2 sockaddr_in

```c
struct sockaddr_in {
    sa_family_t    sin_family;  // 固定为 AF_INET
    in_port_t      sin_port;    // 端口号，网络字节序
    struct in_addr sin_addr;    // IP 地址
    char           sin_zero[8]; // 填充，让它和 sockaddr 一样大
};

struct in_addr {
    in_addr_t s_addr;           // 32 位 IPv4 地址，网络字节序
};
```

`sin_zero` 不承载任何信息，它存在的唯一目的是把 `sockaddr_in` 凑到 16 字节，和 `sockaddr` 大小相同，这样两者之间的指针转换才安全。

> [!warning] IPv6 装不进 sockaddr
> `sockaddr_in6` 是 28 字节，塞不进 16 字节的 `sockaddr`。要写同时支持两种协议的代码，用 `struct sockaddr_storage`（128 字节，对齐要求足够宽），它能装下任何地址族的结构体。`accept()` 的输出参数尤其应该用它。

### 3.3 字节序转换

不同 CPU 的多字节整数在内存里的排列顺序不同（x86 和 ARM 常见的是小端），网络传输统一约定用**大端**，也叫网络字节序：

```c
#include <arpa/inet.h>

uint16_t htons(uint16_t hostshort);  // 主机 → 网络（16 位）
uint32_t htonl(uint32_t hostlong);   // 主机 → 网络（32 位）
uint16_t ntohs(uint16_t netshort);   // 网络 → 主机（16 位）
uint32_t ntohl(uint32_t netlong);    // 网络 → 主机（32 位）
```

记法：`h` = host，`n` = network，`s` = short（16 位，端口号），`l` = long（32 位，IPv4 地址）。

在大端机器上这四个函数是空操作，但**照样要写**。省掉它们的代码在 x86 上能跑，换到别的架构就崩，而且这类 bug 在测试环境很难暴露。

`sin_family` 不需要转换，因为它是给本机内核看的，不上网线。需要转换的只有 `sin_port` 和 `sin_addr` 这两个会出现在报文里的字段。

## 4. bind 函数

```c
#include <sys/socket.h>

int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
```

| 参数 | 说明 |
|:---|:---|
| `sockfd` | `socket()` 返回的描述符 |
| `addr` | 要绑定的地址和端口 |
| `addrlen` | 地址结构体的大小 |

成功返回 0，失败返回 -1 并设置 `errno`。

### 4.1 示例

```c
int sockfd = socket(AF_INET, SOCK_STREAM, 0);
if (sockfd < 0) { perror("socket"); return -1; }

int on = 1;
setsockopt(sockfd, SOL_SOCKET, SO_REUSEADDR, &on, sizeof(on));  // 必须在 bind 之前

struct sockaddr_in addr;
memset(&addr, 0, sizeof(addr));            // ① 整块清零
addr.sin_family = AF_INET;                 // ② IPv4
addr.sin_port   = htons(8080);             // ③ 端口转网络字节序
addr.sin_addr.s_addr = htonl(INADDR_ANY);  // ④ 监听所有网卡

if (bind(sockfd, (struct sockaddr*)&addr, sizeof(addr)) < 0) {
    perror("bind");
    close(sockfd);                         // ⑤ 失败也要关
    return -1;
}
```

逐条说明为什么这么写：

① **`memset` 不是可有可无的形式**。局部变量 `addr` 里是栈上的垃圾数据，其中包括 `sin_zero` 那 8 个字节。虽然内核不解释 `sin_zero`，但有些代码路径会比较整个结构体（比如判断两个地址是否相同），残留垃圾会导致误判。而且用 `sockaddr_storage` 时，未清零的高位字节会被当成地址内容。清零是最省事的做法。

③ `8080` 这个字面量在 x86 上是小端，不转换的话对端看到的是 `0x9020` = 36896。

④ `INADDR_ANY` 就是 `0.0.0.0`，含义是「所有本机网卡」。绑定具体 IP（比如 `127.0.0.1`）会让服务只在那一个接口上可达，这是容器里「本机能连、外面连不上」最常见的原因。虽然 `INADDR_ANY` 的值是 0，转不转字节序结果都一样，但还是要写 `htonl()`，保持代码一致。

⑤ `bind` 失败后 fd 仍然是打开的，不关就泄漏了。C++ 里更好的做法是把 fd 交给 RAII 对象管理：

```cpp
class Fd {
public:
    explicit Fd(int fd) noexcept : fd_(fd) {}
    ~Fd() { if (fd_ >= 0) ::close(fd_); }
    Fd(const Fd&) = delete;
    Fd& operator=(const Fd&) = delete;
    Fd(Fd&& o) noexcept : fd_(std::exchange(o.fd_, -1)) {}
    int get() const noexcept { return fd_; }
private:
    int fd_ = -1;
};
```

这样任何一条错误返回路径都不会漏掉 `close()`，异常抛出时也一样。连接对象的完整生命周期管理见 [[13.8 连接对象生命周期与RAII]]。

> [!note] 客户端要不要 bind
> 通常不用。客户端调 `connect()` 时，内核会自动从临时端口范围里挑一个源端口。只有在需要固定源端口或指定从哪块网卡出去时才显式 `bind`。临时端口的范围和冲突问题见 [[7.3 端口与五元组]]。

## 5. 现代写法：用 getaddrinfo 代替手工填结构体

上面手工填 `sockaddr_in` 的写法只支持 IPv4，而且没法处理域名。实际项目里更推荐：

```c
struct addrinfo hints, *res;
memset(&hints, 0, sizeof(hints));
hints.ai_family   = AF_UNSPEC;      // IPv4 和 IPv6 都要
hints.ai_socktype = SOCK_STREAM;    // TCP

if (getaddrinfo("example.com", "8080", &hints, &res) != 0) { /* 处理错误 */ }

// res 是一个链表，逐个尝试直到连上
for (struct addrinfo *p = res; p != NULL; p = p->ai_next) {
    int fd = socket(p->ai_family, p->ai_socktype, p->ai_protocol);
    if (fd < 0) continue;
    if (connect(fd, p->ai_addr, p->ai_addrlen) == 0) { /* 连上了 */ break; }
    close(fd);
}
freeaddrinfo(res);   // 必须释放
```

它一次解决三件事：域名解析、IPv4 与 IPv6 通吃、多个地址逐个重试。代价是返回的链表必须用 `freeaddrinfo()` 释放，忘了就是内存泄漏。文本 IP 与二进制之间的转换函数（`inet_pton` / `inet_ntop`）见 [[10.1 套接字选项]]。

## 6. 关键要点

1. **socket 就是一个文件描述符**，所以 `read` / `write` / `close` / `epoll` 全都能用在它身上。
2. **`domain` + `type` 基本就决定了协议**，`protocol` 填 0 表示用默认的那个。
3. **强制转换成 `sockaddr*` 是 1983 年的历史包袱**，内核靠头两个字节的 `sa_family` 判断真实类型。
4. **`sin_zero` 只是填充**，作用是让 `sockaddr_in` 和 `sockaddr` 一样大。IPv6 装不下，要用 `sockaddr_storage`。
5. **`sin_port` 和 `sin_addr` 必须转网络字节序**，`sin_family` 不用，因为它不上网线。
6. **`memset` 清零、失败路径 `close`，两个都不能省**。C++ 里用 RAII 包住 fd 更可靠。
7. **新代码优先 `getaddrinfo`**，一次解决域名解析和双栈兼容。

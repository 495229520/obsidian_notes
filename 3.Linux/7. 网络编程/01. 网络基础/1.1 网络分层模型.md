# 7.1 网络分层模型

## 1. 为什么要分层

网络通信涉及多个层次的技术问题：物理信号调制、同一链路内的介质访问控制、跨网络路径寻址、端到端传输可靠性，以及应用层报文的数据解析。

若采用单体式协议设计，底层物理介质的更换（例如从以太网双绞线切换到 Wi-Fi 或光纤）将直接导致整个协议栈重构。分层设计的核心原则是**关注点分离**（Separation of Concerns）与**接口解耦**：
- **屏蔽物理与传输细节**：底层通信介质切换时，仅影响物理层与数据链路层，上层 TCP 与应用协议逻辑无需改动。
- **协议独立演进**：协议变更被限制在所属层次之内。例如从 HTTP/1.1 升级为 HTTP/2 仅改变应用层编码与多路复用，底层的 TCP 保持不变；QUIC 则在传输层引入基于 UDP 的可靠传输，上层仍复用 HTTP 语义。
- **分层故障排查**：排障时可通过分层手段快速缩小范围。`ping` 通代表三层网络可达，若目标端口连接失败则可将问题定位至四层端口监听或防火墙策略。

分层的代价是各层封装产生的协议头部开销（Header Overhead）。

## 2. OSI 参考模型（七层）

OSI（Open Systems Interconnection，开放系统互连）是 ISO 在 1984 年定稿的参考模型，把通信划分成七层。

| 层次  |  名称   | 主要功能                               | 典型协议/设备                   |
| :-: | :---: | :--------------------------------- | :------------------------ |
|  7  |  应用层  | 为应用程序提供网络服务接口                      | HTTP, FTP, SMTP, DNS      |
|  6  |  表示层  | 数据格式转换、加密解密、压缩解压                   | SSL/TLS, JPEG, ASCII      |
|  5  |  会话层  | 建立、管理和终止会话连接                       | NetBIOS, RPC              |
|  4  |  传输层  | 端到端的可靠/不可靠数据传输                     | [[2.1 TCP协议基础\|TCP]], UDP |
|  3  |  网络层  | 路由选择、逻辑寻址（[[1.2 IP地址与CIDR\|IP地址]]） | IP, ICMP, IGMP            |
|  2  | 数据链路层 | 帧的封装与解封、物理寻址（MAC地址）                | Ethernet, PPP             |
|  1  |  物理层  | 比特流传输、物理介质规范                       | 网线、光纤、中继器                 |

### 2.1 数据封装与解封装

数据发送端自顶向下逐层追加协议头（封装，Encapsulation）；接收端自底向上逐层剥离头部向上传递（解封装，Decapsulation）。通信两端对等层处理各自的数据单元，构成**对等层通信**（Peer-to-Peer Communication）。

![[图片/SVG/3_7_7_1_1.svg|1390]]

协议头部开销与有效载荷比率（Payload Ratio）：以标准以太网上的满载 TCP 数据包为例，各层协议封装如下：

```
以太网帧头 14 B + IP 头 20 B + TCP 头 20 B + 数据 1460 B + FCS 4 B = 1518 B
```

在满载状态下，协议头固定开销为 58 字节（含 FCS），占比约 3.8%。
然而协议头部大小固定，当单次传输的数据载荷极小时，协议头部的开销占比显著放大。例如在交互终端中仅发送 1 字节字符，受以太网最小帧长 64 字节限制（不足需硬件填充），有效载荷占比不足 2%。
高频小包不仅浪费链路带宽，还会增加两端协议栈的中断与解析开销。这是引入 [[8.1 Nagle算法|Nagle 算法]] 的核心工程背景：在发送端将连续的小数据写入攒成完整报文段后再送出，以极轻微的延迟换取网络吞吐与带宽利用率的提升。

> [!note] MSS 的推导关系
> MSS（最大报文段长度，Maximum Segment Size）由链路层 MTU 决定：`MSS = MTU - IP头 - TCP头`。以太网标准 MTU 为 1500 字节，扣除标准的各 20 字节头部后，MSS 通常为 1460 字节。
> 超过 MSS 的应用数据由 TCP 协议栈在传输层自动切分（Segment），不会触发 IP 层分片；而 UDP 本身不提供分段机制，若单次 `sendto()` 提交的数据加上 UDP 与 IP 头超出 MTU，便会在网络层触发 IP 分片（Fragmentation）。任何一个分片在链路中丢失，都会导致整个 UDP 数据报无法重组而全部丢弃。

## 3. TCP/IP 四层与五层模型

TCP/IP 是今天所有联网设备实际运行的协议栈。它把 OSI 的上三层合成应用层、下两层合成网络接口层，剩下四层。五层模型是教学上的折中：保留 TCP/IP 的应用层合并，但把链路层和物理层拆开，方便讲交换机和集线器的区别。

![[图片/SVG/3_7_7_1_2.svg|1390]]

| TCP/IP 层次 | 对应 OSI 层 | 主要协议 |
|:---:|:---:|:---|
| 应用层 | 应用层 + 表示层 + 会话层 | HTTP, SMTP, DNS, FTP, SSH |
| 传输层 | 传输层 | [[2.1 TCP协议基础\|TCP]], UDP |
| 网际层 | 网络层 | IP, ICMP, IGMP |
| 网络接口层 | 数据链路层 + 物理层 | 以太网, Wi-Fi, PPP |

### 3.1 五层模型的数据单元与设备

| 层次  |  名称   |               数据单元（PDU）               | 工作在该层的设备  |
| :-: | :---: | :-----------------------------------: | :-------- |
|  5  |  应用层  |             应用报文（message）             | 无（主机上的进程） |
|  4  |  传输层  | TCP 报文段（segment）/ UDP 用户数据报（datagram） | 无         |
|  3  |  网络层  |          IP 数据报（IP datagram）          | 路由器、三层交换机 |
|  2  | 数据链路层 |               帧（frame）                | 交换机、网桥、网卡 |
|  1  |  物理层  |               比特流（bit）                | 中继器、集线器   |

> [!note] 设备层级的划分依据：以处理的最高协议头部为准
> 设备工作在哪一层，取决于它转发报文时需要解析的最高协议头部。物理层设备（中继器、集线器）仅负责电信号的放大与盲泛洪，不解析任何报头；二层交换机解析至 MAC 帧头并依据 MAC 地址表定向转发；路由器与三层交换机则必须解封装并读取 IP 报头以执行路由查找。

### 3.2 表示层和会话层的功能归宿

OSI 中的表示层与会话层功能在 TCP/IP 体系中并未缺失，而是直接收敛至应用层或用户态运行库中实现：

- 数据加密：由用户态 TLS 库（如 OpenSSL）在应用层与套接字之间实现。
- 格式转换与压缩：由应用层协议头部（如 HTTP 的 `Content-Type` 与 `Content-Encoding`）协商并由应用程序解析。
- 会话生命周期维护：由业务层逻辑维持（如 HTTP Cookie、Session ID 或 Token）。

四层模型将上述逻辑交由用户空间灵活定制，使内核协议栈保持精简。

## 4. 逐跳转发：网络设备的分层处理机制

在数据传输路径中，只有通信两端的终端主机会完整执行协议栈各层的封装与解封装；中间经过的网络设备仅处理至其转发决策所需的最高层次。

![[图片/SVG/3_7_7_1_3.svg|1390]]

- **二层交换机**：仅解封装至数据链路层。读取数据帧头部的目的 MAC 地址，通过查询本地 MAC 地址表决定转发端口；上层的 IP 头部及传输层数据均作为透明载荷直接透传。
- **三层路由器**：解封装至网络层。读取 IP 头部中的目的 IP 地址，按最长前缀匹配查询路由表以决定下一跳路径。在转发前，路由器会将 TTL 递减 1、重新计算 IP 头部校验和，并使用下一跳节点的 MAC 地址重新封装以太网帧头。
- **物理层集线器**：不解析任何协议头部，仅在信号层面将接收到的比特流放大并向除接收端口外的所有端口盲目泛洪。

#### IP 寻址与 MAC 寻址的协作机制
主机在路由表查找后仅能得到下一跳节点的 IP 地址（例如网关地址 `192.168.1.1`），但底层链路层网卡只能依靠 MAC 地址组织帧发送。将逻辑 IP 地址映射为链路物理地址的关键协议是 [[7.5 ARP地址解析|ARP]]：

- **目的 IP 负责端到端寻址**：在非 NAT 的标准网络中，源 IP 与目的 IP 全程保持不变，为整条传输链路指引最终目标。
- **目的 MAC 负责逐跳传递**：每个三层节点转发时都会剥离旧帧头，重新写入下一跳节点的 MAC 地址。
- **ARP 桥接逻辑地址与物理地址**：发送节点根据下一跳 IP 查询 ARP 缓存表，获取对应的 MAC 地址后封装进二层帧头。下一跳 IP 仅在本地用于寻径和 ARP 解析，绝不会被写入外发数据包的 IP 头部。

由此形成网络寻址的基本特征：

> **源 IP 与目的 IP 地址端到端保持不变（NAT 场景除外）；源 MAC 与目的 MAC 地址在跨越每个三层节点时均被重新封装。**

```
【源主机 A】                          【路由器 R1】                         【目标主机 B】
1. CIDR 计算：不在同网段                4. 物理层接收信号
2. 查本地路由表 ──► 网关 IP             5. 二层解包：确认 Dst MAC 是自己
3. 查 ARP 表   ──► 网关 MAC            6. 上送三层：查路由表 ──► 下一跳 IP
4. 封装以太网帧 ──► 物理层发送           7. TTL-1，重算校验和
                                     8. 二层查 ARP ──► 下一跳 MAC
                                     9. 封新帧头 ──► 物理层转发 ───────► (到达目标/下一跳)
```

![[图片/SVG/3_7_7_1_4.svg|1240]]

该机制在网络排障中的直接对应：

1. **跨网段通信抓包**：在客户端抓包时，若目的 IP 为公网服务器而目的 MAC 却是本地局域网网关，此属标准转发流程，表明数据正被定向投递至网关路由。
2. **`traceroute` 路径探测**：利用 IP 头部中的 TTL 字段，从 1 开始逐次递增发包。当某跳路由器的 TTL 减至 0 时，该路由器丢弃数据包并向源端回复 ICMP 超时报文（Time Exceeded），源端便可通过该 ICMP 报文的源 IP 获知该跳节点的接口地址。

此外，TCP [[2.1 TCP协议基础#4. 三次握手|三次握手]] 属于传输层控制逻辑，而 ARP 查询、路由检索与二层帧头重写发生在下层物理转发链路中。所有握手控制报文（SYN、ACK 等）在网络中传输时，同样需要依赖上述逐跳路由与 MAC 重写机制推进。

## 5. Socket 在分层中的位置与职责划分

在网络系统编程中，[[3.1 套接字|Socket]] 接口位于用户应用层与内核网络协议栈之间的系统调用边界：

```
       业务应用逻辑           ← 应用层（用户空间）：自定义协议格式与序列化
    ────────────────────
       Socket API            ← 系统调用边界（POSIX 标准接口）
    ────────────────────
       TCP / UDP             ← 传输层（内核空间）：连接状态、可靠传输控制
       IP                    ← 网络层（内核空间）：路由选择、数据报转发
       网卡驱动与物理介质       ← 网络接口层：帧驱动、硬件收发
```

该边界界定了明确的系统职责划分：
- **内核协议栈（Socket 边界以下）**：自动维护底层通信逻辑，包括连接状态转移、丢包重传、流量控制、拥塞控制、数据校验和计算及路由决策。
- **应用层实现（Socket 边界以上）**：由开发者负责定义数据帧结构、编解码及消息边界判定。由于标准 TCP 仅提供无边界的流式（Stream）传输保障，内核并不维系应用层单次 `write()` 与对方 `read()` 的对应关系，因此上层必须通过固定长度、特定分隔符或显式长度字段来划分数据包，即解决 [[4.7 TCP的粘包和拆包|粘包与拆包]] 问题。

## 6. 关键要点

1. **分层实现关注点解耦，代价是头部开销**。以太网标准满载时头部开销约占 3.8%，而在极小载荷下头部与填充占比可达 98%，这是 Nagle 算法合并小包的工程动因。
2. **中间设备依据转发需求按层截断处理**。二层交换机解析至 MAC 帧头，三层路由器解析至 IP 报头，只有通信端点主机才会完整处理至传输层与应用层。
3. **IP 端到端不变，MAC 逐跳重新封装**。跨网段抓包中目的 MAC 指向默认网关、`traceroute` 依赖 TTL 逐跳触发 ICMP 超时，均源于此机制。
4. **网络设备的分层取决于其解析的最高协议头部**。物理层集线器不解析任何报头，仅执行电信号盲泛洪；路由器必须读取并比对 IP 头部。
5. **Socket 位于用户态与内核协议栈的边界**。内核保障传输层的可靠流式传输，应用层负责定义消息格式与处理流式数据的粘包与拆包。

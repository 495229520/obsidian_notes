# 7.2 IP 地址与 CIDR

## 1. 一个 IP 地址就是一个 32 位整数

IPv4 地址是 **32 位无符号整数**，占 4 字节。人读的时候把它按字节切成四段，每段用十进制写出来，段间用点分隔，这叫**点分十进制**。所以每段的取值范围是 0 到 255，地址总数是 2³² = 约 43 亿个。

```
192      .       168     .      1        .        1
11000000      10101000      00000001       00000001
└──────────── 0xC0A80101 = 3232235777 ────────────┘
```

写代码时这一点很实用：结构体 `sockaddr_in` 里的 `sin_addr.s_addr` 就是这个 32 位整数，只不过必须按**网络字节序**（大端）存放。文本形式和整数形式之间用 `inet_pton()` / `inet_ntop()` 转换，具体见 [[3.1 套接字]] 和 [[3.2 套接字选项]]。

---

## 2. 分类地址（classful，历史方案）

早期的做法是看首字节的前导位，把地址空间切成五类，网络号和主机号的分界点固定在第 8、16、24 位。

![[图片/SVG/3_7_7_2_1.svg|1390]]

| 类别  |  首字节范围  | 网络位 | 主机位 | 可用网络数 | 每网可用主机数 | 用途    |
| :-: | :-----: | :-: | :-: | :---- | :------ | :---- |
|  A  |  1-126  |  8  | 24  | 126 | 16 777 214 | 大型网络  |
|  B  | 128-191 | 16  | 16  | 16 384 | 65 534 | 中型网络  |
|  C  | 192-223 | 24  |  8  | 2 097 152 | 254 | 小型网络  |
|  D  | 224-239 |  -  |  -  | - | - | 组播    |
|  E  | 240-255 |  -  |  -  | - | - | 保留/实验 |

几个容易记错的地方：

- **A 类是 1 到 126，不是 1 到 127**。127.0.0.0/8 整段被回环占用，所以从 A 类里扣掉了。
- **E 类的前导位是 1111，不是 11110**。地址范围 240.0.0.0 到 255.255.255.255，至今没有分配用途；其中末尾的 255.255.255.255 是受限广播地址。
- **主机数要减 2**：主机位全 0 的那个地址表示网段本身，主机位全 1 的那个是广播地址，两者都不能配给主机。

### 2.1 分类地址为什么被淘汰

粒度太粗。一个需要 300 台主机的组织，C 类只有 254 个不够用，只能申请 B 类，一下子拿到 65534 个，剩下 6 万多个地址就此浪费。1993 年 RFC 1519 引入 CIDR 之后，分类地址就不再用于实际分配了。

今天还在说「A 类地址」「C 类私有地址」，是沿用称呼，不是说路由器还按类别解析地址。

## 3. CIDR：网络位有多长，由掩码决定

CIDR（Classless Inter-Domain Routing，无类域间路由）把网络号和主机号的分界从固定位置改成**可变位置**，用**子网掩码**来标记分界在哪。掩码里连续的 1 对应网络位，其后全 0 对应主机位，写成 `/n` 的形式，n 就是 1 的个数。

判断两个地址在不在同一网段，就是拿各自的 IP 和掩码做按位与，比较得到的网络号。

![[图片/SVG/3_7_7_2_2.svg|1390]]

从图里的演算可以直接读出三个结论：

- **网络号** = IP AND 掩码，把主机位清零得到。
- **广播地址** = 把主机位全置 1 得到。
- **可用主机数** = 2^(主机位数) − 2。

> [!warning] 「以 0 结尾的是网段」这句话是错的
> 判断依据是**主机位是否全 0**，和点分十进制的最后一段是不是 0 没有关系。两个反例：
>
> - 在 `10.0.0.0/8` 里，主机位是后 24 位。地址 `10.1.2.0` 的主机位是 `0.1.2.0`，不全为 0，是一个完全正常的主机地址。
> - 在 `192.168.1.128/25` 里，网络号是 `192.168.1.128`，它的末段是 128 而不是 0。
>
> 同理，「以 255 结尾的是广播地址」也只在 /24 及更短的前缀下才碰巧成立。

掩码必须是「前面一串连续的 1，后面全是 0」，所以只有 33 种合法掩码（/0 到 /32）。`255.255.0.255` 这种交错的形式在 IPv4 里是非法的，配置时会被拒绝。

## 4. 特殊地址段

这些地址段有专门的语义，不能当普通主机地址随便使用：

| 地址段 | 名称 | 用途 | 能配给主机吗 |
|:---|:---|:---|:---|
| `0.0.0.0/8` | 本网络 | 主机还没拿到地址时用作源地址 | 否 |
| `0.0.0.0` | 未指定地址 | 服务端 bind 时表示监听所有网卡 | 否 |
| `10.0.0.0/8` | A 类私有 | 内网，出网需 NAT | 是 |
| `100.64.0.0/10` | 运营商级 NAT | ISP 内部地址（RFC 6598） | 否 |
| `127.0.0.0/8` | 回环 | 本机进程间通信，常用 127.0.0.1 | 整段仅本机可见 |
| `169.254.0.0/16` | 链路本地 | DHCP 失败时自动配置（RFC 3927） | 自动获得 |
| `172.16.0.0/12` | B 类私有 | 内网，出网需 NAT | 是 |
| `192.168.0.0/16` | C 类私有 | 内网，出网需 NAT | 是 |
| `224.0.0.0/4` | 组播 | 一对多分发 | 否 |
| `240.0.0.0/4` | 保留（E 类） | 未分配 | 否 |
| `255.255.255.255` | 受限广播 | 只在本网段广播，路由器不转发 | 否 |

私有地址段（RFC 1918）的三段容量差别很大：`10.0.0.0/8` 有 1600 多万个地址，`172.16.0.0/12` 有 100 多万，`192.168.0.0/16` 有 6 万多。家用路由器默认用 `192.168.x.x`，企业内网多用 `10.x.x.x`。

私有地址在公网上不可路由。内网主机访问外网时，出口设备做 **NAT**：把源地址换成自己的公网地址、源端口换成一个临时端口，并在表里记下这条映射；回包按端口反查回原来的内网主机。所以一个公网 IP 能带整个内网上网，代价是外部无法主动发起连接进来（这正是 [[5.4 UDP穿透|UDP 穿透]] 要解决的问题）。

## 5. 广播与组播

### 5.1 广播

广播是「一发全收」：数据包发到网段内所有主机。目的地址有两种写法，`255.255.255.255` 是受限广播（路由器不转发），`192.168.1.255` 这种是定向广播（本网段的广播地址）。

ARP 就靠广播工作：主机要发包给同网段的某个 IP，但不知道对方的 MAC，于是广播一句「谁是 192.168.1.5」，网段内所有主机都收到，只有匹配的那台回应。

### 5.2 广播风暴

广播的代价是每台主机都必须处理每一个广播帧，哪怕内容与自己无关。当广播帧的数量失控，整个网段就会瘫痪，这一现象称为**广播风暴**。其主要成因有三类：

- **二层环路（最严重）**：交换机收到广播帧时，会向除接收端口外的所有端口复制泛洪。如果拓扑中存在环路，同一个广播帧就会在环路上被反复复制转发。由于以太网帧头**缺乏 TTL 机制**，报文无法自行消亡，帧数量随环路循环呈指数级增长，数秒内即可打满物理带宽。
- **ARP 泛滥**：当网段内接入主机数量过多，或遭到 ARP 欺骗攻击时，ARP 广播请求速率大幅攀升，严重挤占正常的单播带宽。
- **主机中断与协议栈过载**：主机网卡硬件仅能通过 MAC 地址比对过滤不匹配的单播帧（直接在网卡芯片硬件丢弃，CPU 零开销）。而广播帧目的 MAC 为 `ff:ff:ff:ff:ff:ff`，网卡判定为必收报文，必须触发硬件中断（IRQ）并通过 DMA 将报文推入主机内存。当广播泛滥时，网段内所有主机的 CPU 都会被迫满载处理中断与报文解析，导致业务全面卡死。

### 5.3 广播防御的三道防线：STP、VLAN 与 Storm Control

应对二层广播泛滥，网络工程中形成了“破环治本、切域控界、端口熔断”的三层梯次防御体系（STP / RSTP 深入原理、选举算法与快速收敛见 [[7.7 生成树协议 STP与RSTP]]）。

![[图片/SVG/3_7_7_2_4.svg|1390]]

#### 1. 生成树协议（STP / RSTP）：拓扑破环（治本）
- **物理成环的工程初衷**：在企业网与数据中心，为防止单根网线老化损坏或单台交换机故障导致单点瘫痪，交换机之间通常会接入多条冗余物理链路，客观上构成了物理闭环。
- **动态破环机制**：
  - 运行 STP（IEEE 802.1D）或 RSTP（IEEE 802.1w）的交换机之间通过周期性交换 **BPDU**（Bridge Protocol Data Unit，桥协议数据单元）来协商拓扑结构。
  - 全网选举出唯一的**根交换机**（Root Bridge），其余交换机根据到根桥的链路开销（Path Cost）计算出最短无环路径，选定根端口（Root Port, RP）与指定端口（Designated Port, DP）。
  - 所有多余的、会导致闭环形成的冗余端口被置为**阻塞状态**（STP 的 Blocking / RSTP 的 Discarding）。
- **阻塞端口的行为特征**：
  - **不转发普通业务数据**：切断广播帧在环路中的循环路径。
  - **不学习源 MAC 地址**：防止广播风暴引发的 MAC 地址表频繁震荡（MAC Thrashing）。
  - **持续监听 BPDU 控制报文**：时刻监控网络拓扑健康状态。
- **自动容灾切换**：当正在转发的主链路中断时，阻塞端口因超时收不到 BPDU 获知拓扑变化，自动在极短时间（RSTP 为毫秒级，经典 STP 需 30~50 秒）转换为转发状态（Forwarding），无需人工干预即可恢复网络连通性。

#### 2. 虚拟局域网（VLAN）：切分广播域（控域）
- **隔离广播域的必要性**：单台交换机或默认二层网络是一个扁平的大广播域。当网络规模扩大到数百上千台主机时，日常的 ARP、DHCP 广播流量就会严重影响网络质量。
- **802.1Q 标签机制**：
  - 交换机在标准以太网帧的源 MAC 与类型字段之间插入 4 字节的 **802.1Q Tag**，其中包含 12 位的 VLAN ID（VID，有效范围 1 – 4094）。
  - **Access 端口**：用于连接终端主机或服务器。主机发出的标准以太网帧进入 Access 端口时，交换机为其打上端口所属的默认 VLAN Tag；出向发往主机时，交换机自动剥离 Tag，终端系统无需感知 VLAN。
  - **Trunk 端口**：用于交换机之间或交换机与路由器之间的级联链路。允许多个不同 VLAN 的数据帧同时通过，透传时保留 802.1Q Tag。
- **广播遏制效果**：交换机二层转发广播时严格限定在同一 VID 内部，**广播帧绝不跨越 VLAN 扩散**。例如财务部主机发起的 ARP 广播仅在财务 VLAN 内的主机之间传递，办公区其他 VLAN 主机完全不受干扰。不同 VLAN 之间的正常业务通信则强制上送至三层路由器或三层交换机的路由虚接口（SVI）进行单播路由。

#### 3. 端口风暴控制（Storm Control）：硬件级限速（止血）
- **STP 与 VLAN 之外的防御死角**：
  - STP 依赖设备支持并合规收发 BPDU。若员工在终端私接不支持 STP 的简易 Hub 并形成自环，或某台主机的网卡固件故障持续疯狂向外倾倒 ARP/广播报文，STP 无法感知并抑制这类非标准端点。
  - 单一 VLAN 内部若发生异常泛洪，亦可能耗尽该 VLAN 的交换机端口缓冲区。
- **ASIC 硬件限速原理**：
  - 交换机在物理端口控制芯片（ASIC）层面，对进入端口的泛洪帧进行实时计数监控，受控对象包括三类：**广播（Broadcast）**、**未知组播（Unknown Multicast）**、**未知单播（Unknown Unicast）**。
  - **未知单播的成因**：数据帧的目的 MAC 不在交换机 MAC 地址表中，交换机必须向所有端口泛洪。若网络遭受 MAC 地址泛洪攻击（MAC Flooding，恶意伪造巨量随机源 MAC 塞满交换机内存），正常单播帧也会因 MAC 无法命中而退化为未知单播全面泛洪。
  - **计量与阻断**：限速指标采用 **pps（包每秒）** 或带宽百分比，直接针对数据包频率进行限制。超出安全阈值的报文在 PHY/MAC 硬件层直接丢弃，不占用交换机背板带宽，亦不进入协议栈。
- **超限处置策略**：
  - **drop 模式**：静默丢弃超出阈值的泛洪报文，端口正常单播通信不受干扰，对业务影响最小。
  - **err-disable 模式**：检测到泛洪持续超标时，芯片直接将该物理端口强制切断（关闭链路），隔离故障源，防止突发流量冲击交换机交换核心。

#### 4. 三道防线的协同定位

| 防线 | 作用位置 | 核心动作 | 防御目标 | 局限 |
| :--- | :--- | :--- | :--- | :--- |
| **STP / RSTP** | 交换机拓扑级 | 交互 BPDU 选举树根，逻辑阻塞冗余端口 | 消除交换机间物理环路（**治本**） | 依赖 BPDU，防不住终端私接傻瓜 Hub 自环 |
| **划分 VLAN** | 交换机端口级 | 802.1Q 标签打标，广播不跨 VLAN 扩散 | 压缩广播域与爆炸半径（**控域**） | 无法阻止同一 VLAN 内部的环路与泛洪 |
| **Storm Control** | 交换机物理端口 | ASIC 芯片按 pps 硬性限速或熔断端口 | 阻断突发泛洪冲击交换机核心（**兜底**） | 仅在端口处止血，不修复下游的物理环路 |

怎么判断网络正在遭受广播风暴：
1. 交换机管理面：端口收发速率双双逼近物理线速，交换机转发引擎与控制面 CPU 报警打满。
2. 终端主机：同一网段内所有主机的 CPU 突发异常偏高，网络响应极度迟缓甚至完全失联。

> [!note] 这三个手段防的是「量」，防不了「假」
> STP、VLAN、storm-control 针对的都是广播帧数量失控。ARP 欺骗不一样：攻击者只需发几个伪造的应答就能劫持流量，速率完全正常，storm-control 不会触发。针对欺骗本身要靠另一套手段：
>
> - **DHCP Snooping + DAI（动态 ARP 检测）**：交换机监听 DHCP 交互建立「IP-MAC-端口」绑定表，收到 ARP 报文逐个比对，对不上就丢。企业网的标准做法。
> - **静态 ARP 绑定**（`ip neigh add ... nud permanent`）：表项永不老化、不被免费 ARP 刷新，只适合网关这类数量少且固定的地址。
> - **端口隔离 / 私有 VLAN**：同网段主机之间根本不能直接通信，欺骗报文发不到受害者。
>
> 完整的防御分层（包括旁路监控与端到端加密）见 [[7.5 ARP地址解析#6. ARP 完全没有认证|ARP 那篇的防御表]]。

### 5.4 组播

组播是「一发多收，但只发给订阅者」。发送方把包发到一个 D 类地址（224.0.0.0/4），网络设备负责在分叉点把包复制到各条下游链路。

它省带宽的地方在于：**发送方的上行带宽与接收方数量无关**。一路 5 Mbps 的直播推给 1000 个订阅者，发送方仍然只发一份 5 Mbps，复制工作由网络承担；换成单播就要 5 Gbps。

组播只在支持它的网络内有效（需要交换机支持 IGMP Snooping、路由器支持组播路由），公网上基本不可用，所以实际的直播分发走的是 CDN 而不是组播。

## 6. IPv6 一句话

32 位地址已经分完了，IANA 在 2011 年宣布 IPv4 地址池耗尽。IPv6 把地址扩到 **128 位**，写成 8 组四位十六进制数，用冒号分隔（如 `2001:db8::1`）。写代码时的主要影响是地址结构体从 `sockaddr_in` 换成 `sockaddr_in6`，以及应该用 `getaddrinfo()` 而不是硬编码 IPv4 结构，这样同一份代码能同时跑在两种协议上。

## 7. 关键要点

1. **IP 地址是 32 位整数**，点分十进制只是给人看的写法。
2. **分类地址已经是历史**，今天真正决定网络位长度的是子网掩码。
3. **网络号 = IP AND 掩码**，广播地址 = 主机位全 1，可用主机数 = 2^主机位 − 2。
4. **判断网段看主机位，不看末段数字**。`10.1.2.0` 在 /8 下是合法主机地址。
5. **广播风暴源于二层无 TTL 机制**。防御依靠三道防线协同：STP 逻辑阻塞冗余端口破除环路（治本），VLAN 划分广播域控制爆炸半径（控域），Storm Control 端口硬件限速熔断异常流量（兜底）。
6. **绑定 `0.0.0.0` 表示监听所有网卡**，这是服务端最常用的写法，和「地址 0」无关。

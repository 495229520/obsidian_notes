# 8.6 云计算案例：远程表达式计算器

## 1. 概述

客户端把两个操作数和一个运算符发给服务器，服务器算完把结果送回来。计算本身是一行 `switch`，重点全在**怎么让两台机器对同一段字节达成一致理解**——这就是 RPC（远程过程调用）要解决的核心问题。

和 [[8.5 回声服务器]] 的区别在于：回声不解析数据，怎么切都无所谓；这里服务器必须把字节还原成 `operand1`、`operand2`、`op` 三个字段，一旦切错位，算出来的是别的东西，而且**程序不会报错**。

| 场景 | 这个模型对应什么 |
|:---|:---|
| 云计算 | 计算密集的活交给服务器，客户端只出题收结果 |
| 分布式计算 | 多个客户端共享同一份服务器算力 |
| 瘦客户端 | 客户端只做输入输出，不含业务逻辑 |

---

## 2. 协议设计

两端约定一对定长结构体：

```c
// 计算请求
typedef struct {
    int  operand1;      // 第一个操作数
    int  operand2;      // 第二个操作数
    char op;            // 运算符 (+, -, *, /)
    char padding[3];    // 手工补的对齐字节，让结构体大小可预测
} CalcRequest;

// 计算结果
typedef struct {
    int result;         // 计算结果
    int error;          // 错误码，0 表示成功
} CalcResponse;
```

![[图片/SVG/3_8_8_6_1.svg|1000]]

### 2.1 大小算错是最常见的第一个坑

`CalcRequest` 是 **12 字节**，不是 9 字节，也不是 8 字节。`int` 要求 4 字节对齐，编译器会把结构体总大小补到 4 的倍数——`4 + 4 + 1 = 9`，向上补齐得 12。这里的 `padding[3]` 只是把编译器本来就会插入的那 3 个字节显式写出来，让人一眼看得见，不是它让结构体变大的。

想验证就直接打印：

```c
printf("%zu %zu\n", sizeof(CalcRequest), sizeof(CalcResponse));  // 12 8
```

代码里所有长度都写 `sizeof(CalcRequest)`，不要写死成数字。换个平台、加个 `#pragma pack`，数值就变了。

### 2.2 字节序：本机测试永远发现不了的坑

结构体直接 `send` 出去，`int` 是按本机内存里的顺序走的。x86 是小端，`10` 在内存里是 `0A 00 00 00`；网络字节序规定大端，是 `00 00 00 0A`。

两端都是 x86 时不转也能通，所以本机回环测试永远发现不了问题。等对端换成大端机、或者换成 Java（JVM 统一大端），`10` 就会被读成 `167772160`。

修法是收发前后各转一次：

```c
// 发送前：主机序 → 网络序
req.operand1 = htonl(a);
req.operand2 = htonl(b);
req.op       = op;              // 单字节，没有字节序问题，不用转

// 接收后：网络序 → 主机序
int a = ntohl(req.operand1);
int b = ntohl(req.operand2);
```

`char` 和 `char[]` 不用转，因为单个字节内部没有顺序可言。

## 3. 服务端实现

```c
#include <stdio.h>
#include <string.h>
#include <errno.h>
#include <unistd.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>

typedef struct {
    int  operand1;
    int  operand2;
    char op;
    char padding[3];
} CalcRequest;

typedef struct {
    int result;
    int error;
} CalcResponse;

// 错误码，两端必须用同一份定义
enum { CALC_OK = 0, CALC_DIV_ZERO = 1, CALC_BAD_OP = 2 };

int calculate(int a, int b, char op, int *error) {
    *error = CALC_OK;
    switch (op) {
        case '+': return a + b;
        case '-': return a - b;
        case '*': return a * b;
        case '/':
            if (b == 0) {                 // 不判就是整数除零，直接 SIGFPE 崩掉
                *error = CALC_DIV_ZERO;
                return 0;
            }
            return a / b;
        default:
            *error = CALC_BAD_OP;
            return 0;
    }
}

// 收满 n 字节才返回 0；对端提前关闭或出错返回 -1
static int recv_all(int fd, void *buf, size_t n) {
    size_t got = 0;
    while (got < n) {
        ssize_t k = recv(fd, (char *)buf + got, n - got, 0);
        if (k == 0) return -1;                        // 对端在发完整帧之前就关了
        if (k < 0) {
            if (errno == EINTR) continue;
            return -1;
        }
        got += (size_t)k;
    }
    return 0;
}

void run_server(void) {
    int listenfd = socket(AF_INET, SOCK_STREAM, 0);
    if (listenfd < 0) { perror("socket"); return; }

    int opt = 1;
    setsockopt(listenfd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));

    struct sockaddr_in serveraddr;
    memset(&serveraddr, 0, sizeof(serveraddr));
    serveraddr.sin_family = AF_INET;
    serveraddr.sin_port = htons(9527);
    serveraddr.sin_addr.s_addr = htonl(INADDR_ANY);   // 所有网卡都收

    if (bind(listenfd, (struct sockaddr *)&serveraddr, sizeof(serveraddr)) < 0) {
        perror("bind"); close(listenfd); return;
    }
    if (listen(listenfd, 5) < 0) {
        perror("listen"); close(listenfd); return;
    }
    printf("calculator server started on port 9527...\n");

    while (1) {
        struct sockaddr_in clientaddr;
        socklen_t clientlen = sizeof(clientaddr);

        int connfd = accept(listenfd, (struct sockaddr *)&clientaddr, &clientlen);
        if (connfd < 0) {
            if (errno == EINTR) continue;
            perror("accept");
            continue;
        }
        printf("client connected: %s:%d\n",
               inet_ntoa(clientaddr.sin_addr), ntohs(clientaddr.sin_port));

        CalcRequest  request;
        CalcResponse response;

        // 收满一整帧才动手解析，收不满就当这次请求作废
        if (recv_all(connfd, &request, sizeof(request)) == 0) {
            int a = ntohl(request.operand1);          // 还原字节序
            int b = ntohl(request.operand2);
            printf("received: %d %c %d\n", a, request.op, b);

            int err = CALC_OK;
            int r = calculate(a, b, request.op, &err);

            response.result = htonl(r);               // 回去之前再转回网络序
            response.error  = htonl(err);
            send(connfd, &response, sizeof(response), 0);

            if (err == CALC_OK) printf("result: %d\n", r);
            else                printf("error: %d\n", err);
        }

        close(connfd);
    }

    close(listenfd);
}

int main(void) {
    run_server();
    return 0;
}
```

把循环读取抽成 `recv_all()` 是这一版最重要的改动。它把「收满 n 字节」这件事变成一个能复用、能测试的函数，而不是每处收发都手抄一遍 `while` 循环。原地展开的循环写三遍就会错一遍，[[8.5 回声服务器#4. 循环读取的常见写错法|8.5]] 里那个把长度变量覆盖掉的写法就是这么来的。

`recv_all` 的返回值只有两种结果：收满了，或者没收满。**没收满就不能解析** —— 半个结构体里的字段是垃圾数据，`ntohl` 一样会返回一个看起来正常的数字。

## 4. 客户端实现

```c
int send_calculation(int a, char op, int b) {
    int sockfd = socket(AF_INET, SOCK_STREAM, 0);
    if (sockfd < 0) { perror("socket"); return -1; }

    struct sockaddr_in serveraddr;
    memset(&serveraddr, 0, sizeof(serveraddr));
    serveraddr.sin_family = AF_INET;
    serveraddr.sin_port = htons(9527);
    serveraddr.sin_addr.s_addr = inet_addr("127.0.0.1");

    if (connect(sockfd, (struct sockaddr *)&serveraddr, sizeof(serveraddr)) < 0) {
        perror("connect"); close(sockfd); return -1;
    }

    // 构造请求。memset 把 padding 也清零：不清的话发出去的是栈上的垃圾，
    // 抓包时看到的内容每次都不一样，很难对照
    CalcRequest request;
    memset(&request, 0, sizeof(request));
    request.operand1 = htonl(a);
    request.operand2 = htonl(b);
    request.op       = op;

    send(sockfd, &request, sizeof(request), 0);
    printf("sent: %d %c %d\n", a, op, b);

    CalcResponse response;
    if (recv_all(sockfd, &response, sizeof(response)) != 0) {
        printf("server closed before replying\n");
        close(sockfd);
        return -1;
    }

    int err = ntohl(response.error);
    int r   = ntohl(response.result);

    // 先判 error，再决定要不要读 result
    if (err == CALC_OK) {
        printf("result: %d %c %d = %d\n", a, op, b, r);
    } else {
        printf("calculation error: %d\n", err);
    }

    close(sockfd);
    return err == CALC_OK ? r : -1;
}

int main(void) {
    send_calculation(10, '+', 5);   // 15
    send_calculation(10, '-', 3);   // 7
    send_calculation(6,  '*', 7);   // 42
    send_calculation(20, '/', 4);   // 5
    send_calculation(10, '/', 0);   // error 1
    return 0;
}
```

`memset(&request, 0, sizeof(request))` 不能省。`padding[3]` 不赋值就是栈上的残留数据，虽然对端不读它，但抓包对照时每次内容都不一样，排查协议问题会非常难受。

## 5. 一次完整往返

![[图片/SVG/3_8_8_6_2.svg|1000]]

### 5.1 错误为什么要单独占一个字段

`CalcResponse` 里 `result` 和 `error` 分开，是因为**没有哪个 `int` 值可以拿来当错误标记**。用 `result = -1` 表示出错行不通：`10 - 11` 的正确结果就是 `-1`，客户端分不清这是算出来的还是报错。

客户端的读法也因此固定：**先判 `error`，为 0 才读 `result`**。`error != 0` 时 `result` 里是什么都不算数。

### 5.2 强制类型转换的作用

`recv_all` 里这一句：

```c
recv(fd, (char *)buf + got, n - got, 0);
//       ^^^^^^^^
```

指针加法以指向类型的大小为单位。如果 `buf` 是 `CalcRequest *`，`buf + 1` 会跳过整整 12 字节；转成 `char *` 之后，`+ got` 才是「往后挪 got 个字节」的意思。

`void *` 上不能直接做算术（C 标准未定义，GCC 作为扩展允许），所以要显式转成 `char *`。

## 6. 定长协议能撑到哪一步

这个协议能成立，靠的是三个前提同时满足：

| 前提 | 被破坏会怎样 | 对策 |
|:---|:---|:---|
| 两端对齐规则一致 | `sizeof` 不同，一端多读或少读，此后每一帧都错位 | `#pragma pack`，或逐字段序列化 |
| 两端字节序一致 | 数值被解释成天文数字，程序不报错照跑 | `htonl` / `ntohl` |
| 结构体里没有指针 | 传过去的是本机地址，对端解引用直接崩 | 只传值，变长数据改用长度头 |

第三条常被忽略，但它是定长结构体协议的硬边界：**只要业务需要传字符串或数组，这套做法就到头了**。加一个字段也一样——老客户端仍按 12 字节切帧，新旧混跑时每一帧都错位，而且没有任何一层会报错。

演进路线是长度头 + 版本号（见 [[8.9 TCP的粘包和拆包]]），再往上就交给 Protocol Buffers、gRPC 这类框架统一处理对齐、字节序和版本兼容。

## 7. 扩展：用 [[11.2 进程创建与程序替换#2. fork() - 创建子进程|fork()]] 改成并发

```c
while (1) {
    int connfd = accept(listenfd, NULL, NULL);
    if (connfd < 0) continue;

    pid_t pid = fork();
    if (pid == 0) {
        close(listenfd);              // 子进程不需要监听 fd

        CalcRequest  request;
        CalcResponse response;
        if (recv_all(connfd, &request, sizeof(request)) == 0) {
            int err = CALC_OK;
            int r = calculate(ntohl(request.operand1),
                              ntohl(request.operand2),
                              request.op, &err);
            response.result = htonl(r);
            response.error  = htonl(err);
            send(connfd, &response, sizeof(response), 0);
        }

        close(connfd);
        _exit(0);                     // 子进程用 _exit，不跑父进程的 atexit 和缓冲区刷新
    }
    close(connfd);                    // 父进程放掉这条连接的 fd，否则泄漏
}
```

两处细节：子进程退出用 `_exit()` 而不是 `exit()`，避免把从父进程继承来的 stdio 缓冲区内容重复刷出去；父进程的 `close(connfd)` 不能省，`fork()` 之后 fd 的引用计数是 2，两边都关才真正断开。

子进程会变成 [[11.5 僵尸进程|僵尸进程]]，父进程要装 `SIGCHLD` 处理函数配 `waitpid(-1, NULL, WNOHANG)` 循环回收。

## 8. 关键要点

1. **`sizeof(CalcRequest)` 是 12 不是 9**。对齐规则会在结构体尾部补空洞，长度一律用 `sizeof` 取，不要手算。
2. **多字节数值收发前后各转一次字节序**，`char` 不用转。本机回环测试发现不了字节序问题。
3. **把循环读取抽成 `recv_all()`**，收满一整帧才解析。半帧里的字段是垃圾，而 `ntohl` 照样会给你一个像模像样的数字。
4. **错误码单独占字段**，不能拿返回值的特殊取值表示出错；客户端先判 `error` 再读 `result`。
5. **定长结构体协议的边界**：加字段就不兼容，结构体里不能有指针。跨过这条线就该上长度头或序列化框架。

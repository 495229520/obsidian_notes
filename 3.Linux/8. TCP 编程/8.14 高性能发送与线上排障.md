## 简介

网络编程八股不只问协议，也会追问“怎么把数据高效发出去”和“线上连接异常怎么查”。这篇笔记补充零拷贝、批量 IO、MTU/MSS，以及常见排障命令。

---

## 零拷贝解决什么

普通文件发送到 socket，常见路径是：

```text
磁盘 -> 内核页缓存 -> 用户缓冲区 -> socket 发送缓冲区 -> 网卡
```

零拷贝并不是完全没有拷贝，而是尽量减少用户态和内核态之间的数据复制、减少上下文切换。

---

## sendfile

`sendfile()` 适合把文件内容直接发送到 socket，例如静态文件服务器。

```cpp
#include <sys/sendfile.h>

off_t offset = 0;
ssize_t n = sendfile(sockfd, filefd, &offset, file_size);
```

特点：

- 数据主要在内核态流转
- 避免用户态缓冲区中转
- 适合文件到 socket
- 不适合需要在用户态修改数据的场景

---

## mmap

`mmap()` 把文件映射到进程地址空间，应用像访问内存一样访问文件。

```cpp
void* p = mmap(nullptr, len, PROT_READ, MAP_PRIVATE, filefd, 0);
```

它减少了 `read()` 把文件复制到用户缓冲区的过程，但如果随后再 `send()`，仍然可能从用户空间拷贝到内核 socket 缓冲区。

---

## splice

`splice()` 可以在两个内核对象之间移动数据，常见是 pipe 和 socket/file 之间。

```cpp
splice(filefd, nullptr, pipefd[1], nullptr, len, 0);
splice(pipefd[0], nullptr, sockfd, nullptr, len, 0);
```

它更偏 Linux 专用能力，适合代理、转发、管道式数据搬运。

---

## writev 和 readv

`writev()` / `readv()` 是分散/聚集 IO，可以把多个缓冲区一次写出或一次读入多个缓冲区。

```cpp
#include <sys/uio.h>

iovec iov[2];
iov[0].iov_base = header;
iov[0].iov_len = header_len;
iov[1].iov_base = body;
iov[1].iov_len = body_len;

writev(fd, iov, 2);
```

典型用途：

- 协议头和 body 分开存储，但希望一次发送
- 减少系统调用次数
- 避免为了拼包而额外复制内存

## TCP_CORK 与 TCP_NODELAY

| 选项 | 作用 | 典型场景 |
|:---|:---|:---|
| `TCP_NODELAY` | 禁用 [[10.3 Nagle算法|Nagle]]，小包尽快发送 | 低延迟交互 |
| `TCP_CORK` | 先攒住小片数据，等完整后再发 | 发送 header + body |

`TCP_CORK` 更像“我还没攒完，先别发”；`TCP_NODELAY` 更像“别等，马上发”。两者目标相反，使用时要非常清楚发送模式。

## MTU、MSS、PMTU

| 概念 | 含义 |
|:---|:---|
| MTU | 链路层一次能承载的最大 IP 包大小，以太网常见 1500 |
| MSS | TCP 单段最大数据量，通常约等于 MTU 减去 IP/TCP 头 |
| PMTU | 路径上的最小 MTU |

面试重点：

- TCP 是字节流，应用层不应该依赖一次 `send()` 对应一个包
- MSS 影响 TCP 分段大小
- UDP 大包更容易遇到 IP 分片风险，见 [[9.1 UDP原理#2. MTU、分片与 PMTU]]

## ss

`ss` 是 Linux 上排查连接状态的常用工具。

```bash
ss -tanp
ss -tan state established
ss -tan state time-wait
ss -tan state close-wait
ss -s
```

常用观察点：

- `TIME_WAIT` 是否暴涨
- `CLOSE_WAIT` 是否堆积
- `SYN_RECV` 是否异常
- Send-Q / Recv-Q 是否持续增长

---

## lsof

查看进程打开了哪些 fd：

```bash
lsof -p <pid>
lsof -i :8080
```

适合排查：

- fd 是否泄漏
- 某个端口被哪个进程占用
- 连接对应的进程和文件描述符

---

## tcpdump 与 Wireshark

抓包适合确认“包到底有没有出去/回来”。

```bash
tcpdump -i eth0 tcp port 8080 -nn
tcpdump -i eth0 host 10.0.0.1 and port 8080 -w out.pcap
```

常见观察点：

- 是否完成三次握手
- 谁先发 FIN
- 是否出现 RST
- 是否有重传
- 窗口是否变成 0

Wireshark 更适合打开 `.pcap` 后做协议字段分析。

## /proc/net/tcp

`/proc/net/tcp` 能看到内核记录的 TCP 连接，但状态是十六进制编码。

| 编码 | 状态 |
|:---|:---|
| `01` | ESTABLISHED |
| `02` | SYN_SENT |
| `03` | SYN_RECV |
| `06` | TIME_WAIT |
| `08` | CLOSE_WAIT |
| `0A` | LISTEN |

通常优先用 `ss`，需要脚本化或深入排查时再看 `/proc/net/tcp`。

## errno 排障

| errno | 常见含义 | 排查方向 |
|:---|:---|:---|
| `ECONNREFUSED` | 对端端口没人监听或拒绝 | 服务是否启动、防火墙 |
| `ETIMEDOUT` | 连接超时 | 网络路径、防火墙、SYN 丢失 |
| `ECONNRESET` | 对端 RST | 对端异常关闭、协议错误 |
| `EPIPE` | 对端关闭后继续写 | 关闭逻辑、SIGPIPE |
| `EMFILE` | 进程 fd 用尽 | `ulimit -n`、fd 泄漏 |
| `ENFILE` | 系统 fd 用尽 | 系统级 fd 上限 |
| `EADDRINUSE` | 地址已被占用 | TIME_WAIT、已有监听进程 |

## 面试问法

| 问题 | 回答要点 |
|:---|:---|
| sendfile 为什么快 | 减少用户态和内核态之间的数据拷贝 |
| writev 解决什么 | 多缓冲区一次 IO，减少拼接和系统调用 |
| TCP_CORK 和 TCP_NODELAY 区别 | 一个攒包，一个尽快发 |
| CLOSE_WAIT 多怎么查 | `ss -tanp state close-wait` + 检查应用 close |
| 怎么判断谁先关闭连接 | 抓包看 FIN 方向 |
| Send-Q 一直增长说明什么 | 对端接收慢或网络慢，本端输出积压 |

---

## 关键要点

1. **零拷贝主要减少用户态/内核态数据搬运，不是完全无拷贝**。
2. **`sendfile` 适合文件到 socket，`writev` 适合多缓冲区聚集发送**。
3. **`TCP_CORK` 偏吞吐，`TCP_NODELAY` 偏低延迟**。
4. **线上排障先看状态和队列，再抓包确认协议行为**。
5. **`ss`、`lsof`、`tcpdump` 是 Linux 网络排障基础工具链**。

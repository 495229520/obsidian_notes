# 第 01 集｜这段刺耳的声音里，藏着一个游戏

可修改初稿 v0.1 · 2026-09-08 · 横屏 16:9 · 目标约 9 分钟

**这一版的故事：历史 → 还原 ZX Spectrum 的磁带加载 → 看清速度开销 → 解释当年的取舍 → 留给现代方案一个问题。**

以 MG、程序录屏、模拟器画面和旁白完成，不需要露脸或室内全景。视觉延续米白、近黑、橙、绿的第一版基础；借鉴“回形针”的信息组织与镜头因果，不照搬其版式、标识或素材。一个数据块贯穿“程序—声音—恢复程序”，减少无意义的图标切换。

本稿主线采用**软件生成、音频解码与独立模拟器验证**。真实磁带录放尚未完成，因此旁白没有把模拟器结果说成磁带实测。末尾附可以替换的实拍槽位。时间码是剪辑预算，保留听音、读画面和操作停顿；正式录音后按语速微调。[纯旁白稿](第01集_纯旁白_v0.1.txt) 由下表提取，录音时可以单独打开。

本版验证已完成：27 项 Rust 测试通过，独立模拟器从 WAV 的实际脉冲加载出 712 B 程序，并通过猜错、三次失败、重开和猜中操作。证据见 [独立验证报告](../../artifacts/ep01/independent/verification.json)。

## 素材与录屏命令

在项目根目录运行。默认拒绝覆盖已有输出；需要重新生成同名产物时明确加 `--force`，或换一个实验目录。正片中的数据固定对应 `artifacts/ep01`，改游戏或参数后应重跑并同步更新旁白数字。

```powershell
# C1：生成本集原创游戏和标准音频
cargo run --release -- demo --out-dir artifacts/ep01

# C2：从 WAV 解码成新的 TAP
cargo run --release -- decode artifacts/ep01/game.wav artifacts/ep01/recovered.tap --report artifacts/ep01/decode.json

# C3：完整文件逐字节比对；退出码 0 才算通过
cargo run --release -- verify artifacts/ep01/game.tap artifacts/ep01/recovered.tap --json

# 查看文件头，帮助解释 712 B 程序与 737 B TAP 的区别
cargo run --release -- inspect artifacts/ep01/game.tap --json
```

C4 独立验证的完整命令与产物见 [验证方法](../../docs/验证方法.md)。它把 WAV 实际边沿转换为 TZX 脉冲，再让 SkoolKit 执行原 ROM 的加载流程；不以本项目的收发互相认可作为唯一证据。

## 若加入真实磁带：替换 S18，不预写成功

这一段是可选的后续制作工作，不计入当前已完成验证。

- 先保留原始 `game.wav`，通过线路输出录入磁带，倒带，再用线路输入采集为新的 WAV。设备型号、音量、采样率、关闭或开启的处理和每次结果都记下来。
- 对新的录音执行同一组 `decode` / `verify`。只有整份 TAP 一致，才能说本次磁带录放读回成功。
- **成功时旁白：**“接下来，我把这段声音录进磁带，再倒回来播放。这一次，从磁带回来的音频里，也找到了两个数据块。把文件重新拼好，和原文件逐字节比较，结果一致。这次，声音确实经过磁带，回来了。”旁边上屏实际实验编号、设备和次数。
- **失败时旁白：**“接下来，我把这段声音录进磁带，再倒回来播放。但这一次，程序没有完整回来。现在只能确认，软件里的格式能走通，实体录放这一步还没通过。问题发生在哪里，我们得接着查。”随后只加入已有证据支持的错误位置，不猜测带速或音量就是原因。
- 替换时增加约 20–40 秒，用 S19–S21 的算式动画压缩同等时长，成片仍控制在 10 分钟内。

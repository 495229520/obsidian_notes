# 回声服务器（Echo Server）

## 概述

**回声服务器**把客户端发来的数据原样送回去，业务逻辑等于零。它存在的意义是把网络这一层单独隔离出来：收发对不上，就一定是网络代码的问题，不会是业务算错了。

同时它也是第一个必须面对**字节流没有消息边界**的例子。[[8.4 迭代服务器]] 里一次 `recv` 就读完 21 字节，是数据太小碰巧成立；数据一大，这个假设立刻崩。

![[图片/SVG/3_8_8_5_1.svg|1000]]

比迭代服务器多出来的是**内层循环**。外层 `while` 换客户端，内层 `while` 在同一条连接上反复收发。少写内层循环，一条连接只能服务一个来回；内层退出条件写错，服务器会卡死在里面，再也不回去 `accept()`。

## TCP 字节流特性与数据接收问题

### 一次性发送 1200 字节会发生什么

客户端调一次 `send(buf, 1200)`，服务器调一次 `recv()`，能拿到完整的 1200 字节吗？

**不一定。** 而且「不一定」的具体表现取决于网络状况，本机回环测试时几乎总是能一次读完，换到真实网络就开始丢数据——这类 bug 通常到生产环境才暴露。

![[图片/SVG/3_8_8_5_2.svg|1000]]

TCP 是**字节流**协议（参见 [[7.5 TCP协议基础#核心特性|TCP 核心特性]]），三条性质叠在一起造成了这个结果：

1. **无消息边界**：TCP 不知道你的「一条消息」是什么，它只搬字节
2. **可能拆分或合并**：1200 字节可能被切成多个 TCP 段，也可能和下一次 `send` 的数据合在一个段里
3. **`recv` 只取此刻有的**：它返回接收缓冲区中当前可读的字节数，不会等着凑满你给的 buffer

### 解决方案：循环读取

```c
// 循环读取直到收够 total_len 字节
size_t read_len = 0;
while (read_len < total_len) {
    ssize_t len = recv(fd, buffer + read_len, total_len - read_len, 0);
    if (len == 0) break;                        // 对端关闭
    if (len < 0) {
        if (errno == EINTR) continue;           // 被信号打断，重试
        break;                                  // 真错误
    }
    read_len += len;
}
```

两个参数都要跟着 `read_len` 走：`buffer + read_len` 决定往哪写，`total_len - read_len` 决定还能写多少。漏掉任何一个，第二轮就开始覆盖已经收到的数据。

> [!warning] 这个循环有个前提：你得知道 `total_len`
> 定长协议里 `total_len` 是结构体大小，[[8.6 云计算案例]] 就是这么做的。变长消息得先读长度头，见 [[8.9 TCP的粘包和拆包]] 和 [[8.15 输入输出缓冲区与协议解析器]]。
>
> 回声服务器不需要 `total_len`——它把收到多少就回多少，天然绕开了这个问题。这也是它虽然简单却容易给人错觉的地方。

## 完整代码实现

### 服务端

```c
#include <stdio.h>
#include <string.h>
#include <errno.h>
#include <unistd.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>

void run_echo_server(void) {
    int listenfd = socket(AF_INET, SOCK_STREAM, 0);
    if (listenfd == -1) {
        perror("socket");
        return;
    }

    // 允许端口处于 TIME_WAIT 时重新绑定，否则重启服务要等一两分钟
    int opt = 1;
    setsockopt(listenfd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));

    struct sockaddr_in serveraddr;
    memset(&serveraddr, 0, sizeof(serveraddr));
    serveraddr.sin_family = AF_INET;
    serveraddr.sin_port = htons(9527);
    serveraddr.sin_addr.s_addr = inet_addr("127.0.0.1");

    if (bind(listenfd, (struct sockaddr *)&serveraddr, sizeof(serveraddr)) == -1) {
        perror("bind");
        close(listenfd);
        return;
    }
    if (listen(listenfd, 5) == -1) {
        perror("listen");
        close(listenfd);
        return;
    }
    printf("echo server listening on 127.0.0.1:9527...\n");

    char buffer[1024];

    // 外层循环：一次一个客户端
    while (1) {
        struct sockaddr_in clientaddr;
        socklen_t clientlen = sizeof(clientaddr);

        int connfd = accept(listenfd, (struct sockaddr *)&clientaddr, &clientlen);
        if (connfd == -1) {
            if (errno == EINTR) continue;
            perror("accept");
            continue;
        }
        printf("client connected: %s:%d\n",
               inet_ntoa(clientaddr.sin_addr), ntohs(clientaddr.sin_port));

        // 内层循环：同一条连接上反复收发，直到对端关闭
        while (1) {
            ssize_t len = recv(connfd, buffer, sizeof(buffer), 0);
            if (len == 0) {                  // 对端发来 FIN，正常结束
                printf("client closed\n");
                break;
            }
            if (len < 0) {
                if (errno == EINTR) continue;
                perror("recv");
                break;
            }

            printf("recv %zd bytes\n", len);
            // 回声：收到多少发回多少。这里不需要知道消息边界
            send(connfd, buffer, len, 0);
        }

        close(connfd);   // 只关 connfd，listenfd 留着接下一个客户端
    }

    close(listenfd);
}
```

服务端的回声逻辑刻意不做拼装：`recv` 拿到多少就 `send` 回多少。**这正是回声服务器不会暴露分片问题的原因**——它没有「一条消息」的概念，怎么切都无所谓。真实业务一旦要解析请求，分片问题就跑不掉了。

`send` 这里也留了个简化：它的返回值可能小于 `len`，严格写法要循环发完。发送侧的健壮写法在 [[8.12 非阻塞connect与健壮收发]]。

### 客户端

```c
void echo_once(int sockfd, const char *msg) {
    char buffer[1024];
    size_t msg_len = strlen(msg);
    if (msg_len >= sizeof(buffer)) return;   // 留一个字节给结尾的 \0

    // 发送
    send(sockfd, msg, msg_len, 0);

    // 接收：回声服务器会原样返回 msg_len 字节，所以这里知道该收多少
    size_t read_len = 0;
    while (read_len < msg_len) {
        ssize_t len = recv(sockfd, buffer + read_len, msg_len - read_len, 0);
        if (len == 0) {
            printf("server closed before echoing back\n");
            return;
        }
        if (len < 0) {
            if (errno == EINTR) continue;
            perror("recv");
            return;
        }
        read_len += len;
    }

    buffer[read_len] = '\0';
    printf("echo received (%zu bytes): %s\n", read_len, buffer);
}

int run_echo_client(void) {
    int sockfd = socket(AF_INET, SOCK_STREAM, 0);
    if (sockfd == -1) {
        perror("socket");
        return -1;
    }

    struct sockaddr_in serveraddr;
    memset(&serveraddr, 0, sizeof(serveraddr));
    serveraddr.sin_family = AF_INET;
    serveraddr.sin_port = htons(9527);
    serveraddr.sin_addr.s_addr = inet_addr("127.0.0.1");

    if (connect(sockfd, (struct sockaddr *)&serveraddr, sizeof(serveraddr)) == -1) {
        perror("connect");
        close(sockfd);
        return -1;
    }

    echo_once(sockfd, "Hello, Echo Server!");
    close(sockfd);
    return 0;
}
```

客户端能写循环读取，是因为它**事先知道该收多少**——回声服务器返回的字节数等于发出去的字节数。这个前提在别的协议里不成立，得靠长度头补上。

## 循环读取的常见写错法

下面这段是初学时最容易写出来的版本，它能跑通、能打印出正确结果，但循环是假的：

```c
// ✗ 反例
int len = sizeof(buffer);       // len 一开始表示「缓冲区还剩多少」
int read_len = 0;

while (1) {
    len = recv(client, buffer + read_len, len - read_len, 0);   // len 被覆盖了
    if (len <= 0) break;
    read_len += len;

    if (read_len > 0) {         // 只要读到一个字节就退出
        printf("recv: %s\n", buffer);
        break;
    }
}
```

两处都错：

1. **`len` 被返回值覆盖。** 第一轮 `len` 从 1024 变成 19（实际读到的字节数），第二轮的第三个参数就成了 `19 - 19 = 0`。用长度 0 调 `recv` 会直接返回 0，被当成「对端关闭」——循环悄悄结束，还看不出哪里错了。**缓冲区剩余长度和本次读取长度必须是两个变量。**
2. **退出条件是 `read_len > 0`。** 只要读到一个字节就跳出，这个循环最多跑一轮，等于没写。正确的退出条件是「收够了预期长度」或「对端关闭」。

改法就是把两个含义拆成两个变量，退出条件写成 `read_len < expect_len`：

```c
// ✓ 正确
size_t expect_len = msg_len;     // 期望收多少
size_t read_len = 0;             // 已经收了多少

while (read_len < expect_len) {
    ssize_t n = recv(fd, buffer + read_len, expect_len - read_len, 0);
    if (n <= 0) break;
    read_len += n;
}
```

## 回声服务器的变体

### 1. 用 [[5.1 系统进程控制函数#1. fork() - 创建子进程|fork()]] 改成并发

```c
while (1) {
    int connfd = accept(listenfd, NULL, NULL);
    if (connfd == -1) continue;

    pid_t pid = fork();
    if (pid == 0) {
        close(listenfd);        // 子进程不需要监听 fd
        handle_client(connfd);  // 内层循环搬到这里
        close(connfd);
        _exit(0);
    }
    close(connfd);              // 父进程不需要这条连接的 fd
}
```

两个 `close()` 都不能省。`fork()` 之后父子进程各持有一份 fd，内核的引用计数是 2，只有两边都关掉连接才会真正断开。父进程忘了 `close(connfd)`，fd 会一路泄漏到进程打满 `RLIMIT_NOFILE`。

子进程退出后会变成 [[11.7 僵尸进程|僵尸进程]]，父进程得用 `SIGCHLD` 处理函数配 `waitpid(-1, NULL, WNOHANG)` 回收。

### 2. 加超时，防止慢客户端占死服务器

```c
struct timeval timeout = { .tv_sec = 5, .tv_usec = 0 };
setsockopt(connfd, SOL_SOCKET, SO_RCVTIMEO, &timeout, sizeof(timeout));
```

设了之后，`recv()` 超过 5 秒没数据会返回 −1 并把 `errno` 置为 `EAGAIN`（或 `EWOULDBLOCK`）。**这时候别把它当成连接出错**——它和真错误的区别就在 `errno` 上，判断写漏了就会误杀正常连接。

对迭代服务器来说这不是可选项。没有超时，一个连上来就不说话的客户端能让整个服务停摆。

## 关键要点

1. **回声服务器的作用是隔离变量**：业务逻辑为零，收发对不上就一定是网络代码的问题。
2. **两层循环**：外层换客户端，内层在同一条连接上收发；内层跳出后才 `close(connfd)` 并回到 `accept()`。
3. **一次 `send` 不等于一次 `recv`**。字节流没有消息边界，切法由网络和内核决定，本机测试通过说明不了任何事。
4. **循环读取的两个变量不能合并**：「期望长度」和「本次读到多少」必须分开，合并后循环只会跑一轮。
5. **`recv` 返回 0 是对端有序关闭**，是正常路径，不是错误；返回 −1 还要看 `errno` 区分 `EINTR`、`EAGAIN` 和真错误。
6. **回声服务器天然绕开了分帧问题**，因为它不解析消息。换成真实业务就必须补上定长、长度头或分隔符三者之一。

# 8.4 迭代服务器

## 1. 概述

**迭代服务器**（Iterative Server）一次只服务一个客户端：`accept()` 拿到一条连接后，把它处理完、关掉，才回头 `accept()` 下一条。

它的价值不在于能用，而在于它是理解并发模型的对照组——把「一个请求慢了会怎样」这件事放大到肉眼可见。

![[图片/SVG/3_8_8_4_1.svg|1000]]

图 A 里最容易看错的一点：客户端 B 和 C 的 `connect()` 早就返回成功了。三次握手由内核独立完成，跟服务器进程有没有调用 `accept()` 无关。它们卡的不是握手，是排在全连接队列里等人来取。

### 1.1 特点

| 特点 | 说明 |
|:---|:---|
| **串行处理** | 一次只服务一个客户端，其余的在内核队列里等 |
| **实现简单** | 没有共享状态，不需要考虑同步、竞态、僵尸进程 |
| **等待时间线性累加** | 第 N 个客户端要等前面 N−1 个处理完 |
| **单点阻塞** | 任何一个请求卡住（慢客户端、大文件、死循环），整个服务停摆 |

`listen(fd, 5)` 里的 5 只影响**能排多长的队**，不影响**队伍走多快**。想解决等待问题得换模型，调 backlog 没有用。

## 2. 服务端代码

```c
#include <stdio.h>
#include <string.h>
#include <errno.h>
#include <unistd.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>

void init_listen(void) {
    // 1. 创建监听套接字。这个 fd 从头到尾只负责收连接，不参与收发数据
    int listenfd = socket(AF_INET, SOCK_STREAM, 0);
    if (listenfd == -1) {
        perror("socket");
        return;
    }

    // 2. 填服务器地址结构。memset 是必须的：sockaddr_in 里有 sin_zero 填充字段，
    //    不清零会把栈上的垃圾一起传给内核
    struct sockaddr_in serveraddr;
    memset(&serveraddr, 0, sizeof(serveraddr));
    serveraddr.sin_family = AF_INET;
    serveraddr.sin_port = htons(9527);              // 端口要转成网络字节序
    serveraddr.sin_addr.s_addr = inet_addr("127.0.0.1");

    // 3. 绑定。绑 127.0.0.1 意味着只有本机能连上，外部网卡进来的包收不到
    if (bind(listenfd, (struct sockaddr *)&serveraddr, sizeof(serveraddr)) == -1) {
        perror("bind");
        close(listenfd);
        return;
    }

    // 4. 转为被动套接字，内核开始替我们完成三次握手并把结果排进队列
    if (listen(listenfd, 5) == -1) {
        perror("listen");
        close(listenfd);
        return;
    }
    printf("server is listening on 127.0.0.1:9527...\n");

    // 5. 主循环：取一条连接，服务完，关掉，再取下一条
    char buffer[256];
    while (1) {
        struct sockaddr_in clientaddr;
        socklen_t clientlen = sizeof(clientaddr);

        // accept 在这里睡着，直到全连接队列里有东西
        int connfd = accept(listenfd, (struct sockaddr *)&clientaddr, &clientlen);
        if (connfd == -1) {
            if (errno == EINTR) continue;   // 被信号打断，重试，不是错误
            perror("accept");
            continue;
        }

        printf("client connected: %s:%d\n",
               inet_ntoa(clientaddr.sin_addr),
               ntohs(clientaddr.sin_port));

        // 6. 收发数据走的是 connfd，不是 listenfd
        memset(buffer, 0, sizeof(buffer));
        ssize_t len = recv(connfd, buffer, sizeof(buffer) - 1, 0);
        if (len > 0) {
            printf("recv %zd bytes: %s\n", len, buffer);
            send(connfd, buffer, len, 0);
        }

        // 7. 只关 connfd。关掉 listenfd 服务就结束了
        close(connfd);
        printf("client disconnected\n");
    }

    close(listenfd);
}

int main(void) {
    init_listen();
    return 0;
}
```

> [!warning] 两个必须留意的写法
> - **变量别叫 `client`。** 监听套接字和已连接套接字是两种东西（见 [[8.2 TCP服务端]]），把监听 fd 命名成 `client` 是后续所有混乱的起点，这里改叫 `listenfd`。
> - **`recv` 的第三个参数是 `sizeof(buffer) - 1`。** 后面要把 `buffer` 当字符串 `printf`，得给结尾的 `\0` 留一个字节。如果按 `sizeof(buffer)` 收满 256 字节，`printf("%s")` 会一路读到缓冲区外面去。

## 3. 客户端代码

```c
void send_msg(int sockfd) {
    struct sockaddr_in serveraddr;
    memset(&serveraddr, 0, sizeof(serveraddr));
    serveraddr.sin_family = AF_INET;
    serveraddr.sin_port = htons(9527);
    serveraddr.sin_addr.s_addr = inet_addr("127.0.0.1");

    // 客户端不需要 bind：connect 时内核自动分配一个临时端口
    if (connect(sockfd, (struct sockaddr *)&serveraddr, sizeof(serveraddr)) == -1) {
        perror("connect");
        return;
    }

    const char *msg = "hello, this is client";
    send(sockfd, msg, strlen(msg), 0);   // 注意是 strlen 不是 sizeof，别把 \0 也发过去

    char buffer[256];
    memset(buffer, 0, sizeof(buffer));
    ssize_t len = recv(sockfd, buffer, sizeof(buffer) - 1, 0);
    if (len > 0) {
        printf("server reply: %s\n", buffer);
    }
}

int send_client(void) {
    int sockfd = socket(AF_INET, SOCK_STREAM, 0);
    if (sockfd == -1) {
        perror("socket");
        return -1;
    }

    send_msg(sockfd);
    close(sockfd);
    return 0;
}
```

客户端这段代码有个隐含假设：一次 `recv()` 就能读到完整回复。消息只有 21 字节时它碰巧总能成立，换成大一点的数据就会失效，[[8.5 回声服务器]] 专门讲这件事。

## 4. 一次完整会话

![[图片/SVG/3_8_8_4_2.svg|1000]]

### 4.1 服务端流程

服务端遵循标准的 [[7.8 listen和accept函数|TCP 服务器编程流程]]：

1. **[[7.7 套接字1#2. socket 函数|socket()]]**：创建 TCP [[7.7 套接字1|套接字]]
2. **[[7.7 套接字1#4. bind 函数|bind()]]**：绑定服务器地址（IP + [[7.3 端口与五元组|端口]]）
3. **[[7.8 listen和accept函数#3. listen 函数|listen()]]**：转为被动套接字，backlog 设为 5
4. 循环：
   - **[[7.8 listen和accept函数#4. accept 函数|accept()]]**：从全连接队列取一条已完成 [[7.6 TCP协议基础#4. 三次握手|三次握手]] 的连接
   - **recv()** / **send()**：走 `connfd` 收发
   - **close(connfd)**：触发 [[7.6 TCP协议基础#5. 四次挥手|四次挥手]]，回到 `accept()`

### 4.2 客户端流程

`socket()` → `connect()` → `send()` → `recv()` → `close()`。客户端不调用 `bind()`，源端口由内核在 `connect()` 时从临时端口范围里挑一个。

### 4.3 阻塞点

`accept()` 和 `recv()` 都会让进程睡眠，睡眠期间不占 CPU。这两处的返回值语义差别很大，图 B 的表格是照着写代码时的检查清单：

- `accept()` 返回 −1 且 `errno == EINTR`：被信号打断，重试，不是错误
- `recv()` 返回 0：对端已关闭，不是「读到空数据」
- `send()` 返回值小于 `len`：只发进去了一部分，剩下的要接着发

## 5. buffer 的传递机制

![[图片/SVG/3_8_8_4_3.svg|1000]]

`send()` 做的事情比名字听起来少得多：把用户空间那块内存拷进内核发送缓冲区，然后返回。数据什么时候真的上网，由内核根据 MSS 和拥塞窗口决定。`recv()` 对称——从内核接收缓冲区拷走**此刻已有的**数据，不会等着凑满你给的 buffer。

由此推出三条实践规则：

- `send()` 返回成功只说明数据进了本机内核。要确认对方收到，得靠应用层回执，TCP 的 ACK 帮不了你（它只确认到达内核，不确认应用读走）
- `recv()` 的返回值必须用，它就是这次实际拷进来的字节数
- `close()` 之后，输出缓冲区里的数据内核会继续发完，输入缓冲区里没读的直接丢弃

缓冲区本身的机制、大小设置、以及它和流量控制的关系，见 [[8.7 IO缓冲]]。

## 6. 从迭代到并发

迭代模型的天花板由**单个请求的处理时长**决定。请求处理 2 秒，吞吐就锁死在 0.5 QPS，加机器之前先得换模型：

| 模型 | 做法 | 代价 |
|:---|:---|:---|
| **fork 并发** | 每条连接 fork 一个子进程 | 进程开销大，要回收 [[11.5 僵尸进程\|僵尸进程]] |
| **线程池** | 每条连接分配一个工作线程 | 共享状态要加锁，线程数不能无限涨 |
| **IO 多路复用** | 单线程用 [[13.1 IO复用简介\|select/poll/epoll]] 同时盯多个 fd | 业务逻辑得写成非阻塞的事件回调 |

三者的分界线是「一个请求阻塞时，其他请求还能不能推进」。用 [[11.2 进程创建与程序替换#2. fork() - 创建子进程|fork()]] 的最小改法在 [[8.5 回声服务器#5. 回声服务器的变体|8.5]] 里有。

## 7. 关键要点

1. **迭代 = 服务完一个再取下一个**，第 N 个客户端的等待时间是前面所有人处理时长之和。
2. **连接建立和连接被服务是两件事**：三次握手由内核完成，`accept()` 只是从队列里取结果。客户端 `connect()` 成功不代表服务器在处理它。
3. **`listen()` 的 backlog 只决定队伍多长**，不决定队伍走多快。
4. **两种 fd 别搞混**：`listenfd` 只收连接，`connfd` 只收发数据，`close()` 关的是 `connfd`。
5. **`send`/`recv` 只是内存拷贝**，收发时机由内核掌握；返回值必须检查，不能假设一次调用就搞定。

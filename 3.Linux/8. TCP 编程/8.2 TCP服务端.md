# TCP 服务端

## 概述

TCP 服务端是网络通信中的"被动方"，它需要先启动并等待客户端的连接请求。服务端的核心职责是：
1. 绑定到指定的 [[7.2 IP地址|IP地址]] 和 [[7.3 端口|端口]]
2. 监听客户端的连接请求
3. 接受连接并与客户端进行数据交换

## 服务端编程流程

TCP 服务端的编程遵循固定的步骤：

图 A 把六步排成一条线，重点在第 4 步的颜色分界：前四步操作的都是 `socket()` 创建的那一个 fd，从 `accept()` 开始主角换成了它返回的**另一个** fd。这是服务端和客户端在结构上最大的差别，也是下面「两种套接字」一节要展开的东西。

| 步骤 | 函数 | 说明 |
|:---:|:---|:---|
| 1 | [[7.6 套接字#socket 函数\|socket()]] | 创建套接字，返回文件描述符 |
| 2 | [[7.6 套接字#bind 函数\|bind()]] | 将套接字与 IP 地址和端口绑定 |
| 3 | [[7.7 listen和accept函数#listen 函数\|listen()]] | 将套接字设置为监听状态 |
| 4 | [[7.7 listen和accept函数#accept 函数\|accept()]] | 从已完成连接队列中取出一个连接 |
| 5 | read()/write() | 与客户端进行数据传输 |
| 6 | close() | 关闭套接字，释放资源 |

## 完整服务端代码示例

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>

int main() {
    int server, client;
    struct sockaddr_in server_addr, client_addr;
    socklen_t client_len;
    char message[] = "Hello World!\n";

    // ========== 1. 创建套接字 ==========
    server = socket(AF_INET, SOCK_STREAM, 0);
    if (server < 0) {
        perror("create socket failed");
        exit(1);
    }

    // ========== 2. 绑定地址和端口 ==========
    memset(&server_addr, 0, sizeof(server_addr));
    server_addr.sin_family = AF_INET;                    // IPv4
    server_addr.sin_port = htons(8080);                  // 端口 8080
    server_addr.sin_addr.s_addr = inet_addr("127.0.0.1"); // 本地地址

    if (bind(server, (struct sockaddr*)&server_addr, sizeof(server_addr)) < 0) {
        perror("bindAddress failed");
        exit(1);
    }

    // ========== 3. 开始监听 ==========
    if (listen(server, 128) < 0) {
        perror("listen failed");
        exit(1);
    }

    printf("服务器已启动，等待客户端连接...\n");

    // ========== 4. 接受客户端连接 ==========
    client_len = sizeof(client_addr);
    client = accept(server, (struct sockaddr*)&client_addr, &client_len);
    if (client < 0) {
        perror("accept failed");
        exit(1);
    }

    printf("客户端已连接: %s:%d\n",
           inet_ntoa(client_addr.sin_addr),
           ntohs(client_addr.sin_port));

    // ========== 5. 发送数据 ==========
    ssize_t len = write(client, message, strlen(message));
    if (len < 0) {
        perror("write failed");
    } else {
        printf("发送了 %zd 字节数据\n", len);
    }

    // ========== 6. 关闭连接 ==========
    close(client);
    close(server);

    return 0;
}
```

## 关键函数详解

### 1. socket() - 创建套接字

```c
int socket(int domain, int type, int protocol);
```

- `domain`：地址族，使用 `AF_INET` 表示 IPv4
- `type`：套接字类型，使用 `SOCK_STREAM` 表示 TCP
- `protocol`：通常设为 0，让系统自动选择协议

详细说明参见 [[7.6 套接字#socket 函数]]。

### 2. bind() - 绑定地址

```c
int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
```

将套接字与指定的 IP 地址和端口绑定。服务器必须调用此函数，否则客户端无法知道连接到哪里。

**注意事项**：
- 端口号需要使用 `htons()` 转换为网络字节序
- IP 地址需要转换成网络字节序的二进制形式
- 使用 `INADDR_ANY`（即 0.0.0.0）可以监听所有网卡

> [!warning] 上面示例里的 127.0.0.1 是个陷阱
> 完整示例 `bind` 的是 `127.0.0.1`，意思是**只在回环网卡上监听**。同一台机器上的客户端连得上，局域网里别的机器一律连不上，表现为 `ECONNREFUSED`。这是「本机测试好好的，一部署就连不上」的头号原因。
>
> 想接受所有网卡上的连接，用 `INADDR_ANY`：
>
> ```c
> server_addr.sin_addr.s_addr = htonl(INADDR_ANY);   // 0.0.0.0
> ```
>
> `INADDR_ANY` 是主机字节序的 0，转换结果虽然还是 0，写上 `htonl()` 能表明这里过了字节序这一关。

> [!tip] `inet_addr()` 已经不推荐用
> 它用返回值 `INADDR_NONE`（即 `0xFFFFFFFF`）表示失败，而这个值恰好也是合法地址 `255.255.255.255`，两者无法区分。新代码用 `inet_pton()`：
>
> ```c
> if (inet_pton(AF_INET, "127.0.0.1", &server_addr.sin_addr) != 1) {
>     fprintf(stderr, "invalid address\n");
>     exit(1);
> }
> ```
>
> 只有返回 1 才是成功：0 表示地址串格式不对，-1 表示地址族不支持。对应的反向函数是 `inet_ntop()`，替代同样过时的 `inet_ntoa()`（后者用静态缓冲，不可重入）。

详细说明参见 [[7.6 套接字#bind 函数]]。

### 3. listen() - 开始监听

```c
int listen(int sockfd, int backlog);
```

- `backlog`：等待连接队列的最大长度
- 调用后，套接字从主动模式变为被动模式（监听模式）

`backlog` 背后其实是**两个**队列——半连接队列（握手中）和全连接队列（握完等 accept），而且实际生效值会被内核参数 `net.core.somaxconn` 封顶，只改代码不改内核参数没有用。详见 [[8.13 TCP内核队列与参数调优]]。

详细说明参见 [[7.7 listen和accept函数#listen 函数]]。

### 4. accept() - 接受连接

```c
int accept(int sockfd, struct sockaddr *addr, socklen_t *addrlen);
```

`accept()` 是一个**阻塞函数**：
- 如果已完成连接队列中有等待的连接，立即返回
- 如果队列为空，会阻塞等待直到有新连接到来

**返回值**：返回一个**新的套接字描述符**，用于与客户端通信。

详细说明参见 [[7.7 listen和accept函数#accept 函数]]。

## 两种套接字的区别

服务端程序中存在两种不同用途的套接字：

| 类型 | 描述 | 用途 |
|:---|:---|:---|
| **监听套接字** | `socket()` 创建，经过 `bind()` 和 `listen()` | 只用于监听新连接，不传输数据 |
| **已连接套接字** | `accept()` 返回 | 与特定客户端进行数据传输 |

上图的 B 面板画的就是这件事：`accept()` 每成功一次，内核造出一个新的 fd，监听 fd 自己一动不动。所以 `accept` 天然要放在循环里，每轮拿到的 fd 各归各的连接。

**生命周期**：
- 监听套接字：随服务器启动创建，服务器关闭时销毁
- 已连接套接字：每次 `accept()` 创建一个，通信结束后关闭

### 一个端口为什么能接住上万条连接

图 C 那张表回答的就是这个问题。内核区分连接靠的是**四元组**：`(本端 IP, 本端 Port, 对端 IP, 对端 Port)`。三条已连接套接字的本端全是 `10.0.0.1:8080`，一模一样，但对端各不相同，所以在内核眼里是三条互不相干的连接。

监听套接字只有本端那一半，是个三元组。它不代表任何一条具体连接，只代表「这个地址和端口上有人在收」。

算上协议字段就是 [[7.3 端口#一个端口能被多少条连接用：五元组|7.3 讲的五元组]]，同一台机器上 `TCP:8080` 和 `UDP:8080` 互不相干。那一节还说清了「端口只有 65535 个」限制的是客户端而不是服务端，这里不重复。

对服务端编程来说，从这张表要带走的是两条：

- 监听 fd 上 `read`/`write` 没有意义，它上面没有数据流，只有等着被 accept 的连接
- 真正的并发天花板是 `ulimit -n` 而不是端口数——每条连接吃一个 fd，忘了 `close` 就等于提前撞线

### accept 要放在循环里

上面的完整示例只 `accept()` 一次就退出了，真实服务端长这样：

```c
while (1) {
    struct sockaddr_in client_addr;
    socklen_t client_len = sizeof(client_addr);   // 每轮都要重新赋值

    int client = accept(server, (struct sockaddr*)&client_addr, &client_len);
    if (client < 0) {
        if (errno == EINTR) continue;             // 被信号打断，重试即可
        perror("accept");
        continue;                                 // 一条连接失败不该拖垮整个服务
    }

    handle(client);
    close(client);                                // 用完必须关
}
```

三个细节都不能省：

1. **`client_len` 是值-结果参数**，必须每轮重新赋成 `sizeof(client_addr)`。`accept` 会把实际写入的地址长度回填进去，上一轮的残留值会让下一轮拿到截断的地址。示例里因为只 accept 一次，这个坑看不出来
2. **`EINTR` 要重试**，它不是错误。装了 `SIGCHLD` 之类的处理函数又没加 `SA_RESTART` 时会经常撞上（见 [[5.5 等待函数#6. 三种回收姿势|5.5]]）
3. **`close(client)` 不能忘**。漏掉就是 fd 泄漏，撑到 `ulimit -n` 之后 `accept` 开始返回 `EMFILE`，服务对外表现为「连得上但立刻断」

不关心对端地址时，后两个参数可以直接传 `NULL, NULL`。

## accept 函数的阻塞行为

`accept()` 默认是阻塞的，这意味着：

1. **有等待连接时**：立即返回新的套接字描述符
2. **无等待连接时**：进程被挂起，直到有客户端连接

```c
// accept 会在这里阻塞，等待客户端连接
client = accept(server, (struct sockaddr*)&client_addr, &client_len);
// 只有当客户端连接后，程序才会继续执行
```

### 非阻塞模式

可以通过设置套接字为非阻塞模式来改变这一行为：

```c
#include <fcntl.h>

// 设置为非阻塞
int flags = fcntl(server, F_GETFL, 0);
fcntl(server, F_SETFL, flags | O_NONBLOCK);
```

非阻塞模式下，如果没有等待的连接，`accept()` 会立即返回 -1，并设置 `errno` 为 `EAGAIN` 或 `EWOULDBLOCK`。

## 常见问题

### 1. "Address already in use" 错误

当服务器重启时，可能会遇到这个错误。原因是之前的连接可能还处于 [[10.2 TIME_WAIT状态|TIME_WAIT]] 状态。

**解决方案**：设置 [[10.1 套接字选项#SO_REUSEADDR|地址复用]] 选项

```c
int opt = 1;
setsockopt(server, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));
```

**这一行必须写在 `bind()` 之前。** `bind` 一旦返回，地址就已经定下来了，再设置这个选项对本次绑定毫无影响。正确顺序是 `socket` → `setsockopt` → `bind`。

详细原理和代码示例参见 [[10.2 TIME_WAIT状态#SO_REUSEADDR 解决方案]]。

### 2. 端口选择建议

- 开发测试：使用 8080、9000 等常见的开发端口
- 生产环境：根据服务类型选择合适的端口
- 避免使用 [[7.3 端口#知名端口（0 – 1023）|知名端口]]（0-1023），除非有 root 权限

## 关键要点

1. **服务端流程**：socket → bind → listen → accept → read/write → close
2. **两种套接字**：前四步作用在监听套接字上，`accept()` 返回后换成已连接套接字。监听 fd 不能读写，已连接 fd 用完必须 `close`
3. **一个端口接住上万条连接**靠的是四元组：本端三项完全相同，用对端 IP + Port 区分。真正的天花板是 `ulimit -n`
4. **accept 阻塞**：默认阻塞等待；放进循环时 `client_len` 每轮要重置，`EINTR` 要重试
5. **地址复用**：`SO_REUSEADDR` 要在 `bind()` **之前**设置，否则不生效
6. **绑 127.0.0.1 只能本机连**，要对外服务用 `INADDR_ANY`
7. **`inet_addr()` / `inet_ntoa()` 已过时**，换 `inet_pton()` / `inet_ntop()`

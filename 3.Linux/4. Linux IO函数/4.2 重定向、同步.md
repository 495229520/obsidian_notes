# 文件重定向与同步

本节介绍 Linux 中的文件描述符重定向（`dup`/`dup2`）、文件同步（`fsync`）、文件偏移量操作（`lseek`）以及临时文件创建（`mkstemp`）。

---

## 文件描述符重定向

### dup() - 复制文件描述符

`dup()` 函数用于复制一个现有的[[4.1 打开、读取、写入、关闭#文件描述符（File Descriptor）|文件描述符]]，返回一个新的文件描述符，这两个描述符指向同一个文件表项。

#### 函数原型

```c
#include <unistd.h>

int dup(int oldfd);
```

#### 参数说明

- **oldfd**：要复制的现有文件描述符

#### 返回值

- 成功：返回一个新的文件描述符（当前可用的最小非负整数）
- 失败：返回 -1，并设置 errno

#### 特点

- `dup()` 返回的新描述符与 oldfd 共享同一个文件偏移量
- 访问模式（只读、只写、读写）也与原描述符相同
- 文件状态标志（如 `O_APPEND`）也共享

---

### dup2() - 指定新描述符的复制

`dup2()` 函数与 `dup()` 类似，但允许指定新文件描述符的值。

#### 函数原型

```c
#include <unistd.h>

int dup2(int oldfd, int newfd);
```

#### 参数说明

- **oldfd**：要复制的现有文件描述符
- **newfd**：指定的新文件描述符值。如果 newfd 已经打开，会先将其关闭

#### 返回值

- 成功：返回 newfd
- 失败：返回 -1，并设置 errno

#### dup2 的主要用途

`dup2()` 最常见的用途是**实现输入/输出重定向**，将标准输入/输出/错误重定向到文件。

> **提示**：在标准 I/O 层（`FILE*`），可以使用 [[6.2 高级文件操作函数#freopen() - 重定向文件流|freopen()]] 实现类似的重定向功能。

#### 示例：将标准输出重定向到文件

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

int main() {
    // 1. 以只写方式打开文件
    int fd = open("test.txt", O_RDWR);
    if (fd == -1) {
        perror("open error");
        return 1;
    }

    // 2. 将标准输出重定向到文件
    //    newfd=1 是标准输出，dup2 会先关闭原来的 stdout，再复制 fd 到 1
    dup2(fd, STDOUT_FILENO);  // STDOUT_FILENO = 1

    // 3. 此时 printf 输出会写入文件而非屏幕
    printf("这段文字会被写入 test.txt 文件\n");

    // 4. 刷新缓冲区确保数据写入
    fflush(stdout);

    close(fd);
    return 0;
}
```

## fsync() - 文件同步

在 Linux 中，`write()` 系统调用将数据写入内核的页缓存（page cache）后就返回，数据实际写入磁盘的时机由内核决定。`fsync()` 函数可以强制将缓冲区的数据刷新到磁盘。

### 为什么需要 fsync？

- **数据持久性**：确保数据真正写入磁盘，防止系统崩溃时数据丢失
- **数据一致性**：在关键操作后确保数据已持久化

### 数据流向

![[图片/SVG/3_4_4_2_2.svg|1301]]

`fsync()` 可以将文件的数据和元数据（如修改时间、文件大小等）都刷新到磁盘，确保数据完全落盘后才返回。

### 谁调用 write()：stdio 与系统调用的分工

`write()` 是系统调用。数据能从进程内存走到内核页缓存，只有两种可能：**你自己调了它，或者 glibc 替你调了它**。没有第三种。

#### 路径一：程序直接调用 write()

```c
int fd = open("a.txt", O_WRONLY);
char buf[] = "Hello";

write(fd, buf, 5);   // 一次陷入内核，数据直接进页缓存
```

`buf` 里的 5 个字节经 `copy_from_user()` 拷进页缓存页，`write()` 返回 5，表示内核已经接手这 5 个字节。这条路上只有一层缓冲，就是内核的页缓存。

#### 路径二：printf 背后是 glibc 代劳

```c
printf("Hello");     // 代码里没有 write()，数据最后却到了页缓存
```

`printf`、`fprintf`、`fwrite`、`fputs` 都是**用户态库函数，不是系统调用**。它们只把数据 memcpy 进 `FILE` 结构体的库缓冲区，这一步内核完全不知情。glibc 内部大致是这样两段逻辑：

```c
// 伪代码，示意 stdio 的两步走
void printf_like(FILE *fp, const char *s, size_t n) {
    memcpy(fp->buf + fp->len, s, n);   // 第一步：纯用户态拷贝，无系统调用
    fp->len += n;

    if (fp->len == fp->cap) {          // 缓冲写满，才轮到第二步
        flush_buffer(fp);
    }
}

// fflush / fclose / 正常 exit 时，glibc 走的也是这个函数
void flush_buffer(FILE *fp) {
    write(fp->fd, fp->buf, fp->len);   // 到这里才陷入内核
    fp->len = 0;
}
```

`printf` 平时只做第一步，把字节堆进 `fp->buf`。什么时候进第二步，取决于四个触发点：缓冲写满（上面的 `if`）、显式 `fflush`、`fclose`、以及正常 `exit`——后三者都是从外部调进 `flush_buffer`。

要点是：**真正执行 `write()` 的是 glibc，不是内核**。你没写 `write()`，但库替你写了；四个触发点都没发生时，它就一直不写，数据一直停在库缓冲里。

> [!warning] `_exit()` 和被信号杀死都不刷库缓冲
> `exit()` 会刷 stdio 缓冲，`_exit()` 不会，`kill -9` 更不会。调试时 `printf` 的输出「莫名丢失」，通常就是数据还在库缓冲里、进程已经没了。

#### 内核会不会自己调 write()？

不会，一次也不会。进程里放着 `char buf[100]`，内核既不知道它存在，也不会替你决定「这该写进文件了」。内核是被动的一方：**只有收到系统调用请求，才会执行 `copy_from_user()`**。

这条边界能解释一个常见误解——数据不会「自己」流向磁盘。没人调 `write()`，页缓存就永远收不到这份数据，它会一直停在用户态内存里，直到进程退出时随地址空间一起消失。

![[图片/SVG/3_4_4_2_4.svg|1307]]

#### fflush 与 write 谁调用谁

这一对关系容易记反。`fflush()` 不是被 `write()` 调用的，恰恰相反：

> **`fflush()` 的核心工作，就是在合适的时机调用 `write()`。**

所以这四个函数是**层层叠加**的关系，不是四个并列的选项：

| 函数 | 是系统调用吗 | 谁真正执行它 | 数据从哪到哪 |
|------|-------------|-------------|-------------|
| `printf` / `fwrite` | 否，用户态库函数 | glibc，全程用户态 | 应用 `buf` → FILE 库缓冲 |
| `fflush(fp)` | 否，但内部会调 `write` | glibc 调 `write()`，才陷入内核 | FILE 库缓冲 → 页缓存 |
| `write(fd, ...)` | 是 | 程序自己，或 glibc 代劳 | 用户 `buf` → 页缓存（标脏页） |
| `fsync(fd)` | 是 | 只能程序自己显式调 | 页缓存 → 设备缓存 → 介质 |

`fflush` 和 `write` 都只把数据交到内核为止，两者的差别仅在于「谁调的 `write`」；只有 `fsync` 把数据交给磁盘。

#### 为什么数据库几乎不用 stdio

MySQL、PostgreSQL、RocksDB、Redis AOF 写盘用的都是 `write` / `pwrite` / `pwritev` / `io_uring`，基本见不到 `fwrite`、`fprintf`。

原因不是性能玄学，是**控制权**。用 stdio 就要过三层缓冲：

```text
自己的 buf  →  stdio 库缓冲  →  页缓存
```

中间那层的刷新时机由库决定：缓冲多大、什么时候写满、什么时候刷，应用说了不算。而事务提交要求的恰恰是「这一刻数据必须已经在某个明确的位置」，多一层不可控的缓冲就多一处说不清的状态。所以存储引擎的做法是让自己成为唯一的缓冲决策者：

```text
自己的 Buffer Pool  →  write()  →  页缓存  →  fsync()
```

或者更彻底，用 `O_DIRECT` 连页缓存一起绕开——代价是缓冲区地址、文件偏移、长度都要按块对齐，且它不保证元数据落盘，持久性仍然要靠 `fsync`：

```text
自己的 Buffer Pool  →  O_DIRECT  →  块设备
```

存储引擎视角的完整持久化语义（`fdatasync` 省了什么、`fsync` 失败为什么必须当致命错误）见 [[1.4 fsync fdatasync 与持久化语义]]。

一份数据从 `buf[]` 走到磁盘介质，要**穿过 4 层存储**（用户态内存 → 内核页缓存 → 盘上缓存 → 持久介质），**跨过 2 条边界**（用户态/内核态、内核/硬件）。每一层都有各自的「谁来推它」和「怎么丢」。

![[图片/SVG/3_4_4_2_3.svg|1307]]

#### 1. 用户态内存：应用 buf 与 stdio 库缓冲

| 位置 | 说明 |
|------|------|
| 应用 `buf[]` | 进程虚拟内存（堆 / 栈 / 全局区），CPU 直接寻址，读写它不产生任何系统调用 |
| stdio 库缓冲 `FILE*` | `printf` / `fwrite` **只是 memcpy 到这里**，此时还没有系统调用 |

- 库缓冲的默认模式：普通文件是**全缓冲**（缓冲区大小通常取文件系统块大小，如 4096 字节），连到终端是**行缓冲**，`stderr` **无缓冲**
- 这块内存内核完全不知情。进程被 `kill -9`、或段错误崩溃时，里面还没 `write` 出去的数据**直接消失**
- 推它进下一层的是 glibc 代调的 `write()`，触发时机见上一节[[#谁调用 write()：stdio 与系统调用的分工|谁调用 write()]]

> 上面 dup2 的例子里那句 `fflush(stdout)` 就是为了跨过这一层——不刷缓冲，重定向后的内容可能还躺在库缓冲里没进内核。

#### 2. 跨界：write() 的一次陷入与唯一一次 CPU 拷贝

`write(fd, buf, n)` 是进入内核的唯一入口，它做四件事：

1. **陷入（trap）**：CPU 从用户态切到内核态，这是固定开销，与数据量无关
2. **定位文件**：`fd`（进程内的下标）→ `struct file`（内含偏移量 `f_pos`）→ `inode`
   - `lseek()` 改的就是 `struct file` 里的 `f_pos`
   - `dup` / `dup2` 复制的是 fd 表项，新旧 fd 指向**同一个** `struct file`，所以偏移量和 `O_APPEND` 等状态才是共享的
3. **`copy_from_user`**：把用户 buf 的内容拷进页缓存页——这是整条路径上**唯一一次 CPU 拷贝**
4. 该页被标记 `PG_dirty`（脏页），然后 `write()` **立刻返回**

> [!important] 定位链、页缓存、元数据不是三个独立的东西
> - `fd 表 → struct file → inode` 是**定位链**，它的终点是**唯一的 inode**
> - 页缓存不是一大锅散页：数据页挂在 **`inode->i_mapping`**（address_space）下，按页索引组织，所以「哪个文件的哪一页」是明确的
> - 元数据不在别处，**就是 inode 自己**（`i_size`、`mtime`、块映射），改数据往往顺带改它（文件变大）
>
> 正因为两者都归属同一个 inode，`fsync(fd)` 才能凭一个 fd 一次性把「这个文件的脏数据页 + 它的元数据」都刷下去；`fdatasync(fd)` 则只保证数据页和**读取必需的**那部分元数据。

#### 3. 内核页缓存：write() 返回 ≠ 落盘

- 以 4KB 页为单位缓存文件内容，由内核统一管理；进程看不见，但内核会替你保管
- **进程崩溃不影响这一层**：数据已经交给内核，之后照样会被写下去
- 但它仍然只是内存：内核 panic 或掉电就全丢，`write()` 早已成功返回也救不回来
- 读路径同样走这层：`read()` 命中页缓存时只有一次 `copy_to_user`，不碰磁盘

脏页什么时候真的被写下去？只有三种时机：

| 时机 | 触发条件 |
|------|----------|
| 周期回写 | 回写线程定期唤醒，写出驻留超过 `dirty_expire_centisecs`（默认 3000，即 30 秒）的脏页 |
| 比例回写 | 脏页占比超过 `dirty_background_ratio` 启动后台回写；超过 `dirty_ratio` 时**写者被直接阻塞** |
| 显式同步 | `fsync()` / `fdatasync()` / `sync()`：立刻提交并**等待完成** |

前两种时机由内核决定、不可预测，**只有第三种是应用可控的**——这就是 fsync 存在的理由。

#### 4. 块层与 DMA：内存页变成磁盘请求

- 内核把待写的脏页打包成 `bio`（描述「哪些内存页写到磁盘哪些扇区」），提交给通用块层
- `blk-mq` 多队列负责排队、合并相邻请求、取 tag 后交给驱动
- 驱动敲响设备后由 **DMA** 搬运：设备**主动读取物理内存**，不经过 CPU——所以这一步**没有第二次 CPU 拷贝**

#### 5. 硬盘：介质之前还有一层易失缓存

- 现代机械盘和 SSD 都自带一块 DRAM 写缓存，数据进了它盘就回复「写完了」，但它**是易失的**，断电即丢
- 要让数据从盘上缓存进入盘片 / NAND，必须下发 **FLUSH** 命令，或使用 **FUA**（Force Unit Access）写
- `fsync()` 在现代 Linux 上会连这个 FLUSH 一起下发，所以它的语义才是真正的「落盘」
- 企业盘的**掉电保护 PLP**（超级电容）能在断电瞬间把缓存写完，此时盘缓存才可视为持久；消费级盘一般没有
- 反过来，如果文件系统用 `nobarrier` 一类选项挂载（禁用 flush），fsync 的持久性保证就会打折

#### 旁路：O_DIRECT 与 mmap

| 方式 | 数据怎么走 | 还需要 fsync 吗 |
|------|-----------|----------------|
| `O_DIRECT` | 绕过页缓存，用户 buf 与磁盘之间直接 DMA；要求缓冲区地址、文件偏移、长度按块大小对齐 | **需要**：它不保证元数据落盘，也不保证盘上缓存被 flush |
| `mmap` | 映射到的物理页就是页缓存页，写内存即改页缓存，无系统调用无拷贝 | 用 `msync(MS_SYNC)` 代替 |

#### 丢失边界总结

| 数据停在哪一层 | `kill -9` 进程崩溃 | 内核 panic / 掉电 | 让它继续往下走要靠 |
|---------------|------------------|------------------|------------------|
| ① stdio 库缓冲（用户态内存） | **丢失** | **丢失** | `fflush()`、缓冲写满、正常 `exit` |
| ② 页缓存脏页（内核内存） | 存活 | **丢失** | 回写线程，或 `fsync()` / `fdatasync()` |
| ③ 磁盘控制器缓存（盘上 DRAM） | 存活 | **无 PLP 时丢失** | FLUSH 命令（`fsync()` 会下发） |
| ④ 盘片 / NAND（持久介质） | 存活 | 存活 | 已经到底 |

**结论**：`fflush()` 只跨过第 ① 层的门；`write()` 返回只代表数据到了第 ② 层；只有 `fsync()` 返回，才代表数据穿过了 ②③ 一路写进第 ④ 层。

### 函数原型

```c
#include <unistd.h>

int fsync(int fd);
```

### 参数说明

- **fd**：一个已经打开的文件描述符

### 返回值

- 成功：返回 0
- 失败：返回 -1，并设置 errno

### 相关函数

| 函数 | 说明 |
|------|------|
| `fsync(fd)` | 同步文件数据和元数据到磁盘 |
| `fdatasync(fd)` | 只同步文件数据，不同步元数据（性能更好） |
| `sync()` | 将所有文件系统的缓冲区刷新到磁盘 |

### 示例代码

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>

int main() {
    int fd = open("test.txt", O_RDWR);
    if (fd == -1) {
        perror("open error");
        return 1;
    }

    char buf[20];

    // 1. 从文件开头读取内容
    ssize_t bytes_read = read(fd, buf, sizeof(buf));
    buf[bytes_read] = '\0';
    printf("Read from file: %s\n", buf);  // 输出: Hello

    // 2. 将读写位置移到文件末尾
    lseek(fd, 0, SEEK_END);

    // 3. 将读写位置从末尾向后偏移 5 字节
    off_t new_pos = lseek(fd, 5, SEEK_END);
    printf("New position at end: %ld\n", new_pos);  // 输出: 12 (Hello World! 占12个字符)

    // 4. 获取当前位置偏移量
    new_pos = lseek(fd, -5, SEEK_END);
    printf("New position from end: %ld\n", new_pos);  // 输出: 7

    // 5. 从当前位置（位置 7）开始写入
    const char *data = "Linux";
    write(fd, data, 5);  // 写入 "Linux"，覆盖 "orld!"

    // 6. 重置位置到开头，读取验证
    lseek(fd, 0, SEEK_SET);
    bytes_read = read(fd, buf, sizeof(buf));
    buf[bytes_read] = '\0';
    printf("Content after writing: %s\n", buf);  // 输出: Hello WLinux

    // 7. 确保数据写入磁盘
    fsync(fd);

    close(fd);
    return 0;
}
```

## lseek() - 修改读写位置偏移量

`lseek()` 函数用于改变文件的当前读写位置（偏移量）。这个函数不会移动任何数据，只是修改内核中记录的文件偏移量。

### 函数原型

```c
#include <sys/types.h>
#include <unistd.h>

off_t lseek(int fd, off_t offset, int whence);
```

### 参数说明

- **fd**：一个已打开文件的文件描述符
- **offset**：偏移量，通常是一个有符号整数
- **whence**：基准位置，有三个可选值：

| whence | 说明 |
|--------|------|
| `SEEK_SET` | 从文件**开头**计算偏移量 |
| `SEEK_CUR` | 从文件**当前位置**计算偏移量 |
| `SEEK_END` | 从文件**末尾**计算偏移量 |

### 返回值

- 成功：返回新的文件偏移量（从文件开头算起的字节数）
- 失败：返回 -1，并设置 errno

### 常见用法

```c
// 移动到文件开头
lseek(fd, 0, SEEK_SET);

// 获取当前位置
off_t current_pos = lseek(fd, 0, SEEK_CUR);

// 移动到文件末尾
lseek(fd, 0, SEEK_END);

// 获取文件大小
off_t file_size = lseek(fd, 0, SEEK_END);

// 从当前位置向后移动 100 字节
lseek(fd, 100, SEEK_CUR);

// 从当前位置向前移动 50 字节
lseek(fd, -50, SEEK_CUR);
```

### 示例：使用 lseek 定位读写

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

int main() {
    int fd = open("test.txt", O_RDWR);
    if (fd == -1) {
        perror("open error");
        return 1;
    }

    char buf[20];

    // 读取前 5 个字节
    read(fd, buf, 5);
    buf[5] = '\0';
    printf("First 5 bytes: %s\n", buf);

    // 跳过 3 个字节
    lseek(fd, 3, SEEK_CUR);

    // 读取接下来的 5 个字节
    read(fd, buf, 5);
    buf[5] = '\0';
    printf("After skip: %s\n", buf);

    close(fd);
    return 0;
}
```

## mkstemp() - 创建临时文件

`mkstemp()` 函数用于创建一个唯一的临时文件。它比 `tmpnam` 或 `tmpfile` 更安全，因为它同时创建并打开文件，避免了竞态条件。

### 函数原型

```c
#include <stdlib.h>

int mkstemp(char *template);
```

### 参数说明

- **template**：文件名模板字符串，**必须**包含至少 6 个连续的 `X` 字符。`mkstemp` 会将这 6 个 `X` 替换为随机字符以生成唯一文件名

### 返回值

- 成功：返回已创建的临时文件的文件描述符
- 失败：返回 -1，并设置 errno

### 重要注意事项

1. **template 必须可修改**：不能是字符串字面量（如 `"temp_XXXXXX"`），必须是字符数组
2. **文件不会自动删除**：程序结束后临时文件仍然存在，需要手动调用 `unlink()` 删除
3. **文件已打开**：返回的是文件描述符，可直接进行读写操作

### 示例代码

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <string.h>

int main() {
    // 模板字符串 - 必须以 XXXXXX 结尾
    char template[] = "/tmp/my_temp_file_XXXXXX";

    // mkstemp 会替换 XXXXXX 为随机字符并创建文件
    int fd = mkstemp(template);
    if (fd == -1) {
        perror("mkstemp error");
        return 1;
    }

    printf("Temporary file created: %s\n", template);

    // 写入一些数据到临时文件
    const char *data = "This is a temporary file.\n";
    write(fd, data, strlen(data));

    // 关闭文件描述符
    close(fd);

    // 验证文件存在 - 读取内容
    FILE *file = fopen(template, "r");
    if (file) {
        char buf[100];
        fgets(buf, sizeof(buf), file);
        printf("Content of temp file: %s", buf);
        fclose(file);
    }

    // 删除临时文件
    unlink(template);
    printf("Temporary file deleted.\n");

    return 0;
}
```

### 输出示例

```
Temporary file created: /tmp/my_temp_file_abc123
Content of temp file: This is a temporary file.
Temporary file deleted.
```

## 关键要点

- **dup()/dup2()**：复制文件描述符，常用于实现 I/O 重定向，新旧描述符共享文件偏移量和状态标志
- **write() 只有两个调用者**：程序自己，或 glibc 在缓冲写满 / `fflush` / `fclose` / 正常 `exit` 时代劳。内核从不主动发起写入
- **fsync()**：强制将缓冲区数据和元数据刷新到磁盘，确保数据持久性
- **lseek()**：修改文件读写位置偏移量，支持从文件头、当前位置、文件尾三种基准定位
- **mkstemp()**：安全地创建临时文件，自动生成唯一文件名并返回文件描述符

# 17.8 Modern C++ 同步设施与实战并发模式

> 前面多以 pthread (C 风格) 讲原理。工程实践应使用 **`<thread>` / `<mutex>` / `<atomic>`** 标准设施，并用 **RAII** 自动管理锁的生命周期；再把这些原语组合成可复用的**工程模式**——它们是高性能服务器的基石。
> 关联 [[15. 高性能服务器]] 与 [[13.6 Reactor模式与EventLoop]]。

---

## 一、Modern C++ 同步设施与 RAII

### 1. 为什么用 RAII 管理锁

- 异常安全：临界区抛异常也能自动解锁
- 对比手动 `lock/unlock` 的风险

### 2. 锁包装器

| 包装器 | 特点 | 场景 |
|--------|------|------|
| `std::lock_guard` | 最简、不可移动 | 简单临界区 |
| `std::unique_lock` | 可延迟/转移/配合条件变量 | 条件变量、手动控制 |
| `std::scoped_lock` (C++17) | 同时锁多个、避免死锁 | 多锁 |
| `std::shared_lock` | 读锁 | 配合 `shared_mutex` |

### 3. 互斥量家族

- `std::mutex` / `recursive_mutex` / `timed_mutex` / `shared_mutex`

### 4. 条件变量

- `std::condition_variable` + 谓词重载 `wait(lk, pred)`
> 对照 [[17.4 条件同步：条件变量与信号量]]

### 5. 原子与一次性初始化

- `std::atomic<T>` → 见 [[17.5 无锁编程：CAS、乐观锁与悲观锁]]
- `std::call_once` / `std::once_flag`
- `std::counting_semaphore` (C++20)、`std::latch`、`std::barrier`

### 6. 任务级并发

- `std::async` / `std::future` / `std::promise` / `std::packaged_task`

### 7. 对接项目规范

> 遵循仓库 CLAUDE.md：RAII 优先、禁止裸 `new/delete`、并发遵循 muduo Reactor 模式

## 二、实战并发模式

> 把上面的原语组合成可复用的工程模式。

### 1. 生产者-消费者 / 线程池
> 见 [[12.7 条件变量与线程池]]、[[17.6 并发队列：有界队列与无锁队列]]

### 2. 线程安全的单例

- 饿汉式 vs 懒汉式
- double-checked locking 的坑（为什么需要 atomic / 内存序）
- 推荐：`static` 局部变量 (C++11 magic static) 或 `std::call_once`

### 3. 读多写少优化

- 读写锁
- 双缓冲 (double buffering) / shared_ptr 原子替换
- RCU (Read-Copy-Update) 思想

### 4. 每线程数据 (Thread-Local)

- `thread_local`、`pthread_key_t`
- 避免共享 = 最好的同步

### 5. 无共享架构 (Share-Nothing)

- 每个线程独占 EventLoop → 见 [[13.6 Reactor模式与EventLoop]]
- one loop per thread (muduo)

### 6. 异步与 Future

- 任务编排、回调地狱的规避

### 7. 反模式与陷阱清单

- 锁内调用用户回调
- 持锁做耗时 IO
- 错误的锁粒度
- 伪共享 (false sharing)

# 判断错误

本节介绍 C 标准库中用于检测和处理文件流错误状态的函数，包括 `feof()`、`ferror()` 和 `clearerr()`。

---

## feof() - 检测文件末尾

`feof()` 是一个 C 标准库函数，用于检查文件流是否已到达**文件末尾**（end-of-file）。

### 函数原型

```c
#include <stdio.h>

int feof(FILE *stream);
```

### 参数说明

- **stream**：一个指向已打开文件流的指针

### 返回值

- 如果文件流的 EOF 指示器被设置：返回非零值（真）
- 否则：返回 0（假）

### feof() 的工作方式

理解 `feof()` 的关键在于：EOF 指示器是**滞后**的。只有某次读取**实际撞上**文件末尾之后它才被设置；"位置刚好停在最后一个字节后面"本身不会设置它。换句话说，`feof()` 回答的是"刚才那次读是不是败在文件末尾上"，而不是"接下来还有没有数据"。

### 错误示例（常见陷阱）

```c
// 错误：用 feof 当循环条件，会多循环一次
FILE *fp = fopen("example.txt", "r");
if (fp == NULL) {
    perror("fopen error");
    return 1;
}

int c;
while (!feof(fp)) {   // 读之前判断 feof，判断的其实是"上一次读"的结果
    c = fgetc(fp);
    printf("%c", c);  // 最后一次循环 c == EOF (-1)，被当作字符打印出乱码
}

fclose(fp);
```

### 为什么会多读一次？

把最后两轮循环拆开看：

```mermaid
flowchart LR
    A["读到最后一个字符<br>feof 仍为 0"] --> B["!feof 为真<br>再次进入循环"]
    B --> C["fgetc 撞上末尾<br>返回 EOF"]
    C --> D["EOF 被当字符打印<br>输出乱码"]
    D --> E["feof 此时才为 1<br>循环退出"]
```

**正确方式**：用读取函数自己的返回值控制循环（`fgetc() != EOF`、`fgets() != NULL`、`fread()` 的返回块数），循环结束后再用 `feof()`/`ferror()` 判断退出原因。

### 正确示例

```c
int main() {
    FILE *fp;
    char buffer[10];

    // 创建一个包含一些内容的文件
    fp = fopen("example.txt", "w");
    if (fp == NULL) {
        perror("fopen error");
        return 1;
    }
    fprintf(fp, "1234567890123456789090");
    fclose(fp);

    // 以只读模式打开并读取
    fp = fopen("example.txt", "r");
    if (fp == NULL) {
        perror("fopen error");
        return 1;
    }

    // 循环读取，每次读取 10 个字符
    // fgets 在读取到 EOF 时会返回 NULL
    while (fgets(buffer, sizeof(buffer), fp) != NULL) {
        printf("Read: %s\n", buffer);
    }

    // 检查循环终止的原因
    if (feof(fp)) {
        printf("\n\nEnd-of-file reached successfully.\n");
    } else if (ferror(fp)) {
        printf("\n\nAn error occurred while reading the file.\n");
    }

    fclose(fp);
    return 0;
}
```

## ferror() - 检测文件流错误

`ferror()` 是一个 C 标准库函数，用于检查文件流在最近一次操作中是否发生了**错误**。

### 函数原型

```c
#include <stdio.h>

int ferror(FILE* stream);
```

### 参数说明

- **stream**：一个指向已打开文件流的指针

### 返回值

- 如果文件流的错误指示器被设置：返回非零值（真）
- 否则：返回 0（假）

### ferror() 的工作方式

文件流内部有一个错误标识符，当在任何文件 I/O 函数（如 `fread`、`fwrite`、`fgetc` 等）在执行过程中遇到错误时，比如磁盘空间不足、权限问题或其他 I/O 错误，这个标识符会被设置。

`ferror()` 的作用就是检查这个标识符。它与 `feof()` 不同，`feof()` 检查是否到达文件末尾，而 `ferror()` 检查是否发生了真正的 I/O 错误。

### 为什么需要 ferror？

由于文件 I/O 操作可能因各种原因失败（例如，磁盘已满、文件被锁、权限不足等），仅凭函数返回值有时难以区分是正常的 EOF 还是真正的错误：`fgetc()` 两种情况都返回 `EOF`，`fgets()` 两种情况都返回 `NULL`。`ferror()` 提供了区分两者的明确方式。

注意 `feof()`/`ferror()` 本身不修改 errno。发生真正的 I/O 错误时，stdio 函数内部的系统调用通常已经设置了 errno，此时可以用 `perror()` 打印具体原因。

## clearerr() - 清除错误状态

`clearerr()` 函数用于清除文件流的错误指示器和 EOF 指示器。

### 函数原型

```c
#include <stdio.h>

void clearerr(FILE *stream);
```

### 参数说明

- **stream**：一个指向已打开文件流的指针

### 返回值

- 无返回值（`void`）

### clearerr() 的作用

调用 `clearerr(fp)` 后：

- `feof(fp)` 将返回 0（假）
- `ferror(fp)` 将返回 0（假）

这允许你在处理完错误或 EOF 后，重置流的状态以继续操作。

### 为什么标志需要清除？

EOF 和错误指示器一旦被设置就是**粘性**的：后续的读写会直接失败返回，不再真正尝试 I/O。典型场景是 `tail -f` 式的跟读，即读到文件末尾后等新数据再继续读，这时必须先清掉 EOF 标志。除了 `clearerr()`，[[6.5 移动文件指针]]里的 `fseek()` 和 `rewind()` 也会清除 EOF 标志（`rewind()` 连错误标志一起清）。

## 综合示例

以下示例演示了 `feof()`、`ferror()` 和 `clearerr()` 的用法：

```c
#include <stdio.h>

int main() {
    FILE *fp = NULL;
    char buffer[10];

    // 1. 创建一个文件用于测试正常读取
    fp = fopen("normal.txt", "w");
    if (fp == NULL) {
        perror("Error creating normal.txt");
        return 1;
    }
    fputs("12345", fp);
    fclose(fp);

    // 2. 正常读取：循环到达文件末尾时正常退出
    printf("--- Testing normal read ---\n");
    fp = fopen("normal.txt", "r");
    if (fp == NULL) {
        perror("Error opening normal.txt");
        return 1;
    }

    // fgets 在读取到文件末尾时返回 NULL
    while (fgets(buffer, sizeof(buffer), fp) != NULL) {
        printf("Read: %s\n", buffer);
    }

    if (ferror(fp)) {
        printf("An I/O error occurred while reading!\n");
    } else if (feof(fp)) {
        printf("End-of-file reached successfully.\n");
    }

    fclose(fp);

    // 3. 模拟一个 I/O 错误
    // 在只读模式下尝试写入：这会设置错误标志但可能不会产生明显的错误
    printf("\n--- Testing I/O error ---\n");
    fp = fopen("normal.txt", "r");
    if (fp == NULL) {
        perror("Error opening normal.txt");
        return 1;
    }

    // 尝试写入，这将失败并设置错误标志
    fputc('A', fp);

    // 检查错误状态
    if (ferror(fp)) {
        printf("Successfully detected an I/O error!\n");

        // 使用 clearerr 清除错误状态
        clearerr(fp);
        printf("Error status cleared. ferror(fp) returns: %d\n", ferror(fp));
    } else {
        printf("No I/O error detected.\n");
    }

    fclose(fp);

    return 0;
}
```

### 分析说明

1. **第一次测试**中，我们正常地从文件读取直到 EOF。`fgets()` 在读取到文件末尾时返回 NULL，此时 `feof(fp)` 返回非零值，`ferror(fp)` 返回 0（没有错误）。先查 `ferror` 再查 `feof` 是习惯顺序：错误更需要被优先发现

2. **第二次测试**中，我们以只读模式打开文件，然后尝试写入。`fputc()` 对只读流写入会失败并设置错误标志，`ferror(fp)` 返回非零值

3. `clearerr(fp)` 同时清除错误标志和 EOF 标志，之后 `ferror(fp)` 恢复返回 0，流可以继续使用

---

## 关键要点

- **feof()**：检查是否到达文件末尾，**只有在读取操作实际撞上 EOF 后**才返回真
- **ferror()**：检查文件流是否发生了 I/O 错误；和 `feof()` 一起用于区分"读完了"和"读坏了"
- **clearerr()**：清除文件流的 EOF 标志和错误标志
- 两个标志都是**粘性**的：不清除，后续读写直接失败；`fseek()`/`rewind()` 也能清 EOF 标志

### 函数对比

| 函数 | 功能 | 返回值 | 使用场景 |
|------|------|--------|---------|
| `feof()` | 检测 EOF | 非零（已到 EOF）或 0 | 判断循环终止原因 |
| `ferror()` | 检测错误 | 非零（有错误）或 0 | 区分 EOF 和真正错误 |
| `clearerr()` | 清除状态 | 无 | 重置流状态以继续操作 |

### 最佳实践

1. **不要用 `feof()` 作为循环条件**：应该检查读取函数的返回值
2. **在循环结束后使用 `feof()` 和 `ferror()`** 来判断终止原因
3. **处理完错误后使用 `clearerr()`** 来重置状态（如果需要继续使用该文件流）

### 典型的文件读取模式

```c
// 推荐的读取模式
while (fgets(buffer, sizeof(buffer), fp) != NULL) {
    // 处理数据
}

// 循环结束后检查原因
if (feof(fp)) {
    // 正常到达文件末尾
} else if (ferror(fp)) {
    // 发生了读取错误
    perror("Read error");
}
```

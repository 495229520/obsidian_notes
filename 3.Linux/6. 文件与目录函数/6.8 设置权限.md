# 设置权限

本节介绍 Linux 系统中用于修改文件所有者和权限的函数：`chown()` 和 `fchmodat()`。

---

## 权限位的结构与判定顺序

改权限之前先看清楚改的是什么。`chmod`/`fchmodat` 的 `mode` 参数、`stat` 读回的 `st_mode` 低 12 位，是同一套编码。

![[图片/SVG/3_6_6_8_1.svg|900]]

图 A 的 12 位分四组，每组三位。平时写的 `0644` 是**四位**八进制数，最前面那个 `0` 不是 C 语言的八进制前缀，它就是特殊位那一组。想设 SUID 得写 `04755`，写成 `0755` 只是把特殊位清零。`chmod u+s file` 和 `chmod 4755 file` 等价，原因就在这里。

图 B 是这一节最容易想反的地方：内核判权限时**只挑一档看，命中就停**。先比进程的 euid 和文件的 `st_uid`，相等就只看 owner 那三位，group 和 other 里写了什么都不再理会。所以图里那个 `0466` 的文件，属主 alice 写不进去，同组的 bob 反而可以——三档之间是选择关系，不是并集。

`chmod 0466` 这种写法现实中少见，但同一个机制会以别的面目出现：把目录 chown 给某个 uid、权限只给到 group，进程恰好以那个 uid 跑起来，于是命中 owner 档、拿到只读、写失败。这时候盯着 group 位看是找不到原因的。

图 C 说的是另一件事：**同样三个字母用在目录上，含义完全变了**。`r` 管能不能列出名字，`w` 管能不能增删条目，`x` 管能不能穿过去。三者可以独立开关，「有 x 没 r」就是能进去、能按名字打开里面的文件，但 `ls` 会报 `EACCES`。这一块与 [[6.9 操作目录]] 直接相关。

### 改权限是整体替换，不是加一位

`mode` 参数是**完整的新权限**，不是要追加的位。想给一个 `0644` 的文件补上属主执行位，写成 `chmod(path, 0100)` 会把其余九位一起清掉，文件变成 `--x------`。

要加位就得读回来、或运算、再写回：

```c
struct stat st;
if (stat(path, &st) == -1) { perror("stat"); return -1; }

// st_mode 高位还带着文件类型，必须用 07777 掩掉
mode_t mode = st.st_mode & 07777;
if (fchmodat(AT_FDCWD, path, mode | S_IXUSR, 0) == -1)
    perror("fchmodat");
```

`07777` 这个掩码不能省。`st_mode` 除了低 12 位的权限，高 4 位还编码着文件类型（`S_IFREG`、`S_IFDIR` 等），把它原样传给 `chmod` 等于把类型位当权限写进去。

`stat` 和 `chmod` 之间存在窗口：这期间别人改了权限，你会拿旧值覆盖回去。

### umask 不参与 chmod

[[3.5 权限控制函数#umask 函数|umask]] 只在**创建**时起作用：`open(path, O_CREAT, 0666)` 落到磁盘上的是 `0666 & ~umask`，umask 为 022 时得到 `0644`。

`chmod` 和 `fchmodat` 不经过这一步，写多少就是多少。所以「明明 chmod 0666 了怎么还是 0644」这类问题，原因通常在创建那一步，不在 chmod。

## chown() - 修改文件所有者和组

`chown()` 函数用于修改文件的所有者（owner）和所属组（group）。这涉及到 [[3.5 权限控制函数#UID 和 GID|UID 和 GID]] 的概念。

### 函数原型

```c
#include <unistd.h>

int chown(const char *pathname, uid_t owner, gid_t group);
int fchown(int fd, uid_t owner, gid_t group);
int lchown(const char *pathname, uid_t owner, gid_t group);
```

### 参数说明

- **pathname**：要修改的文件路径名
- **fd**：文件描述符（`fchown` 使用）
- **owner**：新的所有者 [[3.5 权限控制函数#UID（用户标识符）|UID]]，传入 `(uid_t)-1` 表示不修改
- **group**：新的所属组 [[3.5 权限控制函数#GID（组标识符）|GID]]，传入 `(gid_t)-1` 表示不修改（uid_t/gid_t 是无符号类型，-1 实际是"全 1"的哨兵值，习惯上加显式转换）

### 返回值

- 成功：返回 0
- 失败：返回 -1，并设置 errno

### 三个变体的区别

| 函数 | 说明 |
|------|------|
| `chown()` | 通过路径名修改，如果是符号链接则修改链接指向的文件 |
| `fchown()` | 通过文件描述符修改 |
| `lchown()` | 通过路径名修改，如果是符号链接则修改链接本身 |

### 注意事项

- 只有超级用户（root）可以修改文件的所有者。更准确的说法是**持有 `CAP_CHOWN` 能力的进程**——容器里常见的是被摘掉这个能力的 root，此时 chown 照样 `EPERM`
- 普通用户只能将自己拥有的文件的组改为自己所属的其他组
- **改完所有者，`SUID` / `SGID` 会被清掉。** 规则是：对普通文件 `S_ISUID` 一律清除，`S_ISGID` 只在 group-execute 位也置位时才清（`S_ISGID` 单独出现时表示强制锁定，与提权无关）。理由很直接：一个 `04755` 的程序执行时取的是文件属主的身份，chown 若不清这一位，把它送给 root 就等于凭空造出一个 setuid root 程序

### 示例代码

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/stat.h>
#include <pwd.h>
#include <grp.h>

int main() {
    const char *filename = "test_ownership.txt";
    FILE *fp;

    // 1. 创建一个测试文件
    fp = fopen(filename, "w");
    if (fp == NULL) {
        perror("fopen");
        return 1;
    }
    fprintf(fp, "This is a test file.\n");
    fclose(fp);

    // 2. 获取文件当前的所有者信息
    struct stat file_info;
    if (stat(filename, &file_info) == -1) {
        perror("stat");
        return 1;
    }

    printf("File: '%s' created.\n", filename);
    printf("Initial ownership - UID: %d, GID: %d\n",
           file_info.st_uid, file_info.st_gid);

    // 3. 尝试修改文件所有者（需要 root 权限）
    uid_t new_uid = 1000;  // 示例 UID
    gid_t new_gid = 1000;  // 示例 GID

    printf("\nAttempting to change ownership to UID: %d, GID: %d\n",
           new_uid, new_gid);
    printf("Note: This operation usually requires root privileges.\n");

    if (chown(filename, new_uid, new_gid) == -1) {
        perror("chown failed");
    } else {
        printf("Ownership of '%s' changed successfully.\n", filename);

        // 验证修改结果
        stat(filename, &file_info);
        printf("Final ownership - UID: %d, GID: %d\n",
               file_info.st_uid, file_info.st_gid);
    }

    // 4. 只修改组（传入 (uid_t)-1 保持 UID 不变）
    if (chown(filename, (uid_t)-1, new_gid) == -1) {
        perror("chown (group only) failed");
    }

    // 清理
    remove(filename);
    return 0;
}
```

### 编译运行

```bash
gcc -o chown_example chown_example.c
sudo ./chown_example  # 需要 root 权限
```

## fchmodat() - 相对目录修改权限

`fchmodat()` 函数用于相对于目录文件描述符修改文件权限。它是 [[3.5 权限控制函数#chmod 函数|chmod()]] 函数的扩展版本，提供了更灵活的路径解析方式。

### 函数原型

```c
#include <sys/stat.h>
#include <fcntl.h>

int fchmodat(int dirfd, const char *pathname, mode_t mode, int flags);
```

### 参数说明

- **dirfd**：目录文件描述符，或特殊值 `AT_FDCWD`（表示当前工作目录）
- **pathname**：文件路径名
  - 如果是绝对路径，则 `dirfd` 被忽略
  - 如果是相对路径，则相对于 `dirfd` 指向的目录
- **mode**：新的[[3.5 权限控制函数#权限表示方式|权限模式]]
- **flags**：`0` 或 `AT_SYMLINK_NOFOLLOW`。**Linux 上不支持后者**：内核没有实现 `lchmod` 语义，传了会返回 -1 并置 `ENOTSUP`。原因是符号链接自己的权限位在 Linux 上没有意义，路径解析只看它指向谁。所以在 Linux 上这个参数实际只能传 `0`

### 返回值

- 成功：返回 0
- 失败：返回 -1，并设置 errno

### dirfd 的使用

| dirfd 值 | pathname 类型 | 行为 |
|----------|---------------|------|
| `AT_FDCWD` | 相对路径 | 相对于当前工作目录解析 |
| 有效目录 fd | 相对路径 | 相对于该目录解析 |
| 任意值 | 绝对路径 | `dirfd` 被忽略 |

### 为什么使用 fchmodat？

1. **路径只解析一次**。下面两段的差别在于「目录」这个东西是靠名字找的还是靠 fd 抓住的：

```c
// 有窗口：chmod 会把整条路径重新解析一遍。
// 期间攻击者把 spool 换成指向 /etc 的符号链接，就改错了目标
chmod("/var/spool/job/data", 0600);

// 无窗口：dirfd 抓住的是那个 inode，
// 之后 spool 这个名字指向哪里都与它无关
int dfd = open("/var/spool/job", O_RDONLY | O_DIRECTORY);
fchmodat(dfd, "data", 0600, 0);
close(dfd);
```

这就是 TOCTOU（time-of-check to time-of-use）竞态的典型形态：检查的时刻和使用的时刻之间，被检查的东西换了人。拿目录 fd 时加上 `O_DIRECTORY`，目标不是目录会当场失败，而不是拿到一个普通文件的 fd 在后面出怪；只拿它当锚点、不打算读内容时，用 `O_PATH` 要的权限更少。

2. **不依赖当前工作目录**：多线程程序里 `chdir()` 是全进程生效的，相对 dirfd 操作可以让每个线程有自己的"工作目录"

### 示例代码

```c
#include <stdio.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>
#include <errno.h>

int main() {
    const char *filename = "example.txt";
    FILE *fp;

    // 1. 创建一个测试文件
    fp = fopen(filename, "w");
    if (fp == NULL) {
        perror("fopen");
        return 1;
    }
    fprintf(fp, "This is a test file.\n");
    fclose(fp);

    printf("File '%s' created with default permissions.\n", filename);

    // 2. 使用 fchmodat() 把权限改成只读 0444 (r--r--r--)
    printf("\nChanging permissions to octal(0444), read-only...\n");
    if (fchmodat(AT_FDCWD, filename, 0444, 0) == -1) {
        perror("fchmodat");
        return 1;
    }
    printf("Permissions changed successfully.\n");

    // 3. 尝试以写模式打开文件，验证权限确实生效
    // 注意：root 用户不受权限位约束，此验证要以普通用户运行
    printf("\nAttempting to open file in write mode...\n");
    fp = fopen(filename, "w");
    if (fp == NULL) {
        printf("Open failed as expected: Permission denied\n");
    } else {
        printf("Open succeeded unexpectedly.\n");
        fclose(fp);
    }

    // 4. 恢复可写权限 0644，否则连删除前的清理写入都做不了
    printf("\nRestoring write permission (0644)...\n");
    if (fchmodat(AT_FDCWD, filename, 0644, 0) == -1) {
        perror("fchmodat");
        return 1;
    }
    printf("Permissions restored.\n");

    // 5. 使用 unlink() 删除文件
    printf("\nAttempting to delete file '%s' with unlink()...\n", filename);
    if (unlink(filename) == -1) {
        perror("unlink");
        return 1;
    }
    printf("File '%s' deleted successfully.\n", filename);

    return 0;
}
```

### 运行结果

```
File 'example.txt' created with default permissions.

Changing permissions to octal(0444), read-only...
Permissions changed successfully.

Attempting to open file in write mode...
Open failed as expected: Permission denied

Restoring write permission (0644)...
Permissions restored.

Attempting to delete file 'example.txt' with unlink()...
File 'example.txt' deleted successfully.
```

最后一步能删除成功有个细节：`unlink()` 检查的是**所在目录**的写权限，不是文件本身的权限。就算不恢复 0644，只读文件照样能被删掉。

## chmod() vs fchmodat() 对比

| 特性 | chmod() | fchmodat() |
|------|---------|------------|
| 路径解析 | 相对于当前工作目录 | 可相对于任意目录 fd |
| 符号链接处理 | 跟随链接 | 同样跟随（Linux 不支持 `AT_SYMLINK_NOFOLLOW`） |
| 安全性 | 每次调用重新解析整条路径 | dirfd 之后的那一段才重新解析 |
| 可移植性 | POSIX 标准 | POSIX.1-2008 |

---

## 关键要点

- **mode 的低 12 位** = 特殊位 3 位 + owner / group / other 各 3 位；`0644` 最前面那个 `0` 是特殊位那一组，不是八进制前缀
- **判权限只挑一档，命中即停**：euid 匹配就只看 owner 三位。属主可能因为 owner 位比 group 位更严而被卡住，三档不取并集
- **`chmod` 是整体替换**：加一位要先 `stat` 读回、`& 07777` 掩掉类型位、或上新位再写回
- **umask 只管创建，不管 chmod**：`open(..., O_CREAT, 0666)` 拿到的是 `0666 & ~umask`，`chmod(0666)` 写多少是多少
- **目录的 rwx**：`r` 列名字、`w` 增删条目、`x` 穿过去；`unlink` 看的是所在目录的 `w`，与文件自身权限无关
- **chown()**：修改文件所有者和组，通常需要 root 权限（准确说是 `CAP_CHOWN`）
- **fchown()**：通过文件描述符修改所有者
- **lchown()**：修改符号链接本身的所有者
- **fchmodat()**：相对于目录 fd 修改权限，路径不必反复解析，堵住 TOCTOU 窗口；Linux 上 `flags` 只能传 `0`
- 使用 `(uid_t)-1` / `(gid_t)-1` 作为 UID 或 GID 参数表示保持不变
- `AT_FDCWD` 表示当前工作目录
- 修改权限时建议使用八进制数（如 `0644`、`0755`）

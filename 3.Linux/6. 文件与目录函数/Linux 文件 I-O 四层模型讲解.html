02 · Plain-language translation

把图里的术语，翻译成人话。

记住“这一层回答什么问题”，比死记结构体字段更有用。

FILE*用户态的“流”

它替程序做缓冲，减少频繁进入内核的开销，并把一个 fd 包装成更好用的 C 标准库接口。

fread/fwrite/fprintf 先与流和用户态缓冲打交道；需要时才调用 read/write。

fd进程内的小整数

3 不是文件本身，只是当前进程描述符表的一个索引。另一个进程里的 fd 3 完全可能指向别处。

0 / 1 / 2 通常预留给标准输入、标准输出、标准错误。

struct file一次“打开实例”

它保存这次打开的动态状态：当前偏移 f_pos、文件状态标志 f_flags、操作表等。

fork/dup 让多个 fd 指向同一个实例，所以它们会共享偏移；重新 open 则通常产生另一个实例。

inode文件的内核身份

它描述“这是哪个文件”：类型、权限、大小以及与缓存映射有关的信息。同一文件可以被打开很多次，出现多个 struct file，但仍汇聚到同一个 inode。

inode 不是文件名；路径解析最终找到 inode，目录项负责把名字关联到它。

04 · Remember it

最后，只记这一句话。

fd 是号码，
struct file 是这次打开，
inode 是文件本人。

  • 01

    dup/fork 共享的是打开文件描述中的偏移和文件状态标志；描述符自己的 FD_CLOEXEC 等标志并不等同于它们。

  • 02

    FILE* 的缓冲在用户空间。若 fork 前缓冲尚未刷新，父子进程会各自继承一份缓冲副本，之后可能重复刷新同一批数据。

  • 03

    普通缓存 I/O 通常先读写 page cache；写入不等于已经持久化到磁盘，需要持久化语义时还要考虑 fsync 等操作。

  • 04

    原图是帮助理解的简化模型：具体字段和内部路径会随内核、文件系统与 I/O 模式变化，例如 direct I/O 会绕开常规页缓存路径。

# Linux 常用命令补充

[[1.1 ls、echo、cd、head、tail、ps]] 和 [[1.2 cp、rm、chmod、vim、gcc]] 覆盖了目录浏览、文件复制删除和编译工具。本节补充剩下的高频命令：查看与移动文件（`cat`、`mv`、`mkdir`、`touch`）、搜索（`grep`、`find`）、进程控制（`kill`、`top`）、打包压缩（`tar`）、链接（`ln`）和磁盘内存查看（`df`、`du`、`free`）。

---

## cat 命令

`cat` 全称 *concatenate*（连接），作用是**把文件内容完整打印到终端**。它和 `head`/`tail` 的区别：`cat` 输出整个文件，适合看短文件；长文件用 `head`、`tail` 或分页器 `less`。

### 基本用法

```bash
# 查看单个文件
cat /etc/hostname

# 连接多个文件输出——这才是 cat 名字的由来
cat part1.txt part2.txt

# 合并多个文件写入新文件
cat part1.txt part2.txt > merged.txt
```

### 常用选项

| 选项 | 说明 |
|------|------|
| `-n` | 给所有行编号 |
| `-b` | 只给非空行编号 |
| `-A` | 显示不可见字符（行尾显示 `$`，制表符显示 `^I`），排查空白字符问题时有用 |

```bash
# 查看代码文件并带行号，方便对照编译器报错的行号
cat -n main.c

# 检查文件里是不是混入了 Windows 换行符（行尾会显示 ^M$）
cat -A script.sh
```

### 长文件用 less 代替

`cat` 一个几千行的日志会瞬间刷屏。`less` 是分页器，按页显示，支持上下滚动和搜索：

```bash
less /var/log/syslog
# 空格翻页，b 回翻，/关键词 搜索，n 跳到下一个匹配，q 退出
```

## mv 命令

`mv` 全称 *move*，作用是**移动文件/目录，或重命名**。Linux 没有单独的重命名命令，重命名就是"移动到同目录下的新名字"。

### 基本用法

```bash
# 重命名：old.txt 变成 new.txt
mv old.txt new.txt

# 移动文件到目录
mv report.txt ~/Documents/

# 移动并同时重命名
mv report.txt ~/Documents/report_2026.txt

# 移动多个文件到目录（最后一个参数必须是目录）
mv a.txt b.txt c.txt ~/backup/
```

### mv 与 cp 的关键区别

`mv` 在同一文件系统内只修改目录项，不复制数据，所以移动一个几十 GB 的文件也是瞬间完成；跨文件系统（比如从硬盘移到 U 盘）时才会真正复制再删除源文件。

### 常用选项

| 选项 | 说明 |
|------|------|
| `-i` | 目标已存在时提示确认，防止覆盖 |
| `-f` | 强制覆盖，不提示 |
| `-n` | 目标已存在时不覆盖（no-clobber） |

> [!warning] mv 默认直接覆盖
> `mv a.txt b.txt` 时如果 b.txt 已存在，会被直接覆盖且无法恢复。批量移动时建议加 `-i` 或 `-n`。

## mkdir 与 touch 命令

### mkdir：创建目录

`mkdir` 全称 *make directory*。

```bash
# 创建单个目录
mkdir my_project

# -p：递归创建多级目录，父目录不存在时一并创建
mkdir -p my_project/src/utils
# 没有 -p 时，如果 my_project/src 不存在，命令会报错

# 创建目录时指定权限
mkdir -m 700 private_dir
```

`-p` 还有一个特性：目录已存在时不报错。脚本里几乎总是用 `mkdir -p`，保证"目录存在"这个结果而不关心它之前是否存在。

### touch：创建空文件 / 更新时间戳

`touch` 的本职是**更新文件的访问和修改时间**，但它最常见的用法是创建空文件——因为文件不存在时它会创建一个。

```bash
# 创建空文件
touch notes.txt

# 一次创建多个
touch a.c b.c c.c

# 只更新时间戳（文件已存在时）
touch Makefile
# make 依赖文件时间戳判断是否重新编译，touch 可以强制触发重编译
```

## grep 命令

`grep` 的作用是**在文件或输入流中按模式搜索文本行**，输出所有匹配的行。它是命令行下最重要的搜索工具，[[1.1 ls、echo、cd、head、tail、ps#3. 查看特定进程（与 grep 结合）|1.1 节的 ps 部分]]已经见过它与管道的配合。

### 基本用法

```bash
# 在文件中搜索包含 error 的行
grep "error" app.log

# 搜索多个文件
grep "main" *.c

# 从管道输入中过滤
ps aux | grep nginx
```

### 常用选项

| 选项 | 说明 |
|------|------|
| `-i` | 忽略大小写 |
| `-n` | 显示匹配行的行号 |
| `-r` | 递归搜索目录下所有文件 |
| `-v` | 反向匹配，输出**不包含**模式的行 |
| `-c` | 只输出匹配行数 |
| `-l` | 只输出包含匹配的文件名 |
| `-E` | 使用扩展正则表达式（等价于 `egrep`） |
| `-A n` / `-B n` | 同时输出匹配行之后/之前的 n 行上下文 |

### 常见组合

```bash
# 在整个项目里找一个函数在哪些文件出现过
grep -rn "connect_server" src/

# 看日志里的错误及其后 3 行上下文
grep -A 3 "ERROR" app.log

# 统计日志里 404 出现的次数
grep -c "404" access.log

# 过滤掉注释行和空行，只看配置文件的有效内容
grep -v "^#" nginx.conf | grep -v "^$"
```

**`-v` 的典型用途**：`ps aux | grep nginx` 的结果总会带上 grep 自身那一行，用 `grep -v grep` 过滤掉：

```bash
ps aux | grep nginx | grep -v grep
```

## find 命令

`grep` 搜的是**文件内容**，`find` 搜的是**文件本身**——按名字、类型、大小、修改时间在目录树里定位文件。

### 基本语法

```bash
find [起始目录] [条件] [动作]
```

### 按名字查找

```bash
# 在当前目录及子目录中找所有 .c 文件
find . -name "*.c"

# 忽略大小写
find . -iname "makefile"

# 在 /etc 下找 nginx 相关的配置
find /etc -name "nginx*"
```

### 按类型、大小、时间查找

```bash
# 只找目录（-type d）或只找普通文件（-type f）
find . -type d -name "build"

# 找大于 100MB 的文件——磁盘满了排查时最常用
find / -type f -size +100M 2>/dev/null

# 找最近 1 天内修改过的文件
find . -mtime -1

# 找 7 天前的日志
find /var/log -name "*.log" -mtime +7
```

`2>/dev/null` 把"权限不够"之类的报错丢弃，避免刷屏。

### 找到之后执行动作

`-exec` 对每个找到的文件执行命令，`{}` 是文件名占位符，`\;` 表示命令结束：

```bash
# 找到所有 .o 文件并删除
find . -name "*.o" -exec rm {} \;

# 把所有 .sh 脚本加上执行权限
find . -name "*.sh" -exec chmod +x {} \;
```

> [!warning] find 配合 rm 先看后删
> `find ... -exec rm` 一旦条件写错就是批量误删。先只跑 `find` 部分确认列表没问题，再加 `-exec rm`。

## kill 命令

`kill` 的作用是**向进程发送信号**。名字叫 kill，但它发的不一定是"杀死"——信号有很多种，只是默认发终止信号。进程的退出机制详见 [[5.2 结束进程]]。

### 基本用法

先用 `ps` 找到进程的 PID，再对 PID 发信号：

```bash
ps aux | grep my_server
# 假设查到 PID 是 12345

kill 12345        # 发送 SIGTERM（15），请求进程正常退出
kill -9 12345     # 发送 SIGKILL（9），强制杀死
```

### 常用信号

| 信号 | 编号 | 含义 |
|------|------|------|
| `SIGTERM` | 15 | 请求终止（默认）。进程可以捕获它，做清理后退出 |
| `SIGKILL` | 9 | 强制终止。进程无法捕获、无法忽略，内核直接回收 |
| `SIGHUP` | 1 | 挂起。很多守护进程（如 nginx）约定收到它时重新加载配置 |
| `SIGINT` | 2 | 中断，等价于终端里按 `Ctrl+C` |
| `SIGSTOP` / `SIGCONT` | 19 / 18 | 暂停 / 恢复进程 |

```bash
# 查看所有信号列表
kill -l

# 让 nginx 重新加载配置而不停止服务
kill -HUP <nginx主进程PID>
```

### 先 TERM 再 KILL

正确的停进程顺序是先 `kill`（SIGTERM）给进程机会保存数据、关闭文件、释放资源；等几秒还没退出，再 `kill -9`。上来就 `-9` 可能留下没写完的文件或没释放的共享内存。

### killall 与 pkill

按进程名直接操作，不用先查 PID：

```bash
killall my_server      # 杀死所有名为 my_server 的进程
pkill -f "python.*app" # 按完整命令行模糊匹配
```

## top 命令

`ps` 是进程的**快照**，`top` 是**实时刷新的监控面板**，默认每 3 秒刷新一次，按 CPU 占用排序。

```bash
top
```

界面上半部分是系统总览：负载（load average）、任务数、CPU 使用率分解（us 用户态、sy 内核态、id 空闲、wa 等 IO）、内存和交换分区用量。下半部分是进程列表。

### 交互按键

| 按键 | 作用 |
|------|------|
| `P` | 按 CPU 占用排序（默认） |
| `M` | 按内存占用排序 |
| `k` | 输入 PID 杀进程 |
| `1` | 展开显示每个 CPU 核心的占用 |
| `q` | 退出 |

排查"机器变卡"时的习惯路径：`top` 看是谁在吃 CPU/内存 → 记下 PID → `ps` 或 `/proc/PID/` 看详情 → 决定是否 `kill`。

## tar 命令

`tar` 全称 *tape archive*，作用是**把多个文件打包成一个文件，并可选压缩**。Linux 下发布源码、备份目录几乎都用它。

### 核心选项

| 选项 | 说明 |
|------|------|
| `-c` | 创建（create）归档 |
| `-x` | 解开（extract）归档 |
| `-t` | 列出（list）归档内容，不解压 |
| `-f` | 指定归档文件名，**必须紧跟文件名** |
| `-v` | 显示处理过程中的文件列表 |
| `-z` | 用 gzip 压缩/解压（对应 `.tar.gz`） |
| `-j` | 用 bzip2（对应 `.tar.bz2`） |
| `-C` | 解压到指定目录 |

### 最常用的三条命令

```bash
# 打包并 gzip 压缩一个目录
tar -czvf project.tar.gz my_project/

# 解压
tar -xzvf project.tar.gz

# 解压前先看看里面有什么，避免解出一堆散文件铺满当前目录
tar -tzvf project.tar.gz
```

记忆方法：`czf` = **c**reate + g**z**ip + **f**ile；`xzf` = e**x**tract + g**z**ip + **f**ile。

```bash
# 解压到指定目录
tar -xzvf project.tar.gz -C /opt/

# 只打包不压缩
tar -cvf backup.tar dir1/ dir2/
```

`.tar` 只是打包（多个文件合成一个，不减小体积），`.gz` 才是压缩。所以常见后缀 `.tar.gz` 的含义是"先 tar 打包，再 gzip 压缩"。

## ln 命令

`ln` 全称 *link*，作用是**给文件创建链接**。分硬链接和软链接（符号链接）两种，日常使用几乎都是软链接。

```bash
# 软链接（-s）：相当于 Windows 的快捷方式
ln -s /usr/local/gcc-13/bin/gcc ~/bin/gcc

# 硬链接（不加 -s）：同一份数据的另一个名字
ln data.txt data_hard.txt
```

### 两种链接的区别

| | 软链接 | 硬链接 |
|---|--------|--------|
| 本质 | 一个存着目标路径的特殊文件 | 目录里指向同一 inode 的另一个条目 |
| 跨文件系统 | 可以 | 不行 |
| 链接目录 | 可以 | 不行 |
| 原文件删除后 | 链接失效（悬空） | 数据仍在，直到所有硬链接都删除 |

`ls -l` 里第一列以 `l` 开头的就是软链接，并会显示指向：`gcc -> /usr/local/gcc-13/bin/gcc`。

软链接的典型用途是**版本切换**：程序装在 `/opt/app-2.3/`，再建一个 `/opt/app -> /opt/app-2.3` 的软链接，所有脚本都引用 `/opt/app`；升级时只需把链接指向新目录，不用改任何脚本。

## df、du、free 命令

三个查看资源用量的命令：`df` 看磁盘分区、`du` 看目录占用、`free` 看内存。都配 `-h`（human-readable）使用。

### df：磁盘分区剩多少

```bash
df -h
```

```
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1        50G   38G   10G  80% /
/dev/sda2       200G   85G  105G  45% /home
```

看 `Use%` 列，接近 100% 就要清理。程序报 "No space left on device" 时第一个命令就是它。

### du：这个目录占了多少

`df` 告诉你分区快满了，`du` 告诉你是谁占的：

```bash
# 当前目录下每个子目录的占用，-s 只显示汇总不递归展开
du -sh *

# 找出 /var 下最大的几个目录
du -h /var --max-depth=1 | sort -rh | head
```

`sort -rh` 按人类可读的大小（h）逆序（r）排序，配合 `head` 取前几名——这条组合是排查磁盘占用的标准流程。

### free：内存用了多少

```bash
free -h
```

```
              total        used        free      shared  buff/cache   available
Mem:           15Gi       4.2Gi       2.1Gi       310Mi       9.1Gi        10Gi
Swap:          2.0Gi          0B       2.0Gi
```

新手常见误解是看 `free` 列以为内存快用完了。Linux 会把空闲内存拿来做磁盘缓存（`buff/cache` 列），需要时随时释放。**真正能用的内存看 `available` 列**。

## 关键要点

- `cat`：打印整个文件，`-n` 带行号；长文件改用 `less` 分页
- `mv`：移动兼重命名，同文件系统内瞬间完成；默认覆盖同名文件，批量操作加 `-i`
- `mkdir -p`：递归建目录且已存在不报错；`touch`：建空文件或更新时间戳
- `grep`：搜文件内容，`-r` 递归、`-n` 行号、`-v` 反选、`-i` 忽略大小写
- `find`：搜文件本身，按名字/类型/大小/时间；`-exec` 对结果批量执行命令
- `kill`：发信号，默认 SIGTERM 请求退出，`-9` 强制；先 TERM 再 KILL
- `top`：实时监控，`P`/`M` 切换 CPU/内存排序
- `tar -czvf` 打包压缩，`tar -xzvf` 解压，`tar -tzvf` 先看内容
- `ln -s`：软链接，可跨文件系统、可链目录，常用于版本切换
- `df -h` 看分区、`du -sh *` 找占用大户、`free -h` 看内存（看 available 列）

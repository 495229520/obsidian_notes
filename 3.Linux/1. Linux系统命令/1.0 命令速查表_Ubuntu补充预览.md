# 1.0 Ubuntu Linux Shell 命令速查表

本表面向 Ubuntu 桌面版与 Ubuntu Server 的日常终端操作，以交互式 **Bash** 为主要环境。详细用法继续看已有笔记：[[1.1 ls、echo、cd、head、tail、ps]]、[[1.2 cp、rm、chmod、vim、gcc]]、[[1.3 cat、mv、mkdir、grep、find、kill、tar]]。

> [!info] 先区分 Bash、`sh` 与“终端命令”
> - Ubuntu 的默认登录/交互式 Shell 通常是 Bash；`/bin/sh` 通常链接到更精简、面向 POSIX 脚本的 Dash。
> - `cd`、`export`、`alias`、`jobs`、`fg`、`bg` 属于 Shell 内建命令；`ls`、`grep`、`apt`、`systemctl`、`ip` 等通常是外部程序。本表为了便于查询，统一称为“Shell/终端命令”。
> - 使用 Bash 专有语法的脚本应在第一行明确写 `#!/bin/bash`；写 `#!/bin/sh` 时不要使用 Bash 数组、`[[ ... ]]`、`source` 等 Bash 专有语法。
> - `echo "$SHELL"` 显示账号配置的登录 Shell，不一定就是当前正在运行的 Shell；确认当前 Shell 可用 `ps -p $$ -o comm=`。

> [!note] 最小化 Ubuntu Server 不一定预装全部工具
> 遇到 `command not found`，先执行 `command -v 命令名` 判断命令是否存在，再用 `apt search` 查找软件包。`tree`、`dig`、`zip`、`unzip`、`gdb`、`strace` 等在精简安装中可能需要另行安装。

## 0. 获取帮助与确认命令来源

| 命令 | 作用 | 最常用形式 |
|---|---|---|
| `type` | 判断名称是别名、内建命令、函数还是外部程序 | `type -a cd`、`type -a python3` |
| `command -v` | 输出实际会执行的命令路径；适合脚本检测依赖 | `command -v g++` |
| `man` | 查看系统手册 | `man systemctl`；`/关键词` 搜索、`n` 下一个、`q` 退出 |
| `--help` | 快速查看外部命令选项 | `grep --help` |
| `help` | 查看 Bash 内建命令帮助 | `help cd`、`help jobs` |
| `apropos` / `man -k` | 不知道命令名时按功能关键词搜索手册 | `apropos "copy files"` |
| `whatis` | 查看命令的一行简介 | `whatis tar` |

优先顺序可以记成：`type` 确认“它是谁” → `command -v` 确认“它在哪” → `man` 查完整语义。

## 1. 目录与文件浏览

| 命令 | 作用 | 最常用形式 |
|---|---|---|
| `ls` | 列出目录内容 | `ls -alh`（隐藏文件 + 详情 + 人类可读大小） |
| `cd` | 切换目录 | `cd ..` 上级、`cd ~` 主目录、`cd -` 上次目录 |
| `pwd` | 显示当前工作目录 | `pwd` |
| `cat` | 打印整个短文件 | `cat -n file`（带行号） |
| `less` | 分页查看长文件 | `less file`；`/` 搜索、`n` 下一个、`q` 退出 |
| `head` | 查看文件开头 | `head -n 20 file` |
| `tail` | 查看文件末尾或跟踪日志 | `tail -n 50 file`、`tail -F app.log` |
| `file` | 根据内容判断文件类型 | `file ./app` |
| `stat` | 查看大小、权限、inode、时间戳等元数据 | `stat file` |
| `realpath` | 将相对路径或软链接路径解析为绝对路径 | `realpath ../config` |
| `tree` | 树状显示目录；可能需要安装 | `tree -a -L 2` |

`tail -f` 只持续跟踪当前文件描述符；日志轮转后，通常用会重新打开同名文件的 `tail -F` 更稳妥。

## 2. 文件、目录与权限操作

| 命令 | 作用 | 最常用形式 |
|---|---|---|
| `cp` | 复制文件或目录 | `cp -a 源目录/ 目标目录/`（递归并尽量保留属性） |
| `mv` | 移动或重命名 | `mv -i old new`（覆盖前确认） |
| `rm` | 删除文件或目录 | `rm -ri 目录`；`rm -rf` **慎用** |
| `mkdir` | 创建目录 | `mkdir -p a/b/c` |
| `rmdir` | 删除空目录 | `rmdir empty_dir` |
| `touch` | 创建空文件或更新时间戳 | `touch file.cpp` |
| `ln` | 创建链接 | `ln -s 目标 链接名` |
| `chmod` | 修改权限位 | `chmod 755 script.sh`、`chmod +x script.sh` |
| `chown` | 修改所有者和所属组 | `sudo chown user:group file` |
| `chgrp` | 只修改所属组 | `sudo chgrp developers file` |
| `umask` | 查看或设置新文件的默认权限掩码 | `umask`、`umask 022` |

> [!warning] 删除与递归修改权限都不可自动撤销
> 执行 `rm -rf`、`chmod -R`、`chown -R` 前，先用 `pwd`、`realpath 目标`、`ls -ld 目标` 三步确认对象。变量参与路径拼接时尤其不要省略双引号。

### 2.1 用户身份与提权

| 命令 | 作用 | 最常用形式 |
|---|---|---|
| `whoami` | 显示当前有效用户名 | `whoami` |
| `id` | 显示 UID、GID 和附加组 | `id`、`id 用户名` |
| `groups` | 显示用户所属组 | `groups`、`groups 用户名` |
| `who` / `w` | 查看当前登录用户；`w` 还显示正在运行的命令 | `who`、`w` |
| `sudo` | 以授权身份执行单条管理命令 | `sudo systemctl restart nginx` |
| `sudo -i` | 进入 root 的登录 Shell；完成后及时 `exit` | `sudo -i` |
| `passwd` | 修改当前用户密码；管理员可指定用户 | `passwd`、`sudo passwd 用户名` |

Ubuntu 通常以 `sudo` 完成管理操作，不要为了省事长期停留在 root Shell，也不要给普通命令无差别添加 `sudo`。

## 3. 搜索文件与处理文本

### 3.1 搜索

| 命令 | 作用 | 最常用形式 |
|---|---|---|
| `grep` | 搜索文件内容 | `grep -rn "关键词" src/` |
| `find` | 按名称、类型、大小、时间等搜索文件 | `find . -type f -name "*.cpp"` |
| `locate` | 查询文件名数据库，速度快但结果可能不是实时；可能需要 `plocate` | `locate nginx.conf` |
| `pgrep` | 按进程名或命令行查 PID | `pgrep -af nginx` |

区分：找“哪个文件里写了 `connect_server`”用 `grep -rn`；找“`main.cpp` 在哪个目录”用 `find`；找正在运行的进程用 `pgrep`。

### 3.2 文本处理

| 命令 | 作用 | 最常用形式 |
|---|---|---|
| `wc` | 统计行数、单词数、字节数 | `wc -l file` |
| `sort` | 排序文本行 | `sort -n numbers.txt`、`sort -rh sizes.txt` |
| `uniq` | 合并相邻重复行，常与 `sort` 连用 | `sort file \| uniq -c \| sort -nr` |
| `cut` | 按分隔符或字符位置取列 | `cut -d: -f1 /etc/passwd` |
| `tr` | 字符替换、删除或压缩重复字符 | `tr '[:lower:]' '[:upper:]' < file` |
| `sed` | 按行筛选和替换文本 | `sed -n '1,20p' file` |
| `awk` | 按字段处理结构化文本 | `awk '{print $1}' file` |
| `xargs` | 把标准输入转换成后续命令的参数 | `find . -name "*.log" -print0 \| xargs -0 grep -n "ERROR"` |
| `tee` | 一边输出到终端，一边写文件 | `command \| tee output.log`；`tee -a` 追加 |
| `diff` | 比较两个文本文件 | `diff -u old.conf new.conf` |

`uniq` 只合并**相邻**重复行，所以统计重复项时通常要先 `sort`。处理文件名时优先使用 `find -print0 | xargs -0`，避免空格和换行破坏参数边界。

## 4. 进程、信号与 Shell 作业控制

| 命令 / 按键 | 作用 | 最常用形式 |
|---|---|---|
| `ps` | 查看进程快照 | `ps aux`、`ps -ef` |
| `pgrep` | 按名称查 PID 和命令行 | `pgrep -af 进程名` |
| `top` | 实时查看 CPU、内存与进程 | `top`；`P` 按 CPU、`M` 按内存、`q` 退出 |
| `kill` | 向 PID 发送信号 | `kill PID`（SIGTERM）；最后才用 `kill -9 PID` |
| `pkill` | 按名称或命令行模式发送信号 | `pkill -TERM nginx` |
| `killall` | 按可执行文件名发送信号 | `killall 进程名` |
| `jobs` | 查看**当前 Shell**启动的后台/暂停作业 | `jobs -l` |
| `命令 &` | 在后台启动命令 | `sleep 60 &` |
| `Ctrl+Z` | 暂停当前前台作业 | 暂停后可执行 `bg` 或 `fg` |
| `bg` | 让暂停作业在后台继续 | `bg %1` |
| `fg` | 把后台/暂停作业移到前台 | `fg %1` |
| `nohup` | 忽略终端挂断信号，适合临时长任务 | `nohup ./app >app.log 2>&1 &` |
| `wait` | 等待当前 Shell 的后台子任务完成 | `wait`、`wait %1` |
| `watch` | 周期性重复执行命令 | `watch -n 2 'ss -s'` |
| `timeout` | 超时后终止命令 | `timeout 10s ./app` |
| `nice` / `renice` | 启动时或运行中调整 CPU 调度 nice 值 | `nice -n 10 command`、`sudo renice 5 -p PID` |

`jobs` 只能看到当前 Shell 的作业，不等于系统全部进程；系统级查找用 `ps` 或 `pgrep`。生产服务不应长期依赖 `nohup`，应交给 `systemd` 管理。

## 5. Ubuntu 软件包管理

### 5.1 APT

| 命令 | 作用 |
|---|---|
| `sudo apt update` | 刷新软件包索引，不会直接升级已安装软件 |
| `apt list --upgradable` | 查看可升级的软件包 |
| `sudo apt upgrade` | 安装可用升级；执行前阅读变更列表 |
| `apt search 关键词` | 搜索软件包 |
| `apt show 包名` | 查看版本、依赖和描述 |

## 6. systemd 服务与系统日志

Ubuntu 的系统服务通常由 `systemd` 管理，首选 `systemctl`，不要把旧式 `service` 命令当作主要接口。

### 6.1 服务管理

| 命令 | 作用 |
|---|---|
| `systemctl status nginx` | 查看服务状态及最近日志 |
| `sudo systemctl start nginx` | 立即启动服务 |
| `sudo systemctl stop nginx` | 立即停止服务 |
| `sudo systemctl restart nginx` | 重启服务 |
| `sudo systemctl reload nginx` | 请求服务重新加载配置；服务必须支持 reload |
| `sudo systemctl enable nginx` | 设置开机启动，不代表立即启动 |
| `sudo systemctl enable --now nginx` | 设置开机启动并立即启动 |
| `systemctl is-active nginx` | 判断当前是否运行 |
| `systemctl is-enabled nginx` | 判断是否设置开机启动 |
| `systemctl --failed` | 查看启动失败的单元 |
| `sudo systemctl daemon-reload` | 修改 unit 文件后让 systemd 重新读取配置 |

### 6.2 日志

| 命令 | 作用 |
|---|---|
| `sudo journalctl -u nginx -n 100 --no-pager` | 查看某服务最近 100 条日志 |
| `sudo journalctl -u nginx -f` | 实时跟踪某服务日志 |
| `sudo journalctl -b` | 查看本次启动以来的日志 |
| `sudo journalctl -b -p warning` | 只看本次启动的 warning 及更严重日志 |
| `sudo journalctl --since "10 minutes ago"` | 按时间范围查看日志 |
| `sudo journalctl -k -b` | 查看本次启动的内核日志 |
| `sudo dmesg -T \| tail -n 50` | 快速查看最近内核消息 |
| `sudo journalctl --disk-usage` | 查看 journal 占用空间 |

排障顺序通常是：`systemctl status 服务` → `journalctl -u 服务` → 必要时再看 `journalctl -k` 或 `dmesg`。

## 7. 网络、端口与远程操作

现代 Ubuntu 优先使用 `iproute2` 工具：网络接口和路由用 `ip`，套接字用 `ss`。

| 命令 | 作用 | 最常用形式 |
|---|---|---|
| `ip` | 查看接口、地址、路由和邻居表 | `ip -br address`、`ip route`、`ip neigh` |
| `ss` | 查看监听端口和连接 | `sudo ss -lntup`、`ss -s` |
| `ping` | 测试 ICMP 可达性与往返时延 | `ping -c 4 1.1.1.1` |
| `getent hosts` | 按系统 NSS 配置解析主机名，更接近应用实际解析路径 | `getent hosts example.com` |
| `dig` | 直接查询 DNS；通常来自 `dnsutils` 包 | `dig +short example.com` |
| `curl` | 发送 HTTP 请求或下载 | `curl -I https://example.com`、`curl -fL -o file URL` |
| `wget` | 下载文件 | `wget -O file URL` |
| `ssh` | 加密远程登录 | `ssh user@host` |
| `ssh-keygen` / `ssh-copy-id` | 生成密钥并把公钥安装到远端 | `ssh-keygen -t ed25519`、`ssh-copy-id user@host` |
| `scp` | 通过 SSH 复制文件 | `scp file user@host:/path/` |
| `rsync` | 增量同步本地或远程目录 | `rsync -avh --progress src/ user@host:/path/` |
| `lsof` | 查看文件或端口被哪个进程占用 | `sudo lsof -iTCP:8080 -sTCP:LISTEN` |
| `hostnamectl` | 查看或设置主机名及系统摘要 | `hostnamectl` |
| `resolvectl` | 查看 systemd-resolved 的 DNS 状态 | `resolvectl status` |
| `ufw` | Ubuntu 常用防火墙前端 | `sudo ufw status verbose` |

`rsync` 的结尾斜杠有语义：`src/` 表示同步目录里的内容，`src` 表示把 `src` 目录本身放进目标。

> [!warning] 远程服务器启用 UFW 前先放行实际 SSH 端口
> 常见顺序是先 `sudo ufw allow OpenSSH`，确认规则后再 `sudo ufw enable`。如果 SSH 使用了非默认端口，应放行实际端口，否则可能把自己锁在服务器外。

### 7.1 现代 Ubuntu 中的首选替代

| 旧命令 / 习惯 | 现代首选 |
|---|---|
| `ifconfig` | `ip -br address`、`ip link` |
| `route -n` | `ip route` |
| `arp -n` | `ip neigh` |
| `netstat -lntp` | `ss -lntp` |
| `service nginx restart` | `sudo systemctl restart nginx` |
| 只用 `which 命令` 判断来源 | `type -a 命令` 或 `command -v 命令` |

旧命令并非在所有场景都立即失效，但现代 Ubuntu 的默认工具链、功能覆盖和文档都更偏向右侧命令。

| 命令 | 作用 | 最常用形式 |
|---|---|---|
| `df` | 查看文件系统容量与剩余空间 | `df -hT` |
| `du` | 统计目录或文件占用 | `du -sh *`、`sudo du -xhd1 /` |

| `free` | 查看内存与 swap | `free -h`，重点看 `available` |

```bash
df -hT
sudo du -xhd1 / 2>/dev/null | sort -h
sudo find / -xdev -type f -size +1G -printf '%s %p\n' 2>/dev/null \
  | sort -nr \
  | head
```

## 10. 输出、重定向、管道与 Shell 环境

### 10.1 文件描述符与重定向

| 写法 | 含义 |
|---|---|
| `命令 > file` | 标准输出覆盖写入文件 |
| `命令 >> file` | 标准输出追加到文件 |
| `命令 < file` | 从文件读取标准输入 |
| `命令 2> error.log` | 标准错误覆盖写入文件 |
| `命令 2>> error.log` | 标准错误追加到文件 |
| `命令 >all.log 2>&1` | 标准输出和标准错误都写入同一个文件 |
| `命令 >/dev/null 2>&1` | 丢弃标准输出和标准错误 |
| `前一命令 \| 后一命令` | 把前一命令的标准输出接到后一命令的标准输入 |
| `命令 \| tee file` | 输出既显示在终端，也写入文件 |

重定向按从左到右处理。`命令 >all.log 2>&1` 与 `命令 2>&1 >all.log` 不等价：后者的标准错误仍可能留在原终端。

### 10.2 命令组合与退出状态

| 写法 | 含义 |
|---|---|
| `cmd1 && cmd2` | `cmd1` 成功（退出状态为 0）才执行 `cmd2` |
| `cmd1 \|\| cmd2` | `cmd1` 失败才执行 `cmd2` |
| `cmd1 ; cmd2` | 无论前一条成功与否都继续执行 |
| `cmd &` | 后台执行 |
| `echo $?` | 查看上一条命令的退出状态 |
| `result=$(command)` | 命令替换：把输出保存到变量 |
| `VAR=value command` | 只为这一条命令设置环境变量 |

### 10.3 变量、环境、别名与历史

| 命令 | 作用 | 最常用形式 |
|---|---|---|
| `echo` | 打印文本或变量 | `echo "$HOME"` |
| `printf` | 可预测地格式化输出；脚本中比依赖 `echo -e` 更稳妥 | `printf '%s\n' "$value"` |
| `env` / `printenv` | 查看环境变量 | `printenv PATH` |
| `export` | 把 Shell 变量导出给子进程 | `export PATH="$HOME/bin:$PATH"` |
| `unset` | 删除变量或函数 | `unset NAME` |
| `source` / `.` | 在当前 Shell 中读取脚本 | `source ~/.bashrc`；POSIX 写法是 `. ~/.profile` |
| `alias` | 创建交互式别名 | `alias ll='ls -alF'` |
| `unalias` | 删除别名 | `unalias ll` |
| `history` | 查看命令历史 | `history 30` |
| `Ctrl+R` | 反向搜索历史命令 | 输入片段继续匹配 |
| `clear` | 清屏 | `clear` |
| `reset` | 终端显示异常时重新初始化 | `reset` |
| `exit` | 退出当前 Shell | `exit` |

引号规则：

| 写法 | 行为 |
|---|---|
| `'单引号'` | 内容基本按字面处理，不展开变量 |
| `"双引号"` | 展开 `$变量` 和 `$(命令)`，同时保留空格为一个参数 |
| `\字符` | 转义紧随其后的一个字符 |
| `*`、`?`、`[abc]` | 文件名通配；不是正则表达式 |

路径或变量可能含空格时，优先写 `"$path"`，不要写裸的 `$path`。

## 11. 开发、编译与排障工具

| 命令 | 作用 | 最常用形式 |
|---|---|---|
| `nano` | Ubuntu 常见的终端文本编辑器 | `nano file`；`Ctrl+O` 保存、`Ctrl+X` 退出 |
| `vim` | 文本编辑器 | `i` 插入，`Esc` 回命令模式，`:wq` 保存退出，`:q!` 放弃退出 |
| `gcc` | 编译 C | `gcc -std=c17 -Wall -Wextra main.c -o app` |
| `g++` | 编译 C++ | `g++ -std=c++17 -Wall -Wextra -Wpedantic main.cpp -o app` |
| `make` | 按 Makefile 构建 | `make -j"$(nproc)"` |
| `cmake` | 配置并构建 CMake 项目 | `cmake -S . -B build && cmake --build build -j"$(nproc)"` |
| `gdb` | 调试本地程序 | `gdb --args ./app arg1` |
| `strace` | 跟踪系统调用和信号 | `strace -f -o trace.log ./app` |
| `ldd` | 查看 ELF 程序依赖的共享库 | `ldd ./app` |
| `time` | 统计命令的实际、用户态和内核态耗时 | `time ./app` |
| `bash -n` | 只做 Bash 脚本语法检查，不执行 | `bash -n script.sh` |

> [!note] `gcc` 与 `g++` 不应混写
> `gcc` 是 C 编译驱动；C++ 示例优先使用 `g++`，它会按 C++ 方式处理源码并自动链接常用的 C++ 标准库。

## 12. 常见选项字母对照

同一个短选项在不同命令中含义不同，不能脱离具体命令死记。

### 12.1 `-n`

| 命令 | 含义 |
|---|---|
| `head -n 20` / `tail -n 20` | 指定显示的行数 |
| `grep -n` | 显示匹配行的行号 |
| `cat -n` | 给输出行编号 |
| `mv -n` / `cp -n` | 不覆盖已存在目标（no-clobber） |
| `echo -n` | 输出后不换行；可移植脚本更推荐 `printf` |
| `sort -n` | 按数值而不是字符串排序 |

### 12.2 `-f`

| 命令 | 含义 |
|---|---|
| `tail -f` | 持续跟踪文件新增内容（follow） |
| `rm -f` / `cp -f` / `mv -f` | 强制执行或不询问（force） |
| `tar -f` | 指定归档文件名 |
| `ps -ef` | `-e` 全部进程，`-f` 完整格式 |
| `strace -f` | 跟踪 `fork`/`clone` 创建的子进程或线程 |

### 12.3 `-r` / `-R`

| 命令 | 含义 |
|---|---|
| `cp -r` / `rm -r` | 递归处理目录 |
| `grep -r` | 递归搜索目录内容 |
| `sort -r` | 逆序排序（reverse） |
| `ls -R` | 递归列出子目录；这里通常用大写 `R` |

### 12.4 `-s` / `-S`

| 命令 | 含义 |
|---|---|
| `ln -s` | 创建符号链接（symbolic link） |
| `du -s` | 只显示汇总（summarize） |
| `ss -s` | 显示套接字统计摘要 |
| `gcc -S` / `g++ -S` | 编译到汇编文件，生成 `.s` |

### 12.5 `-i`

| 命令 | 含义 |
|---|---|
| `rm -i` / `cp -i` / `mv -i` | 操作前交互确认 |
| `grep -i` | 忽略大小写 |
| `ls -i` | 显示 inode 号 |
| `ss -i` | 显示 TCP 内部信息 |

### 12.6 `-h` / `-l` / `-c`

| 选项 | 命令 | 含义 |
|---|---|---|
| `-h` | `ls -lh` / `df -h` / `du -h` / `free -h` | 人类可读单位 |
| `-l` | `ls -l` | 长格式详情 |
| `-l` | `grep -l` | 只输出包含匹配内容的文件名 |
| `-c` | `head -c` / `tail -c` | 按字节数显示 |
| `-c` | `grep -c` | 输出匹配行数 |
| `-c` | `gcc -c` / `g++ -c` | 生成目标文件 `.o`，不执行链接 |
| `-c` | `tar -c` | 创建归档（create） |

## 13. 场景反查

| 我想…… | 用这个 |
|---|---|
| 确认当前实际运行的 Shell | `ps -p $$ -o comm=` |
| 判断一个名字是别名、内建命令还是程序 | `type -a 名字` |
| 找到某命令的可执行路径 | `command -v 命令` |
| 不知道命令名，只知道想做什么 | `apropos "关键词"` |
| 查看 Ubuntu 版本和内核版本 | `cat /etc/os-release`；`uname -r` |
| 安装一个软件包 | `sudo apt update && sudo apt install 包名` |
| 查看某个文件由哪个软件包提供 | `dpkg -S /完整/路径` |
| 看日志最新内容并持续跟踪 | 普通文件：`tail -F 日志`；服务：`sudo journalctl -u 服务 -f` |
| 检查服务为什么启动失败 | `systemctl status 服务` → `sudo journalctl -u 服务 -b` |
| 查看所有失败的 systemd 单元 | `systemctl --failed` |
| 在整个项目里找函数定义 | `grep -rn "函数名" src/` |
| 找某类文件 | `find . -type f -name "*.cpp"` |
| 找大于 1 GiB 的大文件 | `find /路径 -xdev -type f -size +1G` |
| 找出磁盘被什么占满 | `df -hT` → `sudo du -xhd1 /挂载点 \| sort -h` |
| 查看内存是否紧张 | `free -h`，重点看 `available` |
| 机器卡顿时看谁在吃 CPU/内存 | `top`，按 `P` 或 `M` |
| 精确查进程 | `pgrep -af 关键词` |
| 优雅停止程序 | `kill PID`；超时后再考虑 `kill -9 PID` |
| 把暂停任务放到后台继续 | `Ctrl+Z` → `bg %1` |
| 临时让任务退出终端后继续 | `nohup 命令 >任务.log 2>&1 &` |
| 查看本机 IP 和默认路由 | `ip -br address`；`ip route` |
| 查看谁在监听 8080 端口 | `sudo ss -lntp 'sport = :8080'` |
| 查看 8080 端口对应进程 | `sudo lsof -iTCP:8080 -sTCP:LISTEN` |
| 测试域名按系统配置能否解析 | `getent hosts example.com` |
| 查看 HTTP 响应头 | `curl -I https://example.com` |
| 登录远程服务器 | `ssh user@host` |
| 增量同步目录到服务器 | `rsync -avh --progress src/ user@host:/path/` |
| 把目录打包发送 | `tar -czf 名字.tar.gz 目录/` |
| 给脚本加执行权限并检查语法 | `chmod +x script.sh`；`bash -n script.sh` |
| 强制 Make 重新判断某源文件已修改 | `touch 该源文件` |
| 查看程序依赖哪些动态库 | `ldd ./app` |
| 跟踪程序调用了哪些系统调用 | `strace -f -o trace.log ./app` |

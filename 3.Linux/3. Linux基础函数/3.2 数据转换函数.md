# 3.2 数据转换函数

## 1. 简介

数据转换函数用于在**字符串表示**和**数值类型**之间转换。学习时要先区分两类问题：

1. 字符串能否按指定语法解析；
2. 解析出的值能否由目标类型表示。

| 用途 | C 头文件 | C++ 头文件 |
|---|---|---|
| `atoi`、`strtol`、`strtod` 等 | `<stdlib.h>` | `<cstdlib>` |
| `errno`、`ERANGE` | `<errno.h>` | `<cerrno>` |
| `INT_MAX`、`LONG_MAX` 等 | `<limits.h>` | `<climits>` 或 `<limits>` |
| `snprintf`、`printf` | `<stdio.h>` | `<cstdio>` |
| `std::to_string` | — | `<string>` |
| `std::from_chars`、`std::to_chars` | — | `<charconv>`（C++17） |
| `std::format` | — | `<format>`（C++20） |

> [!note] C 与 C++ 的名字
> C 程序使用 `<stdlib.h>` 中的 `strtol`；C++ 程序推荐包含 `<cstdlib>` 并写成 `std::strtol`。C++ 实现通常也会提供全局名字，但不应依赖这一点。

## 2. `atox` 系列：简单但不适合校验输入

### 2.1 函数原型

```cpp
double    std::atof(const char* str);
int       std::atoi(const char* str);
long      std::atol(const char* str);
long long std::atoll(const char* str); // C99；C++11
```

- `atoi`、`atol`、`atoll` 按十进制转换整数；
- `atof` 转换浮点数；
- 它们会跳过开头的空白，并允许一个可选的 `+` 或 `-`；
- 没有 `endptr`，无法判断转换停在何处；
- 转换失败时返回 `0`，但合法字符串 `"0"` 也返回 `0`；
- 结果超出返回类型可表示范围时，行为未定义，不能依赖 `errno` 检测。

> [!warning] 使用建议
> `atoi`、`atol`、`atoll`、`atof` 只适合已经确认格式和范围都正确的输入。需要校验用户输入、配置文件或网络数据时，应使用 `strto*`、C++ 的 `std::from_chars`，或带异常的 `std::stoi` 系列。

## 3. 字符串转整数：`strtol` 系列

### 3.1 函数原型与返回类型

```cpp
long               std::strtol (const char* str, char** endptr, int base);
long long          std::strtoll(const char* str, char** endptr, int base);
unsigned long      std::strtoul (const char* str, char** endptr, int base);
unsigned long long std::strtoull(const char* str, char** endptr, int base);
```

| 函数 | 返回类型 | 超出范围时的返回值 |
|---|---|---|
| `strtol` | `long` | `LONG_MIN` 或 `LONG_MAX` |
| `strtoll` | `long long` | `LLONG_MIN` 或 `LLONG_MAX` |
| `strtoul` | `unsigned long` | `ULONG_MAX` |
| `strtoull` | `unsigned long long` | `ULLONG_MAX` |

发生范围错误时，上述函数还会把 `errno` 设为 `ERANGE`。

### 3.2 参数顺序与解析规则

```cpp
std::strtol(str, endptr, base);
//             ↑       ↑
//          第二个    第三个参数
```

- `str`：待转换的、以 `\0` 结尾的字符串；不能是空指针；
- `endptr`：若不为 `nullptr`，函数把“第一个未转换字符”的地址写入 `*endptr`；
- `base`：`0`，或 `2`～`36`；它表示**进制**，不是小数位数；
- 函数跳过开头空白，读取可选符号，然后在第一个不属于该进制的字符处停止；
- 进制大于 10 时，`A/a` 表示 10，依次到 `Z/z` 表示 35。

`endptr` 可以传 `nullptr`，但这样会失去语法校验能力。例如：

```cpp
char* end = nullptr;
long value = std::strtol("123xyz", &end, 10);
// value == 123，end 指向 "xyz" 中的 'x'

long decimal = std::strtol("0.0123", &end, 10);
// decimal == 0，end 指向 '.'；整数函数不会解析小数部分
```

> [!warning] `endptr` 的两个必要检查
> `end == str` 表示一个数字都没有读到；`*end != '\0'` 表示只转换了前缀。判断“整个字符串都是合法数字”时，两项都要检查。严格检查还会拒绝尾部空白；若业务允许尾部空白，应显式跳过后再检查。

### 3.3 `base` 与 `base = 0`

| `base` | 规则 | 示例 |
|---|---|---|
| `2`～`36` | 按指定进制解析 | `"1010"`, `base=2` → `10` |
| `0` | `0x/0X` 前缀 → 16 进制 | `"0xFF"` → `255` |
| `0` | 前导 `0` → 8 进制 | `"077"` → `63` |
| `0` | 其他情况 → 10 进制 | `"123"` → `123` |

当 `base == 16` 时可以接受 `0x/0X` 前缀。C23 还规定二进制 `0b/0B` 前缀；Linux 的 glibc 从 2.38 开始在启用 C23 特性时支持它，但它不属于旧版 C/C++ 与 POSIX 的通用规则。需要兼容旧环境时，不要依赖 `0b` 自动识别。

> [!danger] 非法 `base`
> 只传 `0` 或 `2`～`36`。Linux/glibc 通常对非法 `base` 设置 `errno = EINVAL`，但这不是判断普通输入格式错误的可移植方法；非法 `base` 本质上是调用方错误。

### 3.4 `errno`、`endptr` 与边界条件

| 情况 | 返回值 | `endptr` | `errno` |
|---|---|---|---|
| 成功 | 转换结果 | 指向第一个未转换字符 | 不会替你清除旧值 |
| 没有任何数字 | `0` | `end == str` | 不应依赖其值判断此情况 |
| 只转换了前缀 | 已转换的前缀值 | 指向剩余字符 | 通常不变 |
| 有符号结果过小/过大 | 类型最小值/最大值 | 指向数字之后 | `ERANGE` |
| 无符号结果过大 | 类型最大值 | 指向数字之后 | `ERANGE` |

由于 `0`、`LONG_MIN`、`LONG_MAX` 等都可能是合法结果，不能只看返回值。正确顺序是：

1. 调用前执行 `errno = 0`，避免读到旧错误；
2. 调用后先检查 `end == str`；
3. 再检查 `errno == ERANGE`；
4. 若要求完整转换，再检查 `*end == '\0'`；
5. 若还要缩窄到 `int` 等更小类型，继续检查目标类型范围。

```cpp
#include <cerrno>
#include <cstdlib>

bool parse_long(const char* text, int base, long& result)
{
    if (text == nullptr || (base != 0 && (base < 2 || base > 36))) {
        return false;
    }

    errno = 0;
    char* end = nullptr;
    const long value = std::strtol(text, &end, base);

    if (end == text) {          // 没有读到任何数字
        return false;
    }
    if (errno == ERANGE) {      // 超出 long 的范围
        return false;
    }
    if (*end != '\0') {        // 存在未转换字符
        return false;
    }

    result = value;
    return true;
}
```

上面的函数允许前导空白，因为这是 `strtol` 的标准语法；若输入格式禁止前导空白，应在调用前额外检查。

把结果缩窄为 `int` 时，必须再检查一次：

```cpp
#include <limits>

if (value < std::numeric_limits<int>::min() ||
    value > std::numeric_limits<int>::max()) {
    // value 能放进 long，但不能放进 int
}
```

### 3.5 `strtoul` / `strtoull` 会接受负号

无符号转换函数也允许可选的 `-`。如果原始数值没有发生范围溢出，负号会按无符号运算规则作用到结果上：

```cpp
char* end = nullptr;
errno = 0;
unsigned long value = std::strtoul("-1", &end, 10);
// 标准规定：value == ULONG_MAX，errno 仍可为 0
```

因此，`strtoul` 不是“自动拒绝负数”的校验器。业务上只允许非负输入时，应先跳过允许的前导空白，再显式拒绝 `-`。

## 4. 字符串转浮点数：`strtof`、`strtod`、`strtold`

### 4.1 函数原型

```cpp
float       std::strtof (const char* str, char** endptr);
double      std::strtod (const char* str, char** endptr);
long double std::strtold(const char* str, char** endptr);
```

浮点函数**没有 `base` 参数**。它们可以识别：

- 十进制浮点形式，如 `-123.456`、`1.2e3`；
- 十六进制浮点形式，如 `0x1.8p+1`；
- `INF` / `INFINITY`；
- `NAN`，以及实现支持的 `NAN(...)` 形式；
- 当前 locale 规定的小数点字符，因此解析协议数据时通常应固定使用 `C` locale，或使用不受 locale 影响的 `std::from_chars`。

### 4.2 错误与边界

| 情况 | 返回值 | 检查方式 |
|---|---|---|
| 没有任何转换 | `0` | `end == str` |
| 只转换了前缀 | 已转换值 | `*end != '\0'` |
| 上溢 | `±HUGE_VALF`、`±HUGE_VAL` 或 `±HUGE_VALL` | `errno == ERANGE` |
| 下溢 | 绝对值很小的结果，可能是次正规数或 `0` | `errno == ERANGE` |

```cpp
#include <cerrno>
#include <cmath>
#include <cstdlib>

bool parse_finite_double(const char* text, double& result)
{
    if (text == nullptr) {
        return false;
    }

    errno = 0;
    char* end = nullptr;
    const double value = std::strtod(text, &end);

    if (end == text || errno == ERANGE || *end != '\0') {
        return false;
    }
    if (!std::isfinite(value)) { // 按业务要求拒绝 inf 和 nan
        return false;
    }

    result = value;
    return true;
}
```

> [!note]
> `strtod("0.0123456799", &end)` 才是正确的小数字符串转换。使用 `strtol` 会在小数点处停止。

## 5. C++ 的字符串转数值接口

### 5.1 `std::stoi` 系列（C++11）

`<string>` 提供：

```cpp
std::stoi   std::stol   std::stoll
std::stoul  std::stoull
std::stof   std::stod   std::stold
```

- 无法转换时抛出 `std::invalid_argument`；
- 超出目标类型范围时抛出 `std::out_of_range`；
- 整数函数可接收 `base`，规则与对应的 `strto*` 函数一致；
- 可通过 `std::size_t* pos` 获得第一个未转换字符的位置；若不检查 `pos`，`std::stoi("123abc")` 仍会成功返回 `123`；
- `std::stoul` / `std::stoull` 同样不能自动拒绝负号。

### 5.2 `std::from_chars`（C++17）

`std::from_chars` 不分配内存、不抛异常、不依赖 locale，适合严格解析和高性能路径。它通过返回值中的 `ptr` 和 `ec` 报告位置与错误。

与 `strto*` 相比要注意：整数版本只接受 `2`～`36`，不支持 `base = 0`；不跳过前导空白，不接受前导 `+`，也不会把 `0x` 当作十六进制前缀。调用者应明确检查 `ec` 以及 `ptr == last`。

## 6. 数值转字符串

### 6.1 C：`snprintf`

`printf` 是格式化输出函数，不会返回字符串；它返回成功写出的字符数，失败时返回负数。要写入字符数组，应使用有容量限制的 `snprintf`，避免无边界的 `sprintf`。

```c
#include <stdio.h>

char buffer[64];
int n = snprintf(buffer, sizeof buffer, "%lld %.2f", 1234LL, 3.14159);

if (n < 0) {
    /* 编码或输出错误 */
} else if ((size_t)n >= sizeof buffer) {
    /* 输出被截断；n 是完整输出原本需要的字符数，不含结尾 '\0' */
} else {
    /* buffer 中是完整且以 '\0' 结尾的字符串 */
}
```

常用格式符必须与实参的实际类型匹配；可变参数不会替你修正类型，类型不匹配会导致未定义行为。

| 格式符 | `printf` 期望的类型 | 说明 |
|---|---|---|
| `%d` / `%i` | `int` | 有符号十进制整数 |
| `%u` | `unsigned int` | 无符号十进制整数 |
| `%x` / `%X` | `unsigned int` | 十六进制整数 |
| `%o` | `unsigned int` | 八进制整数 |
| `%ld` / `%lu` | `long` / `unsigned long` | 长整型 |
| `%lld` / `%llu` | `long long` / `unsigned long long` | 长长整型 |
| `%f` / `%e` / `%g` | `double` | `float` 传入可变参数时会提升为 `double` |
| `%Lf` / `%Le` / `%Lg` | `long double` | 长双精度浮点数 |
| `%zu` | `size_t` | 大小或长度 |

固定宽度整数（如 `int64_t`）应使用 `<inttypes.h>` 中的 `PRId64` 等宏，不要假定它一定对应 `%ld` 或 `%lld`。

宽度与精度示例：

```c
printf("%10d", 100);      // 右对齐，最小宽度 10
printf("%-10d", 100);     // 左对齐，最小宽度 10
printf("%010d", 100);     // 用 0 填充，最小宽度 10
printf("%.2f", 3.14159);  // 3.14
printf("%10.2f", 3.14);   // 最小宽度 10，小数点后 2 位
```

### 6.2 C++：`std::to_string`、`std::format`、`std::to_chars`

```cpp
#include <format>
#include <string>

std::string a = std::to_string(1234);                     // "1234"
std::string b = std::format("{:#x} {:.2f}", 255, 3.14159); // "0xff 3.14"
```

- `std::to_string`（C++11）最方便，但格式控制很少；浮点格式在 C++26 发生过标准语义变化，不应依赖它得到固定小数位；
- `std::format`（C++20）适合需要可读格式说明的普通 C++ 代码；
- `std::ostringstream`（`<sstream>`）适合需要流式组合或 locale 格式的场景；
- `std::to_chars`（C++17）不分配内存、不依赖 locale，适合高性能或需要明确错误码的场景。

```cpp
#include <charconv>
#include <string>

char buffer[32];
auto [ptr, ec] = std::to_chars(buffer, buffer + sizeof buffer, 255, 16);

if (ec == std::errc{}) {
    std::string text(buffer, ptr); // "ff"
}
```

`std::to_chars` 不会自动补 `\0`；成功时，`ptr` 指向最后一个已写字符之后。缓冲区不足时，`ec == std::errc::value_too_large`。

> [!warning] 非标准函数
> `itoa`、`ltoa` 等不是 ISO C/C++ 标准函数，可移植代码不要依赖它们。

## 7. 修正后的完整示例

```cpp
#include <cerrno>
#include <cstdlib>
#include <iomanip>
#include <iostream>

int main()
{
    char* end = nullptr;

    errno = 0;
    const long decimal = std::strtol("1234", &end, 10);
    std::cout << "decimal=" << decimal << ", rest=\"" << end << "\"\n";

    errno = 0;
    const long binary = std::strtol("1010", &end, 2);
    std::cout << "binary=" << binary << ", rest=\"" << end << "\"\n";

    errno = 0;
    const long automatic = std::strtol("0xFF", &end, 0);
    std::cout << "automatic=" << automatic << ", rest=\"" << end << "\"\n";

    errno = 0;
    const double floating = std::strtod("-123.456789", &end);
    std::cout << std::setprecision(12)
              << "floating=" << floating << ", rest=\"" << end << "\"\n";

    errno = 0;
    const long partial = std::strtol("10#$#@", &end, 10);
    std::cout << "partial=" << partial << ", rest=\"" << end << "\"\n";

    return 0;
}
```

预期关键结果：

```text
decimal=1234, rest=""
binary=10, rest=""
automatic=255, rest=""
floating=-123.456789, rest=""
partial=10, rest="#$#@"
```

## 8. 关键要点

- `base` 是进制；只有整数 `strto*` 函数有 `base` 参数；
- 参数顺序固定为 `str`、`endptr`、`base`；
- `end == str` 判断“没有读到数字”，`*end == '\0'` 判断“没有剩余字符”；
- 调用前清零 `errno`，调用后用 `errno == ERANGE` 判断范围错误；
- 成功返回值可能恰好是 `0`、最小值或最大值，不能只看返回值；
- `base = 0` 会自动识别十六进制和八进制前缀，二进制 `0b` 的可移植性要单独确认；
- `strtoul`、`strtoull` 以及 `std::stoul`、`std::stoull` 都可能接受负号；
- `atoi` 系列不能可靠报告错误，不应用于不可信输入；
- 数值转字符串时，C 优先用 `snprintf`，C++ 可按需求选择 `std::to_string`、`std::format` 或 `std::to_chars`；
- `printf` 格式符必须与实参类型匹配，`itoa` 不是标准函数。

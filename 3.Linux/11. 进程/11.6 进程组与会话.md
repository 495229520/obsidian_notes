## 1. 简介

在终端里敲一句 `ls | grep foo | wc -l`，起来的是三个进程。按一下 Ctrl+C，三个要一起停；用 `fg`/`bg` 挪动，三个要一起挪。

内核没法凭「它们看起来像一条命令」认出这个整体，所以在 PID 之上又加了一层身份：**进程组**（Process Group）。同一条管道里的进程共用一个 PGID，于是它们就成了一个可以被整体寻址的目标。再往上还有一层**会话**（Session），对应一次登录或一个终端窗口。

这一节讲的就是这两层身份怎么读、怎么改，以及它们撑起了 shell 的哪些功能。

---

## 2. 三层身份：进程、进程组、会话

![[图片/SVG/3_11_11_6_1.svg|1307]]

图 A 里三层的范围是层层放大的：**PID 认一个进程，PGID 认一个作业，SID 认一次登录**。

### 2.1 相关术语

| 术语 | 英文 | 含义 |
|------|------|------|
| PID | Process ID | 进程标识符，每个进程唯一 |
| PPID | Parent Process ID | 父进程的 PID |
| PGID | Process Group ID | 进程组标识符 |
| SID | Session ID | 会话标识符 |
| 进程组长 | Process Group Leader | PGID 等于自己 PID 的那个进程 |
| 会话首进程 | Session Leader | SID 等于自己 PID 的那个进程 |

### 2.2 两条不变量

看图时抓住这两条就不会乱：

1. **PGID 就是组长的 PID，SID 就是会话首进程的 PID。** 所以「新建一个组」等价于「让某个进程的 PGID 等于它自己的 PID」，这就是 `setpgid(0, 0)` 在做的事。
2. **组长退出，组不解散。** 只要组里还有别的成员，PGID 就一直有效，也不会换成别人的 PID。上面例子里 `ls` 先跑完，`grep` 和 `wc` 仍然留在 4712 这个组里。

### 2.3 一个终端会话里有什么

图 A 的会话框里三样东西缺一不可：

- **一个控制终端**：会话最多挂一个，也可以一个都没有（守护进程就是这种）
- **一个前台进程组**：同一时刻只有一个，终端产生的信号只发给它
- **任意多个后台进程组**：`&` 起来的每个作业各占一个

### 2.4 进程组解决的三件事

1. **信号可以打中一批**：`kill(-pgid, SIGTERM)` 一次通知整组
2. **作业控制**：shell 用组来表示「一个作业」，`fg`/`bg`/`jobs` 操作的都是组
3. **终端归属**：终端只认前台组，后台组去读它会被停住（见第 7 节）

## 3. 读：getpgrp / getpgid / getsid

### 3.1 getpgrp() - 取自己的 PGID

```c
#include <unistd.h>

pid_t getpgrp(void);
```

- **返回值**：调用进程的 PGID。这个函数没有失败路径，不用检查返回值

### 3.2 getpgid() - 取指定进程的 PGID

```c
#include <unistd.h>

pid_t getpgid(pid_t pid);
```

- **参数**：目标进程的 PID，传 `0` 表示自己
- **返回值**：成功返回 PGID，失败返回 -1（`ESRCH` 查无此进程）

`getpgid(0)` 和 `getpgrp()` 完全等价。

### 3.3 getsid() - 取所在会话的 SID

```c
#include <unistd.h>

pid_t getsid(pid_t pid);
```

同样是传 `0` 表示自己。判断一个进程是不是会话首进程，看 `getsid(0) == getpid()` 即可。

### 3.4 代码示例

```c
#include <stdio.h>
#include <unistd.h>

int main() {
    pid_t pid = getpid();
    pid_t ppid = getppid();
    pid_t pgid = getpgrp();
    pid_t pgid2 = getpgid(0);  // 等同于 getpgrp()

    printf("PID:  %d\n", pid);
    printf("PPID: %d\n", ppid);
    printf("PGID: %d (getpgrp)\n", pgid);
    printf("PGID: %d (getpgid)\n", pgid2);

    return 0;
}
```

从 shell 直接跑这个程序，会看到 PID 和 PGID 相等：shell 启动一个作业时会把它放进一个新进程组，这个程序自己就是组长。把它塞进管道（比如 `./a.out | cat`）再跑，PGID 就会变成管道里第一个进程的 PID。

命令行上看同样的信息用 `ps -o pid,ppid,pgid,sid,tpgid,comm`，最后那个 `tpgid` 是该终端当前的前台进程组。

## 4. 写：setpgid

### 4.1 函数原型

```c
#include <unistd.h>

int setpgid(pid_t pid, pid_t pgid);
```

### 4.2 参数说明

| 参数 | 含义 |
|------|------|
| `pid` | 目标进程的 PID，传 0 表示当前进程 |
| `pgid` | 新的进程组 ID，传 0 表示用 `pid` 的值当 PGID |

两个参数都能传 0，所以 `setpgid(0, 0)` 的意思是「把我自己变成一个新组的组长」。

### 4.3 返回值

| 返回值 | 含义 |
|--------|------|
| `0` | 成功 |
| `-1` | 失败，看 `errno` |

### 4.4 常见用法

```c
// 把当前进程变成新进程组的组长
setpgid(0, 0);

// 把子进程拉进父进程所在的组
setpgid(child_pid, getpgrp());

// 把某个子进程移到指定的组
setpgid(pid, target_pgid);
```

### 4.5 限制条件

四条限制，对应四个 `errno`：

| 限制 | 违反时的 errno |
|------|------|
| 只能改自己或自己的**子进程**，孙进程和别人的进程都不行 | `ESRCH` |
| 子进程一旦调用了 `exec`，父进程就改不动它了 | `EACCES` |
| 目标组必须在**同一个会话**里 | `EPERM` |
| 会话首进程不能换组 | `EPERM` |

第二条的存在是有道理的：子进程 `exec` 之后跑的是另一个程序，那个程序可能自己也在管进程组。内核在 `exec` 处划一条线，避免父进程在它背后改动。

### 4.6 谁来调用：父子两边都要调一次

这是最容易写错的地方。`fork()` 之后父子谁先跑没有保证，如果只让子进程自己调 `setpgid(0, 0)`，父进程可能在它还没调之前就去用新的 PGID 了。

用 `sleep(1)` 等一下**不是解决办法**，那只是把竞态窗口缩小，机器负载一高照样翻车。正确写法是**两边各调一次**：

```c
pid_t pid = fork();
if (pid == 0) {
    setpgid(0, 0);           // 子进程给自己设
    // ...
    execvp(...);
} else {
    setpgid(pid, pid);       // 父进程也给子进程设一次
    // 这里可能返回 -1 且 errno == EACCES，说明子进程已经 exec 了，
    // 也就说明它自己那次调用早就成功了，忽略即可
}
```

两次调用的目标状态完全一样，谁先跑到谁生效，另一次要么是空操作要么合理失败。竞态就这么消掉了，不需要任何等待。shell 启动作业时用的就是这个写法。

## 5. setpgrp() 和 setsid()

### 5.1 setpgrp()：别用

```c
#include <unistd.h>

int setpgrp(void);                        // System V / POSIX，等价于 setpgid(0, 0)
int setpgrp(pid_t pid, pid_t pgid);       // BSD，等价于 setpgid(pid, pgid)
```

同一个名字在两套传统里是**两个不同签名的函数**。glibc 按你定义的特性宏挑一个：默认给 System V 那版，定义了 `_BSD_SOURCE` 且没定义 `_POSIX_SOURCE` 时给 BSD 那版。

移植时踩的坑正是这里，所以直接写 `setpgid()` 就好，多打几个字换来签名确定。

### 5.2 setsid()：另起一个会话

```c
#include <unistd.h>

pid_t setsid(void);
```

调用成功之后，一次性发生三件事：

1. 调用者成为**新会话的会话首进程**，SID 等于它的 PID
2. 调用者成为**新进程组的组长**，PGID 也等于它的 PID
3. 调用者**丢掉控制终端**

**失败条件只有一个**：调用者已经是某个进程组的组长，返回 -1 并置 `EPERM`。原因是会话首进程必须同时是新组的组长，而一个已经是组长的进程改不了自己的 PGID（第 3 节最后一条限制）。

绕开的办法是先 `fork` 一次，让子进程去调用。子进程的 PGID 继承自父进程，肯定不等于自己的 PID，所以不是组长：

```c
if (fork() > 0)
    exit(0);        // 父进程退出，子进程被 init 收养，且保证不是组长
setsid();           // 这下一定成功
```

第 3 点是守护进程的关键：脱离控制终端之后，Ctrl+C 打不到它，终端关闭时的 `SIGHUP` 也轮不到它，进程从此和登录会话彻底无关。

## 6. 向整组发信号

![[图片/SVG/3_11_11_6_2.svg|1307]]

### 6.1 kill 的第一个参数是带符号的

`kill()` 靠 `pid` 的符号区分四种目标，这是本节最容易记错的地方：

| pid | 目标 | 备注 |
|-----|------|------|
| `> 0` | 就那一个进程 | 最常用 |
| `== 0` | 调用者自己所在的整个组 | 包括调用者本身 |
| `< -1` | PGID 等于 `-pid` 的整个组 | Ctrl+C 走的就是这条 |
| `== -1` | 所有有权限发的进程 | Linux 上只放过 init(1) |

中间两行是事故高发区。变量忘了赋值留成 0，`kill(0, SIGKILL)` 就把自己和同组的伙伴一起杀了；把某个返回 -1 的错误码直接当 pid 传进去，在 root 下跑一次基本等于关机。

### 6.2 killpg()：把符号写成名字

```c
#include <signal.h>

int killpg(pid_t pgrp, int sig);
```

`killpg(pgid, sig)` 就是 `kill(-pgid, sig)`，只是意图写在了函数名里，读代码的人不用再去分辨那个负号是笔误还是故意的。`pgrp` 传 0 表示自己所在的组。

### 6.3 组内谁都收到

向组发信号是**一次投递**，不是库函数替你循环调 `kill`。组里每个进程各自按自己的处置方式响应：装了处理函数的走处理函数，没装的走默认动作，屏蔽了的挂起。所以同一个信号在组内不同进程上表现不同是正常的。

## 7. 实际应用示例

### 7.1 创建新进程组

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main() {
    pid_t pid;
    pid_t parent_pgid = getpgrp();

    printf("Parent Process: PID %d, PGID %d\n", getpid(), parent_pgid);

    pid = fork();

    if (pid < 0) {
        perror("fork");
        exit(1);
    } else if (pid == 0) {
        // 子进程：创建新的进程组
        setpgid(0, 0);  // 成为新进程组的组长
        printf("Child Process: PID %d, PGID %d (new group)\n",
               getpid(), getpgrp());

        // 再创建一个孙进程
        pid_t grandchild = fork();
        if (grandchild == 0) {
            printf("Grandchild Process: PID %d, PGID %d\n",
                   getpid(), getpgrp());
            exit(0);
        }
        wait(NULL);
        exit(0);
    } else {
        // 父进程
        sleep(1);  // 等待子进程设置完成
        printf("Child's PGID from parent view: %d\n", getpgid(pid));
        wait(NULL);
    }

    return 0;
}
```

### 7.2 运行结果

```
Parent Process: PID 12345, PGID 12345
Child Process: PID 12346, PGID 12346 (new group)
Grandchild Process: PID 12347, PGID 12346
Child's PGID from parent view: 12346
```

输出里有两处对应着前面的规则。

孙进程那行印证了 PGID 的继承：它没调过任何 `setpgid`，PGID 12346 是从父进程（也就是子进程）那里继承来的。所以子进程建组之后，它 `fork` 出来的后代自动都在这个新组里，不需要挨个设置。

父进程那行 `sleep(1)` 就是上一节说的反面写法。这里能跑出正确结果，靠的是子进程能在 1 秒内跑完 `setpgid`，而不是靠任何保证。改成第 3 节那个父子各调一次的写法，`sleep` 就可以删掉了。

### 7.3 向进程组发送信号

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <signal.h>
#include <sys/wait.h>

void handler(int sig) {
    printf("Process %d received signal %d\n", getpid(), sig);
}

int main() {
    pid_t child1, child2;
    pid_t child_pgid;

    // 创建第一个子进程
    child1 = fork();
    if (child1 == 0) {
        setpgid(0, 0);  // 创建新进程组
        signal(SIGUSR1, handler);
        printf("Child1 (PID %d, PGID %d) waiting for signal...\n",
               getpid(), getpgrp());
        pause();
        exit(0);
    }

    sleep(1);
    child_pgid = getpgid(child1);

    // 创建第二个子进程，加入第一个子进程的进程组
    child2 = fork();
    if (child2 == 0) {
        setpgid(0, child_pgid);  // 加入 child1 的进程组
        signal(SIGUSR1, handler);
        printf("Child2 (PID %d, PGID %d) waiting for signal...\n",
               getpid(), getpgrp());
        pause();
        exit(0);
    }

    sleep(1);
    printf("Parent: Sending SIGUSR1 to process group %d\n", child_pgid);

    // 向整个进程组发送信号（负数 PGID）
    kill(-child_pgid, SIGUSR1);

    // 等待子进程结束
    wait(NULL);
    wait(NULL);

    printf("Parent: All children finished.\n");
    return 0;
}
```

### 7.4 运行结果

```
Child1 (PID 12346, PGID 12346) waiting for signal...
Child2 (PID 12347, PGID 12346) waiting for signal...
Parent: Sending SIGUSR1 to process group 12346
Process 12346 received signal 10
Process 12347 received signal 10
Parent: All children finished.
```

一次 `kill(-12346, SIGUSR1)` 打中两个进程，这就是进程组的价值。信号编号 10 是 x86 Linux 上的 `SIGUSR1`。

**第一行 `setpgid(0, 0)` 不能省。** 去掉它，两个子进程就还留在父进程的组里，`child_pgid` 拿到的是父进程的 PGID，`kill(-child_pgid, SIGUSR1)` 会把父进程一起打中。父进程没装 `SIGUSR1` 的处理函数，默认动作是终止，程序会直接死在那一行。给自己建一个新组，本质上是在划一条边界，把「要一起收信号的」和「不该被波及的」分开。

例子里 `handler` 中调了 `printf`，只是为了看清效果。`printf` 不是异步信号安全的函数，真实代码里不能这么写，理由和处理 SIGCHLD 时一样（见 [[11.4 等待与回收#7. 三种回收姿势|11.4 第 6 节]]）。

## 8. 进程组与作业控制

### 8.1 Shell 作业控制示例

```bash
# 启动后台作业（创建新进程组）
$ sleep 100 &
[1] 12345

# 查看作业
$ jobs
[1]+  Running    sleep 100 &

# 将作业切换到前台
$ fg %1
sleep 100

# 按 Ctrl+Z 暂停（发送 SIGTSTP 给前台进程组）
^Z
[1]+  Stopped    sleep 100

# 在后台继续运行
$ bg %1
[1]+ sleep 100 &
```

`[1]` 是 shell 自己编的作业号，只在这个 shell 里有意义；`12345` 才是内核认的 PGID。`fg %1` 干的事就是查出作业 1 的 PGID，把它设成终端的前台组，再给它发一个 `SIGCONT`。

### 8.2 终端按键对应的信号

| 操作 | 信号 | 默认动作 | 目标 |
|------|------|----------|------|
| Ctrl+C | `SIGINT` | 终止 | 前台进程组 |
| Ctrl+Z | `SIGTSTP` | 停止 | 前台进程组 |
| `Ctrl+\` | `SIGQUIT` | 终止并转储 core | 前台进程组 |

三个都发给**整个前台进程组**，不是只发给某一个进程。键位不是写死的，`stty -a` 能看到当前绑定，`stty intr ^X` 能改。

### 8.3 前台进程组是终端的属性

图 B 的第 ② 步是理解作业控制的关键：**「谁在前台」这条信息记在终端里，不在进程里**。进程本身不知道自己是不是前台，内核在需要时拿终端里记的那个 PGID 去比对。

读写这个值的是这一对：

```c
#include <unistd.h>

pid_t tcgetpgrp(int fd);              // 取 fd 对应终端的前台进程组
int   tcsetpgrp(int fd, pid_t pgrp);  // 把某个组设为前台
```

`fg` 和 `bg` 的核心就是 `tcsetpgrp`。也正因为这个值是终端的属性，同一时刻一个终端只能有一个前台组，`fg` 才必须先把当前前台组换下去。

### 8.4 后台组碰终端会怎样

前后台的差别不止收不收信号，还包括能不能用终端（图 C）：

- **后台组去读终端**：内核发 `SIGTTIN`，整组停住。把 `cat` 丢到后台，`jobs` 里立刻显示 `Stopped (tty input)`，因为它一读 stdin 就被拦下了
- **后台组去写终端**：默认放行，所以后台任务的输出会直接糊在屏幕上。想拦住就 `stty tostop`，之后写终端会触发 `SIGTTOU` 把它停住

### 8.5 关掉终端之后

终端断开时（比如关掉 ssh 窗口），内核向**会话首进程**发 `SIGHUP`。bash 收到之后会把 `SIGHUP` 转发给它管的所有作业，然后自己退出，所以后台任务跟着一起没了。

绕开的办法都是在切断这条链路：`nohup` 让程序忽略 `SIGHUP`，`disown` 把作业从 bash 的作业表里摘掉，`setsid` 干脆另起一个会话。第三种最彻底，因为脱离会话之后这个 `SIGHUP` 从一开始就发不到它头上。

## 9. 总结

| 函数 | 功能 | 失败条件 |
|------|------|----------|
| `getpgrp()` | 取自己的 PGID | 不会失败 |
| `getpgid(pid)` | 取指定进程的 PGID | 进程不存在 |
| `getsid(pid)` | 取指定进程的 SID | 进程不存在 |
| `setpgid(pid, pgid)` | 设置自己或子进程的 PGID | 见第 3 节四条限制 |
| `setpgrp()` | 签名随平台变，别用 | 同上 |
| `setsid()` | 新建会话并脱离控制终端 | 调用者已是组长 |
| `tcgetpgrp(fd)` | 取终端当前的前台组 | fd 不是终端 |
| `tcsetpgrp(fd, pgrp)` | 设置终端的前台组 | fd 不是终端，或不同会话 |

---

## 10. 关键要点

- **三层身份的范围层层放大**：PID 认一个进程，PGID 认一个作业，SID 认一次登录。管道里的进程共用 PGID，才能被一次寻址
- **PGID 就是组长的 PID**，SID 就是会话首进程的 PID。组长退出后组不解散，PGID 也不换人
- 子进程 `fork` 时**同时继承 PGID 和 SID**，所以建完组之后的所有后代自动都在组里
- **`setpgid` 要父子各调一次**：目标状态相同，谁先跑到谁生效。用 `sleep` 等只是缩小竞态窗口，不是消除
- `setpgid` 的四条限制：只能改自己或子进程、子进程 `exec` 后改不动（`EACCES`）、必须同会话（`EPERM`）、会话首进程不能换组（`EPERM`）
- **`setsid()` 一次做三件事**：新建会话、新建进程组、丢掉控制终端。已经是组长会失败，所以守护进程要先 `fork` 一次再调
- **`kill` 的 pid 是带符号的**：`>0` 单个，`==0` 自己那组，`<-1` 指定组，`==-1` 几乎所有。`killpg(pgid, sig)` 是 `kill(-pgid, sig)` 的明确写法
- **前台进程组是终端的属性，不是进程的属性**，由 `tcsetpgrp()` 设置，`fg`/`bg` 改的就是它
- Ctrl+C / Ctrl+Z / `Ctrl+\` 都发给**整个前台进程组**；后台组读终端会被 `SIGTTIN` 停住
- 终端断开时 `SIGHUP` 发给会话首进程，由 bash 转发给各作业。`nohup`、`disown`、`setsid` 各在不同环节切断这条链

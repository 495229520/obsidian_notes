# 11.5 信号量 (Semaphore)

## 1. 什么是信号量

**信号量 (Semaphore)** 是一种用于[[11.2 进程间通信IPC|进程间同步]]的机制。与[[11.4 共享内存|共享内存]]和[[11.6 消息队列|消息队列]]不同，信号量**不用于传递数据**，而是用于**控制对共享资源的访问**。

> 信号量本质上是一个**非负整数计数器**，用于协调多个进程对共享资源的访问，从而避免竞态条件 (Race Condition)。

### 1.1 信号量的核心操作

信号量支持两种原子操作：

| 操作 | 别名 | 描述 |
|------|------|------|
| **P 操作** | wait / down / 申请 | 如果信号量 > 0，则减 1；否则阻塞等待 |
| **V 操作** | signal / up / 释放 | 信号量加 1，唤醒等待的进程 |

```
P 操作 (申请资源):
    if (semaphore > 0) {
        semaphore--;
        // 继续执行
    } else {
        // 阻塞等待
    }

V 操作 (释放资源):
    semaphore++;
    // 唤醒等待队列中的进程
```

## 2. 信号量的类型

### 2.1 二进制信号量 (Binary Semaphore)

二进制信号量的值只能是 **0** 或 **1**，功能类似于**互斥锁 (Mutex)**。

| 值 | 含义 |
|----|------|
| 1 | 资源可用（未被占用） |
| 0 | 资源不可用（已被占用） |

**使用场景**：保护临界区，确保同一时刻只有一个进程访问共享资源。

```c
// 伪代码示例
sem_wait(&sem);      // P 操作：获取锁
// 临界区代码
sem_post(&sem);      // V 操作：释放锁
```

### 2.2 计数信号量 (Counting Semaphore)

计数信号量的值可以是**任意非负整数**，表示可用资源的数量。

| 值 | 含义 |
|----|------|
| n > 0 | 有 n 个资源可用 |
| 0 | 没有资源可用，新请求将阻塞 |

**使用场景**：控制对有限资源池的访问（如数据库连接池、缓冲区槽位）。

```c
// 生产者-消费者模型中的缓冲区管理
#define BUFFER_SIZE 8

sem_t empty_slots;   // 空槽位数量
sem_t filled_slots;  // 已填充槽位数量

// 初始化计数信号量
sem_init(&empty_slots, 0, BUFFER_SIZE);  // 一开始有 BUFFER_SIZE 个空槽位
sem_init(&filled_slots, 0, 0);           // 一开始没有已填充槽位

// 生产者
sem_wait(&empty_slots);   // 等待空槽位
// 生产数据
sem_post(&filled_slots);  // 增加已填充数量

// 消费者
sem_wait(&filled_slots);  // 等待已填充槽位
// 消费数据
sem_post(&empty_slots);   // 增加空槽位数量
```

这里的“计数”不是由 `sem_t empty_slots;` 这一行声明出来的，而是由初始化时传入的初始值决定的。`empty_slots` 初始值是 `BUFFER_SIZE`，表示缓冲区一开始全是空槽；`filled_slots` 初始值是 `0`，表示一开始没有可消费的数据。

以 `BUFFER_SIZE = 8`，先生产 1 个数据、再消费 1 个数据为例，计数变化如下：

| 步骤 | 操作 | `empty_slots` | `filled_slots` | 含义 |
|------|------|---------------|----------------|------|
| 1 | 初始化 | 8 | 0 | 8 个槽位全是空的，没有数据可读 |
| 2 | 生产者 `sem_wait(&empty_slots)` | 7 | 0 | 生产者占用 1 个空槽位准备写入 |
| 3 | 生产者写入数据 | 7 | 0 | 正在写入，还没有通知消费者可读 |
| 4 | 生产者 `sem_post(&filled_slots)` | 7 | 1 | 写入完成，已填充槽位增加 1 |
| 5 | 消费者 `sem_wait(&filled_slots)` | 7 | 0 | 消费者占用 1 个已填充槽位准备读取 |
| 6 | 消费者读取数据 | 7 | 0 | 正在读取，还没有通知生产者槽位已空 |
| 7 | 消费者 `sem_post(&empty_slots)` | 8 | 0 | 读取完成，空槽位恢复为 8 |

所以两者始终满足一个关系：`empty_slots + filled_slots = BUFFER_SIZE`。生产者让“空槽位 -1、满槽位 +1”；消费者让“满槽位 -1、空槽位 +1”。

> [!important] 两个信号量是分开的，关系由代码维护
> `empty_slots` 和 `filled_slots` 是两个独立的计数器，系统不会自动保证它们相加等于 `BUFFER_SIZE`。
>
> 这个关系成立，是因为程序严格遵守固定顺序：生产者每成功占用一个空槽位，就必须在写完后增加一个已填充槽位；消费者每成功占用一个已填充槽位，就必须在读完后释放一个空槽位。
>
> 如果生产者只执行 `sem_wait(&empty_slots)`，却忘了 `sem_post(&filled_slots)`，或者消费者读完后忘了 `sem_post(&empty_slots)`，这个关系就会被破坏，程序也可能卡死。

### 2.3 互斥量 (Mutex) vs 二进制信号量

| 特性 | 互斥量 (Mutex) | 二进制信号量 |
|------|---------------|-------------|
| **所有权** | 有，只有加锁者能解锁 | 无，任何进程都能操作 |
| **用途** | 保护临界区 | 同步和互斥 |
| **递归** | 可以支持递归锁 | 通常不支持 |
| **优先级继承** | 通常支持 | 不支持 |

## 3. System V 信号量

System V 信号量是一组（**信号量集**）而不是单个信号量，可以在一次操作中对多个信号量进行原子操作。

### 3.1 semget() - 创建/获取信号量集

```c
#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/sem.h>

int semget(key_t key, int nsems, int semflg);
```

| 参数 | 说明 |
|------|------|
| `key` | IPC 键值，与[[11.4 共享内存\|共享内存]]使用相同的 `ftok()` 生成 |
| `nsems` | 信号量集中信号量的数量 |
| `semflg` | 标志位（`IPC_CREAT`、权限等） |
| 返回值 | 成功返回信号量集标识符 (semid)，失败返回 -1 |

**示例**：

```c
// 创建包含 1 个信号量的信号量集
int semid = semget(key, 1, IPC_CREAT | 0666);

// 获取已存在的信号量集
int semid = semget(key, 0, 0);
```

### 3.2 semop() - 信号量操作

```c
int semop(int semid, struct sembuf *sops, size_t nsops);
```

| 参数 | 说明 |
|------|------|
| `semid` | 信号量集标识符 |
| `sops` | `sembuf` 结构体数组，描述要执行的操作 |
| `nsops` | 操作的数量 |
| 返回值 | 成功返回 0，失败返回 -1 |

**sembuf 结构体**：

```c
struct sembuf {
    unsigned short sem_num;  // 信号量在集合中的索引（从 0 开始）
    short          sem_op;   // 操作值
    short          sem_flg;  // 操作标志
};
```

| sem_op 值 | 操作类型 | 说明 |
|-----------|----------|------|
| `> 0` | V 操作 | 信号量值增加 sem_op |
| `< 0` | P 操作 | 信号量值减少 \|sem_op\|，若不够则阻塞 |
| `== 0` | 等待零 | 阻塞直到信号量值变为 0 |

**常用标志 (sem_flg)**：

| 标志 | 说明 |
|------|------|
| `0` | 默认行为（阻塞） |
| `IPC_NOWAIT` | 非阻塞操作，资源不足时立即返回错误 |
| `SEM_UNDO` | 进程退出时自动撤销操作（防止死锁） |

**封装 P/V 操作**：

```c
// P 操作（申请资源）
void sem_p(int semid, int sem_num) {
    struct sembuf op;
    op.sem_num = sem_num;
    op.sem_op = -1;          // P 操作：减 1
    op.sem_flg = SEM_UNDO;   // 进程退出时自动释放
    semop(semid, &op, 1);
}

// V 操作（释放资源）
void sem_v(int semid, int sem_num) {
    struct sembuf op;
    op.sem_num = sem_num;
    op.sem_op = 1;           // V 操作：加 1
    op.sem_flg = SEM_UNDO;
    semop(semid, &op, 1);
}
```

### 3.3 semctl() - 信号量控制

```c
int semctl(int semid, int semnum, int cmd, ...);
```

| 参数 | 说明 |
|------|------|
| `semid` | 信号量集标识符 |
| `semnum` | 信号量索引（对于某些命令） |
| `cmd` | 控制命令 |
| `...` | 可选参数（`union semun`） |

**常用命令**：

| 命令 | 说明 |
|------|------|
| `SETVAL` | 设置单个信号量的值 |
| `GETVAL` | 获取单个信号量的值 |
| `SETALL` | 设置所有信号量的值 |
| `GETALL` | 获取所有信号量的值 |
| `IPC_RMID` | 删除信号量集 |
| `IPC_STAT` | 获取信号量集状态 |

**union semun**（需要自己定义）：

```c
union semun {
    int              val;    // SETVAL 使用
    struct semid_ds *buf;    // IPC_STAT/IPC_SET 使用
    unsigned short  *array;  // SETALL/GETALL 使用
};
```

**初始化和删除示例**：

```c
// 初始化信号量值为 1
union semun arg;
arg.val = 1;
semctl(semid, 0, SETVAL, arg);

// 获取信号量值
int val = semctl(semid, 0, GETVAL);

// 删除信号量集
semctl(semid, 0, IPC_RMID);
```

### 3.4 信号量同步流程与函数作用

信号量本身不传输业务数据，真正的数据仍然在[[11.4 共享内存|共享内存]]、文件、缓冲区或连接池里。信号量传递的是一种**访问许可**：谁先通过 `P` 操作拿到许可，谁就能进入临界区；谁执行 `V` 操作释放许可，内核就可能唤醒等待队列中的下一个进程。

![[3_11_11_5_1.svg|760]]

这张图可以按两条线理解：

1. **创建与控制线**：先用 `ftok()` 生成 `key`，再用 `semget(key, nsems, IPC_CREAT | 权限)` 创建或获取内核里的信号量集，返回 `semid`。拿到 `semid` 后，`semctl()` 负责初始化、查询和删除，例如 `SETVAL` 设置初值，`GETVAL` 查看当前值，`IPC_STAT` 查看状态，`IPC_RMID` 删除信号量集。
2. **使用与同步线**：`semop()` 执行真正的原子操作。`sem_op = -1` 是 `P` 操作，值足够就减 1 并进入临界区；值不够就把进程挂到等待队列。`sem_op = +1` 是 `V` 操作，释放资源并唤醒可能正在等待的进程。

> [!note] 为什么说它是“同步工具”而不是“通信工具”
> 信号量不会把 `"Hello from producer"` 这样的内容传给消费者，它只保证生产者写共享内存时消费者不会同时读写同一片区域。因此它常和共享内存一起出现：共享内存负责放数据，信号量负责控制访问顺序。

### 3.5 两个进程如何通过信号量协作

严格地说，两个进程不是靠信号量传输业务数据，而是靠信号量传递“可写、可读、已经完成”的状态。常见做法是让[[11.4 共享内存|共享内存]]保存数据，让两个信号量控制读写顺序：

![[3_11_11_5_2.svg|760]]

在这个模型里：

1. `empty` 表示缓冲区是否还有空位。生产者先 `sem_wait(empty)`，拿到空位后才能写共享内存。
2. `full` 表示缓冲区里是否已有数据。生产者写完后 `sem_post(full)`，消费者的 `sem_wait(full)` 才能继续执行。
3. 消费者读完共享内存后 `sem_post(empty)`，表示空位释放出来，生产者可以继续写下一条数据。

所以“通过信号量通讯”的本质是：**用信号量传递事件，用共享内存传递数据**。

## 4. 代码示例：生产者-消费者模型

以下是使用信号量实现的生产者-消费者模型，用于保护[[11.4 共享内存|共享内存]]的访问。

### 4.1 公共头文件 (common.h)

```c
#ifndef COMMON_H
#define COMMON_H

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/ipc.h>
#include <sys/shm.h>
#include <sys/sem.h>

#define SHM_SIZE 256

// 信号量操作封装
union semun {
    int val;
    struct semid_ds *buf;
    unsigned short *array;
};

// P 操作
void sem_p(int semid) {
    struct sembuf op = {0, -1, SEM_UNDO};
    if (semop(semid, &op, 1) == -1) {
        perror("sem_p failed");
        exit(1);
    }
}

// V 操作
void sem_v(int semid) {
    struct sembuf op = {0, 1, SEM_UNDO};
    if (semop(semid, &op, 1) == -1) {
        perror("sem_v failed");
        exit(1);
    }
}

#endif
```

### 4.2 生产者 (producer.c)

```c
#include "common.h"

int main(void) {
    key_t key = ftok(".", 'a');

    // 创建共享内存
    int shmid = shmget(key, SHM_SIZE, IPC_CREAT | 0666);
    char *shmptr = (char *)shmat(shmid, NULL, 0);

    // 创建信号量（初始值为 1，表示资源可用）
    int semid = semget(key, 1, IPC_CREAT | 0666);
    union semun arg;
    arg.val = 1;
    semctl(semid, 0, SETVAL, arg);

    printf("Producer: Waiting to write...\n");

    // P 操作：获取访问权
    sem_p(semid);

    // 写入数据到共享内存
    strcpy(shmptr, "Hello from producer!");
    printf("Producer: Data written: %s\n", shmptr);

    // 模拟处理时间
    sleep(3);

    // V 操作：释放访问权
    sem_v(semid);
    printf("Producer: Released lock\n");

    shmdt(shmptr);
    return 0;
}
```

### 4.3 消费者 (consumer.c)

```c
#include "common.h"

int main(void) {
    key_t key = ftok(".", 'a');

    // 获取共享内存
    int shmid = shmget(key, SHM_SIZE, 0666);
    if (shmid == -1) {
        perror("shmget failed");
        exit(1);
    }
    char *shmptr = (char *)shmat(shmid, NULL, 0);

    // 获取信号量
    int semid = semget(key, 1, 0666);
    if (semid == -1) {
        perror("semget failed");
        exit(1);
    }

    printf("Consumer: Waiting to read...\n");

    // P 操作：获取访问权
    sem_p(semid);

    // 读取数据
    printf("Consumer: Data read: %s\n", shmptr);

    // V 操作：释放访问权
    sem_v(semid);
    printf("Consumer: Released lock\n");

    // 清理资源
    shmdt(shmptr);
    shmctl(shmid, IPC_RMID, NULL);
    semctl(semid, 0, IPC_RMID);
    printf("Consumer: Resources cleaned up\n");

    return 0;
}
```

### 4.4 编译和运行

```bash
# 编译
gcc -o producer producer.c
gcc -o consumer consumer.c

# 在两个终端中分别运行
# 终端 1
./producer

# 终端 2（在 producer 运行期间启动）
./consumer
```

**预期输出**：

```
# 终端 1 (producer)
Producer: Waiting to write...
Producer: Data written: Hello from producer!
Producer: Released lock

# 终端 2 (consumer) - 会等待 producer 释放锁后才能读取
Consumer: Waiting to read...
Consumer: Data read: Hello from producer!
Consumer: Released lock
Consumer: Resources cleaned up
```

## 5. POSIX 信号量

除了 System V 信号量，还有更现代的 **POSIX 信号量**，使用更简单。

### 5.1 有名信号量 (Named Semaphore)

```c
#include <semaphore.h>
#include <fcntl.h>

// 创建/打开
sem_t *sem = sem_open("/mysem", O_CREAT, 0666, 1);

// P 操作
sem_wait(sem);

// V 操作
sem_post(sem);

// 关闭
sem_close(sem);

// 删除
sem_unlink("/mysem");
```

### 5.2 无名信号量 (Unnamed Semaphore)

```c
#include <semaphore.h>

sem_t sem;

// 初始化（第二个参数: 0=线程间, 非0=进程间）
sem_init(&sem, 0, 1);

// P 操作
sem_wait(&sem);

// V 操作
sem_post(&sem);

// 销毁
sem_destroy(&sem);
```

### 5.3 System V vs POSIX 信号量

| 特性 | System V | POSIX |
|------|----------|-------|
| **复杂度** | 复杂（信号量集） | 简单 |
| **可移植性** | 广泛支持 | 需要 POSIX 支持 |
| **接口** | semget/semop/semctl | sem_open/sem_wait/sem_post |
| **原子操作** | 支持多个信号量原子操作 | 单个信号量操作 |

## 7. 信号量中的 overlap 实现过程

信号量本身不传输数据，但它是实现 overlap 的“交通灯”：让生产者和消费者在不同缓冲区上并行推进，同时避免忙等和数据覆盖。

以共享内存环形队列为例，通常至少需要两个计数信号量：

| 信号量 | 含义 | 谁等待 | 谁释放 |
|--------|------|--------|--------|
| `empty` | 当前还有多少空槽位可以写 | 生产者 | 消费者 |
| `full` | 当前有多少满槽位可以读 | 消费者 | 生产者 |

实现过程：

1. 初始化 `empty = N`，表示环形缓冲区有 `N` 个空槽位；初始化 `full = 0`，表示还没有可读数据。
2. 生产者执行 `P(empty)`，拿到空槽位后写共享内存。
3. 生产者写完后执行 `V(full)`，通知消费者“有一批数据可读”。
4. 消费者执行 `P(full)`，拿到可读槽位后读取并处理数据。
5. 消费者处理完后执行 `V(empty)`，通知生产者“这个槽位又可以写”。
6. 当槽位数量大于 1 时，生产者可以写下一槽，消费者可以处理上一槽，形成 overlap。

```text
生产者: P(empty) -> 写 slot0 -> V(full) -> P(empty) -> 写 slot1
消费者:                    P(full) -> 读 slot0 / 处理 -> V(empty)
```

如果使用 System V 信号量，可以通过 `IPC_NOWAIT` 避免阻塞：

```c
struct sembuf op = {0, -1, IPC_NOWAIT};
if (semop(semid, &op, 1) == -1) {
    do_other_work();  // 暂时拿不到资源，不空转等待
}
```

> [!note] 信号量 overlap 的核心
> 信号量不是让临界区变快，而是让“等待资源”从忙等变成阻塞/唤醒，并让多个缓冲区之间有明确的可读、可写状态。

---

## 8. 关键要点

1. **信号量用于同步，不传递数据**：与[[11.4 共享内存|共享内存]]配合使用
2. **P 操作申请资源，V 操作释放资源**：这两个操作都是原子的
3. **二进制信号量类似互斥锁**：值只能是 0 或 1
4. **计数信号量管理资源池**：值表示可用资源数量
5. **使用 `SEM_UNDO` 防止死锁**：进程异常退出时自动释放
6. **POSIX 信号量更简单**：推荐在新项目中使用
7. **信号量 overlap** 依赖 `empty/full` 这类状态信号，让生产者写下一批时消费者处理上一批

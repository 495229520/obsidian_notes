# 11.13 多进程并发服务器

## 1. 迭代式服务器卡在哪

[[7.7 listen和accept函数#5. 完整示例：一个迭代服务器|基本 TCP 服务器]] 只有一个进程：`accept()` 拿到连接，读写完再 `close()`，然后回头 `accept()` 下一个。这叫**迭代式服务器**。

它的问题不是慢，是**排队**。第二个客户端的连接早就在 backlog 队列里握完手了，`accept()` 却要等第一个客户端彻底聊完才去取。第一个客户端在下载大文件，或者连上之后干脆不说话，后面所有人都得陪着等。

**并发服务器**要做的就是把这些等待重叠起来。常见的三条路：

| 方式 | 怎么重叠 | 代价 |
|:---|:---|:---|
| **多进程** | 每个客户端一个子进程，各自阻塞在自己的连接上 | 进程数量，以及每连接一次 `fork()` |
| **多线程** | 每个客户端一个线程，共享地址空间 | 同步要自己做，一个线程崩了整个进程都没 |
| **[[13.1 IO复用简介\|I/O 多路复用]]** | 一个进程盯着一批 fd，谁就绪处理谁 | 业务代码得改成非阻塞加回调的写法 |

本节讲第一条。它是三种里代码改动最小的一种：原来那段处理客户端的逻辑一行不改，整段搬进 [[11.1 进程简介#4. fork()：创建进程|fork()]] 出来的子进程就行。

## 2. 工作原理

### 2.1 主循环

![[图片/SVG/3_11_11_13_1.svg|1307]]

图 A 就是这个模型的全部内容，一句话说完：**accept 拿到连接就 fork，然后立刻回去 accept**。

父进程走 ①②③④ 这一圈，它从头到尾不 `read` 也不 `write`，手里只有 `listen_fd`。子进程从 ③ `fork()` 的另一支分出来，走 ⑤⑥⑦，手里只有 `conn_fd`，跟客户端说的每一句话都是它说的。

图 B 是三个客户端同时在线时的进程快照，其中有一处容易看错：三个子进程的 `conn_fd` **编号都是 4**。fd 编号归各个进程自己所有，`fork()` 只是把父进程 fd 表当时的样子复制了一份，之后两边各走各的。这三个 4 号槽位指向的是三个不同的 socket。

### 2.2 三个必须做对的地方

**`fork()` 复制的是 fd 表。** 子进程一出生就同时握着 `listen_fd` 和 `conn_fd`，父进程也一样。这不是谁的好意，是 `fork()` 的语义决定的，所以两边都得自己动手清理。

**各关掉不属于自己的那一个。** 父进程 `close(conn_fd)`，子进程 `close(listen_fd)`。这两句不是可选的收尾，第 5.1 节会看到少写一句会漏掉什么。

**子进程要有人收。** 子进程 `exit()` 之后停在僵尸态等父进程取退出状态，而父进程此刻正阻塞在 `accept()` 上，不可能主动去 `wait()`。只能靠 [[11.5 僵尸进程#4. 信号处理方式：signal() 函数|SIGCHLD 处理函数]]，见 5.2 节。

## 3. 服务器端代码

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>
#include <signal.h>
#include <sys/socket.h>
#include <sys/wait.h>
#include <arpa/inet.h>

#define BUFFER_SIZE 1024

// SIGCHLD 处理函数：把当前所有已终止的子进程一次收干净
void sigchld_handler(int signo) {
    int saved_errno = errno;      // handler 抢的是主流程的执行流，
                                  // waitpid 失败会改 errno，进出各存一次
    while (waitpid(-1, NULL, WNOHANG) > 0)
        ;                         // 收到没有可收的为止，原因见 5.2
    errno = saved_errno;
}

int main(int argc, char *argv[]) {
    if (argc != 2) {
        printf("Usage: %s <port>\n", argv[0]);
        return -1;
    }

    signal(SIGCHLD, sigchld_handler);

    // 1. 创建监听套接字
    int listen_fd = socket(AF_INET, SOCK_STREAM, 0);
    if (listen_fd < 0) {
        perror("socket");
        return -1;
    }

    // 服务重启时立刻能重新 bind，不必等上一批连接的 TIME_WAIT 过完
    int opt = 1;
    setsockopt(listen_fd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));

    // 2. 绑定地址
    struct sockaddr_in server_addr;
    memset(&server_addr, 0, sizeof(server_addr));
    server_addr.sin_family = AF_INET;
    server_addr.sin_port = htons(atoi(argv[1]));
    server_addr.sin_addr.s_addr = htonl(INADDR_ANY);

    if (bind(listen_fd, (struct sockaddr *)&server_addr,
             sizeof(server_addr)) < 0) {
        perror("bind");
        return -1;
    }

    // 3. 开始监听
    if (listen(listen_fd, 5) < 0) {
        perror("listen");
        return -1;
    }

    printf("服务器启动，监听端口 %s...\n", argv[1]);

    // 4. 主循环：只做 accept 和 fork 两件事
    while (1) {
        struct sockaddr_in client_addr;
        socklen_t client_len = sizeof(client_addr);

        int conn_fd = accept(listen_fd,
                             (struct sockaddr *)&client_addr,
                             &client_len);
        if (conn_fd < 0) {
            if (errno == EINTR) continue;   // 被信号打断，重来一次
            perror("accept");               // 其它错误别无声吞掉，
            break;                          // 否则会在这里空转
        }

        printf("客户端已连接: %s:%d\n",
               inet_ntoa(client_addr.sin_addr),
               ntohs(client_addr.sin_port));

        pid_t pid = fork();

        if (pid < 0) {
            perror("fork");
            close(conn_fd);                 // fork 失败也得把连接还掉
            continue;
        } else if (pid == 0) {
            // ===== 子进程 =====
            close(listen_fd);               // 不接新连接，这个 fd 留着只会漏

            char buffer[BUFFER_SIZE];
            ssize_t n;

            while ((n = read(conn_fd, buffer, BUFFER_SIZE)) > 0) {
                write(conn_fd, buffer, n);  // 回显，读到多少写回多少
            }
            // read 返回 0 表示对端已关闭写端，这条连接没得读了

            close(conn_fd);
            exit(0);
        } else {
            // ===== 父进程 =====
            close(conn_fd);                 // 这条连接归子进程了
            // 直接回到 while 顶部接下一个
        }
    }

    close(listen_fd);
    return 0;
}
```

代码里有两处刻意的简化，正式代码要补上：

- **`write()` 可能只写一部分。** socket 的发送缓冲满了，`write()` 会返回一个小于 `n` 的值。回显要写成循环，直到写完 `n` 个字节或者出错。
- **`signal()` 的行为随 libc 变。** 这里能正常跑是因为 glibc 给的是 BSD 语义，新代码应该用 `sigaction()` 把 `SA_RESTART` 显式写出来，理由见 [[11.5 僵尸进程#4.6 signal() 的语义随平台变|signal() 的语义随平台变]]。

`while` 循环里没有任何跟具体客户端相关的状态，这是这个模型最舒服的地方：父进程的代码只有 `accept` 加 `fork`，业务逻辑全在 `pid == 0` 那一支里，改业务不会碰到并发。

## 4. 客户端代码

客户端跟并发没关系，一个进程一条连接，写来配合验证服务器：

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/socket.h>
#include <arpa/inet.h>

#define BUFFER_SIZE 1024

int main(int argc, char *argv[]) {
    if (argc != 3) {
        printf("Usage: %s <IP> <port>\n", argv[0]);
        return -1;
    }

    int sock_fd = socket(AF_INET, SOCK_STREAM, 0);
    if (sock_fd < 0) {
        perror("socket");
        return -1;
    }

    struct sockaddr_in server_addr;
    memset(&server_addr, 0, sizeof(server_addr));
    server_addr.sin_family = AF_INET;
    server_addr.sin_port = htons(atoi(argv[2]));

    if (inet_pton(AF_INET, argv[1], &server_addr.sin_addr) <= 0) {
        perror("inet_pton");
        return -1;
    }

    if (connect(sock_fd, (struct sockaddr *)&server_addr,
                sizeof(server_addr)) < 0) {
        perror("connect");
        return -1;
    }

    printf("已连接到服务器 %s:%s\n", argv[1], argv[2]);

    char send_buf[BUFFER_SIZE];
    char recv_buf[BUFFER_SIZE];

    while (1) {
        printf("输入消息 (quit 退出): ");

        if (fgets(send_buf, BUFFER_SIZE, stdin) == NULL) {
            break;                                  // Ctrl-D
        }
        if (strcmp(send_buf, "quit\n") == 0) {
            break;                                  // 整行匹配，
        }                                           // 别用 strncmp(..., 4)

        write(sock_fd, send_buf, strlen(send_buf));

        ssize_t n = read(sock_fd, recv_buf, BUFFER_SIZE - 1);
        if (n > 0) {
            recv_buf[n] = '\0';
            printf("服务器回显: %s", recv_buf);
        } else if (n == 0) {
            printf("服务器断开连接\n");
            break;
        }
    }

    close(sock_fd);                                 // 这里的 close 会发 FIN，
    return 0;                                       // 服务器那边 read 返回 0
}
```

验证并发效果的办法：开三个终端各跑一个客户端，都连上之后 `ps -ef | grep a.out`，应该看到一个父进程带三个子进程。其中一个客户端不输入任何东西，另外两个照常收发，互不影响。这一步换成迭代式服务器就只有第一个客户端能收到回显。

## 5. 容易写错的三处细节

### 5.1 为什么两边都要关

![[图片/SVG/3_11_11_13_2.svg|1307]]

`close()` 的意思不是「关掉这个 socket」，是「我不用它了」。内核给每个打开的 socket 记着一个**引用计数**，`close()` 只把计数减一，减到 0 才真正回收资源、才发出四次挥手的 FIN。

图 A 到 C 是这个计数在 `fork()` 前后的走向：

- **A** `accept()` 刚返回，一个进程两个 fd，两个 socket 的计数都是 1
- **B** `fork()` 之后 fd 表被整张复制，两个 socket 各多一个持有者，计数都变成 2
- **C** 父进程 `close(conn_fd)`、子进程 `close(listen_fd)`，各自减一回到 1，这次是谁该拿着谁拿着

D 那张表列的是漏掉某一句的后果，第二行最阴：父进程忘了 `close(conn_fd)`，子进程处理完 `exit()` 了，计数从 2 掉到 1 但不到 0，于是 **FIN 一直发不出去**。客户端看到的是连接还活着，服务器这边 `netstat` 里一堆 `ESTABLISHED` 挂着不动，fd 一个也没还回来。这个 bug 在自己开两个终端手工测的时候完全看不出来，压测一上量就撞 `RLIMIT_NOFILE`。

### 5.2 SIGCHLD 处理函数里为什么写 while

`SIGCHLD` 是标准信号，内核只用一个 pending 位记「有没有」，不记「有几个」。三个子进程在同一个调度间隙里退出，处理函数只会被调用一次，里面只 `waitpid()` 一次就漏掉两个。所以要 `while` 到它返回 0 或 -1 为止。

`WNOHANG` 也不能省。处理函数抢的是主循环的执行流，在里面阻塞等于把 `accept()` 一起卡住，那就白折腾了。

还有一条：handler 里没打印任何东西。想在这里 `printf("子进程 %d 已回收")` 是很自然的念头，但 `printf` 不是异步信号安全的函数，主流程正在 `printf` 中途被打断时进去会踩坏 `stdio` 的内部状态。要日志就用 `write(STDERR_FILENO, ...)`，或者干脆只在演示时打。三条约束的完整说明在 [[11.5 僵尸进程#4.7 handler 里的三条约束|handler 里的三条约束]]。

### 5.3 accept 返回 -1 不都是被信号打断

写成 `if (conn_fd < 0) continue;` 是常见的偷懒写法，它把所有错误都当成「被信号打断」。真出别的错时后果不一样：`EMFILE`（fd 用完了）会让 `accept()` 立刻再失败，循环变成 100% CPU 的空转，日志里什么都看不到。

分开处理只多一行：`errno == EINTR` 就 `continue`，别的先 `perror()` 再决定退出还是限速重试。

顺带说一句，在 glibc 上这个 `EINTR` 分支基本走不到。glibc 的 `signal()` 是 BSD 语义，带 `SA_RESTART`，被 `SIGCHLD` 打断的 `accept()` 会被内核自动重启。留着它是为了换 libc 或改用不带 `SA_RESTART` 的 `sigaction()` 时代码依然对。

## 6. 优缺点与适用场景

| 优点 | 具体是什么 |
|:---|:---|
| **隔离性** | 一个子进程段错误只带走它自己那条连接，父进程和其他客户端毫无感觉 |
| **代码简单** | 业务逻辑写成同步阻塞的直线代码就行，不用拆成回调，也没有锁 |
| **地址空间独立** | 一个客户端写飞了指针，踩不到别人的数据 |

| 缺点 | 具体是什么 |
|:---|:---|
| **每连接一次 fork** | `fork()` 靠 COW，复制的是页表不是内存，但地址空间越大页表越大，开销跟着涨 |
| **进程比连接贵得多** | 每个子进程一套页表、内核栈、`task_struct`，几千并发就是几千份 |
| **共享数据要走 IPC** | 想统计全局在线人数、共用一份缓存，都得上 [[11.8 进程间通信IPC\|IPC 机制]] |
| **上下文切换成本高** | 进程切换要换页表，比线程切换贵 |

适合的场景有一个共同点：**连接数不多，但每条连接的处理很重**。

- 连接数量在几十到几百
- 单个连接要做大量计算或磁盘 I/O，`fork()` 那点开销摊薄到可以忽略
- 处理逻辑用了不可靠的第三方库，宁愿让它崩在子进程里

反过来，几万个短连接各说一句话就走的场景，时间全花在 `fork()` 上了，该用 I/O 多路复用。

## 7. 多进程服务器里的 overlap

![[图片/SVG/3_11_11_13_3.svg|1307]]

图 A 和 B 是同一批客户端在两种服务器上的时间轴。三段处理时间是一样长的，区别只在排不排队：A 里三段绿色首尾相接，最后一个客户端到第 9 秒才做完；B 里三段几乎完全重叠，第 3.9 秒全部结束。

**并发没让任何单个客户端变快**，每个客户端仍然要 3 秒。省掉的是图 A 里那两条灰色的干等，代价是同时驻留三个进程。这也是 [[11.1 进程简介#6. 进程级 overlap|进程级 overlap]] 最直观的一个例子。

实现上就是六步：

1. 父进程建好监听套接字，进 `accept()` 循环
2. `accept()` 每返回一个 `conn_fd`，立刻 `fork()`
3. 子进程关掉 `listen_fd`，只留 `conn_fd`，负责 `read()`、业务处理、`write()`
4. 父进程关掉这个 `conn_fd`，回到 `accept()` 等下一个
5. 多个子进程各自阻塞在自己客户端的 `read()` 上，谁慢谁自己等
6. 父进程靠 `SIGCHLD` 加 `waitpid(WNOHANG)` 顺手收尸，回收动作不阻塞 `accept()`

剥掉错误处理，父进程的循环只剩这么点东西：

```c
while (1) {
    int conn_fd = accept(listen_fd, NULL, NULL);
    pid_t pid = fork();

    if (pid == 0) {
        close(listen_fd);
        handle_client(conn_fd);  // 慢 I/O 或慢计算都在这里面，卡住的只有自己
        close(conn_fd);
        exit(0);
    }

    close(conn_fd);              // 父进程立刻回去 accept 下一个
}
```

图 B 里父进程那条蓝色长条就是这段代码的效果：它一整段时间都停在 `accept()` 上，没有一秒钟花在客户端身上。

> [!tip] 和 I/O 多路复用的关系
> 两者重叠的都是等待，只是让谁去等不一样。多进程是「多个进程各等一个 fd」，[[13.1 IO复用简介|I/O 多路复用]]是「一个进程一次等一批 fd」。前者不用改业务代码的写法，后者在几万并发下不用付几万份进程的账。

## 8. 关键要点

1. **主循环**：`accept()` 拿到连接就 `fork()`，父进程立刻回去 `accept()`，业务逻辑全在子进程里
2. **父子各关一个**：父进程 `close(conn_fd)`，子进程 `close(listen_fd)`，因为 `fork()` 把 fd 表整张复制了
3. **`close()` 是减引用计数**，减到 0 才发 FIN。父进程漏掉 `close(conn_fd)`，连接会一直挂在 `ESTABLISHED`
4. **回收子进程**用 `SIGCHLD` 处理函数，里面必须 `while` 加 `WNOHANG`：信号不排队，一次调用要收干净
5. **`accept()` 返回 -1 先看 `errno`**，只有 `EINTR` 才该 `continue`，否则会空转
6. **overlap 省的是排队**，不是处理时间；单个客户端一点没变快
7. **适用边界**：连接少、单连接重的场景；几万短连接该换 I/O 多路复用

## 1. 什么是信号量

**信号量 (Semaphore)** 是一种用于[[11.8 进程间通信IPC|进程间同步]]的机制。与[[11.10 共享内存|共享内存]]和[[11.12 消息队列|消息队列]]不同，信号量**不用于传递数据**，而是用于**控制对共享资源的访问**。

> 信号量本质上是一个**非负整数计数器**，用于协调多个进程对共享资源的访问，从而避免竞态条件 (Race Condition)。

### 1.1 信号量的核心操作

信号量支持两种原子操作：

| 操作 | 别名 | 描述 |
|------|------|------|
| **P 操作** | wait / down / 申请 | 如果信号量 > 0，则减 1；否则阻塞等待 |
| **V 操作** | signal / up / 释放 | 信号量加 1，唤醒等待的进程 |

```
P 操作 (申请资源):
    if (semaphore > 0) {
        semaphore--;
        // 继续执行
    } else {
        // 阻塞等待
    }

V 操作 (释放资源):
    semaphore++;
    // 唤醒等待队列中的进程
```

## 2. 信号量的类型

### 2.1 二进制信号量 (Binary Semaphore)

二进制信号量的值只能是 **0** 或 **1**，功能类似于**互斥锁 (Mutex)**。

| 值 | 含义 |
|----|------|
| 1 | 资源可用（未被占用） |
| 0 | 资源不可用（已被占用） |

**使用场景**：保护临界区，确保同一时刻只有一个进程访问共享资源。

```c
// 伪代码示例
sem_wait(&sem);      // P 操作：获取锁
// 临界区代码
sem_post(&sem);      // V 操作：释放锁
```

### 2.2 计数信号量 (Counting Semaphore)

计数信号量的值可以是**任意非负整数**，表示可用资源的数量。

| 值 | 含义 |
|----|------|
| n > 0 | 有 n 个资源可用 |
| 0 | 没有资源可用，新请求将阻塞 |

**使用场景**：控制对有限资源池的访问（如数据库连接池、缓冲区槽位）。

```c
// 生产者-消费者模型中的缓冲区管理
#define BUFFER_SIZE 8

sem_t empty_slots;   // 空槽位数量
sem_t filled_slots;  // 已填充槽位数量

// 初始化计数信号量
sem_init(&empty_slots, 0, BUFFER_SIZE);  // 一开始有 BUFFER_SIZE 个空槽位
sem_init(&filled_slots, 0, 0);           // 一开始没有已填充槽位

// 生产者
sem_wait(&empty_slots);   // 等待空槽位
// 生产数据
sem_post(&filled_slots);  // 增加已填充数量

// 消费者
sem_wait(&filled_slots);  // 等待已填充槽位
// 消费数据
sem_post(&empty_slots);   // 增加空槽位数量
```

这里的“计数”不是由 `sem_t empty_slots;` 这一行声明出来的，而是由初始化时传入的初始值决定的。`empty_slots` 初始值是 `BUFFER_SIZE`，表示缓冲区一开始全是空槽；`filled_slots` 初始值是 `0`，表示一开始没有可消费的数据。

以 `BUFFER_SIZE = 8`，先生产 1 个数据、再消费 1 个数据为例，计数变化如下：

| 步骤 | 操作 | `empty_slots` | `filled_slots` | 含义 |
|------|------|---------------|----------------|------|
| 1 | 初始化 | 8 | 0 | 8 个槽位全是空的，没有数据可读 |
| 2 | 生产者 `sem_wait(&empty_slots)` | 7 | 0 | 生产者占用 1 个空槽位准备写入 |
| 3 | 生产者写入数据 | 7 | 0 | 正在写入，还没有通知消费者可读 |
| 4 | 生产者 `sem_post(&filled_slots)` | 7 | 1 | 写入完成，已填充槽位增加 1 |
| 5 | 消费者 `sem_wait(&filled_slots)` | 7 | 0 | 消费者占用 1 个已填充槽位准备读取 |
| 6 | 消费者读取数据 | 7 | 0 | 正在读取，还没有通知生产者槽位已空 |
| 7 | 消费者 `sem_post(&empty_slots)` | 8 | 0 | 读取完成，空槽位恢复为 8 |

所以两者始终满足一个关系：`empty_slots + filled_slots = BUFFER_SIZE`。生产者让“空槽位 -1、满槽位 +1”；消费者让“满槽位 -1、空槽位 +1”。

> [!important] 两个信号量是分开的，关系由代码维护
> `empty_slots` 和 `filled_slots` 是两个独立的计数器，系统不会自动保证它们相加等于 `BUFFER_SIZE`。
>
> 这个关系成立，是因为程序严格遵守固定顺序：生产者每成功占用一个空槽位，就必须在写完后增加一个已填充槽位；消费者每成功占用一个已填充槽位，就必须在读完后释放一个空槽位。
>
> 如果生产者只执行 `sem_wait(&empty_slots)`，却忘了 `sem_post(&filled_slots)`，或者消费者读完后忘了 `sem_post(&empty_slots)`，这个关系就会被破坏，程序也可能卡死。

### 2.3 互斥量 (Mutex) vs 二进制信号量

| 特性 | 互斥量 (Mutex) | 二进制信号量 |
|------|---------------|-------------|
| **所有权** | 有，只有加锁者能解锁 | 无，任何进程都能操作 |
| **用途** | 保护临界区 | 同步和互斥 |
| **递归** | 可以支持递归锁 | 通常不支持 |
| **优先级继承** | 通常支持 | 不支持 |

## 3. System V 信号量

System V 信号量是一组（**信号量集**）而不是单个信号量，可以在一次操作中对多个信号量进行原子操作。

### 3.1 semget() - 创建/获取信号量集

```c
#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/sem.h>

int semget(key_t key, int nsems, int semflg);
```

| 参数 | 说明 |
|------|------|
| `key` | IPC 键值，与[[11.10 共享内存\|共享内存]]使用相同的 `ftok()` 生成 |
| `nsems` | 信号量集中信号量的数量 |
| `semflg` | 标志位（`IPC_CREAT`、权限等） |
| 返回值 | 成功返回信号量集标识符 (semid)，失败返回 -1 |

**示例**：

```c
// 创建包含 1 个信号量的信号量集
int semid = semget(key, 1, IPC_CREAT | 0666);

// 获取已存在的信号量集
int semid = semget(key, 0, 0);
```

### 3.2 semop() - 信号量操作

```c
int semop(int semid, struct sembuf *sops, size_t nsops);
```

| 参数 | 说明 |
|------|------|
| `semid` | 信号量集标识符 |
| `sops` | `sembuf` 结构体数组，描述要执行的操作 |
| `nsops` | 操作的数量 |
| 返回值 | 成功返回 0，失败返回 -1 |

**sembuf 结构体**：

```c
struct sembuf {
    unsigned short sem_num;  // 信号量在集合中的索引（从 0 开始）
    short          sem_op;   // 操作值
    short          sem_flg;  // 操作标志
};
```

| sem_op 值 | 操作类型 | 说明 |
|-----------|----------|------|
| `> 0` | V 操作 | 信号量值增加 sem_op |
| `< 0` | P 操作 | 信号量值减少 \|sem_op\|，若不够则阻塞 |
| `== 0` | 等待零 | 阻塞直到信号量值变为 0 |

**常用标志 (sem_flg)**：

| 标志 | 说明 |
|------|------|
| `0` | 默认行为（阻塞） |
| `IPC_NOWAIT` | 非阻塞操作，资源不足时立即返回错误 |
| `SEM_UNDO` | 进程退出时自动撤销操作（防止死锁） |

**封装 P/V 操作**：

```c
// P 操作（申请资源）
static int sem_p(int semid, int sem_num) {
    struct sembuf op = { .sem_num = sem_num,
                         .sem_op  = -1,          // P 操作：减 1
                         .sem_flg = SEM_UNDO };  // 进程退出时自动撤销
    while (semop(semid, &op, 1) == -1) {
        if (errno != EINTR) return -1;           // 只有 EINTR 才重试
    }
    return 0;
}

// V 操作（释放资源）
static int sem_v(int semid, int sem_num) {
    struct sembuf op = { .sem_num = sem_num,
                         .sem_op  = 1,           // V 操作：加 1
                         .sem_flg = SEM_UNDO };
    while (semop(semid, &op, 1) == -1) {
        if (errno != EINTR) return -1;
    }
    return 0;
}
```

**为什么要写这个重试循环。** 阻塞在 `semop()` 里的进程，只要收到任何一个被捕获的信号（哪怕只是一个 `SIGCHLD` 或者调试器发的 `SIGWINCH`），系统调用就会返回 -1 并把 `errno` 设成 `EINTR`。这时候锁**并没有拿到**。直接把返回 -1 当成致命错误退出，程序会在完全正常的运行环境里随机崩溃；不判返回值直接往下走，则等于没加锁就进了临界区。这两种写法在没有信号的测试环境里都跑得好好的。

`SEM_UNDO` 让内核记住这个进程对信号量做过的净调整，进程异常退出时自动撤销。它能救回「持锁时崩溃导致其他人全部饿死」这一种情况，但撤的只是计数值，临界区里已经写坏的数据它救不回来。

### 3.3 semctl() - 信号量控制

```c
int semctl(int semid, int semnum, int cmd, ...);
```

| 参数 | 说明 |
|------|------|
| `semid` | 信号量集标识符 |
| `semnum` | 信号量索引（对于某些命令） |
| `cmd` | 控制命令 |
| `...` | 可选参数（`union semun`） |

**常用命令**：

| 命令 | 说明 |
|------|------|
| `SETVAL` | 设置单个信号量的值 |
| `GETVAL` | 获取单个信号量的值 |
| `SETALL` | 设置所有信号量的值 |
| `GETALL` | 获取所有信号量的值 |
| `IPC_RMID` | 删除信号量集 |
| `IPC_STAT` | 获取信号量集状态 |

**union semun**（需要自己定义）：

```c
union semun {
    int              val;    // SETVAL 使用
    struct semid_ds *buf;    // IPC_STAT/IPC_SET 使用
    unsigned short  *array;  // SETALL/GETALL 使用
};
```

**初始化和删除示例**：

```c
// 初始化信号量值为 1
union semun arg;
arg.val = 1;
semctl(semid, 0, SETVAL, arg);

// 获取信号量值
int val = semctl(semid, 0, GETVAL);

// 删除信号量集
semctl(semid, 0, IPC_RMID);
```

### 3.4 信号量同步流程与函数作用

信号量本身不传输业务数据，真正的数据仍然在[[11.10 共享内存|共享内存]]、文件、缓冲区或连接池里。信号量传递的是一种**访问许可**：谁先通过 `P` 操作拿到许可，谁就能进入临界区；谁执行 `V` 操作释放许可，内核就可能唤醒等待队列中的下一个进程。

![[图片/3.Linux/11. 进程/3_11_11_11_1.svg|1307]]

这张图可以按两条线理解：

1. **创建与控制线**：先用 `ftok()` 生成 `key`，再用 `semget(key, nsems, IPC_CREAT | 权限)` 创建或获取内核里的信号量集，返回 `semid`。拿到 `semid` 后，`semctl()` 负责初始化、查询和删除，例如 `SETVAL` 设置初值，`GETVAL` 查看当前值，`IPC_STAT` 查看状态，`IPC_RMID` 删除信号量集。
2. **使用与同步线**：`semop()` 执行真正的原子操作。`sem_op = -1` 是 `P` 操作，值足够就减 1 并进入临界区；值不够就把进程挂到等待队列。`sem_op = +1` 是 `V` 操作，释放资源并唤醒可能正在等待的进程。

> [!note] 为什么说它是“同步工具”而不是“通信工具”
> 信号量不会把 `"Hello from producer"` 这样的内容传给消费者，它只保证生产者写共享内存时消费者不会同时读写同一片区域。因此它常和共享内存一起出现：共享内存负责放数据，信号量负责控制访问顺序。

### 3.5 两个进程如何通过信号量协作

严格地说，两个进程不是靠信号量传输业务数据，而是靠信号量传递“可写、可读、已经完成”的状态。常见做法是让[[11.10 共享内存|共享内存]]保存数据，让两个信号量控制读写顺序：

![[图片/3.Linux/11. 进程/3_11_11_11_2.svg|1307]]

在这个模型里：

1. `empty` 表示缓冲区是否还有空位。生产者先 `sem_wait(empty)`，拿到空位后才能写共享内存。
2. `full` 表示缓冲区里是否已有数据。生产者写完后 `sem_post(full)`，消费者的 `sem_wait(full)` 才能继续执行。
3. 消费者读完共享内存后 `sem_post(empty)`，表示空位释放出来，生产者可以继续写下一条数据。

所以“通过信号量通讯”的本质是：**用信号量传递事件，用共享内存传递数据**。

### 3.6 初始化竞态：System V 信号量最经典的坑

`semget()` 新建出来的信号量，初值是 **0**，不是 1。所以创建之后必须再调一次 `semctl(SETVAL)` 把它设成想要的初值。问题就出在这里：**这是两次独立的系统调用，中间不原子。**

![[图片/3.Linux/11. 进程/3_11_11_11_3.svg|1307]]

两个进程都写成「`semget(IPC_CREAT)` 之后无条件 `SETVAL 1`」时，后启动的那个会把先启动的那个已经拿走的许可凭空补回来，于是两个进程同时进了临界区。它只在启动时刻恰好撞上才复现，测试环境里几乎撞不到。

正确写法是用 `IPC_EXCL` 让内核裁定谁是创建者，把两次调用之间的竞争收敛成一次原子判定：

```c
union semun arg;
int semid = semget(key, 1, IPC_CREAT | IPC_EXCL | 0666);

if (semid >= 0) {                       // 内核保证只有一个进程走到这里
    arg.val = 1;
    semctl(semid, 0, SETVAL, arg);
    struct sembuf nop = {0, 0, 0};      // 一次空操作
    semop(semid, &nop, 1);              // 目的是把 sem_otime 置成非 0
} else if (errno == EEXIST) {           // 别人先建好了，我只管拿
    semid = semget(key, 1, 0666);
    // 关键：不能拿到就用，此刻它可能还是新建时的 0
    struct semid_ds ds;
    arg.buf = &ds;
    for (int i = 0; i < 100; i++) {
        semctl(semid, 0, IPC_STAT, arg);
        if (ds.sem_otime != 0) break;   // 创建者已经 semop 过，初始化完成
        usleep(10 * 1000);
    }
} else {
    perror("semget");
}
```

**为什么创建者要多做一次空的 `semop`。** 后到的进程需要一个信号来判断「初值设好了没有」，但 `SETVAL` 本身不改任何可观测的时间戳。`sem_otime` 记录的是最后一次 `semop` 的时间，新建时它是 0。创建者做一次 `sem_op = 0` 的空操作把它置上，后到者轮询到它非 0 就知道可以用了。这是 Stevens 在《UNIX 网络编程 卷 2》里给出的标准解法，没有更优雅的办法，因为 System V 接口就没设计初始化原语。

**这个坑在 POSIX 信号量上不存在。** `sem_open("/name", O_CREAT, 0666, 1)` 一次调用就完成创建加设初值，内核内部保证原子。新写代码没有理由再去趟 System V 这滩水，除非你需要下面 5.3 说的那个多信号量原子操作能力。

## 4. 代码示例：生产者-消费者模型

以下是使用信号量实现的生产者-消费者模型，用于保护[[11.10 共享内存|共享内存]]的访问。

### 4.1 公共头文件 (common.h)

```c
#ifndef COMMON_H
#define COMMON_H

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/ipc.h>
#include <sys/shm.h>
#include <sys/sem.h>

#include <errno.h>

#define SHM_SIZE 256

// glibc 不定义 union semun，要自己写；某些系统（如部分 BSD）已经定义了，
// 那种系统会给出 _SEM_SEMUN_UNDEFINED 之类的宏，重复定义会编译报错。
union semun {
    int              val;
    struct semid_ds *buf;
    unsigned short  *array;
};

// 写在头文件里的函数要加 static，否则多个 .c 一起链接时符号重复
static int sem_p(int semid) {
    struct sembuf op = {0, -1, SEM_UNDO};
    while (semop(semid, &op, 1) == -1)
        if (errno != EINTR) return -1;
    return 0;
}

static int sem_v(int semid) {
    struct sembuf op = {0, 1, SEM_UNDO};
    while (semop(semid, &op, 1) == -1)
        if (errno != EINTR) return -1;
    return 0;
}

#endif  // COMMON_H
```

原版这段有三处要注意：`#ifndef` 开了头却没有 `#endif`；头文件里定义了非 `static` 的函数，两个 `.c` 都包含它时链接会报符号重复（这里两个程序各自独立编译才没暴露）；`semop` 被信号打断时直接 `exit(1)`，理由见上一节。

### 4.2 生产者 (producer.c)

```c
#include "common.h"

int main(void) {
    key_t key = ftok(".", 'a');

    // 创建共享内存
    int shmid = shmget(key, SHM_SIZE, IPC_CREAT | 0666);
    char *shmptr = (char *)shmat(shmid, NULL, 0);

    // 创建信号量（初始值为 1，表示资源可用）
    // 注意：这两行只有在「确保本程序先启动、且只启动一份」时才安全，
    //       生产代码要按 3.6 节的 IPC_EXCL 写法来
    int semid = semget(key, 1, IPC_CREAT | 0666);
    union semun arg;
    arg.val = 1;
    semctl(semid, 0, SETVAL, arg);

    printf("Producer: Waiting to write...\n");

    // P 操作：获取访问权
    sem_p(semid);

    // 写入数据到共享内存
    strcpy(shmptr, "Hello from producer!");
    printf("Producer: Data written: %s\n", shmptr);

    // 模拟处理时间
    sleep(3);

    // V 操作：释放访问权
    sem_v(semid);
    printf("Producer: Released lock\n");

    shmdt(shmptr);
    return 0;
}
```

### 4.3 消费者 (consumer.c)

```c
#include "common.h"

int main(void) {
    key_t key = ftok(".", 'a');

    // 获取共享内存
    int shmid = shmget(key, SHM_SIZE, 0666);
    if (shmid == -1) {
        perror("shmget failed");
        exit(1);
    }
    char *shmptr = (char *)shmat(shmid, NULL, 0);

    // 获取信号量
    int semid = semget(key, 1, 0666);
    if (semid == -1) {
        perror("semget failed");
        exit(1);
    }

    printf("Consumer: Waiting to read...\n");

    // P 操作：获取访问权
    sem_p(semid);

    // 读取数据
    printf("Consumer: Data read: %s\n", shmptr);

    // V 操作：释放访问权
    sem_v(semid);
    printf("Consumer: Released lock\n");

    // 清理资源
    shmdt(shmptr);
    shmctl(shmid, IPC_RMID, NULL);
    semctl(semid, 0, IPC_RMID);
    printf("Consumer: Resources cleaned up\n");

    return 0;
}
```

```bash
gcc -o consumer consumer.c

# 在两个终端中分别运行
# 终端 1
./producer

# 终端 2（在 producer 运行期间启动）

```

## 5. POSIX 信号量

除了 System V 信号量，还有更现代的 **POSIX 信号量**，使用更简单。

### 5.1 有名信号量 (Named Semaphore)

```c
#include <semaphore.h>
#include <fcntl.h>
#include <sys/stat.h>

// 带 O_CREAT 时是四个参数，最后两个是权限和初始值
sem_t *sem = sem_open("/mysem", O_CREAT, 0666, 1);
if (sem == SEM_FAILED) { perror("sem_open"); return 1; }

// 打开一个已存在的则只要两个参数
// sem_t *sem = sem_open("/mysem", 0);

while (sem_wait(sem) == -1 && errno == EINTR)   // P，同样会被信号打断
    ;
// ... 临界区 ...
sem_post(sem);                                   // V

sem_close(sem);      // 只关闭本进程的引用
sem_unlink("/mysem"); // 真正删掉，最后一个 close 之后生效
```

名字必须以 `/` 开头且中间不再有 `/`，对象出现在 `/dev/shm/sem.mysem`，`ls /dev/shm` 就能看见。这一套没有 3.6 节那个初始化竞态：创建和设初值在 `sem_open` 内部一次完成。

`sem_close` 和 `sem_unlink` 的关系跟 `close` / `unlink` 一样：`unlink` 之后名字立刻消失，新的 `sem_open` 找不到它，但已经打开的进程照常用，直到最后一个 `sem_close`。

### 5.2 无名信号量 (Unnamed Semaphore)

```c
#include <semaphore.h>

sem_t sem;
sem_init(&sem, 0, 1);   // 第二个参数：0 = 只在本进程的线程间用，非 0 = 跨进程

sem_wait(&sem);
sem_post(&sem);
sem_destroy(&sem);
```

> [!warning] pshared 非 0 只是「允许」，不是「实现」
> `sem_init(&sem, 1, 1)` 里的 `1` 只是告诉实现「这个信号量可能被多个进程用」。真正让它跨进程生效的前提是：**`sem_t` 这个变量本身必须位于共享内存里**。
>
> 写成一个普通全局变量再 `fork`，两个进程各自持有一份写时复制出来的副本，各操作各的，完全不互斥。编译不报错，运行不报错，`sem_wait` 每次都立刻成功，看起来一切正常，直到数据开始对不上。
>
> 正确做法是把它放进 `shmat()` 或 `mmap(MAP_SHARED)` 出来的那块内存里：
>
> ```c
> sem_t *sem = (sem_t *)shmptr;          // 共享内存的头部
> sem_init(sem, 1, 1);                   // 只由一个进程初始化一次
> ```

### 5.3 System V vs POSIX 信号量

| 特性 | System V | POSIX |
|------|----------|-------|
| **接口** | `semget` / `semop` / `semctl` | `sem_open` / `sem_wait` / `sem_post` |
| **初始化** | 创建和设初值分两次调用，**有竞态**（见 3.6） | 一次 `sem_open` 完成，无竞态 |
| **句柄** | 整数 `semid`，进不了 epoll | `sem_t *`，同样进不了 epoll |
| **在文件系统里** | 看不见，只能 `ipcs -s` | 在 `/dev/shm/sem.*` 下，`ls` / `rm` 可见 |
| **多信号量原子操作** | **支持**，一次 `semop` 传一个数组 | 不支持，只能一个一个 `sem_wait` |
| **忘了清理** | 一直留在内核里直到重启 | 同样要 `sem_unlink`，但至少看得见 |

**「多信号量原子操作」是 System V 唯一不可替代的地方。** 一次 `semop()` 传进去一个 `sembuf` 数组，内核保证要么全部执行、要么一个都不执行：

```c
struct sembuf ops[2] = {
    {0, -1, 0},     // 同时申请资源 0
    {1, -1, 0},     // 和资源 1
};
semop(semid, ops, 2);   // 两个都够才继续；只够一个就一个都不拿，整体阻塞
```

用 POSIX 信号量做同一件事要写两次 `sem_wait`，中间就有了「拿到第一个、等第二个」的窗口，两个进程反着顺序申请就会死锁。除非你确实需要这个能力，否则新代码用 POSIX。

## 7. 信号量中的 overlap 实现过程

信号量本身不传输数据，但它是实现 overlap 的“交通灯”：让生产者和消费者在不同缓冲区上并行推进，同时避免忙等和数据覆盖。

以共享内存环形队列为例，通常至少需要两个计数信号量：

| 信号量 | 含义 | 谁等待 | 谁释放 |
|--------|------|--------|--------|
| `empty` | 当前还有多少空槽位可以写 | 生产者 | 消费者 |
| `full` | 当前有多少满槽位可以读 | 消费者 | 生产者 |

实现过程：

1. 初始化 `empty = N`，表示环形缓冲区有 `N` 个空槽位；初始化 `full = 0`，表示还没有可读数据。
2. 生产者执行 `P(empty)`，拿到空槽位后写共享内存。
3. 生产者写完后执行 `V(full)`，通知消费者“有一批数据可读”。
4. 消费者执行 `P(full)`，拿到可读槽位后读取并处理数据。
5. 消费者处理完后执行 `V(empty)`，通知生产者“这个槽位又可以写”。
6. 当槽位数量大于 1 时，生产者可以写下一槽，消费者可以处理上一槽，形成 overlap。

```text
生产者: P(empty) -> 写 slot0 -> V(full) -> P(empty) -> 写 slot1
消费者:                    P(full) -> 读 slot0 / 处理 -> V(empty)
```

如果使用 System V 信号量，可以通过 `IPC_NOWAIT` 避免阻塞：

```c
struct sembuf op = {0, -1, IPC_NOWAIT};
if (semop(semid, &op, 1) == -1) {
    do_other_work();  // 暂时拿不到资源，不空转等待
}
```

> [!note] 信号量 overlap 的核心
> 信号量不是让临界区变快，而是让“等待资源”从忙等变成阻塞/唤醒，并让多个缓冲区之间有明确的可读、可写状态。

## 8. 关键要点

1. **信号量用于同步，不传递数据**：数据放[[11.10 共享内存|共享内存]]，信号量只负责传「可写 / 可读 / 已完成」这类许可
2. **P 操作申请资源，V 操作释放资源**：这两个操作本身是原子的
3. **二进制信号量类似互斥锁**：值只能是 0 或 1；计数信号量管理资源池，值表示可用数量
4. **`semget` 新建的信号量初值是 0**，必须再 `SETVAL`；这两步不原子，是 System V 最经典的竞态。正确做法是用 `IPC_EXCL` 裁定创建者，后到者轮询 `sem_otime`
5. **`semop` / `sem_wait` 会被信号打断返回 `EINTR`**，此时锁并没有拿到。必须写重试循环，否则程序会在有信号的环境里随机崩溃或裸奔进临界区
6. **`sem_init(&sem, 1, ...)` 的 pshared 只是「允许」跨进程**，前提是 `sem_t` 变量本身放在共享内存里。放成普通全局变量不会报错，但完全不互斥
7. **`SEM_UNDO` 撤的是计数值**，能救回「持锁时崩溃」，救不回临界区里写坏的数据
8. **新代码优先 POSIX 信号量**：没有初始化竞态、在 `/dev/shm` 下看得见。只有需要「一次原子地拿到多个资源」时才回到 System V
9. **信号量 overlap** 依赖 `empty` / `full` 这类状态信号，让生产者写下一批时消费者处理上一批

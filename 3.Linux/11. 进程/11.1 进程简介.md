## 1. 进程是什么

**进程是内核分配资源的单位。** 每个进程有自己的[[1.C++基础/1. 计算机基础/1.3 进程的虚拟地址空间|虚拟地址空间]]、自己的文件描述符表、自己的信号处置表。进程 A 手里的指针值 `0x7f3a0010`，进程 B 拿同一个数值去解引用，落到的是完全不同的物理内存，或者直接段错误。

「进程就是正在运行的程序」这个说法容易误导两件事：

- 同一个 `/bin/ls` 可以同时有十个进程在跑。它们共享同一份只读的代码页（内核不会复制十遍），但各有各的栈、堆、数据段。
- 一个进程在它的一生里可以换掉整个程序。`exec` 系列函数保留 PID 和打开的 fd，把地址空间整个替换成另一个可执行文件。Shell 执行命令走的就是 `fork` 之后 `exec` 这条路。

## 2. 进程状态

![[图片/3.Linux/11. 进程/11.1-进程生命周期.png|900]]

教科书的三态模型：

| 状态 | 英文 | 含义 |
|------|------|------|
| **就绪** | Ready | 需要的资源都齐了，排在运行队列里等一个 CPU 核 |
| **运行** | Running | 此刻正占着某个核在执行指令 |
| **阻塞** | Blocked | 在等一个事件（I/O 完成、锁、信号、子进程退出），事件不来就不会被调度 |

四种迁移：

- **就绪 → 运行**：调度器从运行队列里挑中了它
- **运行 → 就绪**：时间片用完，或被更高优先级的进程抢占
- **运行 → 阻塞**：主动调用了会睡眠的系统调用，例如 `read()` 撞上未命中的页缓存
- **阻塞 → 就绪**：等待的事件发生了，内核把它放回运行队列。注意不是直接回到运行态，还要再排一次队

### 2.1 ps 看到的状态字母

Linux 内核并不区分「就绪」和「运行」，两者合并成一个 `TASK_RUNNING`，在 `ps` 里都显示 `R`。所以看到 `R` 只能说明它**可以跑**，不代表此刻正占着核。

| ps 字母 | 内核状态 | 含义 | `kill -9` 有效吗 |
|---------|----------|------|-----------------|
| `R` | `TASK_RUNNING` | 正在跑，或在运行队列里等核 | 有效 |
| `S` | `TASK_INTERRUPTIBLE` | 可中断睡眠：等网络、等 `sleep`、等终端输入 | 有效 |
| `D` | `TASK_UNINTERRUPTIBLE` | 不可中断睡眠，通常在等磁盘或 NFS | **无效** |
| `T` | `TASK_STOPPED` | 被 `SIGSTOP` 或调试器暂停 | 有效 |
| `Z` | `EXIT_ZOMBIE` | 已经退出，等父进程回收，见 [[3.Linux/11. 进程/11.7 僵尸进程\|僵尸进程]] | 已经死了，发信号没有意义 |

`D` 态是排查线上「进程杀不掉、负载还高」时的第一嫌疑对象。它卡在内核里等一个不能被打断的事件，信号要等它自己醒来才轮得到处理。另外 `uptime` 的 load average 把 `R` 和 `D` 都算进去，所以磁盘卡住时负载数字也会飙上去，这时候高负载并不代表 CPU 忙。

### 2.2 同时处于运行态的进程数

真正处于运行态（占着核）的进程数，上限就是逻辑核数，`nproc` 可以查。就绪队列里排多少个都行，多出来的只是在等时间片。

「一个双核 CPU 能同时运行两个进程」说的是真正并行的上限；系统里同时存在几百个进程是常态，它们绝大多数处在 `S` 态睡着。

## 3. 进程 ID

`getpid()` 返回自己的 PID，`getppid()` 返回父进程的 PID。几个容易记错的事实：

- **PID 从 1 开始**，上限看 `/proc/sys/kernel/pid_max`。很多发行版仍是 32768，64 位内核最大可以调到 4194304。用到上限之后回绕，从小的空闲号重新分配。
- **PID 1 是 `init` / `systemd`**，内核启动后创建的第一个用户态进程。父进程先退出时，孤儿进程会被它收养。
- **PID 0 不是普通进程**，它是内核的 idle（swapper）任务，`ps` 里看不到。
- **PID 号的释放时机是父进程调用 `wait` 之后**，不是子进程退出的那一刻。退出到被回收之间，进程处于 `Z` 态，几乎不占内存，但那个 PID 号一直被占着。父进程忘了回收，PID 就会一直漏，直到把 `pid_max` 耗光、整个系统 `fork` 不出新进程。

PID 的三个用处：内核用它索引 `task_struct`；`kill`、`ps`、`top` 用它指定目标；[[3.Linux/11. 进程/11.2 进程间通信IPC|进程间通信]]里用它标识对端，例如给指定进程发信号。

> [!warning] PID 会被复用
> 拿到一个 PID 之后隔一段时间再 `kill` 它，很可能杀错人：原进程已经退出，号被回收后分给了别的进程。需要可靠地引用一个进程时，用 `pidfd_open()` 拿到的 pidfd，它绑定的是具体那一个进程，进程消失后 pidfd 直接失效而不会指向别人。

## 4. fork()：创建进程

### 4.1 一次调用，两个返回值

`fork()` 和 `exec` 是两件不同的事：`exec` 把当前进程的地址空间换成另一个程序，进程还是那一个；`fork()` 造出一个新进程，内容是调用者的副本。

```c
pid_t pid = fork();
```

| 返回值 | 在谁那里 | 含义 |
|--------|----------|------|
| `> 0` | 父进程 | 值是新建子进程的 PID |
| `== 0` | 子进程 | 子进程想知道自己的 PID 得调 `getpid()` |
| `== -1` | 父进程 | 创建失败，`errno` 通常是 `EAGAIN`（进程数达上限）或 `ENOMEM` |

父进程拿到的是子进程的 PID，子进程拿到 0。这个不对称是有道理的：父进程可能有很多子进程，需要区分是哪一个；子进程只有一个父进程，`getppid()` 随时能问出来。

### 4.2 fork 不复制内存

「子进程获得父进程内存数据的副本」是**语义**上的承诺。实现上，`fork()` 复制的只是页表，物理页一页都不搬，两边的页表项统统被标记成只读。哪一方真的写下去，才在缺页异常里复制那一页。这套机制叫**写时复制**（copy-on-write，COW）。

![[图片/3.Linux/11. 进程/3_11_11_1_1.svg|1100]]

这解释了两件事：一是 `fork()` 一个占用 4 GB 内存的进程为什么只要几百微秒；二是 `fork` 紧接着 `exec` 为什么几乎不花钱，因为 `exec` 会立刻丢掉整个地址空间，那些共享的只读页一次都没被复制过。

### 4.3 子进程继承了什么，没继承什么

| 继承（子进程有一份） | 不继承（子进程是新的） |
|---|---|
| 地址空间内容（写时复制） | PID 和 PPID |
| 打开的文件描述符，**且共享同一个文件偏移** | 待处理的信号集，被清空 |
| 当前工作目录、根目录、`umask` | 未到期的 `alarm()` / `setitimer()` 定时器 |
| 环境变量、命令行参数 | POSIX 记录锁，见 [[4.3 文件锁]] |
| 信号处置方式（handler 的函数地址） | 除调用者之外的所有线程 |
| 用户/组 ID、进程组、控制终端 | CPU 时间统计，从零开始 |
| `nice` 值、`rlimit` 资源限制 | 信号量的 `SEM_UNDO` 调整值 |

「打开的 fd 共享同一个文件偏移」这一条最常被忽略：`fork` 复制的是 fd 表项，两份 fd 指向的是同一个 open file description，`f_pos` 存在那里，所以是共用的。父进程读走前 100 字节，子进程接着读到的是第 101 字节，而不是各自从头开始。同一张对象图也解释了[[4.3 文件锁|文件锁]]的继承规则。

### 4.4 代码示例

```c
#include <stdio.h>
#include <unistd.h>

int gval = 10;                 // 全局变量，在数据段

int main(void) {
    int lval = 25;             // 局部变量，在栈上
    gval++;                    // gval = 11
    lval += 5;                 // lval = 30
    // 到这一行为止只有一个进程，上面三句跟 fork 没有关系

    pid_t pid = fork();        // 从这一行开始，有两个进程在跑同一份代码

    if (pid == 0) {            // 子进程走这一支
        gval++;                // 改的是子进程自己那份：12
        lval++;                //                        31
        printf("子进程: gval=%d, lval=%d\n", gval, lval);
    } else if (pid > 0) {      // 父进程走这一支
        gval--;                // 改的是父进程自己那份：10
        lval--;                //                        29
        printf("父进程: gval=%d, lval=%d\n", gval, lval);
    } else {
        perror("fork");        // 别漏掉这一支，理由见下
        return 1;
    }
    return 0;
}
```

**为什么两条路径写在同一个 `if` 里。** `fork()` 之后两个进程执行的是同一份代码、同一个位置，唯一的区别就是这一次调用的返回值。拿返回值分流是区分父子的唯一手段。

**为什么全局变量和局部变量表现一样。** 数据段和栈都在地址空间里，都被写时复制覆盖。「全局变量应该是共享的」这个直觉是从[[3.Linux/12. 线程/12.1 线程简介|线程]]那里带过来的：线程共享地址空间，进程不共享。

**为什么必须判 `pid < 0`。** `fork()` 会失败，超过 `RLIMIT_NPROC`、PID 耗尽、内存不足都会返回 -1。写成 `if (pid == 0) ... else ...` 的话，失败返回的 -1 会走进 `else`，父进程逻辑在一个根本没有子进程的前提下继续往下跑，后面的 `waitpid(pid, ...)` 会拿着 -1 去等，行为跟你以为的完全不同。

**输出顺序是不确定的。** 父子谁先被调度由内核决定，两行的先后每次运行都可能不一样。要确定顺序就得用 `wait()` 或者[[3.Linux/11. 进程/11.2 进程间通信IPC|IPC]]显式同步。

### 4.5 三个由「复制」引出的陷阱

上图 B 区的三条，都是「fork 复制的不只是内存」造成的：

1. **`printf` 的内容出现两次。** stdout 接终端时是行缓冲，不带 `\n` 的内容还留在用户态缓冲区里。`fork` 把缓冲区连同内容一起复制，父子退出时各自 flush 一次。重定向到文件时变成全缓冲，触发得更频繁。`fork` 前加一句 `fflush(NULL)` 就能避免。
2. **父子共用文件偏移。** 见上一节。要各读各的，就在 `fork` 之后各自重新 `open()`。
3. **多线程程序里 `fork`。** 子进程里只有调用 `fork` 的那一个线程活着，但所有互斥量都保持着 `fork` 那一刻的状态。如果 `malloc` 的内部锁恰好被另一个线程持有，那个线程在子进程里不存在了，锁永远不会被释放，子进程里任何一次 `malloc` 都会挂死。所以 `fork` 到 `exec` 之间只能调用异步信号安全的函数。

> [!note] 回收子进程
> 子进程退出后，父进程要调用 `wait()` 或 `waitpid()` 取走它的退出状态，内核才会释放它的 PID 和 `task_struct`。漏掉这一步就产生[[3.Linux/11. 进程/11.7 僵尸进程|僵尸进程]]。

## 5. 进程与线程

[[3.Linux/12. 线程/12.1 线程简介|线程]]是 CPU 调度的单位，进程是资源分配的单位。一个进程里的多个线程共享地址空间和 fd 表，各自只有独立的栈和寄存器组。

| 对比项 | 进程 | 线程 |
|--------|------|------|
| 地址空间 | 独立 | 共享 |
| 文件描述符表 | 独立（`fork` 时复制表项） | 共享同一张表 |
| 通信方式 | 需要 IPC | 直接读写同一块内存，用互斥量保护 |
| 崩溃影响面 | 一个进程崩溃不影响别人 | 一个线程段错误，整个进程一起死 |
| 创建开销 | `fork` 要建页表，微秒级 | `pthread_create` 更轻，只分配栈和内核结构 |

在 Linux 内核里，进程和线程都是 `task_struct`，区别只在 `clone()` 时共享了哪些资源。`fork()` 什么都不共享，`pthread_create()` 内部的 `clone(CLONE_VM | CLONE_FILES | CLONE_SIGHAND | ...)` 共享地址空间、fd 表和信号处置表。所谓「线程比进程轻」，轻的是这些共享省掉的复制工作。

## 6. 进程级 overlap

**overlap** 指的是「等一件事发生的同时，另一个执行流继续干活」。它不是某个函数带来的效果，而是任务拆分加上调度器的结果：一个进程在 `read()` 里睡着的时候，内核会把核让给另一个就绪的进程。

典型形态：

1. 父进程 `fork()` 出子进程，把任务拆成两个可以独立调度的执行流。
2. 父进程留下来做控制逻辑：接命令、等新连接、提交下一批任务。
3. 子进程去做慢操作：读文件、处理一个客户端、跑一段计算。
4. 子进程在 `read()`、`accept()`、`msgrcv()` 里进入 `S` 态时，父进程照样可以是 `R` 态。
5. 子进程做完后，父进程通过 [[11.7 僵尸进程|waitpid()]]、信号或 IPC 拿到结果。

```text
时间轴:
父进程: fork() ── 继续接收任务 ── 提交下一批任务 ── waitpid(WNOHANG)
子进程:        └─ 执行慢任务 / 阻塞 I/O ──────── exit()
```

> [!note] overlap 和并行不是一回事
> overlap 说的是「等待和工作重叠」，单核机器靠阻塞切换就能做到。并行说的是「多个核同时执行指令」，需要核数够。一台单核机器上跑十个进程，有 overlap 没有并行。

## 7. 关键要点

1. 进程是**资源分配**的单位，线程是**调度**的单位；内核里两者都是 `task_struct`，区别在 `clone()` 共享了什么。
2. `ps` 里的 `R` 把就绪和运行合并了；`D` 态杀不掉，且会把 load average 抬高，排查 I/O 问题先看它。
3. PID 号在**父进程 `wait` 之后**才释放，不是进程退出时。PID 会被复用，需要可靠引用就用 pidfd。
4. `fork()` 只复制页表，物理页要等到被写才复制。这就是它对大内存进程也很快、和 `exec` 搭配几乎不花钱的原因。
5. `fork()` 之后父子共享**文件偏移**，不共享内存、不共享 POSIX 记录锁、不继承定时器和其它线程。
6. `fork` 的返回值必须判三种情况；漏掉 `-1` 会让父进程在没有子进程的前提下继续跑。
7. overlap 靠的是任务拆分加阻塞切换，跟核数无关；并行才需要核数。

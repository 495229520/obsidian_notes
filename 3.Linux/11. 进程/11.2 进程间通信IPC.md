## 1. 为什么需要 IPC

每个[[11.1 进程简介|进程]]有独立的[[1.3 进程的虚拟地址空间|虚拟地址空间]]。进程 A 里的全局变量 `counter`，进程 B 即使知道它的地址也读不到：同一个虚拟地址在两个进程的页表里指向不同的物理页。`fork()` 出来的子进程也不例外，写时复制保证了两边看到的是各自的副本。

所以进程之间要交换任何信息，都得走内核提供的通道。这些通道统称 **IPC**（Inter-Process Communication）。它们做的事无非两类：

- **搬数据**：把一段字节从 A 的地址空间弄到 B 的地址空间，或者干脆让两边映射到同一批物理页
- **传事件**：不搬数据，只告诉对方「可以动了」「我做完了」

信号量属于第二类，共享内存属于第一类，管道和消息队列两者兼有。实际系统里通常两类搭配着用。

## 2. 选型：先问四个问题

![[图片/3.Linux/11. 进程/3_11_11_2_2.svg|1100]]

「哪个最快」几乎从来不是决定因素。按这四个问题走一遍，答案基本就定了：

1. **传的是数据还是纯信号？** 只需要通知对方「可以开始了」，用信号量或 `eventfd`，别为此搭一条数据通道。
2. **双方是什么关系？** 有亲缘关系（父子）可以用匿名管道，什么关系都没有就得靠一个双方都能看见的名字：文件路径（FIFO、POSIX 共享内存）或者 `ftok` 生成的 key（System V）。跨主机只剩套接字。
3. **需要消息边界吗？** 管道是字节流，写三次读一次可能拿到粘在一起的三条；消息队列一次只给你一条完整消息。这决定了接收端要不要自己做拆包。
4. **需要和 epoll 拼在一起吗？** 这条最容易被忽略，也最能一票否决。事件循环只能等 fd，而 System V 的 `msqid`、`semid` 不是 fd，进不了 `epoll_wait`。要在一个循环里同时等网络和本机 IPC，就只能选那些句柄是 fd 的机制。

## 3. 五种机制的一句话定位

| 机制 | 一句话 | 详情 |
|------|--------|------|
| **管道 / FIFO** | 单向字节流，最简单，`shell` 的 `\|` 就是它 | [[11.3 管道通讯]] |
| **共享内存** | 零拷贝，但同步和通知都得自己搭 | [[11.4 共享内存]] |
| **信号量** | 只传许可，不传数据，是共享内存的搭档 | [[11.5 信号量]] |
| **消息队列** | 带类型的消息，保留边界，收发解耦 | [[11.6 消息队列]] |
| **套接字** | 唯一能跨主机的；Unix 域版本在本机也最好用 | [[7.6 套接字]] |

下面几节只讲各自的定位和最容易记错的点，展开看对应笔记。

### 3.1 管道

`pipe()` 建立的是**单向**通道：`fd[0]` 只能读，`fd[1]` 只能写。要双向就开两个管道。POSIX 只要求单向，某些 Unix 上 `pipe` 是双向的，写可移植代码时按单向用。

命名管道（FIFO）用一个文件系统路径当名字，任意进程 `open()` 这个路径就能接上。但**一个 FIFO 仍然是单向的**，双向同样要开两个。FIFO 在文件系统里只是一个标记，数据不落盘，走的还是内核缓冲区。

### 3.2 消息队列

内核里的一条链表，每个节点是一条带 `long` 类型标签的消息。接收方可以只取自己关心的类型，这是它和管道最本质的区别。

「异步」的准确含义是：发送方不必等接收方**取走**消息就能返回。它不等于「不会阻塞」，队列满时 `msgsnd()` 默认会睡下去，没有匹配消息时 `msgrcv()` 也会睡下去。要真的不阻塞得显式加 `IPC_NOWAIT`。

### 3.3 信号量

一个非负整数计数器。P 操作把它减 1，减不动就睡；V 操作把它加 1，顺便唤醒一个等待者。它不搬任何数据，作用是让多个进程对「谁能进临界区」达成一致。

### 3.4 共享内存

多个进程把同一批物理页映射进各自的地址空间。**建立映射需要系统调用**（`shmat` 或 `mmap`），但映射建好之后的读写就是普通访存指令，不再进内核，也没有任何拷贝。这就是「最快」的确切含义。

代价是内核什么都不管：没有消息边界、没有同步、没有「数据到了」的通知。这三件事都要自己搭，通常配[[11.5 信号量|信号量]]。

### 3.5 套接字

[[7.6 套接字|套接字]]是唯一能跨主机的 IPC。在同一台机器上用 `AF_UNIX` 域套接字，省掉整个协议栈，性能接近管道，还多两个别人没有的能力：`SOCK_SEQPACKET` 保留消息边界，`SCM_RIGHTS` 能把一个文件描述符直接递给对端进程。

## 4. 三代接口

同一件事在 Linux 上通常有三套 API，来自三个年代。看到别人的代码用哪套，基本能判断它写于什么时期。

| | System V | POSIX | 套接字与 fd 家族 |
|---|---|---|---|
| **接口** | `shmget` / `msgget` / `semget` | `shm_open` / `mq_open` / `sem_open` | `socketpair` / `eventfd` / `memfd_create` |
| **怎么寻址** | `ftok()` 生成的整数 key | 文件系统路径 | fd，或 Unix 域套接字的路径 |
| **句柄是 fd 吗** | 不是 | 是（或在 Linux 上等价于 fd） | 是 |
| **能进 epoll** | 不能 | 能 | 能 |
| **在文件系统里看得见吗** | 看不见，只能 `ipcs` | 能，在 `/dev/shm` 下 | Unix 域套接字有路径 |
| **忘了清理会怎样** | 一直留在内核里，直到重启 | 同样要 `unlink`，但至少 `ls` 能看见 | fd 关闭即回收 |

课程和教材里讲的基本都是 System V，因为它出现得最早、接口对称、适合讲清楚概念。工程上新写代码优先用后两代：句柄是 fd 意味着能进事件循环、能被 `SCM_RIGHTS` 传递、能被 RAII 或 `defer` 自动关掉。

## 5. 只传事件的几个现代机制

不需要搬数据、只需要一个「醒一下」的信号时，下面这些比信号量更好用，因为它们都是 fd：

| 机制 | 干什么 | 最小内核版本 |
|------|--------|--------------|
| `eventfd()` | 一个 64 位计数器 + 一个 fd。写它就是加计数并唤醒读端 | 2.6.22 |
| `signalfd()` | 把信号变成可读事件，不用再写异步信号安全的 handler | 2.6.22 |
| `timerfd_create()` | 把定时器变成可读事件 | 2.6.25 |
| `pidfd_open()` | 稳定引用一个进程，进程退出后 fd 变为可读，且不会因 PID 复用杀错人 | 5.3 |
| `memfd_create()` | 创建一块匿名的、有 fd 的内存，可通过 `SCM_RIGHTS` 传给别的进程共享 | 3.17 |

它们的共同点是把「等待一件事」统一成「等一个 fd 可读」，于是一个 `epoll_wait` 就能同时守着网络连接、定时器、子进程退出和 IPC 通知。这是现代事件驱动程序的基本形态。

## 6. IPC 里的 overlap

overlap 不是某个函数带来的效果，而是把「传数据 / 等事件」和「继续计算」拆开，让不同进程在不同阶段各自推进。

| 机制 | 怎么形成 overlap | 适合的场景 |
|------|-----------------|-----------|
| [[11.3 管道通讯\|管道]] | 写进程把一块数据丢进内核缓冲区就继续生产下一块；读进程边读边处理上一块 | Shell 管道、父子进程流水线 |
| [[11.6 消息队列\|消息队列]] | `msgsnd()` 把消息交给内核就返回，发送方继续跑；接收方按类型取 | 控制消息、任务分发 |
| [[11.4 共享内存\|共享内存]] | 生产者写槽位 A 的同时，消费者处理槽位 B，用信号量切换 | 大块数据、高吞吐 |
| [[11.5 信号量\|信号量]] | 不传数据，只负责把「可写 / 可读 / 已完成」通知出去，省掉忙等 | 共享内存同步、资源池 |
| 套接字 | 非阻塞 fd 加 `epoll`，等网络的同时处理已就绪的连接 | 网络服务器 |

![[图片/3.Linux/11. 进程/11.3-管道overlap通用步骤.png|900]]

通用套路：

1. **拆阶段**：把任务分成生产、传递、消费三段，让它们能在不同进程里同时推进。
2. **放缓冲**：中间要有个能存东西的地方，管道缓冲区、消息队列、共享内存环形队列、socket buffer 都行。缓冲区的容量决定了两端速度差多少还能撑住。
3. **别做无意义的阻塞**：等一件必须等的事就用阻塞唤醒，CPU 会让给别人；想在等待期间干别的就用 `IPC_NOWAIT`、`O_NONBLOCK`、`WNOHANG` 或者 I/O 多路复用。忙等是最差的选择，它既占核又不比阻塞快。
4. **批次化**：一次传一批而不是一条，让「传上一批」和「算下一批」真的能重叠。批次太小时系统调用开销会盖过收益。
5. **用同步收边界**：靠信号量、消息类型、结束标记或子进程退出状态告诉对方哪一批已经完整了。

```text
生产者进程: 准备 batch 1 ── 发送/写入 ── 准备 batch 2 ── 发送/写入
IPC 缓冲区:              保存 batch 1 ── 被消费 ── 保存 batch 2
消费者进程:                    读取 batch 1 ── 处理 batch 1 ── 读取 batch 2
```

## 7. 关键要点

1. IPC 做两件事：**搬数据**和**传事件**。分不清要哪一件，就会用共享内存去做本该 `eventfd` 做的通知。
2. 选型的四个问题：传数据还是传信号、双方什么关系、要不要消息边界、**要不要能进 epoll**。最后一条最常被忽略，也最能一票否决。
3. 管道和 FIFO 都是**单向**的，双向要开两个。管道没有消息边界，接收端要自己拆包。
4. 消息队列的「异步」指发送方不等接收方取走，不是「不会阻塞」；队列满照样睡，要非阻塞得写 `IPC_NOWAIT`。
5. 共享内存的零拷贝指**映射建好之后**的读写不进内核；建立映射本身是系统调用。同步、通知、边界三件事都要自己搭。
6. System V 的句柄不是 fd，进不了 epoll，忘了 `IPC_RMID` 会一直留在内核里。新代码优先 POSIX 接口或 Unix 域套接字。
7. overlap 靠缓冲、非阻塞或事件通知、批次化三件事凑成，跟具体用哪个 IPC 关系不大。

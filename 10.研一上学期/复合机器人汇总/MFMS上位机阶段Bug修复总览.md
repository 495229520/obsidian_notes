## §1 跨线程 QSqlDatabase 复用 —— 断库时登录后段错误

- **提交**：`52c1a83`
- **现象**：本地数据库不可达（远程库 `100.84.157.31` 长期离线）时，登录界面能进，但登录成功后客户端**间歇性直接段错误退出**；库在线时一切正常，问题隐蔽。
- **根因**：`DatabasePool` 把在 A 线程创建的 `QSqlDatabase` 连接直接交给其他工作线程使用。Qt 文档明确规定连接只能在创建它的线程中使用，QMYSQL 驱动跨线程复用是**未定义行为**——连接健康时侥幸不炸，连接失败/重连路径一走就踩内存。
- **修法**：
	1. 连接**按线程缓存**：`DatabasePool` 以线程为键管理连接，每个线程首次取用时创建自己的连接，命名互不冲突；
	2. 线程结束时挂钩清理，随线程销毁对应连接，防连接泄漏；
	3. `LogHandle::getLogs()` 在连接未打开时直接跳过查询，不再拿着坏连接执行 SQL。
- **配套**（`f697b0e`，非 bug 但同因）：Docker 部署内置 `mysql:8.0` 服务，首次启动自动导入 `MFMS_BASE.sql`，用 `MFMS_DB_*` 环境变量指向本地库——从根上摆脱对长期离线的远程库的依赖。

> [!tip] 经验
> Qt 数据库连接的线程亲和性是硬约束：**谁创建，谁使用**。连接池若要跨线程服务，正确形态是"每线程一连接"，而不是"一个连接大家用"。这类错误在依赖方（数据库）健康时完全无症状，排查时要主动制造故障（拔库）复现。

## §2 AGV 40020 拒令与控制权接管缺失

- **提交**：`7d7c695`（含 B1/B2 两个子修复）
- **现象**：现场 AGV 对上位机的运动指令报错 40020，UI 无解释；抓包确认**指令实际已到达真车**，是仙工 RBK 返回 `locked`——控制权被 Roboshop/调度占用，而上位机没有任何接管手段。
- **根因**：SEER 协议下控制权是独占资源，旧版上位机根本没有实现接管/释放/查询（SEER 301/302/303）这组命令，被夺权后只能干瞪眼。
- **修法**：
	1. 全链路（UI → CommunicationInterface → Worker → Gateway → CommandService → AgvProxyAdapter → SeerCtrl）新增接管/释放/查询控制权；控制页加「接管权限」按钮，未接管时禁用 AGV 运动控件，40020 拒令时明确提示并复位接管态；
	2. **接管即停**（B1）：SEER 被夺权时车不会自动停，接管成功后立即下发 `guideCancel + stopManualCtrl`；停车结果无法由返回码可靠判定，UI 措辞如实提示人工确认；
	3. **结果通道隔离**（B2）：控制权结果走独立信号 `agvControlAuthority*`，与导航/普通指令结果分离，防止接管状态机被导航轮询结果击穿；
	4. AGV 连接成功写 `device_state=connected`、断开回 `online`，使设备进入可控状态（参考 AUBO 连接即自动使能的做法）。
- **后续**：接管后控制权仍可能被再次夺走，由此引出 40101 卡死问题，在 `55421a1` 修复（指纹轮询 + 错误码自愈），见 [[MFMS上位机Bug修复汇总-锁竞态与控制权#Bug 1：AGV 控制权被外部夺走后 UI 状态不同步（40101 卡死）]]。

## §3~§8 锁、竞态、控制权与单位（索引）

以下六项的完整"现象 → 根因 → 修法 → 验证"记录在 [[MFMS上位机Bug修复汇总-锁竞态与控制权]]，此处只留一句话结论：

- **全局锁跨 RPC**（`bac7252` ①）：适配器全局 `QMutex` 持锁横跨 8s 阻塞 RPC，是"偶发全面失控、重启才好"的元凶。修法：全局锁只护代理表，RPC 改在**每设备互斥**下执行，超时 8s→3s，连接前加 service 就绪预检。
- **连接必回包**（`bac7252` ②）：设备不在线的连接路径永远无回包。修法：`doConnectRobot` 加 20s 死线强制收尾发 `connectionResult`。
- **结果关联 ID**（`bac7252` ③）：`armControlRes`/`agvControlRes` 追加 `requestId` 尾参，运动接口返回请求 ID；Qt 信号尾参机制保证存量 UI 零改动。
- **40101 卡死**（`55421a1`）：接管期间 2s 轮询 SEER 303 + 占用者指纹比对，撞 40101/40020 自动把本地状态同步为未接管。
- **模拟器兼容**（`11b042c`）：状态话题 BEST_EFFORT→RELIABLE（代理订阅是 RELIABLE，QoS 不兼容收不到状态）；Fr 指令服务名改用完整设备 ID `/robFro0002_cmd`。
- **Aubo 单位**（`29cc7c6`→`4f33b3b`）：据 aubo_sdk 头文件注释加的 米/弧度 换算是错的——下位机封装层已归一为 mm/deg，0.5mm 被缩成半微米导致"路点不可达 -1"。撤销换算，**单位以 `ros2 topic echo` 实测量级为准，不信 SDK 注释**。

## 定位方法论（本阶段最大收获）

1. **自研浸泡测试代替猜测**：`soak_arm_jog` 走与 UI 完全相同的 7 层客户端栈做成对自抵消 jog，按 `timeout_late`（锁/阻塞）vs `timeout`（竞态）vs 串扰（配对错误）自动分类，把"感觉卡"变成可量化证据——模拟环境 1.2 万条零丢失排除竞态，Phase B 时延 2.3 倍实锤锁排队。
2. **制造故障验证假设**：拔库复现段错误、中途重启下位机观察阻塞窗口归属，比等现场偶发高效得多。
3. **单位、协议一律实测**：`ros2 topic echo` 看量级、抓服务名对拍 `dev_proxy::get_service_name()`，SDK 注释和文档只作参考。

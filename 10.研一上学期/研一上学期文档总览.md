## 主题一：课题定位与总体成果

### 开题与研究目标

[[10.研一上学期/开题报告_复合机器人数据中台代理适配器协同系统|开题报告]]把课题定义为“基于代理适配器的复合机器人数据中台协同系统”，核心目标包括：

- 用 PIMPL 和设备代理隔离 Fairino、Aubo、仙工 AGV 等异构 SDK；
- 统一设备 ID、状态结构、命令语义和 ROS Topic/Service 命名；
- 用 Facade 网关聚合数据库、ROS 和命令能力；
- 向 Qt 上位机提供线程安全接口；
- 通过真机联调、性能优化、测试和文档形成工程闭环。

### 学期阶段性成果

综合现有资料，已经形成以下主要成果：

- `mfms_server` 从模拟器工具演进为包含 `client_api`、`gateway`、`mfms_db`、`ros_bridge`、`cmd_service` 和代理适配器的中间层。
- `CommunicationInterface` 已覆盖设备列表、连接、机械臂控制、AGV 站点/路径/导航和手动控制等能力。
- 上位机与下位机形成 ROS 实时通道、MySQL 事件通道以及本地告警日志通道。
- 针对数据库线程亲和性、阻塞 RPC、控制权、请求关联、单位、UI 生命周期和现场网络完成多轮治理。
- 建立 `.trellis` 任务、规范、检查、归档和经验回写机制。

## 主题二：数据中台架构

### 当前实现的主文档

[[10.研一上学期/复合机器人汇总/MFMS数据中台技术文档-架构线程与代理层|MFMS 数据中台技术文档：架构、线程与代理层]]是当前目录中描述现行实现时优先级最高的架构笔记。它基于 2026-07-18 左右的代码核实，明确了：

- Qt 只通过 `CommunicationInterface` 接入，不直接依赖设备 SDK；
- UI 请求进入独立 Worker，随后经过 Gateway 分发到 DB、ROS 和命令服务；
- 同设备操作串行、跨设备操作并行；
- `requestId` 用于把异步结果与原请求关联；
- ROS 负责实时控制和状态，MySQL 负责生命周期、脚本和资源，日志文件负责告警增量读取；
- 首页跨设备数据在中台侧聚合，避免 UI 自行拼装系统状态。

### 4 月架构基线

- [[10.研一上学期/MFMS_DataCenter_Architecture|MFMS 数据中台架构分析文档]]：内容最全面，包含整体架构、线程、数据库、代理层、接口状态和源码索引，但基于 2026-04 的代码，应作为早期基线使用。
- [[10.研一上学期/MFMS_DataCenter_Technical_Documentation|MFMS 数据中台完整技术文档]]：偏开发交接和端到端调用链，覆盖包结构、线程、状态机、数据库和构建验证；涉及 7 月以后演进时，应以较新的“架构、线程与代理层”为准。

### 新版架构方向

[[10.研一上学期/复合机器人汇总/MFMS数据中台新版架构设计-分层功能与拍板记录|新版架构设计]]描述的是未来方向，不是当前代码事实：

- 数据中台从 Qt 进程内中间层变为局域网独立服务；
- Qt、Web、SCADA、MES 等客户端通过 HTTP、推送或 OPC UA 服务面接入；
- MySQL 双事件表与 ROS 2 总线继续并存；
- 当前仍待拍板推送机制、OPC UA 排期和代码落点。

> [!warning] 架构边界
> 新版架构和 LightCore 相关提案属于候选路线图。没有专门设计任务和明确批准时，不能据此提前删除 Gateway、改变线程模型或替换现有命令链。

### 可复用的排障方法

- 先用日志和成功回包确认用户描述是否准确，再构造根因链。
- 用浸泡测试区分“慢而不丢”“真正丢失”和“结果串扰”。
- 主动制造故障，例如断库、重启下位机，验证异常路径。
- 单位和协议以运行时量级、Topic/Service 和真机结果为准，不只相信 SDK 注释。
- 网络问题按物理链路、IP/路由、ROS/服务、应用层四级逐层验证。

```text
需求 → Task/PRD → Design/Implement → 注入相关 Spec
  → 实现 → Check → 提炼稳定经验 → 更新 Spec
```

## 重复项与后续整理建议

# 15.12 回调函数

---

## 什么是回调函数

**回调函数（Callback Function）不是 C++ 的某一种特殊语法，而是一种调用方式。**

简单来说：

> [!note]
> 把一个函数或可调用对象交给另一个函数、类或框架，由对方在合适的时机反过来调用，这个被传入并稍后执行的逻辑就叫**回调函数**。

普通调用是“我主动调用你”：

```cpp
result = add(10, 20);
```

回调调用是“我把要做的事情交给你，你需要的时候再调用”：

```cpp
calculate(10, 20, add);
```

在这个例子里：

- `add` 是调用方提供的处理逻辑
- `calculate` 是接收回调的函数
- `calculate` 内部决定什么时候调用 `add`

这就是回调的核心思想：**调用方提供行为，框架或库决定调用时机**。

---

## 为什么需要回调函数

回调函数最重要的价值是：**把固定流程和可变行为分离开**。

例如一个排序函数的整体流程是固定的：

1. 遍历元素
2. 比较元素
3. 交换位置
4. 得到有序结果

但是“怎么比较两个元素”是可变的：

- 可以升序
- 可以降序
- 可以按字符串长度
- 可以按结构体中的某个字段

所以排序函数不应该把比较规则写死，而应该让调用者把比较规则传进来。这个被传入的比较规则，就是一种回调。

常见动机包括：

1. **解耦**：库代码只负责流程，用户代码只负责具体行为
2. **扩展**：同一套流程可以替换不同处理逻辑
3. **事件驱动**：按钮点击、消息到达、定时器触发后执行用户逻辑
4. **算法定制**：`std::sort`、[[15.5 for_each|std::for_each]] 等算法接收自定义行为
5. **异步通知**：任务完成后调用用户传入的完成处理函数
6. **C/C++ 混合编程**：C 接口通过函数指针调用 C++ 逻辑

---

## 回调的本质：可调用对象

在 C++ 中，能被“像函数一样调用”的东西都可以作为回调。常见形式包括：

| 回调形式 | 示例 | 特点 |
| --- | --- | --- |
| 普通函数 | `int add(int, int)` | 简单、高效，但不能直接携带状态 |
| 函数指针 | `int (*)(int, int)` | C 风格回调的基础，详见 [[9.1.5 函数指针]] |
| 仿函数 | `object.operator()` | 可以用成员变量保存状态，详见 [[15.6 仿函数]] |
| Lambda | `[](int x) { ... }` | 现代 C++ 最常用，详见 [[15.4 lambda]] |
| `std::function` | `std::function<void(int)>` | 统一包装不同类型的可调用对象 |
| 成员函数包装 | `[this] { handle(); }` | 常用于对象方法回调 |

回调函数的重点不是“它长什么样”，而是：**它被作为参数、成员变量或注册项交给别人，并由别人稍后调用**。

---

## 常见回调实现方式

### 1. 普通函数和函数指针回调

函数指针是最传统的回调方式，尤其常见于 C 接口。

```cpp
using Operation = int (*)(int, int);
```

这表示 `Operation` 是一种函数指针类型，指向“接收两个 `int`，返回一个 `int`”的函数。

优点：

- 开销小
- 和 C 接口兼容
- 适合简单、无状态的回调

缺点：

- 类型写法较复杂
- 不能直接保存状态
- 不能直接接收捕获变量的 lambda
- 不能直接绑定非静态成员函数

---

### 2. 仿函数回调

仿函数是重载了 `operator()` 的对象。

它看起来像函数，但本质上是对象，所以可以保存状态：

```cpp
class Counter {
public:
    void operator()(int value) {
        if (value > 0) {
            ++count_;
        }
    }

    int count() const {
        return count_;
    }

private:
    int count_ = 0;
};
```

仿函数适合：

- 回调逻辑需要复用
- 回调需要保存配置
- 回调需要在多次调用之间保存状态

---

### 3. Lambda 回调

[[15.4 lambda|Lambda 表达式]]是现代 C++ 中最常用的回调写法。

它的优势是：**可以在调用现场直接写出回调逻辑**。

```cpp
std::for_each(numbers.begin(), numbers.end(), [](int value) {
    std::cout << value << ' ';
});
```

如果需要访问外部变量，可以使用捕获列表：

```cpp
int sum = 0;

std::for_each(numbers.begin(), numbers.end(), [&sum](int value) {
    sum += value;
});
```

这里的 lambda 就是传给 `std::for_each` 的回调。`std::for_each` 遍历容器，并在每个元素上调用这个 lambda。

---

### 4. `std::function` 统一回调接口

`std::function` 可以保存各种可调用对象：

- 普通函数
- 函数指针
- 仿函数
- Lambda
- 绑定后的成员函数

例如：

```cpp
std::function<void(int)> callback;
```

这表示 `callback` 可以保存任何“接收一个 `int`，返回 `void`”的可调用对象。

`std::function` 的优势是接口统一：

```cpp
void registerCallback(std::function<void(int)> callback);
```

调用方可以自由传入普通函数、lambda 或仿函数，而接口不需要改变。

需要注意的是，`std::function` 使用了类型擦除，灵活性更高，但通常会比直接模板参数或函数指针多一点开销。日常业务代码和学习阶段优先理解清楚它的表达能力即可。

---

### 5. 成员函数回调

非静态成员函数不能直接当作普通函数指针使用。

原因是非静态成员函数隐含一个 `this` 参数：

```cpp
class Controller {
public:
    void handleClick();
};
```

`Controller::handleClick` 表面上没有参数，但真正调用时必须知道“调用哪个对象的 `handleClick`”。这就是 `this`。

因此成员函数回调通常要绑定对象，最常见写法是用 lambda 包装：

```cpp
Controller controller;

button.setOnClick([&controller] {
    controller.handleClick();
});
```

更底层的成员函数指针知识可以看 [[9. 指向类成员的指针]]。

---

### 6. C 风格回调桥接 C++ 对象

很多 C 库只认识普通函数指针，不认识 C++ 对象和成员函数。

典型 C 风格接口会长这样：

```cpp
using CCallback = void (*)(int, void*);

void registerCallback(CCallback callback, void* userData);
```

这里的 `void* userData` 用来保存调用方的上下文，常见做法是把 C++ 对象地址传进去，回调触发时再转回对象指针。

这个模式在系统 API、C 库、跨语言接口中非常常见，详细原理可以看 [[3.1 C回调接口与C++对象]]。

## 详细示例

### 示例 1：函数指针回调——计算器操作

#### 场景说明

假设我们写一个通用计算函数 `calculate`，它只负责接收两个数字和一个操作规则。至于到底做加法、减法还是乘法，由调用者传入。

#### 代码

```cpp
#include <iostream>

using Operation = int (*)(int, int);

int add(int lhs, int rhs) {
    return lhs + rhs;
}

int subtract(int lhs, int rhs) {
    return lhs - rhs;
}

int calculate(int lhs, int rhs, Operation operation) {
    return operation(lhs, rhs);
}

int main() {
    std::cout << calculate(20, 10, add) << std::endl;
    std::cout << calculate(20, 10, subtract) << std::endl;

    return 0;
}
```

#### 执行流程

1. `main` 调用 `calculate(20, 10, add)`
2. `calculate` 接收到函数指针 `operation`
3. `calculate` 内部调用 `operation(lhs, rhs)`
4. 实际执行的是 `add(20, 10)`
5. 第二次调用时传入 `subtract`，同一个 `calculate` 执行了不同逻辑

#### 为什么这是回调

`add` 和 `subtract` 并不是由 `main` 直接调用的，而是先传给 `calculate`，再由 `calculate` 内部调用。

所以：

- `calculate` 是接收回调的宿主函数
- `add` / `subtract` 是回调函数
- 调用方决定“做什么”
- 宿主函数决定“什么时候做”

#### 适用场景

函数指针回调适合简单、无状态、对性能和 C 兼容性有要求的场景。

### 示例 2：Lambda 回调——遍历容器并处理元素

#### 场景说明

我们写一个 `forEachElement` 函数，它负责遍历 `std::vector<int>`，但不规定每个元素应该怎么处理。

处理逻辑由调用方通过 lambda 传入。

#### 代码

```cpp
#include <functional>
#include <iostream>
#include <vector>

void forEachElement(const std::vector<int>& numbers,
                    const std::function<void(int)>& callback) {
    for (int value : numbers) {
        callback(value);
    }
}

int main() {
    std::vector<int> numbers = {1, 2, 3, 4, 5, 6};

    forEachElement(numbers, [](int value) {
        std::cout << value << ' ';
    });
    std::cout << std::endl;

    int evenCount = 0;

    forEachElement(numbers, [&evenCount](int value) {
        if (value % 2 == 0) {
            ++evenCount;
        }
    });

    std::cout << "偶数个数：" << evenCount << std::endl;

    return 0;
}
```

#### 执行流程

第一次调用：

1. `main` 把打印元素的 lambda 传给 `forEachElement`
2. `forEachElement` 遍历 `numbers`
3. 每遇到一个元素，就调用一次 `callback(value)`
4. 实际执行的是调用方传入的打印逻辑

第二次调用：

1. lambda 通过引用捕获 `evenCount`
2. `forEachElement` 每遍历一个元素，就调用一次 lambda
3. lambda 判断当前元素是否为偶数
4. 如果是偶数，就修改外部变量 `evenCount`

#### 为什么这是回调

`forEachElement` 不知道调用方要打印、统计还是筛选。它只知道“每个元素都调用一次传入的 callback”。

这就是回调带来的灵活性：**遍历流程固定，元素处理逻辑可替换**。

#### 适用场景

Lambda 回调适合短小、就地定义、只在当前调用点使用一次的逻辑。

### 示例 3：仿函数回调——带状态的统计器

#### 场景说明

如果回调逻辑需要保存状态，并且这个逻辑可能被复用，可以使用[[15.6 仿函数|仿函数]]。

下面的 `EvenCounter` 会统计被调用过程中遇到的偶数数量。

#### 代码

```cpp
#include <algorithm>
#include <iostream>
#include <vector>

class EvenCounter {
public:
    void operator()(int value) {
        if (value % 2 == 0) {
            ++count_;
        }
    }

    int count() const {
        return count_;
    }

private:
    int count_ = 0;
};

int main() {
    std::vector<int> numbers = {1, 2, 3, 4, 5, 6, 7, 8};

    EvenCounter counter;

    counter = std::for_each(numbers.begin(), numbers.end(), counter);

    std::cout << "偶数个数：" << counter.count() << std::endl;

    return 0;
}
```

#### 执行流程

1. `EvenCounter counter` 创建一个可调用对象
2. `std::for_each` 遍历 `numbers`
3. 每个元素都会触发 `counter(value)`
4. 实际调用的是 `EvenCounter::operator()`
5. `count_` 在多次调用之间保存统计结果

#### 为什么这是回调

`std::for_each` 是宿主算法，`counter` 是传入的回调对象。

算法负责遍历，仿函数负责处理每个元素。

#### 适用场景

仿函数适合：

- 回调逻辑较复杂
- 需要保存状态
- 需要封装多个成员变量
- 需要在多个地方复用同一类处理逻辑

### 示例 4：`std::function` 回调——任务完成通知

#### 场景说明

回调经常用于“某件事完成之后通知调用者”。

下面的 `runTask` 接收两个回调：

- `task`：真正要执行的任务
- `onFinished`：任务完成后的处理逻辑

#### 代码

```cpp
#include <functional>
#include <iostream>

void runTask(const std::function<int()>& task,
             const std::function<void(int)>& onFinished) {
    int result = task();
    onFinished(result);
}

int main() {
    runTask(
        [] {
            std::cout << "正在执行任务..." << std::endl;
            return 42;
        },
        [](int result) {
            std::cout << "任务完成，结果是：" << result << std::endl;
        }
    );

    return 0;
}
```

#### 执行流程

1. `main` 把任务逻辑和完成逻辑传给 `runTask`
2. `runTask` 调用 `task()` 执行任务
3. `task()` 返回结果 `42`
4. `runTask` 调用 `onFinished(result)` 通知调用方

#### 为什么这是回调

`runTask` 本身并不知道任务要做什么，也不知道任务完成后要怎么处理。它只定义流程：

1. 运行任务
2. 得到结果
3. 调用完成回调

这种结构在异步编程、线程任务、网络请求完成通知中非常常见。线程相关基础可以看 [[15.2 thread]]。

#### 适用场景

`std::function` 适合作为对外接口中的回调参数，尤其当你希望调用方可以传入普通函数、lambda、仿函数等不同形式时。

### 示例 5：成员函数回调——用 lambda 绑定对象

#### 场景说明

GUI、游戏、服务器事件系统中经常出现这样的需求：

- `Button` 负责检测点击
- `Controller` 负责处理点击后的业务逻辑

`Button` 不应该依赖具体的 `Controller` 类型，所以可以让外部注册一个点击回调。

#### 代码

```cpp
#include <functional>
#include <iostream>
#include <utility>

class Button {
public:
    void setOnClick(std::function<void()> callback) {
        onClick_ = std::move(callback);
    }

    void click() const {
        if (onClick_) {
            onClick_();
        }
    }

private:
    std::function<void()> onClick_;
};

class Controller {
public:
    void handleClick() const {
        std::cout << "Controller 处理按钮点击" << std::endl;
    }
};

int main() {
    Button button;
    Controller controller;

    button.setOnClick([&controller] {
        controller.handleClick();
    });

    button.click();

    return 0;
}
```

#### 执行流程

1. `Button` 保存一个 `std::function<void()>` 类型的回调
2. `Controller` 提供成员函数 `handleClick`
3. `main` 用 lambda 捕获 `controller`
4. lambda 内部调用 `controller.handleClick()`
5. `button.click()` 触发点击事件
6. `Button` 调用保存的 `onClick_`
7. 实际执行的是 `Controller::handleClick`

#### 为什么不能直接传成员函数

非静态成员函数需要对象才能调用：

```cpp
controller.handleClick();
```

而不是单独调用：

```cpp
handleClick();
```

所以成员函数回调必须把“对象 + 成员函数”一起绑定起来。lambda 是最直观的绑定方式。

#### 适用场景

成员函数回调适合面向对象设计中的事件处理，例如：

- 按钮点击
- 网络连接建立
- 消息到达
- 定时器触发
- 状态变化通知

这类设计和 [[16.3 观察者模式]] 很接近。

### 示例 6：C 风格接口桥接 C++ 对象

#### 场景说明

有些 C 库要求你注册一个普通函数指针，但你的处理逻辑写在 C++ 类中。

这时可以使用 `void* userData` 传递对象地址，再在回调函数中恢复对象。

#### 代码

```cpp
#include <iostream>

using CCallback = void (*)(int, void*);

class CEventSource {
public:
    void registerCallback(CCallback callback, void* userData) {
        callback_ = callback;
        userData_ = userData;
    }

    void emit(int value) const {
        if (callback_ != nullptr) {
            callback_(value, userData_);
        }
    }

private:
    CCallback callback_ = nullptr;
    void* userData_ = nullptr;
};

class Receiver {
public:
    void onEvent(int value) const {
        std::cout << "收到事件值：" << value << std::endl;
    }
};

void receiverCallback(int value, void* userData) {
    auto* receiver = static_cast<Receiver*>(userData);
    receiver->onEvent(value);
}

int main() {
    CEventSource source;
    Receiver receiver;

    source.registerCallback(receiverCallback, &receiver);
    source.emit(100);

    return 0;
}
```

#### 执行流程

1. `Receiver receiver` 是真正处理事件的 C++ 对象
2. `receiverCallback` 是 C 风格普通函数指针，符合 `CCallback` 类型
3. 注册时把 `receiverCallback` 和 `&receiver` 一起传给 `source`
4. `source.emit(100)` 触发事件
5. `emit` 内部调用 `callback_(value, userData_)`
6. `receiverCallback` 使用 `static_cast<Receiver*>(userData)` 恢复对象指针
7. 最终调用 `receiver->onEvent(value)`

#### 为什么这是回调

`Receiver::onEvent` 没有被 `main` 直接调用，而是通过 C 风格函数指针和 `void*` 上下文间接触发。

这就是 C 接口桥接 C++ 对象的经典回调模式。

#### 适用场景

这种方式常见于：

- 操作系统 API
- C 语言库
- 跨语言绑定
- 旧项目中的 C 接口
- 网络库或图形库的事件回调

更完整的调用约定、`this` 指针和 static 桥接模式解释，可以看 [[3.1 C回调接口与C++对象]]。

## 常见使用场景

### 1. STL 算法定制

标准库算法经常接收回调来定制行为。

```cpp
std::sort(numbers.begin(), numbers.end(), [](int lhs, int rhs) {
    return lhs > rhs;
});
```

这里的 lambda 是排序比较回调。`std::sort` 决定什么时候比较元素，调用方决定比较规则。

---

### 2. 容器遍历处理

`std::for_each` 会遍历区间，并对每个元素调用用户传入的可调用对象。

```cpp
std::for_each(numbers.begin(), numbers.end(), [](int value) {
    std::cout << value << std::endl;
});
```

这类写法适合把“遍历流程”和“处理动作”分离。

---

### 3. 事件通知

按钮点击、键盘输入、网络消息到达，都可以使用回调表达：

```cpp
button.setOnClick([] {
    std::cout << "按钮被点击" << std::endl;
});
```

这也是 [[16.3 观察者模式]] 的基础思想：对象状态变化后，通知外部注册的处理逻辑。

---

### 4. 异步任务完成处理

回调经常用于“任务完成之后”：

```cpp
runTask(task, [](int result) {
    std::cout << "处理任务结果：" << result << std::endl;
});
```

这种写法让任务执行和结果处理分离，也方便后续扩展为线程、事件循环或网络请求。

---

### 5. 策略替换

如果一个算法中的某一步经常变化，可以把这一步做成回调。

例如 [[16.4 策略模式]] 中，策略对象本质上也是“可替换行为”。

使用 `std::function` 后，很多简单策略可以直接写成回调：

```cpp
class PriceCalculator {
public:
    explicit PriceCalculator(std::function<double(double)> discount)
        : discount_(std::move(discount)) {}

    double calculate(double price) const {
        return discount_(price);
    }

private:
    std::function<double(double)> discount_;
};
```

这里 `discount_` 就是一个价格计算策略，也可以理解成一个回调。

---

## 常见误区

### 误区 1：回调一定是异步的

不一定。

例如 `std::for_each` 中的回调就是同步调用：

```cpp
std::for_each(numbers.begin(), numbers.end(), callback);
```

每遍历一个元素就立刻调用一次 `callback`。

异步任务中的完成通知也可以用回调，但“异步”不是回调的必要条件。

---

### 误区 2：Lambda 就是回调

不准确。

Lambda 是一种可调用对象，只有当它被传给别人，并由别人调用时，它才扮演回调角色。

```cpp
auto add = [](int lhs, int rhs) {
    return lhs + rhs;
};

int result = add(1, 2);
```

这里 lambda 被直接调用，不是典型回调。

```cpp
calculate(1, 2, add);
```

这里 lambda 被传入 `calculate`，并由 `calculate` 调用，它才是回调。

---

### 误区 3：成员函数可以直接当普通函数指针

非静态成员函数不能直接当普通函数指针，因为它需要 `this`。

```cpp
class Receiver {
public:
    void onEvent(int value);
};
```

`Receiver::onEvent` 需要知道调用哪个 `Receiver` 对象，因此通常要通过 lambda、`std::bind` 或 static 桥接函数绑定对象。

---

### 误区 4：引用捕获总是安全的

lambda 回调中按引用捕获变量时，要确保回调执行时被捕获的变量仍然存在。

```cpp
std::function<void()> makeCallback() {
    int value = 10;

    return [&value] {
        std::cout << value << std::endl;
    };
}
```

这个例子有问题：`makeCallback` 返回后，局部变量 `value` 已经销毁，回调中的引用变成悬空引用。

更安全的写法是按值捕获：

```cpp
std::function<void()> makeCallback() {
    int value = 10;

    return [value] {
        std::cout << value << std::endl;
    };
}
```

## 如何选择回调写法

| 写法 | 适合场景 | 优点 | 注意点 |
| --- | --- | --- | --- |
| 函数指针 | C 接口、简单无状态回调 | 高效、兼容 C | 不能直接携带状态 |
| 仿函数 | 复杂逻辑、需要保存状态 | 封装性强、可复用 | 写法比 lambda 重 |
| Lambda | 临时、小型、就地定义的回调 | 简洁、最常用 | 注意捕获变量生命周期 |
| `std::function` | 对外暴露统一回调接口 | 灵活、可读性好 | 有类型擦除开销 |
| 成员函数包装 | 对象方法作为事件处理逻辑 | 适合面向对象设计 | 需要绑定对象 |
| C 风格桥接 | C API 调用 C++ 对象 | 工程中很常见 | 需要正确管理 `void*` 上下文 |

一般建议：

1. **写现代 C++ 业务代码**：优先使用 lambda 和 `std::function`
2. **回调需要保存复杂状态**：考虑仿函数或类对象
3. **对接 C 接口**：使用函数指针和 `void* userData`
4. **回调成员函数**：优先用 lambda 绑定对象
5. **性能极端敏感**：可以考虑模板参数或函数指针，避免不必要的 `std::function` 类型擦除

---

## 关键要点

1. 回调是一种设计思想，不是某一种固定语法。
2. 回调的核心是：把可调用对象交给别人，由别人决定调用时机。
3. 函数指针是传统回调方式，尤其适合 C 接口。
4. Lambda 是现代 C++ 中最常用的回调写法。
5. `std::function` 可以统一保存不同类型的可调用对象，适合作为回调接口。
6. 仿函数适合封装带状态、可复用的回调逻辑。
7. 非静态成员函数需要绑定对象，不能直接当普通函数指针使用。
8. 回调能提升扩展性，但过度嵌套或生命周期管理不当会降低可读性和安全性。

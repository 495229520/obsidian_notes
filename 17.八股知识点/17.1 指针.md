# 17.1 指针

按 C++17 整理；其他版本单独标注。每题末尾链接到原笔记，便于回查。

## 一、基础指针

### 1. 空指针、野指针、悬空指针有什么区别？

- 空指针：明确不指向对象，如 `int* p = nullptr;`，不能解引用。
- 野指针：通常指未初始化的局部指针，如 `int* p;`，不能拿来访问内存。
- 悬空指针：原来指向的对象已经结束生命周期，如 `delete` 后、返回局部变量地址、容器扩容使原指针失效。
- `delete p;` 不会把 `p` 自动置空；`p = nullptr;` 也不会修复其他指向同一对象的悬空指针。`if (p)` 只能判断是否为空，不能证明对象还活着。
- `nullptr` 有专门的类型 `std::nullptr_t`，比通常定义为整数空指针常量的 `NULL` 更适合重载和模板。

引用：[[1.C++基础/6. 指针/6.3 动态内存分配的风险|动态内存风险]]。

### 2. 指针大小、运算步长和成员访问怎么答？

指针存储地址；`p` 是保存的地址，`*p` 访问目标，`&p` 是指针变量自身的地址。常见 32/64 位平台的普通对象指针分别为 4/8 字节，具体以实现为准。

`T* p` 的 `p + 1` 前进一个 `T` 元素，即 `sizeof(T)` 字节。运算结果必须在同一数组内或恰好到尾后位置；尾后指针可以作边界，不能解引用。同一数组内两个指针相减得到元素个数。

结构体指针的 `p->member` 等价于 `(*p).member`；结构体可能含对齐填充，`sizeof` 不一定等于成员大小之和。对齐看 `alignof`，不能一律拿成员的 `sizeof` 代替。

引用：[[1.C++基础/6. 指针/6.1基本指针|基本指针]]、[[1.C++基础/6. 指针/6.9 总结#指针运算|指针运算]]、[[1.C++基础/6. 指针/6.7 指针结构体|结构体与对齐]]。

### 3. const 放在指针的哪里有什么区别？

| 声明                              | 能否改变指向 | 能否通过 p 修改对象 |
| ------------------------------- | ------ | ----------- |
| `const int* p` / `int const* p` | 能      | 不能          |
| `int* const p = &x`             | 不能     | 能           |
| `const int* const p = &x`       | 不能     | 不能          |

“不能通过这个指针修改”不代表原对象一定是常量。

引用：[[1.C++基础/6. 指针/6.1基本指针#四、常量指针与指针常量|const 与指针]]。

### 4. 指针与引用有什么区别？

指针是保存地址的对象，可以为空、可以改指向；引用是对象的别名，定义时需要绑定，之后不能改绑，没有合法的空引用。引用也可能悬空，不能返回局部变量的引用。

普通 `T* p` 参数按值传递，函数内改 `p` 不会改变调用者的指针；要改调用者的指向，可用 `T*&` 或 `T**`。引用底层常用地址实现，但标准不要求它就是指针或必占一个指针的大小。

引用：[[1.C++基础/6. 指针/6.4 引用|引用]]。

### 5. 数组名是指针吗？数组指针与指针数组呢？

数组是数组类型，在多数表达式中才转换为首元素指针。对 `int a[5]`：

- `sizeof(a)` 是整个数组大小；`int* p = a;` 后，`sizeof(p)` 是指针大小。
- `a + 1` 跳过一个 `int`；`&a + 1` 跳过整个数组，`&a` 的类型为 `int (*)[5]`。
- `int* p[5]` 是“装了 5 个指针的数组”；`int (*p)[5]` 是“指向 5 个 int 所组成数组的指针”。
- `int a[2][5]` 转换后是 `int (*)[5]`，不是 `int**`。
- 函数形参 `void f(int a[5])` 实际调整为 `int*`，不会保留数组长度。

引用：[[1.C++基础/6. 指针/6.5 数组与指针的区别|数组与指针]]。

## 二、动态内存与资源释放

### 6. 栈、堆和指针变量是什么关系？

普通局部对象通常在栈上，退出作用域时自动销毁；动态对象通常在堆上，生命周期由所有者管理。全局变量和 `static` 变量具有静态存储期，不能归为普通栈对象。

`int* p = new int(10);` 中，局部指针 `p` 和动态创建的 `int` 是两个对象。`p` 离开作用域不会自动释放那个 `int`，必须 `delete` 或交给 RAII 所有者。

引用：[[1.C++基础/6. 指针/6.6 堆与栈的区别|堆与栈]]。

### 7. 如何动态分配、初始化和释放？

| 分配方式 | 初始化与失败行为 | 释放方式 |
|---|---|---|
| `new T(args...)` | 分配存储并初始化对象；通常的分配失败抛 `std::bad_alloc` | `delete p;` |
| `new T[n]{}` | 创建数组；空花括号使 int 元素初始化为 0 | `delete[] p;` |
| `std::malloc(n)` | 分配 n 字节，不调用构造函数；失败返回空指针 | `std::free(p);` |

`new int` 的值未初始化，`new int{}` 为 0，`new int(10)` 为 10。`new (std::nothrow)` 在分配失败时返回空指针，但对象构造函数仍可能抛异常。

`delete` 对类对象先析构，再释放存储；`operator new` 只负责分配存储，不等于整个 `new` 表达式，也不保证底层一定调用 `malloc`。三组分配/释放必须配对，混用是未定义行为；释放空指针安全，重复释放同一资源不安全。

引用：[[1.C++基础/6. 指针/6.2 动态内存分配与释放|动态分配与释放]]。

### 8. 内存泄漏、double free 怎么出现？RAII 怎么解决？

泄漏常见于丢失唯一地址、提前返回、异常跳过释放，或 `shared_ptr` 循环引用。重复释放常见于多个所有者分别释放同一资源，以及含拥有型裸指针的类发生浅拷贝。

浅拷贝只复制地址；深拷贝另分配资源并复制内容。按需求选择深拷贝、禁止复制，或明确共享所有权。

RAII 将释放责任交给对象：正常退出作用域、提前返回或异常栈展开时，由析构函数清理。优先用容器、`unique_ptr` 等表达所有权；借出的裸指针仍可能悬空。

引用：[[1.C++基础/6. 指针/6.3 动态内存分配的风险|泄漏与重复释放]]、[[1.C++基础/6. 指针/智能指针/删除器#1. 删除器、析构函数与 RAII|RAII]]。

## 三、智能指针

### 9. unique_ptr、shared_ptr、weak_ptr 的底层区别？

| 类型 | 所有权 | 常见实现 |
|---|---|---|
| `unique_ptr<T, D>` | 独占，可移动、不可复制 | 资源指针 + 删除器，无引用计数控制块 |
| `shared_ptr<T>` | 共享，拷贝增加强引用 | 保存对象指针和控制块指针 |
| `weak_ptr<T>` | 观察，不延长对象生命周期 | 关联同一个控制块，不增加强引用 |

控制块通常包含强计数、弱计数、资源清理信息，以及按需保存的删除器、分配器。强弱计数都在控制块里，不是每个 `weak_ptr` 自带一份计数。

强计数归零时执行资源释放；随后没有弱引用需要它时，控制块才释放。实现中的弱计数可能包含隐含引用，不能直接认定它等于 `weak_ptr` 对象个数。

引用：[[1.C++基础/6. 指针/智能指针/共享智能指针#2. 内部结构与控制块（Control Block）|shared_ptr 控制块]]、[[1.C++基础/6. 指针/智能指针/弱引用智能指针#2. 内部模型：强计数、弱计数与控制块生命周期|强弱计数与生命周期]]。

### 10. unique_ptr 怎么创建和转移？

以下片段需要 `<memory>`、`<utility>`：

```cpp
auto p = std::make_unique<int>(10);        // C++14 起，常用方式
std::unique_ptr<int> q(new int(20));       // 直接接管新对象
auto arr = std::make_unique<int[]>(5);     // 数组，析构时 delete[]
auto next = std::move(p);                 // 转移所有权，p 变空
```

返回局部 `unique_ptr` 时通常直接 `return p;`，可进行返回值优化或隐式移动，不必写 `return std::move(p);`。`unique_ptr` 可移动构造成 `shared_ptr`，不能直接反向转换。

默认/空删除器下，`unique_ptr` 通常与一个裸指针一样大；有状态删除器可能增大体积，具体大小不是标准保证。

引用：[[1.C++基础/6. 指针/智能指针/独享智能指针|unique_ptr]]、[[1.C++基础/6. 指针/智能指针/智能指针总结与练习题#4. 面试重点：返回局部 unique_ptr 要不要 std::move？|返回值与移动]]。

### 11. get、release、reset 有什么区别？

- `get()`：借出裸指针，所有权不变；不能手动删除，也不要用它创建另一个独立所有者。
- `unique_ptr::release()`：返回裸指针并把自己置空，**不释放资源**；接收方承担后续释放责任。`shared_ptr` 没有这个接口。
- `unique_ptr::reset()`：释放当前资源并置空；`reset(new_p)` 再接管新资源。
- `shared_ptr::reset()`：放弃当前这一份所有权，只有最后一个强所有者离开时才执行释放。

不要写 `p.reset(p.get())`；它可能让智能指针继续保存已经释放的地址。

引用：[[1.C++基础/6. 指针/智能指针/独享智能指针#5. 核心接口与所有权语义辨析|unique_ptr 接口]]、[[1.C++基础/6. 指针/智能指针/共享智能指针#7. 核心操作接口与状态查询|shared_ptr 接口]]。

### 12. make_shared 和 shared_ptr(new T) 有什么区别？

`std::make_shared<T>(args...)` 通常把对象与控制块放在一次分配的存储中；`std::shared_ptr<T>(new T(...))` 通常分别分配对象和控制块。这是常见实现方式，不能把分配次数写成所有情形下的硬性保证。

`make_shared` 没有接收自定义删除器的接口，需要时用 `shared_ptr<T>(raw, deleter)`。合并分配还有一个代价：强计数归零后对象已经析构，但只要弱引用仍保留控制块，整块存储就不能回收；对象内部另行申请的资源仍会随析构释放。

引用：[[1.C++基础/6. 指针/智能指针/共享智能指针#3. 对象创建：std::make_shared vs 裸 new 构造|两种创建方式]]；[标准草案：make_shared](https://eel.is/c++draft/util.smartptr.shared.create)。

### 13. shared_ptr 的线程安全到底保证什么？

- 不同 `shared_ptr` 实例共享同一控制块时，可以并发复制、销毁各自的实例，引用计数不会因此发生数据竞争。
- 同一个 `shared_ptr` 变量被并发访问，且存在赋值、`reset` 等写操作，需要同步；可加锁，或使用 C++20 的 `std::atomic<std::shared_ptr<T>>`。
- 被指向对象的数据不受自动保护；并发读写仍须按对象自身的规则加锁或使用原子操作。

`use_count() == 1` 不是并发环境下可以安全修改对象的依据。

引用：[[1.C++基础/6. 指针/智能指针/共享智能指针#6. 线程安全边界与多核性能损耗|线程安全边界]]；[标准草案：数据竞争规则](https://eel.is/c++draft/util.smartptr.shared.general)。

### 14. weak_ptr 怎么访问对象？为什么能解决循环引用？

用 `std::weak_ptr<T> w = shared;` 建立观察关系；不能直接 `*` 或 `->`，要先 `lock()`。成功时得到共享原控制块的 `shared_ptr`，使对象在持有期间存活；失败时返回空指针。检查存活与取得强引用作为一个原子操作完成。

常用形式是 `if (auto p = w.lock()) { /* 使用 p */ }`。单独检查 `expired()` 后，对象仍可能立即销毁，不能据此直接使用之前保存的裸指针。

若 A 和 B 用 `shared_ptr` 相互持有，外部指针消失后仍各有强引用，无法析构。将合适的一条非拥有关系改成 `weak_ptr`，不再增加强计数，就能打破这个环。

引用：[[1.C++基础/6. 指针/智能指针/弱引用智能指针|weak_ptr]]；[标准草案：lock 的原子语义](https://eel.is/c++draft/util.smartptr.weak.obs)。

### 15. 删除器是什么？怎么定义？有什么作用？

删除器是“收到资源指针后执行清理”的可调用对象，可以是函数、函数对象或 lambda。默认执行 `delete` / `delete[]`；自定义删除器可执行 `free`、`fclose`、归还对象池等匹配的清理动作，且不应向外抛异常。

```cpp
#include <cstdio>
#include <memory>

struct FileCloser {
    void operator()(std::FILE* f) const noexcept {
        if (f) std::fclose(f);
    }
};

// 放在函数内：作用域结束时自动关闭文件
std::unique_ptr<std::FILE, FileCloser> file(
    std::fopen("data.txt", "r"), FileCloser{});
```

`unique_ptr<T, D>` 的删除器类型 `D` 是智能指针类型的一部分；`shared_ptr<T>(raw, deleter)` 通常把删除器经类型擦除保存在控制块中，不改变 `shared_ptr<T>` 类型。`make_unique` 和 `make_shared` 都不能直接传入自定义删除器。

引用：[[1.C++基础/6. 指针/智能指针/删除器|删除器]]。

### 16. 成员函数返回 shared_ptr(this)，为什么会 double free？

假设对象已由一个 `shared_ptr` 管理，再执行 `std::shared_ptr<T>(this)` 会从裸地址建立第二个独立控制块。裸指针不携带原控制块信息，两个控制块各自计数、各自认为负责释放同一个对象，最终可能重复析构、double free 或无效释放，属于未定义行为。

`std::shared_ptr<T>(p.get())` 也是同类错误。要共享所有权，应复制已有 `shared_ptr`，或在对象内部使用 `shared_from_this()`。

引用：[[1.C++基础/6. 指针/智能指针/enable_shared_from_this#1. 核心问题：为什么严禁 shared_ptr(this)|双重控制块]]。

### 17. enable_shared_from_this 怎么解决？底层是什么？

公有、无歧义地继承 `std::enable_shared_from_this<T>`。基类内部维护一个弱引用，首个合适的 `shared_ptr` 接管对象时，把它绑定到已有的控制块。

`shared_from_this()` 从这个弱引用构造 `shared_ptr`，共享原控制块并增加强计数，不新建控制块。内部使用弱引用，避免对象自己强持有自己形成循环。

```cpp
#include <memory>

struct Node : std::enable_shared_from_this<Node> {
    std::shared_ptr<Node> self() {
        return shared_from_this();
    }
};

// 放在函数内
auto p = std::make_shared<Node>();
auto q = p->self();                       // 同一控制块，强计数为 2
```

`shared_from_this()` 失效时抛 `std::bad_weak_ptr`；`weak_from_this()`（C++17）只返回弱引用，之后 `lock()` 失败返回空指针。两种失败行为不同。

引用：[[1.C++基础/6. 指针/智能指针/enable_shared_from_this|enable_shared_from_this]]；[标准草案：内部弱引用与返回语义](https://eel.is/c++draft/util.smartptr.enab)、[失效时的异常](https://eel.is/c++draft/util.smartptr.shared.const)。


#### 什么情况下需要在成员函数里取得自身的 shared_ptr？

当其他地方需要在成员函数返回后继续使用当前对象，并承担保活责任时。例如注册异步网络请求的完成回调、投递线程池任务、注册定时器。普通同步成员访问通常直接使用 `this` 即可。

以网络请求为例：`start()` 发起请求后就返回，响应稍后才到达。若回调只捕获 `[this]`，外部所有者可能提前释放对象，回调再访问成员就会发生 use-after-free。

下面是接口示意：假设 `Session` 公有继承 `enable_shared_from_this<Session>`，已由 `shared_ptr` 管理，`async_request` 会保存回调。

```cpp
void Session::start() {
    auto self = shared_from_this();
    async_request([self](const Response& response) {
        self->on_response(response);
    });
}
```

`[self]` 按值捕获一份共享指针。即使外部指针已释放，回调持有期间对象仍然存活；操作完成或取消后，异步框架销毁回调及其副本，才释放这些强引用。只创建局部 `self` 而不捕获，或写成 `[&self]`，都不能保证后续回调的生命周期。

如果允许“对象已销毁就跳过处理”，则捕获 `weak_from_this()`，回调里先 `lock()`，成功才访问。若对象自己长期保存捕获 `self` 的回调，会形成“对象 → 回调 → 对象”的强引用环，需要改用弱引用或明确解除注册。保活也不等于成员数据线程安全。

引用：[[1.C++基础/6. 指针/智能指针/enable_shared_from_this#3. 异步网络工程中的生命周期接力|异步回调与生命周期]]。
### 18. 为什么构造、析构、普通栈对象中不能正常 shared_from_this？

| 场景 | 原因 |
|---|---|
| 构造函数内 | 对象还在构造，外部共享所有权尚未绑定内部弱引用 |
| 最后一个 shared_ptr 触发的析构函数内 | 强计数已经归零，无法再取得强引用来“复活”对象 |
| 普通栈对象，或仅裸 new、未被 shared_ptr 接管的对象 | 内部弱引用从未绑定有效控制块 |

这些情况下，C++17 的 `shared_from_this()` 会抛 `std::bad_weak_ptr`。根因是没有可取得的共享所有权，并不是函数检查了对象是否位于堆上。

需要依赖自身共享指针的初始化，放到 `make_shared` 完成之后再调用的 `init()` / `start()` 中。普通栈对象用引用或借用指针；不要用默认删除器的 `shared_ptr(&obj)` 包装栈对象。

引用：[[1.C++基础/6. 指针/智能指针/enable_shared_from_this#4. 典型陷阱与防御型设计|调用时机与陷阱]]；[标准草案：弱引用绑定](https://eel.is/c++draft/util.smartptr.shared.const#1)。

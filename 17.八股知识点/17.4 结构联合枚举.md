# 17.4 结构联合枚举

按 C++17 整理，C++20 特性单独标注。代码片段按题独立；涉及具体字节数时，要先确认平台的类型大小、对齐要求和编译选项。

## 一、结构体与内存布局

### 1. struct 和 class 有什么区别？结构体默认是公有的吗？

| 默认规则 | `struct` | `class` |
|---|---|---|
| 成员访问权限 | `public` | `private` |
| 继承权限 | `public` | `private` |

两者都能定义成员函数、构造和析构函数，也支持访问控制、继承、虚函数和模板。`struct` 中写了 `private:`，后续成员一样是私有的。

`struct` 常用来表达一组数据，但这个关键字不保证类型是聚合类型、标准布局类型或可平凡复制类型。

引用：[[1.C++基础/7. 结构体 & 联合体/7.1 结构体#结构体和类的区别|struct 与 class]]。

### 2. 结构体一定在栈上吗？访问和传参怎么写？

存储位置由对象的创建方式决定：局部非静态对象具有自动存储期，常见实现放在栈上；普通 `new` 创建的对象具有动态存储期；全局对象和普通 `static` 对象具有静态存储期。成员对象是外层对象的一部分。C++ 标准不要求所有自动对象都实际占用栈空间。

- 对象访问成员用 `obj.x`；指针访问用 `p->x`，等价于 `(*p).x`。
- `*p.x` 会解析成 `*(p.x)`，对普通结构体指针 `p` 来说不成立。
- 小对象或需要独立副本时可按值传递；只读大对象常用 `const T&`。
- 修改已有对象用 `T&`；允许“没有对象”时可用 `T*`，使用前检查是否为空。

引用：[[1.C++基础/7. 结构体 & 联合体/7.1 结构体#内存分配|存储位置]]、[[1.C++基础/7. 结构体 & 联合体/7.1 结构体#结构体作为函数参数和返回值|参数传递]]。

### 3. 结构体怎样初始化？C++20 指定初始化有什么限制？

```cpp
struct Point {
    int x;
    int y;
};

Point a{1, 2};  // 聚合初始化，按声明顺序
Point b{};      // 此例中 x、y 都是 0
Point c{1};     // 此例中 y 是 0
```

对这个没有成员默认值的简单类型，函数内的 `Point p;` 不会初始化两个 `int` 成员，不能直接读取它们。`Point p{};` 则会初始化成员；别把这个结论推广成“任意类用 `{}` 都会把整块内存清零”。

C++20 可写 `Point p{.x = 1, .y = 2};`。指定初始化器用于聚合类型，必须按成员声明顺序，不能写成 `{.y = 2, .x = 1}`；允许跳过成员。

引用：[[1.C++基础/7. 结构体 & 联合体/7.1 结构体#结构体初始化|初始化规则]]。

### 4. sizeof 为什么不等于成员大小之和？padding 怎么算？

对本节这种没有继承、虚函数、位域和特殊对齐设置的普通结构体，按以下方法计算：

1. 按成员声明顺序排列，每个成员开始的位置满足它的对齐要求；空隙是成员间 padding。
2. 整体对齐通常取成员中最严格的要求。`alignas` 等设置可能提高整体对齐。
3. 最后补齐到整体对齐的整数倍；尾部 padding 保证数组中下一个对象也能正确对齐。

```cpp
struct A {
    char c1;
    int i;
    char c2;
};

struct B {
    int i;
    char c1;
    char c2;
};
```

假设 `sizeof(int) = alignof(int) = 4`、`sizeof(char) = alignof(char) = 1`，采用常见自然布局：

| 类型 | 各成员偏移 | padding | `sizeof` |
|---|---|---|---|
| `A` | `c1: 0, i: 4, c2: 8` | 中间 3 字节，尾部 3 字节 | 12 |
| `B` | `i: 0, c1: 4, c2: 5` | 尾部 2 字节 | 8 |

`sizeof(T)` 是对象所占字节数；`alignof(T)` 是对齐要求。重排成员能减少填充，但会改变布局，已有二进制接口不能随意这样改。

普通成员函数代码、静态数据成员不计入每个对象的大小。空结构体的独立对象大小也不能是 0，常见 `sizeof(Empty) = 1`。

引用：[[1.C++基础/7. 结构体 & 联合体/7.1 结构体#内存对齐与 padding|对齐与 padding]]。

## 二、二进制读写、序列化与位域

### 5. 结构体能直接 fwrite、fread，或者通过 socket 收发吗？

可以在条件受控时按对象内存读写，但**处理对齐只是其中一个条件**。作为可移植的 C++ 字节复制依据，应先确认类型可平凡复制（trivially copyable）；作为文件或网络格式，还要保证布局、类型宽度、字节序、数据版本兼容，而且不能依赖另一个进程无法使用的指针或资源句柄。

下面演示同一兼容环境内的本地记录读写。`out`、`in` 必须是成功打开的二进制文件流，分别使用 `"wb"`、`"rb"`；读取数据应由兼容程序写出。

```cpp
#include <cstdio>
#include <cstdint>
#include <type_traits>

struct Record {
    std::uint32_t id;
    char name[12];
};

static_assert(std::is_trivially_copyable_v<Record>);

bool writeRecord(std::FILE* out, const Record& record) {
    return std::fwrite(&record, sizeof record, 1, out) == 1;
}

bool readRecord(std::FILE* in, Record& record) {
    Record temp{};
    if (std::fread(&temp, sizeof temp, 1, in) != 1) {
        return false;
    }
    record = temp;
    return true;
}
```

`fwrite/fread` 返回完整元素的个数，这里成功返回 `1`；写成 `fread(buf, 1, n, file)` 时才按字节数判断。读不足一条记录就不能使用该条记录；`readRecord` 先读临时对象，失败时保留调用方原值。调用方还要检查文件打开、写入后的刷新或关闭是否成功。

直接写对象会连 padding 一起写出，其字节内容未必稳定，可能带出无关数据。`Record{}` 也不能被当作任意类型、任意生命周期内 padding 始终为零的保证。比较两个结构体的逻辑值，应比较成员，不能普遍用 `memcmp` 代替。

跨平台文件和网络通信应定义独立字节格式，再序列化。TCP 的 `send/recv` 还可能只处理部分数据，必须累计发送、接收并处理错误，不能把一次调用当作完整的一条记录。

引用：[[1.C++基础/7. 结构体 & 联合体/7.1 结构体#网络协议传输中的风险|直接发送结构体的风险]]；[C++17 草案：可平凡复制对象的字节复制](https://timsong-cpp.github.io/cppwp/n4659/basic.types#2)、[Microsoft：fread 返回值与二进制模式](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/fread?view=msvc-170)。

### 6. 有非基本类型就必须序列化吗？为什么 string 和指针不能直接存？

“基本类型 / 非基本类型”不能直接作为判断标准。

| 成员情况 | 直接复制对象字节的含义 |
|---|---|
| `int`、`char`、定长整数 | 复制其表示；仍要考虑宽度、字节序和有效值 |
| `char name[12]` | 数组内容就在对象内，会一起复制；不保证存在字符串结束符 |
| 由简单成员组成的嵌套结构体 | 也可能可平凡复制；需要检查整个类型及布局 |
| `char*`、其他裸指针 | 只复制地址，不复制指向的数据；指针可平凡复制也不代表能跨进程使用 |
| `std::string`、`std::vector` | 内部表示包含资源管理状态，直接覆写对象字节不能正确重建内容 |

`serialize`（序列化）把逻辑字段编码成约定的字节；`deserialize`（反序列化）校验字节并重建对象。字符串可编码为“长度 + 指定编码的字符数据”，数组可编码为“元素个数 + 各元素内容”，指针关联可改存对象 ID。

即使全部成员都是整数，跨平台协议也通常要序列化。常见做法是使用 `std::uint16_t/std::uint32_t` 等固定宽度类型，再逐字段写入字节缓冲区，约定大小端、字段偏移、长度和版本。只替换字段类型，仍然没有消除结构体 padding。

### 7. trivially copyable 和 standard layout 是一回事吗？

- `std::is_trivially_copyable_v<T>`：判断类型是否具备标准保证的按字节复制能力。这里讨论完整对象及其有效表示，不意味着任意外部字节都能解释为合法对象。
- `std::is_standard_layout_v<T>`：判断类型是否满足一组布局限制，例如没有虚函数、非静态数据成员具有相同访问权限等；常用于 `offsetof` 和 C 接口布局设计。

两者关注的性质不同，不能互相替代，也都不保证跨平台序列化安全。POD 是较早的组合概念；面试时直接说明需要“字节复制能力”还是“布局限制”更准确。

引用：[[1.C++基础/7. 结构体 & 联合体/7.3 结构体与联合体题目汇总#七、概念辨析进阶|类型性质辨析]]；[C++17 草案：类型性质查询](https://timsong-cpp.github.io/cppwp/n4659/meta.unary.prop)。

### 8. 截图中的 :1、:4 是什么？位域能防止 padding 吗？

这是位域（bit-field），冒号后面指定字段的位宽：

```cpp
struct Header {
    unsigned int flag     : 1;  // 0～1
    unsigned int sig      : 1;  // 0～1
    unsigned int sn       : 4;  // 0～15
    unsigned int reserved : 2;  // 协议预留字段
    unsigned int crc      : 8;  // 0～255
};
```

字段位宽合计 `1 + 1 + 4 + 2 + 8 = 16` 位，**不能据此断定 `sizeof(Header) == 2`**。实现可能按较大的分配单元存放，并加入填充。

- 位域类型必须是整型或枚举类型；`char`、`bool` 也属于整型。不能用 `float`、`double`、`std::string` 定义位域。
- 位域可以压缩小范围数据，但位的分配方向、是否跨分配单元、对齐和 padding 由实现决定。
- `reserved : 2` 是人为声明的字段，与编译器自动插入的 padding 不同；发送时应按协议设置它。
- 不能对位域单独取地址，也不能对位域表达式使用 `sizeof` 或直接绑定非 `const` 引用。
- 匿名零宽位域，如 `unsigned int : 0;`，用于让后续位域从新的分配单元边界开始，可能增加填充。

差异来自编译器、ABI、目标架构及编译选项，不能只看是不是同一个操作系统。位域适合布局已核实的环境，跨平台传输应显式打包。

引用：[C++17 草案：位域类型、布局与访问限制](https://timsong-cpp.github.io/cppwp/n4659/class.bit)。

### 9. 怎样用移位和掩码得到固定的二进制格式？

可以直接定义“发送的每一位”，不让结构体内存布局决定协议。把上题规定为两个 8 位字节：

| 位置 | 协议含义 |
|---|---|
| 第 0 字节 bit 0 | `flag` |
| 第 0 字节 bit 1 | `sig` |
| 第 0 字节 bit 2～5 | `sn` |
| 第 0 字节 bit 6～7 | 保留位，写 0 |
| 第 1 字节 | `crc` |

以下约定 bit 0 是一个字节的最低有效位；输入已确认 `flag/sig ≤ 1`、`sn ≤ 15`。

```cpp
#include <array>
#include <cstdint>

std::array<std::uint8_t, 2> encodeHeader(
    unsigned flag, unsigned sig, unsigned sn, std::uint8_t crc) {
    return {
        static_cast<std::uint8_t>(
            (flag & 1u) | ((sig & 1u) << 1) | ((sn & 0x0Fu) << 2)),
        crc
    };
}
```

`encodeHeader(1, 0, 9, 0xA5)` 得到两个字节 `25 A5`（十六进制）。接收端用 `buf[0] & 1u` 取 flag，`(buf[0] >> 1) & 1u` 取 sig，`(buf[0] >> 2) & 0x0Fu` 取 sn，`buf[1]` 取 crc；还应检查保留位和校验值。此例只打包已有 crc，不计算校验码。

这里掩码截取低位，不能代替输入范围校验。这两个字段字节分别构造，不依赖主机多字节整数的内存字节序。以后增加 16 位、32 位字段时，还要明确高低字节的输出顺序。

引用：[[1.C++基础/7. 结构体 & 联合体/7.3 结构体与联合体题目汇总#六、综合设计与手写代码|跨平台包头设计]]。

### 10. #pragma pack(1) 和 alignas 能解决什么？

`#pragma pack(push, 1)` 与 `#pragma pack(pop)` 是常见编译器扩展，用于在限定范围内改变成员对齐。它可能减少普通字段之间的 padding，但不能统一字节序、指针含义、位域排列或协议版本；未对齐访问还可能变慢，某些硬件上甚至触发异常。

`alignas` 是标准 C++ 的对齐说明，不能降低类型原本必需的对齐要求，所以不能用 `alignas(1)` 把含自然 4 字节对齐成员的结构体强行压紧。

处理可移植协议时，通常把字段编码到字节数组更直接。接收缓冲区也不能仅靠 `reinterpret_cast<Header*>` 就变成合法 Header 对象，还涉及对齐、对象生命周期和类型访问规则。

引用：[Microsoft：pack 的作用与限制](https://learn.microsoft.com/en-us/cpp/preprocessor/pack?view=msvc-170)。

## 三、联合体

### 11. union 的大小由最大的成员决定吗？

所有非静态数据成员共享同一块存储，起始地址相同。大小至少能容纳最大的成员，还要满足整体对齐；通常按成员中最严格的对齐要求向上补齐。

```cpp
union U {
    int i;
    char buf[5];
};
```

在 `sizeof(int) = alignof(int) = 4`、`char` 对齐为 1 的常见自然布局下：

- 最大成员是 `buf[5]`，占 5 字节。
- `alignof(U)` 通常为 4，`sizeof(U)` 通常为 8。
- 末尾 3 字节 padding 让 `U array[2]` 的第二个元素也满足对齐。

因此不能只背“union 大小等于最大成员大小”。`struct` 可同时保存各成员的值，`union` 同一时刻至多有一个活动成员，节省的是互斥使用的数据所需的存储。

引用：[[1.C++基础/7. 结构体 & 联合体/7.2 联合体#union 大小与对齐|联合体大小与对齐]]；[C++17 草案：联合体存储](https://timsong-cpp.github.io/cppwp/n4659/class.union#2)。

### 12. 活动成员是什么意思？能用 union 做类型转换吗？

活动成员是生命周期已经开始且尚未结束的成员。简单标量成员的常见操作如下：

```cpp
union Value {
    int i;
    float f;
};

Value value{42};  // 初始化第一个成员 i
value.f = 3.5f;    // 开始 f 的生命周期，结束 i 的生命周期
// 此后读取 value.i：标准 C++ 中是未定义行为
```

活动成员不一定存在，不能无条件说“始终有一个”。普通聚合初始化如 `Value{42}` 初始化首成员；C++20 可用 `Value{.f = 3.5f}` 指定另一个成员。

写 `f` 再读 `i` 不等于数值转换，也不是标准 C++ 对类型双关的通用许可。需要数值转换用 `static_cast`；要查看表示字节可用 `std::memcpy`，C++20 还有 `std::bit_cast`（要求源、目标同大小且可平凡复制，目标表示也必须合法）。判断大小端可用 C++20 的 `std::endian`。

标准有有限例外，例如满足条件的标准布局 union 中，可以读取不同标准布局结构体成员的共同初始序列。这个例外不能用于任意 `int/float` 重解释。

> [!note] 区分字节观察与非活动成员读取
> [[1.C++基础/7. 结构体 & 联合体/7.2 联合体#内存访问注意事项|复制表示字节]]可用于观察字节序；[[1.C++基础/7. 结构体 & 联合体/7.3 结构体与联合体题目汇总|题目汇总]]第 8 题的 union 读取则是未定义行为。编译器扩展下出现确定结果，不等于标准 C++ 保证该结果。

### 13. union 可以放 string 吗？为什么常用 enum 标签或 variant？

C++11 起可以在 union 中声明 `std::string` 等非平凡类型，但要正确管理活动成员的构造、析构和切换。相关默认特殊成员函数可能被删除；不能把尚未构造的 string 当普通对象直接赋值。

手写带标签联合时，用 `enum` 记录当前存储的种类，再按标签读取对应成员。匿名 union 的成员名可直接从外层访问，但标签不会自动随写入更新；匿名 union 也不能声明成员函数或私有、受保护成员。

C++17 的 `std::variant<int, std::string>` 会管理当前类型及生命周期：

- `std::holds_alternative<T>(v)` 检查当前类型。
- `std::get<T>(v)` 取值，类型不符时抛 `std::bad_variant_access`。
- `std::get_if<T>(&v)` 取指针，类型不符时返回 `nullptr`。
- `std::visit` 按当前类型调用访问器。

variant 的候选值存放在对象内部，string 自己仍可能申请堆内存。它有类型索引和对齐开销，不能假设大小等于最大候选类型；某些抛异常的切换还可能产生 `valueless_by_exception` 状态。

引用：[[1.C++基础/7. 结构体 & 联合体/7.2 联合体#std::variant（C++17 推荐）|variant 用法]]；[C++17 草案：union 的非平凡成员](https://timsong-cpp.github.io/cppwp/n4659/class.union#3)、[variant 访问规则](https://timsong-cpp.github.io/cppwp/n4659/variant.get)。

## 四、枚举

### 14. enum 的值怎样确定？大小一定是 int 吗？

枚举是独立类型，用一组名字表示整数常量。第一个未显式赋值的枚举器为 0，后续未赋值项等于前一项加 1；不同枚举器可以具有相同数值。

```cpp
enum Code {
    Ok,          // 0
    Busy = 4,    // 4
    Retry,       // 5
    Again = 5    // 允许与 Retry 同值
};
```

普通 `enum` 未指定底层类型时，由实现选择能容纳其枚举值的整型，不能假定总是 `int`。`enum class` 未指定底层类型时默认为 `int`。两者都能显式指定，例如 `enum class Status : unsigned char { Ok, Error };`。

底层类型必须是整型：`char/short/int/long` 等可以，`float/double` 不可以。枚举大小与底层类型一致；用于协议时应约定固定宽度并按数值编码。

引用：[[1.C++基础/2. 基本数据类型/2.4 枚举与结构体#枚举类型（enum）|枚举基础]]；[C++17 草案：枚举值与底层类型](https://timsong-cpp.github.io/cppwp/n4659/dcl.enum)。

### 15. 两个枚举怎样避免名称冲突？enum class 有什么优势？

要避免的是**同一作用域中普通 enum 的枚举器同名**。普通枚举的类型名不同，仍可能冲突：

```cpp
enum Color { Red, Green };
// enum Signal { Red, Yellow };  // 错误：Red 在同一作用域重复声明

enum class Paint { Red, Green };
enum class Signal { Red, Yellow };

Paint paint = Paint::Red;
Signal signal = Signal::Red;    // 合法：各自具有作用域
```

普通 enum 可以用前缀或不同命名空间避免冲突；新代码常用 `enum class`。`Paint::Red` 与 `Signal::Red` 类型不同，不能直接互相赋值；它们也不隐式转换为整数。`enum struct` 与 `enum class` 含义相同。

引用：[[1.C++基础/2. 基本数据类型/2.4 枚举与结构体#普通枚举 vs 枚举类（enum class）|普通枚举与枚举类]]；《Effective Modern C++》条款 10：优先考虑限定作用域的枚举。

### 16. 枚举和数值能互相转换吗？强转会校验枚举值吗？

| 转换方向 | 规则 |
|---|---|
| 普通 `enum` → 整数 | 可以隐式转换，仍需留意目标整数的范围 |
| `enum class` → 整数 | 使用 `static_cast` 等显式转换 |
| 整数 → 任一种枚举 | 不能直接隐式赋值，通常用 `static_cast` |
| 一种枚举 → 另一种枚举 | 不能直接隐式赋值；数值相同也不会成为同一类型 |

```cpp
#include <cstdint>

enum class State : std::uint8_t {
    Idle = 0,
    Running = 1
};

int code = static_cast<int>(State::Running);  // 1
State state = static_cast<State>(1);         // Running
State unknown = static_cast<State>(2);       // 转换合法，但没有对应命名枚举器
```

`static_cast` 不检查这个数是否对应某个已声明的枚举器。固定底层类型的枚举可表示底层类型的值，`2` 落在 `uint8_t` 范围内，但业务可能不接受它。读取文件、网络数据时，应先检查整数范围和允许的编码，再转换。

未固定底层类型的枚举还有自己的可表示值范围，越界转换可能是未定义行为；这个范围也不等于“写在声明中的那几个值”。不要把强转当输入验证。

引用：[C++17 草案：显式枚举转换](https://timsong-cpp.github.io/cppwp/n4659/expr.static.cast#10)、[枚举可表示值范围](https://timsong-cpp.github.io/cppwp/n4659/dcl.enum#8)。

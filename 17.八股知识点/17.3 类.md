# 17.3 类

## 一、类的定义与封装

### 1. 类的声明、定义和成员函数实现放在哪里？

- `class Point;` 是前向声明：类型还不完整，可以声明指针、引用，不能据此创建对象、访问成员或计算 `sizeof(Point)`。
- `class Point { ... };` 是**类的定义**，通常放头文件，里面可以同时有成员函数的声明和定义。
- 较长的成员函数在 `.cpp` 中定义，加 `Point::`；调用方包含头文件，编译链接时还要加入对应 `.cpp` 或库。

`Point.h`：

```cpp
#ifndef CPP_NOTES_POINT_H
#define CPP_NOTES_POINT_H

class Point {
    int x_;                       // class 默认 private
public:
    explicit Point(int x);
    int getX() const { return x_; } // 类内定义，C++17 中隐式 inline
    void setX(int x);
};

#endif
```

`Point.cpp`：

```cpp
#include "Point.h"

Point::Point(int x) : x_(x) {}
void Point::setX(int x) { x_ = x; }
```

类内定义的成员函数可以使用类中稍后声明的成员。`inline` 不保证机器码展开，主要允许满足 ODR 条件的定义出现在多个翻译单元中。类外定义不会仅因为是成员函数就自动 `inline`。

头文件保护防止**同一翻译单元**内重复包含；不能解决普通函数定义放头文件后，被多个 `.cpp` 包含造成的重复定义。`#pragma once` 是常见替代写法。

### 2. 默认权限是什么？如何访问私有成员？

`class` 的默认成员权限、默认继承方式都是 `private`；`struct` 都是 `public`。两者都可以有构造函数、继承和虚函数。

| 访问位置 | public | protected | private |
|---|---|---|---|
| 本类成员、获授权的友元 | 可以 | 可以 | 可以 |
| 派生类成员 | 按继承路径可访问 | 按继承路径可访问 | 不能直接访问 |
| 普通类外代码 | 可访问的 public 接口 | 不可以 | 不可以 |

`protected` 还有对象限制：派生类成员不能拿任意 `Base&` 去访问其受保护成员，通常要通过当前派生类型的对象访问。

访问私有数据优先提供 `public` 接口，例如 `int getX() const`；返回字符串可写 `const std::string& getName() const`，引用的有效期受原对象约束。也可以授权友元。

`private` 是编译期访问控制，不是内存加密。通过指针猜偏移、强转类型读取私有字段，依赖布局、对齐和别名规则，可能产生未定义行为，不能当作通用访问方式。

引用：[[1.C++基础/12. OOP/12.1 封装/12.1.2 类#类的访问控制|访问控制]]、[[1.C++基础/12. OOP/12.1 封装/12.1.11 友元|友元]]。

### 3. const 成员函数限制什么？和 public/private 有关系吗？

`int getX() const` 最后的 `const` 约束当前对象，与访问权限无关：私有的 `const` 函数仍然不能随便在类外调用。

- 不能通过 `this` 修改普通非静态成员，也不能通过它调用非 `const` 成员函数。
- 可以修改 `mutable` 成员、可修改的静态成员；指针成员指向的对象不自动变成 `const`。
- `const` 对象只能调用 `const` 非静态成员函数；普通对象两种都能调用。
- `get()` 和 `get() const` 可以重载。前面的 `const` 返回类型，与末尾的 `const` 是两件事。

引用：[[1.C++基础/12. OOP/12.1 封装/12.1.5 const成员函数#const 成员函数规则总结|const 成员函数规则]]。

### 4. this 是什么？它占对象空间吗？

`this` 是非静态成员函数中指向当前调用对象的指针表达式。普通成员函数中类型是 `T*`，`const` 成员函数中是 `const T*`。

它不是对象中额外保存的一份数据成员；实现上通常作为隐式参数传入。不能给 `this` 赋值，但其类型**不是 `T* const`**。静态成员函数没有 `this`。

常见用途：`this->x = x` 区分同名参数、`this == &other` 检查自赋值、`return *this;` 返回当前对象引用以支持链式调用。

引用：[[1.C++基础/12. OOP/12.1 封装/12.1.4 类的成员函数#this 指针|this 指针]]；[C++17 草案：this 的类型](https://timsong-cpp.github.io/cppwp/n4659/class.this)。

### 5. 友元函数、友元类有什么特点？

在 `A` 内写 `friend class B;`，表示 **A 授权 B** 的成员访问 A 的私有、受保护成员；也能只授权一个函数或某个类的成员函数。

友元不自动成为本类成员。友元关系**单向、不传递、不继承**：A 的友元不自动获得 A 的派生类新增私有成员的访问权；B 的派生类也不自动成为 A 的友元。声明放在 `public/private/protected` 区域都不改变授权。

引用：[[1.C++基础/12. OOP/12.1 封装/12.1.11 友元#友元关系的特点|友元关系]]。

## 二、对象创建、构造析构与拷贝

### 6. 创建、拷贝、赋值和移动对象怎么区分？

以下假设对应构造、赋值操作可用，`a` 已存在；智能指针需 `<memory>`，`std::move` 需 `<utility>`。

| 写法 | 含义 |
|---|---|
| `T obj{};` | 创建局部自动对象，通常所说的“栈上对象”，离开作用域自动析构 |
| `T b = a;` / `T b(a);` | 用已有对象创建新对象：拷贝构造 |
| `b = a;` | 两个对象都已存在：拷贝赋值 |
| `T b(std::move(a));` | 用右值初始化新对象，优先匹配可用的移动构造 |
| `b = std::move(a);` | 给已有对象赋值，优先匹配可用的移动赋值 |
| `T* p = new T{};` | 动态创建对象，返回指针；用 `delete p;` 析构并释放 |
| `auto p = std::make_unique<T>();` | 动态创建对象，由独占智能指针管理 |
| `auto p = std::make_shared<T>();` | 动态创建对象，由共享智能指针管理 |

`T obj();` 是函数声明，别当成创建对象。`T* q = p;` 只复制指针，不拷贝所指对象。

`std::unique_ptr<T> p(new T{});` 也能接管资源，通常优先 `make_unique`。裸指针变量离开作用域不会自动 `delete`；智能指针的 RAII 才负责释放资源。

引用：[[1.C++基础/12. OOP/12.1 封装/12.1.2 类#类的使用|创建对象]]、[[17.八股知识点/17.1 指针|动态内存与智能指针速记]]、[[2.C++高级/15. C++11/15.8 移动语义与右值引用&&#std::move|std::move]]。

### 7. 构造函数、默认构造与初始化列表怎么记？

- 构造函数与类同名，没有返回类型，不能是 `virtual` 或 `static`；可以重载。
- 默认构造函数是**可以不传实参调用**的构造函数，不一定没有形参，例如 `T(int x = 0)`。
- 没有用户声明的构造函数时，编译器才隐式声明默认构造；也可以写 `T() = default;` 请求生成，但成员或基类无法默认构造时，它仍可能被删除。
- 初始化列表真正初始化基类和成员；进入函数体时，它们的初始化阶段已经结束，`x_ = x;` 是赋值。
- 引用、`const int` 等成员必须在构造阶段初始化，可用初始化列表或合适的类内初始值；没有默认构造的基类、成员对象也要提供构造实参。
- `explicit` 常用于单参数构造，阻止意外隐式转换；普通整数成员不会因为属于类就自动初始化为 0。

引用：[[1.C++基础/12. OOP/12.1 封装/12.1.6 构造函数#成员列表构造函数|初始化列表]]、[[1.C++基础/12. OOP/12.1 封装/12.1.6 构造函数#explicit 关键字|explicit]]。

### 8. 构造和析构顺序是什么？

构造顺序：**虚基类 → 直接非虚基类 → 非静态成员 → 当前类构造函数体**。

- 虚基类由最派生类初始化；多个虚基类按继承图“深度优先、从左到右”的顺序处理。
- 直接非虚基类按继承列表的书写顺序；成员按类内声明顺序。
- 初始化列表写成什么顺序，不会改变实际构造顺序。

析构顺序相反：**当前类析构函数体 → 成员逆序 → 直接非虚基类逆序 → 虚基类逆序**。因此析构函数体执行时，成员和基类通常还在。

同一作用域内的局部对象按构造完成的逆序析构；数组按下标从小到大构造、从大到小析构。

引用：[[1.C++基础/12. OOP/12.2 继承/12.2.2 继承构造函数#构造函数的调用顺序|继承构造顺序]]、[[1.C++基础/12. OOP/12.1 封装/12.1.7 析构函数#析构顺序|析构顺序]]；[C++17 草案：基类和成员初始化顺序](https://timsong-cpp.github.io/cppwp/n4659/class.base.init#13)。

### 9. 析构函数和 RAII 负责什么？构造失败怎么办？

析构函数写成 `~T()`，无返回类型、无参数，不能重载。析构函数体执行完后，成员对象和基类会自动析构；**裸指针成员指向的资源不会自动释放**。

RAII 把资源交给对象管理：构造时取得资源，析构时释放，正常离开作用域或异常展开时都能清理。优先用 `std::string`、容器、智能指针等成员管理资源。

非委托构造过程中抛出异常，尚未构造完成的对象不会调用自己的析构函数；已构造完成的基类、成员会逆序析构。普通 `new T` 中 T 的构造失败，对应对象内存也会被回收。

引用：[[1.C++基础/12. OOP/12.1 封装/12.1.7 析构函数#RAII 模式|RAII]]、[[1.C++基础/12. OOP/12.1 封装/12.1.13 malloc与new|new 与对象生命周期]]。

### 10. 拷贝构造和“赋值构造”有什么区别？怎么写？

“赋值构造”应称为**拷贝赋值运算符**。拷贝构造初始化新对象；拷贝赋值更新已有对象，还要处理其原有资源。

下面用一个独占 `int` 的小类展示深拷贝；实际只存整数时直接用 `int` 成员即可。

```cpp
class Box {
    int* data_;
public:
    explicit Box(int value) : data_(new int(value)) {}
    Box(const Box& other) : data_(new int(*other.data_)) {}

    Box& operator=(const Box& other) {
        if (this == &other) return *this;
        *data_ = *other.data_;     // 复用已有空间，复制内容
        return *this;
    }

    ~Box() { delete data_; }
    int get() const { return *data_; }
};
```

`Box a(1); Box b = a;` 调用拷贝构造；之后 `b = a;` 才是拷贝赋值。参数通常用 `const T&`，避免传值拷贝并兼容 const 对象；赋值返回 `T&` 以支持链式赋值。

上例始终拥有一个有效 `int`，没有定义移动操作。复制可变长资源时，要处理自赋值、旧资源和异常安全；可以先分配新资源再替换旧资源，或使用 copy-and-swap。

引用：[[1.C++基础/12. OOP/12.1 封装/12.1.6 构造函数#副本构造函数|拷贝构造]]、[[1.C++基础/9. 函数/9.3 运算符重载/9.3.2 重载赋值运算符#6. 赋值运算符 vs 拷贝构造函数|拷贝与赋值的区别]]。

### 11. 默认拷贝、浅拷贝和深拷贝是什么？

编译器生成的拷贝是**逐基类、逐成员拷贝**，不等于“所有成员都按字节复制”。

- 原始指针成员通常只复制地址：若两个对象都把该内存当作独占资源，可能互相影响、悬空或重复释放。这是典型浅拷贝问题。
- 深拷贝为目标对象建立独立资源并复制内容，两个对象各自管理资源。
- `std::string`、`std::vector` 成员按自身的值语义复制；`shared_ptr` 复制后共享所有权，`unique_ptr` 不可复制。
- 非拥有型指针只引用外部对象时，复制地址可以是合理设计；不是所有浅拷贝都有错。

引用：[[2.C++高级/8. 浅拷贝与深拷贝/8. 浅拷贝与深拷贝#浅拷贝|浅拷贝]]、[[2.C++高级/8. 浅拷贝与深拷贝/8. 浅拷贝与深拷贝#深拷贝|深拷贝]]。

### 12. 如何禁止拷贝？移动和三／五／零法则怎么记？

```cpp
class NonCopyable {
public:
    NonCopyable() = default;
    NonCopyable(const NonCopyable&) = delete;
    NonCopyable& operator=(const NonCopyable&) = delete;
};
```

`= delete` 明确禁止调用，连本类成员、友元也不能调用；比旧式“放 private 且不定义”更直接。

- 三法则：手动管理资源时，析构、拷贝构造、拷贝赋值通常要一起考虑。
- 五法则：再考虑移动构造 `T(T&&)`、移动赋值 `T& operator=(T&&)`；转移资源后，源对象仍应能安全析构。
- 零法则：把资源交给标准库成员管理，让编译器生成合适的特殊成员函数。
- 用户声明拷贝操作或析构函数会抑制隐式移动；上面的类没有自动生成移动操作。若要“不可拷贝但可移动”，在成员支持时显式提供或 `= default` 移动操作。

`std::move` 只做类型转换，不保证真的移动；没有可用移动时可能转而拷贝，也可能编译失败。只在移动操作确实不抛异常时标 `noexcept`，这也有利于容器扩容时选用移动。

引用：[[2.C++高级/8. 浅拷贝与深拷贝/8. 浅拷贝与深拷贝#关键要点|三法则]]、[[2.C++高级/15. C++11/15.8 移动语义与右值引用&&|移动语义]]；[C++17 草案：隐式移动构造的条件](https://timsong-cpp.github.io/cppwp/n4659/class.copy.ctor#8)。

## 三、继承与虚基类

### 13. public、protected、private 继承分别改变什么？

`class Derived : public Base {};` 中 Base 是基类，Derived 是派生类。关键字是 `protected`，不是 `protect`。

| 基类成员 | public 继承后 | protected 继承后 | private 继承后 |
|---|---|---|---|
| public | public | protected | private |
| protected | protected | protected | private |
| private | 派生类不能直接访问 | 派生类不能直接访问 | 派生类不能直接访问 |

基类的私有成员仍属于基类子对象，没有消失，可以通过基类允许的接口间接使用。

公有继承表达“派生类是一种基类”；在基类无二义性时，普通外部代码可以把 `Derived*`／`Derived&` 隐式转换为 `Base*`／`Base&`。保护、私有继承限制这种外部转换。

引用：[[1.C++基础/12. OOP/12.2 继承/12.2.1 类的继承#三种继承方式|三种继承]]。

### 14. 哪些东西不能简单地说“继承下来了”？

| 项目 | 准确说法 |
|---|---|
| 构造函数 | 不会自动作为派生类构造函数使用；C++11 可用 `using Base::Base;` 继承构造 |
| 析构函数 | 不作为普通成员继承；派生类有自己的析构函数，随后自动析构基类 |
| 拷贝／移动特殊成员 | 派生类有自身的生成规则，不能拿基类操作代替整个派生对象的操作 |
| `operator=` | 基类版本会被派生类自身的赋值运算符隐藏；可用 `using Base::operator=;` 引入需要的基类重载 |
| `operator()` | 可以继承，遵守普通成员函数的访问、隐藏和重载规则 |
| 友元关系 | 不继承 |

继承构造函数时，基类按选中的构造函数初始化，派生类新增成员仍依赖类内初始值或默认初始化；并不自动获得正确的成员初值。

引用：[[1.C++基础/12. OOP/12.2 继承/12.2.2 继承构造函数#构造函数的继承（using 声明）|继承构造函数]]；[C++17 草案：继承构造的初始化](https://timsong-cpp.github.io/cppwp/n4659/class.inhctor.init)、[赋值运算符的隐藏](https://timsong-cpp.github.io/cppwp/n4659/class.copy.assign#8)。

### 15. 基类没有默认构造，派生类怎么办？拷贝时呢？

在派生类构造函数的初始化列表中，明确调用可访问的基类构造函数。不能在函数体里写 `Base(x);` 来补做基类初始化，那只是创建临时对象。

```cpp
class Base {
    int id_;
public:
    explicit Base(int id) : id_(id) {}
    int id() const { return id_; }
};

class Derived : public Base {
    int value_;
public:
    Derived(int id, int value) : Base(id), value_(value) {}
    Derived(const Derived& other)
        : Base(other), value_(other.value_) {}
};
```

编译器生成的派生类拷贝构造会复制基类部分；**手写拷贝构造却省略 `Base(other)`，基类才会尝试默认初始化**，可能报错或丢失应复制的状态。手写派生类赋值时，也要记得处理基类部分，例如 `Base::operator=(other);`。

引用：[[1.C++基础/12. OOP/12.2 继承/12.2.2 继承构造函数#自定义选择基类构造函数|选择基类构造函数]]；[C++17 草案：默认拷贝逐基类、逐成员进行](https://timsong-cpp.github.io/cppwp/n4659/class.copy.ctor#14)。

### 16. 虚继承、虚基类解决什么问题？

菱形继承 `A → B/C → D` 中，如果 B、C 都普通继承 A，D 内有两份 A 子对象，可能造成重复数据和访问二义性。

```cpp
struct A { explicit A(int) {} };
struct B : virtual public A { B() : A(1) {} };
struct C : virtual public A { C() : A(2) {} };
struct D : public B, public C { D() : A(3), B(), C() {} };
```

创建 D 时，共享的一份虚基类 A 由 D 初始化，使用 `A(3)`；B、C 中对 A 的初始化此时不执行。单独创建 B 时才使用 `A(1)`。

虚继承解决的是**基类子对象共享**；虚函数解决的是**动态分派**。虚基类不等于抽象类，也不要求自身含虚函数。如果混用虚继承和普通继承，仍可能另外存在非虚的 A 子对象。

引用：[[1.C++基础/12. OOP/12.2 继承/12.2.4 多重继承#菱形继承问题（二义性）|菱形继承]]、[[1.C++基础/12. OOP/12.2 继承/12.2.5 虚基类#构造函数的特殊规则|虚基类初始化]]。

## 四、多态、虚函数与对象模型

### 17. 静态多态、动态多态有什么区别？动态多态有哪些条件？

静态多态通常指重载、模板等编译期选择；动态多态通过虚函数，根据对象的动态类型选择最终重写版本。

常见写法：**公有继承 + 基类虚函数 + 派生类重写 + 基类指针／引用指向派生对象**。

这是一组常用场景，不是每项都绝对必需：虚分派不要求必须公有继承，公有继承主要保证外部向上转换可访问；派生类不重写时会沿用继承来的实现。直接通过对象调用虚函数也是合法的。

`Base b = derived;` 会发生对象切片，新对象只有 Base 部分；用基类指针、引用可以保留原派生对象。

引用：[[1.C++基础/12. OOP/12.3 多态/12.3.1 静态多态与动态多态|静态与动态多态]]、[[1.C++基础/12. OOP/12.3 多态/12.3.3 对象多态#对象切片问题（Object Slicing）|对象切片]]。

### 18. 派生对象、基类指针和基类引用，分别调用谁？

```cpp
struct Base {
    const char* normal() const { return "Base"; }
    virtual const char* greet() const { return "Base"; }
    virtual ~Base() = default;
};

struct Derived : Base {
    const char* normal() const { return "Derived"; }
    const char* greet() const override { return "Derived"; }
};

Derived obj;
Base* p = &obj;
Base& r = obj;
```

| 调用 | 非虚函数 `normal()` | 虚函数 `greet()` |
|---|---|---|
| `obj.函数()` | Derived | Derived |
| `p->函数()` | Base | Derived |
| `r.函数()` | Base | Derived |

非虚调用按静态类型选择；虚调用按动态类型的最终重写版本选择。`p->Base::greet()` 显式限定基类，会抑制虚分派并调用 Base 版本。

引用：[[1.C++基础/12. OOP/12.3 多态/12.3.2 虚函数#虚函数的概念|虚函数调用]]、[[1.C++基础/12. OOP/12.3 多态/12.3.3 对象多态#通过指针实现多态|指针与多态]]。

### 19. 重载、隐藏、重写有什么区别？构造函数能重写吗？

- 重载：同一重载集合中，依据不同参数列表等区分函数。
- 隐藏：派生类声明同名函数后，基类同名重载可能都被遮住，即使参数不同；可用 `using Base::f;` 引回基类重载。
- 重写：派生类提供匹配基类**虚函数**的版本；名字、参数类型、成员函数的 cv/ref 限定等要匹配。
- 返回类型通常相同，也允许符合规则的协变类指针／引用；不包括 `unique_ptr<Derived>` 与 `unique_ptr<Base>`。异常规格不能比基类更宽松。

构造函数不能是虚函数，因此不能 `override`。继承构造、调用基类构造，都不是重写构造函数。基类私有虚函数也可以被重写；访问控制与是否构成重写是两件事。

引用：[[1.C++基础/12. OOP/12.2 继承/12.2.3 继承析构函数#名称隐藏规则|名称隐藏]]、[[1.C++基础/12. OOP/12.3 多态/12.3.2 虚函数#1. 重写条件|重写条件]]；[C++17 草案：虚函数重写](https://timsong-cpp.github.io/cppwp/n4659/class.virtual)。

### 20. override 和 final 怎么用？

- `void f() const override;`：让编译器检查“确实重写了基类虚函数”；签名写错或基类函数非虚，就报错。省略 `override` 不会取消正确的重写。
- `void f() override final;`：此虚函数不允许更下层派生类再次重写。
- `class Leaf final : public Base {};`：整个类不允许再被继承。

基类函数是虚函数，派生类匹配的重写函数就自动保持虚性，不必重复写 `virtual`；通常写 `override` 更明确。

引用：[[1.C++基础/12. OOP/12.3 多态/12.3.2 虚函数#override 关键字（C++11）|override]]、[[1.C++基础/12. OOP/12.3 多态/12.3.2 虚函数#final 关键字（C++11）|final]]。

### 21. 为什么多态基类通常需要虚析构？

若执行 `Base* p = new Derived; delete p;`，Base 析构必须为虚函数，才能通过基类接口正确销毁完整派生对象：

`virtual ~Base() = default;`

析构非虚时，C++17 下是**未定义行为**，不能只背“只调用基类析构，漏掉子类资源”。有其他虚函数也不会自动让析构函数变虚；但基类析构已经虚时，派生类析构自动保持虚性。

`unique_ptr<Base>` 的默认删除器同样受此规则约束。并非所有类都必须有虚析构：允许通过基类删除时通常采用 `public virtual` 析构；禁止这样删除时，可设计为 `protected` 非虚析构。

引用：[[1.C++基础/12. OOP/12.1 封装/12.1.7 析构函数#虚析构函数|虚析构函数]]；[C++17 草案：通过基类指针 delete 的要求](https://timsong-cpp.github.io/cppwp/n4659/expr.delete#3)。

### 22. 抽象类、接口类和纯虚函数怎么记？

```cpp
struct ITask {
    virtual void run() = 0;
    virtual ~ITask() = default;
};

struct Task : ITask {
    void run() override {}
};
```

有至少一个最终重写版本仍为纯虚函数的类是抽象类，不能创建独立对象，但能声明其指针、引用。派生类想成为具体类，就要让所有纯虚函数都有非纯的最终重写版本。

抽象类可以有数据成员、构造函数和普通成员函数；构造函数用于初始化派生对象中的基类部分。“接口类”是设计习惯，通常以公有纯虚函数为主、没有业务状态，虚析构不必写成纯虚。

纯虚函数可以在类外提供定义，类仍可能是抽象类。纯虚析构 `virtual ~Base() = 0;` 在创建派生对象的常规用法中仍必须有定义，如 `Base::~Base() = default;`，因为销毁派生对象会调用它。

引用：[[1.C++基础/12. OOP/12.3 多态/12.3.4 抽象类|抽象类]]、[[1.C++基础/12. OOP/12.3 多态/12.3.5 接口类|接口类]]；[C++17 草案：抽象类与纯虚函数](https://timsong-cpp.github.io/cppwp/n4659/class.abstract)。

### 23. vtable、vptr 在哪里？每个对象都有一张表吗？

常见实现：**对象 → vptr（虚表指针）→ vtable（虚函数表）→ 目标函数**。

- 对象通常保存 vptr；同一完整动态类型的不同对象通常共享相应的虚表，不为每个对象复制一整张表。
- 虚表包含虚函数相关入口，还可能带 RTTI、偏移等信息；不能只当作纯函数指针数组。
- 多重继承、虚继承时可能存在多个 vptr、多个表，转换基类指针时也可能调整地址。
- 具体布局由编译器和 ABI 决定，C++ 标准不规定“vptr 必在首地址”“一个类只能一张表”。
- 虚调用有间接访问成本，但编译器能确定目标时可以去虚化甚至内联，不能说“虚函数绝不能内联”。

`sizeof(T)` 会考虑非静态数据、基类子对象、必要的隐藏信息和对齐填充；不把静态成员数据、成员函数代码或 `this` 作为每对象数据计入。

引用：[[1.C++基础/12. OOP/12.1 封装/12.1.14 类的底层#虚函数表（vtable）|虚表概念]]、[[1.C++基础/12. OOP/12.3 多态/12.3.7 从内存角度理解|对象内存布局]]；[Itanium C++ ABI：虚表布局示例](https://itanium-cxx-abi.github.io/cxx-abi/abi.html#vtable)。

### 24. 在构造、析构函数里调用虚函数，会去派生类吗？

在 Base 的构造、析构期间，对当前对象的虚调用按 **Base 阶段**分派，不会跳到更下层 Derived 的重写版本。此时派生部分尚未构造好，或已经完成析构。

不要依赖这种调用触发派生类行为；在构造、析构中对当前对象进行纯虚函数的虚调用是未定义行为，不能把它当作初始化钩子。

引用：[[1.C++基础/12. OOP/12.1 封装/12.1.14 类的底层#对象构造过程|对象构造过程]]；[C++17 草案：构造析构期间的虚调用](https://timsong-cpp.github.io/cppwp/n4659/class.cdtor#3)。

## 五、静态成员与单例

### 25. 静态成员变量如何定义、访问？生命周期多长？

静态成员属于类，不属于某一个实例；普通类的各对象共享同一份静态成员数据。

- 传统写法：类内 `static int count;` 声明，在一个 `.cpp` 中 `int Counter::count = 0;` 定义；类外不再写 `static`。
- C++17 可以类内写 `inline static int count = 0;`，通常无需再到 `.cpp` 定义。
- 权限允许时，用 `Counter::count`，也可用 `obj.count`／`p->count`；后两者不会创建每对象副本。

不带 `thread_local` 的静态成员变量具有静态存储期，不随某个实例销毁。其存储贯穿程序执行；需要动态初始化的对象要等初始化完成后才可正常使用，成功构造的对象通常在程序正常结束时析构。

引用：[[1.C++基础/12. OOP/12.1 封装/12.1.9 静态成员变量#声明与定义|静态成员定义]]、[[1.C++基础/12. OOP/12.1 封装/12.1.9 静态成员变量#访问方式|静态成员访问]]。

### 26. 静态成员函数真的只能访问静态成员吗？

准确说法：它**没有隐含的 this，不能无对象地使用非静态成员**；传入或创建一个对象后，可以访问那个对象的成员，包括本类私有成员。

```cpp
class Counter {
    int value_ = 0;
public:
    inline static int total = 0;
    static int read(const Counter& obj) { return obj.value_; }
    void add() { ++value_; ++total; }
};
```

`Counter::read(obj)`、`obj.read(obj)` 都可调用。非静态成员函数既有对象，也能访问静态成员。

静态成员函数不能加末尾的 `const`，也不能是虚函数。函数本身没有对象那样的构造析构生命周期；函数内普通局部变量仍按每次调用创建，只有声明成 `static` 的局部变量才长期保留。

引用：[[1.C++基础/12. OOP/12.1 封装/12.1.10 静态成员函数#可以访问的内容|静态成员函数访问规则]]；[C++17 草案：静态成员函数没有 this](https://timsong-cpp.github.io/cppwp/n4659/class.static.mfct)。

### 27. 如何用 static 实现单例？private 构造有什么作用？

私有构造限制外部创建；静态 `getInstance()` 不依赖已有实例，可以调用私有构造。再禁止拷贝、赋值，避免复制出额外实例。

```cpp
class Singleton {
    Singleton() = default;
    ~Singleton() = default;
public:
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;

    static Singleton& getInstance() {
        static Singleton instance;
        return instance;
    }
};
```

调用 `Singleton::getInstance()` 返回同一对象的引用，不需要 `new` 或手动 `delete`；已有用户声明的拷贝操作，也不会隐式生成移动操作。

C++11 起，局部静态对象首次动态初始化由语言保证线程安全，正常程序结束时析构。但**单例成员的并发读写仍需要自己的同步**。

截图中的裸指针 `if (!instance) instance = new Singleton;` 没有同步会有数据竞争，也没有自动释放机制。私有构造本身不保证单例或线程安全。

引用：[[2.C++高级/16. 设计模式/16.1 单例模式#4. Meyers' Singleton（推荐）|局部静态单例]]；[C++17 草案：局部静态初始化](https://timsong-cpp.github.io/cppwp/n4659/stmt.dcl#4)。

## 六、类模板

### 28. 类模板怎样定义、实例化、特化？为什么通常放头文件？

```cpp
template<class T>
class Holder {
    T value_;
public:
    explicit Holder(T value) : value_(value) {}
    const T& get() const;
};

template<class T>
const T& Holder<T>::get() const { return value_; }

Holder<int> a(1);
Holder b(2.5);                     // C++17 类模板实参推导：Holder<double>
```

- 类模板是生成一组类的模板，`Holder<int>` 是具体类型；不同模板实参通常形成不同类型，各自的静态成员也分别存在。
- 类外定义成员要写 `template<class T>` 和 `Holder<T>::`；C++17 可在有合适推导依据时省略模板实参，不能保证所有场景都能推导。
- 隐式实例化所需的定义通常要对使用方可见，所以类模板及其成员定义一般都放头文件；也可用显式实例化，将支持的类型限定在实现文件中。
- 类模板支持全特化和偏特化：`template<> class Holder<int>;` 是全特化声明，`template<class T> class Holder<T*>;` 是偏特化声明；创建相应对象等需要完整类型时，还要提供定义。函数模板不支持偏特化。
- 一般只在需要时实例化成员定义，不是实例化类时就立刻生成所有成员函数实现。

引用：[[2.C++高级/10. 模版/10.2 类模版#模板类成员方法的声明与定义|类模板声明与定义]]、[[2.C++高级/10. 模版/10.2 类模版#类模版有选择性实例化的特征|成员实例化]]、[[17.八股知识点/17.2 函数#六、函数模板|函数模板速记]]；[C++17 草案：类模板偏特化](https://timsong-cpp.github.io/cppwp/n4659/temp.class.spec)。

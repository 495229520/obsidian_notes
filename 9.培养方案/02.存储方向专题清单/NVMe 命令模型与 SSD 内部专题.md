## 1. 协议对比：为并行闪存重新发牌

| 维度 | AHCI（机械盘时代） | NVMe |
|---|---|---|
| 队列 | 1 × 32 深 | 最多 64K × 64K 深 |
| 多核 | 全局队列抢锁 | per-CPU qpair 免锁 + MSI-X 定向中断 |
| 每命令开销 | 多次不可缓存寄存器访问 | 提交/完成各一次 doorbell 写 |
| 命令集 | ATA 历史包袱 | 精简必选集 |

一句话版本：SSD 内部是"多通道 NAND + 主控"的并行计算机，AHCI 的单队列是它的漏斗，NVMe 把漏斗拆成了与 CPU 核数、NAND 通道数匹配的并行管道。内核侧的 blk-mq（软件多队列，S-Week 8）就是为对接它而生。

## 2. 命令生命周期与两个精巧设计

八步流程（SQE → SQ doorbell → 取命令 → DMA → CQE → 中断 → 消费 → CQ doorbell）的完整展开见前置知识；这里沉淀两个必考设计点：

- **doorbell**：主机内存里的队列 + 设备寄存器的指针通告——提交路径除一次 MMIO 写外全是普通内存操作。它是"共享内存环"模式的同步原语。
- **phase bit**：CQ 环形复用，控制器每绕一圈翻转相位位；host 比对期望相位即知条目新旧——**免清理设计**，省掉"消费后写回无效标志"的一半内存流量。

admin qpair 管控制面（identify / 建队列 / features），IO qpair 管数据面；qpair 在 NVMe-oF 里映射为网络连接、在 NVMe/RDMA 里映射为 RDMA QP——这个概念是 S3 的贯穿主线。

## 3. SSD 内部：append-only 的第三次重现

NAND 约束（页读写、块擦除、不能原地改）→ FTL 异地更新 + 改映射 → 无效页积累 → GC 搬运 → 写放大：

$$
WAF = \frac{W_{nand}}{W_{host}}
$$

OP 是 GC 的腾挪空间：预留越多、稳态 WAF 越低——企业盘与消费盘的核心差异之一。

**把三层串成一条线**（面试高光）：FTL 的 GC、bitcask 的 merge、LSM 的 compaction——同一个"追加写 + 后台回收"模式在设备固件、单机引擎、分布式引擎三个层次重现。追加写换来的都是顺序写性能，欠下的都是垃圾回收的债，谁也逃不掉。

## 4. 稳态 vs 空盘：benchmark 的设备层纪律

空盘随机写虚高（空闲块充足、GC 不干活）；持续随机写后进入稳态（每次写背着 GC 搬运的税）。预处理三步：顺序写满 1-2 遍 → 目标块大小随机写到性能平台 → 正式测量。报告纪律：随机写数据必须声明"空盘 / 稳态 / 云盘不可判"三选一。

## 5. 面试口述模板

```text
NVMe 快在协议为并行闪存重新设计：最多 64K 条深队列、per-CPU qpair
免锁、MSI-X 定向中断，每条命令的开销只有提交完成各一次 doorbell 写。
生命周期我能画：SQE 进提交环、敲 doorbell、控制器 DMA 取命令和数据、
CQE 带 phase bit 写回完成环、中断或轮询收割——phase bit 是免清理
设计，靠相位翻转区分新旧条目。SSD 内部 NAND 页写块擦不能原地改，
FTL 用异地更新加映射表把它藏起来，代价是 GC 和写放大——这和 bitcask
的 merge、LSM 的 compaction 是同一个模式在三个层次的重现。所以随机
写测试必须预处理到稳态，空盘数字是厂商标称值最爱的假象。我的基线
数据全部标注了冷热与预处理状态。
```

追问预案：

- "phase bit 没有会怎样？" → host 无法区分环上旧 CQE 与新 CQE，要么加 valid 位清理（多一半写流量）要么读脏数据。
- "%util 100% 为什么不代表 NVMe 饱和？" → 多队列设备"有请求在途"≠"满负荷"，饱和看 IOPS 是否还能涨、延迟是否起飞（S-Week 8 的数据）。
- "写放大怎么降？" → 加 OP、顺序化写模式（大块/append）、TRIM 让 FTL 知道哪些块可回收、ZNS 这类新接口把回收权交还主机（提一句即可）。
- "你的云主机上这些还成立吗？" → 虚拟 NVMe 看不到真实 FTL，smart-log 多失真——我的 env.md 逐字段标了可信/失真，稳态实验做了边界声明。

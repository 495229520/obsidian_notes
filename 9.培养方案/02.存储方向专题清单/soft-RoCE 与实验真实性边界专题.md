# soft-RoCE 与实验真实性边界专题

## 1. soft-RoCE（rxe）是什么

内核模块 `rdma_rxe` 用**软件**实现 RoCEv2：完整的 verbs API（PD/MR/QP/CQ 全套可用），报文封成 UDP（端口 4791）走任意普通网卡。一条命令就能把任何 Linux 机器变成"RDMA 机器"：

```bash
sudo rdma link add rxe0 type rxe netdev eth0
```

**关键悖论一句话**：RDMA 的性能来自"绕过内核软件栈"，而 soft-RoCE 本身就是一层内核软件栈——**它模拟的恰恰是被真 RDMA 消灭的东西**。所以它的功能保真、性能失真是结构性的，不是"机器不够好"的问题，租再贵的云主机也救不回来。

## 2. 能证什么、不能证什么

| 能证（功能级，放心用） | 不能证（性能级，一票否决） |
|---|---|
| verbs 编程模型正确性（对象创建、状态机、收发） | 延迟绝对值（软件栈微秒级 vs 真网卡亚微秒级） |
| 双边/单边语义、RNR/rkey 等错误行为 | 带宽上限（受 CPU 软件封包能力限制） |
| NVMe-oF RDMA 的路径连通与结构差异 | CPU 占用对比（它烧 CPU 恰是真 RDMA 省掉的） |
| 与 TCP transport 的**形态**对照（qpair 映射方式） | 任何"RDMA 比 TCP 快 X%"的结论 |
| 程序的可移植性（同一套代码上真卡直接跑） | 拥塞行为（无真实交换机参与，PFC/ECN 全不存在） |

一个易错点：soft-RoCE 上 `ib_write_lat` 比 `ib_send_lat` 的相对关系有时与真卡一致，诱惑人下"形态结论"——**相对形态可以观察记录，但也要标注环境**，因为软件实现的成本结构与硬件不同，相对关系也可能失真。

## 3. 三类实验分层法（总纲原文的展开）

```text
功能级实验：soft-RoCE / network namespace
  —— 只讲路径和机制；小节里可以有数字，但标题写明"数值无性能意义"
性能级实验：真实 RDMA NIC / 本地 NVMe / 裸金属
  —— 唯一允许进结论和简历的数字；每个带环境三元组（机器/内核/网络）
云环境实验：云虚拟机上的一切
  —— 默认降一级看待：虚拟盘只做流程验证；虚拟网络的数字标注
     "受虚拟化影响"；不得写成设备/网卡性能结论
```

落进报告的三条操作规则：

1. **数字不越界**：每个数字只出现在自己层级的小节，结论一章只引用性能级。
2. **标签前置**：每个实验小节的第一行就是层级标签，不藏在脚注里。
3. **边界主动写**：局限声明是一节而不是一句——云主机虚拟化影响、单盘单文件系统、soft-RoCE 结构性失真、毛刺注入是人为构造，全部列条。

这套方法不只服务 RDMA：S-Week 18 的云盘 smart-log 失真、S-Week 19 的 netns 回环、S1 的云主机 page cache 数据，全部适用。**它是作品集的可信度框架，不是某一周的免责声明。**

## 4. 裸金属补测：决策与执行

- **决策输入**：预算（1-2 天实例费）、目标岗位（端侧 RDMA / AI Infra 存储岗值得补；泛后端岗可不补）、报告完成度（功能级故事已完整，补测是升级不是补救）。
- **执行纪律**：租之前脚本与清单全部就绪，租期只跑不调；优先补 `ib_write_lat / ib_send_lat` 真实值和 NVMe-oF RDMA vs TCP 的 QD1 对比。
- **不补也完整**：三分法保证了报告在纯功能级下自洽——"我知道哪些数字缺、为什么缺、补齐要什么条件"，这句话本身就是工程成熟度。

## 5. 面试口述模板

```text
我的 RDMA 实验跑在 soft-RoCE 上，这一点我主动声明：rxe 是内核软件
实现的 RoCEv2，verbs API 完整所以功能级结论全部成立——编程模型、
状态机、单双边语义、NVMe-oF RDMA 的路径都验证过；但它本身就是一层
内核软件栈，模拟的恰恰是真 RDMA 绕过的东西，所以性能数字结构性失真，
我一个都没写进结论。我的报告用三分法组织：功能级只讲机制、性能级
才有数字且带环境三元组、云环境默认降级——每个数字都待在自己的可信
度层级里。如果需要真实数字，我的补测清单和脚本是现成的，租两天带
RDMA 网卡的裸金属就能把关键几个数补上。
```

追问预案：

- "那你怎么知道你的程序在真卡上能跑？" → verbs API 是同一套，rxe 与真卡走同一个 libibverbs——可移植性正是功能级实验能证明的东西；真卡上要重新标定的只是性能参数（inline 阈值、MTU 等）。
- "soft-RoCE 有什么正经用途？" → 上游内核开发和 CI 测试（无硬件跑 RDMA 测试集）、教学、协议原型——它是正规工具，只是不是性能工具。
- "云上的 eRDMA/弹性 RDMA 实例算哪级？" → 真硬件参与但有虚拟化层——性能级但标注"云化 RDMA，与裸金属有差异"，仍然优于 soft-RoCE。

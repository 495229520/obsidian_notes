# S-Week 28 - 开源贡献冲刺

> [!goal] 本周目标
> 把总纲的开源贡献目标落袋（三选一：1 个 merged PR / 3 个高质量 issue reproduction / 2 篇被社区认可的 benchmark report），优先级 LMCache > JuiceFS/fio > RocksDB/SPDK。方法沿用四步法 Reproduce → Minimize → Analyze → Contribute。核心纪律：**从自己 S4 实验里长出来的贡献才有命中率**——为贡献而贡献的 PR 大概率石沉大海。

## 学习目标

1. **为什么 LMCache 优先？** 新项目文档与边角多、贡献门槛低、贴 AI 存储叙事——而且你刚在 S4 里真实使用过它，遇到的每个坑都是贡献素材。
2. **什么样的 issue reproduction 算高质量？** 环境完整、步骤最小化、现象与预期对照清楚、附上初步归因——维护者照着能十分钟复现（S-Week 17 已练过一次）。
3. **benchmark report 怎么被社区认可？** 环境三元组 + 方法透明 + 与已知结论对照 + 提出一个可讨论的问题——本质是把你的报告纪律用到别人的项目上。
4. **PR 的存活率由什么决定？** 选题（文档修正/复现脚本/小修复 > 功能）、提前在 issue 里沟通、遵循项目的贡献规范与代码风格、耐心跟进 review。
5. **时间盒怎么切？** 本周主产出 1-2 个具体贡献物；merged 与否不完全可控（review 周期），**提交质量和跟进记录本身就是面试素材**。

## 1. 贡献点挖掘（Day 1）

从 S4 的实验记录里筛（存量优先，不新挖坑）：

- LMCache：安装/集成时文档与实际不符处、配置项含义不清处 → 文档 PR；你的三档对照数据 → benchmark report（发 discussion/issue）；复现过的异常行为 → issue reproduction。
- fio / JuiceFS 备选：S1-S3 期间записанные怪现象翻一遍（gap-analysis 和各周 notes 里应有存货）。
- 每个候选按"工作量 × 命中率"打分，选 Top 2-3 进时间盒。

## 2. 执行：四步法走完（Day 2-4）

- Reproduce：干净环境复现，版本与 commit 固定。
- Minimize：砍到最小复现（配置最少、步骤最短）。
- Analyze：初步归因（代码定位或行为对照），不确定就写"怀疑点 + 证据"。
- Contribute：按项目模板提交（issue/PR/discussion 各按其规范）；PR 提前在 issue 沟通意向；全程截图与链接归档进 `docs/oss_contrib.md`。

## 3. 跟进与沉淀（Day 5）

- 逐条记录状态（提交/回复/修改/合并），设置后续每周跟进的提醒节奏。
- `docs/oss_contrib.md`：每个贡献一节——动机（从哪个实验来）、过程、当前状态、学到什么；这份文档在面试里的价值不低于 merged 本身。
- 简历与 portfolio 更新：贡献条目按事实写（"提交并被合并" vs "提交待 review"，不夸大）。

## 4. 推理线合流（约 25%）

- LMCache 社区跟踪本身就是合流动作：读它的 roadmap/近期 PR，理解 KV 存储层的工程演进方向——面试聊"这个领域在发生什么"的素材。

## 5. 面试保底（约 15%）

> 阶段 3 秋招冲刺编排第 6 讲。

- 算法（5-8 题）：CodeTop 保温 + 手撕一道：LFU 或时间轮定时器（数据结构设计压轴题型）。
- 系统设计练习（新增）：出一道"设计一个多级 KV cache 存储层（显存/DRAM/NVMe/远端）"自答 45 分钟——S4 的全部积累正好是标准答案素材。
- 项目问答：10 个 Q&A（本周素材：贡献动机与过程、社区协作）。

## 6. 本周产出文件

| 文件 | 内容 | 验收方式 |
|---|---|---|
| 贡献物 1-2 个 | PR / issue repro / benchmark report | 链接可查、符合项目规范 |
| `docs/oss_contrib.md` | 贡献记录与状态 | 每条有动机与学到什么 |
| 简历/portfolio 更新 | 贡献条目 | 按事实表述不夸大 |

## 7. 验收标准

- [ ] 至少 1-2 个贡献物提交完成（质量优先于数量）。
- [ ] 每个贡献都能追溯到自己的实验（不是为贡献而贡献）。
- [ ] 四步法记录完整，跟进节奏已设置。
- [ ] 总纲三选一目标达成或有明确在途路径（review 中的 PR + 已有 issue repro 计数）。
- [ ] 系统设计题自答完成并复盘。
- [ ] 合流与面试保底完成本周额度。

## 面试问题

- 讲一个你的开源贡献：动机、过程、结果。
- 你提交的 issue 为什么维护者愿意理？
- 你的 benchmark report 和项目官方数据不一致时怎么处理？
- 设计一个多级 KV cache 存储层，你会怎么分层、怎么定驱逐与预取？
- 开源协作里你学到的最反直觉的一课是什么？

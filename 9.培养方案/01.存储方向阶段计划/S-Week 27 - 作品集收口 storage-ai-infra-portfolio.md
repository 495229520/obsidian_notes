# S-Week 27 - 作品集收口 storage-ai-infra-portfolio

> [!goal] 本周目标
> 不写新代码，只做整合（总纲原话）：四个仓库（linux-io-lab / mini-kv-engine / nvme-of-lab / gds-kv-offload-lab）统一报告模板与环境记录，画出从 VFS 到 GPU 的**总路径图**，把秋招故事线打磨到"任何一段被打断都能下潜两层"。本周结束，散装项目变成一份有主线的作品集——面试官 15 分钟能建立你的全貌。

## 学习目标

1. **作品集和四个仓库的区别是什么？** 仓库证明"做过"，作品集证明"成体系"：统一模板 + 关键结论汇总 + 一条故事线——评委的阅读成本降一个数量级。
2. **总路径图长什么样？** [[S-Week 11 - 完整版收口]] 的 io_path_notes 向右扩展：VFS → page cache → 块层 → NVMe →（NVMe-oF/RDMA 分支）→ 主机内存 →（GDS 直达分支）→ GPU 显存——每段标三元组（延迟量级 / 哪次实验 / 什么工具），全图每一段都有自己的数据。
3. **秋招故事线的骨架？** 总纲原文："从 LLM 推理入门 → 发现瓶颈在数据路径 → 系统补齐 Linux I/O、NVMe、RDMA、存储引擎 → 现在能同时讲清 GPU 在等什么数据、数据卡在哪一层。"
4. **统一模板统一什么？** 报告六段式、环境记录字段（总纲第十一节的必记清单）、复现脚本约定、局限与 Agent 声明——四仓库同构，读一个就会读全部。
5. **推理版作品怎么并入？** CUDA Week 1-4 与 serving harness 作为"入门与工具"章节并入故事线，不单列为第五个项目——主线是存储，推理是起点和交汇点。

## 1. 统一模板与四仓库对齐（Day 1-2）

- 定模板：`README 结构 / docs/report 六段式 / env.md 字段 / reproduce.sh 约定 / LIMITS.md（局限+Agent 声明）`。
- 逐仓库对齐：不重写内容，只统一结构与缺项补齐（S1 最老，缺项最多）；每仓库 README 顶部加"在作品集中的位置"一句话 + 指向 portfolio 的链接。
- 数字一致性扫描：简历、各报告、interview_qa 三处的关键数字（毛刺定位、崩溃注入 1000 次、延迟分解、TTFT 改善）逐一对账——一处对不上就全体扣分。

## 2. 总路径图与关键结论页（Day 3-4）

- `storage-ai-infra-portfolio` 仓库（或主仓库的 portfolio/ 目录）：总 README = 故事线一页 + 总路径图 + 四项目卡片（每个：一句定位 + 三个最硬数字 + 链接）。
- 总路径图（SVG，存 `图片/9.培养方案/`）：横跨四个项目的全路径 + 三元组标注；配三分钟口述稿——这张图是面试白板题的母版。
- 关键结论页：十条左右"我验证过的事实"（每条一句 + 数据出处），例如"顺序读快于随机读的块层证据""fsync 三档的吞吐比值""QD1 远程延迟的三段分解""KV offload 的临界带宽对账"。

## 3. 故事线与简历终稿（Day 5）

- 五分钟版故事线（S-Week 22 的三段式扩成四段：+S4 交汇段）演练三遍，录音回听。
- 简历终稿：主标题 AI Infrastructure Systems Engineer（总纲第十三节），四项目按故事线排序；每 bullet 数字可溯源。
- interview_qa.md 与五板块题库互链核对：题库每题的"证据"都能点进作品集对应页。

## 4. 推理线合流（约 25%）

- 推理版作品并入：CUDA Week 1-4 小结 + harness 使用说明并入 portfolio 的"入门与工具"章；[[Week 5 - Serving Benchmark Harness]] 在 S4 中的复用写清（它是贯穿两条线的工具资产）。

## 5. 面试保底（约 15%）

> 阶段 3 秋招冲刺编排第 5 讲。

- 算法（5-8 题）：CodeTop 保温；手撕一道：单例 + 线程安全初始化（[[16.1 单例模式]]、[[17.8 Modern C++ 同步设施与实战并发模式]]）。
- 题库轮换：五板块随机抽 15 题混答（跨板块跳转训练——真实面试不按板块出题）。
- 项目问答：四段式故事线 + 任意段下潜两层的追问演练（找同学/录音自练）。

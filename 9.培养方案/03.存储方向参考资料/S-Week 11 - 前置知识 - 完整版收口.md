## 0. 先建立直觉：收口周在做什么

面试官不会按周次问你问题，他问的是"讲讲你这个项目"。散落在 11 周里的实验必须收敛成一条 3 分钟能讲完的故事线：

```text
一次 read 的完整路径（图）
 → 每层我都测过（延迟量级 + 实验编号）
 → 每层我都能观测（工具矩阵）
 → 出了问题我能定位（p99 毛刺案例）
 → 全部可复现（reproduce.sh）
```

本周所有任务都是在为这条故事线补最后的洞：readahead 定量数据补"page cache 层"的洞，全路径图是故事线载体，README 是对外门面。

## 1. readahead 定量实验要点

S-Week 1/4 已定性讲过预读，本周升级成三组定量证据：

- **窗口扫描**：`/sys/block/<dev>/queue/read_ahead_kb` 取 0 / 128 / 1024。注意这是全设备参数，改完要记得还原（写进脚本的 trap 里）；每组之间照旧 sync + drop_caches。
- **收益侧**（冷顺序读）：期望看到延迟随窗口增大而下降后趋平；blktrace 的 rareq-sz 随窗口同步变大——"预读批量化"的直接证据链。
- **误伤侧**（冷随机读 + 大窗口）：对比 rkB/s 与程序实际消费字节数，差值就是白读的带宽；再看 buff/cache 涨幅里有多少是无效页。

一个必须想清楚的对照：`read_ahead_kb=0` 与 `POSIX_FADV_RANDOM` 都能关预读，但作用域不同——前者影响整个设备上所有进程，后者只影响单个 fd。生产里该用哪个，答案不言自明。

## 2. fadvise 语义精确版

| 提示 | 语义 | 关键细节 |
|---|---|---|
| POSIX_FADV_SEQUENTIAL | 加大预读窗口 | 是"提示"不是命令，内核可忽略 |
| POSIX_FADV_RANDOM | 关闭该 fd 的预读 | 每次读老老实实到设备 |
| POSIX_FADV_WILLNEED | 异步预取指定范围 | 发起即返回，不等数据就位 |
| POSIX_FADV_DONTNEED | 提示丢弃干净页 | 脏页不丢；想丢先 fsync——轻量"变冷"手段 |

WILLNEED 与"自己先 read 一遍"的区别是本周面试问题之一：WILLNEED 异步、不占用户 buffer、不产生拷贝；预热读是同步的且多一次用户态拷贝。

## 3. 全路径图怎么画才是"自己的图"

网上到处有 Linux I/O 栈层次图；你的图的差异化在**每层挂三元组**：

```text
层名 + 延迟量级（本机实测） + 测它的实验（周次/文件） + 观测它的工具
```

画图纪律（沿用 obsidian-svg 的资产规范）：

- 主干一条：用户态 → syscall/VFS → page cache → 块层 blk-mq → NVMe 驱动 → 设备；写路径以 dirty/writeback 分支挂在 page cache 层。
- 变体路径用旁支标注：O_DIRECT（跳过 cache）、mmap（缺页进入）、io_uring（提交/完成环）。
- 每层的数字必须能溯源到 `results/` 里的某个文件——图上标注实验编号，口述时才能"这个数我测过"。
- SVG 存 `图片/9.培养方案/` 下，笔记内嵌引用。

自检标准：盖住图，能凭记忆重画并把每层数字讲出来，才算过。

## 4. README 与复现工程的定稿标准

新读者 15 分钟建立全貌，意味着 README 必须有这几段（顺序即阅读动线）：

1. **一句话定位**：这个仓库回答什么问题。
2. **结论速览**：三五条最有价值的实验结论，各附一个数字。
3. **实验索引表**：每行 = 问题 → 方法 → 结论文档链接（11 周全覆盖）。
4. **复现指引**：环境要求 + `reproduce.sh` 用法 + 预计耗时。
5. **局限声明**（见下节）。
6. **Agent 使用声明**：哪些部分 AI 生成、如何验证——沿用推理版的诚实纪律。

`reproduce.sh` 定稿检查：阶段 1 新增实验（blktrace、eBPF、消融、readahead）都已纳入；破坏性步骤（drop_caches、改 read_ahead_kb）有确认提示且退出时还原；在干净机器上通跑过一次。

## 5. 局限声明怎么写才加分

原则：**每条局限 = 事实 + 影响范围 + 如果有条件怎么补**。三段俱全才是工程判断，只有第一段是自我检讨。

```text
云主机虚拟化层：延迟绝对值含 hypervisor 开销，跨层对比结论不受影响；
  有物理机后优先重跑 O_DIRECT 基线。
单盘单文件系统（ext4）：结论未验证 XFS/btrfs 的日志策略差异；
  预期 fsync 家族数据变化最大。
毛刺注入为人为构造：真实生产干扰更复杂（多租户、GC 叠加）；
  runbook 的定位流程不依赖干扰来源。
```

## 6. gap-analysis 方法

投递以来攒下的 JD 逐条拆成能力项，三栏归位：

| 归位 | 处理 |
|---|---|
| 已覆盖 | 标注对应周次/产出，面试直接引用 |
| 阶段 2 会覆盖 | 映射到 mini-kv-engine / nvme-of-lab 的哪个月 |
| 计划外 | 评估：高频出现则挤进阶段 2，低频则明确放弃 |

输出就是阶段 2 的排期依据：出现频率最高的"计划内缺口"排最前。别跳过"明确放弃"这栏——什么都想补等于什么都补不深，放弃清单和优先级清单同样重要。

## 7. 常见错误

- **改了 read_ahead_kb 忘还原**：后续所有实验带着 1024 的窗口跑，整批数据作废——参数修改必须进脚本 trap。
- **全路径图抄成教科书图**：没有本机数字和实验编号，面试一追"这个数哪来的"就露馅。
- **README 写成周记**：按时间流水而不是按问题组织，读者 15 分钟建立不了全貌。
- **局限藏着不写**：面试官问出来再承认，印象分远低于主动声明。
- **gap-analysis 只列缺口不排优先级**：等于没做，阶段 2 排期仍然拍脑袋。
- **复盘只看完成度不看配比**：60/25/15 的时间配比漂移了多少、往哪漂，是复盘的第一个数字。

## 9. 关键要点总结

- 收口 = 组装：全路径图（故事线）+ README（门面）+ gap-analysis（下一步依据）。
- readahead 实验把阶段 0 的定性推断升级成 trace 证据，全路径图的 page cache 层因此有了完整数据。
- 图的价值在三元组：每层有本机数字、有实验出处、有观测工具。
- 局限声明三段式：事实 + 影响范围 + 补救路径。
- 放弃清单与优先级清单同等重要——gap-analysis 的产出是排期，不是愿望单。

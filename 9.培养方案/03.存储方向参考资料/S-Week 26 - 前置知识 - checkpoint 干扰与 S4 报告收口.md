## 0. 先建立直觉：老实验、新场景、同一条伤害链

S-Week 9 你做过：后台大量 buffered 写 + 周期 sync → 前台 4K 随机读 p99 起飞，biosnoop 抓到肇事者。当时它叫"writeback 干扰注入"；套上 AI 场景的名字，它就是"checkpoint burst 打伤在线负载"。本周的实验只是把注入源参数化成 checkpoint 的形态（数十 GB、周期性、大块顺序），再把四种缓解姿势各跑一轮——**证明你不仅能复现问题，还能量化每种解法的收益**。

> [!important] 第一性原理
> 面试官对"跑过实验"和"能迁移方法"的估值差一个级别。本周的叙事重点不是 checkpoint 本身，而是：**同一条伤害链、同一套工具，我在通用场景定位过、在 AI 场景量化过**——方法可迁移，这才是系统能力。

## 1. checkpoint 模拟实验：四姿势的设计细节

- 前台：S-Week 9 的 io_uring 4K 随机读程序原样复用，QD4，逐笔延迟进 CSV，先采 5 分钟干净基线。
- 注入源：单文件顺序写数十 GB（fio 或 dd 均可，块大小 1M+），周期性触发（模拟每小时级 checkpoint 的 burst 特征，实验里压缩到分钟级周期）。
- 四姿势各一轮，每轮覆盖 2-3 个注入周期：

| 姿势 | 实现 | 验证点 |
|---|---|---|
| buffered | 默认写 | 复现 p99 起飞 + `Dirty` 水位飙升 + writeback 风暴 |
| buffered + 限速 | cgroup v2 `io.max` 限写带宽 | p99 受控但注入拖长——收益与代价同框 |
| O_DIRECT | 直写绕过 page cache | 脏页海啸消失；剩余干扰 = 纯带宽争抢 |
| O_DIRECT + 限速 | 两者叠加 | 前台最稳的组合，代价最长的写完时间 |

- 观测三件套：前台 p99 时间线（与注入周期对齐画图）、`grep Dirty /proc/meminfo` 采样、biosnoop 抓肇事样本各留一段。
- 关键对比数字：每姿势一行——前台 p99 恶化倍数 / 注入完成时间 / 结论一句。

## 2. 异步快照演示组：验证"受扰时段搬家"

加一组轻量演示（不需要 GPU）：注入源先把数据写进内存 buffer（模拟 D2H 快照到 pinned 内存），再由后台线程慢速刷盘。预期观测：**前台受扰时段从"快照期"移到"后台刷盘期"，且刷盘期可叠加限速把干扰压平**——这就是异步 checkpoint 的收益结构：训练（前台快照期）不停顿，代价转移到可调度的后台。落盘补上原子模式（临时文件 + fsync + rename + 目录 fsync），与 mini-kv-engine 的切换语义连线一句。

## 3. 模拟边界：你的实验和真实训练框架差在哪

主动写清四条（面试必被问）：

1. 注入源是 fio/dd，不是真实框架的 checkpoint 序列化（真实的还有 GPU 停顿、序列化 CPU 开销、分片并行）；
2. 单机单盘，没有分布式文件系统上的多写者汇聚；
3. 恢复侧的"读风暴"未实验（多节点拉同一份），只有机制口述；
4. 数据量按租期缩放，周期压缩。

边界声明的价值定式（S3 学的）：**说清"测的是伤害链和缓解手段的相对收益，不是生产绝对值"**——诚实框定后，结论反而立得住。

## 4. S4 报告的骨架与主线一页

`ai_data_path_report.md` 定稿结构：

```text
0. 主线一页：GPU 时薪 vs 存储毫秒的经济学；
   训练侧论据（checkpoint 干扰实测）+ 推理侧论据（KV offload 对账）
1. GDS 章：三路径对照、归因、compat mode 方法论
2. KV offload 章：三档对照、收支对账表、条件化判据
3. checkpoint 章：四姿势对照、异步快照演示、四层缓解
4. 边界与声明：机型/驱动/模型规模/模拟性质/三类实验标签
5. 复现：reproduce.sh 索引（GPU 依赖项标注）
```

主线一页的写法：第一段抛问题（"一块 GPU 每小时的钱 > 一块 NVMe 每月的钱——所以数据路径上每一毫秒都在给最贵的资源计费"），第二段训练侧一句 + 指向第 3 章的数字，第三段推理侧一句 + 指向第 2 章的对账表，收尾一句"这就是我整个作品集回答的问题"。**定稿标准 = 对着 [[存储面试问题清单 - AI 数据路径]] Q1-Q6 逐题脱稿无卡壳**——报告写到能答面试题为止。

## 5. 精简版决策：砍什么、怎么声明

总纲授权的精简路径（实习挤压时）：

- 砍 checkpoint 实验，保留口述级（素材在 [[checkpoint I O 专题 - burst write 隔离]]，S-Week 9 的实测可以引用为"同伤害链的通用场景版"）；
- GDS 与 KV offload 两个核心实验不可砍（报告面试题 4/8 直接依赖）；
- 报告第 3 章改为"机制分析 + S-Week 9 实测引用 + 生产实验 TODO"——结构完整、深度声明。

决策纪律：本周开始前定下来（看实习占用的真实情况），不要做一半再砍——半成品实验比声明砍掉更伤报告。

## 6. 常见错误

- **重做 S-Week 9 已证明的事**：干净基线和 buffered 伤害链已有方法，本周直接参数化复用——时间花在四姿势对比和异步演示这些新增量上。
- **注入周期太密**：前台没有恢复窗口，四姿势的差异被压扁；周期间要留干净段。
- **限速值拍脑袋**：先测注入源的裸带宽，限速取其 1/4 与 1/2 两档才有梯度。
- **报告三章各写各的**：没有主线一页，就是三份报告的合订本——装裱失败。
- **边界声明写成免责堆砌**：四条模拟边界要各配"为什么不影响相对结论"的一句论证。
- **精简版做一半**：要么完整做、要么干净砍——半成品最伤。

## 8. 关键要点总结

- checkpoint 实验 = S-Week 9 伤害链的 AI 场景参数化：证明方法可迁移比证明现象存在值钱。
- 四姿势对照的灵魂是"收益与代价同框"：p99 恶化倍数 × 注入完成时间。
- 异步快照的收益结构：停顿搬到后台、后台可限速——原子落盘与 KV 引擎同源。
- 报告定稿标准 = 能脱稿答面试题；主线一页把三章缝成一个论点。
- 精简版是被授权的正路：干净砍 + 深度声明，不做半成品。

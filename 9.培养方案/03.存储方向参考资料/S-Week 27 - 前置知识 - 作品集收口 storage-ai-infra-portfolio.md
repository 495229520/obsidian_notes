> 总纲原话：不写新代码，只做整合。这句约束是保护你的——收口周最大的敌人是"顺手再补个实验"的冲动。本周的产出物只有一个衡量标准：**一位没见过你的面试官，15 分钟能不能建立"这个人成体系"的判断**。信息架构、模板统一、数字对账，全部为这 15 分钟服务。

## 0. 先建立直觉：评委只有 15 分钟

简历筛选阶段，评委看你 GitHub 的真实时间可能只有几分钟；面试前的功课也就 15 分钟。四个孤立仓库的阅读成本是：进第一个 → 看 README → 不知道和其他仓库什么关系 → 退出。作品集要做的就是把阅读路径变成：**进 portfolio → 一页故事线 + 总图 → 按兴趣点进某个项目卡片 → 深读那份报告**——每一步都有明确的"下一步"，评委的注意力永远花在你最想展示的东西上。

> [!important] 第一性原理
> 作品集是一个**导航系统**，不是内容仓库。内容已经在四个仓库里了；本周做的一切——模板、总图、卡片、故事线——都是降低"从任意入口到关键证据"的跳数。跳数 ≤ 2 是设计目标。

## 1. 作品集的信息架构：三层漏斗

```text
第一层（30 秒）：故事线一段 + 总路径图 —— "他做了什么、为什么成体系"
第二层（3 分钟）：四张项目卡片 —— 每张 = 一句定位 + 三个最硬数字 + 链接
第三层（15 分钟+）：各仓库的报告与代码 —— 深挖的证据层
```

- 第一层放 portfolio 仓库（或主仓库 portfolio/ 目录）的 README 顶部；关键结论页（十条已验证事实）紧随其后——它是面试官抽问的题库，也是你自己的复习卡。
- 项目卡片的三个数字怎么选：**可追问、可复现、有对比基线**的优先——"崩溃注入 1000 次零丢失"优于"实现了 KV 引擎"；"QD1 远程延迟三段分解误差 <20%"优于"搭了 NVMe-oF"。
- 推理版作品（CUDA Week 1-4、harness）放进"入门与工具"章：故事线的起点和贯穿工具，不占第四张卡片——主线是存储，卡片给 S1-S4。

## 2. 统一模板：统一什么、不统一什么

统一的（读一个仓库就会读所有仓库）：

| 项 | 约定 |
|---|---|
| README 结构 | 定位一句 → 关键结论 → 实验索引表 → 复现 → 局限与声明 → 在作品集中的位置 |
| 报告六段式 | 沿用 [[benchmark 报告与可复现工程专题]]：问题/环境/方法/结果/分析/局限 |
| `env.md` 字段 | 总纲第十一节必记清单：机器/内核/文件系统与挂载/盘型号/云盘与否/工具版本/重复次数 |
| `reproduce.sh` | 一键复跑 + 特殊依赖标注（GPU/GDS 机型） |
| `LIMITS.md` | 局限 + Agent 使用声明（可生成脚手架与脚本、不可决定结论与改数据） |

不统一的：各项目的实验内容、报告篇幅、目录深度——**模板管骨架不管血肉**，把 S1 的报告重写成 S4 的口吻是浪费时间。

对齐顺序：从最老的 S1 开始（缺项最多），S4 最新基本达标——预算前重后轻。

## 3. 总路径图：从 io_path_notes 到 VFS→GPU 全图

[[S-Week 11 - 完整版收口]] 画过左半张（VFS → page cache → 块层 → NVMe，每层三元组）；本周向右接上三段：

```text
（左半：S1 的 io_path_notes 原图）
→ NVMe-oF 分支：transport（TCP/RDMA）+ target 栈   [S3 的延迟分解]
→ 主机内存：pinned buffer / page cache              [S1/S23 的对照]
→ GPU 显存：cudaMemcpy 路径 vs GDS P2P 直达         [S23 的三组对照]
旁注：KV offload 的读回走这条路的哪几段              [S25 的对账]
```

三元组纪律不变：每段标"延迟/带宽量级 + 哪次实验测的 + 什么工具观测的"——图上不允许出现没有自己数据的段落（没测过的段用虚线 + "文献值/未测"标注，诚实分层）。这张图是面试白板的母版：口述稿按"从左讲到右 3 分钟、任意段可下潜"打磨。

## 4. 故事线写作：四段式与下潜层

四段式（S-Week 22 的三段 + S4 交汇段），每段三件套：**能力定位一句 + 最硬数字一个 + 衔接句**。总纲的秋招故事线原文是纲，四段是目：

```text
起点：从 LLM 推理入门（CUDA + serving harness）——发现推理的下一个
     瓶颈在数据路径 →
会测：linux-io-lab，逐层测量 + 毛刺定位 →
会写：mini-kv-engine，crash consistency + 1000 次注入 →
会连：nvme-of-lab，延迟分解 + RDMA + SPDK →
交汇：gds-kv-offload-lab，GDS 直读 + KV offload 收支对账——
     "现在我能同时讲清 GPU 在等什么数据、数据卡在哪一层"
```

下潜层准备：每段预埋两层追问的答案（第一层机制、第二层取舍/边界）——例如"会写"段被追问，第一层讲 group commit 机制，第二层讲单 writer 的三个备选否决。**下潜材料全部已有**（各周 Q&A 和五板块题库），本周只做索引对齐，不写新内容。

## 5. 数字一致性扫描：三处对账

简历、各报告、interview_qa/题库三处出现的同一数字必须完全一致——一处冲突，面试官对全部数字打问号。扫描方法：

1. 列"关键数字清单"（十个左右：毛刺定位倍数、注入次数、三段分解各值、TTFT 改善、对账达成率……）；
2. 每个数字标注唯一权威出处（某报告某表）；
3. grep 三处文本逐一核对，不一致的以权威出处为准改齐；
4. 清单本身进 portfolio 的关键结论页——对账副产品直接变成资产。

## 6. 常见错误

- **收口周开新实验**：总纲明令禁止；发现实验缺口记进"入职后/面试聊"清单，不动手。
- **把四份 README 重写一遍**：模板管骨架不管血肉——只补缺项、只统一结构。
- **总图出现没测过的实线段**：白板上被追问"这段你怎么测的"当场露怯——没测的用虚线声明。
- **故事线背成简历朗读**：衔接句和下潜层才是灵魂；录音回听治这个病。
- **卡片数字选"最大的"而不是"最硬的"**：可追问、可复现、有基线的数字才经得起面试。
- **数字对账偷懒**：三处不一致是最低级也最致命的失分。

## 7. 学习检查清单

- [ ] 三层漏斗的信息架构清楚，跳数 ≤ 2 的设计目标认可。
- [ ] 统一模板五项约定与"不统一什么"明确。
- [ ] 总图右半三段的三元组数据来源都能指出；未测段的虚线纪律清楚。
- [ ] 四段式故事线每段三件套齐备，下潜两层的材料索引对齐。
- [ ] 关键数字清单与三处对账方法就绪。

## 8. 关键要点总结

- 作品集是导航系统不是内容仓库：为"15 分钟建立判断"设计每一跳。
- 模板统一骨架（README/六段式/env/reproduce/LIMITS），血肉不动。
- 总图 = io_path_notes 右扩三段，三元组纪律不变，没数据的段虚线诚实。
- 故事线四段式：定位 + 硬数字 + 衔接，每段预埋两层下潜。
- 数字三处对账，清单变资产——收口周不写新代码、不开新实验。

## 1. Day 4 要解决什么

Day 4 的目标可以压成一句话：

```text
跑通 FP16 GEMM baseline，并知道什么时候只用 cublasHgemm，什么时候要看 cublasGemmEx。
```

这一天不要求你手写 Tensor Core，也不要求你追 cuBLAS 性能。你要先能回答：

- 输入矩阵是 FP32 还是 FP16？
- 输出矩阵是 FP16 还是 FP32？
- 累加是 FP16 语义还是 FP32 accumulate？
- benchmark 表里有没有记录这些差异？

> [!important] 第一层直觉
> SGEMM 的重点是 FP32 baseline；HGEMM / GemmEx 的重点是把“数据类型”和“计算类型”说清楚。否则两个数字看起来都是 GEMM，实际比较的可能不是同一种工作负载。

---

## 2. 从 SGEMM 到 HGEMM

Day 1 的 SGEMM 可以记成：

```text
float input
float output
FP32 GEMM baseline
```

Day 4 开始进入 HGEMM：

```text
half input
half output 或 mixed output
可能触发更强的库内部路径
```

从项目组织上看，建议不要覆盖 Day 3 的 `bench_sgemm.cu`，而是新增一个明确文件：

```text
bench_hgemm.cu
```

这样 README 和 benchmark 表里可以直接区分：

| API | 主要用途 | 入门理解 |
|---|---|---|
| `cublasSgemm` | FP32 baseline | 先证明普通 GEMM 对拍和计时正确 |
| `cublasHgemm` | FP16 baseline | 最小 HGEMM 入口 |
| `cublasGemmEx` | 显式类型控制 | 记录 input、output、compute type |

### 2.1 half 数据准备

Day 4 开始，输入不再只是 `float`。CUDA 代码里常见的 half 类型是：

```cpp
#include <cuda_fp16.h>

__half x;
```

host 侧准备数据时，可以先从 `float` 生成，再转换成 `__half`：

```cpp
float v = std::sin(i) * 0.01f;
__half h = __float2half(v);
```

建议输入范围先保持小一点，例如：

```text
[-0.01, 0.01]
```

这样做的目的不是模拟所有真实模型分布，而是先降低溢出、舍入误差和 reference 对拍难度。Day 4 的目标仍然是跑通 HGEMM baseline，而不是做完整数值分析。

> [!tip] reference 建议
> 可以用 FP32 reference 计算期望值，再用适合 FP16 的 tolerance 判断。不要用 `==`，也不要照搬 Day 1 的严格 FP32 阈值。

## 3. cublasHgemm 的位置

`cublasHgemm` 可以作为 Day 4 的最小入口。它适合先跑这种实验：

```text
FP16 input
FP16 output
```

它仍然是 GEMM 形式：

```text
C = alpha * op(A) * op(B) + beta * C
```

你可以先把它当成：

```text
SGEMM 的 half precision 版本
```

但要注意：这只是入门记法，不代表底层实现和 SGEMM 一样。到了 Day 5，需要进一步解释 cuBLAS 可能选择 Tensor Core 路径。

---

## 4. cublasGemmEx 的位置

`cublasGemmEx` 的价值在于显式指定：

- A / B 的数据类型。
- C 的数据类型。
- compute type。
- GEMM algorithm。

Day 4 至少要理解两类实验：

```text
FP16 input, FP16 output
FP16 input, FP32 accumulate, FP16 or FP32 output
```

也就是说，`GemmEx` 不只是另一个函数名，而是把原本隐含的类型选择写到调用参数里。

> [!tip] 什么时候更应该看 GemmEx
> 当你要比较 FP16 输入但 FP32 accumulate、或者要在报告里解释 input dtype / output dtype / compute type 的时候，`cublasGemmEx` 比裸写 `cublasHgemm` 更适合作为实验接口。

### 4.1 Hgemm 和 GemmEx 选择决策表

可以先按这个规则选择：

| 目标 | 推荐入口 | 原因 |
|---|---|---|
| 最小 FP16 baseline | `cublasHgemm` | API 更直接，适合先跑通 |
| 记录 input / output / compute type | `cublasGemmEx` | 类型控制更显式 |
| 比较 FP16 input + FP32 accumulate | `cublasGemmEx` | 能表达 mixed precision |
| 写作品集实验说明 | `cublasGemmEx` | 表格和 README 更容易讲清楚 |

Day 4 可以先让 `cublasHgemm` 跑通，再补一个 `GemmEx` 实验。不要一开始就把所有 dtype 组合铺开，否则容易把普通 cuBLAS baseline 做散。

---

## 5. 需要记录的 dtype 信息

Day 4 开始，benchmark 表不应该只写 `dtype = FP16`。更清楚的写法是：

```text
input_dtype
output_dtype
compute_type
api
```

最小表格可以这样扩展：

| M | N | K | API | input dtype | output dtype | compute type | ms | TFLOPS |
|---:|---:|---:|---|---|---|---|---:|---:|
| 1024 | 1024 | 1024 | cublasHgemm | FP16 | FP16 | implicit |  |  |
| 1024 | 1024 | 1024 | cublasGemmEx | FP16 | FP16 | FP32 accumulate |  |  |

README 里至少要写清楚：

```text
SGEMM is FP32 GEMM.
HGEMM is FP16 GEMM.
For GemmEx, we record input dtype, output dtype, and compute type explicitly.
```

### 5.1 FP16 correctness 注意事项

FP16 的对拍阈值通常要比 FP32 宽松。最低限度要记录：

```text
max_abs_error
max_relative_error
tolerance
reference dtype
```

一个入门阶段可接受的表达是：

```text
reference uses FP32 accumulation
HGEMM output is compared with relaxed FP16 tolerance
```

不要只写：

```text
correct = pass
```

而不说明 tolerance。因为 FP16 的舍入误差、累加路径和输出类型都会影响结果差异。

> [!warning] 阈值不是永久常量
> Day 4 可以先用宽松阈值跑通，但正式报告里要根据输入范围、K 大小、output dtype 和 reference 路径解释 tolerance。

---

## 6. 常见坑

- 只写 `FP16`，没有说明 input、output、accumulate 分别是什么类型。
- 把 `cublasHgemm` 和 `cublasGemmEx` 的结果混在同一行里比较。
- 没有重新做 correctness 对拍，只看 HGEMM 性能数字。
- FP16 reference 仍用过严的 FP32 阈值，导致误判失败。
- 没有记录 GPU、CUDA 和 cuBLAS 版本，后续解释 Tensor Core 路径时缺少背景。

> [!warning] 不要把 HGEMM 当成“只是 SGEMM 换了类型”
> FP16 GEMM 的性能路径、误差特征和解释方式都可能和 FP32 不一样。Day 4 的重点是把类型记录完整。

---

## 7. 当天验收标准

Day 4 结束时，至少要做到：

- [ ] 能跑 `cublasHgemm` 或 `cublasGemmEx`。
- [ ] 至少 3 个 shape 有 HGEMM benchmark。
- [ ] 每条结果记录 API、input dtype、output dtype、compute type。
- [ ] correctness 对拍使用适合 FP16 的 tolerance。
- [ ] 记录 reference dtype 和 tolerance。
- [ ] README 明确区分 SGEMM 和 HGEMM。

验收输出可以写成：

```text
HGEMM benchmark generated
api = cublasHgemm or cublasGemmEx
input_dtype = FP16
output_dtype = FP16 or FP32
compute_type = recorded
```

## 1. Day 6 要解决什么

目标可以压成一句话：

```text
让 README 解释清楚 cuBLAS baseline 是什么、怎么测、为什么这样比。
```

README 至少要回答：

- 使用了哪些 cuBLAS API？
- 项目矩阵 layout 是什么？
- cuBLAS column-major 差异怎么处理？
- timing 是否排除了 H2D / D2H？
- benchmark 表格记录了哪些字段？
- 为什么不要求学习型 kernel 打赢 cuBLAS？

> [!important] 第一层直觉
> README 不是事后装饰，而是实验可信度的一部分。没有实验规范的性能数字，很难变成作品集里的工程证据。

---

## 2. README 最小结构

建议 README 至少有这些小节：

```markdown
## cuBLAS Baseline

### APIs

### Layout

### Timing

### Benchmark Results

### Why not beating cuBLAS is OK
```

这几个块分别解决：

| 小节 | 解决的问题 |
|---|---|
| APIs | 到底用了 SGEMM、HGEMM 还是 GemmEx |
| Layout | row-major 项目如何调用 column-major cuBLAS |
| Timing | 性能数字的计时范围是否公平 |
| Benchmark Results | shape、dtype、ms、TFLOPS 和 ratio |
| Why not beating cuBLAS is OK | cuBLAS 是工业 baseline，不是失败判定器 |

### 2.1 README 检查清单

写完 README 后，可以直接按这个 checklist 检查：

- [ ] 说明 cuBLAS 是 vendor-optimized GEMM baseline。
- [ ] 写清楚使用了 `cublasSgemm`、`cublasHgemm` 或 `cublasGemmEx`。
- [ ] 说明项目矩阵是 row-major，cuBLAS 默认是 column-major。
- [ ] 说明 wrapper 为什么交换 A/B。
- [ ] 说明 timing 使用 CUDA event。
- [ ] 说明 H2D / D2H 不计入 GEMM 时间。
- [ ] benchmark 表包含 correctness、ms、TFLOPS 和 ratio。
- [ ] FP16 / GemmEx 结果记录 input dtype、output dtype 和 compute type。
- [ ] 解释 cuBLAS 可能使用 Tensor Core。
- [ ] 解释打不过 cuBLAS 不是失败。

这个 checklist 的意义是防止 README 只剩一张性能表，而没有实验协议和结果解释。

## 3. APIs 和 layout 怎么写

API 小节可以写：

```markdown
### APIs

- SGEMM: `cublasSgemm`
- HGEMM: `cublasHgemm` or `cublasGemmEx`
- For `GemmEx`, input dtype, output dtype, and compute type are recorded explicitly.
```

layout 小节可以写：

```markdown
### Layout

cuBLAS assumes column-major matrices.
Our project stores matrices in row-major layout.
For row-major `C[M,N] = A[M,K] @ B[K,N]`,
the wrapper calls cuBLAS with swapped A/B:

`C^T[N,M] = B^T[N,K] @ A^T[K,M]`
```

这段要和 [[3.6.2.2 cuBLAS Day 2 前置知识 - Layout Wrapper|Day 2 wrapper]] 保持一致。

---

## 4. timing 和 benchmark 怎么写

timing 小节可以写：

```markdown
### Timing

- warmup: 10 iterations
- repeat: 100 iterations
- timing: CUDA events
- data transfer excluded
- reported time: median or min
```

benchmark 表至少包含：

```text
M, N, K, dtype, layout, implementation, ms, TFLOPS, ratio_vs_cublas, correct
```

如果进入 HGEMM / GemmEx，建议增加：

```text
api, input_dtype, output_dtype, compute_type
```

> [!tip] 表格行要成对出现
> 同一个 shape 下，custom kernel 和 cuBLAS baseline 最好相邻出现。这样读者能直接看到 ratio，而不用在表里来回找。

### 4.1 表格模板升级版

SGEMM 表格可以先保持简洁：

| M | N | K | dtype | layout | implementation | ms | TFLOPS | ratio vs cuBLAS | correct |
|---:|---:|---:|---|---|---|---:|---:|---:|---|
| 1024 | 1024 | 1024 | FP32 | row-major wrapper | tiled CUDA |  |  |  | pass |
| 1024 | 1024 | 1024 | FP32 | row-major wrapper | cuBLAS SGEMM |  |  | 1.00 | pass |

HGEMM / GemmEx 表格要把类型说清楚：

| M | N | K | API | input dtype | output dtype | compute type | ms | TFLOPS | correct |
|---:|---:|---:|---|---|---|---|---:|---:|---|
| 1024 | 1024 | 1024 | cublasHgemm | FP16 | FP16 | implicit |  |  | pass |
| 1024 | 1024 | 1024 | cublasGemmEx | FP16 | FP16 | FP32 accumulate |  |  | pass |

如果一张表太宽，可以把 SGEMM 和 HGEMM 分成两个表。不要为了省列，把 `compute type` 省略成一个模糊的 `dtype=FP16`。

## 5. 为什么打不过 cuBLAS 不是失败

README 可以直接写：

```text
cuBLAS is a vendor-optimized GEMM baseline.
The goal is to measure the gap and explain where it comes from,
not necessarily to outperform cuBLAS.
```

中文报告可以写：

```text
cuBLAS 是工业级 GEMM baseline，不是必须战胜的目标。
本项目用 cuBLAS 校准同一 GPU、同一 dtype、同一 shape 下的参考性能。
手写 CUDA / Triton / CUTLASS 版本的价值在于解释性能差距来自哪里：
数据复用、访存合并、Tensor Core 路径、寄存器压力、occupancy 和边界处理。
```

这段要表达的是：

```text
我不是不知道自己慢。
我知道 baseline 很强，并且能解释为什么慢、下一步优化什么。
```

### 5.1 作品集表达模板

英文版可以写：

```text
cuBLAS is used as the vendor-optimized GEMM baseline.
The goal of this project is not to outperform cuBLAS, but to quantify the gap
and explain it in terms of memory reuse, tiling, scheduling, register pressure,
and possible Tensor Core paths for mixed-precision GEMM.
```

中文版可以写：

```text
本项目使用 cuBLAS 作为工业级 GEMM baseline。
目标不是证明手写 kernel 一定能超过 cuBLAS，而是用同一 GPU、同一 shape、
同一 dtype 下的参考结果，量化差距并解释差距来自数据复用、tiling、
调度、寄存器压力以及混合精度场景下可能的 Tensor Core 路径。
```

更短的 README 版本可以写：

```text
cuBLAS is the baseline, not the target to beat.
The learning value is in explaining the gap.
```

## 6. 常见坑

- README 只贴表格，没有说明 timing 范围。
- 没有说明 row-major wrapper，读者看不懂为什么 cuBLAS 参数是 `N, M, K`。
- FP32 和 FP16 结果混在一起，没有标明 dtype 和 compute type。
- 只写“cuBLAS 很快”，没有说明 Tensor Core 可能参与。
- 把“打不过 cuBLAS”写成缺点，而不是写成学习型 kernel 的合理 baseline 差距。

## 7. 当天验收标准

Day 6 结束时，README 至少要包含：

- [ ] cuBLAS baseline 定位。
- [ ] SGEMM / HGEMM / GemmEx API 说明。
- [ ] row-major wrapper 解释。
- [ ] timing 规则。
- [ ] benchmark 表格。
- [ ] “打不过 cuBLAS 不是失败”的解释。
- [ ] Tensor Core 可能参与的边界说明。
- [ ] 作品集表达里能说明“差距来自哪里”和“下一步优化什么”。

验收输出可以写成：

```text
README explains cuBLAS baseline, layout wrapper, timing scope, benchmark fields, and performance gap.
```

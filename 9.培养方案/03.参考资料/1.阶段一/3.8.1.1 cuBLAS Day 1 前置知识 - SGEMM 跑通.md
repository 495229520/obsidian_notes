## 1. Day 1 要解决什么

Day 1 的目标可以压成一句话：

```text
用 cuBLAS 跑一个 FP32 GEMM，并和 reference 对拍正确。
```

这里的 GEMM 形式是：

```text
C = alpha * op(A) * op(B) + beta * C
```

入门阶段先固定：

- dtype：`float`
- API：`cublasSgemm`
- op：`CUBLAS_OP_N`
- alpha：`1.0f`
- beta：`0.0f`
- reference：CPU、PyTorch 或 NumPy 任意一种

> [!important] 第一层直觉
> Day 1 的价值不是跑出漂亮 TFLOPS，而是建立“这个 baseline 能编译、能运行、能对拍”的最低可信度。

---

## 2. 最小调用链

最小 cuBLAS 程序绕不开三个动作：

```cpp
cublasHandle_t handle;
cublasCreate(&handle);

cublasSgemm(
    handle,
    CUBLAS_OP_N, CUBLAS_OP_N,
    m, n, k,
    &alpha,
    A, lda,
    B, ldb,
    &beta,
    C, ldc
);

cublasDestroy(handle);
```

这段代码先记成：

```text
handle 表示 cuBLAS 上下文
cublasSgemm 表示 FP32 GEMM
cublasDestroy 负责释放 cuBLAS 上下文
```

如果项目使用 CMake，链接时至少要确认链接了 cuBLAS：

```cmake
target_link_libraries(your_target PRIVATE cublas)
```

如果直接用 `nvcc` 测试，形状通常是：

```powershell
nvcc bench_sgemm.cu -lcublas -o bench_sgemm.exe
```

### 2.1 最小数据流

真正写 `bench_sgemm.cu` 时，不是只有一行 `cublasSgemm`。最小数据流可以先记成：

```text
host 初始化 A/B/C
cudaMalloc 分配 d_A / d_B / d_C
cudaMemcpy 把 A/B/C 从 host 拷到 device
cublasSgemm 在 device 上计算
cudaMemcpy 把 C 从 device 拷回 host
CPU / PyTorch / NumPy reference 对拍
cudaFree 释放 device memory
cublasDestroy 释放 handle
```

这条链路的重点是：Day 1 的 timing 可以先粗糙一点，但 correctness 必须覆盖完整数据流。否则你可能只验证了 API 能调用，却没有验证 device 结果真的被正确拷回并对拍。

> [!tip] Day 1 的最低代码意识
> `cublasSgemm` 接收的是 device pointer。`A / B / C` 如果还是 host pointer，程序不是慢一点的问题，而是调用语义就错了。

## 3. SGEMM 参数怎么读

`cublasSgemm` 最容易混的是 `m / n / k` 和 `lda / ldb / ldc`。

先按 cuBLAS 自己的数学视角理解：

| 参数 | 含义 |
|---|---|
| `m` | `op(A)` 和 `C` 的行数 |
| `n` | `op(B)` 和 `C` 的列数 |
| `k` | `op(A)` 的列数，也是 `op(B)` 的行数 |
| `lda` | A 在内存中的 leading dimension |
| `ldb` | B 在内存中的 leading dimension |
| `ldc` | C 在内存中的 leading dimension |

入门阶段先不要把 `lda` 理解成“随便填一个 stride”。它描述的是 cuBLAS 按 column-major 解释矩阵时，两列之间在内存中相隔多少元素。

> [!warning] Day 1 先少做一件事
> 如果你还没完全理解 row-major wrapper，可以先用一个和 cuBLAS column-major 语义一致的小例子跑通 API。Day 2 再专门处理 C/C++ row-major 项目里的参数交换。

### 3.1 极小 column-major sanity case

Day 1 可以先用一个极小矩阵按 cuBLAS column-major 语义跑通，不急着处理 row-major wrapper。例如：

```text
A = 2 x 2
B = 2 x 2
C = A @ B
alpha = 1
beta = 0
```

如果按 column-major 存储，一个矩阵：

```text
[ 1  2
  3  4 ]
```

在一维数组里是：

```cpp
std::vector<float> A = {
    1.0f, 3.0f,
    2.0f, 4.0f
};
```

也就是先放第一列，再放第二列。这个小例子的作用不是训练 layout wrapper，而是确认：

- `cublasCreate` 能成功。
- device memory 分配和拷贝没问题。
- `cublasSgemm` 参数在 cuBLAS 自己的语义下能跑通。
- D2H 拷回后能和 reference 对上。

等这个 sanity case 稳了，再进入 [[3.8.1.2 cuBLAS Day 2 前置知识 - Layout Wrapper|Day 2]] 处理 C/C++ row-major 项目里更自然的写法。

## 4. correctness 对拍

cuBLAS 跑完以后，必须和 reference 对拍。最低要求不是打印几个元素，而是输出误差指标：

```cpp
float max_abs_error(const std::vector<float>& actual,
                    const std::vector<float>& expected) {
    float max_err = 0.0f;
    for (size_t i = 0; i < actual.size(); ++i) {
        max_err = std::max(max_err, std::abs(actual[i] - expected[i]));
    }
    return max_err;
}
```

建议输入不要全是 `1.0f`：

```cpp
A[i] = std::sin(i) * 0.01f;
B[i] = std::cos(i) * 0.01f;
```

Day 1 可以先用比较保守的 FP32 阈值：

```text
atol = 1e-4
rtol = 1e-4
```

实际项目里阈值要结合输入范围、shape 和 reference 路径调整，不要永久照抄。

## 5. 常见坑

- 忘记链接 `cublas`，导致编译或链接失败。
- `cublasCreate` 成功后没有在退出前 `cublasDestroy`。
- 把 `m / n / k` 当成 row-major 项目里的 `M / N / K` 机械照搬。
- `lda / ldb / ldc` 随手填，结果小 shape 看似能跑，大 shape 或非方阵出错。
- 没有检查 `cublasStatus_t`，API 失败后继续读错误结果。
- 只看性能数字，不做 correctness 对拍。

建议把 CUDA Runtime 和 cuBLAS 调用都加上最小检查宏：

```cpp
#define CHECK_CUDA(call)                                        \
    do {                                                        \
        cudaError_t err = (call);                               \
        if (err != cudaSuccess) {                               \
            std::cerr << "CUDA error: "                         \
                      << cudaGetErrorString(err) << "\n";       \
            std::exit(1);                                       \
        }                                                       \
    } while (0)
```

```cpp
#define CHECK_CUBLAS(call)                                      \
    do {                                                        \
        cublasStatus_t status = (call);                         \
        if (status != CUBLAS_STATUS_SUCCESS) {                  \
            std::cerr << "cuBLAS error: " << status << "\n";    \
            std::exit(1);                                       \
        }                                                       \
    } while (0)
```

这样 `cudaMalloc`、`cudaMemcpy`、`cublasCreate` 和 `cublasSgemm` 都能在失败时立刻停下来，不会把错误结果带进 correctness 或 benchmark。

## 6. 当天验收标准

Day 1 结束时，至少能给出这样的输出：

```text
SGEMM result correct
shape = M x N x K
cuBLAS time = xxx ms
TFLOPS = xxx
max_abs_error = xxx
```

最小 checklist：

- [ ] `cublasCreate / cublasDestroy` 路径完整。
- [ ] `cublasSgemm` 能运行。
- [ ] FP32 输出和 reference 对拍通过。
- [ ] 记录 `M / N / K / dtype / time / TFLOPS`。
- [ ] 能解释 `m / n / k` 和 `lda / ldb / ldc` 的含义。

建议 Day 1 最小交付物：

- [ ] 一个最小 `bench_sgemm.cu`。
- [ ] 一条能复现的编译命令，例如 `nvcc bench_sgemm.cu -lcublas -o bench_sgemm.exe`。
- [ ] 一个极小 shape 的 correctness sanity case。
- [ ] 一个稍大 shape 的粗略 timing 记录。

这里的 timing 只要求能记录，不要求已经形成 Day 3 那种完整 benchmark 框架。

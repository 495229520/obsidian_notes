# NVMe-oF Subsystem 与 Namespace

> [[3.10 Namespace]] 在本地盘上建立了三层对象模型（Subsystem ⊃ Controller ⊃ Namespace），当时说 subsystem「本地感知不到」。上了网络它就成了主角：贯穿案例里 4 台存储节点共 64 块盘要切给 64 台 GPU 节点和好几个租户用，**切多大一块、以什么名义导出、谁有权看见**——这些设计决定全部落在 subsystem 与 namespace 这两个词上。本篇先把本地模型平移到 fabric 上（三个词各自变了什么、没变什么），再回答访问控制怎么做，最后算一笔切分粒度的账：subsystem 怎么切，直接决定集群的连接数、target 内存与尾延迟。

前置：[[3.10 Namespace]]（本地对象模型与 NGUID）、[[5.1 NVMe-oF 架构]]（NQN 与五个名词）、[[5.3 Host 与 Target]]（configfs 实操）。

---

## 1. 从本地到 fabric：三个词各自变了什么

先用大白话回收定义，再对照【事实】：

- **subsystem**：一个「存储实体」的壳子，由 NQN 全局命名。本地盘上一块 SSD 就是一个 subsystem，你从没需要跟它打交道；fabric 上它是 **host 连接的目标 + 权限挂靠点**——`nvme connect -n` 后面跟的就是它；
- **controller**：命令的受理者、队列的属主。本地是盘上固化的 PCIe function，数量出厂就定了；fabric 上是**每个 host 每次 connect 时动态创建的软件实例**，host 断开就销毁；
- **namespace**：容量切分单元，带独立 LBA 空间与全局身份（NGUID/UUID）。**这个词在两边完全同义**——fabric 没有改动它一个字节的语义，target 只是把「本地的块设备或文件」包装成 namespace 挂进 subsystem。

| | 本地 NVMe | NVMe-oF |
| --- | --- | --- |
| subsystem | 就是那块盘，感知不到 | 导出单元 + ACL 挂靠点，NQN 是它的名字 |
| controller | PCIe function，静态，一两个 | 每 host 每连接动态创建一个（cntlid 标识） |
| namespace | 容量单元，NSID + NGUID | 同左，语义零改动 |
| 队列归属 | 属 controller，**所有使用者共享** | 属 controller，**每 host 独享自己那套** |

最后一行是平移中最有意思的变化【事实】：[[3.10 Namespace]] §3 说过「队列属于 controller，namespace 之间无性能隔离」。fabric 上这条事实没变，但「一 host 一 controller」让每台 host 天然拥有**独立的队列集**——host 之间在队列层互不挤压了。不过别高兴太早：所有 controller 的命令最终汇入 target 后端**同一块盘**的队列与 FTL，GC 噪声照样跨租户传播（[[3.5 GC 写放大与 Over-Provisioning]]）——**fabric 把隔离往前推进到队列层，但止步于盘**【事实/取舍】。

## 2. 导出模型全景：port、subsystem、namespace 三者正交

![[图片/SVG/8_5_17_1.svg|900]]

target 侧只有三类对象，职责严格正交【事实】：

| 对象 | 回答的问题 | configfs 位置 |
| --- | --- | --- |
| **port** | 从哪个地址、哪种 transport 进来 | `ports/` |
| **subsystem** | 以什么名义导出、允许谁连 | `subsystems/<NQN>/` |
| **namespace** | 具体是哪块容量、什么后端 | `subsystems/<NQN>/namespaces/<n>/` |

`ln -s` 把 subsystem 挂到 port 上才算「导出」；同一 subsystem 可以挂多个 port（多路径的来源，[[5.16 Discovery Controller]] §5），同一 port 也可以挂多个 subsystem。NQN 的命名格式顺手记一下【事实】：`nqn.<yyyy-mm>.<倒序域名>:<自定义串>`，如 `nqn.2026-07.io.lab:tenantA`——年月和域名共同保证全球唯一，冒号后面随便你编。

图里另外两个要点：

1. **NSID 是 subsystem 内编号**：tenantA 和 tenantB 各有一个 NSID=1，互不相干。跨 subsystem、跨路径、跨重启认盘，一律用 namespace 自带的 **NGUID/UUID**（`/dev/disk/by-id/`）——与 [[3.10 Namespace]] §2 同一条军规，fabric 上更容易踩，因为**不同 host 上的 `/dev/nvme1n1` 同名不同盘**是常态；
2. **controller 是查表后的产物**：host 发 Fabrics Connect，target 查过 `allowed_hosts` 才创建 controller 实例并分配 cntlid（[[5.18 Queue 建立过程]] 有命令级细节）；不在名单里，连 controller 都不会诞生。

## 3. 访问控制：一张名单、两道门、零加密

nvmet 的 ACL 模型简单到一句话【事实】：**subsystem 维护一张 `allowed_hosts` 名单，按 host 自报的 hostnqn 查表**。它体现在两道门上：

- **看见门**：discovery 目录按 host 身份过滤——不许你连的 subsystem，`nvme discover` 里根本不出现【实现】；
- **连接门**：Fabrics Connect 时正式查表，不在名单直接拒绝。

必须诚实标注这套模型的强度【事实/安全】：hostnqn 是 host **自报**的字符串（`/etc/nvme/hostnqn`，谁都能改），默认既无认证也无加密——它防的是**误操作**（挂错盘、脚本连错目标），不防**恶意**。协议层的补强是 DH-HMAC-CHAP 双向认证（内核已支持，可选开启）与 TLS（NVMe/TCP）【实现】；但工程实践里第一道真正的防线是**网络隔离**：存储平面走独立 VLAN/子网，不与业务网互通【实践】。三层配齐才算完整：网络隔离挡外人，allowed_hosts 挡自己人误操作，认证挡仿冒。

配置实操在 [[5.3 Host 与 Target]] §3 的基础上补上多租户（差异只有两处）：

```bash
cd /sys/kernel/config/nvmet

# 登记 host 身份（名单里的"人"）
mkdir hosts/nqn.2026-07.io.lab:hostA

# subsystem 侧：关掉 allow_any_host，软链接名单
echo 0 > subsystems/nqn.2026-07.io.lab:tenantA/attr_allow_any_host
ln -s /sys/kernel/config/nvmet/hosts/nqn.2026-07.io.lab:hostA \
      subsystems/nqn.2026-07.io.lab:tenantA/allowed_hosts/

# 验证两道门：hostB 上
nvme discover -t tcp -a 192.168.1.10 -s 8009    # 看不到 tenantA（看见门）
nvme connect  -t tcp -a 192.168.1.10 -s 4420 -n nqn.2026-07.io.lab:tenantA
# → connect 失败（连接门）；hostA 上同一命令成功
```

## 4. 切分粒度的账：subsystem 怎么切，决定连接数、内存与尾延迟

现在回到贯穿案例做设计题：一台存储节点 16 块盘，导出方案至少有三种。评价维度来自一条因果链【事实】：

**每 host 可见的 subsystem 数 × (1 + IO 队列数) = 每 host 连接数**（[[5.3 Host 与 Target]] §2 的连接账）→ 连接数决定 target 的**每连接内存**（TCP 的接收缓冲 + in-capsule 预留，RDMA 的每 QP RECV 缓冲）与**网卡 QP cache 压力**（[[4.1 RDMA 为什么快]] §5：QP 状态挤出网卡缓存 → 每笔 IO 多一次 PCIe 取状态 → 尾延迟上行）。

| 方案 | ACL/故障域 | 连接账（64 host × 8 IO 队列） | 判断 |
| --- | --- | --- | --- |
| **一节点一 subsystem**，16 盘全塞进去当 16 个 namespace | 整包授予：连上就看见 16 块盘；subsystem 级维护操作波及全部 | 64 × 1 × 9 = 576 条 | 内部集群、单一租户可用；多租户不可用 |
| **一租户一 subsystem**，各挂自己的卷 | 按租户隔离，故障域=租户 | 64 × ~4 × 9 ≈ 2300 条 | **常见折中**【实践】 |
| **一卷一 subsystem** | 最细，ACL 精确到卷 | 64 × 16 × 9 ≈ 9200 条 | 连接爆炸；除非编排层强需求 |

三条派生结论：

1. **粒度是乘法因子**：从方案一到方案三，连接数放大 16 倍，target 内存与 QP cache 压力同步放大——「ACL 想切多细」与「连接账付不付得起」是同一个决定的两面【取舍】；
2. **同 subsystem 内的卷共享该 host 的 controller 队列**：一个 namespace 上的写洪峰会挤压同 controller 其他 namespace 的 p99（本地 3.10 的老问题在每个 controller 内重演）——延迟敏感的卷值得单独一个 subsystem，给它独立队列【实践】；
3. **缓解手段在 host 侧**：`nvme connect --nr-io-queues=4` 收敛每 subsystem 的队列数，用队列数换连接数——代价与收益的细账在 [[5.18 Queue 建立过程]] §5。

## 5. 身份与多路径：NGUID 聚合与 ANA

同一 namespace 从两个 port 导出、host 两条路都连上时，host 端看到的是两个 controller 各报告一个 namespace——内核靠 **NGUID 相同**判定「这是同一块盘的两条路」，聚合成一个多路径设备【实现】。这也是为什么 namespace 的全局身份在 fabric 上升格为关键机制而不只是运维便利。

路径有了优劣之分后，target 用 **ANA**（Asymmetric Namespace Access）状态告诉 host 每条路的成色【事实】：optimized（优先走）、non-optimized（能走但绕，比如跨了存储节点内部互联）、inaccessible（这条路暂时到不了该 namespace）。host 的多路径策略据此选路；状态变化通过 AEN 推送——完整的切换行为见 [[5.5 Multipath 与故障切换]]。

## 6. 陷阱与误区

> [!warning] 常见错误
> 1. **`allow_any_host=1` 带上生产**：等于全网可写你的盘。实验环境的便利开关，上线前逐 subsystem 核对。
> 2. **把 allowed_hosts 当安全边界**：hostnqn 可自由仿冒；没有网络隔离和认证时，这张名单只防误操作。
> 3. **拿设备名当身份**：hostA 和 hostB 的 `/dev/nvme1n1` 是两块盘；同一 host 重连后编号也会变。挂载、fstab、脚本一律 `/dev/disk/by-id/`。
> 4. **ACL 放行两台 host 就当共享盘用**：namespace 是块设备，两台 host 同挂 ext4 = 文件系统损坏（[[5.1 NVMe-oF 架构]] §6 军规）。ACL 允许 ≠ 并发安全；多写者要集群文件系统或上层协调。
> 5. **切分只按逻辑美感、不算连接账**：每卷一 subsystem 在 16 host 的实验集群没问题，放大到 64 host 就是近万条连接——设计评审时把 §4 的乘法先做了。
> 6. **忘了隔离止于队列层**：subsystem 切得再细，盘内 FTL/GC 的噪声邻居问题原样存在；跨租户的 QoS 要靠分盘或上层限流（[[6.16 Rate Limiter 与后台任务隔离]]）。

## 7. 关键结论

| 结论 | 性质 |
| --- | --- |
| 本地模型平移到 fabric：subsystem 升格为导出与权限单位，controller 变为每 host 每连接动态创建，namespace 语义零改动 | 事实 |
| port/subsystem/namespace 三者正交：地址、权限、容量各管一摊，`ln -s` 到 port 才算导出 | 事实 |
| 一 host 一 controller ⇒ 队列层按 host 天然隔离；但所有 controller 汇入同一块盘——隔离止于队列层，FTL/GC 噪声照传 | 事实 / 取舍 |
| ACL = 按自报 hostnqn 查 allowed_hosts，作用于「看见」与「连接」两道门；防误操作不防恶意，安全靠网络隔离 + 认证补齐 | 事实 / 实践 |
| NSID 是 subsystem 内编号；跨 host/路径/重启认 NGUID——不同 host 的同名设备是不同的盘 | 事实 |
| 连接数 ≈ host 数 × 可见 subsystem 数 × (1 + IO 队列数)：切分粒度通过这个乘法作用于 target 内存、QP cache 与尾延迟 | 量级 / 取舍 |
| 一租户一 subsystem 是 ACL 粒度与连接账之间的常见折中；延迟敏感卷可独占 subsystem 换独立队列 | 实践结论 |
| NGUID 是多路径聚合的判据；ANA 状态标注每条路径的成色 | 事实 |

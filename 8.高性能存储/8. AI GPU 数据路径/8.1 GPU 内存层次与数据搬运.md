# GPU 内存层次与数据搬运

> 第 8 章回到本专题的第一性问题（[[00. 总纲]]）：**GPU 是集群里最贵的部件，数据供不上它就在空转烧钱**。前七章把数据从盘搬到了主机内存；最后一公里——主机内存到显存——有自己的层次、自己的总线、自己的坑。本篇建立第 8 章的坐标系：GPU 的内存层次各有多快、`cudaMemcpy` 底下到底发生了什么、一个 batch 从盘到显存的传统路径要过几次内存总线——数出这笔账，后面每一篇（GDS、bounce buffer、KV Cache offload）都是对这笔账的某一项动刀。好消息是：这里没有新机制，**pinned memory 就是 [[4.4 内存注册与零拷贝]] 的内存注册，拓扑账就是 [[3.8 PCIe 拓扑与 NUMA]] 的账**——同一套 OS 知识，第三次收租。

前置：[[3.8 PCIe 拓扑与 NUMA]]（PCIe 交换网络与带宽账）、[[4.4 内存注册与零拷贝]]（pin 页 + 地址下发给设备——本篇的 pinned 同源）、[[1.2 Page Cache 命中与未命中]]（传统读路径的上半段）。

## 1. 层次表：每下一层慢一个量级

![GPU 内存层次与两条搬运路径：左侧为带宽阶梯——片上 SRAM、HBM 显存 TB/s 级、NVLink 数百 GB/s、PCIe x16 几十 GB/s、主机 DRAM 百 GB/s 级、NVMe 与网络 GB/s 到几十 GB/s，标注 PCIe 是显存的唯一入口瓶颈；右侧上半为 pageable 与 pinned 两条 H2D 拷贝路径对比（pageable 多一次 CPU 拷贝进驱动暂存区，pinned 直接 DMA），右侧下半为一个 batch 从盘到显存的传统路径拷贝对账（盘 DMA 进页缓存、CPU 拷到用户缓冲、CPU 拷到 pinned 暂存、DMA 过 PCIe 进显存，内存总线合计穿越 5 次）](../../图片/SVG/gpu-内存层次与搬运路径.svg)

| 层 | 带宽量级【量级】 | 备注 |
| --- | --- | --- |
| 片上 SRAM（寄存器/shared memory） | ~10 TB/s 级 | SM 内部，容量 MB 级 |
| **HBM 显存** | **数 TB/s** | GPU 的「主存」，容量几十 GB |
| NVLink（GPU↔GPU） | 数百 GB/s | 仅同机 GPU 间；不通盘 |
| **PCIe x16**（GPU↔主机） | Gen4 ~32 GB/s、Gen5 ~64 GB/s（理论） | **显存与外界的唯一入口** |
| 主机 DRAM | 一二百 GB/s（每 socket） | 所有中转都消耗它 |
| 本地 NVMe | 单盘几 GB/s，盘阵几十 GB/s | [[3.7 nvme-cli 实操]] 的供给端 |
| 数据中心网络 | 25~400 Gb/s ≈ 3~50 GB/s | NVMe-oF / 对象存储入口 |

两个结构性结论直接从表里掉出来【事实】：

1. **HBM 比 PCIe 快约两个数量级**——显存内的数据随便用，跨 PCIe 的数据要精打细算；「把数据留在显存里」是第 8 章一半议题（KV Cache、重叠预取）的动机；
2. **PCIe 是入口瓶颈**：盘阵供得出 100 GB/s（[[3.7 nvme-cli 实操]] 的 16 盘节点），但每张 GPU 的入口只有 ~32/64 GB/s——**供给要按「每 GPU 的 PCIe 入口」规划，不是按集群总带宽**。

## 2. `cudaMemcpy` 底下：pageable 与 pinned 的分水岭

CUDA 的 H2D（host-to-device）拷贝有两条完全不同的路径【事实】：

- **pageable 内存**（`malloc`/`new` 出来的普通内存）：GPU 的 DMA 引擎**不能直接读它**——页可能被内核换出或迁移，物理地址不稳定。于是驱动先用 CPU 把数据**拷进自己内部的 pinned 暂存区**，再从暂存区 DMA 进显存：**每字节多一次 CPU 拷贝 + 一次内存总线往返**，带宽常只有直连的一半上下，且吃 CPU；
- **pinned 内存**（`cudaMallocHost`/`cudaHostRegister`，page-locked）：页被钉死、物理地址固定并登记给设备，DMA 引擎直接读，**一次 DMA 拉满 PCIe**。

这就是 [[4.4 内存注册与零拷贝]] 的机制原样重演【事实】：RDMA 的 MR 注册与 CUDA 的 pinned 是**同一个 OS 机制（pin 页 + 把物理页表交给设备）的两个客户**，代价也相同——注册本身毫秒级、pinned 内存不可换出、要池化复用而不是临时申请（[[4.4 内存注册与零拷贝]] 的军规全部适用）。

第二条分水岭【事实】：**`cudaMemcpyAsync` 只有配 pinned 才真异步**。pageable 路径里驱动要用 CPU 做暂存拷贝，「异步」调用实际同步执行——想用 CUDA stream 重叠「搬运下一个 batch」与「计算当前 batch」，pinned 是入场券，不是优化。

## 3. 端到端对账:一个 batch 从盘到显存的传统路径

buffered 读 + pageable 内存的朴素训练数据路径,逐步数内存总线【事实】(计数方法与 [[4.1 RDMA 为什么快]] §2 同一口径)：

| 步 | 动作 | 内存总线穿越 |
| --- | --- | --- |
| ① | 盘 DMA → 页缓存（[[1.2 Page Cache 命中与未命中]]） | 1 |
| ② | `read()`：CPU 拷 页缓存 → 用户 buffer | 2（读 + 写） |
| ③ | 驱动：CPU 拷 用户 buffer → pinned 暂存区 | 2 |
| ④ | DMA：暂存区 → PCIe → 显存 | 1 |

**合计：内存总线 6 次穿越、CPU 拷贝 2 次，才换来 1 次 PCIe 穿越**。10 GB/s 的喂卡流量在主机内存总线上是 60 GB/s，还占着几个核搬字节。第 8 章后面每一篇都是在删这张表的某一行：O_DIRECT 删②（[[1.3 Buffered IO 与 O_DIRECT]]）、pinned 用户缓冲删③（[[8.3 Bounce Buffer vs 直读]]）、GDS 把①~④合并成「盘 DMA 直写显存」（[[8.2 GDS 与 cuFile]]）。

## 4. 拓扑：P2P 的前提是「同一个 Switch」

[[3.8 PCIe 拓扑与 NUMA]] 的账在 GPU 服务器上有专用读法。**可复现命令**：

```bash
nvidia-smi topo -m        # GPU/NIC/NVMe 两两之间的拓扑关系矩阵
```

输出矩阵里的字母是关键【实现】：

| 标记 | 含义 | 对数据路径的意义 |
| --- | --- | --- |
| PIX | 同一个 PCIe Switch 下 | **P2P DMA 最优**：设备互传不过根复合体、不过主存 |
| PXB | 跨多个 Switch（不过 CPU） | P2P 可行，多一跳 |
| PHB | 经过 CPU 的根复合体 | P2P 流量挤占根端口，带宽下降 |
| NODE / SYS | 同/跨 NUMA 节点，走 CPU 互联 | **SYS = 跨 socket 互联**：P2P 带宽腰斩甚至不可用，GDS 收益消失 |

这解释了 GPU 服务器的机内摆位【事实】：NVMe 与 NIC 刻意与 GPU 挂在同一个 Switch 下（[[3.8 PCIe 拓扑与 NUMA]] §5 已埋此伏笔）——GDS/GPUDirect RDMA 的「直达」物理上就是**同 Switch 的 P2P DMA**。买同样的卡、插错槽位，第 8 章的一切收益直接蒸发【实践】。

## 5. 可复现实验：把自己机器的量级量出来

```bash
# ① 官方基准：pageable vs pinned 的 H2D/D2H 带宽（CUDA samples）
./bandwidthTest --memory=pageable && ./bandwidthTest --memory=pinned

# ② 链路协商核对：GPU 实际跑在 Gen 几 × 几条 lane（3.8 §3 同款）
nvidia-smi -q | grep -A 3 "GPU Link"      # 或 lspci -vv 看 LnkSta

# ③ 拓扑矩阵：确认 GPU 与 NVMe/NIC 的关系（§4 的字母表）
nvidia-smi topo -m
```

**指标读法与常见误读**【实践】：

- pinned H2D 实测 ~25–28 GB/s（Gen4 x16）就是健康值——理论 32 GB/s 含协议开销，**拿理论值当预期会误判 15% 的「丢失」**；
- pageable 只有一半上下**是设计不是故障**——修法是换 pinned，不是调系统；
- 实测远低于预期先查两件事：`LnkSta` 降速降宽（插槽/散热问题，[[3.8 PCIe 拓扑与 NUMA]] §3）、拓扑里目标对是 SYS（跨 socket）。

## 6. Modern C++：RAII 管理两种内存，量出分水岭

```cpp
#include <cuda_runtime.h>

#include <chrono>
#include <cstddef>
#include <memory>
#include <print>
#include <system_error>
#include <vector>

static void ck(cudaError_t e, const char* what) {
    if (e != cudaSuccess)
        throw std::runtime_error(std::string{what} + ": " + cudaGetErrorString(e));
}

// RAII：pinned 主机内存（cudaMallocHost / cudaFreeHost 配对）
class PinnedBuffer {
public:
    explicit PinnedBuffer(std::size_t n) : size_{n} {
        ck(cudaMallocHost(&p_, n), "cudaMallocHost");   // pin 页 + 登记给设备（≈ 4.4 的 MR）
    }
    ~PinnedBuffer() { cudaFreeHost(p_); }
    PinnedBuffer(const PinnedBuffer&) = delete;
    PinnedBuffer& operator=(const PinnedBuffer&) = delete;
    [[nodiscard]] void* data() const { return p_; }
    [[nodiscard]] std::size_t size() const { return size_; }
private:
    void* p_ = nullptr;
    std::size_t size_;
};

struct DevDeleter { void operator()(void* p) const { cudaFree(p); } };
using DevBuffer = std::unique_ptr<void, DevDeleter>;    // RAII：显存

double h2d_gbps(const void* src, void* dst, std::size_t n) {
    const auto t0 = std::chrono::steady_clock::now();
    ck(cudaMemcpy(dst, src, n, cudaMemcpyHostToDevice), "memcpy H2D");
    const std::chrono::duration<double> dt = std::chrono::steady_clock::now() - t0;
    return static_cast<double>(n) / dt.count() / 1e9;
}

int main() {
    constexpr std::size_t N = 1ull << 30;               // 1 GiB：大到摊薄启动开销
    void* draw = nullptr;
    ck(cudaMalloc(&draw, N), "cudaMalloc");
    DevBuffer dev{draw};

    std::vector<std::byte> pageable(N);                 // 普通内存：走驱动暂存区
    PinnedBuffer pinned{N};                             // 钉住：直接 DMA

    std::println("pageable H2D: {:.1f} GB/s", h2d_gbps(pageable.data(), dev.get(), N));
    std::println("pinned   H2D: {:.1f} GB/s", h2d_gbps(pinned.data(),  dev.get(), N));
    // 预期（Gen4 x16 量级）：pageable ~10±几 GB/s 且烧 CPU；pinned ~25-28 GB/s
}
```

**关键点**：

- 两次测量之间唯一变量是「内存是否 pinned」——差值就是 §2 那次驱动暂存拷贝的价格；
- pinned 分配毫秒级且不可换出：生产代码**池化复用**，禁止在数据路径上临时 `cudaMallocHost`（与 [[4.4 内存注册与零拷贝]] 的 MR 池同一军规）；
- 想看「真异步」的差别，把 `cudaMemcpy` 换成 `cudaMemcpyAsync` + stream，pageable 版本的「异步」调用会同步阻塞——一行实验戳破一个常见误解。

## 7. 陷阱与误区

> [!warning] 常见错误
> 1. **拿 PCIe 理论带宽当预期**：Gen4 x16 实测 ~25–28 GB/s 是健康的；先扣协议开销再谈「变慢」。
> 2. **pageable 内存 + `cudaMemcpyAsync` 以为在重叠**：pageable 路径根本不异步；pinned 是重叠计算与搬运的入场券。
> 3. **数据路径上临时分配 pinned**：pin 页毫秒级且全程占物理内存——预分配 + 池化，泄漏的 pinned 比泄漏堆内存更疼（不可换出、拖慢整机回收）。
> 4. **按集群总带宽规划喂卡**：入口是每张 GPU 的 PCIe x16；盘阵再快，过不了这个口。
> 5. **忽略拓扑就上多卡**：GPU 与 NVMe/NIC 落在 SYS 关系（跨 socket）时，P2P/GDS 的前提不成立——买对卡还要插对槽。
> 6. **CPU 拷贝「免费」的错觉**：§3 的账——喂卡 10 GB/s 在主存总线上是 60 GB/s；主存带宽被搬运吃掉后，DataLoader 的 CPU 预处理跟着慢（[[8.7 DataLoader 与 GPU 空闲归因]] 的常见根因）。

## 8. 关键结论

| 结论 | 性质 |
| --- | --- |
| 层次表：HBM 数 TB/s ≫ PCIe 几十 GB/s ≫ NVMe/网络——PCIe x16 是每张 GPU 的数据入口瓶颈 | 量级 / 事实 |
| pageable 拷贝 = CPU 先搬进驱动暂存再 DMA（多一次拷贝、半速、吃核）；pinned = 直接 DMA 拉满 | 事实 |
| pinned 与 RDMA MR 是同一 OS 机制（pin 页 + 页表交给设备）；毫秒级注册、不可换出、必须池化 | 事实 / 实践 |
| `cudaMemcpyAsync` 仅配 pinned 才真异步——流水线重叠的前提条件 | 事实 |
| 传统盘→显存路径：内存总线 6 穿越 + CPU 拷贝 2 次换 1 次 PCIe——第 8 章逐篇删这张表 | 事实 / 伏笔 |
| P2P/GDS 的物理前提是拓扑：`nvidia-smi topo -m` 里 PIX 最优、SYS 即收益蒸发 | 事实 / 实践 |
| 实测口径：Gen4 x16 pinned ~25–28 GB/s 为健康；异常先查 LnkSta 协商与拓扑，pageable 慢是设计 | 量级 / 实践 |

# Signaled / Unsignaled WR

> [[4.3 QP WQE CQ 状态机]] §5 用一段话带过了 signaled/unsignaled，本篇把它展开成一套完整的记账纪律：**CQE 不只是"完成通知"，它同时是 SQ 槽位与发送 buffer 的回收凭证——unsignaled 省掉的是通知，凭证也一起没了，所以它占的资源要等它后面第一个 signaled CQE 被收割才批量归还**。高 IOPS 路径上，每条消息一个 CQE 意味着网卡每条消息多一次 DMA 写、CPU 每条消息多一次收割；把这笔账除以 N，是小消息场景省 CPU 的第一刀（第二刀省的是每次提交的固定成本，在 [[4.16 Inline Batching 与 Doorbell 优化]]）。代价不是免费的：账本从"硬件替你记"变成"自己记"。

前置：[[4.3 QP WQE CQ 状态机]]（WQE 的一生、CQE 收割与 buffer 所有权移交——本篇直接使用）、[[4.2 Verbs 编程模型]]（WR/WQE/CQE 术语的出处）。

## 1. 先把名词说直白

三个缩写先对齐（详细定义在 [[4.2 Verbs 编程模型]]）：

| 术语 | 是什么 | 直白说法 |
| --- | --- | --- |
| WR（Work Request） | 你在软件里填的一张"操作申请表" | 我要发这段内存，发完叫我 |
| WQE（Work Queue Entry） | WR 被写进发送队列（SQ）后的表项 | 排进队里的那张表 |
| CQE（Completion Queue Entry） | 网卡写进完成队列（CQ）的回执 | "第 k 张表办完了"的凭条 |

**signaled 位【事实】**：`ibv_send_wr.send_flags` 里的 `IBV_SEND_SIGNALED`。带上它，这条 WR 完成后网卡写一条 CQE（signaled）；不带，完成后什么都不写（unsignaled）。两个开关配合使用：

- **QP 级默认**：创建 QP 时 `ibv_qp_init_attr.sq_sig_all = 1` 表示"发送侧每条 WR 都产生 CQE"；`= 0` 表示"默认都不产生，只有显式带 `IBV_SEND_SIGNALED` 的才产生"。高性能路径一律用 `sq_sig_all = 0` + 逐条控制；
- **作用范围**：这套机制**只存在于发送侧（SQ）**。接收侧每个 Recv WQE 被消费时必然产生 CQE——没有"unsignaled recv"这回事【事实】，因为接收完成是软件知道"数据到了"的唯一途径。

一个类比：给每个快递都发签收短信，和每 16 个快递发一条"第 16 件已签收"。中间 15 件送没送到，靠第 16 件的确认**间接推断**——这个推断之所以成立，是因为 RC 保证按序交付（§3）。

## 2. 为什么要省 CQE：一条消息的完成成本

**【事实】** 每条 signaled WR 的完成路径要付三笔钱：

1. **网卡侧**：往 CQ 环 DMA 写一条 CQE（几十字节的 PCIe 写）；
2. **内存侧**：这条 CQE 把 CQ 所在 cache line 弄脏，收割核下次读必然 cache miss（[[0.1 CPU Cache Cache Line 与内存屏障]]）；
3. **CPU 侧**：`ibv_poll_cq` 读出、判断 status、按 `wr_id` 对号处理。

单条是百 ns 量级的小钱【量级】，但小消息场景按每秒几百万条算：4 Mpps 就是每秒 400 万次 CQE 生成 + 收割，足以吃掉收割核的大头。每 N 条才写一条 CQE，这笔账直接除以 N。

两个必须先说清的边界【事实】：

- **unsignaled 不让任何一条消息变快**——数据上线的路径一个字节都没变。省的是本端 CPU 时间与 PCIe 上的 CQE 写流量，受益指标是**消息率（Mpps）与 CPU 占用**，不是单条 RTT。瓶颈在网络或对端时，调它没用（§6 排障清单最后一行）；
- **完成本身照常发生**——网卡照样发包、收 ACK、按序推进，只是不告诉你。所以"什么时候能复用 buffer、什么时候能再 post"这本账，硬件不再替你记。

**【类比】** io_uring 有同一个思想的开关：`IOSQE_CQE_SKIP_SUCCESS`——成功就不写 CQE，失败仍然写（[[2.1 SQ CQ 模型]]）。两边的设计者做了同一个判断：成功是常态、可以批量确认；失败是例外、必须逐条上报（§3 的 R4 正是这条）。

## 3. 回收规则：三帧快照

![[图片/SVG/8_4_15_1.svg|900]]

四条规则，前两条是机制、后两条是边界：

- **R1（回收粒度）【事实】**：unsignaled WQE 占用的 SQ 槽位与它锁住的发送 buffer，在**它后面第一个 signaled WQE 的 CQE 被收割之后**才允许复用。注意是"被 `poll_cq` 收割"，不是"CQE 已写进 CQ"——软件没读到凭证，就不能动账；
- **R2（推断依据）【事实】**：R1 成立的前提是 RC 的完成按提交序返回（[[4.13 RDMA 操作顺序性]]）。收到 `wr_id = k` 的 CQE，等于拿到"k 以及 k 之前所有 WQE 都已完成"的证明——unsignaled 搭 signaled 的车出账；
- **R3（泄漏底线）【事实】**：全部 unsignaled 意味着永远没有凭证，槽位只进不出，攒满 SQ 后 `ibv_post_send` 返回 ENOMEM；如果你还在等 completion channel 事件，那就是永久卡死（没有 CQE 可触发事件，[[4.3 QP WQE CQ 状态机]] §4）；
- **R4（错误例外）【事实】**：完成出错的 WR **无论是否 signaled 都会写一条错误 CQE**，其后的在途 WQE 以 `IBV_WC_WR_FLUSH_ERR` 冲出（[[4.3 QP WQE CQ 状态机]] §6）。所以 unsignaled 不会吞掉错误——它只对成功沉默。

## 4. 节奏怎么定：signaled 间隔 N 的交易

**【取舍】** N 每调大一档，买到的和付出的：

| | N 小（极端 N=1，全 signaled） | N 大 |
| --- | --- | --- |
| CQE 生成/收割成本 | 每条都付 | ÷ N |
| 槽位与 buffer 占用峰值 | 最低（逐条回收） | 至少 N 条起批，峰值 ↑ |
| buffer 解锁延迟 | 一条完成就解锁 | 最长多等 N-1 条的完成时间 |
| 停止发送时 | 账自动清零 | 最后不足一批的资源**永远锁着**，必须补一条 signaled 冲账 |

收益是 1/N 曲线，递减得很快【量级】：N 从 1 → 16 已经省掉约 94% 的 CQE 开销，16 → 256 只再省不到 6%。**没有理由为很大的 N 去冒占用与延迟的风险**——取一个远小于 SQ 深度的适中值，然后把注意力移到下一刀（[[4.16 Inline Batching 与 Doorbell 优化]]）。

硬边界三条【事实/实践】：

1. **N 必须严格小于 SQ 深度**，且要保证"SQ 满之前一定有 signaled CQE 可收"——否则回到 R3 的死局；
2. **CQ 深度按在途 signaled 数配**，不是按在途 WR 数：同一 CQ 上所有 QP 的在途 signaled 总和不能超过 CQ 容量（溢出是连接级错误，[[4.3 QP WQE CQ 状态机]] §5）。unsignaled 的一个隐性红利：CQ 需要的深度也 ÷ N；
3. **对照实验现成有**：perftest 的 `-Q / --cq-mod` 就是这个 N。`ib_write_bw -s 8 --cq-mod 1` 与 `--cq-mod 16` 对比 Mpps 与 CPU 占用，一组数据把本篇结论钉死（[[4.9 ibv_perftest 基准实验]]）。

## 5. 实践模板（Modern C++）

把 `wr_id` 直接用作**单调递增序号**，回收就变成一次减法——收割到序号 k，说明 `[reaped, k]` 整批出账：

```cpp
#include <infiniband/verbs.h>

#include <array>
#include <cstdint>
#include <span>
#include <stdexcept>
#include <system_error>

// 发送侧记账：wr_id = 单调序号；每 every 条标一个 signaled。
// 两本账合一：in_flight = next_seq - reaped_seq，同时约束槽位与 buffer。
class SendRing {
public:
    SendRing(ibv_qp& qp, std::uint32_t sq_depth, std::uint32_t signal_every)
        : qp_{&qp}, depth_{sq_depth}, every_{signal_every} {
        if (every_ == 0 || every_ >= depth_)
            throw std::invalid_argument{"signal_every 必须在 [1, sq_depth) 内"};
    }

    std::uint64_t in_flight() const { return next_seq_ - reaped_seq_; }

    // 返回 false 表示 SQ 满：先去 reap 再重试，不要自旋 post（§3 R3）
    bool post(const ibv_sge& sge, ibv_wr_opcode op) {
        if (in_flight() >= depth_)
            return false;
        ibv_send_wr wr{};
        ibv_send_wr* bad = nullptr;
        wr.wr_id   = next_seq_;
        wr.sg_list = const_cast<ibv_sge*>(&sge);
        wr.num_sge = 1;
        wr.opcode  = op;
        const bool signaled = (next_seq_ % every_ == every_ - 1);
        wr.send_flags = signaled ? IBV_SEND_SIGNALED : 0;
        if (int rc = ibv_post_send(qp_, &wr, &bad); rc != 0)
            throw std::system_error{rc, std::system_category(), "ibv_post_send"};
        ++next_seq_;
        return true;
    }

    // 停止发送前必须调用：把尾部不足一批的 unsignaled 用一条 signaled 冲账（§4 边界）
    // 实现从略：post 一条零长度 SEND（或把最后一条改为 signaled）后 reap 到 in_flight()==0。

    // 收割一批；返回本轮释放的槽位数（含搭车的 unsignaled）
    std::uint64_t reap(ibv_cq& cq) {
        std::array<ibv_wc, 16> wc{};
        const int n = ibv_poll_cq(&cq, static_cast<int>(wc.size()), wc.data());
        if (n < 0)
            throw std::runtime_error{"ibv_poll_cq failed"};
        const std::uint64_t before = reaped_seq_;
        for (const ibv_wc& c : std::span{wc.data(), static_cast<std::size_t>(n)}) {
            if (c.status != IBV_WC_SUCCESS && c.status != IBV_WC_WR_FLUSH_ERR) {
                // 根因 CQE：错误 WR 无论是否 signaled 都会浮出（§3 R4），
                // 之后走 4.3 §6 / 4.19 的排水与重建流程
                throw std::runtime_error{ibv_wc_status_str(c.status)};
            }
            reaped_seq_ = c.wr_id + 1;   // RC 按序完成：一条 CQE 出一整批账（§3 R2）
        }
        return reaped_seq_ - before;
    }

private:
    ibv_qp* qp_;
    std::uint64_t next_seq_   = 0;   // 已 post 的下一个序号
    std::uint64_t reaped_seq_ = 0;   // 已证明完成的序号上界（不含）
    std::uint32_t depth_;
    std::uint32_t every_;
};
```

两个约定支撑了这段代码的简洁：`wr_id` 序号化（回收量 = 序号差，不需要额外容器）；buffer 解锁与槽位回收共用 `reaped_seq_` 这一个水位（序号 < `reaped_seq_` 的 buffer 可复用）。多线程下谁持有这本账、CQ 由谁收割，是 [[4.18 多线程下 QP 使用模型]] 的主题。

## 6. 排障清单：症状 → 原因 → 检查

| 症状 | 常见原因 | 检查动作 |
| --- | --- | --- |
| `ibv_post_send` 返回 ENOMEM，且 poll 一直返回 0 | 全 unsignaled 槽位泄漏；或 signaled CQE 没人收割 | 打印 in_flight 与 signaled 节奏；确认每 N 条确有一条 signaled 且收割循环在跑 |
| 等 completion channel 事件永久卡死 | 没有任何 signaled ⇒ 没有 CQE ⇒ 事件永不触发 | 至少周期性 signaled；再核对 [[4.3 QP WQE CQ 状态机]] §4 的"先武装再排空"顺序 |
| 对端偶发收到旧内容 / 半新半旧的数据 | unsignaled 的 buffer 在解锁前被复用改写，网卡 DMA 读到改了一半的内容 | buffer 解锁必须以"覆盖它的 signaled CQE 被收割"为准（§3 R1）；小消息可改 `IBV_SEND_INLINE` 让 post 返回即解锁（[[4.16 Inline Batching 与 Doorbell 优化]]） |
| 停止发送后资源迟迟不归还 | 尾部不足一批的 unsignaled 没有凭证 | 停发前补一条 signaled（零长度 SEND 亦可）并收割到 in_flight 为 0（§4） |
| 调了 N 但吞吐没变化 | 瓶颈不在 CQE 路径（在网线、对端或 PCIe） | `ib_write_bw --cq-mod 1` vs `--cq-mod N` 对照：看 Mpps 与 CPU 占用是否变化；都不变就去查别处（[[4.9 ibv_perftest 基准实验]]） |
| "没请求过 CQE"的 WR 冒出一条错误 CQE | 规范行为，不是 bug：出错必上报（§3 R4） | 按根因处理并走重建（[[4.3 QP WQE CQ 状态机]] §6、[[4.19 RDMA 故障恢复与连接重建]]），别当成收割逻辑错乱 |
| 批量回收后 `wr_id` 对不上号 | 把 CQE 的 `wr_id` 当"单个完成"处理，丢了搭车的那一批 | `wr_id = k` 代表 `[上次水位, k]` 整批；用序号水位而不是逐条匹配（§5） |

## 7. 陷阱与误区

> [!warning] 常见错误
> 1. **把 unsignaled 当"免费"**：完成仍然发生，账必须自己记。省掉的是通知成本，换来的是记账责任——poll 返回 0 从此不再意味着"没有在途"。
> 2. **全 unsignaled**：槽位慢性泄漏，ENOMEM 或永久卡死。任何时刻至少保有一个在途 signaled。
> 3. **post 返回就复用 buffer**：非 inline 的发送 buffer 在收到覆盖它的 CQE 前属于网卡（[[4.3 QP WQE CQ 状态机]] §3 的所有权移交）；unsignaled 只是把"收到 CQE"推迟到了下一个 signaled。
> 4. **以为接收侧也能省**：Recv 完成必有 CQE，`sq_sig_all` 与 `IBV_SEND_SIGNALED` 只管发送侧。
> 5. **为大 N 冒险**：收益 1/N 递减，N=16 已拿走绝大部分；继续加大只换来占用峰值与解锁延迟。
> 6. **忘了 CQ 深度也要配套**：好消息是 unsignaled 让 CQ 需求 ÷ N，坏消息是如果你按"每 WR 一条"配了 CQ 又共享给多个 QP，别的 QP 的在途 signaled 可能把它挤爆（[[4.3 QP WQE CQ 状态机]] §5）。

## 8. 关键结论

| 结论 | 性质 |
| --- | --- |
| CQE 身兼两职：完成通知 + 回收凭证；unsignaled 两个都放弃，账转由软件自记 | 事实 |
| unsignaled 只作用于 SQ；Recv 完成必有 CQE | 事实 |
| 回收粒度 = 下一个 signaled CQE 被收割；依据是 RC 完成按提交序 | 事实 |
| 出错的 WR 无论是否 signaled 都写错误 CQE——unsignaled 只对成功沉默 | 事实 |
| 全 unsignaled = 槽位泄漏 → ENOMEM / 永久卡死；停发前必须补 signaled 冲账 | 事实（约束） |
| 收益 1/N 递减：适中的 N + 序号化 wr_id 的水位记账即够；受益指标是 Mpps 与 CPU，不是单条 RTT | 取舍 / 实践结论 |
| io_uring 的 `IOSQE_CQE_SKIP_SUCCESS` 是同一思想：成功批量确认，失败逐条上报 | 类比 |

# rkey / lkey 生命周期

> [[4.4 内存注册与零拷贝]] 讲了两把钥匙怎么造出来（`ibv_reg_mr` 三件事的第三件）；本篇跟着它们走完一生。**lkey 从不出门，活在本端每个 WQE 的 SGE 里；rkey 一旦交出去，就成了散落在远端的授权副本——网卡只认钥匙不认人：连接断了、buffer 换用途了，钥匙都不会自动作废**。生命周期管理的全部难点在"撤销"这一幕：撤早了是响亮的报错，撤晚了是静默数据损坏，而每一次撤销都有真金白银的性能代价。真实系统（NVMe-oF）为此把"注册→授权→使用→撤销"做成了每 IO 一轮的流水线动作，本篇用它串起所有取舍。

前置：[[4.4 内存注册与零拷贝]]（MR、pin、翻译表、权限位——本篇直接使用）、[[4.5 Send Recv 与 RDMA Read Write]]（谁消费 lkey、谁消费 rkey）。

---

## 1. 名词精确化：两把钥匙到底是什么

先把 [[4.4 内存注册与零拷贝]] 的结论压成三行定义：

- **MR（Memory Region）**：一段向网卡登过记的内存——物理页已 pin、地址翻译表已下发、权限已声明；
- **lkey（local key）**：一个 32 位整数，是"**本端网卡**访问这块内存"的许可证。每个 WQE 的 SGE 里必填：发送时网卡凭它读 buffer，接收时网卡凭它写 buffer；
- **rkey（remote key）**：同样是 32 位整数，是发给**远端**的门禁卡。远端把它填进 RDMA READ/WRITE/ATOMIC 的 WQE，请求到达时由**我方网卡**验卡放行。

类比一句话【类比】：lkey 是你自己家的钥匙（只在自家门口用），rkey 是复制给客人的门禁卡（客人拿着它随时能进，直到你换锁）。

硬件视角【实现】：钥匙不是加密令牌，而是网卡内部 MR 表（Mellanox 称 MPT/MTT）的**索引 + 低位版本字节**。每次 DMA 前网卡拿钥匙查表做三连查（范围、PD、权限，[[4.4 内存注册与零拷贝]] §2）；低位版本字节让"注销后又注册"的新 MR 拿到不同钥匙值，旧钥匙查表即失效——这是防悬空的最后一道硬件闸，但**只在表项被复用后生效**，不能替代下面的时序纪律。

安全边界要说破【事实】：32 位、明文传输（RoCE 不加密时抓包可见）、无次数与时间限制——rkey 挡得住无意的越权，挡不住恶意伪造。真正的硬隔离是 PD（跨 PD 一票否决）与权限位，rkey 只是"授权的载体"。

## 2. 生命周期全景：四幕与三个危险窗口

![[图片/SVG/8_4_12_1.svg|900]]

四幕【事实】：

| 幕 | 动作 | 发生地 | 成本量级 |
| --- | --- | --- | --- |
| ① 出生 | `ibv_reg_mr`：pin + 下发翻译表 + 铸造 lkey/rkey | 本端，系统调用 | GB 级毫秒计（[[4.4 内存注册与零拷贝]] §2） |
| ② 出境 | rkey + raddr + len 交给远端：CM private_data（≤56 B，[[4.11 RDMA CM 与连接建立]]）、握手期 SEND、或每 IO 捎带在命令里 | 带外/带内消息 | 一条消息 |
| ③ 在途使用 | 本端每个 WQE 消费 lkey；远端每条单边操作携带 rkey，我方网卡逐次验卡 | 两端热路径 | 硬件查表，纳秒级 |
| ④ 失效 | dereg / rereg / invalidate（§5 的四种武器） | 本端（或远端代劳） | 从一个 WQE 到毫秒不等 |

三个危险窗口，对应图中红区——前两个违反时序纪律，第三个违反"授权与连接无关"的事实：

1. **dereg 早于 CQE 收割**：在途 WR 还引用着这个 lkey/这块内存。轻则后续完成报 `IBV_WC_LOC_PROT_ERR`，重则 DMA 与注销竞态——归还页面后网卡还在写（[[4.4 内存注册与零拷贝]] §5 的静默损坏）；
2. **buffer 复用早于撤销**：MR 还活着、rkey 还在远端手里，你把这块内存挪作他用——远端一条迟到的（或有 bug 的）WRITE 原地命中，新数据被无声覆盖。**没有任何错误码**，因为对网卡来说这是一次完全合法的访问；
3. **断连 ≠ 撤销**：见 §4，最反直觉、事故最多的一个。

## 3. lkey 的一生：不出门，但要跨过每个在途窗口

lkey 的规则简单，因为消费者只有本端网卡：

- **有效期 = 注册到注销**。期间它被填进任意多个 WQE 的 SGE（[[4.3 QP WQE CQ 状态机]] §3 第 4 站消费它）；
- **注销的前提是"账清"**：所有引用它的 WR 都已收割完成（signaled 的看 CQE；unsignaled 的看其后第一个 signaled CQE，[[4.15 Signaled Unsignaled WR]]）。这就是 [[4.4 内存注册与零拷贝]] §6 借还池"只能在 CQE 之后 give_back"纪律的钥匙侧表述；
- **PD 一致**：lkey 所属 MR 与 QP 必须同 PD，否则 `IBV_WC_LOC_PROT_ERR`——错误在完成时才浮出，离提交点很远【事实】。

工程上 lkey 几乎不需要"管理"：预注册池里它与 buffer 同生共死，RAII 把 dereg 排在 free 之前（[[4.4 内存注册与零拷贝]] §6 的 `RegisteredArena`），生命周期问题就只剩"归还时机"一件事。

---

## 4. rkey 的一生：出境之后，你就失去了控制

rkey 的复杂全部来自一个事实【事实】：**它的有效性绑定在 MR + PD 上，与任何 QP、任何连接无关**。远端请求到达时，网卡只检查三件事：地址在 MR 范围内、承载请求的 QP 与 MR 同 PD、权限位允许——"这条连接是不是当初拿到 rkey 的那条"根本不在检查项里。

三个直接推论：

1. **连接断了，钥匙还活着**。QP 进 ERR、销毁、重建（[[4.19 RDMA 故障恢复与连接重建]]），MR 纹丝不动。对端重连后拿着旧 rkey 继续用，完全合法——如果你以为断连"清了场"而把 buffer 挪作他用，就踩进 §2 的窗口 2；
2. **同 PD 的任何连接都能用这把钥匙**。把多个客户端挂在同一个 PD 下，客户端 A 泄露/误用的 rkey，客户端 B 的 QP 也验得过——多租户必须按租户拆 PD（[[4.4 内存注册与零拷贝]] §4 最小权限的结构性做法）；
3. **撤销是唯一的收回手段**，而且是本端的显式动作（§5）。协议设计要把"何时收回授权"写成正式步骤，与"何时交出授权"同等重要。

**故障案例**【实践】：存储节点给客户端 A 一块预注册读缓冲的 rkey；A 侧网络抖动触发重连，节点把这块缓冲划给了客户端 B 的请求。A 的旧网卡队列里一条在途 WRITE 迟到抵达——验卡通过（MR 没动、PD 相同），B 收到的数据块中间嵌进了 A 的残页。全程零错误码，只有上层校验和（如果有）能发现。根因：把"连接销毁"当成了"授权收回"。

## 5. 撤销的四种武器：粒度、成本、谁来执行

失效不是只有 dereg 一条路。四种机制，成本差三个数量级，选型就是设计【取舍】：

| 武器 | 做法 | 成本 | 粒度 | 适用 |
| --- | --- | --- | --- | --- |
| `ibv_dereg_mr` | 拆翻译表 + 解 pin，系统调用 | 毫秒级（GB 级 MR） | 整个 MR | 生命周期终点：进程退出、池销毁 |
| `ibv_rereg_mr` | 原地换钥匙（rkey 轮换），系统调用 | 与 dereg 同量级 | 整个 MR | 低频的"换锁"：怀疑泄露、周期轮换 |
| Memory Window（`ibv_alloc_mw` + bind） | 在已注册 MR 上开一扇"窗"，**bind/unbind 是 WQE 不是系统调用** | 一个 WQE，微秒以内 | 任意子区间，每次 bind 换新 rkey | 高频细粒度授权：每请求开窗、用完关窗 |
| SEND with Invalidate（`IBV_WR_SEND_WITH_INV`） | **远端**发响应时捎带失效指令，我方网卡收到即作废指定 rkey，完成里带 `IBV_WC_WITH_INV` 标志 | 捎带，零额外消息 | 一把 rkey | 请求-响应协议的收尾：省掉本端一次显式失效 |

【实现】内核态还有第五种：FRWR（Fast Registration WR）——内核 ULP（nvme-rdma、NFS/RDMA）用 `REG_MR` / `LOCAL_INV` 两种 WQE 在 QP 上完成注册与失效，把系统调用成本压成 WQE 成本。用户态 Verbs 没有完整对等物，MW 是最接近的替代。

选型准则一句话【实践】：**授权变更频率决定武器**——一次授权用到天荒地老，dereg 足矣；每个 IO 换一次授权，必须让撤销的成本降到 WQE 级（MW / FRWR / 远端 invalidate），否则撤销本身成为 IOPS 上限。

## 6. 真实工作负载：NVMe-oF 的每 IO 密钥流水线

把四幕加速到每个 IO 转一轮，看看工业协议怎么付这笔账。NVMe-oF host 发一条读命令（target 数据要 WRITE 回 host buffer）时【实现】：

1. **出生**：host 内核用 FRWR 为这次 IO 的 buffer 注册 MR（一个 REG_MR WQE，不是系统调用）；
2. **出境**：rkey + 地址 + 长度装进 NVMe 命令的 keyed SGL 描述符，随 SEND 发给 target——授权粒度精确到"这一个 IO 的这一块 buffer"；
3. **使用**：target 发起 RDMA WRITE 直写 host buffer（host CPU 全程不参与，[[5.3 Host 与 Target]]）;
4. **失效**：target 的响应用 SEND with Invalidate 捎带作废这把 rkey；host 网卡验证完成里的 `IBV_WC_WITH_INV` 确认钥匙已死，才向上层报 IO 完成。若对端没做远端失效，host 自己补一个 LOCAL_INV WQE。

**为什么不用一把长命 rkey 覆盖整个 buffer 池？** 快是真快——省掉每 IO 两个 WQE。但授权窗口从"一个 IO 的微秒级"膨胀成"连接的整个生命周期 × 整个池"：target 侧任何一个 bug（地址算错、重放、firmware 异常）都可以在任意时刻改写 host 任意在池内存——而 host 正把这些页交给 Page Cache、文件系统元数据用。每 IO 密钥把爆炸半径钉死在单个 IO 上【取舍】。

**这笔账的因果链**【实践】：

- **CPU / IOPS**：每 IO 多两个 WQE（REG_MR + 失效），占 SQ 槽位、占网卡处理带宽——百万 IOPS 时这是可测的开销；远端失效把两个砍成一个，这就是协议里专门定义它的原因；
- **尾延迟**：失效是 IO 关键路径的一环（不失效不能报完成）——网卡 MR 表更新的偶发慢速会直接进 p99；
- **内存**：per-IO 注册的是早已 pin 好的池内页（FRWR 只更新翻译表映射），锁页配额不随 IOPS 波动；
- **网络**：零额外报文——授权与撤销全部捎带在本来就要发的命令/响应里。

对照组：自己写的用户态 RPC 若在热路径上调 `ibv_reg_mr`/`ibv_dereg_mr` 模仿这套流程，成本是**系统调用 + 毫秒级 pin/解 pin**，IOPS 直接掉两个数量级——同样的协议形状，武器选错就是灾难（§5 的选型准则）。

## 7. Modern C++：把"授权"做成一个 RAII 对象

把 §4 的纪律固化成类型：**授权的生死与对象的生死绑定**，advert 是显式动作、撤销是析构，杜绝"忘了收回"：

```cpp
#include <infiniband/verbs.h>

#include <cstdint>
#include <span>
#include <system_error>

// 一次远端写授权：构造 = 铸钥匙，析构 = 换锁（撤销）
// 纪律：本对象析构之前，buffer 不得挪作他用；析构之后 rkey 全网作废
class RemoteWriteGrant {
public:
    RemoteWriteGrant(ibv_pd* pd, std::span<std::byte> buf)
        : mr_{ibv_reg_mr(pd, buf.data(), buf.size(),
                         IBV_ACCESS_LOCAL_WRITE | IBV_ACCESS_REMOTE_WRITE)} {
        if (mr_ == nullptr)
            throw std::system_error{errno, std::system_category(), "ibv_reg_mr"};
    }
    ~RemoteWriteGrant() {
        // 前提：引用本 MR 的在途 WR 已全部收割（4.3 的所有权纪律）
        ibv_dereg_mr(mr_);
    }
    RemoteWriteGrant(const RemoteWriteGrant&) = delete;
    RemoteWriteGrant& operator=(const RemoteWriteGrant&) = delete;

    // 出境包：序列化进握手消息或每 IO 命令（对应 NVMe-oF 的 keyed SGL）
    struct Advert {
        std::uint64_t addr;
        std::uint32_t len;
        std::uint32_t rkey;
    };
    Advert advert() const noexcept {
        return {reinterpret_cast<std::uintptr_t>(mr_->addr),
                static_cast<std::uint32_t>(mr_->length), mr_->rkey};
    }

    std::uint32_t lkey() const noexcept { return mr_->lkey; }

private:
    ibv_mr* mr_;
};
```

两点说明【实践】：

- 这是**低频授权**（连接级、池级）的形状：构造/析构走 reg/dereg，热路径零成本。若授权要随每个 IO 轮换，把内部实现换成 MW bind/unbind（接口不变，成本从毫秒降到一个 WQE）——这正是 RAII 的价值：纪律不变，武器可换；
- `advert()` 返回值经 SEND 出境后，**撤销时机就成了协议的一部分**：对端必须先确认不再使用（响应到达、或远端 invalidate），本对象才允许析构。把这个等待做进上层状态机，而不是指望析构函数替你等。

## 8. 排障清单：症状 → 原因 → 检查

| 症状 | 常见原因 | 检查动作 |
| --- | --- | --- |
| `IBV_WC_LOC_PROT_ERR` | lkey 与 QP 不同 PD；SGE 越出 MR；MR 已被提前 dereg | 打印 SGE 的 addr/len/lkey 与 MR 边界；核对 dereg 时序是否在全部 CQE 之后 |
| `IBV_WC_REM_ACCESS_ERR`（对端报） | rkey 已失效（dereg/rereg/invalidate 过）、权限位不含所需操作、raddr/len 越界 | 两端打印 rkey 与 MR flags 逐项比对；查本端是否轮换过钥匙而没通知对端 |
| 重连后对端一操作就 `REM_ACCESS_ERR` | 重建时重新注册了 MR（新 rkey），对端还拿旧的 | 重连协议里必须重新交换 advert（[[4.19 RDMA 故障恢复与连接重建]]） |
| 数据偶发被覆盖、无错误码 | §2 窗口 2：buffer 复用早于撤销；或断连未撤销（§4 案例） | 审计"复用前是否先失效"；给每块出境 buffer 记录 rkey 台账 |
| 完成里没有 `IBV_WC_WITH_INV` | 对端没做远端失效（能力未协商或没实现） | 回退到本端显式失效；协商阶段确认双方支持 |
| IOPS 上不去，火焰图里全是 reg/dereg | 每 IO 用系统调用级武器 | 换 MW / 预注册池 / （内核态）FRWR——§5 选型准则 |
| 疑似 rkey 被别的连接使用 | 多个租户共用一个 PD | 按租户/信任域拆 PD（[[4.4 内存注册与零拷贝]] §4） |

## 9. 陷阱与误区

> [!warning] 常见错误
> 1. **把断连当撤销**：rkey 绑定 MR + PD，与连接无关。QP 销毁一万次，钥匙照样开门——收回授权只能靠 dereg/rereg/invalidate。
> 2. **dereg 抢在 CQE 前面**：在途 WR 还引用着 MR。必须先收干净账（包括 unsignaled 的批量确认），再动钥匙。
> 3. **复用 buffer 不换钥匙**：MR 活着 + rkey 在外 = 远端随时可写。挪用前先失效，是与"free 前先 dereg"并列的第二条时序军规。
> 4. **把 rkey 当秘密**：32 位明文，protection 靠 PD 与权限位，不靠钥匙难猜。安全设计按"rkey 会泄露"做。
> 5. **热路径上用毫秒级武器**：撤销频率决定武器选择——每 IO 换钥匙就必须用 WQE 级机制，reg/dereg 只配出现在初始化与销毁。
> 6. **远端失效不验证**：收到响应就报完成，不检查 `IBV_WC_WITH_INV`——对端没失效时钥匙继续裸奔。协议规定谁失效，就要验证谁真的失效了。

## 10. 关键结论

| 结论 | 性质 |
| --- | --- |
| lkey 供本端网卡验证 SGE，rkey 供远端携带、我方网卡验卡；都是 MR 表索引 + 版本字节，不是加密令牌 | 事实 / 实现 |
| rkey 有效性 = MR + PD，与 QP/连接无关：断连不撤销，同 PD 任意连接可用 | 事实 |
| 三个危险窗口：dereg 早于 CQE（报错）、复用早于撤销（静默损坏）、断连当撤销（静默损坏） | 事实（约束） |
| 撤销武器按成本分级：dereg/rereg（毫秒、系统调用）→ MW bind（WQE 级）→ 远端 invalidate（捎带、零消息） | 事实 / 取舍 |
| 授权变更频率决定武器：连接级授权用 reg/dereg，每 IO 授权必须 WQE 级 | 实践结论 |
| NVMe-oF 每 IO 密钥流水线：FRWR 注册 → keyed SGL 出境 → 单边使用 → 远端失效收尾；用两个 WQE 买单 IO 级爆炸半径 | 实现 / 取舍 |
| 撤销时机是协议的一部分：出境的钥匙必须有对应的"确认收回"步骤 | 实践结论 |

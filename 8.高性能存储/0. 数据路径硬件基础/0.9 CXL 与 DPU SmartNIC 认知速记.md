# CXL 与 DPU/SmartNIC 认知速记

> 认知级速记，不排实验。两者都在重划数据路径的层级边界：CXL 在 DRAM 与 NVMe 之间插入新的内存层级；DPU 把网络与存储的数据面从 host CPU 搬到网卡上。面试中属于加分题——答出"它解决什么、插在路径哪一层"即可，不需要实操细节。

---

## 1. CXL：字节可寻址的一致性内存扩展

### 是什么

CXL（Compute Express Link）复用 PCIe 物理层，在其上跑三个子协议：`CXL.io`（配置，等价 PCIe）、`CXL.cache`（设备缓存 host 内存并保持一致）、`CXL.mem`（host 按 load/store 访问设备内存）。关键区别于普通 PCIe 设备：**访问是缓存一致的字节寻址，不是 DMA 块搬运**——CPU 直接执行 load/store，不需要驱动发命令（对比 [[0.4 PCIe BAR MMIO 与 MSI-X]] 的 MMIO 和 [[0.3 DMA IOMMU 与 Pinned Memory]] 的 DMA 路径）。

设备分三型，存储视角只需记 Type-3：**内存扩展器**——一块插在 PCIe 插槽上的 DRAM，操作系统把它呈现为一个没有 CPU 的 NUMA 节点（【事实】这直接复用 [[0.5 NUMA CPU 亲和性与内存亲和性]] 的全部机制：numactl、页迁移、分层回收都能用）。

### 在延迟坐标系里的位置

【量级】本地 DRAM ~100 ns；CXL 内存大致落在"跨 socket NUMA 远端再慢一些"的档位（数百 ns）；NVMe 随机读 ~10–100 μs。也就是说 CXL 与 DRAM 差一倍上下，与 NVMe 差两个数量级——它填的是总纲量级表里 DRAM 和 SSD 之间那道最宽的鸿沟。

### 对存储/AI 数据路径的意义

- **容量墙**：单机 DRAM 插槽有限且贵；CXL 允许在不加 CPU 的前提下扩内存池。
- **分层缓存多一档**：KV cache 分层从 "HBM → DRAM → NVMe → 远端"（[[8.14 分层缓存与 KV Cache 生命周期]]、[[8.4 KV Cache Offload]]）变成中间可插一层 CXL——比 DRAM 便宜、比 NVMe 快两个数量级，且字节寻址免去了块 IO 的整块读写。
- 【事实→演进】截至本笔记时间，内存**扩展**（单机 Type-3）已商用落地；跨主机的内存**池化/共享**（CXL 2.0/3.x 交换机方案）仍在生态演进期，面试表述要区分这两档成熟度。

## 2. DPU / SmartNIC：数据面卸载

### 是什么

在网卡上加通用核（常为 ARM）+ 硬件加速器（加解密、压缩、RDMA、NVMe 模拟），让网卡从"收发包的被动设备"变成"能独立跑软件栈的小型服务器"。代表：NVIDIA BlueField、AWS Nitro、阿里 CIPU。

### 卸载什么、为什么

| 卸载项 | 说明 | 与已有笔记的衔接 |
| --- | --- | --- |
| 云盘数据面 | DPU 向 host 模拟标准 NVMe/virtio-blk 设备，后端在卡上跑网络存储客户端连远端集群；host 只看到一块"本地盘" | 后端协议即 [[5.1 NVMe-oF 架构]]；SPDK 的 bdev/target 栈可以整体跑在 DPU 的 ARM 核上（[[5.6 SPDK 用户态驱动]]） |
| NVMe-oF target/initiator | 协议处理、RDMA 收发在卡上完成，不占 host CPU | [[5.19 RDMA Transport 数据路径]] |
| 网络虚拟化 | OVS/VPC 转发、租户隔离下沉到卡 | 与 [[4.1 RDMA 为什么快]] 同一动机：把 per-packet 固定成本从 host CPU 移走 |
| 加解密 / 压缩 / EC | 硬件加速器做行内处理 | EC 计算成本见 [[7.1 副本 vs EC]] |
| GPU 直通路径 | GPUDirect RDMA / GDS 场景中，DPU 即 RNIC，数据不经 host 内存 | [[8.12 GPUDirect RDMA]]、[[8.2 GDS 与 cuFile]] |

动机两条，缺一不可：

1. **还 CPU**：存储/网络栈在大带宽下能吃掉可观的 host 核数——这些核本可以卖给租户或留给业务。总纲的"减少切换/拷贝"杠杆做到极致，就是把整个数据面挪到专用硬件。
2. **隔离与信任边界**：基础设施软件跑在卡上，租户拿到整台裸金属也碰不到云管理面——Nitro/CIPU 架构的安全出发点。【事实】这一条解释了"为什么云厂商都自研 DPU"：不只是性能，更是多租户的信任边界划分。

## 3. 面试一句话

- CXL：「解决内存墙——PCIe 上的缓存一致字节寻址内存，OS 视角是无 CPU 的 NUMA 节点，在 DRAM 和 NVMe 之间插入新层级，KV cache 分层多了一档。」
- DPU：「解决数据面占 host CPU——把 NVMe-oF/云盘/网络虚拟化整栈搬到网卡上的 ARM 核和加速器里，host 只看到标准 NVMe 设备；同时是云厂商的多租户信任边界。」

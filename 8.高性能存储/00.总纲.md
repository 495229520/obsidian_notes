## 知识体系

![[图片/SVG/RDMA-for-AI-Infra-知识体系架构.svg|1100]]

两条路径在硬件、RDMA 与 GPU 处相交：

```text
C++ / Linux 并发 → RPC / 主机网络 → RDMA / RoCE → GPU 通信 → KV / PD
                               ↑                   ↑
                   DMA / PCIe / NUMA         Stream / Event / GDR
                               ↑                   ↑
Linux I/O → NVMe / SPDK → 远端存储 → 数据加载 / Checkpoint / KV Offload
```

`3.Linux` 保持独立，作为共同基础通过链接接入。先复习 [[7. 网络编程/00. 学习路线|Linux 网络学习路线]]，再看 [[18.7 RDMA Verbs 与 CQ 非阻塞 RPC]]。图中的层次表示知识依赖，不是固定调用栈；DPDK 是可选分支，通信库按项目选择组合。

## 当前取舍与项目范围

优先把异步提交、缓冲区生命周期、背压、错误恢复与测量做成可运行证据。后续从 Mooncake 或 NIXL 中选一条传输路径，不同时精读全部通信库。

保留项目数量上限：保留最接近完成的一项系统作品，为一项 RDMA/AI 传输作品留出位置。现有 `linux-io-lab` 与 `mini-kv-engine` 的完成度仍需按实际产物确认，不自动取消进行中工作，也不要求两项全部做完才学习 GPU 数据路径。

GEMM、CUTLASS、FlashAttention 手写、编译器、DPU 自研协议栈及 Kubernetes Operator 继续后置。DPDK、GDS、NCCL 深度开发根据岗位和实验需要选择，不各自扩成并行项目。

## 实验与完成证据

| 可用环境 | 可以证明 | 尚不能据此证明 |
|---|---|---|
| 普通 Linux / 软件 RoCE | API 功能、协议流程、失败处理 | 硬件 RNIC 性能与 GPU 直达 |
| CUDA GPU | Host–Device 搬运、Stream/Event、时间线 | 跨机 GPUDirect RDMA |
| 双机 RNIC | 主机内存传输与对应拓扑性能 | 任意 GPU/NIC 组合的 GDR 支持 |
| 兼容 GPU/RNIC | 注册、直达、同步和 Host staging 对照 | 大规模 Fabric 拥塞行为 |
| 对应多节点 Fabric | 多路径、拥塞、共享资源与故障域 | 其他配置或规模下的普遍收益 |

## 一、选择题（概念基础）

**1.** 使用 `std::string` 需要包含的头文件是：
- A. `<cstring>`　　B. `<string>`　　C. `<string_view>`　　D. `<cctype>`

**2.** 关于 `length()` 和 `size()`，正确的是：
- A. `length()` 含 `\0`，`size()` 不含　　B. 两者功能完全相同
- C. `size()` 返回字节数，`length()` 返回字符数　　D. `length()` 只能用于 C 风格字符串

**3.** `std::string str = "HelloWorld"; str.substr(0, 5);` 的结果是：
- A. `"Hello"`　　B. `"World"`　　C. `"HelloW"`　　D. `"elloW"`

**4.** `find()` 在未找到目标时返回：
- A. `-1`　　B. `0`　　C. `nullptr`　　D. `std::string::npos`

**5.** 把 `std::string("3.14")` 转成 `double` 应使用：
- A. `std::stoi`　　B. `std::stof`　　C. `std::stod`　　D. `std::to_string`

**6.** C 风格字符串 `char str[6] = {'H','e','l','l','o','\0'};`，`strlen(str)` 返回：
- A. 4　　B. 5　　C. 6　　D. 取决于平台

**7.** 下列哪个访问方式带**边界检查**：
- A. `str[i]`　　B. `str.at(i)`　　C. `*(str.begin()+i)`　　D. `str.data()[i]`

**8.** 关于 `std::cin >> str` 读入字符串，正确的是：
- A. 读取整行包括空格　　B. 遇到空白字符（空格/换行/Tab）停止
- C. 必须配合 `cin.ignore()`　　D. 会把 `\0` 也读进来

**9.** `std::string_view`（C++17）的核心价值是：
- A. 可变长字符串　　B. 只读视图，避免不必要的复制
- C. 自动管理堆内存　　D. 支持宽字符

**10.** 宽字符字符串字面量的正确写法是：
- A. `"Hello"`　　B. `W"Hello"`　　C. `L"Hello"`　　D. `wchar_t"Hello"`

**11.** `char1 = 'A';` 的 ASCII 值是：
- A. 64　　B. 65　　C. 97　　D. 66

**12.** 重复字符构造 `std::string s(5, '*');` 得到：
- A. `"5*"`　　B. `"*****"`　　C. `"*"`　　D. 编译错误

> [!success]- 参考答案（第一节）
> 1. **B**。`std::string` 在 `<string>`；`<cstring>` 是 C 风格函数（`strcpy` 等）；`<string_view>` 是 `std::string_view`；`<cctype>` 是字符分类。
> 2. **B**。两者完全等价，都返回字符个数（不含 `\0`）。`size()` 来自容器统一接口，`length()` 是字符串语义别名。
> 3. **A**。`substr(pos, len)` 从索引 `pos` 起截取 `len` 个字符，`substr(0,5)` = `"Hello"`。
> 4. **D**。`find()` 返回 `size_t`，未找到是 `std::string::npos`（值为 `size_t` 的最大值，通常 `(size_t)-1`）。**绝不能**用 `-1` 或 `pos >= 0` 判断（`size_t` 无符号永远 ≥ 0）。
> 5. **C**。`stod`→double，`stof`→float，`stoi`→int，`stol`→long，`to_string` 是反向（数值→string）。
> 6. **B**。`strlen` 数到 `\0` 为止、不含 `\0`，"Hello" 是 5 个字符。
> 7. **B**。`at(i)` 越界抛 `std::out_of_range`；`operator[]` 越界是未定义行为（UB），不检查。
> 8. **B**。`>>` 以空白分隔，遇空格即停。读整行用 `std::getline`。
> 9. **B**。`string_view` 只持有指针+长度，不拷贝、不拥有底层数据，适合只读传参。
> 10. **C**。宽字符字面量加 `L` 前缀：`L"Hello"`，类型 `const wchar_t*`。
> 11. **B**。`'A'`=65，`'B'`=66，`'a'`=97，`'0'`=48。
> 12. **B**。`string(count, ch)` 构造 `count` 个 `ch`，得 `"*****"`。

## 二、概念辨析（判断对错并说明理由）

**13.** `std::string` 末尾一定不存 `\0`，因为它用长度记录大小。

**14.** `str.length()` 的返回值是 `int`，可以直接和 `-1` 比较判断查找失败。

**15.** `std::string s = "Hello"; s[0] = 'h';` 是合法的，可以原地修改字符。

**16.** `std::string_view` 总是比 `std::string` 安全，应该无脑替换所有字符串参数。

**17.** `strlen("Hello")` 和 `sizeof("Hello")` 的值相同。

**18.** `==` 比较两个 `std::string` 比较的是内容是否相等，而不是地址。

**19.** C 风格字符串 `strcpy(dest, src)` 会自动检查 `dest` 缓冲区是否够大。

**20.** `std::cin >> num` 之后直接 `std::getline(std::cin, line)`，能正确读到下一行内容。

> [!success]- 参考答案（第二节）
> 13. **错**。C++11 起标准保证 `std::string` 内部以 `\0` 结尾，`c_str()`/`data()` 返回的是合法 C 字符串。它**额外**用长度字段记录 size，但仍维护结尾 `\0`。
> 14. **错**。`length()`/`size()` 返回**无符号** `size_t`。查找失败要用 `find(...) == std::string::npos` 判断，跟长度无关；把无符号数和 `-1` 比较会触发隐式转换陷阱。
> 15. **对**。`operator[]` 返回 `char&`，非 const string 可原地改字符。注意 `at`/`[]` 不能越界。
> 16. **错**。`string_view` **不拥有**数据，一旦底层字符串销毁/重分配，view 就悬空。返回临时 `std::string` 的 `string_view`、或对会扩容的 string 持久持有 view 都是 UB。它适合"短生命周期只读传参"。
> 17. **错**。`strlen("Hello")`=5（运行期数到 `\0`）；`sizeof("Hello")`=6（编译期，字面量是 `char[6]`，含 `\0`）。
> 18. **对**。`std::string::operator==` 逐字符比较内容，与底层指针地址无关。
> 19. **错**。`strcpy` 不做任何边界检查，`dest` 太小会缓冲区溢出（经典安全漏洞）。需用 `strncpy`/`snprintf`，或直接用 `std::string`。
> 20. **错**。`>>` 会把换行符留在缓冲区，`getline` 立刻读到空行。需在两者之间 `std::cin.ignore()`（忽略残留换行）。

char c1 = 'A';

> [!success]- 参考答案（第三节）

> 22. 输出 `cde`。`"abc"`→append→`"abcde"`→`erase(0,2)` 删前两字符→`"cde"`。
> 23. 输出 `5 6`。`strlen` 不含 `\0` 为 5；`sizeof` 是数组总字节数 6。

> 25. 输出 `HiWorld`。`replace(0,5,"Hi")` 把索引 0 起的 5 个字符 `"Hello"` 换成 `"Hi"`。
> 26. 输出**负数**（通常 `-1`）。`compare` 逐字符比，`'c'`<`'d'`，故 `"abc"` < `"abd"`，返回负值。

## 四、找错与修复（指出 bug 并改正）

**27.**
```cpp
char dest[5];
strcpy(dest, "Hello World");   // ?
```

**28.**
```cpp
std::string s = "abc";
size_t pos = s.find("z");
if (pos >= 0) std::cout << "found";   // ?
```

**29.**
```cpp
int num;
std::cin >> num;
std::string line;
std::getline(std::cin, line);   // 想读下一行，结果是空的
```

**30.**
```cpp
// 拼接姓名和编号
char name[20] = "Tom";
int id = 42;
strcat(name, id);   // ?
```

**31.** 用 Modern C++ 重写下面这段 C 风格代码：
```cpp
char buf[64];
strcpy(buf, "Hello, ");
strcat(buf, "World");
if (strcmp(buf, "Hello, World") == 0)
    printf("%s, len=%zu\n", buf, strlen(buf));
```

> [!success]- 参考答案（第四节）
> 27. **缓冲区溢出**：`dest` 只有 5 字节，源串 12 字符（含 `\0` 13 字节），越界写是 UB。修复：扩大缓冲并用安全版本 `strncpy(dest, src, sizeof(dest)-1); dest[sizeof(dest)-1]='\0';`，或直接 `std::string dest = "Hello World";`。
> 28. **无符号比较恒真**：`pos` 是 `size_t`，`pos >= 0` 永远成立，未找到时 `pos = npos` 也判成 found。修复：`if (pos != std::string::npos)`。
> 29. **残留换行符**：`>>` 把 `\n` 留在缓冲区，`getline` 读到空行。修复：在两者之间加 `std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');`（或简写 `std::cin.ignore()` 忽略一个字符）。
> 30. **类型错误 + 行为灾难**：`strcat` 第二参须是 `const char*`，传 `int 42` 被当成指针 `0x2A` 解引用→UB/崩溃。修复（Modern C++）：`std::string s = "Tom" + std::to_string(id);`。
> 31. **Modern C++ 重写**：
> ```cpp
> std::string buf = "Hello, ";
> buf += "World";                        // 或 buf.append("World")
> if (buf == "Hello, World")
>     std::cout << buf << ", len=" << buf.size() << "\n";
> ```
> 要点：`std::string` 自动管理内存、无溢出风险，`+`/`+=` 拼接，`==` 比较，`size()` 取长度，全程无裸缓冲区。

## 五、简答题

**32.** `length()`/`size()` 有区别吗？为什么标准库提供两个名字？

**33.** `std::string` 和 C 风格字符串（`char[]`）相比有哪些优势？

**34.** `find()` 返回值为什么必须用 `std::string::npos` 判断而不能用 `-1`？

**35.** `cin >> str` 和 `std::getline(cin, str)` 读取行为有什么区别？混用要注意什么？

**36.** `std::string_view` 解决什么问题？使用时最大的坑是什么？

**37.** `c_str()` 和 `data()` 返回什么？拿到的指针能长期保存吗？

> [!success]- 参考答案（第五节）
> 32. 无任何区别，完全等价。`size()` 是所有 STL 容器的统一接口名；`length()` 是字符串语义上更自然的别名。任选其一。
> 33. ① 自动管理堆内存、自动扩容，无需手动算缓冲区大小；② `+`/`==`/`<` 等运算符直观；③ 不易缓冲区溢出（比 `strcpy`/`strcat` 安全）；④ 携带长度，取 size 是 O(1) 而非 `strlen` 的 O(n)；⑤ 丰富成员方法（`substr`/`find`/`replace`）。
> 34. `find` 返回 `size_t`（无符号）。未找到的哨兵值 `npos` 是无符号最大值；若误用 `-1` 比较或 `pos >= 0` 判断，无符号语义会让逻辑出错。统一写 `if (pos != std::string::npos)`。
> 35. `>>` 以空白（空格/Tab/换行）为分隔符，只读一个"单词"并把分隔符留在缓冲区；`getline` 读到换行为止（含空格、丢弃换行）。混用时 `>>` 后残留的 `\n` 会被随后的 `getline` 立即吃掉成空行，需 `cin.ignore()` 清理。
> 36. 解决"只读传参时不必要的字符串拷贝/构造"——`string_view` 只存指针+长度，O(1) 构造、零拷贝，能同时接受 `std::string`、字面量、`char[]`。最大坑：它**不拥有**数据，底层串销毁或扩容后 view 悬空（典型：返回指向局部/临时 string 的 view）。
> 37. 都返回指向内部缓冲、以 `\0` 结尾的字符序列（C++11 起 `data()` 也保证有 `\0`，C++17 起返回非 const 可写指针）。该指针**不能长期保存**：一旦 string 被修改、扩容或析构即失效。需要长期持有就拷一份 `std::string`。（SSO 等底层细节本章笔记未覆盖，建议补充。）

## 六、综合设计与手写代码

**38.** 写一个函数 `int count_char(std::string_view s, char target)`，统计字符出现次数。要求用 `std::` 算法 + lambda。

**39.** 写一个 `std::string trim(std::string_view s)`，去掉首尾空白字符（用 `<cctype>` 的 `isspace`）。

**40.** 把下面这段有缺陷的 C-style 代码用 Modern C++ 重写：拼接路径并判断是否以 `.cpp` 结尾。
```cpp
char path[256];
strcpy(path, "src/");
strcat(path, "main.cpp");
char* dot = strrchr(path, '.');
if (dot != nullptr && strcmp(dot, ".cpp") == 0)
    printf("C++ source: %s\n", path);
```

> [!success]- 参考答案（第六节）
> **38.**
> ```cpp
> int count_char(std::string_view s, char target) {
>     return static_cast<int>(std::count(s.begin(), s.end(), target));
> }
> ```
> 要点：`std::count` 直接数等于 `target` 的元素；`string_view` 入参避免拷贝。
>
> **39.**
> ```cpp
> std::string trim(std::string_view s) {
>     auto not_space = [](unsigned char c) { return !std::isspace(c); };
>     auto b = std::find_if(s.begin(), s.end(), not_space);
>     auto e = std::find_if(s.rbegin(), s.rend(), not_space).base();
>     return (b < e) ? std::string(b, e) : std::string{};
> }
> ```
> 要点：`isspace` 传参须转 `unsigned char`（避免负值 char 导致 UB）；`rbegin().base()` 定位尾部。
>
> **40.** Modern C++ 重写：
> ```cpp
> std::string path = "src/";
> path += "main.cpp";
> if (path.size() >= 4 && path.substr(path.size() - 4) == ".cpp")
>     std::cout << "C++ source: " << path << "\n";
> // 或 C++20: if (path.ends_with(".cpp"))
> ```
> 要点：`+=` 拼接无溢出，`substr` 取后缀比较；C++20 直接 `ends_with`。

## 七、简答深化题

**41.** `std::string` 内部"实际保存的是指向字符串数据的指针，超出作用域自动释放堆内存"——结合 RAII 解释它如何做到自动管理。（可串联 [[6.6 堆与栈的区别]]）

**42.** 为什么 `std::string` 取长度是 O(1)，而 C 字符串 `strlen` 是 O(n)？这对性能意味着什么？

**43.** `std::string s = a + b + c;` 这种链式 `+` 拼接可能有什么性能问题？工程上如何优化？

**44.** 为什么 `char` 既能当字符又能当整数？`'A' + 'B'` 的结果类型是什么？（串联 [[8.2 字符处理|ASCII]]）

**45.** 宽字符 `wchar_t` 在 Windows 和 Linux 上有什么差异？为什么现代跨平台项目更倾向 UTF-8 + `std::string`？

> [!success]- 参考答案（第七节）
> 41. `std::string` 是典型 RAII 封装：构造时在堆上分配缓冲（小串可能走 SSO 存栈上），把指针/长度/容量作为成员持有；离开作用域时**析构函数**自动 `delete` 堆缓冲。用户无需手动释放，异常路径也安全。这与 [[6.6 堆与栈的区别|堆内存需手动 new/delete]] 的裸指针形成对比——所有权由对象生命周期托管。
> 42. `std::string` 用成员变量缓存了 size，读长度直接返回字段=O(1)；C 字符串无长度信息，`strlen` 必须从头扫到 `\0`=O(n)。在循环条件里反复 `strlen` 会退化成 O(n²)（经典陷阱），而 `s.size()` 无此问题。
> 43. 朴素实现下每个 `+` 都生成一个临时 `std::string` 并拷贝，N 段拼接产生 O(N) 次分配/拷贝。优化：① 用 `+=` 就地追加；② 先 `reserve` 预估容量减少扩容；③ 或用 `std::ostringstream`/`std::format`(C++20)。（现代库的移动语义/表达式优化能缓解部分开销。）
> 44. `char` 本质是 1 字节整数类型，字面量 `'A'` 就是其 ASCII 码 65，故能参与算术。整型提升规则下 `'A' + 'B'` 先把两个 `char` 提升为 `int` 再相加，**结果类型是 `int`**（=131），不是 `char`；要存回字符需显式 `static_cast<char>`。
> 45. Windows 上 `wchar_t` 是 2 字节（UTF-16），Linux 上是 4 字节（UTF-32），宽度不一致使 `wchar_t` 不可移植。跨平台更推荐用 UTF-8 编码存进 `std::string`（字节序列统一、与 C API/网络/文件天然兼容），仅在调用平台宽字符 API 时临时转换。（编码细节本章笔记较浅，建议补充。）

## 八、概念辨析进阶

**46.** 辨析 `str[i]` / `str.at(i)` / `str.front()`/`str.back()`。

**47.** 辨析 `size()` / `length()` / `capacity()` / `strlen()`。

**48.** 辨析 `std::string` / `const char*` / `std::string_view` 三种"字符串"。

**49.** 辨析 `==`（string）/ `compare()`（string）/ `strcmp()`（C 风格）。

> [!success]- 参考答案（第八节）
> 46. `[]`：下标访问，**不检查**越界（UB）、最快；`at()`：检查越界、越界抛 `out_of_range`；`front()`/`back()`：取首/尾字符（空串上调用是 UB）。口诀：要安全用 `at`，要性能用 `[]`。
> 47. `size()`==`length()`：当前字符数（不含 `\0`）；`capacity()`：当前已分配、可容纳的字符数（≥size，扩容才变）；`strlen()`：C 字符串运行期数 `\0`，O(n)。口诀：size 是"用了多少"，capacity 是"租了多大"。
> 48. `std::string`：**拥有**并管理堆缓冲，可变、自动扩容；`const char*`：裸指针，不拥有、需手动保证生命周期与 `\0` 结尾；`string_view`：**不拥有**的只读视图（指针+长度），零拷贝但易悬空。口诀：string 拥有、view 借用、char* 裸奔。
> 49. `==`：返回 `bool`，只问"相不相等"，最直观；`compare()`：返回三态 `int`（负/0/正），需要排序/字典序时用；`strcmp()`：C 风格，逐字节比到 `\0`，同样三态返回，但要求两边都是合法 C 字符串。口诀：判等用 `==`，排序用 `compare`，C 串才用 `strcmp`。

## 九、大厂面试场景题 / 八股常考

**50.** 线上服务把一个函数参数从 `const std::string&` 改成按值 `std::string` 后，QPS 下降明显。为什么？什么时候按值传 string 反而合理？

**51.** 排查一个崩溃：函数返回了 `std::string_view`，调用方读出来全是乱码或崩溃。最可能的原因是什么？怎么修？

**52.** 日志模块里 `for (size_t i = 0; i < strlen(buf); ++i) {...}` 在大字符串上 CPU 飙高，定位原因并优化。

> [!success]- 参考答案（第九节）
> 50. **现象**：按值传参导致每次调用都构造一份 string（小串走 SSO 还好，长串触发堆分配+拷贝），高频路径上分配/拷贝开销累积拖垮 QPS。**原因**：只读不需要拥有所有权时，按值是多余拷贝。**解决**：只读用 `const std::string&` 或 `std::string_view`（更通用）。**延伸**：只有当函数**确实要持有/移动**这个 string（如存进成员、塞进容器）时，按值传 + `std::move` 才是更优的"sink 参数"惯用法。
> 51. **现象**：`string_view` 读出乱码/崩溃。**原因**：view 指向的底层数据已失效——典型是返回了指向**局部 `std::string` 或临时对象**的 view，函数返回后缓冲已析构（悬空）；或底层 string 之后 `append`/`+=` 触发扩容、旧缓冲被释放。**解决**：返回真正拥有数据的 `std::string`；或保证被引用的 string 生命周期长于 view。**延伸**：`string_view` 只适合参数传递这种"调用期内"的短生命周期场景，不要当返回值/成员长期保存。
> 52. **现象**：循环 CPU 高。**原因**：`strlen(buf)` 写在循环条件里，每次迭代都重新 O(n) 扫一遍 `\0`，整体退化成 O(n²)。**解决**：循环外 `const size_t n = strlen(buf);` 缓存一次；更彻底地改用 `std::string`/`string_view`，`size()` 是 O(1)。**延伸**：编译器有时能优化掉重复 `strlen`，但别依赖它；"循环条件里调 O(n) 函数"是通用反模式。

## 十、补充加分题

**53.** 从复杂度与内存分配角度分析：把 1 万个短字符串拼成一个大字符串，`s += piece` 逐个追加 vs 先 `s.reserve(total)` 再追加，性能差在哪？

**54.** `std::string` 的 SSO（小字符串优化）是什么？它如何影响"短字符串拷贝"的开销？（本章笔记未覆盖，作了解）

**55.** `std::stoi("123abc")` 和 `std::stoi("abc")` 分别会发生什么？相比 C 的 `atoi` 安全在哪？

> [!success]- 参考答案（第十节）
> 53. **复杂度/分配分析**：不 `reserve` 时，string 容量按倍增策略扩容，N 次追加触发 O(log N) 次重分配，每次重分配要把已有内容整体拷到新缓冲，累计搬运量可观；虽然均摊仍是 O(总长度)，但常数大、内存抖动多。先 `reserve(total)` 一次性分配到位，后续追加零重分配，缓存局部性也更好。结论：已知最终大小务必 `reserve`。
> 54. SSO：`std::string` 对象内部留有一小块栈上缓冲（典型 15~22 字节，实现相关），短字符串直接存在对象里、**不走堆分配**；超过阈值才转堆。好处：短串构造/拷贝/析构极快（无 malloc/free），这也是"小串按值传也不贵"的原因。是标准库常见但非强制的优化。
> 55. `stoi("123abc")` 解析到非法字符**停止**，返回 `123`（只转前缀合法部分）；`stoi("abc")` 开头就无合法数字，**抛 `std::invalid_argument`**；溢出则抛 `out_of_range`。相比 C 的 `atoi`（无法区分"转换失败"与"真的是 0"、且无溢出报错），`stoi` 通过异常显式报错，更安全。

## 十一、字符编码与缓冲区安全专项

> 本章涉及 C 风格字符串与宽字符，缓冲区溢出和编码是高频考点，单列一节强化。

**56.** 下面代码读用户输入，存在什么安全隐患？给出安全写法。
```cpp
char name[16];
scanf("%s", name);          // 用户可能输入超长串
printf("Hi %s\n", name);
```

**57.** 解释 `strncpy(dest, src, n)` 一个容易被忽略的"坑"：它不保证 `dest` 以 `\0` 结尾。给出安全用法。

**58.** 小端机上 `char buf[4]; int x = 0x41424344; memcpy(buf, &x, 4);`，`buf[0]` 是哪个字符？（串联 [[8.2 字符处理|ASCII]] 与字节序）

**59.** 为什么把 `std::string` 直接当二进制缓冲区在网络上发送，接收端用 `strlen` 解析长度是错的？

> [!success]- 参考答案（第十一节）
> 56. **隐患**：`%s` 无长度限制，输入超过 15 字符即缓冲区溢出（栈溢出，经典漏洞）。**安全写法**：限定宽度 `scanf("%15s", name);`（Windows 可用 `scanf_s("%15s", name, 16);`，见笔记）；Modern C++ 更推荐 `std::string s; std::cin >> s;` 让标准库自动扩容。
> 57. `strncpy` 复制不超过 `n` 字符：若 `src` 长度 ≥ `n`，**不会**补 `\0`，`dest` 就成了无结尾的"野串"，后续 `strlen`/`printf("%s")` 会越界读。安全用法：`strncpy(dest, src, n-1); dest[n-1] = '\0';`，或干脆用 `snprintf(dest, n, "%s", src)`（保证截断并补 `\0`），最佳是 `std::string`。
> 58. `buf[0]` 是 `'D'`（0x44）。小端序低地址存低位字节，`x` 的最低字节 `0x44`('D') 落在 `buf[0]`，依次 `buf[1]='C'`、`buf[2]='B'`、`buf[3]='A'`。这正说明"按字节解读整数"依赖字节序。
> 59. C 风格按 `\0` 界定长度，但**二进制数据本身可能含 `\0`**——`strlen` 会在第一个 `\0` 处提前截断，丢失后续数据；二进制串也未必有结尾 `\0`，`strlen` 可能越界。正确做法：显式传输长度字段（如 4 字节网络序长度前缀），按长度而非 `\0` 解析。这与 [[8.1 string|std::string 携带长度]] 的设计思想一致。

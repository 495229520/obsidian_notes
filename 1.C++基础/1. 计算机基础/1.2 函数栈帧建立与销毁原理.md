函数调用在底层的本质，是 CPU 寄存器（ESP/EBP）对进程栈空间内存地址的划定、读写与回收。以 x86 架构和 `__cdecl` 调用约定为例，整个过程涵盖实参入栈、`call` 指令保护现场、函数序言分配空间、计算取值、函数尾声释放局部变量以及调用者平栈等关键步骤。

## 示例代码

以下分析均基于这段加法调用：

```cpp
#include <iostream>

int sum(int a, int b) {
    int temp = 0;
    temp = a + b;
    return temp;
}

int main() {
    int a = 10;
    int b = 20;

    int ret = sum(a, b);
    std::cout << "ret:" << ret << std::endl;
    return 0;
}
```

## 1. 栈帧结构与相对寻址模型

每个正在执行的函数都拥有自己独立的栈空间切片，称为**栈帧（Stack Frame）**。

![[图片/SVG/1_1_1_2_1.svg|1700]]

### 1.1 核心指针与空间约定

- **地址约定**：图示采用“上方 = 低地址，下方 = 高地址”的视图。由于 x86 架构下栈是**向低地址生长**的，因此执行 `push` 压栈时，栈顶在视觉上向页面上方推进，对应内存地址数值递减；执行 `pop` 出栈时地址数值递增。详见[[1.3 进程的虚拟地址空间#5.3 堆和栈为什么相向生长？|堆栈相向生长的设计原因]]。
- **ESP (Stack Pointer，栈顶指针)**：始终指向当前已分配栈空间的最高点（数值上的最低内存地址）。函数执行期间如果有临时寄存器保护或子表达式计算，ESP 会频繁变化。
- **EBP (Base Pointer，基址/帧指针)**：指向当前栈帧的底部固定位置。函数序言执行完毕后，EBP 在整个函数体运行期间保持不变，作为读写局部变量与形参的固定坐标锚点。

### 1.2 相对寻址法则

有了固定的 EBP 作为原点，编译器在编译阶段就能静态计算出所有变量的相对偏移，避免受动态浮动的 ESP 干扰：

- **局部变量寻址 (`[ebp - 偏移量]`)**：局部变量分配在 EBP 的上方（更低地址处）。例如 `temp` 位于 `[ebp - 4]`。
- **保存的旧 EBP (`[ebp]`)**：当前 EBP 指向的位置正好存放着主调函数（`main`）原先的 EBP 地址。
- **返回地址 (`[ebp + 4]`)**：紧挨在旧 EBP 下方（更高地址处），由 `call` 指令在跳转前压入，指示函数执行完后回到哪里继续运行。
- **函数形参寻址 (`[ebp + 偏移量]`)**：形参由调用者压入，位于更高地址区。跨过 4 字节的旧 EBP 和 4 字节的返回地址后，第一个实参 `a` 位于 `[ebp + 8]`，第二个实参 `b` 位于 `[ebp + 12]`。

## 2. 局部变量与参数的汇编对照

在进入汇编前，先对比局部变量在内存中的实际落点：

| 变量定义 | 对应 32 位汇编指令 | 内存位置 | 说明 |
| :--- | :--- | :--- | :--- |
| `int a = 10;` (main 内) | `mov dword ptr [ebp-4], 0Ah` | `ebp - 4` | main 栈帧内部的局部变量 a |
| `int b = 20;` (main 内) | `mov dword ptr [ebp-8], 14h` | `ebp - 8` | main 栈帧内部的局部变量 b |
| `int temp = 0;` (sum 内) | `mov dword ptr [ebp-4], 0` | `ebp - 4` | sum 栈帧内部的局部变量 temp |

虽然 `main` 和 `sum` 内部都出现了 `[ebp - 4]`，但由于两者的 EBP 指向各自独立的基准地址，这两个内存槽位互不干扰。

## 3. 函数调用全生命周期演变

从 `main` 准备调用 `sum` 到最终清理现场，堆栈状态共经历四个核心演进阶段。

![[图片/SVG/1_1_1_2_2.svg|1700]]

### 3.1 步骤一：实参压栈（从右向左）

按照 `__cdecl` 调用约定，函数实参由调用者从右往左依次压栈：

```assembly
; 准备调用 sum(a, b)
mov eax, dword ptr [ebp-8]    ; 取出变量 b 的值 (20)
push eax                       ; 将实参 b 压入栈中 (先压右参数)
mov ecx, dword ptr [ebp-4]    ; 取出变量 a 的值 (10)
push ecx                       ; 将实参 a 压入栈中 (后压左参数)
```

两次 `push` 执行后，ESP 向上移动 8 字节（数值减小 8），此时栈顶正好是实参 `a`。

### 3.2 步骤二：执行 `call` 指令

```assembly
call sum                       ; 调用 sum 函数
```

CPU 在执行 `call` 时内部完成两项原子动作：
1. **压入返回地址**：将 `call` 指令紧接着的下一条指令地址（即函数返回后的接力点）自动压入栈顶，ESP 减小 4。
2. **转移控制权**：将指令寄存器 EIP 设置为 `sum` 函数入口地址，实现代码跳转。

### 3.3 步骤三：函数序言（Prologue，创建新栈帧）

进入 `sum` 函数后，前三条汇编指令负责搭建当前函数专属的栈帧环境：

```assembly
push ebp                       ; 1. 将调用者(main)的 ebp 压栈保存
mov ebp, esp                   ; 2. 将当前栈顶赋值给 ebp，确立 sum 的栈底基准
sub esp, 4Ch                   ; 3. 栈顶上移 76 字节，为局部变量预留空间
```

执行后：
- 旧的 `main` 栈底地址被妥善存放在栈中（即 `[ebp]` 位置）。
- EBP 指向新基准，接管当前栈底。
- ESP 减去 `0x4C`（Debug 模式下通常分配较大缓冲区并填充 `0xCC` 断点中断码，Release 优化下则按需精准分配）。

### 3.4 步骤四：执行函数体与结果返回

```assembly
mov dword ptr [ebp-4], 0       ; temp = 0
mov eax, dword ptr [ebp+8]     ; 读取参数 a (10) 送入 eax
add eax, dword ptr [ebp+0Ch]    ; 将参数 b (20) 累加到 eax
mov dword ptr [ebp-4], eax     ; temp = a + b
mov eax, dword ptr [ebp-4]     ; return temp：将最终返回值放入 eax 寄存器
```

函数计算结果并不保存在栈内存中，而是统一存放在通用寄存器 **EAX** 中带回。由于栈空间在返回后会被销毁，依赖硬件寄存器传递返回值是跨函数边界交接数据的标准方式。

### 3.5 步骤五：释放局部变量空间

```assembly
mov esp, ebp                   ; 将 esp 重置回 ebp 的位置
```

该指令让 ESP 瞬间落回当前栈帧的 EBP 基准点。原来由 `sub esp, 4Ch` 开辟的所有局部变量空间在逻辑上被一次性全部作废回收。

### 3.6 步骤六：函数尾声（Epilogue，还原调用者栈帧）

```assembly
pop ebp                        ; 将栈顶保存的旧 ebp 弹回 ebp 寄存器
```

此时栈顶刚好是指向 `main` 栈底的值。`pop ebp` 执行后，EBP 寄存器恢复为 `main` 函数原有的栈底数值，ESP 随之下移 4 字节，此时栈顶直接暴露出了先前 `call` 压入的返回地址。

### 3.7 步骤七：返回主调函数与调用者平栈

```assembly
ret                            ; 弹出栈顶的返回地址送入 EIP，CPU 跳回 main 函数继续执行
```

回到 `main` 之后，CPU 紧接着执行一条清理参数栈的指令：

```assembly
add esp, 8                     ; 恢复调用前压入的 2 个参数空间 (4*2=8 字节)
mov dword ptr [ebp-0Ch], eax   ; 将 eax 中的返回值写入 main 的 ret 变量
```

在 `__cdecl` 约定下，**由调用者负责清理参数栈空间**。`add esp, 8` 让 ESP 恢复到压参前的位置。到此为止，堆栈恢复完全平衡，整个函数调用周期闭环完成。

## 4. 关键底层机制盘点

- **实参从右向左入栈**：`__cdecl` 规约先压入最右边的实参，使得最左侧的第一个实参始终位于离返回地址最近的固定偏移处（`[ebp + 8]`）。这也是 C 语言支持 `printf` 等可变参数函数的基础。
- **返回地址由硬件指令维护**：`call` 自动压栈保护下一条 EIP，`ret` 自动弹栈交还控制权，配对出现。
- **EBP 形成调用链回溯**：由于每个栈帧的 `[ebp]` 都记录着上一层函数的 EBP，调试器（如 GDB）正是顺着这条指针链层层反查，还原出完整的函数调用栈轨迹（Call Stack Backtrace）。
- **EAX 规避栈生命周期问题**：4 字节或 8 字节（EDX:EAX）的基本数据类型通过寄存器回传，避免了栈销毁导致的数据丢失。

## 5. 常见陷阱与原理延伸

### 5.1 为什么禁止返回局部变量的指针？

```cpp
int* get_data() {
    int data = 10;
    return &data; // 危险操作：返回局部变量地址
}
```

当 `get_data()` 执行 `mov esp, ebp` 和 `pop ebp` 后，`data` 所在的栈内存已被逻辑释放。虽然该物理地址的数据暂时可能未被立刻擦除，但只要随后的代码发生任何新的函数调用、中断处理或操作系统调度，新栈帧就会立刻覆盖这片内存。此时主调函数使用该悬空指针（Dangling Pointer）读写数据，必然引发未定义行为或段错误。

### 5.2 缓冲区溢出机理与现代防御

当局部字符数组写入的数据超过其预设长度时，写入动作会沿着内存地址递增方向（向高地址）继续冲刷，接连覆写邻近的旧 EBP 与返回地址。

![[图片/SVG/1_1_1_2_3.svg|1700]]

一旦函数的返回地址被恶意篡改为外部注入的代码入口或特定跳转跳板（ROP Gadget），当函数触发 `ret` 指令时，CPU 就会无条件跳往攻击者指定的地址执行，从而实现控制流劫持。

现代编译器与操作系统针对此类攻击部署了三道联合防线：
- **Stack Canary（栈金丝雀 / GS 保护）**：在局部变量与旧 EBP 之间安插一个随机生成的校验值（Canary）。函数返回前先检查该数值是否遭到改变；一旦发现变动，立即触发 `__stack_chk_fail` 终止进程，阻断 `ret` 的执行。
- **DEP / NX（数据执行保护）**：通过 CPU 内存分页属性将栈内存严格标记为“只读写、不可执行”（No-Execute）。即便恶意代码被注入到栈空间，一旦 EIP 指向栈地址，硬件直接抛出段错误异常。
- **ASLR（地址空间布局随机化）**：程序每次加载启动时，操作系统随机偏移栈区、堆区以及共享动态库的映射基址，剥夺攻击者硬编码跳转地址的预测可能。

### 5.3 核心汇编指令速查

| 指令 | 核心动作 | 堆栈与寄存器变动 |
| :--- | :--- | :--- |
| `push X` | 将数据 X 压入栈 | `esp -= 4; *esp = X` |
| `pop X` | 从栈顶弹出数据至 X | `X = *esp; esp += 4` |
| `call ADDR` | 调用目标函数 | `push EIP_next; EIP = ADDR` |
| `ret` | 函数返回 | `pop EIP` |
| `mov ebp, esp` | 确立新栈帧基准 | `ebp = esp`（将当前栈顶快照为新栈底） |
| `add esp, N` | 平衡堆栈 | `esp += N`（丢弃栈顶 N 字节实参或临时数据） |

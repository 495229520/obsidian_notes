## 二、逐题精讲

### 错题 1 —— 编译四阶段顺序

**题目**：C/C++ 从源代码到可执行文件的四个阶段，正确顺序是？
**我选 C（预处理→汇编→编译→链接），正确是 B。**

正确顺序 —— **预处理 → 编译 → 汇编 → 链接**：

```text
.c/.cpp ──预处理──▶ .i ──编译──▶ .s ──汇编──▶ .o ──链接──▶ 可执行
```

> [!tip] 记忆钩子
> 谐音 **"预编汇链"**；产物链 `.i → .s → .o → 可执行`。我把"编译"和"汇编"倒了。

### 错题 3 —— `.s` → `.o` 属于哪个阶段

**题目**：把汇编代码 `.s` 翻成机器指令、生成可重定位目标文件 `.o` 的阶段是？
**我选 D（链接），正确是 C（汇编）。**

- **汇编器**：把 `.s`（汇编代码）翻成机器码，产出 `.o`，但外部符号地址还未定。
- **链接器**：把多个 `.o` 合并 + 符号解析 + 重定位，才产出可执行文件。

> [!warning] 易混
> `.o` 是**汇编阶段**的产物，不是链接。链接的输入才是 `.o`。

### 错题 9 —— `nm` 输出 `U printf` 的含义

**题目**：`nm` 输出中符号 `U printf` 表示？
**我选 B（局部函数），正确是 C（未定义符号）。**

`U` = **U**ndefined：本文件**引用了但未定义**该符号（`printf` 定义在 libc），留待链接时解析。

| 符号 | 含义 |
|------|------|
| `T`/`t` | 代码段函数（大写全局 / 小写 static 内部） |
| `D`/`d` | `.data` 已初始化变量（大写全局 / 小写内部） |
| `B`/`b` | `.bss` 未初始化变量 |
| `U` | 未定义（本文件引用、别处定义） |

### 错题 10 —— cdecl 参数压栈顺序

**题目**：cdecl 调用约定中，参数的压栈顺序是？
**我选 A（从左向右），正确是 B（从右向左）。**

**从右向左压** → 最后压的是**第一个（最左）参数**，它落在**最低地址**、紧挨返回地址，永远在 `ebp+8`。

> [!note] 为什么这样设计
> 第一个参数偏移固定（`ebp+8`）→ 支持**可变参数**（如 `printf(fmt, ...)`，先在固定位置拿到 fmt，再向高地址依次取后续参数）。若从左向右，第一个参数位置会随参数个数漂移。

**易错点纠正（我之前弄反的空间关系）**：

- 最右参数**先**压 → 在**最高地址**（`ebp+12`）→ 离 ebp **最远**
- 最左参数**后**压 → 在 `ebp+8` → 离 ebp **最近**
- 参数全在 ebp **上方**（`ebp+`）；局部变量在 ebp **下方**（`ebp-`）靠近 esp

### 错题 12 —— 堆和栈的生长方向

**题目**：堆和栈的生长方向是？
**我选 B（都向下），正确是 C。**

- **堆**：低地址 → 高地址（`malloc`/`new`）
- **栈**：高地址 → 低地址（每次 `call`/`push` 往下走）
- 二者**相向生长**，中间留最大空洞。我只答对了栈的方向。

单帧内部（已掌握，巩固）：`esp` 在低地址端（栈顶）、`ebp` 在高地址端（帧基准）；局部变量 `ebp-`、参数 `ebp+`。

### 错题 14 —— `.bss` 的磁盘占用（理由修正）

**题目（判对错）**：`.bss` 段在可执行文件里要占用和变量总大小一样多的磁盘空间。→ **错**
**我判"错"结论对，但理由不准。**

- 不是"占的磁盘**小于**变量大小"，而是 **`.bss` 在磁盘上占 0 字节**，只记录一个"需要多大"的尺寸数字。
- 真正的内存等**运行时**才分配并清零。
- 对比 `.data`：要把非零初值实打实存进文件，所以占磁盘。

> [!tip] 口诀
> **data 有初值占盘，bss 零初值不占盘（只记大小）。**

### 错题 16 —— 普通局部变量是否产生符号

**题目（判对错）**：普通局部变量会在符号表中产生一个符号。→ **错**
**我不确定。**

普通（非 static）局部变量**不产生符号**。编译器直接生成 `mov [ebp-4], ...` 操作栈空间的指令，名字在编译期就消化掉了。**只有全局变量、静态变量、函数**才进符号表。

### 错题 19 —— cdecl 由谁清理参数

**题目（判对错）**：cdecl 约定中，由被调用者(Callee)负责清理参数栈。→ **错**
**我不确定。**

cdecl 由 **调用者(Caller)** 清理，即 `call` 之后的 `add esp, 8`。正因为清理责任在调用者，才能支持**可变参数**（被调方不知道有几个参数，无法自清）。

> [!note] 对比
> `stdcall` 才是被调用者清理（`ret n`），常见于 Win32 API。

### 错题 20 —— 字符串字面量能否修改（重点误区）

**题目（判对错）**：`char* p = "hello"; *p='a';` 可以修改。→ **错**
**我以为会变成 "aello"，实际会段错误。**

- `"hello"` 在 **`.rodata`（只读段）**。
- `*p='a'` 想往只读内存写 → MMU 触发 **段错误（Segmentation Fault）程序崩溃**，**不会**变成 `"aello"`。
- `*p` 指向 `'h'` 的理解没错，但**只读段不可写**。

想真正修改，先准备可写副本：

```cpp
char buf[] = "hello";   // 栈上可写副本
buf[0] = 'a';           // OK -> "aello"

std::string s = "hello";
s[0] = 'a';             // OK
```

> [!tip] 一句话
> 指针能**读** `.rodata`，不能**写**；要写就先要一份可写副本。

### 错题 21 —— 段归属（全局变量 + 指针 vs 字面量）

**题目**：判断各变量/对象存储在哪个段。
**我把全局变量 a、b 当成栈，d 的 msg 与 "hello" 完全弄反。**

先看清作用域：`g1 / g2 / s1 / msg` 在 `func` **外面（全局）**，只有 `local / sl / p` 在函数内。

| 项 | 代码 | 我的答案 | 正确 | 备注 |
|----|------|---------|------|------|
| a | `int g1 = 10;` 全局非零 | 栈 | **`.data`** | 全局，不在栈 |
| b | `int g2 = 0;` 全局零初始化 | 栈 | **`.bss`** | 全局，不在栈 |
| c | `static int s1 = 5;` | `.data` | `.data` | ✓ |
| d | `msg` 指针 / `"hello"` | msg在rodata/hello在堆 | **msg在`.data` / "hello"在`.rodata`** | 完全弄反 |
| e | `int local = 1;` | 栈 | 栈 | ✓ |
| f | `static int sl;` | `.bss` | `.bss` | ✓ |
| g | `p` / `new int(7)` | p在栈/new在堆 | p在栈/new在堆 | ✓ |

**两个纠正点：**

1. **a、b 是全局变量，不在栈上。** 栈只放**函数内的普通局部变量**。判断顺序：先看**作用域**（全局/静态 → 静态存储区；函数内非 static → 栈），再看**初值**（非零 → `.data`，零/未初始化 → `.bss`）。
2. **d：msg 和 "hello" 弄反了**（同判断题 20 的"指针 vs 指向对象"坑）：
   - `msg` = 全局指针**变量本身**，已初始化非零 → **`.data`**（存的是地址值）
   - `"hello"` = 字符串字面量 → **`.rodata`**（只读）
   - **没有任何东西在堆**——这里没有 `new`/`malloc`

> [!tip] 口诀
> `.rodata` 存"hello"这串字符，`.data` 存"指向它的指针 msg"；全局变量永远不在栈。

### 错题 22 —— `nm` 符号标识（大小写 = 可见性）

**题目**：预测各符号的 `nm` 标识字母。
**我不确定。** 规律两条：**大写=全局可见（外部链接），小写=本文件可见（static/内部链接）**；字母本身表示所在段。

| 项 | 声明 | 符号 | 为什么 |
|----|------|------|--------|
| a | `int global_initialized = 42;` | **D** | 全局 + 已初始化非零 → `.data`，大写 |
| b | `int global_uninitialized;` | **B** | 全局 + 零初始化 → `.bss`，大写 |
| c | `static int static_initialized = 100;` | **d** | `.data` 但 `static` → 内部链接，**小写** |
| d | `static void helper() {}` | **t** | `.text` 但 `static` → 内部链接，小写 |
| e | `void public_function() {}` | **T** | `.text` 全局函数 → 大写 |
| f | `main` / `printf` | **T** / **U** | main 全局函数 T；printf 未定义（libc）→ **U** |

`nm` 字母速查表：

```text
T/t  .text 代码（函数）      大写全局 / 小写 static
D/d  .data 已初始化非零变量   大写全局 / 小写 static
B/b  .bss  零/未初始化变量    大写全局 / 小写 static
R/r  .rodata 只读常量
U    未定义（引用别处符号，等链接解析）
```

> [!note] 串联
> 与选择题 9（`U printf`）、判断题 16（局部变量不产生符号）是同一考点：**谁进符号表、标什么字母**。

### 错题 23 —— ebp± 寻址（概念对，表述待精确）

**题目**：为什么局部变量用 `ebp-`、参数用 `ebp+`？`ebp+8` 跳过了什么？
**方向和结构我都答对了**：ebp 固定基准，上方（`ebp+`，高地址）是返回地址和参数，下方（`ebp-`，低地址）是本帧局部变量。只需把 `ebp+8` 说精确——它跳过**两个 4 字节**：

```text
ebp+8  ← 第一个参数 a      ← 参数从这里开始
ebp+4  ← 返回地址（call 压入）
ebp+0  ← saved ebp（push ebp 压入）   ← ebp 指这里
ebp-4  ← 第一个局部变量
```

> [!tip] 标准表述
> `ebp+0` 是**保存的旧 ebp**，`ebp+4` 是**返回地址**，跳过这两格，第一个参数才在 `ebp+8`。

### 错题 25 —— strcpy 是"溢出"不是"截断"

**题目**：`char buf[8]; strcpy(buf, src);` 找错。
**我答"信息损失"，后果说反了。**

`strcpy` **不截断**，它一路复制到 `src` 的 `\0`。`buf[8]` 装不下就**越过数组边界继续往高地址写**，覆盖栈上的 **saved ebp 和返回地址**：

- 真正后果 = **缓冲区溢出**：破坏栈帧，`ret` 跳到被篡改的地址 → 崩溃，甚至被攻击者劫持控制流。
- 不是"信息损失/截断"——那是 `strncpy` 缓冲区不够时的行为。

**修复**：用 `std::string`，或 `snprintf`/有界拷贝并检查长度，杜绝 `strcpy`。

> [!warning] 记忆
> `strcpy` 溢出 = **写越界**（破坏相邻内存），不是"少写了"。

### 错题 27 —— 是重复定义(ODR)，不是竞态

**题目**：头文件里 `int counter = 0;` 被多个 `.cpp` 包含，找错。
**我答"竞态"，方向错了。**

"竞态(race condition)"是**多线程并发**问题，与此无关。真 bug 是 **ODR 违反 / 重复定义**：头文件里的 `int counter = 0;` 是**定义**，被 N 个 `.cpp` 包含 → N 份强符号 → 链接报 `multiple definition of 'counter'`。

**修复**：

```cpp
// util.h —— 只声明
extern int counter;
// 某一个 .cpp —— 唯一定义
int counter = 0;
// 或 C++17：头文件里 inline int counter = 0;
```

### 错题 28 —— 跨文件引用全局变量用 extern

**题目**：`b.cpp` 里 `int gdata;` 想引用 `a.cpp` 的 `gdata`，找错。
**我误判为局部变量，还想用 `#include .cpp` / static。**

纠正两个误区：

1. `gdata`（`a.cpp` 里 `int gdata = 999;`）是**全局变量**，不是局部。
2. **不能 `#include "a.cpp"`**（把整个源文件塞进来 → 重复定义）；**不能用 static**（static 是内部链接，反而让别的文件看不见它，正好相反）。

正确：`b.cpp` 里写**声明** `extern int gdata;`（对应 `nm` 的 `U`），链接器再去 `a.o` 的 `D gdata` 解析。

```cpp
// b.cpp
extern int gdata;      // 声明：别处定义的，我引用
int x = gdata + 1;
```

> [!note] 串联
> 呼应错题 46 类考点：**声明用 `extern`（承诺有）→ 符号 U；定义分配存储（真的有）→ 符号 D。**

### 错题 29 —— Modern C++ 重写（三个语法陷阱）

**题目**：把 `malloc` 版 `makeBuf` 用 Modern C++ 重写。
**我用了 vector 方向对，但代码编译不过。**

原始错误代码的三个 bug：

```cpp
int* makeBuf(int n) {        // ① 返回类型还是 int*，却返回 vector → 类型不匹配
   std::vector<int> p();     // ② 最令人烦恼的解析：声明了一个函数 p，不是建 vector！
    for(int i=0;i<n;i++)
        p[i] = i;            // ③ 就算 p 是空 vector，size=0，p[i] 越界
    return p;
}
```

**陷阱②「最令人烦恼的解析(most vexing parse)」**：`std::vector<int> p();` 被编译器当成"声明一个无参、返回 `vector<int>` 的**函数** p"。要建大小为 n 的 vector 得写 `p(n)`（有实参就不会被误读）。

**正确写法：**

```cpp
#include <vector>
#include <numeric>

std::vector<int> makeBuf(int n) {   // 返回类型改成 vector
    std::vector<int> v(n);          // 建 n 个元素，注意 (n) 不是 ()
    std::iota(v.begin(), v.end(), 0); // 填 0,1,2,...
    return v;                       // 移动/RVO 返回，自动释放；调用方无需 free
}
```

**另一个我踩过的坑：`v(n)` 与 `push_back` 不能混用。**

- `std::vector<int> v(n);` = **已经建好 n 个元素**（全 0），要填就用**下标** `v[i] = i;`
- `push_back` 是**追加**，必须从**空 vector** 开始，否则 `v(n)` + n 次 push_back = **2n 个元素**（前 n 个是 0）

```cpp
// 写法 A：预分配 + 下标赋值
std::vector<int> v(n);
for (int i = 0; i < n; ++i) v[i] = i;

// 写法 B：空 vector + reserve + push_back
std::vector<int> v;
v.reserve(n);                       // 只预留容量(capacity)，不建元素
for (int i = 0; i < n; ++i) v.push_back(i);
```

> [!tip] size vs capacity
> `v(n)` 直接建 n 个元素（size=n）；`reserve(n)` 只预留容量（capacity=n, size=0）。`push_back` 配 `reserve`，下标赋值配 `v(n)`。

### 知识点 38 —— Modern C++ 重构：消灭全局裸指针

**题目**：把"头文件全局裸指针 + `new[]` 无 `delete`"的计数器模块用 Modern C++ 重写。

原代码三宗罪：① 头文件里定义 `int* g_counts`（多个 `.cpp` 包含 → ODR 重复定义）；② `new int[n]` 全程无 `delete[]`（内存泄漏）；③ 裸全局可变状态不可控。

```cpp
// counter.hpp
#include <vector>
class Counter {
public:
    explicit Counter(int n) : counts_(n, 0) {}   // RAII：构造即分配
    void inc(int i) { ++counts_.at(i); }         // at() 越界抛异常
    int get(int i) const { return counts_.at(i); }
private:
    std::vector<int> counts_;                    // 析构自动释放，无裸 new/delete
};
```

| 坏味道 | Modern 方案 | 好处 |
|--------|------------|------|
| 头文件全局 `int* g_counts` | 类私有成员 `counts_` | 无 ODR，每对象独立 |
| `initCounts(n)` 手动初始化 | 构造函数 | 构造即可用，不会忘 |
| 裸 `new int[n]` | `std::vector<int>` | 离开作用域自动释放，零泄漏 |
| 无边界检查 `g_counts[i]` | `.at(i)` | 越界抛 `std::out_of_range`，非 UB |

> [!tip] RAII 一句话
> 资源生命周期绑定到对象生命周期：构造时获取、析构时释放。`std::vector` 是 RAII 典范，不用手动 `delete`。

### 错题 39 —— Section→内存映射 & 堆栈为何不在文件里

**题目**：Section（文件层面）如何映射到运行时内存？为什么堆和栈不是 `.o` 里预先存在的 Section？
**我的错误**：① 把答案写成了编译流程（预处理/编译/汇编/链接）——答非所问；② 说"链接把 `.s` 变成 `.o`"（错，是**汇编器**做的）；③ 说堆栈位置"由符号表决定"（错，堆栈是**运行时**动态生成，根本不在符号表）；④ 二刷又说成"用户态映射到内核态"（错）。

**第一问：Section → 内存映射**。程序启动时 OS 的**加载器(loader)** 把文件里的 Section 映射到**进程虚拟地址空间**（仍在用户态，不涉及内核态切换）：

| 文件 Section | 运行时内存区域 | 权限 |
|---|---|---|
| `.text` | 代码区 | 只读 + 可执行 |
| `.rodata` | 只读数据区 | 只读 |
| `.data` | 已初始化数据区 | 可读写 |
| `.bss` | 未初始化数据区 | 可读写，运行时清零 |

**第二问：堆栈为何不在文件里**。因为它们是**运行时才产生的**：

- **堆**：`new`/`malloc` 运行时才向 OS 申请（`brk`/`mmap`），分配多少、何时分配，编译时完全未知。
- **栈**：函数调用时才动态创建栈帧、返回即销毁，文件里没法预存"将来有哪些调用"。

所以 `.o` 里只有 `.text/.data/.bss/.rodata`，**没有 heap/stack section**。

> [!warning] 我踩的坑
> 编译流程（源码→可执行）和内存映射（文件→进程地址空间）是**两件事**。本题问的是后者。别一看到 `.o` 就背编译四阶段。

### 错题 40 —— 字符串字面量永远在 `.rodata`

**题目**：`const char* msg = "hello";` 中 msg 与 "hello" 各在哪？
**我的错误**：msg 位置答对了（全局→`.data`，局部→栈），但说"局部的 'hello' 在栈中"——**错**。

**`"hello"` 永远在 `.rodata`，与写在全局还是函数内无关。** 字符串字面量是**编译期常量**，编译器生成目标文件时就把它固定进 `.rodata`。

```cpp
void func() {
    const char* msg = "hello";  // msg 在栈，但 "hello" 仍在 .rodata
}
```

```text
栈：[msg] ───存的是地址───▶ .rodata: ['h','e','l','l','o','\0']
```

| | msg（指针变量本身） | "hello"（指向的对象） |
|---|---|---|
| 位置由谁决定 | 声明位置（全局→`.data`/局部→栈） | 恒由编译器决定 → `.rodata` |
| 能否修改 | 能（可指向别处） | 不能（写入段错误） |

> [!tip] 一句话
> `const char*` 的 `const` 管的是"指向的内容只读"，不是"指针本身不可改"。指针位置随声明，字面量位置恒在 `.rodata`。

### 错题 41 —— 非静态成员变量跟随对象本体（根本误解）

**题目**：非静态 vs 静态成员变量存储上的根本区别？`A* p = new A;` 时 `p->x`、`A::count` 各在哪？
**我的错误**：以为非静态成员"按声明位置决定段（函数内→栈、全局→`.data`）"——把成员变量当成了普通变量。

**关键：非静态成员变量不能脱离对象独立存在，它的位置取决于"对象本体在哪"，而不是它写在哪。**

```cpp
A  a;            // 对象在栈 → a.x 在栈
A* p = new A;    // 对象在堆 → p->x 在堆
static A g;      // 对象在 .bss → g.x 在 .bss
```

本题 `A* p = new A;`：

| | 存哪 | 为什么 |
|---|---|---|
| `p` 本身 | 栈 | 局部指针变量 |
| `p->x`（非静态） | **堆** | 对象 `new` 在堆，成员跟对象走 |
| `A::count`（静态） | **`.data`/`.bss`** | 不属于对象，全类共享一份 |

> [!warning] 思维纠正
> **普通变量**看声明位置；**成员变量**看所属对象创建在哪。同一个 class，成员 x 可在栈/堆/`.data`——全看对象怎么建的。静态成员则像全局变量，全类一份，生命周期整个程序。

### 错题 42 —— 悬垂 vs 栈溢出：同源于"栈又小又短命"

**题目**：为什么"不能返回局部变量地址""大数组放栈上易崩溃"本质是同一类问题？
**我的错误**：前半（返回局部地址→栈帧销毁→悬垂）答对；后半说"大数组崩溃因为栈频繁变动、要遵循 RAII"——**原因说错**。

**大数组栈上崩溃与 RAII、栈变动无关，真正原因是：栈容量有限且固定（线程栈通常 1~8MB）。**

```cpp
void func() {
    int huge[10000000];   // 约 40MB，远超栈容量 → 栈溢出崩溃
}
```

**题眼——两者同源**：

| 表现 | 触发的栈特性 |
|---|---|
| 返回局部地址 → 悬垂 | 栈内存**随栈帧释放**（生命周期短） |
| 大数组放栈 → 崩溃 | 栈内存**容量有限**（1~8MB） |

一个栽在"栈会被回收"，一个栽在"栈放不下"，根子都是**栈这块内存又小又短命**。解决办法都是把对象移到堆：

```cpp
std::vector<int> huge(10000000);   // 放堆，容量大、生命周期自控
```

> [!tip] 纠正
> `vector` 能解决问题是因为**数据放到了堆上**（堆大、跨函数存活），不是因为"遵循 RAII"。RAII 解决的是"堆内存谁释放"，不是"大数组为何不能放栈"。

### 错题 43 —— 强/弱/未定义符号解析规则

**题目**：强符号、弱符号（W）、未定义符号（U）在链接时如何解析？弱符号有何用途？
**我的状态**：不懂。

| 符号 | `nm` | 是什么 |
|---|---|---|
| 强符号 | `T`/`D` | 已初始化的全局变量、函数定义 |
| 弱符号 | `W`/`V` | 未初始化全局变量、`__attribute__((weak))` 标记 |
| 未定义 | `U` | 本文件引用、别处定义 |

**链接器三条解析规则（面试高频）：**

1. **强符号只能有一个** —— 两处都强 → `multiple definition` 报错。
2. **强 + 弱 → 选强**，弱的被忽略。
3. **多个弱 → 任选一个**（通常占空间最大的）。
4. **U 必须被解析** —— 找不到定义 → `undefined reference`。

**弱符号用途：**

```cpp
// 库的默认实现（弱符号）
__attribute__((weak)) void on_error() { /* 默认空 */ }
// 用户自定义（强符号）→ 自动覆盖库默认版
void on_error() { log("出错了"); }
```

① 提供**可被用户覆盖的默认实现**（不改库代码就能替换）；② 未初始化全局变量默认是弱符号，避免多文件同名 `int g;` 直接链接失败。

> [!note] 一句话
> 强唯一、弱可多；强弱并存选强、全弱任选其一；U 必须解析。弱符号主要做"可覆盖的默认实现"。

## 二·补·附 —— 符号表三大作用 & 重定位

配合错题 39/43，把符号表本身讲透。

**符号表三大作用：**

1. **符号解析**：链接器扫描各 `.o` 符号表，把 `U foo`（引用）与某文件的 `T foo`（定义）配对。
2. **重定位**：编译单个 `.o` 时不知最终地址，跳转填占位符；链接合并后地址定了，回填真实地址。
3. **调试**：调试器用符号表把地址翻回函数名/变量名/行号（Debug 版更大就因保留完整符号表）。

**重定位举例：**

```cpp
// main.cpp 调用 foo() → 编译成 main.o 时：
call [????]    // foo 在哪不知道，先占位
```

```cpp
// 链接合并 main.o + foo.o 后，地址定了：
//   0x4050 → foo
call 0x4050    // 回填 foo 的真实地址 ← 这就是重定位
```

> [!tip] 一句话
> 编译时不知别人在哪就先留空，链接时地址凑齐再回来把空填上 = 重定位。符号表就是链接器的"字典"。

## 三、知识点总复习（本次暴露的薄弱点）

1. **编译流水线**：预处理 `.i` → 编译 `.s` → 汇编 `.o` → 链接 可执行（"预编汇链"）。
2. **符号表标识**：`T/t` 函数、`D/d` 已初始化、`B/b` 未初始化、`U` 未定义。
3. **cdecl 三件套**：从右向左压栈；第一个参数固定在 `ebp+8`；**调用者**清理 → 支持可变参数。
4. **栈帧空间方向**：esp 低 / ebp 高；参数 `ebp+`（上）、局部变量 `ebp-`（下）；堆栈相向生长。
5. **段与磁盘**：`.data` 占盘、`.bss` 不占盘只记大小、`.rodata` 只读（写=段错误）。
6. **符号产生规则**：全局 / 静态 / 函数才进符号表，普通局部变量不进。
7. **段归属判断法**：先看作用域（全局/静态 → 静态区；函数内非 static → 栈），再看初值（非零 → `.data`，零/未初始化 → `.bss`）；全局变量永远不在栈。
8. **指针 vs 指向对象**：指针变量本身按它的作用域定段（全局 → `.data`），指向的内容另有其段（字面量 → `.rodata`，`new` → 堆）。
9. **`nm` 大小写规则**：大写 = 全局可见，小写 = `static` 内部链接；`T/t`=代码、`D/d`=已初始化、`B/b`=未初始化、`R/r`=只读、`U`=未定义。
10. **溢出 ≠ 截断**：`strcpy` 越界是往相邻内存写坏数据（破坏 saved ebp/返回地址），不是"少写"；有界拷贝用 `std::string`/`snprintf`。
11. **头文件放声明不放定义**：变量重复定义(ODR)报 `multiple definition`；头文件用 `extern`（或 C++17 `inline`），定义放唯一 `.cpp`。跨文件引用全局变量用 `extern`，绝不 `#include .cpp`、绝不用 `static`（static 是内部链接会适得其反）。
12. **most vexing parse**：`vector<int> p();` 是声明函数不是建对象；建对象要 `p(n)`。`v(n)`（建 n 个元素，用下标赋值）与 `reserve(n)`+`push_back`（空表追加）不能混用——`size` vs `capacity`。
13. **Section→内存映射**：加载器把 `.text/.rodata/.data/.bss` 映射到进程虚拟地址空间的代码区/只读区/数据区/清零区（仍在用户态）；**堆栈不在文件里**，是运行时动态生成（堆靠 `new/malloc`、栈靠函数调用）。别把内存映射答成编译四阶段。
14. **字符串字面量恒在 `.rodata`**：无论写在全局还是函数内。指针 msg 的位置随声明（全局→`.data`/局部→栈），指向的字面量恒在 `.rodata`。
15. **成员变量跟随对象本体**：非静态成员在哪取决于**对象**建在哪（栈/堆/`.data`），不是它声明在哪；静态成员像全局变量，全类一份存 `.data`/`.bss`。普通变量看声明位置，成员变量看对象位置。
16. **悬垂 vs 栈溢出同源**：都因"栈内存又小又短命"——返回局部地址栽在"随帧释放"，大数组栽在"容量有限(1~8MB)"。解决都是移到堆（`vector`/智能指针）；`vector` 有效是因为数据在堆，不是因为 RAII。
17. **强/弱/未定义符号**：强唯一、弱可多、强弱并存选强、全弱任选、U 必须解析。弱符号用于"可被用户覆盖的默认实现"。
18. **符号表三大作用**：符号解析（配对 U 与定义）、重定位（回填占位地址）、调试（地址↔名字）。重定位 = 编译时留空、链接时回填真实地址。

> [!tip] 交互动画版
> [▶ 在浏览器中打开逐帧动画](<../1. 计算机基础/函数调用栈-main调用sum.html>)（可播放/单步/点击汇编跳转）。更多配套动画见 [[计算机基础·动画合集]]。

**读图要点：**

- **esp（棕）** 随 `push`/`call` 一路走向低地址、`sub esp` 到最低，再随尾声 `mov esp,ebp`/`pop ebp`/`ret` 逐步回升。
- **ebp（蓝）** 在步骤 5 `mov ebp,esp` 才降到帧基准并**保持不动**，步骤 8 `pop ebp` 一次性还原。
- 走完第 10 步 `add esp,8`，esp 回到 `0x1000`、ebp 回到 `0x1020`，**与调用前完全一致** → main 栈帧被精确恢复，这就是调用能层层嵌套的根本。
- 两条对称关系：`push ebp`+`sub esp` ⟷ `mov esp,ebp`+`pop ebp`；`call` 压返回地址 ⟷ `ret` 弹返回地址。

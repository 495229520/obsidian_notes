## 二、逐题精讲

### 错题 1 —— 编译四阶段顺序

**题目**：C/C++ 从源代码到可执行文件的四个阶段，正确顺序是？
**我选 C（预处理→汇编→编译→链接），正确是 B。**

正确顺序 —— **预处理 → 编译 → 汇编 → 链接**：

```text
.c/.cpp ──预处理──▶ .i ──编译──▶ .s ──汇编──▶ .o ──链接──▶ 可执行
```

> [!tip] 记忆钩子
> 谐音 **"预编汇链"**；产物链 `.i → .s → .o → 可执行`。我把"编译"和"汇编"倒了。

---

### 错题 3 —— `.s` → `.o` 属于哪个阶段

**题目**：把汇编代码 `.s` 翻成机器指令、生成可重定位目标文件 `.o` 的阶段是？
**我选 D（链接），正确是 C（汇编）。**

- **汇编器**：把 `.s`（汇编代码）翻成机器码，产出 `.o`，但外部符号地址还未定。
- **链接器**：把多个 `.o` 合并 + 符号解析 + 重定位，才产出可执行文件。

> [!warning] 易混
> `.o` 是**汇编阶段**的产物，不是链接。链接的输入才是 `.o`。

### 错题 9 —— `nm` 输出 `U printf` 的含义

**题目**：`nm` 输出中符号 `U printf` 表示？
**我选 B（局部函数），正确是 C（未定义符号）。**

`U` = **U**ndefined：本文件**引用了但未定义**该符号（`printf` 定义在 libc），留待链接时解析。

| 符号 | 含义 |
|------|------|
| `T`/`t` | 代码段函数（大写全局 / 小写 static 内部） |
| `D`/`d` | `.data` 已初始化变量（大写全局 / 小写内部） |
| `B`/`b` | `.bss` 未初始化变量 |
| `U` | 未定义（本文件引用、别处定义） |

### 错题 10 —— cdecl 参数压栈顺序

**题目**：cdecl 调用约定中，参数的压栈顺序是？
**我选 A（从左向右），正确是 B（从右向左）。**

**从右向左压** → 最后压的是**第一个（最左）参数**，它落在**最低地址**、紧挨返回地址，永远在 `ebp+8`。

> [!note] 为什么这样设计
> 第一个参数偏移固定（`ebp+8`）→ 支持**可变参数**（如 `printf(fmt, ...)`，先在固定位置拿到 fmt，再向高地址依次取后续参数）。若从左向右，第一个参数位置会随参数个数漂移。

**易错点纠正（我之前弄反的空间关系）**：

- 最右参数**先**压 → 在**最高地址**（`ebp+12`）→ 离 ebp **最远**
- 最左参数**后**压 → 在 `ebp+8` → 离 ebp **最近**
- 参数全在 ebp **上方**（`ebp+`）；局部变量在 ebp **下方**（`ebp-`）靠近 esp

### 错题 12 —— 堆和栈的生长方向

**题目**：堆和栈的生长方向是？
**我选 B（都向下），正确是 C。**

- **堆**：低地址 → 高地址（`malloc`/`new`）
- **栈**：高地址 → 低地址（每次 `call`/`push` 往下走）
- 二者**相向生长**，中间留最大空洞。我只答对了栈的方向。

单帧内部（已掌握，巩固）：`esp` 在低地址端（栈顶）、`ebp` 在高地址端（帧基准）；局部变量 `ebp-`、参数 `ebp+`。

### 错题 14 —— `.bss` 的磁盘占用（理由修正）

**题目（判对错）**：`.bss` 段在可执行文件里要占用和变量总大小一样多的磁盘空间。→ **错**
**我判"错"结论对，但理由不准。**

- 不是"占的磁盘**小于**变量大小"，而是 **`.bss` 在磁盘上占 0 字节**，只记录一个"需要多大"的尺寸数字。
- 真正的内存等**运行时**才分配并清零。
- 对比 `.data`：要把非零初值实打实存进文件，所以占磁盘。

> [!tip] 口诀
> **data 有初值占盘，bss 零初值不占盘（只记大小）。**

---

### 错题 16 —— 普通局部变量是否产生符号

**题目（判对错）**：普通局部变量会在符号表中产生一个符号。→ **错**
**我不确定。**

普通（非 static）局部变量**不产生符号**。编译器直接生成 `mov [ebp-4], ...` 操作栈空间的指令，名字在编译期就消化掉了。**只有全局变量、静态变量、函数**才进符号表。

---

### 错题 19 —— cdecl 由谁清理参数

**题目（判对错）**：cdecl 约定中，由被调用者(Callee)负责清理参数栈。→ **错**
**我不确定。**

cdecl 由 **调用者(Caller)** 清理，即 `call` 之后的 `add esp, 8`。正因为清理责任在调用者，才能支持**可变参数**（被调方不知道有几个参数，无法自清）。

> [!note] 对比
> `stdcall` 才是被调用者清理（`ret n`），常见于 Win32 API。

---

### 错题 20 —— 字符串字面量能否修改（重点误区）

**题目（判对错）**：`char* p = "hello"; *p='a';` 可以修改。→ **错**
**我以为会变成 "aello"，实际会段错误。**

- `"hello"` 在 **`.rodata`（只读段）**。
- `*p='a'` 想往只读内存写 → MMU 触发 **段错误（Segmentation Fault）程序崩溃**，**不会**变成 `"aello"`。
- `*p` 指向 `'h'` 的理解没错，但**只读段不可写**。

想真正修改，先准备可写副本：

```cpp
char buf[] = "hello";   // 栈上可写副本
buf[0] = 'a';           // OK -> "aello"

std::string s = "hello";
s[0] = 'a';             // OK
```

> [!tip] 一句话
> 指针能**读** `.rodata`，不能**写**；要写就先要一份可写副本。

## 三、知识点总复习（本次暴露的薄弱点）

1. **编译流水线**：预处理 `.i` → 编译 `.s` → 汇编 `.o` → 链接 可执行（"预编汇链"）。
2. **符号表标识**：`T/t` 函数、`D/d` 已初始化、`B/b` 未初始化、`U` 未定义。
3. **cdecl 三件套**：从右向左压栈；第一个参数固定在 `ebp+8`；**调用者**清理 → 支持可变参数。
4. **栈帧空间方向**：esp 低 / ebp 高；参数 `ebp+`（上）、局部变量 `ebp-`（下）；堆栈相向生长。
5. **段与磁盘**：`.data` 占盘、`.bss` 不占盘只记大小、`.rodata` 只读（写=段错误）。
6. **符号产生规则**：全局 / 静态 / 函数才进符号表，普通局部变量不进。

## 四、函数调用栈变化图（配合错题 10 / 12）

`main` 调用 `sum(10, 20)` 全过程中 `esp` / `ebp` 的逐帧轨迹。左侧是完整栈帧布局，右侧网格标出 11 步里两个指针的位置移动：

![[图片/1.C++基础/1. 计算机基础/1_1_1_5_1.svg|900]]

**读图要点：**

- **esp（棕）** 随 `push`/`call` 一路走向低地址、`sub esp` 到最低，再随尾声 `mov esp,ebp`/`pop ebp`/`ret` 逐步回升。
- **ebp（蓝）** 在步骤 5 `mov ebp,esp` 才降到帧基准并**保持不动**，步骤 8 `pop ebp` 一次性还原。
- 走完第 10 步 `add esp,8`，esp 回到 `0x1000`、ebp 回到 `0x1020`，**与调用前完全一致** → main 栈帧被精确恢复，这就是调用能层层嵌套的根本。
- 两条对称关系：`push ebp`+`sub esp` ⟷ `mov esp,ebp`+`pop ebp`；`call` 压返回地址 ⟷ `ret` 弹返回地址。

## 一、选择题（概念基础）

**1.** 关于 `class` 和 `struct`，唯一的本质区别是：
- A. struct 不能有成员函数　　B. class 不能继承
- C. 默认访问权限与默认继承方式不同　　D. struct 不能有构造函数

**2.** 用 `class` 定义类、用 `struct` 定义结构体，二者**默认继承方式**分别是：
- A. 都是 public　　B. 都是 private
- C. class 是 private，struct 是 public　　D. class 是 public，struct 是 private

**3.** 下列关于 `this` 指针的说法，**错误**的是：
- A. 普通成员函数中 `this` 类型是 `ClassName* const`
- B. const 成员函数中 `this` 类型是 `const ClassName* const`
- C. 静态成员函数也有 `this` 指针
- D. `this` 由编译器隐式传入

**4.** 静态成员函数**不能**直接访问非静态成员，根本原因是：
- A. 语法不允许　　B. 静态函数没有 `this` 指针
- C. 非静态成员是私有的　　D. 静态函数在编译期执行

**5.** 关于拷贝构造函数 `ClassName(const ClassName& other)`，参数必须是**引用**的原因是：
- A. 提高效率　　B. 防止修改 other
- C. 否则按值传参会无限递归调用拷贝构造　　D. 语法规定

**6.** 在常见 4 字节对齐规则、64 位平台下，`class A { int x; char c; };` 的 `sizeof(A)` 是：
- A. 5　　B. 8　　C. 9　　D. 12

**7.** `class E {};`（空类）的 `sizeof(E)` 是：
- A. 0　　B. 1　　C. 4　　D. 8

**8.** 一个含**虚函数**的类 `class V { int x; virtual void f(); };`，64 位平台下 `sizeof(V)` 通常是：
- A. 4　　B. 8　　C. 12　　D. 16

**9.** 下列关于虚函数的说法，**正确**的是：
- A. 构造函数可以是虚函数
- B. 静态成员函数可以是虚函数
- C. 析构函数可以且（多态基类）应该是虚函数
- D. 内联函数一定不能是虚函数

**10.** 通过**基类指针**删除一个**派生类对象**，若基类析构函数非虚，结果是：
- A. 正常析构　　B. 编译错误
- C. 只调用基类析构，派生类资源可能泄漏　　D. 调用两次析构

**11.** 实现**动态多态**必须同时满足的条件**不包括**：
- A. 继承关系　　B. 基类有虚函数
- C. 通过基类指针或引用调用　　D. 派生类必须是抽象类

**12.** 关于纯虚函数 `virtual void f() = 0;`，**错误**的是：
- A. 含纯虚函数的类不能实例化
- B. 纯虚函数绝对不能有函数体
- C. 派生类不实现它则自己也是抽象类
- D. 它强制派生类提供实现

**13.** 安全的**向下转型**（基类指针 → 派生类指针）应优先使用：
- A. C 风格强制转换　　B. `static_cast`
- C. `reinterpret_cast`　　D. `dynamic_cast`

**14.** 关于友元（friend）关系，**正确**的是：
- A. 是双向的　　B. 可以传递　　C. 可以被继承　　D. 单向、不传递、不继承

**15.** C++17 中，想在头文件里直接定义并初始化类的静态成员变量，最简洁的写法是：
- A. `static int x = 0;`　　B. `const static int x = 0;`
- C. `inline static int x = 0;`　　D. 必须在 .cpp 中类外定义

> [!success]- 参考答案（第一节）
> 1. **C**。`class` 默认成员 `private`、默认 `private` 继承；`struct` 默认成员 `public`、默认 `public` 继承。除此之外二者完全等价（都能有成员函数、构造、继承）。
> 2. **C**。同上：默认继承方式 class=private、struct=public。
> 3. **C**。静态成员函数不与对象绑定，**没有 `this`**，故不能直接访问非静态成员。
> 4. **B**。没有 `this` 就无法定位"哪个对象"的非静态成员。
> 5. **C**。若按值传参，构造这个值参本身又要调拷贝构造……无限递归。所以必须按引用；`const` 是为不改原对象。
> 6. **B**。`int`(4) + `char`(1) + 3 填充 = 8（总大小须为最大成员 4 的倍数）。
> 7. **B**。空类大小为 1，保证不同对象有不同地址。
> 8. **D**。64 位：vptr(8) + int(4) + 4 填充 = 16。
> 9. **C**。构造函数不能虚（构造时 vptr 尚未就绪、且需确定类型）；静态函数无 this 不能虚；多态基类析构**应**为虚。D 错：虚函数也可被内联（编译器能静态确定类型时）。
> 10. **C**。非虚析构 + 基类指针 delete → 只走 `~Base()`，派生类析构不执行，资源泄漏（UB）。
> 11. **D**。多态不要求派生类是抽象类。需要的是"继承 + 虚函数 + 指针/引用调用"。
> 12. **B**。纯虚函数**可以**有函数体（类外定义），常用于提供默认实现，但类仍是抽象类。
> 13. **D**。`dynamic_cast` 运行时检查类型，失败返回 `nullptr`（引用版抛 `bad_cast`），最安全。
> 14. **D**。友元三特性：单向、不传递、不继承。
> 15. **C**。`inline static`（C++17）允许类内定义并初始化，链接器保证全程序唯一实例。

## 二、概念辨析（判断对错并说明理由）

**16.** 成员函数的代码会存放在每个对象内部，所以对象越多占用内存越大。

**17.** 静态成员变量会计入 `sizeof(ClassName)`。

**18.** const 成员函数内绝对不能修改任何成员变量。

**19.** 构造函数可以重载，析构函数也可以重载。

**20.** 成员初始化列表中成员的初始化顺序，由列表中书写的先后顺序决定。

**21.** 只要给单参数构造函数加 `explicit`，就能禁止该构造函数参与隐式类型转换。

**22.** 派生类的同名函数只会隐藏基类中**参数相同**的那个重载，参数不同的重载仍可直接调用。

**23.** `private` 继承下，仍然可以在类外把派生类对象的地址赋给基类指针。

**24.** 把派生类对象赋值给基类对象（值语义）时会发生对象切片，导致多态失效。

**25.** 在基类的构造函数中调用虚函数，会调用到派生类重写的版本。

**26.** 虚继承（虚基类）能保证菱形继承中共同基类只有一份实例。

**27.** `new[]` 分配的数组可以用 `delete`（不带 `[]`）释放，只要元素是内置类型。

**28.** `dynamic_cast` 可以用于任何类之间的向下转型，不要求基类有虚函数。

**29.** 接口类（interface）是所有成员函数都是纯虚函数、且没有数据成员的抽象类。

> [!success]- 参考答案（第二节）
> 16. **错**。成员函数代码在代码区只有**一份**，被所有对象共享，靠 `this` 区分对象；不计入对象大小。
> 17. **错**。静态成员属于类、存于静态区，**不计入** `sizeof`。
> 18. **错**。const 成员函数不能改普通成员，但能改 `mutable` 成员（如缓存、计数）。
> 19. **错**。构造函数能重载；**析构函数不能重载**，每个类只有一个 `~ClassName()`。
> 20. **错**。初始化顺序由**成员声明顺序**决定，与初始化列表书写顺序无关——这是经典 bug 源。
> 21. **对**。`explicit` 禁止该构造函数的隐式转换，必须显式构造。
> 22. **错**。名称隐藏是**按名字**隐藏：派生类一旦定义同名函数，会隐藏基类**所有**同名重载（即使参数不同）。要恢复需 `using Base::func;`。
> 23. **错**。`private`（及 `protected`）继承不对外暴露 is-a 关系，类外不能把派生类指针隐式转成基类指针。
> 24. **对**。值语义只拷贝基类子对象，派生部分被"切掉"，通过该基类对象调用虚函数走基类版本。
> 25. **错**。构造期间对象"还只是基类"，vptr 指向当前（基类）vtable，调用的是**基类**版本，不是派生类。（注：此结论笔记未显式给出，可由 [[12.1.14 类的底层]] 的"构造时逐层设置 vptr"推出，建议补充到笔记。）
> 26. **对**。`virtual` 继承让共同基类在最终派生类中只存一份，消除二义性与冗余。
> 27. **错**。`new[]` 必须配 `delete[]`，混用是 UB（即便内置类型，标准也要求配对；类类型还会漏析构）。
> 28. **错**。`dynamic_cast` 依赖 RTTI，要求基类是**多态类型**（至少一个虚函数），否则编译错误。
> 29. **对**。接口类 = 全纯虚函数 + 无数据成员，只定义"能做什么"，特别适合多重继承。

**52.**（用 Modern C++ 重写）
```cpp
class Stack {
    int* arr; int top; int cap;
public:
    Stack(int c) { arr = new int[c]; cap = c; top = 0; }
    ~Stack() { delete[] arr; }
    Stack(const Stack& o) {      // 浅拷贝
        arr = o.arr; cap = o.cap; top = o.top;

    void push(int v) { arr[top++] = v; }
};
```

> [!success]- 参考答案（第四节）
> 43. **bug**：非虚析构 + 基类指针删除 → 只调 `~Base`，`buf` 泄漏。**修复**：`virtual ~Base() = default;`（多态基类必须虚析构）。
> 44. **bug**：拷贝构造**按值**传参 → 无限递归（构造参数副本又要拷贝构造）。**修复**：`Role(const Role& other)`。
> 45. **bug**：默认拷贝是浅拷贝，`a`、`b` 的 `data` 指向同一块 → **double free**。**修复**：遵循 Rule of Three/Five 实现深拷贝与拷贝赋值，或改用 `std::vector<int>`/智能指针管理。
> 46. **bug**：`new[]` 配了 `delete`（漏 `[]`）→ UB / 漏析构。**修复**：`delete[] p;`（更优：用 `std::vector<int>`）。
> 47. **bug**：静态成员只在类内**声明**未定义 → 链接错误 `undefined reference to Widget::count`。**修复**：类外 `int Widget::count = 0;`，或改 `inline static int count = 0;`（C++17）。
> 48. **bug**：静态成员函数无 `this`，不能访问非静态成员 `base`。**修复**：去掉 `static`（设为普通成员函数），或把 `base` 设为静态。
> 49. **bug**：placement new 构造的对象**不能 `delete`**（内存来自栈数组 `buf`）→ UB。**修复**：显式调析构 `o->~Obj();`，内存由 `buf` 自行管理无需释放。
> 50. **bug**：`Shape` 是抽象类（含纯虚函数），不能实例化。**修复**：定义具体派生类并用 `Shape*`/`Shape&` 多态使用，例如 `Circle c; Shape& s = c;`。
> 51. **bug**：`f(double)` 与基类 `f(int)` 签名不同，并未重写，`override` 触发编译错误（这其实是 `override` 帮你抓 bug）。**修复**：`void f(int) override {}`。
> 52. **bug**：浅拷贝导致两个 `Stack` 共享 `arr`，析构 double free。**Modern C++ 重写**：
> ```cpp
> #include <vector>
> class Stack {
>     std::vector<int> data_;          // RAII 容器，自动深拷贝/释放
> public:
>     explicit Stack(int cap) { data_.reserve(cap); }
>     void push(int v) { data_.push_back(v); }
>     int  pop()       { int v = data_.back(); data_.pop_back(); return v; }
>     bool empty() const { return data_.empty(); }
> };
> // 拷贝、移动、析构全部由 vector 自动正确处理（Rule of Zero）
> ```

**54.** `this` 指针是什么？它在普通成员函数和 const 成员函数中的类型有何不同？

**56.** 解释构造函数与析构函数的调用顺序（含基类、成员对象），并说明为什么这样设计。

**57.** 静态成员变量为什么传统上要"类内声明、类外定义"？C++17 怎样简化？

**58.** `new`/`delete` 与 `malloc`/`free` 有哪些关键区别？

**59.** 静态多态与动态多态分别靠什么实现？各有什么优缺点？

**60.** 什么是虚函数表（vtable）和虚函数指针（vptr）？虚函数调用的完整过程是怎样的？

**61.** 抽象类和接口类有什么区别？纯虚函数还能有函数体吗？

**62.** 什么是对象切片？为什么实现多态必须用指针或引用而不能用值？

> [!success]- 参考答案（第五节）
> 53. 封装是把数据和操作数据的方法绑定在一起、隐藏内部实现、只暴露必要接口。C++ 用访问修饰符 `public/protected/private` 实现。数据私有化能保护不变量、降低耦合（实现可自由改、接口不变）、便于在 setter 里做校验。
> 54. `this` 是隐式传给每个**非静态**成员函数、指向当前对象的指针。普通成员函数里类型为 `ClassName* const`（指向可改、指针本身不可改）；const 成员函数里为 `const ClassName* const`（连指向的对象也不可改）。
> 55. 优势：直接初始化而非"先默认构造再赋值"，效率更高；类类型成员只调用一次构造。**必须**用初始化列表的：`const` 成员、引用成员、没有默认构造的类类型成员、以及要选择基类特定构造函数时。
> 56. 构造：基类（从顶向下）→ 成员对象（按声明顺序）→ 本类构造体；析构严格相反：本类析构体 → 成员对象逆序 → 基类。这样保证构造时能安全使用已就绪的基类/成员，析构时先清理自己再清理依赖。
> 57. 类内只是声明不分配存储；类定义常被多个 TU 包含，若类内定义会重复定义违反 ODR，故放唯一 `.cpp` 类外定义。C++17 用 `inline static`（及隐式 inline 的 `constexpr static`）允许类内定义并初始化，链接器保证唯一实例。
> 58. `new` 调用构造函数、`delete` 调用析构；`malloc/free` 不调用。`new` 自动算大小、返回正确类型指针、失败抛 `bad_alloc`；`malloc` 返回 `void*` 需转型、需手算大小、失败返回 `NULL`。`new` 可重载。三组必须配对，不可混用。
> 59. 静态多态靠函数重载、模板、运算符重载，编译期定（早绑定），高效、可内联但类型须编译期已知；动态多态靠继承 + 虚函数，运行期定（晚绑定），灵活可扩展但有 vtable 间接调用开销、且难内联。
> 60. 每个含虚函数的类有一张 vtable（存该类各虚函数地址），每个对象内含一个 vptr 指向所属类的 vtable。调用 `p->f()`：取对象 vptr → 找到 vtable → 按 `f` 的固定槽位取函数地址 → 调用。对象真实类型决定 vptr 指向，从而实现动态绑定。
> 61. 抽象类含至少一个纯虚函数、可有数据成员和部分实现；接口类是其特例：**全部**纯虚函数、无数据成员，只定义契约。纯虚函数**可以**有函数体（须类外定义），用于给默认实现，但类仍不可实例化。
> 62. 对象切片：把派生类对象按值赋给基类对象时，派生部分被截断只留基类子对象，且 vptr 变为基类的，多态失效。指针/引用不复制对象、保留真实 vptr，所以多态必须用指针或引用。

## 七、简答深化题

**68.** 为什么构造函数不能是虚函数，而析构函数可以、且多态基类必须是虚析构？请从 vptr 的建立时机解释。

**70.** 什么是协变返回类型（covariant return type）？给一个合法例子，说明它和"返回类型必须相同"的关系。

**71.** `override` 和 `final` 各自的作用是什么？它们在**编译期**帮你挡住哪些 bug？

**72.**（跨章）`inline static` 成员变量（C++17）是如何解决静态成员的 ODR 问题的？请联系 [[11.1 ODR唯一定义规则]] 说明链接器的处理方式。

**73.**（跨章）名称修饰（name mangling）如何区分重载函数？它与"重写"在符号层面有何不同？请联系 [[11.2 编译器基本概念]]。

**74.** 为什么虚继承要引入 vbptr / 虚基类表？它带来的额外开销体现在哪里？

**75.** `static_cast` 向下转型和 `dynamic_cast` 向下转型在机制和安全性上有何区别？`dynamic_cast` 失败时分别如何表现（指针 vs 引用）？

**76.**（跨章）RAII 与智能指针的关系是什么？为什么说"析构函数 + 不可拷贝"是资源安全的基石？请联系智能指针（[[12.1.13 malloc与new]] 的推荐做法）。

> [!success]- 参考答案（第七节）
> 68. 构造期间 vptr 是**逐层设置**的：进入某层构造函数时，vptr 才指向该层的 vtable。构造函数若是虚的就需要靠 vptr 分派，但此时对象类型/vptr 尚未建立，自相矛盾；且"创建对象必须先知道确切类型"，与"运行期再定"冲突。析构相反：析构是销毁已存在的对象，vptr 完好，可以也应该虚——否则基类指针删派生对象只走基类析构，漏掉派生资源。
> 69. vtable **每类一份**（同类所有对象共享），通常放在只读数据段；vptr **每对象一份**，存于对象内存（多数实现放最前）。虚函数难内联是因为编译器在调用点往往不知道对象的真实类型（要运行期经 vtable 间接跳转），没有确定的函数体可展开；只有当编译器能静态确定具体类型时才可能内联（去虚化）。
> 70. 协变返回：派生类重写虚函数时，返回类型可由"基类指针/引用"换成"派生类指针/引用"，仍算合法重写。例：`virtual Base* clone()` → 派生 `Derived* clone() override`。它是"返回类型必须相同"的**唯一放宽**，专为 clone 这类工厂方法服务。
> 71. `override` 声明"我在重写基类虚函数"，若签名不符（名字、参数、const、返回不兼容）编译报错，挡住"以为重写其实是新增/隐藏"的 bug；`final` 禁止该虚函数再被重写、或禁止类被继承，挡住不该被扩展的扩展，并利于去虚化优化。
> 72. `inline` 变量享有 ODR 豁免：允许它在多个翻译单元各有一份**相同**定义，链接器按弱符号/COMDAT 折叠成唯一实例、地址唯一。于是 `inline static int x = 0;` 直接写在头文件、被多处包含也不再 `multiple definition`，省去了类外定义的样板（详见 [[11.1 ODR唯一定义规则]]）。
> 73. 重载函数同名不同参，编译器把参数类型编码进符号名（如 `_Z1fi` vs `_Z1fd`），生成不同符号以共存；这是静态多态。重写是动态多态：基类与派生的虚函数符号各自存在，但调用走 vtable 槽位、运行期选择，与符号名解析（链接期）是两回事（详见 [[11.2 编译器基本概念]] 名称修饰）。
> 74. 普通多重继承下共同基类有多份；虚继承要让它"全程序唯一一份"，但中间类编译时并不知道最终布局中该唯一实例在哪，于是引入 vbptr 指向虚基类表，运行期据此算出虚基类子对象的偏移。开销：每条虚继承路径多一个指针（增大对象）、访问虚基类成员多一次间接寻址、构造由最终派生类负责。
> 75. `static_cast` 向下转型是**编译期**按继承关系算偏移，不校验对象真实类型，类型不符即 UB；`dynamic_cast` 依赖 RTTI 在**运行期**校验，安全。失败时：指针版返回 `nullptr`，引用版抛 `std::bad_cast`（引用没有"空"可表达）。
> 76. RAII = 用对象生命周期管理资源：构造获取、析构释放。智能指针正是把"裸指针所有权"封进 RAII 对象：`unique_ptr` 析构即 `delete`、且不可拷贝（独占所有权），从根本上消除漏释放/重复释放。"析构保证释放 + 不可随意拷贝"避免了双重释放，这就是资源安全的基石（推荐做法见 [[12.1.13 malloc与new]]）。

## 八、概念辨析进阶

**77.** 辨析 **重载（overload）/ 重写（override）/ 隐藏（hide）**。

**78.** 辨析 **静态多态 / 动态多态**。

**79.** 辨析 **虚函数 / 纯虚函数 / 普通成员函数**。

**80.** 辨析 **public / protected / private 三种继承方式**对基类成员可见性的影响。

**81.** 辨析 **抽象类 / 接口类 / 具体类**。

**82.** 辨析 **`static_cast` / `dynamic_cast` / `reinterpret_cast`**（聚焦类指针转换）。

**83.** 辨析 **构造顺序 / 析构顺序 / 成员初始化顺序**三者的"顺序"。

> [!success]- 参考答案（第八节）
> 77. 重载：同一作用域、同名、参数不同，编译期按实参选——静态多态。重写：派生类重定义基类**虚函数**且签名一致，运行期按对象真实类型选——动态多态。隐藏：派生类定义与基类同名的成员（无论是否虚、参数是否同），遮蔽基类同名成员，需 `Base::` 或 `using` 访问。口诀：**同层不同参=重载，跨层虚同签=重写，跨层同名遮蔽=隐藏**。
> 78. 静态多态编译期绑定（重载/模板/运算符重载），快、可内联、类型须已知；动态多态运行期绑定（虚函数+继承+指针/引用），灵活可扩展、有 vtable 开销。口诀：**编译期定 vs 运行期定**。
> 79. 普通成员函数：编译期绑定，派生同名会隐藏。虚函数：可被重写、运行期绑定、有默认实现。纯虚函数：`=0`，使类成为抽象类、强制派生实现（可有类外实现）。口诀：**普通遮蔽 / 虚可重写 / 纯虚必实现**。
> 80. public 继承保持基类 public→public、protected→protected（is-a 成立）；protected 继承把基类 public 降为 protected；private 继承把 public、protected 都降为 private（is-a 不对外）。三者下基类 private 都不可直接访问。口诀：**取继承说明符与成员权限中"更严"的那个**。
> 81. 具体类：无纯虚函数、可实例化。抽象类：≥1 纯虚函数、不可实例化、可含数据与部分实现。接口类：全纯虚 + 无数据成员，纯契约。口诀：**能 new 是具体，含纯虚是抽象，全纯虚无数据是接口**。
> 82. `static_cast`：按继承关系做上/下转型，编译期、无运行期检查（下转有风险）。`dynamic_cast`：多态类型间安全下转/交叉转，运行期 RTTI 检查。`reinterpret_cast`：纯位重解释，不做任何继承偏移调整，几乎总是危险。口诀：**编译期信任 / 运行期校验 / 位级蛮干**。
> 83. 构造顺序：基类→成员→本类体（从顶向下）。析构顺序：本类体→成员逆序→基类（严格相反）。成员初始化顺序：永远按**声明顺序**，与初始化列表书写顺序无关。口诀：**先基后己、析构倒放、成员认声明**。

> [!success]- 参考答案（第九节）
> 84. **现象**：基类指针调虚函数执行派生版本。**机制**：每个多态类有一张 vtable（虚函数地址数组），每个对象头部有 vptr 指向其真实类型的 vtable；调用时取 vptr→查 vtable 槽位→间接调用。**vptr 个数**：单继承通常 1 个；多重继承中每个含虚函数的基类子对象各一个 vptr（可能多个）。**延伸**：vtable 还含 RTTI、`type_info` 指针。
> 85. **现象**：`delete basePtr` 漏调派生析构。**原因**：非虚析构是静态绑定，只走基类。**解决**：凡可能被继承且通过基类指针删除的类，析构设 `virtual`。**可不虚**：该类不作多态基类、从不通过基类指针删除（如纯值类型、`final` 且不被多态删）。**延伸**：可用 `protected` 非虚析构禁止基类指针删除。
> 86. **现象**：虚调用常比普通调用慢。**原因**：调用点通常不知道真实类型，需经 vtable 间接跳转，编译器无确定函数体可内联。**解决/延伸**：当编译器能静态确定具体类型（如对具体对象、`final`、LTO 全程序分析）时可"去虚化"，把虚调用变成直接调用甚至内联——这也是给类/函数加 `final` 的性能收益之一。
> 87. **现象**：`sizeof(Empty)==1`。**原因**：标准要求不同对象地址不同，0 大小会让相邻对象同址，故给 1 字节占位。**EBO**：当空类作**基类**时，它不必再占独立字节，可与派生类布局重叠，使派生类不因这个空基类变大——常用于把无状态策略/分配器作基类而零开销。
> 88. **继承**用于真正的 is-a + 需要多态替换的场景；**组合**用于 has-a / 复用实现。优先组合的原因：继承是最强耦合（派生依赖基类实现细节，基类改动易破坏派生）、易导致脆弱基类问题和深继承链；组合更灵活、可运行期替换、边界清晰。**延伸**：需要多态接口时用"接口继承 + 组合实现"。
> 89. **机制**：开启 RTTI 后，多态对象的 vtable 关联 `type_info`；`dynamic_cast` 顺着 vptr 取真实类型信息，沿继承图判断目标类型是否可达并算偏移。**代价**：少量空间（type_info）、运行期查找耗时。**关闭**：`-fno-rtti`（GCC/Clang）可关 RTTI，则 `dynamic_cast`/`typeid` 多态用法不可用。**延伸**：高性能路径常用虚函数或访问者模式替代频繁 `dynamic_cast`。
> 90. **现象**：`Base2* p = &derived;` 的 `p` 值可能 ≠ `&derived`。**原因**：多重继承下，派生对象里第二个基类子对象不在对象起始处，转换为 `Base2*` 时编译器会**加上偏移**指向 Base2 子对象，故指针值不同；转回派生指针再减回来。这正是 `static_cast`/隐式转换会做的 this 调整。**延伸**：`reinterpret_cast` 不做该调整，所以多继承下用它转基类指针会出错。
> 91. **禁拷贝**：`A(const A&)=delete; A& operator=(const A&)=delete;`。**禁继承**：`class A final {};`。**禁堆分配**：把 `operator new` 设为 `=delete` 或私有（`static void* operator new(std::size_t)=delete;`）。**延伸**：反之"只能堆分配"可把析构设私有 + 提供工厂。
> 92.
> ```cpp
> struct Shape {
>     virtual Shape* clone() const = 0;     // 协变返回
>     virtual ~Shape() = default;
> };
> struct Circle : Shape {
>     Circle* clone() const override { return new Circle(*this); }  // 返回 Circle*
> };
> ```
> **作用**：协变返回让 `clone` 在派生类里返回更具体的指针类型，调用方拿到 `Circle*` 而非 `Shape*`，无需手动向下转型。**延伸**：现实中返回 `std::unique_ptr<Shape>` 更安全（虽不满足协变语法，但所有权清晰）。

## 十、补充加分题

**93.**（性能分析）虚函数调用相比普通函数调用，多了哪些开销？请从指令层面（间接跳转、分支预测、能否内联、i-cache/d-cache）分析，并说明它是否改变算法的时间复杂度。

**94.**（性能/缓存）`std::vector<Base*>`（指针数组，对象散落堆上）与把对象紧密排布相比，遍历调用虚函数时为什么前者缓存局部性差？这对热点循环意味着什么？

**95.** 纯虚析构函数 `virtual ~Base() = 0;` 合法吗？使用时有什么必须注意的点？

**96.**（进阶）CRTP（奇异递归模板模式）如何用**静态多态**实现"虚函数"的效果而零运行期开销？给最小示例。

**97.**（进阶）在含虚函数的单继承下，画出"`Base* p = new Derived(); p->f();`"从指针到最终函数地址的完整间接链。

> [!success]- 参考答案（第十节）
> 93. 多出的开销：① 一次间接读取 vptr + 一次 vtable 取址（额外内存访问）；② 间接跳转对**分支预测**不友好，预测失败要冲刷流水线；③ 调用点通常**无法内联**，丢失常量传播/死代码消除等后续优化；④ vtable 与代码可能造成额外 i-cache/d-cache 压力。但这些都是**常数级**开销，**不改变** Big-O；只在极热点的小函数循环里才显著。
> 94. `vector<Base*>` 里存的是指针，真实对象分散在堆各处，遍历时每次解引用都可能 cache miss，且对象内存不连续、预取无效；vtable 也可能各异。若改为存值（同类型紧密排布）或做数据导向设计（SoA），遍历命中率大幅提升。对热点循环（如每帧更新上万对象）意味着可能数倍性能差距——"少用多态、批量同类处理"是高性能常见手段。
> 95. 合法。纯虚析构使类成为抽象类，但析构函数**必须提供函数体**（通常 `Base::~Base() = default;` 或类外定义），因为派生类析构结束后一定会调用基类析构——没有实现就链接错误。用途：想让类抽象但又没有其它合适的纯虚函数时。
> 96.
> ```cpp
> template <class D>
> struct Shape {                       // 基类模板
>     double area() const { return static_cast<const D&>(*this).areaImpl(); }
> };
> struct Circle : Shape<Circle> {
>     double r;
>     explicit Circle(double r) : r(r) {}
>     double areaImpl() const { return 3.14159 * r * r; }  // 编译期绑定
> };
> ```
> `Shape<D>::area` 静态转成派生类并调 `areaImpl`，编译期解析、可内联，无 vptr/vtable 开销。代价：失去运行期统一容器（`Shape<Circle>` 与 `Shape<Square>` 是不同类型）。（注：CRTP 属本章笔记未覆盖的进阶点，建议补充。）
> 97. 链路：`p`（栈上指针，值=Derived 对象首地址）→ 对象内存起始处的 `vptr` → `Derived` 的 vtable → `f` 所在固定槽位（索引在编译期确定）→ 取出 `&Derived::f` → 间接 `call` 该地址。一句话：**指针 → 对象 → vptr → vtable → 槽位 → 函数地址**。

## 十一、vtable / 对象内存布局专项

> OOP 系统岗高频：能"画出对象在内存里长什么样"。

**98.** 画出下面 `Derived` 对象在 64 位下的内存布局（标出 vptr、各成员偏移与 padding），并给出 `sizeof`：
```cpp
class Base    { int a;  virtual void f(); };
class Derived : public Base { int b; void f() override; virtual void g(); };
```

**99.** `Derived` 的 vtable 里有哪些条目？分别指向谁？基类指针调用 `g()` 能成功吗？

**100.** 画出下面**多重继承**对象 `C` 的布局，说明它含几个 vptr：
```cpp
class A { int a; virtual void fa(); };
class B { int b; virtual void fb(); };
class C : public A, public B { int c; void fa() override; void fb() override; };
```

**101.** 不含虚函数的 `class P { char c; int i; short s; };`，64 位下 `sizeof(P)` 是多少？画出 padding。

**102.** 成员变量的内存排列顺序由什么决定？`public`/`private` 修饰符会影响布局吗？把 `class M { char a; double b; char c; };` 的成员重排以最小化 `sizeof`，给出前后大小。

**103.** 对象的 vptr 是在什么时候被写入的？同一个 `Derived` 在"构造到一半（基类已构造、派生未构造）"时，它的 vptr 指向谁？

> [!success]- 参考答案（第十一节）
> 98.
> ```
> Derived 对象（64 位）:
> 偏移 0   : vptr        (8 字节)   ← 指向 Derived 的 vtable
> 偏移 8   : Base::a     (4 字节)
> 偏移 12  : Derived::b  (4 字节)
> ---------------------------------
> sizeof(Derived) = 16
> ```
> 单继承共享一个 vptr；`a`、`b` 紧接其后，正好对齐到 16，无额外尾部 padding。
> 99. `Derived` 的 vtable 槽位：`[0] &Derived::f`（重写）、`[1] &Derived::g`（新增）。基类指针 `Base*` 只能看到 `Base` 接口里的 `f`，**不能**直接调 `g`（`g` 不在 `Base` 的接口里，编译期就报错）；要调 `g` 须先向下转型到 `Derived*`。
> 100.
> ```
> C 对象（64 位，Itanium/GCC/Clang ABI）:
> 偏移 0-7 : vptrA (8)        ← A 子对象
> 偏移 8-11: a(4)
> 偏移12-15: pad(4)           （对齐 vptrB 到 8）
> 偏移16-23: vptrB (8)        ← B 子对象
> 偏移24-27: b(4)
> 偏移28-31: c(4)             ← C 自己（复用 B 子对象尾部空位）
> sizeof(C) = 32
> ```
> **关键**：含 **两个 vptr**（A、B 各一个）。`b` 与 `c` 各 4 字节正好填满 `vptrB` 之后的 8 字节，故为 32；若按"基类子对象不被复用尾部 padding"的简化模型则为 40（具体随 ABI 不同，MSVC 也可能不同）。重点不在精确字节数，而在**多重继承下有多个 vptr、第二基类子对象有偏移**。用 `B* p = &c;` 时指针会被调整到 B 子对象处（偏移 16）。
> 101. `char c`(1) + 3pad + `int i`(4) + `short s`(2) + 2pad = **12**。
> ```
> 0: c | 1-3: pad | 4-7: i | 8-9: s | 10-11: pad   → 12
> ```
> 102. 由**声明顺序**决定；`public/private` 只影响访问权限，**不影响**布局。`class M { char a; double b; char c; };` 原大小：a(1)+7pad+b(8)+c(1)+7pad = **24**。重排为 `double b; char a; char c;`：b(8)+a(1)+c(1)+6pad = **16**。把大对齐成员放前面可减少 padding。
> 103. vptr 在**构造期逐层写入**：进入某层构造函数体之前，编译器先把 vptr 设成该层 vtable。所以"基类已构造、派生未构造"的中途时刻，vptr 指向 **Base 的 vtable**——这正是构造函数里虚调用不走派生版本的原因（呼应第 35 题）。

**106.** 虚基类的构造顺序有何特殊？写出输出：
```cpp
struct V { V(){ std::cout << "V"; } };
struct X : virtual V { X(){ std::cout << "X"; } };
struct Y : virtual V { Y(){ std::cout << "Y"; } };
```

**107.** 局部对象数组的构造与析构顺序：
```cpp
struct T { T(){ std::cout << "+"; } ~T(){ std::cout << "-"; } };
int main() { T arr[3]; }
```

**108.** 若在派生类**析构函数**里调用虚函数，会调用到派生版本还是基类版本？为什么？

> [!success]- 参考答案（第十二节）
> 104. 输出 **`BMDdmb`**。构造：基类 `Base`(B) → 成员 `m`(M) → 本体(D)；析构相反：本体(d) → 成员(m) → 基类(b)。
> 105. 顺序为 **`ZAB`**：先基类 `Base`(Z)，再按**声明顺序** `a`(A)、`b`(B)。初始化列表写成 `b(), a()` **不改变**实际顺序（仍 a 先于 b），但会引发编译器告警，且若有依赖会造成 bug。

> 107. 输出 **`+++---`**。数组按下标 0→1→2 构造，析构按 2→1→0 逆序。
> 108. 调用到**当前（基类正在析构的那一层）版本**，不是更派生的版本。因为析构是从派生向基类逐层进行，进入基类析构时派生部分已销毁、vptr 已被改回基类的 vtable，故虚调用解析到基类版本——这与构造期对称（构造/析构中虚分派都"停在当前层"）。

## 十三、对象切片 & 向下转型专项

**109.** 下面哪几处发生了对象切片？分别说明后果：
```cpp
struct Base { virtual void f(){ std::cout << "B"; } };
struct Der : Base { int extra = 1; void f() override { std::cout << "D"; } };
void byVal(Base b)  { b.f(); }      // (1)
void byRef(Base& b) { b.f(); }      // (2)
int main() {
    Der d;
    Base b = d;                     // (3)
    std::vector<Base> v; v.push_back(d);   // (4)
    byVal(d);                       // (5)
    byRef(d);                       // (6)
}
```

**110.** `static_cast` 向下转型在什么情况下会导致未定义行为？给一个会 UB 的例子和一个安全的例子。

**111.** 用 `dynamic_cast` 安全地把 `Base*` 转 `Der*`，分别写出"转型成功"和"转型失败"时的处理；再说明对**引用**做 `dynamic_cast` 失败时的不同表现。

**112.** 为什么 STL 容器（如 `std::vector<Base>`）按值存储多态对象是个常见错误？正确做法是什么？

> [!success]- 参考答案（第十三节）
> 109. 切片发生在 **(1)(3)(4)(5)**——都按**值**生成 `Base` 子对象：`extra` 丢失、`f()` 调用基类版本输出 `B`。**(2)(6)** 是引用，不切片，`b.f()` 动态绑定输出 `D`。后果：切片处多态失效 + 派生数据丢失。
> 110. 当基类指针实际**并不指向**该派生类对象时，`static_cast` 仍按"是该派生类"去算偏移/访问派生成员 → UB。
> ```cpp
> Base* p = new Base();
> Der*  q = static_cast<Der*>(p);   // UB：p 其实不是 Der
> q->extra;                          // 越界访问派生成员
> // 安全：p 确实指向 Der
> Base* p2 = new Der();
> Der*  q2 = static_cast<Der*>(p2);  // OK
> ```
> 111.
> ```cpp
> Base* p = /* ... */;
> if (Der* d = dynamic_cast<Der*>(p)) {
>     d->f();           // 成功：p 确实指向 Der（或其派生）
> } else {
>     /* 失败：返回 nullptr，走兜底逻辑 */
> }
> // 引用版失败不会返回空，而是抛异常：
> try { Der& r = dynamic_cast<Der&>(*p); }
> catch (const std::bad_cast&) { /* 处理 */ }
> ```
> 要求 `Base` 是多态类型（有虚函数）。
> 112. 因为 `vector<Base>` 的元素是 `Base` 大小的值槽，`push_back(派生对象)` 会切片：派生数据丢失、多态失效，且元素全是 `Base`。正确做法：存**指针/智能指针** `std::vector<std::unique_ptr<Base>>`，既保留真实类型与多态，又自动管理生命周期。

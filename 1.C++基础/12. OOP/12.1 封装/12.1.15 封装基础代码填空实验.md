# 12.1.15 封装基础代码填空实验

范围：12.1.1 面向对象概念～12.1.7 析构函数。共 8 个实验，重点是自己写成员函数、维护对象状态，以及观察对象的创建和销毁。

## 怎么做

- 每题独立保存成一个 `.cpp` 文件，每个文件只有一个 `main()`。
- 把 `/*A*/` 等占位符整体替换成代码；标着“填写逻辑”的空允许写多行。不要改动原有验收断言来让题目通过。
- `assert(条件)` 来自 `<cassert>`：条件为假会终止程序。编译时不要定义 `NDEBUG`，否则断言不执行。
- 先完成并运行，再做题后的改动实验，最后看折叠答案。故意制造的编译错误验证完后要恢复。
- 参考答案是可行写法之一。行为正确、满足访问控制和题面要求的其他实现也可以。

macOS / Linux 编译运行示例（文件名按实际替换）：

```bash
c++ -std=c++17 -Wall -Wextra -pedantic lab01.cpp -o lab01
./lab01
```

前四题填语法和短逻辑，后四题需要处理初始化、复制和资源归还。做完某题后，合上模板重写一次该类，保留 `main()` 检查行为。

> [!note] 阅读原笔记时的几处校正
> - `Role(const Role&)` 是拷贝构造的一种常见形式，普通构造函数并不要求接收同类引用。
> - 成员按声明顺序初始化；初始化列表的书写顺序不会改变执行顺序。未显式初始化的普通整型成员也不保证自动归零。
> - 类类型成员可以默认构造；是否必须显式提供初始化，取决于其类型是否有可用的默认构造函数等条件。
> - `const` 成员函数允许修改 `mutable` 成员。普通成员函数中 `this` 表达式的类型是 `T*`，const 成员函数中是 `const T*`；不能给 `this` 赋值，不等于其类型带有顶层 const。
> - 空类的独立完整对象大小非零，常见实现为 1；具体布局依赖实现。
> - 通过析构函数非虚的基类指针删除派生类对象，在这里讨论的 C++17 场景中是未定义行为，不能保证“只调用基类析构”。本组实验使用明确的局部对象生命周期。

## 实验 1：保护角色血量

对应笔记：[[12.1.1 面向对象概念]]、[[12.1.2 类]]。

补齐访问权限和受伤逻辑。血量初始为 100；非正伤害被忽略，伤害超过剩余血量时归零。不能通过公开数据成员绕过检查。

```cpp
#include <cassert>
#include <iostream>

class Role {
/*A*/:
    int hp_ = 100;
/*B*/:
    void takeDamage(int damage) {
        /*C：填写完整函数体逻辑*/
    }
    int hp() const { return hp_; }
};

int main() {
    Role hero;
    Role enemy;
    hero.takeDamage(30);
    assert(hero.hp() == 70);
    assert(enemy.hp() == 100);
    hero.takeDamage(-20);
    hero.takeDamage(0);
    assert(hero.hp() == 70);
    hero.takeDamage(1000);
    assert(hero.hp() == 0);
    hero.takeDamage(1);
    assert(hero.hp() == 0);
    std::cout << "lab1 passed\n";
}
```

验收输出：

```text
lab1 passed
```

改动实验：临时在 main 中加入 hero.hp_ = -1;，确认编译失败后删掉。再自行加入一次“伤害恰好等于剩余血量”的断言。

> [!success]- 实验 1 参考答案
> 按字母顺序替换：
>
> A：
>
> ```cpp
> private
> ```
>
> B：
>
> ```cpp
> public
> ```
>
> C：
>
> ```cpp
> if (damage <= 0) {
>             return;
>         }
>         hp_ = damage >= hp_ ? 0 : hp_ - damage;
> ```
>
> 先检查伤害，再修改血量。两个对象各有自己的 hp_，修改 hero 不会修改 enemy。只设置 private 还不够，公开接口也需要维护血量范围。

## 实验 2：测量对象占用的空间

对应笔记：[[12.1.3 类的空间]]。

填写三个测量表达式。先预测输出，再运行。最后在 Compact 中添加一个普通成员函数，重新测量，记录大小是否改变。

```cpp
#include <cassert>
#include <iostream>

struct Loose {
    char first;
    int value;
    char last;
};
struct Compact {
    int value;
    char first;
    char last;
};
class Empty {};

int main() {
    std::cout << /*A*/ << ' ' << /*B*/ << ' ' << /*C*/ << '\n';
    assert(sizeof(Empty) >= 1);
}
```

验收：记录实际输出，并解释成员之间和末尾的填充；不能仅凭总成员大小相加。

改动实验：画出两种布局的成员偏移和填充位置。验证“只增加一个普通成员函数”与“增加一个 int 数据成员”带来的差别。

> [!success]- 实验 2 参考答案
> 按字母顺序替换：
>
> A：
>
> ```cpp
> sizeof(Loose)
> ```
>
> B：
>
> ```cpp
> sizeof(Compact)
> ```
>
> C：
>
> ```cpp
> sizeof(Empty)
> ```
>
> 在 int 大小和对齐均为 4、char 对齐为 1 的常见布局下，输出 12 8 1。Loose 通常有中间和尾部填充；Compact 把两个 char 放在一起，减少填充。普通成员函数的代码不计入每个对象的大小。具体字节数依赖实现，不要把这些数字当作跨平台保证。

## 实验 3：类外定义、this 与链式调用

对应笔记：[[12.1.4 类的成员函数]]。

保持参数名不变。补齐类外定义，使 set(10).add(5).add(-3) 连续修改同一个对象。

```cpp
#include <cassert>
#include <iostream>

class Counter {
    int value = 0;
public:
    Counter& set(int value);
    Counter& add(int delta);
    int get() const { return value; }
};

/*A*/ Counter::set(int value) {
    /*B*/ = value;
    return /*C*/;
}

Counter& /*D*/(int delta) {
    value += delta;
    return /*E*/;
}

int main() {
    Counter a;
    Counter b;
    Counter& result = a.set(10).add(5).add(-3);
    assert(a.get() == 12);
    assert(b.get() == 0);
    assert(&result == &a);
    std::cout << "lab3 passed\n";
}
```

验收输出：

```text
lab3 passed
```

改动实验：把 set 的赋值临时改为 value = value;，观察哪个断言失败。然后恢复正确版本。

> [!success]- 实验 3 参考答案
> 按字母顺序替换：
>
> A：
>
> ```cpp
> Counter&
> ```
>
> B：
>
> ```cpp
> this->value
> ```
>
> C：
>
> ```cpp
> *this
> ```
>
> D：
>
> ```cpp
> Counter::add
> ```
>
> E：
>
> ```cpp
> *this
> ```
>
> this->value 指向当前对象的成员，右侧 value 是参数。返回 *this 的引用让下一次调用继续作用于原对象，地址断言检查了这一点。

## 实验 4：通过 const 对象读取，并统计读取次数

对应笔记：[[12.1.5 const成员函数]]。

补齐 const 和 mutable，使只读对象能读取数值，并累计 get() 的调用次数。reads() 自身不增加次数。

```cpp
#include <cassert>
#include <iostream>

class Meter {
    int value_ = 42;
    /*A*/ int reads_ = 0;
public:
    int get() /*B*/;
    int reads() /*C*/ { return reads_; }
};

int Meter::get() /*D*/ {
    /*E*/;
    return value_;
}

int main() {
    const Meter meter;
    assert(meter.reads() == 0);
    int first = meter.get();
    int second = meter.get();
    assert(first == 42 && second == 42);
    assert(meter.reads() == 2);
    assert(meter.reads() == 2);
    std::cout << "lab4 passed\n";
}
```

验收输出：

```text
lab4 passed
```

改动实验：分别尝试去掉 mutable、去掉定义末尾的 const、在 get 中加入 ++value_;。每次只改一处，记录编译器拒绝的原因，再恢复。

> [!success]- 实验 4 参考答案
> 按字母顺序替换：
>
> A：
>
> ```cpp
> mutable
> ```
>
> B：
>
> ```cpp
> const
> ```
>
> C：
>
> ```cpp
> const
> ```
>
> D：
>
> ```cpp
> const
> ```
>
> E：
>
> ```cpp
> ++reads_
> ```
>
> 声明和类外定义都必须带匹配的 const。value_ 表示被观察的值，reads_ 是读取统计。mutable 只放宽该成员的修改限制，不会让整个对象变成可写。

## 实验 5：初始化列表、委托构造与 explicit

对应笔记：[[12.1.6 构造函数]]。

构造一个绑定外部计数器的角色。单参数构造必须委托给双参数构造，默认等级为 1；不允许把 int 隐式转换为 Role。外部计数器必须比 Role 活得更久。

```cpp
#include <cassert>
#include <iostream>

class Role {
    const int level_;
    int damage_;
    int& actions_;
public:
    Role(int level, int& actions)
        : /*A*/, /*B*/, /*C*/ {}

    /*D*/ Role(int& actions) : /*E*/ {}

    int level() const { return level_; }
    int damage() const { return damage_; }
    void attack() { ++actions_; }
};

int main() {
    int actions = 0;
    Role novice{actions};
    Role expert{3, actions};
    assert(novice.level() == 1 && novice.damage() == 10);
    assert(expert.level() == 3 && expert.damage() == 30);
    novice.attack();
    expert.attack();
    assert(actions == 2);
    // Role bad = actions;  // 验收时取消注释：应编译失败
    std::cout << "lab5 passed\n";
}
```

验收输出：

```text
lab5 passed
```

改动实验：单独取消 bad 那行的注释确认失败，再恢复。说明为什么在构造函数体中写 actions_ = actions; 是赋值，而不是给引用建立绑定。

> [!success]- 实验 5 参考答案
> 按字母顺序替换：
>
> A：
>
> ```cpp
> level_(level)
> ```
>
> B：
>
> ```cpp
> damage_(level_ * 10)
> ```
>
> C：
>
> ```cpp
> actions_(actions)
> ```
>
> D：
>
> ```cpp
> explicit
> ```
>
> E：
>
> ```cpp
> Role(1, actions)
> ```
>
> level_ 是 const 成员，actions_ 是引用成员，两者在这里都需要在初始化列表中完成初始化。成员按类中的声明顺序初始化，所以 damage_ 可以读取已经初始化的 level_。委托构造把初始化工作交给另一个构造函数。explicit 拒绝题中注释行的隐式转换，仍允许 Role novice{actions}。本题等级限定为 1～100。

## 实验 6：拷贝一个角色，修改副本

对应笔记：[[12.1.6 构造函数]]。

补齐拷贝构造函数、受伤逻辑和函数参数，使伤害模拟只修改副本。拷贝构造时输出 copy，借此观察调用次数。

```cpp
#include <cassert>
#include <iostream>
#include <string>

class Role {
    std::string name_;
    int hp_;
public:
    Role(const std::string& name, int hp) : name_(name), hp_(hp) {}
    Role(/*A*/ other) : /*B*/, /*C*/ {
        std::cout << "copy\n";
    }
    void hurt(int damage) {
        /*D：正伤害扣血，血量最低为 0*/
    }
    int hp() const { return hp_; }
    const std::string& name() const { return name_; }
};

void simulate(/*E*/ role) {
    role.hurt(30);
    assert(role.hp() == 70);
}

int main() {
    Role original{"Knight", 100};
    Role backup{original};
    assert(backup.name() == "Knight");
    backup.hurt(20);
    assert(backup.hp() == 80);
    assert(original.hp() == 100);
    simulate(original);
    assert(original.hp() == 100);
    std::cout << "lab6 passed\n";
}
```

验收输出：

```text
copy
copy
lab6 passed
```

## 实验 7：观察成员对象与局部对象的析构顺序

对应笔记：[[12.1.6 构造函数]]、[[12.1.7 析构函数]]。

补齐析构函数名和成员初始化。不要显式调用任何析构函数。先手写完整输出，再运行对照。

```cpp
#include <iostream>
#include <string>

class Trace {
    std::string name_;
public:
    explicit Trace(const std::string& name) : name_(name) {
        std::cout << "+ " << name_ << '\n';
    }
    /*A*/() {
        std::cout << "- " << name_ << '\n';
    }
};

class Team {
    Trace first_;
    Trace second_;
public:
    Team() : /*B*/, /*C*/ {
        std::cout << "+ Team\n";
    }
    /*D*/() {
        std::cout << "- Team body\n";
    }
};

int main() {
    Trace outer{"outer"};
    {
        Team team;
        Trace local{"local"};
        std::cout << "inside\n";
    }
    std::cout << "outside\n";
}
```

验收：输出必须与折叠答案中的完整日志一致。

改动实验：把 local 移到 Team team; 前面，先预测析构日志怎么变化，再验证。不能通过显式调用析构函数来调整日志。

> 按字母顺序替换：
>
> A：
>
> ```cpp

> ```
>
> B：
>
> ```cpp
> first_("first")
> ```
>
> C：

## 实验 8：综合：用对象自动归还名额

对应笔记：[[12.1.2 类]]、[[12.1.4 类的成员函数]]、[[12.1.5 const成员函数]]、[[12.1.6 构造函数]]、[[12.1.7 析构函数]]。

用 available 模拟可用名额。构造时有名额就减 1 并获得资格，没有名额则保持未持有状态；只有持有者析构时才归还 1 个名额。提前 return 也必须归还。available 初始非负，生命周期长于所有借用它的 Slot。

```cpp
#include <cassert>
#include <iostream>

class Slot {
    int& available_;
    bool acquired_;
public:
    explicit Slot(int& available) : /*A*/, /*B*/ {
        /*C：尝试获取名额*/
    }
    ~Slot() {
        /*D：必要时归还名额*/
    }
    bool acquired() const {
        /*E*/
    }

    // 一份资格只能归还一次。本题禁止复制持有者。
    Slot(const Slot&) = delete;
    Slot& operator=(const Slot&) = delete;
};

void visit(int& available, bool leaveEarly) {
    Slot slot{available};
    assert(slot.acquired());
    assert(available == 0);
    if (leaveEarly) {
        return;
    }
    std::cout << "work\n";
}

int main() {
    int available = 1;
    {
        Slot first{available};
        assert(first.acquired());
        assert(available == 0);
        {
            Slot second{available};
            assert(!second.acquired());
            assert(available == 0);
        }
        assert(available == 0);
    }
    assert(available == 1);
    visit(available, true);
    assert(available == 1);
    visit(available, false);
    assert(available == 1);
    std::cout << "lab8 passed\n";
}
```

验收输出：

```text
work
lab8 passed
```

改动实验：暂时去掉析构中的 if，定位哪条断言捕获“获取失败却归还”的问题。恢复后，将初始名额改为 2，自行写出两个成功持有者和一个失败持有者的嵌套作用域测试。

> [!success]- 实验 8 参考答案
> 按字母顺序替换：
>
> A：
>
> ```cpp
> available_(available)
> ```
>
> B：
>
> ```cpp
> acquired_(false)
> ```
>
> C：
>
> ```cpp
> if (available_ > 0) {
>             --available_;
>             acquired_ = true;
>         }
> ```
>
> D：
>
> ```cpp
> if (acquired_) {
>             ++available_;
>         }
> ```
>
> E：
>
> ```cpp
> return acquired_;
> ```
>
> 引用成员连接外部计数器，acquired_ 记录当前对象是否负有归还责任。获取失败的对象不能归还，否则会凭空增加名额。普通 return 同样离开作用域，因此局部对象会自动析构。两行 = delete 禁止拷贝构造和拷贝赋值，避免复制一份“归还责任”。这是单线程下的 RAII 模拟，不是线程同步工具。

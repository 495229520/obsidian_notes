## 一、选择题（概念基础）

**1.** 常见平台下，`struct A { char c; int i; };` 的 `sizeof(A)` 是：
- A. 5　　B. 8　　C. 4　　D. 12

**2.** 关于 `struct` 和 `class`，正确的是：
- A. struct 不能有成员函数　　B. struct 默认 `private`，class 默认 `public`
- C. struct 默认 `public`，class 默认 `private`　　D. 二者完全没有区别

**3.** `union U { int i; double d; char c; };` 的 `sizeof(U)` 是：
- A. 4　　B. 8　　C. 13　　D. 16

**4.** `p->member` 等价于：
- A. `*p.member`　　B. `(*p).member`　　C. `*(p.member)`　　D. `&p.member`

**5.** 关于联合体，正确的是：
- A. 所有成员可同时有效　　B. 同一时刻至多有一个活动成员
- C. 成员各自占独立内存　　D. union 不能放数组

**6.** 关于 C++20 指定初始化器 `S s = {.a=1, .b=2};`，正确的是：
- A. 可以任意乱序，和 C 一样　　B. 必须按成员声明顺序书写
- C. 不能跳过任何成员　　D. C++ 不支持指定初始化器

**7.** `union U { int i; char buf[5]; };` 的 `sizeof(U)` 和 `alignof(U)`：
- A. 5, 1　　B. 5, 4　　C. 8, 4　　D. 8, 1

**8.** 按标准 C++ 判断：小端系统上 `union { int i; char c; } u; u.i = 0x12345678;` 后读取 `u.c`，结果是：
- A. 0x12　　B. 0x78　　C. 0x34　　D. 未定义

**9.** C++17 中类型安全、替代 `union` 的设施是：
- A. `std::any`　　B. `std::optional`　　C. `std::variant`　　D. `std::tuple`

**10.** 下列哪个**不能**出现在匿名联合体里：
- A. `int` 成员　　B. 数组成员　　C. 成员函数　　D. `float` 成员

> [!success]- 参考答案（第一节）
> 1. **B**。`char`(1) + 3 padding + `int`(4) = 8（`int` 须 4 字节对齐）。
> 2. **C**。唯一实质区别是默认成员访问权限和默认继承权限：struct 为 `public`，class 为 `private`。struct 同样可以有成员函数、构造、继承、多态。
> 3. **B**。最大成员 `double` 为 8 字节、对齐 8，`sizeof` = 8。
> 4. **B**。`->` 是"先解引用再取成员"。注意 `*p.member` 因 `.` 优先级更高会被解析成 `*(p.member)`，对指针 `p` 是错的。
> 5. **B**。union 的非静态数据成员共享存储；活动成员由生命周期决定，同一时刻至多一个，也可能没有。简单标量成员常可通过赋值切换，但不能把任意写入都当成合法构造。
> 6. **B**。C++20 的指定初始化器要求顺序与声明一致（C 允许乱序，C++ 不允许）。
> 7. **C**。`buf[5]` 虽达 5 字节，但 `int` 要求 4 字节对齐 → 尾部补齐到 8；`alignof` 取成员最严格者 = 4。
> 8. **D**。`i` 是活动成员，读取非活动成员 `c` 在标准 C++ 中是未定义行为。小端只描述表示字节的顺序，不会使这种读取合法；先用 `memcpy` 复制到 `unsigned char` 数组，才可以在本题前提下观察到首字节 `0x78`。
> 9. **C**。`std::variant` 是类型安全的"带标签联合"。
> 10. **C**。匿名联合体只能含非静态数据成员，不能有成员函数，也不能有 `private`/`protected` 成员。

## 二、概念辨析（判断对错并说明理由）

**11.** 结构体对象一定分配在栈上。

**12.** `union` 的大小一定等于其最大成员的大小。

**13.** `struct` 不能定义成员函数，要用成员函数必须改成 `class`。

**14.** 写入 `union` 的一个成员后，可以在标准 C++ 中任意读取其他成员做类型双关。

**15.** 把结构体用 `send(fd, &header, sizeof(header), 0)` 直接发出去，是可靠的跨平台协议传输方式。

**16.** `union` 也可能包含 padding。

**17.** `struct B { int i; char c1; char c2; };` 比 `struct A { char c1; int i; char c2; };` 占用内存更小。

**18.** `std::variant<int, double>` 通常会在堆上分配它存储的值。

> [!success]- 参考答案（第二节）
> 11. **错**。结构体只是类型，对象位置由创建方式决定：局部非静态→栈，`new`→堆，全局/`static`→静态存储区，成员对象跟随外层对象。
> 12. **错**。是"**至少**能容纳最大成员"，还要按最严格成员的对齐补齐尾部 padding。如 `union{int i; char buf[5];}` 大小是 8 而非 5。
> 13. **错**。`struct` 完全可以有成员函数、构造/析构、继承、多态。它和 `class` 只差默认访问/继承权限。
> 14. **错**。标准 C++ 不允许任意读取非活动成员；共同初始序列等规则有有限例外，但不允许任意 `int/float` 重解释。GCC 支持部分 union 类型双关扩展，也不能据此当成标准保证。表示字节的观察方法见第 39 题，C 与 C++ 的区别见第 42 题。
> 15. **错**。结构体内存布局含 padding（可能是未初始化垃圾）、跨平台/编译器/ABI 布局可能不同、多字节整数有字节序问题。应使用定长类型 + 手动序列化 + 约定字节序。
> 16. **对**。union 通常是**尾部 padding**，用于保证 union 数组中每个元素都满足整体对齐。
> 17. **对**。`B`（int,char,char）= 8；`A`（char,int,char）= 12。把小成员集中、大成员靠前可减少中间 padding。
> 18. **错**。`std::variant` 把当前值**内联存储**在自身（对齐存储），不额外堆分配（除非某个候选类型自己会分配）。

> [!success]- 参考答案（第三节）

> 22. 输出 `12`。struct 可以有成员函数，`area()` 返回 `3*4`。
> 23. 输出 `8 4`。尾部补齐到 8，对齐取成员最严格者 `int`=4。
> 24. 输出 `1 100`。`byVal` 改的是副本，`a` 不变；`byRef` 改的是本体，`b` 变 100。
> 25. 输出 `1 0`。初值是 `int` → `holds_alternative<int>` 为真(1)；赋 string 后变为假(0)。
> 26. 输出 `2.5`。`type` 作判别标签，按 `FLT` 读 `f`，匿名联合体成员可直接用名字访问。

## 四、找错与修复（指出 bug 并改正）

**27.**
```cpp
struct S { int id; };
S* p = new S;
std::cout << *p.id << "\n";   // 想打印 id
```

**28.**
```cpp
union U { int i; double d; };
U u;
u.i = 5;
std::cout << u.d << "\n";     // 想"顺便"看看 d
```

**29.**
```cpp
struct Student { int id; char name[20]; float gpa; };
Student s = {.name = "Tom", .id = 1, .gpa = 3.9};  // C++20
```

**30.**
```cpp
struct PacketHeader { char type; int length; short checksum; };
PacketHeader h{ 'A', 100, 7 };
send(fd, &h, sizeof(h), 0);   // 发给另一台机器的服务
```

**31.**
```cpp
union MyUnion { int i; float f; };
MyUnion u = {1, 3.14f};       // 想同时给 i 和 f 初始化
```

> [!success]- 参考答案（第四节）
> 27. **优先级错误**：`*p.id` 被解析为 `*(p.id)`，但 `p` 是指针没有 `.id`，编译错误。改为 `p->id` 或 `(*p).id`。（用完记得 `delete p;`）
> 28. **读非活动成员**：活动成员是 `i`，读 `u.d` 是未定义行为。要数值转换用 `static_cast<double>(u.i)`；要观察 `i` 的表示，复制到 `unsigned char` 数组。本题的 `int/double` 大小不同，不能直接 `bit_cast<double>(u.i)`，也不能用 `memcpy` 随意拼出一个 double 值。
> 29. **指定初始化器乱序**：C++20 要求按声明顺序 `id, name, gpa`。改为 `{.id=1, .name="Tom", .gpa=3.9f}`。
> 30. **直接发结构体不可靠**：padding（含未初始化字节）、字节序、跨平台布局差异。改用定长类型 `uint8_t/uint32_t/uint16_t` 并按协议逐字段序列化、统一字节序（如网络序）。
> 31. **union 只能初始化一个成员**：它们共享内存，`{1, 3.14f}` 非法。写 `MyUnion u = {1};`（初始化 `i`）或 C++20 `MyUnion u = {.f = 3.14f};`。

## 五、简答题

**32.** `struct` 和 `class` 在 C++ 中有什么区别？

**33.** 联合体为什么能节省内存？它的代价（限制）是什么？

**34.** 简述结构体内存对齐的三条基本规则。

**35.** 为什么调换结构体成员的声明顺序会改变 `sizeof`？给出减少 padding 的经验法则。

**36.** `.` 和 `->` 有什么区别？为什么 `*p.member` 通常是错的？

**37.** 传结构体参数时，按值 / `const T&` / `T&` / `T*` 分别在什么场景下用？

> [!success]- 参考答案（第五节）
> 32. 唯一实质区别是**默认访问权限和默认继承权限**：`struct` 默认 `public`，`class` 默认 `private`。其余功能（成员函数、构造析构、继承、多态、模板）完全相同。惯例：`struct` 偏数据聚合，`class` 偏封装与不变量。
> 33. 非静态数据成员共享存储，空间至少容纳最大成员并满足整体对齐。同一时刻至多有一个活动成员；一般不能读取非活动成员，共同初始序列等有限例外不等于任意类型双关。union 不记录当前类型，需要维护标签；含非平凡类型成员时还要管理构造、析构和切换。
> 34. 对本卷普通结构体及自然布局：① 按声明顺序，让每个成员的起始位置满足自身对齐，必要时加中间 padding；② 整体对齐通常取最严格的成员对齐；③ 最后补齐到整体 `alignof(T)` 的整数倍，保证数组后续元素也对齐。`alignas` 可提高整体对齐，打包扩展另有规则，不能无条件说整体对齐等于成员最大对齐。
> 35. padding 用于满足成员和整体的对齐要求。把对齐要求较大的成员靠前、较小成员集中，通常能减少填充；按实际 `alignof` 比较，不要只看 `sizeof` 或死记类型排序。重排会改变偏移和 ABI，已有二进制接口要检查兼容性。
> 36. `.` 用于对象访问成员，`->` 用于指针访问成员（`p->m` 等价 `(*p).m`）。`.` 优先级高于 `*`，所以 `*p.member` 被解析为 `*(p.member)`；对指针 `p` 没有 `.member`，应写 `p->member` 或 `(*p).member`。
> 37. 只读且对象较大 → `const T&`（零拷贝、防改）；必须修改且对象一定存在 → `T&`；对象可能为空 → `T*`（判 `nullptr`）；对象很小或需要独立副本 → 按值。要转移所有权 → `T&&` + `std::move`。

## 六、综合设计与手写代码

**38.** 用结构体 + `enum` 标签 + 联合体，手写一个**带标签联合（tagged union）**，能安全地存 `int` 或 `double`，并写一个按标签读取的函数。再说明 `std::variant` 相比它好在哪。

**39.** 为什么先写 union 的整数成员、再读其字节数组成员，不能作为标准 C++ 的可移植字节序检测？用 `std::memcpy` 实现 `isLittleEndian()`，再说明 C++20 的替代方式。

**40.** 给定下面的结构体，在不改变成员类型的前提下重排成员，使 `sizeof` 最小，并写出两种布局的字节数。
```cpp
struct Bad { char a; double b; char c; int d; short e; };
```

**41.** 设计一个跨平台的网络包头 `PacketHeader`（含 1 字节类型、4 字节长度、2 字节校验和），给出**安全序列化**到字节缓冲区的思路（不直接 `memcpy` 整个结构体）。

> [!success]- 参考答案（第六节）
> **38.**
> ```cpp
> struct Number {
>     enum Tag { INT, DOUBLE } tag;
>     union { int i; double d; };
> };
> double readAsDouble(const Number& n) {
>     return n.tag == Number::INT ? double(n.i) : n.d;   // 按标签读，避免读错成员
> }
> ```
> `std::variant` 的优势：自动维护"当前类型"、访问错类型抛 `std::bad_variant_access`、支持 `std::visit` 模式匹配、对非平凡类型自动管理构造析构——比手写 tagged union 更安全省心。
>
> **39.**
> ```cpp
> #include <climits>
> #include <cstdint>
> #include <cstring>
>
> bool isLittleEndian() {
>     static_assert(CHAR_BIT == 8);
>     std::uint32_t value = 0x01020304;
>     unsigned char bytes[sizeof value];
>     std::memcpy(bytes, &value, sizeof value);
>     return bytes[0] == 0x04 && bytes[1] == 0x03
>         && bytes[2] == 0x02 && bytes[3] == 0x01;
> }
> ```
> 该函数在本题的 8 位字节、存在 `uint32_t` 的平台上检查完整的小端表示。它读取的是复制出的字节数组；先写 union 的整数成员再读另一个数组成员，则违反活动成员规则。
> C++20 可以直接查询字节序：
> ```cpp
> #include <bit>
> constexpr bool little = std::endian::native == std::endian::little;
> ```
> `little` 为假不自动等于大端，也可能是混合字节序；需要时另行比较 `std::endian::big`。观察表示还可以使用符合条件的 `std::bit_cast`。
>
> **40.** 按本卷布局假设，`Bad` 的成员偏移依次是 `a: 0, b: 8, c: 16, d: 20, e: 24`。最后一个成员结束于偏移 26，再补到 8 的倍数，得到 **32 字节**。重排为：
> ```cpp
> struct Good { double b; int d; short e; char a; char c; };  // 8+4+2+1+1=16
> ```
> `Good` 的偏移依次是 `b: 0, d: 8, e: 12, a: 14, c: 15`，总计 **16 字节**，已经满足 8 字节对齐，无需额外尾部填充；成员大小之和就是 16，因此在这些条件下已达到最小值。
>
> **41.** 思路：①用定长类型定义逻辑字段 `uint8_t type; uint32_t length; uint16_t checksum;`；②准备 `uint8_t buf[7]`；③逐字段写入，多字节字段统一转**网络字节序**（`htonl`/`htons`）：
> ```cpp
> uint8_t buf[7];
> buf[0] = type;
> uint32_t len_n = htonl(length);  std::memcpy(buf + 1, &len_n, 4);
> uint16_t crc_n = htons(checksum); std::memcpy(buf + 5, &crc_n, 2);
> // buf 的协议长度固定为 7 字节；TCP 发送还需循环处理部分发送和错误
> ```
> 接收端累计收到完整的 7 字节后，按相同偏移和字节序反序列化，并校验长度及字段值。这里定义的是独立于结构体布局的协议格式。

## 七、概念辨析进阶

**42.** "类型双关 (type punning)" 通过 union 实现，在 C 和 C++ 标准里的合法性有什么不同？C++ 里推荐的可移植替代是什么？

**43.** `sizeof` 和 `alignof` 各表示什么？对 `union{int i; char buf[5];}` 它们分别是多少？

**44.** 什么是**位域 (bit-field)**？写一个用位域压缩存储的例子，并指出它的可移植性陷阱。

**45.** 解释 trivially-copyable / standard-layout 两个概念，为什么它们和"能不能 `memcpy` 整个对象""能不能跨语言/跨进程传"有关？

> [!success]- 参考答案（第七节）
> 42. C 与 C++ 的规则不同。C 对通过 union 成员访问重新解释表示有相应规则，但结果依赖对象表示，还可能形成陷阱表示，不能理解为“任意两个类型都能安全转换”；见 [C11 草案 N1570，6.5.2.3 脚注 95](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)。标准 C++ 不允许任意读取非活动成员，只有共同初始序列等有限例外。GCC 明确把部分 union 类型双关作为扩展支持，见 [GCC 文档](https://gcc.gnu.org/onlinedocs/gcc/Optimize-Options.html#index-fstrict-aliasing)。C++ 观察表示可用 `memcpy` 复制到字节数组；若用 C++20 `bit_cast<To>(from)`，源、目标须同大小且可平凡复制，目标位模式还必须合法。
> 43. `sizeof` 是对象占用的字节数；`alignof` 是该类型要求的对齐字节数（地址须为它的整数倍）。对 `union{int i; char buf[5];}`：`sizeof = 8`（5 向上补齐到 4 的倍数），`alignof = 4`（取成员最严格的 `int`）。
> 44.
> ```cpp
> struct Flags {
>     unsigned ready : 1;   // 占 1 bit
>     unsigned mode  : 3;   // 占 3 bit
>     unsigned count : 12;  // 占 12 bit
> };
> ```
> 位域可压缩小范围字段，但类型必须是整型或枚举；`char/bool` 也属于整型。这里位宽合计 16 位，**不保证 `sizeof(Flags) == 2`，也不保证没有 padding**。分配单元、位的排列方向、是否跨分配单元、对齐和填充由实现决定，差异不只取决于操作系统。匿名零宽位域可能增加填充；不能对位域单独取地址、使用 `sizeof` 或直接绑定非 `const` 引用。跨平台格式应使用移位、掩码和明确的字节序逐字段打包；`#pragma pack(1)` 也不能统一位域排列或字节序。见 [[7.1 结构体#位域能压缩字段，但不保证没有 padding|位域与填充]]。
> 45.
> - **trivially copyable**：为完整对象的按字节复制提供标准保证，可用 `std::is_trivially_copyable_v<T>` 判断；不是说任意外部字节都构成合法对象值。
> - **standard layout**：满足一组布局限制，例如无虚函数、非静态数据成员访问权限一致等；可用 `std::is_standard_layout_v<T>` 判断，常用于 `offsetof` 和 C 接口布局设计。
> 两者不能互相替代，也都不保证跨平台、跨进程传递安全。指针本身可平凡复制，但地址通常不能给另一个进程使用；还要确认 ABI、对齐、字节序、生命周期和版本。`std::string` 不可平凡复制；它是否满足标准布局不能一概断言，也不影响必须按内容序列化的结论。规则见 [C++17 草案：对象字节复制](https://timsong-cpp.github.io/cppwp/n4659/basic.types#2)；应用见 [[17.八股知识点/17.4 结构联合枚举#7. trivially copyable 和 standard layout 是一回事吗？|两种类型性质]]。

## 八、大厂面试场景题

> 偏真实工程，含网络/系统/性能方向。

**46.** 同事把一个 C++ 结构体直接 `memcpy` 进缓冲区通过 socket 发给另一台不同架构的机器，对端解析出来字段全乱。请系统地列出**所有可能的原因**和**正确做法**。

**47.** 项目里有个"值可能是 int、string 或一组坐标"的配置项，老代码用 `union` + 手写 `enum` 标签实现，经常因为忘了更新标签而读错类型导致崩溃。你会怎么用现代 C++ 重构？怎么遍历处理？

**48.** 一个 `struct` 在 64 位机上 `sizeof` 是 40 字节，里面只有几个 `int` 和 `bool`。怎么会这么大？你怎么排查并优化？这对一个要装进数组、被 GPU/SIMD 批量处理的热数据结构有什么意义？

**49.** 嵌入式/驱动里常见这种写法：把一个寄存器地址 `reinterpret_cast` 成结构体指针，或用 union 把一个 32 位寄存器拆成若干位域来读写。这样做的好处和风险分别是什么？

**50.** 为什么说"`union` 知道大小但不知道类型"是它最大的安全隐患？`std::variant` 是如何解决的？它在异常安全上有什么代价（valueless_by_exception）？

> [!success]- 参考答案（第八节·上）
> 46. 原因包括：padding 位置和内容不稳定；字节序、类型宽度、ABI 或版本不同；指针只带出地址而不带出所指数据；`std::string` 等对象的内部表示无法在对端重建。裸指针本身可平凡复制，不能把它笼统归为非平凡类型。正确做法是定义固定宽度的逻辑字段，按协议逐字段序列化并统一字节序；字符串编码长度和内容，指针关联改为可解析的 ID。TCP 还要处理部分读写和消息边界，不能把一次收发当成一条完整记录。
> 47. 用 `std::variant<int, std::string, Point>` 替换手写 tagged union——它自动记录当前类型，访问错类型抛异常而非静默崩溃。遍历处理用 `std::visit` + 重载的 visitor：
> ```cpp
> std::variant<int, std::string, Point> cfg = ...;
> std::visit([](auto&& v){ /* 按实际类型处理 */ }, cfg);
> // 或 std::holds_alternative<T> / std::get_if<T> 做条件分支
> ```
> 好处：编译期类型集合固定、运行期类型安全、无需手动同步标签。
> 48. 先看完整定义、成员数量和编译选项；“64 位”不决定结构体大小，也不能在只有 `int/bool` 的前提下凭空补出 double 或指针。逐项检查 `sizeof`、`alignof`，标准布局类型可用 `offsetof`，也可查看编译器布局报告或 `-Wpadded` 提示，确认是成员间填充、尾部填充还是额外对齐要求。按实际对齐重排、集中小成员可能减少大小，但要检查 ABI。对批量处理还要结合访问模式评估 AoS/SoA 和缓存行为；强行压紧可能造成未对齐访问，不能保证越小越快。

> [!success]- 参考答案（第八节·下）
> 49. 这种写法能提供字段式访问，但必须依赖明确的硬件、编译器和 ABI 契约。位域排列和访问宽度可能不同，对单个位域的修改还可能生成整单元读改写，对有副作用的寄存器并不安全。`reinterpret_cast` 本身不建立对象生命周期，也不保证对齐或访问合法；通过 union 读非活动成员仍有相应限制。应使用平台提供的 MMIO 接口或已验证的访问方式；`volatile` 按实现规则影响访问，但不能修复布局或类型错误，也不保证原子性、线程同步或硬件屏障。普通协议字节缓冲区应另行解析。
> 50. `union` 的存储至少容纳最大成员并满足整体对齐，但不记录当前活动成员，需要维护标签及生命周期。一般读取非活动成员是未定义行为，不能依赖它给出稳定结果。`std::variant` 维护类型索引并管理候选值：`get` 类型不匹配时抛 `std::bad_variant_access`，`get_if` 则返回空指针，也可用 `visit` 分发。某些抛异常的切换可能产生 `valueless_by_exception()` 状态，此时 `index()` 为 `variant_npos`。

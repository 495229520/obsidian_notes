# 7.1 结构体

C++ 中的结构体（struct）是一种用户自定义的数据类型，它允许你将多个不同类型的数据组合成一个单一的单元。可以将结构体看作是一个自定义的"容器"，它可以容纳多个相关的变量，这些变量被称为结构体的**成员**。

> 结构体的基础概念可参考 [[2.4 枚举与结构体#结构体（struct）]]

---

## 定义

使用 `struct` 关键字定义一个结构体，其基本语法如下：

```cpp
struct 结构体名 {
    成员类型  成员名1;
    成员类型  成员名2;
    // ... 更多成员
};  // 注意分号结尾
```

**示例**：

```cpp
struct Student {
    int id;
    char name[50];
    float gpa;
};
```

---

## 内存分配

结构体只是一个**类型**，它本身不决定对象一定在栈上还是堆上。结构体对象的存储位置取决于对象的创建方式。

### 常见存储位置

#### 1. 局部非静态对象：通常在栈上

```cpp
void someFunction() {
    Role myRole;  // 局部非静态对象，通常在栈上
    myRole.hp = 100;
    myRole.mp = 50;
}
// someFunction 退出后，myRole 的生命周期结束。
```

#### 2. new 创建的对象：在堆上

如果使用 `new` 运算符动态创建 `Role` 结构体对象，那么对象本身在堆上：

```cpp
Role* myRolePtr = new Role;  // *myRolePtr 指向的 Role 对象在堆上
myRolePtr->hp = 100;
myRolePtr->mp = 50;

delete myRolePtr;  // 手动释放堆上对象
```

> Modern C++ 中应优先使用 RAII 和智能指针管理资源，避免裸 `new/delete`。关于动态内存分配，参考 [[6.2 动态内存分配与释放]]。

#### 3. 全局对象和静态对象：在静态存储区

```cpp
Role globalRole;  // 全局对象，静态存储区

void f() {
    static Role staticRole;  // 静态局部对象，静态存储区
}
```

#### 4. 成员对象：跟随外层对象

```cpp
struct Team {
    Role leader;
};

Team localTeam;              // localTeam 在栈上，leader 作为其一部分也在栈上
Team* heapTeam = new Team;   // *heapTeam 在堆上，leader 作为其一部分也在堆上
```

> 关键理解：不要说“结构体一定在栈上”。应说“结构体对象的位置由对象的存储期和创建方式决定”。关于栈和堆的区别，参考 [[6.6 堆与栈的区别]]。

## 成员访问

### 点运算符（.）

可以使用点运算符来访问结构体成员：

```cpp
Student stu1;
stu1.id = 1001;
strcpy(stu1.name, "Alice");
stu1.gpa = 3.8;

std::cout << stu1.name << "'s GPA is " << stu1.gpa << std::endl;
```

### 箭头运算符（->）

如果有一个指向结构体的[[6.1基本指针|指针]]，可以使用箭头运算符来访问成员：

```cpp
Student* stuPtr = new Student;
stuPtr->id = 1002;
strcpy(stuPtr->name, "Bob");
stuPtr->gpa = 3.5;

std::cout << stuPtr->name << "'s GPA is " << stuPtr->gpa << std::endl;

delete stuPtr;  // 释放堆上分配的内存
```

`->` 本质上是“先解引用指针，再访问成员”：

```cpp
stuPtr->id      // 等价于 (*stuPtr).id
```

不能写成：

```cpp
*stuPtr.id      // 错误理解：这会先计算 stuPtr.id
```

因为成员访问运算符 `.` 的优先级高于解引用运算符 `*`，所以 `*stuPtr.id` 会被解析为：

```cpp
*(stuPtr.id)
```

但 `stuPtr` 是指针，指针本身没有 `id` 成员，因此这种写法是错误的。

> 关于指针访问结构体的详细内容，包括汇编分析和内存对齐，参考 [[6.7 指针结构体]]

## 结构体初始化

### 1. 花括号初始化

可以使用花括号 `{}` 初始化结构体：

```cpp
Student stu2 = {1003, "Charlie", 3.9};
```

### 2. 成员名称初始化（C++20）

可以使用成员名称初始化：

```cpp
Student stu3 = {.id = 1004, .name = "David", .gpa = 3.7};
```

C++20 指定初始化器要求初始化顺序与成员声明顺序一致。以上 `Student` 的声明顺序是 `id`、`name`、`gpa`，因此不能写成：

```cpp
Student stu4 = {.name = "David", .id = 1004, .gpa = 3.7};  // 非标准 C++20 写法
```

> 注意：C 语言的指定初始化器允许乱序，但 C++20 不允许乱序。

## 结构体数组

可以创建结构体数组，存储多个结构体实例：

```cpp
Student students[3];
students[0] = {1001, "Alice", 3.8};
students[1] = {1002, "Bob", 3.5};
students[2] = {1003, "Charlie", 3.9};
```

## 结构体作为函数参数和返回值

结构体可以作为函数的参数和返回值：

```cpp
void printStudent(Student stu) {
    std::cout << "'s ID: " << stu.name << stu.id << ", GPA: " << stu.gpa;
}

Student createStudent(int id, const char* name, float gpa) {
    Student stu = {id, "", gpa};
    strcpy(stu.name, name);
    return stu;
}
```

### 参数传递方式

#### 1. 按值传递

```cpp
void printStudent(Student stu);
```

按值传递会复制整个结构体对象。结构体很小时影响不大，但如果结构体包含较大数组、字符串或其他复杂成员，复制成本可能较高。

#### 2. const 引用传递：只读大对象的常用写法

如果函数只读取结构体内容，不修改对象，优先使用 `const T&`：

```cpp
void printStudent(const Student& stu) {
    std::cout << stu.name << "'s ID: " << stu.id << ", GPA: " << stu.gpa;
}
```

这样既避免了拷贝，又通过 `const` 防止函数内部修改原对象。

#### 3. 非 const 引用传递：必须修改对象

如果函数需要修改传入对象，并且这个对象必须存在，可以使用非 `const` 引用：

```cpp
void updateGpa(Student& stu, float newGpa) {
    stu.gpa = newGpa;
}
```

引用表达的语义是：调用者必须传入一个有效对象。

#### 4. 指针传递：对象可能为空

如果参数可以为空，或者需要表达“可能没有对象”，可以使用指针：

```cpp
void updateGpa(Student* stu, float newGpa) {
    if (stu == nullptr) {
        return;
    }
    stu->gpa = newGpa;
}
```

> 经验规则：只读大对象用 `const T&`；必须修改且对象不能为空时用 `T&`；对象可能为空时用 `T*`。

## 结构体和类的区别

在 C++ 中，`struct` 和 `class` 的主要区别在于**默认访问权限**和**默认继承权限**：

| 对比项 | struct | class |
|---|---|---|
| 默认成员访问权限 | `public` | `private` |
| 默认继承权限 | `public` | `private` |

除此之外，它们几乎是相同的。二者都可以有成员变量、成员函数、构造函数、析构函数、访问控制、继承和多态。

```cpp
struct Base {};

struct DerivedStruct : Base {};  // 默认 public 继承
class DerivedClass : Base {};    // 默认 private 继承
```

实际编码中，`struct` 通常用于以数据聚合为主的类型，`class` 通常用于强调封装和不变量的类型。

    int area() {

## 内存对齐与 padding

结构体大小通常不是所有成员大小的简单相加，因为编译器会为了内存访问效率插入 padding（填充字节）。

### 对齐的基本规则

结构体成员按照声明顺序依次排列。每个成员通常要放在满足自身对齐要求的地址上；结构体整体大小通常要补齐到最大对齐要求的整数倍。

```cpp
struct A {
    char c;
    int i;
};
```

在常见平台上，`char` 大小为 1 字节、对齐要求为 1；`int` 大小为 4 字节、对齐要求为 4。内存布局通常是：

```text
偏移 0: char c      // 1 字节
偏移 1-3: padding   // 3 字节，使 int 从 4 的倍数地址开始
偏移 4-7: int i     // 4 字节
```

因此 `sizeof(A)` 通常是 8，而不是 5。

### 成员顺序会影响结构体大小

```cpp
struct A {
    char c1;
    int i;
    char c2;
};

struct B {
    int i;
    char c1;
    char c2;
};
```

在常见平台上，`sizeof(A)` 通常是 12，`sizeof(B)` 通常是 8。

`A` 的布局通常是：

```text
char c1       // 1 字节
padding       // 3 字节
int i         // 4 字节
char c2       // 1 字节
tail padding  // 3 字节，使整体大小为 4 的倍数
```

`B` 的布局通常是：

```text
int i         // 4 字节
char c1       // 1 字节
char c2       // 1 字节
tail padding  // 2 字节，使整体大小为 4 的倍数
```

> 重点：padding 不是“把所有小成员补到最大成员大小”，而是为了让每个成员位于满足其对齐要求的地址上，并让整个结构体大小满足整体对齐要求。

### 网络协议传输中的风险

如果结构体用于网络协议或二进制文件格式，不应直接发送整个结构体内存：

```cpp
struct PacketHeader {
    char type;
    int length;
    short checksum;
};

send(socketFd, &header, sizeof(header), 0);  // 不推荐
```

常见布局可能是：

```text
偏移 0: type         // 1 字节
偏移 1-3: padding    // 3 字节
偏移 4-7: length     // 4 字节
偏移 8-9: checksum   // 2 字节
偏移 10-11: padding  // 2 字节
```

直接发送 `sizeof(header)` 字节可能带来几个问题：padding 字节可能包含未初始化数据；不同平台、编译器或 ABI 下结构体布局可能不同；多字节整数还存在大小端问题；`int`、`short` 这类类型大小也不适合作为跨平台协议字段。

更可靠的方式是使用定长整数类型，并按协议手动序列化：

```cpp
struct PacketHeader {
    std::uint8_t type;
    std::uint32_t length;
    std::uint16_t checksum;
};
```

发送前将字段逐个写入缓冲区，并按协议要求处理字节序。

---

## 关键要点

1. **结构体定义**：使用 `struct` 关键字将多个逻辑相关的数据组合成一个自定义类型
2. **存储位置**：结构体只是类型，对象在栈、堆还是静态存储区取决于创建方式
3. **成员访问**：对象用 `.`，指针用 `->`，`p->x` 等价于 `(*p).x`
4. **初始化方式**：支持花括号初始化和 C++20 指定成员名初始化，指定初始化器必须按成员声明顺序书写
5. **参数传递**：只读大对象优先使用 `const T&`，需要修改且对象不能为空时使用 `T&`，对象可能为空时使用 `T*`
6. **与类的区别**：主要是默认成员访问权限和默认继承权限不同
7. **内存对齐**：结构体大小可能包含 padding，不一定等于所有成员大小之和

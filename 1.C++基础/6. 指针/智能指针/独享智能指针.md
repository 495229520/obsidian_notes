> [!abstract] unique_ptr 速记卡片
> **一句话**：独占堆对象所有权，禁止拷贝、仅允许移动（`std::move`）；依托 RAII 离开作用域自动析构释放；默认删除器下体积与裸指针一致（64 位下 8 字节，零额外运行时开销）。以下示例除特别注明外省略 `std::`，以 C++14/17 为准。
>
> | 要做什么 | 常用写法 / 要点 |
> | --- | --- |
> | 头文件与类型 | `#include <memory>`；类型写作 `unique_ptr<T>` 或带自定义删除器的 `unique_ptr<T, Deleter>` |
> | 推荐创建 | `make_unique<T>(args...)`（C++14），具备强异常安全保证且避免重复写类型；不可用于私有构造或自定义删除器 |
> | 直接绑定原生指针 | `unique_ptr<T> p(new T(args...));`；严禁将同一原生指针绑定给两个独立智能指针 |
> | 访问与判空 | `*p` 解引用；`p->member` 访问成员；`if (p)` 或 `if (p != nullptr)` 检查是否持有有效对象 |
> | 借用原生指针 | `p.get()` 获取底层裸指针，**不改变所有权**，调用方绝不可手动 `delete` |
> | 移交所有权 | `p.release()` 返回裸指针并将 `p` 置空，**切断所有权**，后续代码必须接管该指针并负责释放 |
> | 销毁或替换对象 | `p.reset()` 立即 `delete` 原对象并将 `p` 置空；`p.reset(new_ptr)` 释放原对象并接管新指针 |
> | 移动语义移交 | `unique_ptr<T> p2 = std::move(p1);`（移动后 `p1` 为空，`p2` 接管）；禁止拷贝构造与拷贝赋值 |
> | 管理动态数组 | `unique_ptr<T[]> arr(new T[n]);` 或 `make_unique<T[]>(n)`；支持 `arr[i]` 下标访问，析构调用 `delete[]` |
> | 自定义删除器 | 需作为模板第二参数：`unique_ptr<FILE, decltype(&fclose)> f(fopen(...), &fclose);` |
> | 单向转为 shared_ptr | `shared_ptr<T> sp = std::move(up);` 安全接管独占指针并建立共享控制块；反向转换不成立 |
>
> **关键接口区别（get / release / reset）**
>
> | 接口 | 原对象是否被释放 | 原智能指针状态 | 调用后责任边界 |
> | --- | --- | --- | --- |
> | `p.get()` | 否 | 保持持有 | 纯粹借用观察，外部绝不可执行 `delete` |
> | `p.release()` | 否 | 置为 `nullptr` | 外部必须手动 `delete` 或转交其他 RAII 对象，否则泄漏 |
> | `p.reset(...)` | **是**（旧对象立即析构） | 置空或指向新地址 | 智能指针继续托管新传入的地址（若有） |
>
> **常用操作模板**
> ```cpp
> // 1. 工厂函数：返回值返回独占指针（利用移动语义与 RVO，外部按需接收）
> std::unique_ptr<Widget> createWidget(int id) {
>     return std::make_unique<Widget>(id);
> }
>
> // 2. 所有权传递契约：接收所有权用值传递，仅借用数据传 const 引用或裸指针
> void consume(std::unique_ptr<Widget> w);     // 移交所有权，调用方必须使用 std::move
> void inspect(const Widget& w);               // 仅借用，通过 *p 传入，生命周期由外部保证
>
> // 3. 自定义删除器：无状态仿函数（零额外体积开销，sizeof 为 8 字节）
> struct FileCloser {
>     void operator()(FILE* fp) const { if (fp) fclose(fp); }
> };
> std::unique_ptr<FILE, FileCloser> fp(fopen("data.txt", "r"));
>
> // 4. 容器存储多态对象集合
> std::vector<std::unique_ptr<Base>> vec;
> vec.push_back(std::make_unique<Derived>());
> ```
>
> **四个必记易错点**
> - **严禁自重置**：`p.reset(p.get())` 会导致内部先释放裸指针指向的内存，再将已被释放的悬空地址重新赋值给自己，触发双重释放与未定义行为。
> - **release 泄漏**：调用 `p.release()` 会直接脱离智能指针管理，如果返回值未被接收且无后续 `delete`，等同于原生内存泄漏。
> - **多态基类虚析构**：用 `unique_ptr<Base>` 持有派生类对象时，基类 `Base` 必须声明 `virtual ~Base()`；否则析构时只会调用基类析构函数，引发派生类资源泄漏。
> - **删除器与对象体积**：`unique_ptr` 默认通过空基类优化（EBO）让无状态删除器不占内存。如果使用普通函数指针（如 `decltype(&free)`），指针实例体积将翻倍至 16 字节；优先使用无状态仿函数或无捕获 lambda。
>
> **口诀**：独占不拷贝，转移靠 move；借用拿 get，放权 release；换人用 reset，多态基类虚析构。
>

# 独享智能指针 (unique_ptr)

> `unique_ptr` 是 C++11 引入的独占式智能指针，表示对动态分配资源的**单一所有权**。当持有该资源的 `unique_ptr` 离开作用域或被重置时，它所管理的对象会自动销毁并释放资源。

---

## 模板类核心实现代码

这里给出符合标准语义的 `unique_ptr` 模板类实现骨架，涵盖默认删除器、单对象主模板、数组偏特化以及 `make_unique` 工厂函数：

```cpp
#include <utility>      // std::move, std::forward
#include <cstddef>      // std::size_t, std::nullptr_t
#include <type_traits>  // std::is_array, std::enable_if_t, std::remove_extent_t

// ==========================================
// 1. 默认删除器
// ==========================================
template <typename T>
struct default_delete {
    constexpr default_delete() noexcept = default;

    template <typename U, typename = std::enable_if_t<std::is_convertible<U*, T*>::value>>
    default_delete(const default_delete<U>&) noexcept {}

    void operator()(T* ptr) const noexcept {
        static_assert(sizeof(T) > 0, "can not delete incomplete type");
        delete ptr;
    }
};

template <typename T>
struct default_delete<T[]> {
    constexpr default_delete() noexcept = default;

    void operator()(T* ptr) const noexcept {
        static_assert(sizeof(T) > 0, "can not delete incomplete type");
        delete[] ptr;
    }
};

// ==========================================
// 2. unique_ptr 单对象主模板
// ==========================================
template <typename T, typename Deleter = default_delete<T>>
class unique_ptr {
public:
    using pointer = T*;
    using element_type = T;
    using deleter_type = Deleter;

private:
    pointer ptr_ = nullptr;
    deleter_type deleter_{};

public:
    // --- 构造与析构 ---
    constexpr unique_ptr() noexcept : ptr_(nullptr), deleter_() {}
    constexpr unique_ptr(std::nullptr_t) noexcept : ptr_(nullptr), deleter_() {}

    explicit unique_ptr(pointer p) noexcept : ptr_(p), deleter_() {}

    unique_ptr(pointer p, const deleter_type& d) noexcept : ptr_(p), deleter_(d) {}
    unique_ptr(pointer p, deleter_type&& d) noexcept : ptr_(p), deleter_(std::move(d)) {}

    ~unique_ptr() {
        if (ptr_ != nullptr) {
            deleter_(ptr_);
            ptr_ = nullptr;
        }
    }

    // --- 禁用拷贝语义（独占所有权） ---
    unique_ptr(const unique_ptr&) = delete;
    unique_ptr& operator=(const unique_ptr&) = delete;

    // --- 移动构造与移动赋值 ---
    unique_ptr(unique_ptr&& other) noexcept
        : ptr_(other.release()), deleter_(std::forward<deleter_type>(other.deleter_)) {}

    unique_ptr& operator=(unique_ptr&& other) noexcept {
        if (this != &other) {
            reset(other.release());
            deleter_ = std::forward<deleter_type>(other.deleter_);
        }
        return *this;
    }

    unique_ptr& operator=(std::nullptr_t) noexcept {
        reset();
        return *this;
    }

    // --- 支持多态向上移动转换 (Derived* -> Base*) ---
    template <typename U, typename E, typename = std::enable_if_t<
        std::is_convertible<typename unique_ptr<U, E>::pointer, pointer>::value &&
        !std::is_array<U>::value &&
        std::is_convertible<E, deleter_type>::value>>
    unique_ptr(unique_ptr<U, E>&& other) noexcept
        : ptr_(other.release()), deleter_(std::forward<E>(other.get_deleter())) {}

    template <typename U, typename E, typename = std::enable_if_t<
        std::is_convertible<typename unique_ptr<U, E>::pointer, pointer>::value &&
        !std::is_array<U>::value &&
        std::is_assignable<deleter_type&, E&&>::value>>
    unique_ptr& operator=(unique_ptr<U, E>&& other) noexcept {
        reset(other.release());
        deleter_ = std::forward<E>(other.get_deleter());
        return *this;
    }

    // --- 观察接口 ---
    pointer get() const noexcept { return ptr_; }
    deleter_type& get_deleter() noexcept { return deleter_; }
    const deleter_type& get_deleter() const noexcept { return deleter_; }
    explicit operator bool() const noexcept { return ptr_ != nullptr; }

    typename std::add_lvalue_reference<T>::type operator*() const { return *ptr_; }
    pointer operator->() const noexcept { return ptr_; }

    // --- 所有权控制接口 ---
    pointer release() noexcept {
        pointer temp = ptr_;
        ptr_ = nullptr;
        return temp;
    }

    void reset(pointer p = pointer()) noexcept {
        pointer old = ptr_;
        ptr_ = p;
        if (old != nullptr) {
            deleter_(old);
        }
    }

    void swap(unique_ptr& other) noexcept {
        using std::swap;
        swap(ptr_, other.ptr_);
        swap(deleter_, other.deleter_);
    }
};

// ==========================================
// 3. unique_ptr 动态数组偏特化
// ==========================================
template <typename T, typename Deleter>
class unique_ptr<T[], Deleter> {
public:
    using pointer = T*;
    using element_type = T;
    using deleter_type = Deleter;

private:
    pointer ptr_ = nullptr;
    deleter_type deleter_{};

public:
    constexpr unique_ptr() noexcept : ptr_(nullptr), deleter_() {}
    constexpr unique_ptr(std::nullptr_t) noexcept : ptr_(nullptr), deleter_() {}

    explicit unique_ptr(pointer p) noexcept : ptr_(p), deleter_() {}

    unique_ptr(pointer p, const deleter_type& d) noexcept : ptr_(p), deleter_(d) {}
    unique_ptr(pointer p, deleter_type&& d) noexcept : ptr_(p), deleter_(std::move(d)) {}

    ~unique_ptr() {
        if (ptr_ != nullptr) {
            deleter_(ptr_);
            ptr_ = nullptr;
        }
    }

    unique_ptr(const unique_ptr&) = delete;
    unique_ptr& operator=(const unique_ptr&) = delete;

    unique_ptr(unique_ptr&& other) noexcept
        : ptr_(other.release()), deleter_(std::forward<deleter_type>(other.deleter_)) {}

    unique_ptr& operator=(unique_ptr&& other) noexcept {
        if (this != &other) {
            reset(other.release());
            deleter_ = std::forward<deleter_type>(other.deleter_);
        }
        return *this;
    }

    unique_ptr& operator=(std::nullptr_t) noexcept {
        reset();
        return *this;
    }

    pointer get() const noexcept { return ptr_; }
    deleter_type& get_deleter() noexcept { return deleter_; }
    const deleter_type& get_deleter() const noexcept { return deleter_; }
    explicit operator bool() const noexcept { return ptr_ != nullptr; }

    // 下标访问，数组特化版本不提供 operator* 与 operator->
    T& operator[](std::size_t i) const { return ptr_[i]; }

    pointer release() noexcept {
        pointer temp = ptr_;
        ptr_ = nullptr;
        return temp;
    }

    void reset(pointer p = pointer()) noexcept {
        pointer old = ptr_;
        ptr_ = p;
        if (old != nullptr) {
            deleter_(old);
        }
    }

    void swap(unique_ptr& other) noexcept {
        using std::swap;
        swap(ptr_, other.ptr_);
        swap(deleter_, other.deleter_);
    }
};

// 非成员辅助函数
template <typename T, typename D>
void swap(unique_ptr<T, D>& lhs, unique_ptr<T, D>& rhs) noexcept {
    lhs.swap(rhs);
}

template <typename T, typename D>
bool operator==(const unique_ptr<T, D>& x, std::nullptr_t) noexcept {
    return !x;
}
template <typename T, typename D>
bool operator==(std::nullptr_t, const unique_ptr<T, D>& x) noexcept {
    return !x;
}
template <typename T, typename D>
bool operator!=(const unique_ptr<T, D>& x, std::nullptr_t) noexcept {
    return static_cast<bool>(x);
}
template <typename T, typename D>
bool operator!=(std::nullptr_t, const unique_ptr<T, D>& x) noexcept {
    return static_cast<bool>(x);
}

// ==========================================
// 4. make_unique 辅助构造函数（C++14）
// ==========================================
template <typename T, typename... Args, typename = std::enable_if_t<!std::is_array<T>::value>>
unique_ptr<T> make_unique(Args&&... args) {
    return unique_ptr<T>(new T(std::forward<Args>(args)...));
}

template <typename T, typename = std::enable_if_t<std::is_array<T>::value && std::extent<T>::value == 0>>
unique_ptr<T> make_unique(std::size_t size) {
    using Element = std::remove_extent_t<T>;
    return unique_ptr<T>(new Element[size]());
}
```

## 1. 为什么需要 unique_ptr

在传统 C++ 中使用裸指针直接操作堆内存，存在几个根本性的生命周期问题：

1. **所有权不明确**：裸指针类型仅代表一个内存地址，无法表达谁拥有该对象、谁负责 `delete`、何时释放。
2. **释放机制不确定**：无法直接从声明判断是指向单一对象（需 `delete`）还是动态数组（需 `delete[]`），亦或是需要特定的释放函数（如 `free` 或 `fclose`）。
3. **控制流分支与异常泄漏**：在多分支函数或异常抛出时，手动调用的 `delete` 很容易被跳过。

```cpp
void process() {
    int* p = new int(10);

    if (condition_failed) {
        return; // 提前返回，发生内存泄漏
    }

    doSomethingRisky(); // 若此处抛出异常，栈展开会直接跳过后续代码

    delete p; // 正常路径才能到达
}
```

`std::unique_ptr` 基于 **RAII（Resource Acquisition Is Initialization）** 模式构建：将堆资源的生命周期绑定到栈对象的生命周期上。局部变量离开作用域触发析构函数，析构函数自动执行清理。

```text
process() 进入
  │
  ├── 栈上创建 unique_ptr<int> p ──► 指向堆上分配的 int(10)
  │
  ├── 发生分支 return 或异常抛出
  │
  ▼
栈展开，局部对象 p 析构
  │
  ▼
自动调用 delete 释放堆内存（无泄漏）
```

## 2. 核心特征与内存开销

- **独占所有权**：同一时刻有且仅有一个 `unique_ptr` 拥有对应资源。
- **禁止复制，仅允许移动**：拷贝构造与拷贝赋值被显式删除（`= delete`），仅能通过 `std::move` 转移所有权。
- **零开销抽象**：在默认删除器或无状态删除器下，`sizeof(std::unique_ptr<T>)` 与原生裸指针完全相同（64 位系统下为 8 字节），没有控制块与原子引用计数开销。

### 删除器类型对大小的影响

`unique_ptr` 的内存开销取决于删除器是否占用状态：

| 删除器类型 | `sizeof(unique_ptr)` | 原理说明 |
|---|---|---|
| 默认删除器 `std::default_delete<T>` | `sizeof(T*)`（8 字节） | 利用空基类优化（EBO），不占额外空间 |
| 无状态函数对象 / 无状态 lambda | `sizeof(T*)`（8 字节） | 空类不增加大小 |
| 普通函数指针 | `2 * sizeof(T*)`（16 字节） | 需要存储函数指针本身的地址 |
| 有状态 lambda / 绑定器 | `sizeof(T*) + sizeof(state)` | 需额外存储捕获的状态变量 |

```cpp
auto stateless = [](int* p) { delete p; };
auto stateful = [token = 100](int* p) { delete p; };

std::unique_ptr<int> p1;                                            // 8 字节
std::unique_ptr<int, decltype(stateless)> p2(nullptr, stateless);   // 8 字节
std::unique_ptr<int, void(*)(int*)> p3(nullptr, [](int* p){ delete p; }); // 16 字节
std::unique_ptr<int, decltype(stateful)> p4(nullptr, stateful);     // 16 字节
```

> **建议**：自定义删除器优先使用无捕获的 lambda 或无状态的 `struct` 仿函数，保持零内存开销。

## 3. 基础用法与对象构造

### 使用 std::make_unique（C++14 推荐）

直接使用 `std::make_unique` 优于裸 `new`：代码更紧凑，并能规避 C++17 之前复杂表达式求值顺序不确定带来的异常安全隐患。

```cpp
#include <iostream>
#include <memory>

class Task {
public:
    int id;
    explicit Task(int i) : id(i) { std::cout << "Task " << id << " created\n"; }
    ~Task() { std::cout << "Task " << id << " destroyed\n"; }
    void run() const { std::cout << "Task " << id << " is running\n"; }
};

int main() {
    // 推荐方式：make_unique
    auto task = std::make_unique<Task>(1);

    // 访问成员：操作符重载模拟原生指针
    task->run();
    std::cout << "ID: " << (*task).id << "\n";

    // 布尔转换：operator bool 检查是否持有有效对象
    if (task) {
        std::cout << "task is valid\n";
    }

    return 0;
} // 离开作用域，Task 自动析构
```

### 管理动态数组

`unique_ptr` 拥有针对数组类型的偏特化版本 `std::unique_ptr<T[]>`，其析构时会自动调用 `delete[]`。

```cpp
// 分配 5 个元素的 int 数组
auto arr = std::make_unique<int[]>(5);

for (int i = 0; i < 5; ++i) {
    arr[i] = i * 10; // 支持 operator[]
}

for (int i = 0; i < 5; ++i) {
    std::cout << arr[i] << " ";
}
std::cout << "\n";
// 离开作用域自动执行 delete[]
```

> 普通动态数组更推荐直接使用 `std::vector<T>`，它提供动态扩容、边界安全检查及标准迭代器支持。`std::unique_ptr<T[]>` 多用于对接底层 C 风格缓冲区或固定尺寸的原始内存块。

## 4. 所有权转移：移动语义深层机制

`unique_ptr` 禁止复制的核心目的是杜绝 **Double Free（双重释放）**。若允许多个 `unique_ptr` 拷贝指向同一地址，它们析构时会先后对同一块内存调用 `delete`，导致未定义行为或进程崩溃。

```cpp
std::unique_ptr<int> p1 = std::make_unique<int>(42);
// std::unique_ptr<int> p2 = p1; // 编译报错：copy constructor 被删除
```

### 移动构造与指针置空

所有权的流转必须依赖移动语义（Move Semantics）：

```cpp
auto p1 = std::make_unique<int>(42);
auto p2 = std::move(p1); // 所有权从 p1 移交给 p2
```

执行时发生的底层变化：

```text
移动前：
  p1 ──────► [ 堆内存: 42 ]
  p2         (未初始化)

执行 p2 = std::move(p1) 后：
  p1 ──────► nullptr
  p2 ──────► [ 堆内存: 42 ]
```

1. `std::move(p1)` 不会产生任何运行时代码去搬运对象，它仅是编译期的静态类型转换，将左值引用转换为右值引用 `std::unique_ptr<int>&&`。
2. 移动构造函数接管 `p1` 内部保存的原生指针地址，并将 `p1` 内部的原生指针赋值为 `nullptr`。
3. 移动后，`p1` 变为逻辑上的空指针（`!p1` 为 `true`），后续对其解引用属于未定义行为，但安全析构（`delete nullptr` 是合法的空操作）。

### 移动赋值运算符的处理细节

当向一个已经持有资源的 `unique_ptr` 进行移动赋值时，它必须**先释放自身原有的资源**，再接管新资源：

```cpp
auto a = std::make_unique<int>(10);
auto b = std::make_unique<int>(20);

a = std::move(b);
```

```text
内部执行流程：
1. 释放 a 原本持有的堆对象（delete 原来的 10）
2. 将 b 内部的指针赋值给 a（a 指向 20）
3. 将 b 内部指针清零（b = nullptr）
```

若忽略第一步直接覆盖指针，`10` 所在的堆内存就会永久泄漏。

## 5. 核心接口与所有权语义辨析

| 接口 | 作用 | 是否放弃所有权 | 谁负责释放资源 |
|---|---|---|---|
| `get()` | 获取底层原生指针 | **否**（临时借出） | 依然由原 `unique_ptr` 管理 |
| `release()` | 放弃所有权并返回原生指针，自身置空 | **是**（彻底交出） | **调用者必须手动释放**（如 `delete`） |
| `reset(p)` | 释放当前资源，可选接管新指针 `p` | **是**（立即销毁旧资源） | 原对象立即被 `delete`，新对象由它管理 |

### get() 的典型用途：借用权限

`get()` 用于将指针传递给不参与生命周期管理的老式 C 接口或只读观察函数：

```cpp
void printValue(const int* ptr) {
    if (ptr) std::cout << *ptr << "\n";
}

auto p = std::make_unique<int>(100);
printValue(p.get()); // 借用指针地址，不转让所有权

// 严重错误：千万不要对 get() 出来的指针调用 delete
// delete p.get(); // 导致 double free！
```

### release() 的使用场景：移交底层控制权

`release()` 切断 `unique_ptr` 与资源的联系：

```cpp
auto p = std::make_unique<int>(100);
int* raw = p.release(); // p 变为 nullptr

// 此时 p 不再负责释放内存
// 开发者必须手动管理 raw
delete raw;
```

### reset() 的使用场景：提前释放与资源替换

`reset()` 用于重置指针状态：显式销毁当前管理的对象，并可选地接管一个新传入的原生指针。

#### 1. 提前释放资源，降低峰值开销

`unique_ptr` 通常在离开作用域时自动析构。但如果它持有的对象占用了大块内存（如大型缓冲区），或持有了稀缺的系统资源（如文件句柄、网络套接字），而在后续耗时流程中不再需要，可以主动调用无参 `reset()` 提前释放：

```cpp
void processData() {
    auto buffer = std::make_unique<BigBuffer>(1024 * 1024);
    buffer->loadAndProcess();

    // 数据处理已完成，后续是耗时的网络同步或计算
    // 提前释放大内存，无需等待函数执行完毕
    buffer.reset(); // 立即 delete 底层对象，buffer 变为 nullptr
    // 等价写法：buffer = nullptr;

    doLongTimeNetworkSync();
}
```

#### 2. 接管新资源或重新绑定

当同一个智能指针变量在运行期间需要更换管理对象时（例如网络重连、重载配置、或者对接返回裸指针的第三方接口），传入新原生指针调用 `reset(new_ptr)`。它会先销毁旧对象，再接管新指针：

```cpp
auto conn = std::make_unique<Connection>("192.168.1.10");
conn->send("ping");

// 切换到备用节点：先析构原连接，再接管新连接
conn.reset(new Connection("192.168.1.20"));

// 对接返回裸指针的第三方或遗留接口
conn.reset(createLegacyConnection());
```

> 如果新对象可以通过 `std::make_unique` 构造，通常推荐直接使用移动赋值：
> ```cpp
> conn = std::make_unique<Connection>("192.168.1.20"); // 同样会先释放旧资源，且避免了手写裸 new
> ```

#### 3. 陷阱：禁止自重置（传递自身持有的原生指针）

不要把 `unique_ptr` 自身持有的原生指针传给 `reset`：

```cpp
auto p = std::make_unique<int>(42);

// 严重错误：未定义行为
p.reset(p.get());
```

`reset(ptr)` 的内部机制是先将内部指针更新为传入的新地址，随后对旧地址调用删除器。当传入 `p.get()` 时，旧地址与新地址相同，导致底层对象被立即 `delete`，而 `p` 依然保存该已失效的地址。离开作用域时析构函数再次执行 `delete`，引发 double free。

## 6. 函数设计中的所有权契约

在接口设计中，参数与返回值的类型直接定义了所有权流动契约：

### 函数参数语义

```cpp
// 1. 只借用对象，不关心生命周期（最通用）
void inspect(const Task& task);      // 不需要空指针时
void inspect(const Task* task);      // 允许传入空指针时

// 2. 接收所有权（Sink 参数）
void consume(std::unique_ptr<Task> task) {
    // task 在此处被独占，函数结束时其生命周期终结并销毁
}

// 调用端：
auto t = std::make_unique<Task>(10);
// consume(t);             // 编译报错：禁止隐式拷贝
consume(std::move(t));     // 必须显式 move，调用端清楚所有权已被移交
// 此处 t 已变为 nullptr
```

### 函数返回值语义：工厂模式

函数返回 `std::unique_ptr<T>` 是将堆对象所有权转交给调用方的标准做法：

```cpp
std::unique_ptr<Task> createTask(int id) {
    auto task = std::make_unique<Task>(id);
    // 配置 task...
    return task; // 推荐直接 return task，不要写 return std::move(task);
}

// 调用方接收所有权
auto myTask = createTask(101);
```

> **为什么不写 `return std::move(task);`？**
> C++ 标准规定，返回局部变量时编译器优先应用 NRVO（命名返回值优化）直接在调用方栈空间构造；即使无法优化，也会隐式将其视为右值进行移动。显式写 `std::move` 反而会抑制 RVO/NRVO 优化，徒增一次移动调用。

## 7. 多态场景与基类虚析构

`unique_ptr` 原生支持面向对象的多态转换：派生类的 `unique_ptr` 可以隐式向上转换为基类的 `unique_ptr`。

```cpp
class Animal {
public:
    virtual void speak() const = 0;
    // 基类必须声明虚析构函数！
    virtual ~Animal() { std::cout << "~Animal\n"; }
};

class Dog : public Animal {
public:
    void speak() const override { std::cout << "Woof\n"; }
    ~Dog() override { std::cout << "~Dog\n"; }
};

int main() {
    // 基类指针管理派生类对象
    std::unique_ptr<Animal> pet = std::make_unique<Dog>();
    pet->speak();

    return 0;
}
```

执行输出：
```text
Woof
~Dog
~Animal
```

> **关键规则**：只要通过基类智能指针 `std::unique_ptr<Base>` 管理派生类对象，**基类的析构函数必须为虚函数（`virtual`）**。默认删除器内部调用的是 `delete ptr`（其中 `ptr` 为 `Base*`），若析构函数非虚，C++ 标准规定通过基类指针删除派生类属于未定义行为（通常导致派生类析构函数无法执行，成员变量泄漏）。

## 8. 自定义删除器与非内存系统资源管理

`unique_ptr` 不仅用于释放堆内存，它的类型模板全称为：

```cpp
template <typename T, typename Deleter = std::default_delete<T>>
class unique_ptr;
```

通过指定自定义删除器，可以利用 RAII 统一管理各类非内存系统资源（文件句柄、Socket、锁、驱动资源等）。

### 包装 C 标准文件句柄

```cpp
#include <cstdio>
#include <memory>

struct FileCloser {
    void operator()(FILE* fp) const {
        if (fp) {
            std::fclose(fp);
            std::cout << "FILE closed\n";
        }
    }
};

using ScopedFile = std::unique_ptr<FILE, FileCloser>;

void readFile() {
    ScopedFile file(std::fopen("test.txt", "r"));
    if (!file) return;

    // 读取文件内容...
    // 无论是正常离开还是抛出异常，fclose 都会被确定性触发
}
```

### 包装 Linux 系统描述符（Socket / File Descriptor）

```cpp
#include <unistd.h>
#include <memory>

struct FdCloser {
    void operator()(int* fd) const {
        if (fd) {
            if (*fd >= 0) ::close(*fd);
            delete fd;
        }
    }
};
// 或者为带句柄的封装结构体定义删除器
```

> 在网络编程与高性能存储中，这种模式广泛用于管理各类 C API 句柄（如 RDMA 的 `ibv_destroy_cq`、SPDK 控制器句柄等），消除手动调用销毁接口的遗漏风险。

## 9. 容器与数据结构中的所有权模式

### 配合 std::vector 管理对象集合

传统裸指针容器 `std::vector<Task*>` 析构时仅释放指针数组本身的内存，不会释放指针指向的堆对象，容易导致内存泄漏。而 `std::vector<std::unique_ptr<Task>>` 将生命周期完全绑定：

```cpp
#include <vector>

void processBatch() {
    std::vector<std::unique_ptr<Task>> taskList;

    taskList.push_back(std::make_unique<Task>(1));
    taskList.push_back(std::make_unique<Task>(2));

    for (const auto& task : taskList) {
        task->run();
    }
    // taskList 析构时，其中存储的每个 unique_ptr 逐一析构，释放堆上的 Task
}
```

### 树状与图状结构的所有权设计

在树形数据结构中，父节点对子节点是完全包含的生命周期关系，可以使用 `std::unique_ptr` 表达独占所有权；而子节点回指父节点时，应使用裸指针（观察者模式）：

```cpp
class TreeNode {
public:
    int val;
    TreeNode* parent;                                  // 借用指针：父节点生命周期必然长于子节点
    std::vector<std::unique_ptr<TreeNode>> children;  // 独占子节点所有权

    explicit TreeNode(int v, TreeNode* p = nullptr) : val(v), parent(p) {}

    TreeNode* addChild(int childVal) {
        children.push_back(std::make_unique<TreeNode>(childVal, this));
        return children.back().get();
    }
};
```

100 万个节点的树，使用 `unique_ptr` 相比 `shared_ptr` 能节省约 8MB 的控制块内存以及数百万次原子增减计数操作。

### 递归数据结构的级联释放

在单链表中，节点之间的独占所有权天然形成级联析构链：

```cpp
struct ListNode {
    int val;
    std::unique_ptr<ListNode> next; // 当前节点独占下一个节点
    explicit ListNode(int v) : val(v), next(nullptr) {}
};

void demoList() {
    auto head = std::make_unique<ListNode>(1);
    head->next = std::make_unique<ListNode>(2);
    head->next->next = std::make_unique<ListNode>(3);
} // head 析构 -> 触发 Node(1).next 析构 -> Node(2).next 析构 -> 整个链表自动完整回收
```

> **注意深度链表的栈溢出风险**：如果链表节点极多（如数万层），级联递归析构会导致函数调用栈溢出。这种极端场景下可在最外层手动采用迭代循环释放节点。

## 10. unique_ptr 极简实现模型

以下为约 40 行的简化实现，剥离了删除器特化与异常处理，集中展示其内部所有权控制骨架：

```cpp
template <typename T>
class MiniUniquePtr {
private:
    T* ptr_ = nullptr;

public:
    constexpr MiniUniquePtr() noexcept = default;
    explicit MiniUniquePtr(T* p) noexcept : ptr_(p) {}

    // 析构自动清理
    ~MiniUniquePtr() { delete ptr_; }

    // 1. 删除拷贝
    MiniUniquePtr(const MiniUniquePtr&) = delete;
    MiniUniquePtr& operator=(const MiniUniquePtr&) = delete;

    // 2. 移动构造：接管指针并置空原对象
    MiniUniquePtr(MiniUniquePtr&& other) noexcept : ptr_(other.ptr_) {
        other.ptr_ = nullptr;
    }

    // 3. 移动赋值：释放自身原有资源，再接管新资源
    MiniUniquePtr& operator=(MiniUniquePtr&& other) noexcept {
        if (this != &other) {
            delete ptr_;          // 先释放旧资源
            ptr_ = other.ptr_;    // 接管新资源
            other.ptr_ = nullptr; // 置空来源
        }
        return *this;
    }

    // 4. 指针模拟与观察接口
    T* get() const noexcept { return ptr_; }
    T& operator*() const noexcept { return *ptr_; }
    T* operator->() const noexcept { return ptr_; }
    explicit operator bool() const noexcept { return ptr_ != nullptr; }

    // 5. 控制权分离
    T* release() noexcept {
        T* temp = ptr_;
        ptr_ = nullptr;
        return temp;
    }

    void reset(T* p = nullptr) noexcept {
        T* old = ptr_;
        ptr_ = p;
        delete old; // 避免自重置导致的悬空问题
    }
};
```

## 11. 选型模型：栈对象 vs unique_ptr vs shared_ptr

### 所有权三问思维模型

遇到指针或动态资源设计时，先问三个问题：
1. **谁创建？**
2. **谁拥有？**（单一实体还是多个实体？）
3. **谁负责销毁？**

传统裸指针无法在类型层面回答这三个问题；而 `std::unique_ptr` 将所有权内化为编译期类型契约。

### 选型决策流

```text
需要管理一个资源？
  │
  ├── 作用域仅限于单个函数栈帧？ ──► 优先使用直接的栈局部对象（Person p;），最轻量
  │
  └── 必须分配在堆上（生命周期跨越作用域 / 需多态 / 动态数据结构）？
        │
        ├── 能够确定唯一拥有者？ ──► 优先选 std::unique_ptr（默认首选）
        │
        └── 资源生命周期由多个实体共同决定，无法确定谁最后销毁？ ──► 使用 [[共享智能指针|std::shared_ptr]]
```

### 特性与开销对比

| 维度 | 原生裸指针 `T*` | 独占指针 `std::unique_ptr<T>` | 共享指针 `std::shared_ptr<T>` |
|---|---|---|---|
| **所有权语义** | 无（仅代表地址） | 独占（单一拥有者） | 共享（多个拥有者） |
| **复制支持** | 支持（浅拷贝） | **禁止**（编译期拦截） | 支持（引用计数加 1） |
| **移动支持** | 支持（仅复制地址） | 支持（零开销转移所有权） | 支持（转移引用计数） |
| **内存开销** | 8 字节 | **8 字节**（默认删除器） | 16 字节（包含控制块指针） + 控制块内存 |
| **性能损耗** | 无 | **无**（完全等同于裸指针） | 原子操作引用计数增加/减少的开销 |
| **系统资源管理** | 需手动配对释放函数 | 支持自定义删除器（EBO 优化） | 支持自定义删除器（存储于控制块） |

### unique_ptr 向 shared_ptr 单向转换

`unique_ptr` 可以隐式转换为 `shared_ptr`，反之则不可：

```cpp
std::unique_ptr<Task> uTask = std::make_unique<Task>(1);
// 允许：unique_ptr 移动给 shared_ptr，控制块在此刻按需创建
std::shared_ptr<Task> sTask = std::move(uTask);

// 不允许：shared_ptr 无法隐式转回 unique_ptr
// std::unique_ptr<Task> back = std::move(sTask); // 编译错误
```

因此工厂函数统一返回 `std::unique_ptr<T>` 是最具弹性的设计方案：调用方若仅需独占，直接使用 `unique_ptr` 获得零开销抽象；若后续需共享，可随时就地转换为 `shared_ptr`。

> [!abstract] weak_ptr 速记卡片
> **一句话**：依附于 `shared_ptr` 控制块的非拥有型观察者，不增加强引用计数、不延长对象生命周期；禁止直接解引用，必须通过 `lock()` 原子升级为 `shared_ptr` 后方可安全访问；核心用于打破循环引用与观察异步对象。以下示例除特别注明外省略 `std::`，以 C++14/17 为准。
>
> | 要做什么 | 常用写法 / 要点 |
> | --- | --- |
> | 头文件与类型 | `#include <memory>`；类型写作 `weak_ptr<T>`，占用 16 字节（对象指针 + 控制块指针） |
> | 初始化与绑定 | `weak_ptr<T> wp = sp;` 从 `shared_ptr` 构造；弱计数 +1，强计数不变；不可脱离 `shared_ptr` 独立存在 |
> | 安全访问对象 | `if (auto sp = wp.lock()) { ... }` 原子提升为 `shared_ptr`，使用期间保证底层对象不被析构 |
> | 检查是否失效 | `wp.expired()` 返回 `true` 表示底层对象已销毁（`use_count() == 0`）；不可用于多线程下前置安全判断 |
> | 强引用计数查询 | `wp.use_count()` 查看当前关联对象的强引用持有者数量 |
> | 重置与解绑 | `wp.reset()` 脱离当前控制块，弱计数 -1，`wp` 变为空指针 |
> | 抛异常强制转换 | `shared_ptr<T> sp(wp);` 若对象已析构则抛出 `std::bad_weak_ptr` 异常 |
> | 自身安全转 weak_ptr | 继承 `enable_shared_from_this<T>` 后调用 `weak_from_this()`（C++17 引入，避免强引用计数扰动） |
>
> **核心机制：对象与控制块生命周期演进**
>
> | 阶段 | 触发条件 | 发生的操作 | 内存状态 |
> | --- | --- | --- | --- |
> | **阶段 1：强引用归零** | 最后一个 `shared_ptr` 析构（`strong_count == 0`） | 调用被管理对象的**析构函数**清理资源 | 底层对象已销毁；若存在 `weak_ptr`，控制块依然保留 |
> | **阶段 2：弱引用归零** | 最后一个 `weak_ptr` 析构（`weak_count == 0`） | 销毁控制块自身元数据 | 控制块内存正式释放并交还系统 |
> | **make_shared 影响** | 对象与控制块连在同一块内存中 | 对象已析构但内存整块不归还 | 必须等阶段 2 弱计数归零后整块内存才返还 OS |
>
> **常用操作模板**
> ```cpp
> // 1. lock() 标准安全访问范式（原子提升，杜绝 TOCTOU 竞态）
> if (auto sp = wp.lock()) {
>     sp->doSomething(); // 在此作用域内 sp 强引用保活，绝对安全
> } else {
>     // 底层对象已被释放，执行降级或清理逻辑
> }
>
> // 2. 打破双向循环引用（父持子强引用，子持父弱引用）
> struct Node {
>     std::shared_ptr<Node> child;
>     std::weak_ptr<Node> parent; // 弱引用防止环形引用导致内存泄漏
> };
>
> // 3. 异步回调与观察者模式（避免回调强制延长对象寿命）
> class Subscriber : public std::enable_shared_from_this<Subscriber> {
> public:
>     void subscribe(Publisher& pub) {
>         // 传递 weak_ptr，观察目标存活状态而不过度持有
>         pub.onEvent([wp = weak_from_this()]() {
>             if (auto self = wp.lock()) self->handleEvent();
>         });
>     }
>     void handleEvent() { /* ... */ }
> };
> ```
>
> **四个必记易错点**
> - **禁止直接解引用**：`weak_ptr` 没有重载 `operator*` 和 `operator->`，无法直接通过 `wp->func()` 访问成员，必须先 `lock()` 升级成功后再访问。
> - **expired() 竞态陷阱（TOCTOU）**：严禁写 `if (!wp.expired()) { auto sp = wp.lock(); }`；在多线程环境中，判断之后对象可能在另一线程立刻析构，必须直接通过 `if (auto sp = wp.lock())` 完成原子判断与提升。
> - **裸指针代替观察者的悬空风险**：若用裸指针代替 `weak_ptr` 充当观察者，对象销毁后裸指针沦为悬空野指针且无法被代码感知，后续访问触发未定义行为（UAF）。
> - **构造函数内调用 from_this**：在对象的构造函数执行期间，控制块尚未完成与 `shared_ptr` 的完整绑定，此时调用 `shared_from_this()` 或 `weak_from_this()` 会抛出 `std::bad_weak_ptr`。
>
> **口诀**：弱引不掌生与死，依附控制查存亡；访问绝不先 expired，直接 lock 判空最妥当；双向持有留一边，打破环路不泄漏。
>

# 弱引用智能指针 (weak_ptr)

> `std::weak_ptr` 是与 [[共享智能指针|std::shared_ptr]] 配套使用的非拥有型智能指针。它依附于控制块观察对象，不增加对象的强引用计数，因而不延长对象生命周期。核心用途是**安全观察共享对象生命周期**以及**打破 `shared_ptr` 的循环引用**。

---

## 1. 核心定位与设计诉求

在动态内存管理中，通常存在两类完全不同的指针使用意图：
1. **拥有者（Owner）**：决定对象的生死，对象在所有拥有者全部离开前必须保持存活。
2. **观察者（Observer）**：需要获知对象的状态或在对象活着时临时访问它，但不应该强行延长对象的寿命。

若直接使用裸指针（`T*`）充当观察者，一旦底层对象被释放，裸指针会变成**悬空指针（Dangling Pointer）**，后续访问直接引发未定义行为（Use-After-Free）。

若使用 `std::shared_ptr` 充当观察者，指针会自动将引用计数加 1，变成拥有者之一，强行改变了生命周期契约，甚至可能导致双向强引用死锁。

`std::weak_ptr` 专为解决这一矛盾而设计：
- **不参与所有权**：构造、拷贝或赋值 `weak_ptr` 均不会增加被管理对象的强引用计数。
- **具备生命周期感知**：能够精准判断底层对象是处于存活状态还是已被析构。
- **不能独立存在**：必须依附于由 `std::shared_ptr` 管理的对象和控制块。

```cpp
#include <iostream>
#include <memory>

int main() {
    auto sp = std::make_shared<int>(42);
    std::weak_ptr<int> wp = sp; // 观察 sp

    std::cout << "强引用计数: " << sp.use_count() << "\n"; // 输出 1，wp 不增加计数

    sp.reset(); // 唯一拥有者退出，堆上 int(42) 被析构

    std::cout << "是否已失效: " << std::boolalpha << wp.expired() << "\n"; // 输出 true
    return 0;
}
```

## 2. 内部模型：强计数、弱计数与控制块生命周期

与 `shared_ptr` 类似，`std::weak_ptr` 在 64 位系统下同样占用 **16 字节**，包含一个指向对象的指针和一个指向控制块的指针。控制块由两个独立的原生原子计数器共同驱动：

```text
控制块 Control Block
  ├── strong_count (原子计数) ──► 决定被管理对象的存活状态
  ├── weak_count   (原子计数) ──► 决定控制块本身的内存释放时机
  ├── 自定义删除器 Deleter
  └── 分配器元数据
```

```text
shared_ptr sp
├── ptr ──────────────────► [ T 对象 (堆内存) ]
└── cb ────────┐                     ▲
               │                     │
weak_ptr wp    │                     │
├── ptr ───────┼─────────────────────┘ (不直接使用)
└── cb ────────┴──────────► [ 控制块 Control Block ]
                            ├── strong_count = 1
                            └── weak_count   = 1
```

### 对象与控制块的三阶段生命周期演进

由于存在双计数机制，底层对象与控制块的销毁时机被彻底解耦：

1. **阶段 1：对象存活（strong > 0, weak >= 0）**
   - 至少存在一个 `shared_ptr` 持有该对象。
   - 对象在堆上正常工作，`weak_ptr` 可随时通过 `lock()` 升级访问。
2. **阶段 2：对象销毁，控制块驻留（strong == 0, weak > 0）**
   - 最后一个 `shared_ptr` 析构，`strong_count` 归零。
   - **立即执行被管理对象的析构函数，释放对象所占用的资源**。
   - 但因为还有 `weak_ptr` 在观察，控制块必须继续驻留内存，用于响应 `expired()` 和 `lock()` 调用。
3. **阶段 3：完全释放（strong == 0, weak == 0）**
   - 最后一个 `weak_ptr` 析构，`weak_count` 归零。
   - **控制块占用的堆内存被系统分配器最终释放**。

> **make_shared 的内存驻留权衡**：使用 `std::make_shared` 时，对象与控制块被打包在单次连续分配中。如果处于阶段 2（`strong == 0` 但 `weak > 0`），对象已析构，但整块内存无法拆分，必须等到阶段 3 才能整块归还堆管理器。如果对象本身占用大内存（如数兆字节的图像数据），且存在长生命周期的 `weak_ptr`，应改为分开分配的裸 `new` 构造，让大对象能更早退回系统。

## 3. 核心操作：安全访问与原子升级（lock 机制）

### 为什么禁止直接解引用

`std::weak_ptr` 没有重载 `operator*` 或 `operator->`。

在多线程环境下，若允许直接解引用弱指针，可能在解引用的瞬间底层对象恰好被其他线程的 `shared_ptr` 析构，直接酿成竞态段错误。要使用对象，必须将弱引用“升级”为真正的共享所有权。

### lock()：原子生命周期提升

`lock()` 方法尝试从弱引用生成一个强引用的 `std::shared_ptr`：
- 若底层对象仍然存活（`strong_count > 0`），原子自增 `strong_count` 并返回有效的 `shared_ptr`。只要该 `shared_ptr` 还在当前作用域内，**对象在访问期间绝对安全，绝不会被意外销毁**。
- 若对象已经析构（`strong_count == 0`），返回空的 `std::shared_ptr`（即 `nullptr`）。

```cpp
std::weak_ptr<Task> wp = ...;

// 推荐的标准访问范式
if (auto sp = wp.lock()) {
    sp->execute(); // 存活时安全使用，sp 维持当前强计数
} else {
    // 对象已经死亡，执行降级或清理逻辑
}
```

### 竞态陷阱：为什么不要用 expired() 做前置判断

以下写法属于典型的 **TOCTOU（Time-of-Check to Time-of-Use，检查时到使用时）** 竞态漏洞：

```cpp
// ❌ 错误且危险的写法
if (!wp.expired()) {
    // 线程并发危险区：若另一个线程在此刻析构了最后的 shared_ptr，
    // 对象被销毁，随后的 lock() 会返回 nullptr，造成潜在空指针解引用
    auto sp = wp.lock();
    sp->execute();
}
```

`expired()` 的检查与后续操作不是一个不可分割的原语。而 `wp.lock()` 内部通过原子 CAS 操作（如 `compare_exchange`）将“检查强计数是否大于 0”与“强计数原子递增”打包为单步原子操作，杜绝了时序窗口。

> `expired()` 与 `use_count()` 主要用于调试断言、日志输出与外部健康监控，不应作为业务执行逻辑的前提分支判断。

## 4. 经典场景一：打破 shared_ptr 循环引用

### 循环引用的成因与内存泄漏

当两个对象通过 `std::shared_ptr` 彼此持有对方时，引用计数便无法降为 0：

```cpp
struct B;

struct A {
    std::shared_ptr<B> b;
    ~A() { std::cout << "~A()\n"; }
};

struct B {
    std::shared_ptr<A> a; // 双方互相强持有
    ~B() { std::cout << "~B()\n"; }
};

void demoCycle() {
    auto a = std::make_shared<A>();
    auto b = std::make_shared<B>();

    a->b = b; // b 的 strong_count = 2
    b->a = a; // a 的 strong_count = 2
} // 作用域结束：栈上 a、b 析构，但堆上两者的 strong_count 仅降为 1，析构函数永远不会执行！
```

```text
离开 demoCycle 后：
  ┌──────┐    shared_ptr (count=1)    ┌──────┐
  │ 堆 A │ ─────────────────────────► │ 堆 B │
  │      │ ◄───────────────────────── │      │
  └──────┘    shared_ptr (count=1)    └──────┘

A 等待 B 销毁自身，B 等待 A 销毁自身，形成死锁式环路。
```

### 使用 weak_ptr 解除环路

将环形链路中属于“反向引用”或“从属观察”的一侧改成 `std::weak_ptr`：

```cpp
struct B;

struct A {
    std::shared_ptr<B> b; // A 拥有 B 的所有权
    ~A() { std::cout << "~A()\n"; }
};

struct B {
    std::weak_ptr<A> a;   // B 仅作为观察者，不持有 A 的所有权
    ~B() { std::cout << "~B()\n"; }

    void notifyParent() {
        if (auto parent = a.lock()) {
            // 安全通知 A
        }
    }
};

void demoBreakCycle() {
    auto a = std::make_shared<A>();
    auto b = std::make_shared<B>();

    a->b = b; // b 的 strong_count = 2
    b->a = a; // a 的 strong_count = 1（weak_ptr 不增加强计数）
}
```

```text
离开 demoBreakCycle 时的析构顺序：
1. 栈变量 a 析构，堆 A 的 strong_count 从 1 降为 0。
2. 堆 A 触发析构函数 ~A()，其成员 a->b 随之析构，堆 B 的 strong_count 从 2 降为 1。
3. 栈变量 b 析构，堆 B 的 strong_count 从 1 降为 0。
4. 堆 B 触发析构函数 ~B()，所有内存被彻底回收。
```

## 5. 数据结构选型：树结构 vs 图结构

并非所有相互关联的节点都需要使用 `shared_ptr + weak_ptr`。在真实工程设计中，需根据结构拓扑确定权责归属：

| 数据结构 | 拓扑特征 | 父向子引用 | 子向父引用 | 设计 rationale |
|---|---|---|---|---|
| **树结构（严格单亲）** | 单向层级，生命周期严格包含 | `std::unique_ptr` | 原生裸指针 `T*` | 父节点必然长于子节点，子向父回指裸指针零开销且绝对安全 |
| **DAG（有向无环图）** | 多父共享同一子节点 | `std::shared_ptr` | `std::weak_ptr` | 子节点被多个父节点共同拥有，反向需要弱引用防止环形误伤 |
| **通用图（可能有环）** | 节点间网状互联 | `std::shared_ptr` | `std::weak_ptr` | 拓扑复杂、生命周期不确定，必须依赖双计数打破闭环 |

### 树结构为何优先推荐 unique_ptr + 裸指针

在树型结构中，父节点通过 `std::vector<std::unique_ptr<TreeNode>>` 独占子节点。当父节点析构时，子节点必然优先析构；只要子节点还存在，父节点必定存活。这种结构性保证使得子回指父无需承受弱引用的原子计数和控制块开销，直接使用 `TreeNode*` 既高效又安全。

只有当子节点可能被脱离父树单独摘出、被外部异步缓存长久持有，导致两者的生命周期发生脱节时，才需要升级为 `shared_ptr + weak_ptr` 模式。

## 6. 经典场景二：异步网络与事件循环（Callback 生命周期管理）

在异步网络服务、定时器和线程池任务中，闭包捕获指针存在两种截然不同的策略：

### 策略对比：强持有 vs 弱观察

```cpp
// 策略 A：闭包强持有（强保证执行）
auto self = shared_from_this();
async_op([self]() {
    self->handle(); // 即使外部销毁了该连接，操作也必须完整执行完毕
});

// 策略 B：闭包弱观察（允许中途取消 / 随缘执行）
std::weak_ptr<Connection> weak = shared_from_this();
async_op([weak]() {
    if (auto self = weak.lock()) {
        self->handle(); // 连接还活着才处理；若外部已断开并析构，则静默丢弃
    }
});
```

### 定时器闭环打破

```text
Connection 拥有 Timer 对象
    │
    ▼
  Timer 拥有异步 Callback 闭包
    │
    ▼
若 Callback 按值捕获 shared_ptr<Connection>
    │
    └──────► 形成闭环循环引用：Connection 无法释放，Timer 无法停止！
```

解决之道是将回调内的捕获改为 `weak_ptr`。当网络连接由于对端关闭而被外部移除时，强引用清零，连接得以正常析构，定时器被注销清理。

### enable_shared_from_this 与 weak_from_this()

`std::enable_shared_from_this<T>` 内部本身就是通过保存一个私有的 `std::weak_ptr<T>` 来实现控制块复用的。

C++17 引入了 `weak_from_this()` 接口，允许成员函数直接获取自身的弱引用，而无需先调用 `shared_from_this()` 再构造 `weak_ptr`（减少了一次强引用的原子递增与析构递减）：

```cpp
class Session : public std::enable_shared_from_this<Session> {
public:
    void registerTimer(TimerQueue& queue) {
        // C++17 推荐：直接获取 weak_ptr，零原子自增开销
        auto weakSelf = weak_from_this();

        queue.addTimer(1000, [weakSelf]() {
            if (auto self = weakSelf.lock()) {
                self->onTimeout();
            }
        });
    }

    void onTimeout() { /* 超时处理 */ }
};
```

## 7. weak_ptr 与原生裸指针的本质差异与性能权衡

| 特性维度 | 原生指针 `T*` | 弱引用指针 `std::weak_ptr<T>` |
|---|---|---|
| **所有权语义** | 无所有权（仅存储地址） | 无所有权（依附于控制块） |
| **生命周期感知** | **完全无法感知**（悬空时解引用导致崩溃） | **安全感知**（`expired()` / `lock() == nullptr`） |
| **解引用操作** | 直接通过 `*`、`->` 访问 | 必须通过 `lock()` 原子提升后访问 |
| **内存与调用开销** | 8 字节，零开销 | 16 字节，`lock()` 伴随控制块原子增减开销 |
| **适用环境** | 生命周期稳定或有严格包含关系的局部借用 | 生命周期不确定且由 `shared_ptr` 管理的对象观察 |

> `weak_ptr` 不是免费的指针替代品。如果在单函数局部调用或生命周期绝对受控的上下文（如树的父子借用），应优先使用 `const T&` 或 `T*`；仅当对象被多个模块共享持有且存活时间不可预测时，才引入 `std::weak_ptr`。

## 8. 现代 C++ 所有权思维模型全景

### 四类指针的职责分工

```text
                         堆内存实体
                             ▲
                             │
          ┌──────────────────┼─────────────────┐
          │                  │                 │
   std::unique_ptr    std::shared_ptr   std::weak_ptr
          │                  │                 │
      独占所有者         共享所有者         非所有者观察句柄
          │                  │                 │
   离开作用域即销毁   强引用计数归零销毁   不影响对象生命周期
          │                  │                 │
     禁止拷贝(move)      支持共享拷贝(copy)   通过 lock() 原子升级
          │                  │                 │
          └──────────► 资源清理基石 ◄──────────┘
                             │
                        原生指针 T*
                             │
                      仅用于非拥有型借用
```

### 生产开发选型闭环

```text
需要管理或引用一个对象？
  │
  ├── 1. 作用域严格限定在局部栈帧？ ──► 直接定义普通栈对象（T obj;）
  │
  └── 2. 需要动态分配或跨作用域管理？
        │
        ├── 能够确定唯一拥有者？ ──► 优先选 std::unique_ptr<T>
        │
        └── 需要多个拥有者共同维护？
              │
              ├── 真正参与生命周期的共享？ ──► 使用 std::shared_ptr<T>
              │
              └── 仅为反向观察 / 打破循环 / 异步解耦？ ──► 使用 std::weak_ptr<T>
```

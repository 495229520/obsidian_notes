> [!abstract] shared_ptr 速记卡片
> **一句话**：通过堆上控制块的原子引用计数实现多所有者共同持有；最后一个持有者离开作用域时自动释放对象；64 位下占 16 字节（对象指针 + 控制块指针），删除器类型擦除，支持安全共享但存在计数原子操作开销。以下示例除特别注明外省略 `std::`，以 C++14/17 为准。
>
> | 要做什么 | 常用写法 / 要点 |
> | --- | --- |
> | 头文件与类型 | `#include <memory>`；类型写作 `shared_ptr<T>`（删除器不属于模板类型声明） |
> | 推荐创建 | `make_shared<T>(args...)`；一次堆分配（对象与控制块合并内存），Cache 友好且异常安全，new 则会在堆区分配两个单独空间，分别存储控制块和对象 |
> | 裸指针构造 | `shared_ptr<T> sp(new T(args...));`；两次堆分配；需自定义删除器或私有构造时使用 |
> | 拷贝与共享 | `auto sp2 = sp1;` 强引用计数原子 +1；支持任意多个持有者协同共享 |
> | 移动语义移交 | `auto sp2 = std::move(sp1);` 强引用计数不变，`sp1` 置空，零计数开销转交所有权 |
> | 访问与判空 | `*sp` 解引用；`sp->member` 访问成员；`if (sp)` 或 `if (sp != nullptr)` 检查非空 |
> | 借用原生指针 | `sp.get()` 获取底层原生指针，生命周期依附于 `sp`，外部绝不可执行 `delete` |
> | 重置与替换 | `sp.reset()` 强计数 -1 并将 `sp` 置空；`sp.reset(new T)` 释放原对象引用并接管新对象 |
> | 状态查询 | `sp.use_count()` 查看当前强引用计数（仅供调试排查，多线程下仅为即时快照） |
> | 管理动态数组 | C++17 起支持 `shared_ptr<T[]>` 与 `make_shared<T[]>(n)`；支持下标访问 `sp[i]` |
> | 自定义删除器 | 构造函数传参即可：`shared_ptr<FILE> f(fopen(...), fclose);`（无需作为模板参数） |
> | 自身安全转 shared_ptr | 类继承 `enable_shared_from_this<T>`，内部调用 `shared_from_this()`，严禁 `shared_ptr<T>(this)` |
>
> **关键机制对比（std::make_shared vs new + shared_ptr）**
>
> | 维度 | `std::make_shared<T>` | `std::shared_ptr<T>(new T)` |
> | --- | --- | --- |
> | **堆内存分配次数** | **1 次**（对象与控制块一次性合并分配） | **2 次**（先分配对象，再分配控制块） |
> | **CPU Cache 局部性** | **高**（对象与控制块内存紧凑相邻） | **较低**（两块内存分散在堆的不同位置） |
> | **异常安全性** | 天然异常安全，无泄漏风险 | 复杂参数表达式求值异常时可能泄漏裸对象 |
> | **内存释放延迟** | 对象析构后，若有 `weak_ptr` 未释放，整块内存无法归还系统 | 强计数归零对象内存立即释放，控制块独立延迟释放 |
> | **自定义删除器** | 不支持 | **支持**（通过构造函数传入） |
>
> **常用操作模板**
> ```cpp
> // 1. 基本共享与工厂函数创建
> auto sp1 = std::make_shared<Session>(101);
> auto sp2 = sp1; // 强引用计数增为 2，共同管理底层 Session
>
> // 2. 函数传参语义契约
> void keep(std::shared_ptr<Session> s);       // 参与共享所有权（按值传递，计数 +1）
> void observe(const std::shared_ptr<Session>& s); // 内部临时使用，不增加引用计数开销
> void process(Session& s);                   // 纯借用，与生命周期解耦，直接解引用传参
>
> // 3. enable_shared_from_this：安全转出自身 shared_ptr（如网络回调）
> class Conn : public std::enable_shared_from_this<Conn> {
> public:
>     void registerCallback() {
>         // 捕获 shared_from_this() 保活当前对象，防止异步回调执行前对象提前析构
>         eventLoop.post([self = shared_from_this()] { self->onMessage(); });
>     }
>     void onMessage() { /* ... */ }
> };
>
> // 4. 自定义删除器（类型擦除，统一类型标识）
> std::shared_ptr<FILE> fp(fopen("log.txt", "w"), [](FILE* p) {
>     if (p) fclose(p);
> });
> ```
>
> **四个必记易错点**
> - **双重控制块陷阱**：严禁用同一个裸指针分别构造两个独立的 `shared_ptr`（如 `shared_ptr<T> p1(raw); shared_ptr<T> p2(raw);`），会创建两个互不知晓的控制块，导致同一内存被释放两次（Double Free）。
> - **严禁 shared_ptr(this)**：在类成员函数中直接用 `shared_ptr<T>(this)` 会建立全新控制块引发双重释放；必须继承 `enable_shared_from_this<T>` 并在对象已被外部 `shared_ptr` 管理后调用 `shared_from_this()`。
> - **循环引用内存泄漏**：若对象 A 持有对象 B 的 `shared_ptr`，对象 B 同时持有对象 A 的 `shared_ptr`，两者的强引用计数永远无法降至 0，形成死锁内存泄漏；必须将其中一侧断开改用 `weak_ptr`。
> - **线程安全边界**：控制块内部引用计数的增减是原子线程安全的；但**所指向对象的并发读写不是线程安全的**，同一个 `shared_ptr` 变量在多线程中同时被读写也不是线程安全的。
>
> **口诀**：共享用 shared，创建 make 优先；双重构造必崩溃，内部转出 from_this；循环引用找 weak，计数安全对象不安全。
>
> 关联：[[独享智能指针]] · [[弱引用智能指针]] · [[删除器]] · [[智能指针总结与练习题]]


# 共享智能指针 (shared_ptr)

> `shared_ptr` 是 C++11 引入的共享式智能指针，表示多个所有者**共同拥有**同一个动态分配资源。内部通过原子引用计数跟踪所有者数量，当最后一个拥有者销毁或重置时，被管理的对象才会被自动释放。

## 模板类核心实现代码

这里给出符合标准语义的 `shared_ptr` 模板类实现骨架，涵盖堆控制块（强弱引用计数与生命周期调度）、自定义删除器类型擦除、拷贝与移动语义、多态向上转换以及 `make_shared` 工厂函数：

```cpp
#include <atomic>       // std::atomic
#include <utility>      // std::move, std::forward
#include <cstddef>      // std::size_t, std::nullptr_t
#include <type_traits>  // std::is_convertible, std::enable_if_t

// ==========================================
// 1. 控制块抽象基类（强/弱引用计数与生命周期调度）
// ==========================================
struct control_block_base {
    std::atomic<long> strong_count{1}; // 强引用计数：跟踪 shared_ptr 持有者
    std::atomic<long> weak_count{1};   // 弱引用计数：当 strong_count > 0 时隐含持有 1 个 weak_count

    virtual ~control_block_base() = default;

    // 释放所托管的对象内存/资源
    virtual void dispose() noexcept = 0;

    // 释放控制块自身内存
    virtual void destroy() noexcept {
        delete this;
    }

    void add_shared() noexcept {
        strong_count.fetch_add(1, std::memory_order_relaxed);
    }

    void release_shared() noexcept {
        if (strong_count.fetch_sub(1, std::memory_order_acq_rel) == 1) {
            dispose();      // 强引用归 0，立即析构受管对象
            release_weak(); // 扣除受管对象存活期间隐含的 1 个 weak 引用
        }
    }

    void add_weak() noexcept {
        weak_count.fetch_add(1, std::memory_order_relaxed);
    }

    void release_weak() noexcept {
        if (weak_count.fetch_sub(1, std::memory_order_acq_rel) == 1) {
            destroy();      // 弱引用归 0，释放控制块自身内存
        }
    }

    long use_count() const noexcept {
        return strong_count.load(std::memory_order_relaxed);
    }
};

// ==========================================
// 2. 携带删除器的控制块具体派生类（类型擦除载体）
// ==========================================
template <typename T, typename Deleter>
struct control_block_impl : public control_block_base {
    T* ptr;
    Deleter deleter;

    control_block_impl(T* p, Deleter d) : ptr(p), deleter(std::move(d)) {}

    void dispose() noexcept override {
        deleter(ptr);
        ptr = nullptr;
    }
};

// 前向声明 weak_ptr
template <typename T> class weak_ptr;

// ==========================================
// 3. shared_ptr 模板类实现
// ==========================================
template <typename T>
class shared_ptr {
public:
    using element_type = T;

private:
    element_type* ptr_ = nullptr;        // 受管对象指针（支持别名）
    control_block_base* ctrl_ = nullptr; // 堆上控制块指针

    template <typename Y> friend class shared_ptr;
    template <typename Y> friend class weak_ptr;

    // 内部私有构造：直接绑定指针与控制块（用于 weak_ptr 升级或别名构造）
    shared_ptr(element_type* p, control_block_base* cb) noexcept
        : ptr_(p), ctrl_(cb) {}

public:
    // --- 构造与析构 ---
    constexpr shared_ptr() noexcept = default;
    constexpr shared_ptr(std::nullptr_t) noexcept : shared_ptr() {}

    // 普通原生指针构造（默认使用 delete 释放）
    template <typename Y, typename = std::enable_if_t<std::is_convertible<Y*, T*>::value>>
    explicit shared_ptr(Y* p) {
        if (p) {
            auto del = [](Y* raw) { delete raw; };
            ctrl_ = new control_block_impl<Y, decltype(del)>(p, del);
            ptr_ = p;
        }
    }

    // 自定义删除器构造（删除器类型被擦除并封装进控制块）
    template <typename Y, typename Deleter, typename = std::enable_if_t<std::is_convertible<Y*, T*>::value>>
    shared_ptr(Y* p, Deleter d) {
        if (p) {
            ctrl_ = new control_block_impl<Y, Deleter>(p, std::move(d));
            ptr_ = p;
        }
    }

    ~shared_ptr() {
        if (ctrl_) {
            ctrl_->release_shared();
            ctrl_ = nullptr;
            ptr_ = nullptr;
        }
    }

    // --- 拷贝构造与拷贝赋值（强引用计数递增） ---
    shared_ptr(const shared_ptr& other) noexcept
        : ptr_(other.ptr_), ctrl_(other.ctrl_) {
        if (ctrl_) {
            ctrl_->add_shared();
        }
    }

    template <typename Y, typename = std::enable_if_t<std::is_convertible<Y*, T*>::value>>
    shared_ptr(const shared_ptr<Y>& other) noexcept
        : ptr_(other.ptr_), ctrl_(other.ctrl_) {
        if (ctrl_) {
            ctrl_->add_shared();
        }
    }

    shared_ptr& operator=(const shared_ptr& other) noexcept {
        if (this != &other) {
            shared_ptr(other).swap(*this);
        }
        return *this;
    }

    template <typename Y, typename = std::enable_if_t<std::is_convertible<Y*, T*>::value>>
    shared_ptr& operator=(const shared_ptr<Y>& other) noexcept {
        shared_ptr(other).swap(*this);
        return *this;
    }

    // --- 移动构造与移动赋值（零引用计数原子操作，接管控制块） ---
    shared_ptr(shared_ptr&& other) noexcept
        : ptr_(other.ptr_), ctrl_(other.ctrl_) {
        other.ptr_ = nullptr;
        other.ctrl_ = nullptr;
    }

    template <typename Y, typename = std::enable_if_t<std::is_convertible<Y*, T*>::value>>
    shared_ptr(shared_ptr<Y>&& other) noexcept
        : ptr_(other.ptr_), ctrl_(other.ctrl_) {
        other.ptr_ = nullptr;
        other.ctrl_ = nullptr;
    }

    shared_ptr& operator=(shared_ptr&& other) noexcept {
        if (this != &other) {
            shared_ptr(std::move(other)).swap(*this);
        }
        return *this;
    }

    template <typename Y, typename = std::enable_if_t<std::is_convertible<Y*, T*>::value>>
    shared_ptr& operator=(shared_ptr<Y>&& other) noexcept {
        shared_ptr(std::move(other)).swap(*this);
        return *this;
    }

    shared_ptr& operator=(std::nullptr_t) noexcept {
        reset();
        return *this;
    }

    // --- 观察与解引用接口 ---
    element_type* get() const noexcept { return ptr_; }
    element_type& operator*() const noexcept { return *ptr_; }
    element_type* operator->() const noexcept { return ptr_; }
    explicit operator bool() const noexcept { return ptr_ != nullptr; }

    long use_count() const noexcept {
        return ctrl_ ? ctrl_->use_count() : 0;
    }

    bool unique() const noexcept {
        return use_count() == 1;
    }

    // --- 修改接口 ---
    void reset() noexcept {
        shared_ptr().swap(*this);
    }

    template <typename Y>
    void reset(Y* p) {
        shared_ptr(p).swap(*this);
    }

    template <typename Y, typename Deleter>
    void reset(Y* p, Deleter d) {
        shared_ptr(p, std::move(d)).swap(*this);
    }

    void swap(shared_ptr& other) noexcept {
        using std::swap;
        swap(ptr_, other.ptr_);
        swap(ctrl_, other.ctrl_);
    }
};

// --- 非成员辅助函数 ---
template <typename T>
void swap(shared_ptr<T>& lhs, shared_ptr<T>& rhs) noexcept {
    lhs.swap(rhs);
}

template <typename T>
bool operator==(const shared_ptr<T>& x, std::nullptr_t) noexcept {
    return !x;
}
template <typename T>
bool operator==(std::nullptr_t, const shared_ptr<T>& x) noexcept {
    return !x;
}
template <typename T>
bool operator!=(const shared_ptr<T>& x, std::nullptr_t) noexcept {
    return static_cast<bool>(x);
}
template <typename T>
bool operator!=(std::nullptr_t, const shared_ptr<T>& x) noexcept {
    return static_cast<bool>(x);
}

// ==========================================
// 4. make_shared 辅助工厂函数
// ==========================================
template <typename T, typename... Args>
shared_ptr<T> make_shared(Args&&... args) {
    return shared_ptr<T>(new T(std::forward<Args>(args)...));
}
```

## 1. 核心概念与共享所有权模型

与 [[独享智能指针|unique_ptr]] 的独占语义不同，`std::shared_ptr` 解决的是**多个实体需要共同维护同一对象生命周期**的场景。

```text
       ┌──────────────┐
p1 ───►│              │
       │  堆内存对象   │ ◄── 多个指针共享同一底层实例
p2 ───►│              │
       └──────────────┘
```

- **允许多重所有权**：多个 `shared_ptr` 可以复制并指向同一对象，拷贝操作会增加引用计数。
- **状态同步可见**：通过任何一个 `shared_ptr` 修改对象内部状态，其他所有持有该对象的指针访问时都能看到修改结果。
- **协同生命周期**：单个 `shared_ptr` 析构仅减少引用计数，对象本身保持存活；只有当最后一个持有该对象的 `shared_ptr` 析构、引用计数减为 0 时，底层对象才会被真正释放。

```cpp
#include <iostream>
#include <memory>

int main() {
    auto p1 = std::make_shared<int>(10);
    auto p2 = p1; // 共享所有权，引用计数变为 2

    *p2 = 100;    // 通过 p2 修改
    std::cout << *p1 << "\n"; // 输出 100，p1 看到的是同一对象

    return 0;
}
```

## 2. 内部结构与控制块（Control Block）

`std::shared_ptr` 并非简单的单一裸指针封装，其在 64 位系统下通常占用 **16 字节**（2 个指针大小），由两个核心成员组成：

1. **指向托管对象的原生指针**（`T* ptr`）：直接提供解引用（`->`、`*`）访问，无间接寻址开销。
2. **指向控制块的原生指针**（`ControlBlock* cb`）：指向由所有引用者共享的堆控制块。

### 控制块的组成

控制块在堆上动态分配，是实现共享机制的核心中枢，包含：
1. **强引用计数（shared_count）**：当前拥有该 **对象（堆内存）** 的 `shared_ptr` 实例数量。归零时触发对象析构。
2. **弱引用计数（weak_count）**：当前指向该 **控制块** 的 [[弱引用智能指针]] 实例数量。当 `shared_count` 与 `weak_count` 均归零时，控制块自身才会被释放。
3. **自定义删除器（Deleter）**：释放资源时调用的函数对象（如果有）。
4. **自定义内存分配器（Allocator）**：用于控制块内部内存管理的分配器。

## 3. 对象创建：std::make_shared vs 裸 new 构造

### 为什么推荐 make_shared

在创建 `shared_ptr` 时，应优先使用 `std::make_shared`：

```cpp
// 推荐写法
auto sp = std::make_shared<Task>(1);

// 不推荐写法
std::shared_ptr<Task> sp(new Task(1));
```

两者的内存分配与控制流行为差异明显：

```text
std::make_shared<T>() 内存布局（单块连续）：
┌─────────────────────────────────┬─────────────────────────────────┐
│        T 托管对象 (N 字节)        │    Control Block 控制块 (M 字节)  │
└─────────────────────────────────┴─────────────────────────────────┘
▲ 1 次分配。对象与控制块共享同一物理块，必须等两者计数全归零才整体 free()

std::shared_ptr<T>(new T) 内存布局（两块离散）：
┌─────────────────────────────────┐         ┌─────────────────────────────────┐
│        T 托管对象 (N 字节)        │   ...   │    Control Block 控制块 (M 字节)  │
└─────────────────────────────────┘         └─────────────────────────────────┘
▲ 2 次分配。shared_count 归零立即 free() 对象；weak_count 归零单独 free() 控制块
```

| 对比维度 | `std::make_shared<T>()` | `std::shared_ptr<T>(new T)` | 底层原理与工程影响 |
|---|---|---|---|
| **堆内存分配次数** | **1 次** | **2 次** | `make_shared` 将对象与控制块合并打包，减少一次 `malloc`/`new` 系统调用 |
| **内存物理布局** | **单块连续内存** | **两块独立离散内存** | `make_shared` 数据与控制块紧挨，显著提升 CPU 缓存局部性（减少 Cache Miss） |
| **异常安全性** | **绝对安全** | **存在泄漏风险**（C++17 前） | 若写在函数参数中且编译器乱序执行，裸 `new` 可能在传入智能指针前抛异常导致泄漏 |
| **内存归还时机（free）** | **整块延迟归还** | **分步即时归还** | `make_shared` 必须等 `weak_count` 归零才整体释放；大对象可能被 `weak_ptr` 滞留 |
| **自定义删除器** | ❌ **不支持** | ✅ **原生支持** | `make_shared` 模板参数无法接收 Deleter；管理文件句柄、Socket 等系统资源必须用构造函数 |
| **类私有/保护构造函数** | ❌ **无法直接访问** | ✅ **类内可直接调用** | `make_shared` 内部在命名空间域构造，无法访问类的私有构造函数（除非使用 Passkey 技巧） |
| **大括号列表初始化** | ⚠️ **需显式指定类型** | ✅ **支持直接传 `{...}`** | 完美转发无法直接推导未指定类型的 `{...}` 列表（如 `make_shared<T>({1, 2})` 编译失败） |
| **最佳选型建议** | **常规首选** | **特定场景专用** | 默认一律优先 `make_shared`；仅在需自定义删除器、防大对象滞留或私有构造时使用 `new` |

在 C++17 之前，若将表达式写在函数参数中：

```cpp
processWidget(std::shared_ptr<Widget>(new Widget), computePriority());
```

若编译器的求值顺序为先执行 `new Widget`，接着执行 `computePriority()`，一旦 `computePriority()` 抛出异常，`std::shared_ptr` 的构造函数尚未执行，`new Widget` 产生的内存将永久泄漏。`std::make_shared` 避免了裸 `new` 悬挂，彻底杜绝该漏洞。

### make_shared 的隐形代价与局限

尽管 `make_shared` 高效，但在特定场景下也有权衡考量：

1. **大对象的内存滞留问题**：
   因为 `make_shared` 将对象和控制块分配在同一块内存中，当 `shared_count == 0` 时，对象析构函数虽然会被调用，但**整块堆内存必须等到 `weak_count == 0` 时才能归还给系统分配器**。如果托管对象占用很大内存（如数兆字节的图像或缓冲区），且有长生命周期的 `weak_ptr` 持续观察，这块大内存就无法及时释放。此时手动分开分配（`new` 构造）反而能让大对象尽早退还堆空间。
2. **不支持自定义删除器**：`std::make_shared` 无法接收自定义 Deleter，需要非默认清理方式时只能使用构造函数。

## 4. 拷贝、移动与所有权流转机制

### 拷贝构造：增加引用计数

每次拷贝 `shared_ptr` 时，内部执行三件事：
1. 复制对象指针。
2. 复制控制块指针。
3. 对控制块内的 `shared_count` 执行**原子自增操作**（`atomic increment`）。

```cpp
auto p1 = std::make_shared<int>(42); // count = 1
auto p2 = p1;                        // count = 2（原子自增）
```

### 移动语义：零开销所有权转移

`std::shared_ptr` 支持移动构造与移动赋值。移动操作只复制指针并置空源对象，**不会触发原子引用计数的增减**：

```cpp
auto p1 = std::make_shared<int>(42); // count = 1
auto p2 = std::move(p1);             // count 仍为 1，p1 变为 nullptr
```

```text
移动前：
  p1 ──► [Object] & [Control Block (count=1)]
  p2 ──► 未初始化

移动后：
  p1 ──► nullptr
  p2 ──► [Object] & [Control Block (count=1)]
```

在无需增加所有者、仅仅在作用域之间交接智能指针时，显式使用 `std::move` 可以避免无谓的原子操作，减少多核总线同步损耗。

### 经典致命错误：双重控制块

绝对不能用同一个原生裸指针去初始化两个独立的 `shared_ptr`：

```cpp
int* raw = new int(10);

std::shared_ptr<int> sp1(raw);
std::shared_ptr<int> sp2(raw); // 严重错误！
```

```text
sp1 ──► 控制块 A (count=1) ──► raw
sp2 ──► 控制块 B (count=1) ──► raw
```

`sp1` 和 `sp2` 各自创建了独立的控制块，对彼此的存在毫无感知。当 `sp1` 离开作用域析构时会执行 `delete raw`；随后的 `sp2` 析构时会再次对 `raw` 执行 `delete`，直接引发 **Double Free** 崩溃。

## 5. 函数接口设计契约与参数传递

在函数设计中滥用智能指针是常见反模式。应根据所有权语义选择最精简的参数类型：

```cpp
// 1. 只借用对象，不参与生命周期管理（推荐做法）
void process(const Task& task); // 无需为空时
void process(const Task* task); // 允许空指针时

// 2. 参与共享所有权（Sink 参数 / 存活延长）
void registerTask(std::shared_ptr<Task> task) {
    globalTaskList.push_back(task); // 需要在函数外长久保存引用
}
```

### 参数设计语义速查

| 参数形式 | 语义倾向 | 性能开销 | 适用场景 |
|---|---|---|---|
| `const T&` / `T&` | 纯借用，不涉及生命周期 | 零开销（最快） | 90% 的普通业务逻辑函数 |
| `T*`（通过 `ptr.get()`） | 纯借用，且参数可能为空 | 零开销 | 对接 C API 或可选参数接口 |
| `std::unique_ptr<T>` | 独占所有权转让 | 零开销（移动） | 资源消费型函数（Sink） |
| `const std::shared_ptr<T>&` | 共享观察，不增加计数 | 仅传递指针引用 | 需要在内部可能升级所有权，但不常态拷贝 |
| `std::shared_ptr<T>`（按值传递） | 明确获取一份共享所有权 | **产生原子增减计数** | 函数内部需要将指针存入容器、队列或回调闭包 |

> **工程原则**：如果一个函数只是读写对象的数据、不负责决定对象的生死，直接传引用或裸指针；不要为了“方便”让每个函数签名都接收 `std::shared_ptr`，否则会引发大量的原子计数同步开销。

## 6. 线程安全边界与多核性能损耗

### 引用计数安全 vs 对象访问安全

关于 `shared_ptr` 的线程安全，行业标准定义非常明确：

1. **控制块引用计数的增减是线程安全的**：
   内部使用 `std::atomic` 原语，多个线程同时对不同的 `shared_ptr` 实例进行拷贝或析构，指向同一个底层对象时，引用计数的计算绝对准确，不会发生竞态破坏。
2. **被管理对象的读写不是线程安全的**：
   多个线程通过各自的 `shared_ptr` 同时修改同一个底层对象的数据，必须由使用者自行提供同步原语（如 `std::mutex`、读写锁等）。
3. **同一个 `shared_ptr` 实例本身的并发写入不是线程安全的**：
   若线程 A 正在对 `sp` 执行赋值操作，而线程 B 同时在读取同一个 `sp`，必须加锁或使用 C++20 的 `std::atomic<std::shared_ptr<T>>`。

```text
                 shared_ptr 的线程安全维度
                             │
     ┌───────────────────────┴───────────────────────┐
     ▼                                               ▼
控制块与引用计数 (Thread-Safe)               对象数据读写 (Non-Thread-Safe)
多线程并发拷贝/析构安全                      多线程并发修改对象需额外加锁
```

### 高并发下的 Cache 颠簸问题

在 RDMA、高性能存储（如 SPDK）和极低延迟系统中，开发者往往对 `std::shared_ptr` 非常谨慎：

- 每次拷贝 `shared_ptr` 都会对控制块中的 `shared_count` 执行原子递增（如 `LOCK XADD` 汇编指令）。
- 在多核 CPU 架构下，存放引用计数的 Cache Line 会在不同核心的 L1/L2 缓存间频繁进行所有权转移（Cache Coherence 颠簸），导致明显的总线开销与流水线停顿。
- 高性能架构更倾向于：**单个拥有者（unique_ptr 或 arena 内存池）+ 无拥有权的指针/引用借用**。

## 7. 核心操作接口与状态查询

### use_count()：调试与观察

```cpp
auto sp1 = std::make_shared<int>(10);
std::cout << sp1.use_count() << "\n"; // 输出 1

auto sp2 = sp1;
std::cout << sp1.use_count() << "\n"; // 输出 2
```

> **注意**：在多线程环境中，`use_count()` 返回的值仅在读取瞬间有效，随后随时可能被其他线程修改，因此**严禁将其用于程序逻辑分支控制**（例如 `if (sp.use_count() == 1)`），它仅供调试与日志打印使用。

### reset()：脱离当前所有权

`reset()` 表示当前实例主动放弃管理权：
- 若不带参数：当前指针置为 `nullptr`，引用计数减 1。若计数变为 0，销毁对象。
- 若带参数 `reset(newPtr)`：放弃原对象的所有权（可能析构原对象），并接管新对象的管理权。

```cpp
auto sp1 = std::make_shared<int>(10);
auto sp2 = sp1;

sp1.reset(); // sp1 变为 nullptr，引用计数从 2 降为 1，底层 int(10) 不受影响
sp2.reset(); // 引用计数从 1 降为 0，底层 int(10) 真正执行 delete
```

### get()：借用底层指针

返回底层的原生指针 `T*`，不改变引用计数：
- 常用于向不接管生命周期的老旧 C 接口传递参数。
- **严禁对 `get()` 返回的指针手动执行 `delete`**，否则智能指针后续析构时必然导致崩溃。

## 8. 循环引用与 weak_ptr 打破方案

### 循环引用如何导致内存泄漏

当两个对象内部相互使用 `std::shared_ptr` 指向对方时，会形成闭环依赖：

```cpp
struct B;

struct A {
    std::shared_ptr<B> b_ptr;
    ~A() { std::cout << "~A()\n"; }
};

struct B {
    std::shared_ptr<A> a_ptr;
    ~B() { std::cout << "~B()\n"; }
};

void createCycle() {
    auto a = std::make_shared<A>();
    auto b = std::make_shared<B>();

    a->b_ptr = b; // b 的引用计数变为 2
    b->a_ptr = a; // a 的引用计数变为 2
} // 作用域结束：栈变量 a、b 析构，但堆上对象的引用计数都仅降为 1，永远无法归零！
```

```text
离开 createCycle 后：
  ┌──────┐    shared_ptr (count=1)    ┌──────┐
  │ 堆 A │ ─────────────────────────► │ 堆 B │
  │      │ ◄───────────────────────── │      │
  └──────┘    shared_ptr (count=1)    └──────┘

结果：A 析构依赖 B 先销毁，B 析构依赖 A 先销毁，形成生命周期死锁，内存永久泄漏。
```

### 解决方案：引入 weak_ptr

使用 [[弱引用智能指针]] 打破强引用闭环：弱指针只观察对象，**不增加控制块中的强引用计数 `shared_count`**。

```cpp
struct B;

struct A {
    std::shared_ptr<B> b_ptr; // A 强拥有 B
    ~A() { std::cout << "~A()\n"; }
};

struct B {
    std::weak_ptr<A> a_ptr;   // B 仅弱引用观察 A，不参与所有权
    ~B() { std::cout << "~B()\n"; }
};
```

此时 `a` 退出作用域时 `shared_count` 可以正常归零，触发析构级联，解除循环。

## 9. enable_shared_from_this 与异步工程实战

> [!tip] 专项机制深度解析
> 双重控制块的内存时序推演、标准库内部 `_M_weak_this` 回溯通道、构造期挂载时机与完整防御范式，详见独立笔记：[[enable_shared_from_this]]。

### 为什么不能直接 shared_ptr(this)

在类成员函数内部，若需要将当前对象的 `shared_ptr` 传递给外部系统，直接使用 `std::shared_ptr<T>(this)` 会导致双重控制块灾难：

```cpp
class Session {
public:
    void registerSelf() {
        // 错误：根据 raw this 创建了全新的控制块！
        auto sp = std::shared_ptr<Session>(this);
    }
};
```

### 正确做法：继承 enable_shared_from_this

类继承自 `std::enable_shared_from_this<T>`，在内部通过 `shared_from_this()` 获取共享指针：

```cpp
#include <iostream>
#include <memory>

class Session : public std::enable_shared_from_this<Session> {
public:
    void registerSelf() {
        // 正确：复用已有的控制块，引用计数原子递增
        std::shared_ptr<Session> self = shared_from_this();
        std::cout << "use_count: " << self.use_count() << "\n";
    }
};

int main() {
    auto s = std::make_shared<Session>();
    s->registerSelf(); // 安全执行
    return 0;
}
```

> **调用约束**：调用 `shared_from_this()` 前，**该对象必须已经被某个 `std::shared_ptr` 管理**。如果是栈上直接构造的对象（`Session s; s.registerSelf();`），调用会直接抛出 `std::bad_weak_ptr` 异常。

### 异步网络模型实战（Reactor / EventLoop 回调）

在异步网络服务开发中，连接对象（`Connection`）通常是生命周期极难预测的实体：外部可能因超时主动踢掉连接，但底层内核的异步读写事件可能还在排队。

使用 `enable_shared_from_this` 保证异步回调期间对象存活：

```cpp
class TcpConnection : public std::enable_shared_from_this<TcpConnection> {
public:
    void doAsyncRead() {
        // 获取自身的 shared_ptr，并将其捕获进 lambda 回调中
        auto self = shared_from_this();

        async_read_some([self](const std::string& data) {
            // 只要回调未执行完，self 维持引用计数，TcpConnection 绝不会提前析构
            self->handleData(data);
        });
    }

    void handleData(const std::string& data) {
        // 处理数据
    }
};
```

只要回调未被触发或正在执行，Lambda 闭包内保存的 `self` 就确保了 `TcpConnection` 实例不会成为悬空指针；一旦回调完成销毁，若外部也无持有者，连接便顺畅析构。

## 10. 管理动态数组与自定义删除器

### 数组管理演进

- **C++11 / C++14**：`std::shared_ptr` 默认通过 `delete` 释放对象。管理数组必须显式传入调用 `delete[]` 的删除器：
  ```cpp
  std::shared_ptr<int> arr(new int[10], [](int* p){ delete[] p; });
  ```
- **C++17 之后**：增加了对数组偏特化的原生支持，析构时自动匹配 `delete[]`，且支持 `operator[]`：
  ```cpp
  std::shared_ptr<int[]> arr(new int[10]);
  arr[0] = 100;
  ```
- **C++20 之后**：可以使用 `std::make_shared<int[]>(10)` 直接构造数组。

### 自定义删除器的类型擦除（Type Erasure）

与 `std::unique_ptr<T, Deleter>` 将删除器类型固化在模板参数不同，**`std::shared_ptr<T>` 的删除器类型被擦除并保存在堆上的控制块中**：

```cpp
auto customDeleter = [](FILE* fp) { if (fp) std::fclose(fp); };

// shared_ptr 类型仅为 std::shared_ptr<FILE>，与删除器类型无关
std::shared_ptr<FILE> filePtr(std::fopen("log.txt", "w"), customDeleter);
```

- **优点**：不同删除器的 `shared_ptr` 拥有完全相同的类型，可以无缝放进同一个容器或通过相同接口传递。
- **代价**：控制块必须在堆上存储可调用对象，增加了少许间接调用开销。

## 11. 资源选型思维模型与完整对比

### 选型决策流

在现代 C++ 架构设计中，对象的存储与指针选型应遵循自底向上的约束顺序：

```text
需要声明或管理一个资源？
  │
  ├── 1. 作用域严格限定在局部栈帧？ ──► 优先使用直接栈对象（T obj;），性能最高
  │
  └── 2. 必须堆分配或生命周期跨越作用域？
        │
        ├── 能够确定唯一拥有者？ ──► 优先选 std::unique_ptr<T>（零开销抽象，默认选择）
        │
        └── 确实需要多个拥有者共同维持存活（如异步连接、共享缓存）？
              │
              ├── 真正参与生命周期持有 ──► 使用 std::shared_ptr<T>
              │
              └── 仅为反向观察或防止循环引用 ──► 配合 std::weak_ptr<T>
```

### 生产架构典型案例（网络服务）

```cpp
class Server {
private:
    // 独占资源：服务器配置由 Server 单独拥有
    std::unique_ptr<Config> config_;

    // 共享资源：连接可能同时被 Server、EventLoop、定时器、异步回调持有
    std::vector<std::shared_ptr<TcpConnection>> activeConnections_;
};
```

### 指针类别全景对比表

| 特性维度 | 原生指针 `T*` | 独占指针 `unique_ptr<T>` | 共享指针 `shared_ptr<T>` | 弱引用指针 `weak_ptr<T>` |
|---|---|---|---|---|
| **所有权语义** | 无所有权（仅存地址） | 独占所有权 | 共享所有权 | 观察者（无所有权） |
| **可拷贝性** | 是 | 否（仅支持移动） | 是（增加引用计数） | 是（增加弱引用计数） |
| **内存开销** | 8 字节 | 8 字节（默认删除器） | **16 字节** + 堆控制块 | **16 字节**（共用控制块） |
| **性能损耗** | 无 | 无（零开销抽象） | 原子递增/递减计数开销 | `lock()` 产生原子自增开销 |
| **解引用操作** | `*p`、`p->` | `*p`、`p->` | `*p`、`p->` | **不可直接解引用**，需先 `lock()` |
| **循环引用风险** | 悬空指针风险 | 不存在 | **存在**（导致内存泄漏） | **用于打破循环** |
| **转换为 shared_ptr**| 易误用导致双重释放 | 支持（通过移动单向转换） | - | 支持（调用 `lock()` 返回） |

# 6.3 动态内存分配的风险

> 本节是 [[6.2 动态内存分配与释放]] 的延续，讨论动态内存管理中常见的风险、典型错误场景及防范方案。

动态内存分配将内存生命周期的管理权限完全交给了开发者。一旦管理不善，轻则导致内存泄漏、进程变慢，重则引发段错误（Segmentation Fault）崩溃或严重的安全漏洞（如任意代码执行）。以下是开发中最常见的风险类型与错误场景。

---

## 1. 内存泄漏 (Memory Leak)

**定义**：在堆上动态申请内存后，未及时释放或丢失了对该内存的指针引用，导致这块内存无法被系统回收重用，直到进程结束。

### 典型发生场景

#### 场景一：指针重新赋值导致地址丢失
在释放原有堆内存前，指针直接被赋予新地址，导致上一块内存的地址彻底遗失，再也无法被释放。

```cpp
int* p = new int(10);

// 错误：未释放旧内存，直接覆盖指针，值为 10 的堆内存发生泄漏
p = new int(20);

delete p; // 仅释放了值为 20 的内存
p = nullptr;
```

#### 场景二：多分支或提前 return 遗漏释放
函数内部存在多处条件返回分支，部分分支跳过了末尾的释放代码。

```cpp
void process(int code) {
    int* buffer = new int[100];

    if (code < 0) {
        // 错误：直接退出，跳过了底部的 delete[]
        return;
    }

    // 正常业务逻辑...

    delete[] buffer;
}
```

#### 场景三：异常中断跳过释放逻辑
在 `new` 之后、`delete` 之前发生异常，由于没有使用 RAII 对象管理资源，执行流直接跳转到上层 catch 块，堆内存得不到释放。

```cpp
void executeTask() {
    int* data = new int[1024];

    // 如果此函数抛出异常，下方的 delete[] 永远不会被执行
    mayThrowException();

    delete[] data;
}
```

### 危害与排查
- **危害**：长期运行的服务端进程内存不断升高，最终耗尽系统物理内存或触发 Linux OOM Killer 被强行杀死。
- **排查工具**：GCC/Clang 的 AddressSanitizer（编译时加 `-fsanitize=address -g`）、Valgrind。

---

## 2. 野指针 (Wild Pointer)

**定义**：未经初始化的指针。指针变量被声明时如果没有赋初值，它的值是栈上残留的随机垃圾地址，处于未定义状态。

```cpp
void testWildPointer() {
    int* p; // 局部变量未初始化，内部存储的是随机地址（野指针）

    // 危险：试图解引用野指针
    *p = 100; // 未定义行为：可能触发段错误崩溃，也可能静默破坏其他栈变量
}
```

### 为什么野指针极难排查
野指针的值完全取决于当时栈帧内存里的残留数据：
- 若碰巧指向未映射或内核只读区域，程序会直接崩溃（`SIGSEGV`）。
- 若碰巧落在一块合法的、可写的进程内存中，修改操作会**静默破坏其他变量**，程序不会立即崩溃，而是在后续无关代码中诡异出错。

### 防御方案
- **声明时必须初始化**：如果不确定初值，必须显式赋为 `nullptr`。
- **尽可能推迟声明**：直到需要用到指针且有合法地址可赋时再声明。

---

## 3. 悬空指针 (Dangling Pointer) 与 Use-After-Free

**定义**：指针曾经指向一块合法的内存，但在该内存被释放（`free` 或 `delete`）后，指针变量本身仍然保存着已失效的原内存地址。

```cpp
int main() {
    int* ptr = new int(10);
    delete ptr;
    // 关键认知：delete 只负责通知堆管理器回收内存，不会把 ptr 变量本身清零！
    // 此时 ptr 依然存储原内存地址，它成为了悬空指针

    // 危险：解引用悬空指针（Use-After-Free，UAF）
    // cout << *ptr << endl; // 未定义行为！该内存可能已被分配给其他对象

    ptr = nullptr; // 正确做法：释放后立即将指针置空
    return 0;
}
```

### 另一高频场景：返回栈上局部变量的指针
函数返回了指向自身栈帧内局部变量的地址。函数调用结束后，该栈帧已被弹出销毁，外部获取到的指针就是悬空指针。

```cpp
int* getStackPointer() {
    int localVal = 42;
    return &localVal; // 严重错误：返回局部变量地址
}
```

---

## 4. 野指针 vs 悬空指针对比

两者在面试和实战中极易混淆，核心区别在于**指针是否曾经合法过**：

| 对比维度 | 野指针 (Wild Pointer) | 悬空指针 (Dangling Pointer) |
|----------|----------------------|---------------------------|
| **产生时机** | 指针声明后**未初始化** | 指针指向的内存被释放（`free`/`delete`）后 |
| **合法历史** | **从未**指向过合法内存 | **曾经**指向过合法的有效内存 |
| **内存中的值** | 栈上随机的垃圾数据 | 之前分配过、但现已失效的旧内存地址 |
| **核心成因** | 漏写初始化 | 释放内存后未将指针重置（未置空） |
| **解决方案** | 声明即赋初值（如 `nullptr`） | 释放后立即置 `nullptr`，或改用智能指针 |

## 5. 重复释放 (Double Free)

**定义**：对同一块动态分配的内存执行了两次或多次释放操作。

```cpp
int main() {
    int* p1 = new int[50];
    int* p2 = p1; // p2 和 p1 指向同一块堆内存（指针别名）

    delete[] p1;
    // 错误：p2 指向的内存刚被释放，再次调用 delete[] 触发 Double Free
    delete[] p2;
}
```

### 产生的常见场景
1. **指针别名（Aliasing）**：多个指针同时持有同一块堆内存的地址，其中一个指针释放后，其余指针未置空且再次执行释放。
2. **类的浅拷贝（Shallow Copy）**：类包含原始指针成员，使用默认的拷贝构造函数或拷贝赋值运算符导致两个对象的指针成员指向同一地址，两个对象析构时重复释放该指针。

### 运行时后果
堆管理器（如 glibc 的 ptmalloc）在维护空闲块链表时具有完整性校验。重复释放会破坏堆元数据链表，系统会立即抛出 `double free or corruption` 并发送 `SIGABRT` 强行中止程序。这在安全领域也是常见的可利用堆漏洞。

## 6. 错误的释放方式 (Mismatched Free)

**定义**：申请内存的方式与释放内存的方式不配对。

```cpp
// 错误 1：new[] 分配的数组用 delete 释放
int* arr = new int[10];
delete arr; // 应该用 delete[] arr;

// 错误 2：malloc 分配的内存用 delete 释放；或 new 分配的内存用 free 释放
int* p = (int*)malloc(sizeof(int));
delete p;   // 应该用 free(p);
```

### 配对规则与底层原理

| 分配方式 | 释放方式 | 底层原因 |
|----------|----------|----------|
| `malloc` / `calloc` | `free` | C 运行时函数，仅分配裸内存，不调用构造/析构函数 |
| `new` | `delete` | 先调用单个对象的析构函数，再回收该对象占用的内存 |
| `new[]` | `delete[]` | 在数组头部额外记录了元素个数（Cookie），`delete[]` 会据此逐个调用每个元素的析构函数并释放整块内存 |

> 如果对 `new[]` 分配的对象数组错用 `delete`，编译器通常只调用第一个元素的析构函数，其余元素的资源无法析构；同时由于传入堆管理器的指针偏移量可能不匹配，还会破坏堆元数据引发 Crash。

## 7. 内存分配失败未检查

当物理内存耗尽或单次申请极大内存时，分配可能失败。不同分配机制失败时的表现不同：

```cpp
#include <iostream>
#include <new>
#include <cstdlib>

void checkAllocation() {
    // 1. malloc 失败：返回 NULL，若不判断直接解引用会崩溃
    int* p1 = (int*)malloc(1024ULL * 1024 * 1024 * 1024); // 极大尺寸
    if (p1 == nullptr) {
        // 处理分配失败
    }

    // 2. new 失败：默认抛出 std::bad_alloc 异常，而非返回 nullptr
    try {
        int* p2 = new int[100000000000ULL];
    } catch (const std::bad_alloc& e) {
        std::cerr << "分配失败: " << e.what() << '\n';
    }

    // 3. std::nothrow 版 new：失败时不抛异常，返回 nullptr
    int* p3 = new (std::nothrow) int[100000000000ULL];
    if (p3 == nullptr) {
        // 处理分配失败
    }
}
```

## 8. 内存拷贝与初始化隐患

### 8.1 memcpy 隐患
- **缓冲区越界（Heap Buffer Overflow）**：目标内存空间小于拷贝字节数，越界破坏临近堆数据。
- **内存重叠**：源区间与目的区间存在重叠时，`memcpy` 的行为未定义，必须使用能处理重叠的 `memmove`。

### 8.2 memset 按字节填充陷阱
`memset` 是逐**字节**写入内存。如果用于非单字节类型（如 `int`、`float`），除 `0` 和 `-1`（按补码每一位全是 1）外，通常会得到意料之外的数值：

```cpp
int arr[5];
memset(arr, 0, sizeof(arr)); // 正确：每个字节填 0，结果为 0
memset(arr, 1, sizeof(arr)); // 错误：每个 int 被设为 0x01010101（十进制 16843009），并不是 1
```

## 9. 现代 C++ 的工程防御策略

现代 C++ 通过语言特性大幅降低了裸指针带来的风险：

1. **坚持 RAII 原则**：用对象的生命周期自动绑定堆内存资源，构造时申请，析构时自动释放。
2. **使用智能指针替代裸指针**：
   - 独占语义使用 [[独享智能指针|std::unique_ptr]]。
   - 共享语义使用 [[共享智能指针|std::shared_ptr]]，结合 [[弱引用智能指针]] 打破循环引用。
   - 优先通过 `std::make_unique` 和 `std::make_shared` 创建对象，避免裸 `new`。
3. **优先使用标准容器**：动态数组首选 `std::vector`，字符串首选 `std::string`，将内存管理完全委托给经过严格测试的标准库。
4. **编译期预警与运行时检测**：
   - 编译阶段开启 `-Wall -Wextra`。
   - 测试阶段启用 AddressSanitizer（`-fsanitize=address`），能精准捕获内存泄漏、野指针解引用、UAF 和堆越界。

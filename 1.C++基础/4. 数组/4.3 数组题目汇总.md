## 一、选择题（概念基础）

**1.** 数组的本质是：
- A. 一组分散的同类型变量　　B. 向操作系统申请的一段连续内存空间　　C. 一个指向首元素的指针　　D. 一个链表

**2.** C 风格数组通过索引访问元素的时间复杂度是：
- A. O(1)　　B. O(log n)　　C. O(n)　　D. 取决于元素位置

**3.** `int data[5]{1, 2};` 后，`data[3]` 的值是：
- A. 垃圾值　　B. `2`　　C. `0`　　D. 未定义行为

**4.** 数组作为函数参数 `void f(int arr[5])` 传递时，`arr` 的实际类型是：
- A. `int[5]`　　B. `int*`　　C. `int(&)[5]`　　D. `std::array<int,5>`

**5.** `int m[2][3]` 在内存中的排列顺序是：
- A. 列优先　　B. 行优先：`m[0][0],m[0][1],m[0][2],m[1][0]...`　　C. 不连续　　D. 随机

**6.** 关于 `std::array<int,5>` 与 C 数组，下列正确的是：
- A. `std::array` 在堆上分配　　B. `std::array` 传参会衰减为指针　　C. `std::array` 不衰减、保留大小、与 C 数组同样的内存布局　　D. `std::array` 比 C 数组慢很多

**7.** `vector` 的 `size()` 和 `capacity()` 的关系是：
- A. 永远相等　　B. `size <= capacity`　　C. `size >= capacity`　　D. 无关

**8.** `vec.reserve(100)` 之后，`vec.size()` 是：
- A. `100`　　B. `0`（仅改变 capacity，不创建元素）　　C. 未定义　　D. `>= 100`

**9.** `vector::push_back` 的时间复杂度是：
- A. 严格 O(1)　　B. 均摊（amortized）O(1)　　C. O(n)　　D. O(log n)

**10.** 局部变量 `std::vector<int> v{1,2,3};`，下列对存储位置描述正确的是：
- A. 对象和元素都在栈上　　B. 对象和元素都在堆上　　C. 对象在栈上，元素在堆上　　D. 对象在堆上，元素在栈上

**11.** `std::vector<std::vector<int>> matrix` 的内存特点是：
- A. 是一整块连续的二维矩阵　　B. 每行内部连续，但所有行不一定连成一整块，且每行长度可不同　　C. 所有行长度必须相同　　D. 在栈上连续分配

**12.** 与 C 数组相比，`std::array` 和 `std::vector` 都提供边界检查的方法是：
- A. `operator[]`　　B. `front()`　　C. `at()`　　D. `data()`

> [!success]- 参考答案（第一节）
> 1. **B**。数组本质是按数据类型向系统申请的一段**连续内存**，知道首地址即可 O(1) 计算任意元素地址。
> 2. **A**。连续存储 + 起始地址，`addr = base + i*sizeof(T)`，常数时间随机访问。
> 3. **C**。部分初始化时，未列出的元素被**值初始化为 0**，故 `data[3]==0`。
> 4. **B**。数组形参中的大小被忽略，发生**数组衰减**，`int arr[5]` 等价于 `int*`。
> 5. **B**。多维数组连续存储，按**行优先**展开。
> 6. **C**。`std::array` 是零开销封装，栈上、不衰减、保留大小、内存布局与 C 数组相同。
> 7. **B**。`size` 是有效元素数，`capacity` 是已分配容量，恒有 `size <= capacity`。
> 8. **B**。`reserve` 只改 capacity 不创建元素，`size` 仍为 0；访问 `v[k]` 是越界 UB。
> 9. **B**。单次可能触发扩容（O(n) 拷贝），但扩容呈翻倍摊销，平均下来是**均摊 O(1)**。
> 10. **C**。vector 对象本身（含 3 个管理指针）在栈，元素数据在堆。
> 11. **B**。二维 vector 是"vector 的 vector"，锯齿结构，行长可不同，不会自动补齐。
> 12. **C**。`at()` 有边界检查越界抛 `std::out_of_range`；`[]` 无检查。

## 二、概念辨析（判断对错并说明理由）

**13.** C 风格数组的大小可以在运行时改变。

**14.** `sizeof(arr)/sizeof(arr[0])` 对任意接收数组的函数形参都能正确求出元素个数。

**15.** `std::array` 的大小是其类型的一部分，`std::array<int,3>` 与 `std::array<int,4>` 是不同类型。

**16.** `vec.clear()` 会把 `size` 和 `capacity` 都变为 0。

**17.** `reserve(n)` 之后就可以安全访问 `v[n-1]`。

**18.** `emplace_back("Bob", 21)` 相比 `push_back(Student("Bob",21))` 可以省去一次临时对象的构造/拷贝。

**19.** 一维 `vector` 的元素在内存中连续存储。

**20.** `push_back` 触发扩容后，之前保存的指向元素的指针/迭代器仍然有效。

> [!success]- 参考答案（第二节）
> 13. **错**。C 数组大小编译期固定，运行时不可变；需要动态大小用 `std::vector`。
> 14. **错**。仅对**原始数组**有效。数组作为函数参数会衰减为指针，`sizeof(arr)` 得到指针大小（如 8），算出错误个数。
> 15. **对**。大小是模板参数，是类型的一部分，不同大小是不同类型，这也是它"不衰减、类型安全"的原因。
> 16. **错**。`clear()` 把 `size` 清零但**不释放内存**，`capacity` 不变；要释放用 `shrink_to_fit()`。
> 17. **错**。`reserve` 只预留容量不创建元素，访问 `v[n-1]` 是越界 UB；要让元素有效需 `resize` 或 `push_back`。
> 18. **对**。`emplace_back` 用参数在容器内**原地构造**，省去临时对象的构造与拷贝（一次构造 vs 构造+拷贝）。
> 19. **对**。一维 vector 元素在堆上连续存储，可像数组一样 O(1) 随机访问。
> 20. **错**。扩容会重新分配内存并搬移元素，**旧迭代器/指针/引用全部失效**，继续使用是 UB。

## 四、找错与修复（指出 bug 并改正）

**27.**
```cpp
// 想求数组元素个数
void printCount(int arr[]) {
    std::cout << sizeof(arr) / sizeof(arr[0]);  // 期望元素个数
}
```

**28.**
```cpp
int arr[5]{1,2,3,4,5};
for (int i = 0; i <= 5; ++i)        // 想遍历全部元素
    std::cout << arr[i] << " ";
```

**29.**
```cpp
std::vector<int> v{1,2,3,4,5};
for (auto it = v.begin(); it != v.end(); ++it)
    if (*it % 2 == 0) v.erase(it);   // 想删除所有偶数
```

**30.**
```cpp
std::vector<int> v;
v.reserve(5);
for (int i = 0; i < 5; ++i) v[i] = i;   // 想填入 0..4
std::cout << v.size();
```

**31.**
```cpp
// 返回局部数组的"指针"给外部用
int* makeArray() {
    int a[3]{1,2,3};
    return a;            // 返回栈上数组首地址
}
```

**32.**
```cpp
// C with Classes 风格：手动管理一段可变长 int 序列
int* buf = (int*)malloc(sizeof(int) * 3);
buf[0] = 1; buf[1] = 2; buf[2] = 3;
// ... 需要扩到 6 个
buf = (int*)realloc(buf, sizeof(int) * 6);
free(buf);
// 要求：用 Modern C++ 重写
```

> [!success]- 参考答案（第四节）
> 27. **数组衰减**：形参 `int arr[]` 实为 `int*`，`sizeof(arr)` 是指针大小，结果恒为 `8/4=2`（64 位）。修复：额外传 `size`，或用模板 `template<std::size_t N> void f(int(&arr)[N])` 保留大小，或改用 `std::array`/`std::span`（C++20）。
> 28. **越界访问**：`i<=5` 访问 `arr[5]` 越界 UB。修复：`i < 5`，或更安全地用范围 for `for (int x : arr)`/`std::size(arr)`。
> 29. **迭代器失效**：`erase` 使该位置及之后迭代器失效，`++it` 跳过元素甚至越界。修复：`it = v.erase(it);` 否则 `++it`；最佳：`std::erase_if(v, [](int x){return x%2==0;});`（C++20）或 erase-remove 惯用法。
> 30. **越界写 UB**：`reserve` 只给容量不创建元素，`v[i]=i` 写入未构造区域，且 `size` 仍为 0。修复：用 `v.push_back(i)`，或先 `v.resize(5)` 再 `v[i]=i`。
> 31. **悬垂指针**：返回栈上局部数组地址，函数返回后内存失效。修复：返回 `std::vector<int>` 或 `std::array<int,3>`（按值返回，有 RVO/移动，安全）。
> 32. **C 风格手动内存管理**。Modern 重写：
> ```cpp
> #include <vector>
> std::vector<int> buf{1, 2, 3};
> buf.resize(6);          // 自动扩容到 6（新增元素值初始化为 0）
> // 离开作用域自动释放，无需 free
> ```
> 要点：`std::vector` 取代 `malloc/realloc/free`，自动管理生命周期，异常安全，无内存泄漏。

## 五、简答题

**33.** 数组的四大关键特性是什么？

**34.** 什么是"数组衰减"？它会带来什么问题？有哪些规避方式？

**35.** `vector` 的 `size` 和 `capacity` 有什么区别？为什么要分开？

**36.** `reserve(n)` 和 `resize(n)` 有什么本质区别？

**37.** `push_back` 为什么是"均摊 O(1)"而不是严格 O(1)？

**38.** `at()` 和 `operator[]` 有什么区别？分别适合什么场景？

> [!success]- 参考答案（第五节）
> 33. ① **同质性**：所有元素同类型；② **连续存储**：内存紧密排列，可由首地址计算任意元素地址；③ **固定大小**：编译期确定，运行时不可改；④ **索引访问**：从 0 开始整数下标，随机访问 O(1)。
> 34. 数组作为函数参数传递时**衰减为指向首元素的指针**，丢失大小信息，导致 `sizeof` 失效、易越界。规避：额外传 size、用引用模板 `int(&)[N]` 保留大小、改用 `std::array`/`std::vector`/`std::span`。
> 35. `size` 是当前**有效（已构造）元素数量**，`capacity` 是**已分配内存能容纳的元素数量**。分开是为了支持"预留空间但不构造元素"，从而把多次扩容的内存分配摊销掉，减少重分配和拷贝。
> 36. `reserve(n)` 只改 `capacity`（预留空间、不创建元素、`size` 不变）；`resize(n)` 改 `size`（真正增删元素，新增元素被默认初始化）。口诀：reserve 占座人没来，resize 真的改人数。
> 37. 大多数 `push_back` 是 O(1)，但当 `size==capacity` 时触发扩容：分配更大内存（通常翻倍）+ 搬移全部元素，单次 O(n)。由于容量按倍数增长，n 次插入的总搬移代价是 O(n)，平摊到每次即**均摊 O(1)**。
> 38. `at()` 有运行时边界检查，越界抛 `std::out_of_range`；`operator[]` 无检查，越界是 UB 但更快。需要安全/外部输入索引用 `at()`；性能敏感且索引已保证合法用 `[]`。

## 六、综合设计与手写代码

**39.** 写一个模板函数 `template<std::size_t N> int sumArr(const int(&arr)[N])`，对 C 数组求和且**保留大小信息**（不衰减）。

**40.** 用 `std::vector<std::vector<int>>` 创建一个 3×4、初值为 0 的矩阵，并把对角线置 1，然后用范围 for（常量引用）打印。

**41.** （Modern C++ 重构题）把下面这段 C 风格"找数组最大值并排序"改写为 Modern C++：
```cpp
int arr[5] = {5, 3, 1, 4, 2};
int maxV = arr[0];
for (int i = 1; i < 5; ++i)
    if (arr[i] > maxV) maxV = arr[i];
for (int i = 0; i < 4; ++i)               // 冒泡排序
    for (int j = 0; j < 4 - i; ++j)
        if (arr[j] > arr[j+1]) { int t = arr[j]; arr[j] = arr[j+1]; arr[j+1] = t; }
printf("max=%d\n", maxV);
```

> [!success]- 参考答案（第六节）
> **39.**
> ```cpp
> template<std::size_t N>
> int sumArr(const int(&arr)[N]) {           // 引用形参保留大小 N
>     return std::accumulate(std::begin(arr), std::end(arr), 0);
> }
> ```
> 要点：引用 `(&arr)[N]` 不衰减，`N` 编译期可用；用 `std::accumulate` 取代手写循环。
>
> **40.**
> ```cpp
> #include <vector>
> #include <iostream>
> std::vector<std::vector<int>> m(3, std::vector<int>(4, 0));
> for (std::size_t i = 0; i < m.size(); ++i)
>     if (i < m[i].size()) m[i][i] = 1;
> for (const auto& row : m) {
>     for (int v : row) std::cout << v << ' ';
>     std::cout << '\n';
> }
> ```
> 要点：`vector(3, vector(4,0))` 构造矩阵；打印用 `const auto&` 避免拷贝整行。
>
> **41.**
> ```cpp
> #include <array>
> #include <algorithm>
> #include <iostream>
> std::array<int, 5> arr{5, 3, 1, 4, 2};
> int maxV = *std::max_element(arr.begin(), arr.end());
> std::sort(arr.begin(), arr.end());
> std::cout << "max=" << maxV << '\n';
> ```
> 要点：`std::array` + `std::max_element` + `std::sort` 取代裸数组、手写查找与冒泡，无 `printf`、无手写交换。

## 七、简答深化题

**42.** 从内存模型角度说明：为什么 `std::array` 对象和元素"绑在一起"，而 `std::vector` 对象和元素"分开存储"？这对拷贝、传参、性能各有什么影响？

**43.** vector 对象内部通常维护哪三个指针？`size` 和 `capacity` 如何由它们计算得出？

**44.** 为什么二维 `std::vector` 不是一整块连续矩阵？与 C 风格二维数组 `int m[3][4]` 相比，在缓存局部性上有什么劣势？

**45.** （跨章综合）结合[[3.3 位运算]]/底层知识，解释为什么"已知首地址 + 下标"就能 O(1) 定位数组元素，地址是如何算出来的？数组衰减为指针后为何还能 `arr[i]` 访问？

**46.** 范围 for 中 `auto x`、`auto& x`、`const auto& x` 三者有何区别？遍历一个 `vector<std::string>` 只读打印时应选哪个，为什么？

> [!success]- 参考答案（第七节）
> 42. `std::array` 大小是类型一部分，元素直接内嵌在对象内部（对象多大就含多少元素），故"绑在一起"，拷贝即拷贝全部元素，传参默认整体拷贝（除非引用），无堆分配。`vector` 对象只含几个管理指针（小且固定大小），元素在堆上独立分配，故"分开"：拷贝 vector 要深拷贝堆数据，移动则只搬指针（O(1)），有堆分配开销但大小可变。影响：array 适合小且固定、零堆开销；vector 适合动态、移动廉价。
> 43. 三个指针：`start`（首元素）、`finish`（最后一个有效元素的下一个位置）、`end_of_storage`（已分配容量末尾）。`size = finish - start`，`capacity = end_of_storage - start`。
> 44. 二维 vector 是"vector 的 vector"：外层连续存放各行的 vector 对象，但每行的元素各自在堆上独立分配，行与行之间不连续。相比 `int m[3][4]` 的一整块连续内存，遍历时跨行会发生指针跳转、缓存命中率低，且每行多一次堆分配与一层间接寻址，缓存局部性更差。
> 45. 数组连续存储且元素等大，`&arr[i] = base + i * sizeof(T)`，一次乘加即得地址，故 O(1)。`arr[i]` 本质是 `*(arr + i)` 的语法糖；数组名在表达式中衰减为指向首元素的指针后，指针算术 `arr + i` 仍按 `sizeof(T)` 步进，因此 `arr[i]` 照常工作——下标访问本就建立在指针算术之上。
> 46. `auto x` 拷贝元素（可改副本不影响原值）；`auto& x` 引用（可修改原元素）；`const auto& x` 常量引用（不拷贝、只读）。遍历 `vector<std::string>` 只读打印应选 `const auto&`：`string` 拷贝代价大，引用避免逐个深拷贝，`const` 表明只读意图、防误改。

## 八、概念辨析进阶

**47.** 辨析 C 风格数组 `int[N]` / `std::array<T,N>` / `std::vector<T>`（大小、内存位置、衰减、边界检查）。

**48.** 辨析 `size()` / `capacity()` / `reserve()` / `resize()`。

**49.** 辨析 `push_back` / `emplace_back` / `insert`。

**50.** 辨析 `[]` / `at()` / `front()` / `data()`。

> [!success]- 参考答案（第八节）
> 47. C 数组：编译期固定大小、栈、会衰减、无边界检查；`std::array`：编译期固定、栈、不衰减、`at()` 有检查；`vector`：运行期可变、（元素在）堆、不衰减、`at()` 有检查。口诀：固定用 array，动态用 vector，C 数组只留给 C 接口。
> 48. `size()` 当前有效元素数；`capacity()` 已分配可容纳数；`reserve(n)` 只增容量不增元素；`resize(n)` 改有效元素数（增删 + 默认初始化）。口诀：size 看人，capacity 看座，reserve 加座，resize 加人。
> 49. `push_back(val)` 末尾追加（拷贝/移动已存在对象）；`emplace_back(args...)` 末尾**原地构造**（省临时对象）；`insert(pos,val)` 任意位置插入（O(n) 搬移）。末尾首选 `emplace_back`/`push_back`，中间插入才用 `insert`。
> 50. `[]` 无检查随机访问（快）；`at()` 有边界检查（越界抛异常）；`front()`/`back()` 取首/尾元素引用；`data()` 取底层连续数组指针（用于和 C 接口对接）。

## 九、大厂面试场景题 / 八股常考

**51.** 面试官问："已知要往 vector 里塞 100 万个元素，怎么写性能最好？为什么？"

**52.** 一段代码在遍历 vector 时调用 `push_back`，偶发崩溃。诊断原因并给出正确写法。

**53.** "vector 是连续内存，那为什么 `std::vector<bool>` 经常被说有坑？" 请说明（结合本章 vector 的一般模型）。

**54.** 为什么很多高性能代码偏好 `std::array`/连续 `vector` 而非"指针数组 / 二维 vector"？从缓存角度解释。

**55.** `clear()` 之后内存为什么没释放？如何真正归还内存？这在长期运行的服务里有什么影响？

> [!success]- 参考答案（第九节）
> 51. **现象/做法**：先 `vec.reserve(1'000'000)` 再循环 `emplace_back`。**原因**：不 reserve 会经历多次翻倍扩容，每次重分配 + 搬移全部元素，累计大量拷贝与内存抖动；一次 reserve 把容量备足，后续插入都是 O(1) 且无重分配；`emplace_back` 再省临时对象。**延伸**：元素是 trivially-copyable 时扩容用 memcpy 较快，复杂对象则移动语义很关键。
> 52. **现象**：遍历中 `push_back` 触发扩容，正在用的迭代器/引用全部失效，继续解引用 UB → 偶发崩溃。**原因**：扩容重分配内存搬移元素。**解决**：遍历时不改容器；若必须追加，先 `reserve` 足够容量，或把新元素收集到另一容器再合并，或改用下标且每次重新取 `size()`。**延伸**：`insert/erase` 同样使迭代器失效，注意失效规则。
> 53. **现象**：`vector<bool>` 不是普通 vector。**原因**：标准对它做了**位压缩特化**，每个 bool 占 1 bit，`operator[]` 返回的是**代理对象**而非真正的 `bool&`，因此不能取元素地址、`auto&` 绑定行为反直觉、与泛型代码配合易出错。**解决**：需要真正 bool 数组用 `vector<char>`/`std::deque<bool>`/`bitset`（固定大小）。**延伸**：这是"为效率破坏一致性"的经典争议特化。
> 54. **现象**：连续容器更快。**原因**：连续内存对 CPU **缓存预取**友好，顺序遍历几乎全是缓存命中；而指针数组/二维 vector 元素分散在堆各处，遍历频繁 cache miss + 指针跳转，且多一层间接寻址。**解决**：能用一维连续就别用嵌套，必要时用 `vector<int>` 模拟二维（`idx=row*cols+col`）。**延伸**：这是数据导向设计（DOD）的核心动机之一。
> 55. **现象**：`clear()` 后 `capacity` 不变。**原因**：`clear()` 只销毁元素、把 `size` 归零，保留已分配内存以便复用（避免下次又重分配）。**解决**：`shrink_to_fit()`，或 `std::vector<T>().swap(vec)` 惯用法强制释放。**延伸**：长期服务中若大 vector 反复涨缩却不归还，会造成内存占用居高不下（内存"水位"问题），需按场景显式回收。

## 十、补充加分题

**56.** （复杂度/性能分析题）分别给出 vector 的：随机访问、尾插、头插、中间删除、无序查找的时间复杂度，并说明头插为什么慢、有什么替代容器。

**57.** vector 扩容为什么常选"翻倍（×2）"而不是"每次 +1"或"×10"？从均摊复杂度和内存利用率两个角度分析。

**58.** `std::array<int, 1000000> big;` 定义为函数局部变量有什么风险？换成 `std::vector` 为什么没有这个问题？

**59.** 对一个已排序的 `std::array`/`vector`，用什么算法能做到 O(log n) 查找？为什么 C 数组也能用同样的算法？

> [!success]- 参考答案（第十节）
> 56. 随机访问 `[]`/`at()` **O(1)**；尾插 `push_back` **均摊 O(1)**；头插（`insert(begin())`）**O(n)**（要搬移后续所有元素）；中间删除 `erase` **O(n)**；无序查找 **O(n)**。头插慢是因为 vector 连续存储，前面插入要整体后移。频繁头插/双端操作应改用 `std::deque` 或 `std::list`。
> 57. 翻倍使 n 次 `push_back` 的总搬移代价为 `1+2+4+...+n ≈ 2n = O(n)`，平摊到每次为均摊 O(1)；若每次 +1，则每次都搬移，总代价 O(n²)，退化严重。倍数太大（×10）虽更少扩容，但会浪费大量未用内存、降低利用率。×2（或 ×1.5）是时间与空间的折中。
> 58. 局部 `std::array<int,1000000>` 约占 4MB，直接放在**栈**上，极易**栈溢出**（线程栈通常仅 1~8MB）导致崩溃。`std::vector` 把元素分配在**堆**上，对象本身仅几个指针在栈，故大容量也安全。大数组应优先 vector 或静态/堆分配。
> 59. 用 `std::binary_search` / `std::lower_bound`，对有序连续序列做二分查找 O(log n)。C 数组也能用，因为这些算法基于**随机访问迭代器**，而指针正是满足要求的随机访问迭代器（`std::begin/std::end` 对 C 数组也成立），故 `std::lower_bound(arr, arr+n, x)` 同样工作。

## 十一、容器专项（选型 · 迭代器失效 · 复杂度）

**60.** 给出容器选型：以下场景分别选 C 数组 / `std::array` / `std::vector`，并说明理由。
- (a) 固定 3 个分量的三维坐标
- (b) 运行时读入未知数量的成绩
- (c) 与一个只接收 `int*` + 长度的 C 库函数对接

**61.** 下面代码想"在遍历中把所有等于 `target` 的元素删掉"，指出迭代器失效问题并用 ≥2 种正确写法修复。
```cpp
std::vector<int> v{1, 2, 2, 3, 2, 4};
int target = 2;
for (auto it = v.begin(); it != v.end(); ++it)
    if (*it == target) v.erase(it);
```

**62.** 判断下列操作后，原先保存的迭代器/引用是否失效：(a) `push_back` 未触发扩容；(b) `push_back` 触发扩容；(c) `clear()`；(d) 中间 `erase(it)`。

**63.** 已知要构建一个 `vector<Student>`（`Student` 构造较重），对比"`push_back(Student(...))` 不 reserve" 与 "先 `reserve` 再 `emplace_back`" 的开销差异（构造、拷贝/移动、内存分配次数）。

> [!success]- 参考答案（第十一节）
> 60. (a) `std::array<double,3>`：大小固定且小、栈上零开销、类型安全。(b) `std::vector<int>`：数量运行时才知、需动态增长。(c) `std::vector<int>` 后用 `v.data()` 和 `v.size()` 传给 C 库（或 `std::array`），既安全又能拿到连续指针；纯 C 数组仅在极简/遗留场景用。
> 61. **失效问题**：`erase(it)` 使 `it` 及之后迭代器失效，`++it` 会跳过元素或越界 UB（连续的 `2` 尤其漏删）。修复方式：
> ```cpp
> // 写法1：用 erase 返回值
> for (auto it = v.begin(); it != v.end(); )
>     if (*it == target) it = v.erase(it); else ++it;
> // 写法2：erase-remove 惯用法
> v.erase(std::remove(v.begin(), v.end(), target), v.end());
> // 写法3（C++20）：
> std::erase(v, target);
> ```
> 62. (a) `push_back` **未扩容**：尾后迭代器 `end()` 失效，其余元素引用/迭代器仍有效；(b) **触发扩容**：全部迭代器/指针/引用失效；(c) `clear()`：全部失效（元素已销毁）；(d) 中间 `erase(it)`：被删点及其**之后**的迭代器失效，之前的仍有效。
> 63. **不 reserve + push_back(临时对象)**：每个元素先构造临时 `Student`，再拷贝/移动进容器；且容量从 0 起多次翻倍扩容，每次重分配并搬移已有元素（额外多次拷贝/移动）。**reserve + emplace_back**：一次性分配足量内存（**0 次中途扩容**），每个元素在容器内**原地构造**（无临时对象、无额外拷贝）。差异：后者省去 N 次临时构造+拷贝、省去 log₂N 次扩容搬移，对重构造对象提升显著。

## 十二、内存布局画图专项

**64.** 用 ASCII 画出局部变量 `std::vector<int> v{1,2,3};` 在 `reserve(5)` 后的内存模型：标出栈上的三个管理指针（`start`/`finish`/`end_of_storage`）与堆上元素的对应关系，并写出此时的 `size` 与 `capacity`。

> [!success]- 参考答案（第十二节）
> 64.
> ```text
> 栈上：vector 对象 v
> ┌──────────────────────┐
> │ start          ──────┼──┐
> │ finish         ──────┼──┼────┐
> │ end_of_storage ──────┼──┼────┼──────┐
> └──────────────────────┘  │    │      │
>                           ↓    ↓      ↓
> 堆上：（reserve(5) 已分配 5 格容量，仅前 3 格是有效元素）
> ┌────┬────┬────┬────┬────┐
> │ 1  │ 2  │ 3  │    │    │
> └────┴────┴────┴────┴────┘
>  ↑              ↑         ↑
> start        finish   end_of_storage
> ```
> `size = finish - start = 3`；`capacity = end_of_storage - start = 5`。
> 要点：对象（3 个指针）在栈、元素在堆；后两格是预留容量，**未构造、不可访问**；`reserve` 只移动了 `end_of_storage`，没动 `finish`，所以 size 不变。

## 一、选择题（概念基础）

**1.** 关于关系运算符的返回类型，下列说法正确的是：
- A. 返回 `int`，`1` 或 `0`　　B. 返回 `bool`，`true` 或 `false`　　C. 返回比较的较大值　　D. 返回 `void`

**2.** 表达式 `a < b == c`（`a=5, b=10, c=5`）的求值结果是：
- A. `true`　　B. `false`　　C. 编译错误　　D. 未定义行为

**3.** 下列哪种比较两个浮点数是否相等的方式最可靠？
- A. `a == b`　　B. `a - b == 0`　　C. `abs(a - b) < epsilon`　　D. `(int)a == (int)b`

**4.** 对于 C 风格字符串 `char s1[]="hi", s2[]="hi";`，`s1 == s2` 比较的是：
- A. 字符串内容，结果 `true`　　B. 字符串长度　　C. 两个数组的首地址，结果 `false`　　D. 编译错误

**5.** 条件运算符 `?:` 在 C++ 中的优先级：
- A. 高于算术运算符　　B. 高于关系运算符　　C. 仅高于赋值和逗号运算符　　D. 最高

**6.** `auto r = (a > 5) ? a : b;`，其中 `int a; double b;`，则 `r` 的类型是：
- A. `int`　　B. `double`　　C. `auto` 推导失败编译错误　　D. 取决于运行期 `a` 的值

**7.** 下列关于条件运算符作左值的说法，正确的是：
- A. C++ 中 `?:` 永远不能作左值　　B. 只有两个分支都是左值时，`?:` 结果才能作左值　　C. `?:` 结果总能作左值　　D. 只有第一个分支是左值即可

**8.** `std::bitset<8> b(42);` 后输出 `b`，结果是：
- A. `42`　　B. `00101010`　　C. `01010100`　　D. `00000042`

**9.** `switch` 中某个 `case` 后缺少 `break`，会发生：
- A. 编译错误　　B. 跳到 `default`　　C. case 穿透，继续执行下一个 `case`　　D. 直接结束 `switch`

**10.** C++17 中 `if (int x = f(); x > 0) {...}` 里变量 `x` 的作用域是：
- A. 整个函数　　B. 仅 `if` 的真分支　　C. 整个 `if-else` 结构（含 `else`）　　D. 全局

**11.** 关于右移运算 `>>`，下列说法正确的是：
- A. `int` 和 `unsigned` 右移行为完全相同　　B. 负数 `int` 右移高位补 0　　C. `unsigned` 右移高位补 0，负数 `int` 右移通常补 1　　D. 右移一定等价于乘 2

**12.** 汇编中 `jg` 与 `ja` 的区别是：
- A. 没有区别　　B. `jg` 是无符号比较，`ja` 是有符号比较　　C. `jg` 是有符号大于跳转，`ja` 是无符号大于跳转　　D. `jg` 用于浮点，`ja` 用于整数

> [!success]- 参考答案（第一节）
> 1. **B**。关系运算符返回 `bool`（`true`/`false`）。虽然能隐式转成 `1`/`0`，但本身类型是 `bool`。
> 2. **B**。`<` 优先级高于 `==`，等价于 `(a < b) == c` → `(5<10)==5` → `true==5` → `1==5` → `false`。
> 3. **C**。浮点有精度误差（如 `0.1+0.2 != 0.3`），应判断差值绝对值是否小于一个很小的 `epsilon`。
> 4. **C**。C 风格字符串名退化为首地址，`==` 比较的是两个数组的地址（不同），结果 `false`。比较内容要用 `strcmp`。
> 5. **C**。`?:` 优先级很低，仅高于赋值运算符和逗号运算符，所以 `cout << x > 3 ? ...` 会被错误结合，必须加括号。
> 6. **B**。`?:` 的结果类型由两分支共同决定，`int` 与 `double` 取公共类型 `double`，`int` 被提升为 `double`。
> 7. **B**。C++ 中当两个分支都是左值（且类型一致）时，`?:` 结果是左值，可被赋值，如 `((a>b)?a:b)=100;`。
> 8. **B**。`bitset<8>(42)` 即二进制 `00101010`，输出高位在左。
> 9. **C**。缺 `break` 会 case 穿透，继续执行后续 `case` 直到遇到 `break` 或 `switch` 结束。
> 10. **C**。C++17 的 `if` 初始化语句声明的变量作用域覆盖整个 `if-else` 结构，含 `else` 分支，离开后失效。
> 11. **C**。`unsigned` 逻辑右移高位补 0；`int` 为负时多数平台算术右移补 1（保符号）。这也是位移演示用 `unsigned` 的原因。
> 12. **C**。`jg`（jump if greater）有符号大于跳转；`ja`（jump if above）无符号大于跳转。`switch` 范围检查常用 `ja` 一次排除越界与负数。

## 二、概念辨析（判断对错并说明理由）

**13.** `if (x = 10)` 是一个合法的 C++ 语句，且条件恒为真。

**14.** 关系运算符 `<` 和 `==` 优先级相同。

**15.** 条件运算符 `?:` 是 C++ 中唯一的三元运算符。

**16.** `a ^ a` 的结果是把 `a` 按位取反。

**17.** `std::bitset<N>` 中 `N` 可以是运行期才确定的变量。

**18.** `switch` 的 `case` 标签后可以跟浮点数或字符串字面量作为匹配值。

**19.** `goto` 在现代 C++ 中已被语言移除，不能再使用。

**20.** 当 `case` 值非常分散（如 `1`、`100`、`9999`）时，编译器更倾向于生成跳转表而非链式比较。

> [!success]- 参考答案（第二节）
> 13. **对**。`x = 10` 是赋值表达式，其值为 `10`（非零即真），所以条件恒真。这正是 `=`/`==` 混淆的经典 bug，写 `if (10 == x)` 可让编译器在误写时报错。
> 14. **错**。`<`、`>`、`<=`、`>=` 一组（较高），`==`、`!=` 一组（较低），两组优先级不同。
> 15. **对**。`?:` 是 C++ 唯一的三元运算符，形如 `条件 ? 值1 : 值2`。
> 16. **错**。`a ^ a == 0`（相同为 0，全部抵消），与按位取反 `~a` 完全不同。`~a` 是每位翻转。
> 17. **错**。`bitset<N>` 的 `N` 是模板参数，必须编译期常量确定。运行期大小要用 `vector<bool>` 或动态 `bitset` 替代品。
> 18. **错**。`case` 只能跟整型/枚举等离散的**编译期整型常量**，不能是浮点或字符串。
> 19. **错**。`goto` 仍是合法 C++，只是现代实践中应尽量避免（用循环/函数拆分/异常替代）。
> 20. **错**。值分散时跳转表会浪费大量空间，编译器更可能用链式比较；值紧凑连续时才用跳转表。

## 四、找错与修复（指出 bug 并改正）

**28.**
```cpp
int x = 5;
if (x = 10) {            // 想判断 x 是否等于 10
    std::cout << "等于10";
}
```

**29.**
```cpp
double a = 0.1 + 0.2, b = 0.3;
if (a == b) {            // 想判断两浮点是否相等
    std::cout << "相等";
}
```

**30.**
```cpp
char str1[] = "hello";
char str2[] = "hello";
if (str1 == str2) {      // 想比较内容
    std::cout << "相等";
}
```

**31.**
```cpp
int a = 5;
std::cout << a > 3 ? "大" : "小";   // 想根据 a 输出大或小
```

**32.**
```cpp
int sId = 666, sPr = 0;
switch (sId) {
    case 666:
        sPr = sId * 2;   // 想让 666 和 321 都走这段，但漏写了
    case 321:
        sPr = sId * 2;
        break;
    default:
        sPr = 0;
}
// 期望 case 666 直接复用 321 的逻辑
```

**33.**
```cpp
// 用 C 风格实现"两数取较大值并打印二进制"
int a = 42, b = 17;
int max = a > b ? a : b;
char buf[33];
for (int i = 31; i >= 0; --i) buf[31 - i] = ((max >> i) & 1) + '0';
buf[32] = '\0';
printf("%s\n", buf);
// 要求：用 Modern C++ 重写
```

> [!success]- 参考答案（第四节）
> 28. **`=`/`==` 混淆**：`x = 10` 是赋值，恒为真。修复：`if (x == 10)`，或写 `if (10 == x)` 让编译器在误写时报错。
> 29. **浮点直接比较**：精度误差使 `a != b`。修复：`if (std::abs(a - b) < 1e-9)`（需 `<cmath>`）。
> 30. **比较地址而非内容**：数组名退化为地址。修复：用 `std::strcmp(str1, str2) == 0`；更 Modern 的做法是改用 `std::string` 后直接 `s1 == s2`。
> 31. **`?:` 优先级太低 + `<<` 结合错误**：实际被解析为 `(std::cout << a) > 3 ? ...`，编译/逻辑错误。修复：`std::cout << (a > 3 ? "大" : "小");`。
> 32. **缺 `[[fallthrough]]` 语义不清 + 重复代码**：原意是 `case 666` 穿透到 `case 321`。修复：去掉 `666` 内的语句，用 `case 666: [[fallthrough]]; case 321: sPr = sId*2; break;`，让两者共享逻辑且消除编译器穿透警告。
> 33. **C 风格数组 + 手写位提取**。Modern 重写：
> ```cpp
> #include <bitset>
> #include <iostream>
> #include <algorithm>
>
> int a = 42, b = 17;
> int max = std::max(a, b);              // 用标准算法
> std::cout << std::bitset<32>(max) << '\n';   // bitset 直接输出二进制
> ```
> 要点：`std::max` 取代三元、`std::bitset` 取代手写循环与 C 数组，无裸数组、无 `printf`。

## 五、简答题

**34.** 为什么浮点数不能直接用 `==` 比较？正确做法是什么？

**35.** 条件运算符 `?:` 和 `if-else` 有什么本质区别？各适合什么场景？

**36.** 异或运算有哪两条关键性质？为什么这两条性质能用来做"防作弊还原"？

**37.** 位移演示中为什么右移要用 `unsigned` 而不用 `int`？

**38.** `switch` 中 `break`、`default`、case 穿透分别是什么作用？

**39.** C++17 给 `if`/`switch` 增加的"初始化语句"语法解决了什么问题？

> [!success]- 参考答案（第五节）
> 34. 浮点采用二进制有限位表示，很多十进制小数（如 `0.1`）无法精确表示，运算后存在舍入误差，`0.1+0.2` 不严格等于 `0.3`。正确做法：判断差的绝对值小于一个很小的 `epsilon`（如 `std::abs(a-b) < 1e-9`）。
> 35. `?:` 是**表达式**，有返回值，可直接用于赋值/初始化；`if-else` 是**语句**，无返回值。`?:` 适合简单二选一赋值，简洁；`if-else` 适合复杂逻辑和多层嵌套，可读性好。超过两层嵌套的 `?:` 应改 `if-else`。
> 36. 两条性质：① `a ^ a == 0`（自身异或抵消）；② `a ^ 0 == a`（与 0 异或不变）。由此 `(a ^ b) ^ b = a ^ (b ^ b) = a ^ 0 = a`，可在不存储原值的情况下用校验码 `xbase = a ^ b` 还原 `a`，篡改 `a` 后用 `xbase ^ b` 即可恢复原始值。
> 37. 右移对 `unsigned` 是逻辑右移，高位恒补 0，行为确定；对负 `int` 多数平台是算术右移补 1（保符号），且符号位语义会干扰"纯位模式"演示。用 `unsigned` 能稳定看到"高位补 0"的效果，行为可移植可预测。
> 38. `break`：结束当前 `switch`，防止继续执行后续 `case`；`default`：没有任何 `case` 匹配时的兜底分支；case 穿透：某 `case` 无 `break` 时控制流继续落入下一个 `case`（可故意利用，用 `[[fallthrough]]` 标注）。
> 39. 它允许把"只在这个判断里用一次"的临时变量声明限制在 `if`/`switch` 结构内部（含 `else`），离开后即失效，避免污染外层作用域、减少命名冲突和误用，如 `if (auto it = m.find(k); it != m.end()) {...}`。

## 六、综合设计与手写代码

**40.** 写一个函数 `clamp3(int x, int lo, int hi)`，用条件运算符把 `x` 限制在 `[lo, hi]` 区间内并返回。

**41.** 用异或实现一个"不借助临时变量交换两个整数"的函数 `swapXor(int& a, int& b)`，并说明其风险。

**42.** （Modern C++ 重构题）把下面这段"C with Classes"风格的等级判定改写为 Modern C++：
```cpp
char grade[10];
int score = 75;
if (score >= 90) strcpy(grade, "优秀");
else if (score >= 80) strcpy(grade, "良好");
else if (score >= 60) strcpy(grade, "及格");
else strcpy(grade, "不及格");
printf("%s\n", grade);
```

> [!success]- 参考答案（第六节）
> **40.**
> ```cpp
> int clamp3(int x, int lo, int hi) {
>     return (x < lo) ? lo : (x > hi) ? hi : x;
> }
> // 或直接用标准库：return std::clamp(x, lo, hi);  // <algorithm>, C++17
> ```
> 要点：两层 `?:` 已是可读上限，再复杂应改 `if`；生产代码优先 `std::clamp`。
>
> **41.**
> ```cpp
> void swapXor(int& a, int& b) {
>     if (&a == &b) return;     // 关键：自交换会把值清零
>     a ^= b;
>     b ^= a;
>     a ^= b;
> }
> ```
> 风险：当 `a` 与 `b` 是**同一变量**（地址相同）时，`a ^= a` 会把它清成 0，必须先判等。实践中应直接用 `std::swap`，可读性和正确性都更好，异或交换只是异或性质的演示。
>
> **42.**
> ```cpp
> #include <string>
> #include <iostream>
>
> int score = 75;
> std::string grade = (score >= 90) ? "优秀" :
>                     (score >= 80) ? "良好" :
>                     (score >= 60) ? "及格" : "不及格";
> std::cout << grade << '\n';
> ```
> 要点：`std::string` 取代 C 数组 + `strcpy`，消除缓冲区溢出风险；用链式 `?:` 或 `if-else` 均可，无裸数组、无 `printf`。

## 七、简答深化题

**43.** 从汇编层面解释：一条 `if (a > b) {...}`（无 `else`）是如何被翻译成 `cmp + 条件跳转`的？为什么跳转用的是"反条件"`jle`？

**44.** `switch` 的"跳转表"和"链式比较"两种底层实现各自的时间/空间权衡是什么？编译器如何选择？

**45.** 在 `switch` 跳转表的范围检查里，为什么用 `ja default` 一条指令就能同时排除 `x > 上界` 和 `x < 0`？（结合补码与无符号解释）

**46.** （跨章综合）结合[[3.1 关系运算符]]与字符串知识，说明为什么 C 风格字符串用 `==` 比较是 bug，而 `std::string` 可以直接 `==`？这背后涉及什么 C++ 机制？

**47.** 条件运算符的返回类型是如何确定的？当两分支类型不同时会发生什么？给出一个会"意外提升类型"的例子。

> [!success]- 参考答案（第七节）
> 43. 先 `mov eax,[a]` 取 `a`，`cmp eax,[b]` 做比较（实质是 `a-b` 并设置标志位），然后 `jle end_if`：若 `a <= b` 直接跳过 `if` 体。用反条件是因为汇编的自然结构是"条件不满足就跳过代码块"——C++ 判断 `a > b`，跳过时判断它的反面 `a <= b`，落到 `if` 体反而是"条件成立"的顺序执行路径，省一次无条件跳转。
> 44. **跳转表**：`O(1)` 查表跳转，速度快，但需要一块连续地址数组，`case` 值稀疏时浪费大量空间；适合值紧凑连续。**链式比较**：逐个 `cmp+je`，`O(n)` 比较，省空间，但 `case` 多时慢；适合值分散。编译器据 `case` 值的密度/范围自动选择，甚至混合使用。
> 45. 先 `sub` 把下标归一化到 `[0, 上界]`。负数 `x`（如 `-1` = `0xFFFFFFFF`）在无符号视角下是极大值 `4294967295`，必然 `> 上界`；正常越界 `x > 上界` 也 `> 上界`。`ja`（无符号大于）于是一次性把"负数"和"超上界"都判为越界跳 `default`，省去对下界单独比较。
> 46. C 风格字符串是 `char[]`/`char*`，`==` 比较的是**指针/地址**而非内容，地址不同就 `false`，与字符内容无关——必须 `strcmp`。`std::string` 是类类型，**重载了 `operator==`**，会逐字符比较内容。背后机制是**运算符重载**：内置类型 `==` 行为固定，而类可自定义比较语义。
> 47. 返回类型由两分支按"公共类型/隐式转换规则"统一确定。当类型不同会发生算术提升或转换：如 `(cond) ? intVal : doubleVal` 整体类型为 `double`，`int` 分支被提升——即便条件取了 `int` 分支，结果仍是 `double`。若两分支无法找到公共类型（如 `const char*` 与 `int`）则编译失败。

## 八、概念辨析进阶

**48.** 辨析 `=` / `==` / `^=`。

**49.** 辨析 `~`（按位取反）/ `!`（逻辑非）/ `^`（异或）。

**50.** 辨析 `<<` 作为"左移运算符" / 作为"流插入运算符"两种身份。

**51.** 辨析 `jg` / `ja` / `jl` / `jb`。

> [!success]- 参考答案（第八节）
> 48. `=` 赋值（把右值写入左值，表达式值为被赋的值）；`==` 相等比较（返回 `bool`）；`^=` 复合异或赋值（`a ^= b` 等价 `a = a ^ b`）。口诀：一个等号是"给"，两个等号是"问"，带 `^` 是"异或后再给"。
> 49. `~a` 按位取反（逐位 0↔1，作用于整数位模式）；`!a` 逻辑非（`a` 为 0 得 `true`，非 0 得 `false`，作用于布尔语义）；`a ^ b` 按位异或（相同为 0，不同为 1）。口诀：`~` 翻位、`!` 翻真假、`^` 比异同。注意 `~a` ≠ `a ^ a`（后者恒为 0）。
> 50. 同一符号 `<<`：操作数是**整数**时是左移（`x << 2` 即乘 4）；左操作数是**流对象**（如 `std::cout`）时是流插入运算符（`std::ostream` 重载了 `operator<<`）。这是运算符重载带来的"一符两义"，由操作数类型决定。
> 51. 都是条件跳转：`jg` 有符号大于、`ja` 无符号大于（above）、`jl` 有符号小于、`jb` 无符号小于（below）。口诀：`g/l` 看符号（signed），`a/b` 不看符号（unsigned，above/below）。比较 `int` 用 `g/l`，比较地址/下标/无符号用 `a/b`。

## 九、大厂面试场景题 / 八股常考

**52.** 面试官给你一段代码：`if (flag = checkStatus())`，问"这段代码有没有问题，编译器为什么大多不报错，如何排查这类 bug？"

**53.** 一个 `switch` 处理上千个枚举值，有同事担心"分支太多会很慢"。请从底层解释 `switch` 是否真的随分支数线性变慢，并给出优化判断。

**54.** 线上代码用 `float` 累加金额后 `if (total == expected)` 做对账，偶发对不上。定位原因并给修复方案。

**55.** 一段位标志代码 `flags = flags ^ MASK` 本想"设置某标志位"，结果反复调用后标志位时有时无。诊断问题并给正确写法。

**56.** 用一行表达式判断"整数 `n` 是否为 2 的幂"，并解释原理（结合位运算）。

> [!success]- 参考答案（第九节）
> 52. **现象**：`flag = checkStatus()` 是赋值非比较，条件恒取赋值结果的真假，逻辑可能与预期不符。**原因**：`=` 在条件中合法（赋值表达式有值），编译器默认不报错；部分编译器开 `-Wparentheses` 会警告。**解决**：开启 `-Wall -Wparentheses` 警告并视为错误；约定常量左置 `if (X == flag)`；用 `static analyzer`/clang-tidy。**延伸**：现代写法 `if (auto flag = checkStatus(); flag) {...}` 显式分离赋值与判断。
> 53. **现象**：担心 `O(n)` 分支。**原因**：若 `case` 值紧凑，编译器生成**跳转表**，查表跳转是 `O(1)`，与分支数无关；只有值极度稀疏才退化为链式比较 `O(n)`（或编译器用二分，`O(log n)`）。**解决**：让枚举值连续紧凑以触发跳转表；必要时查看汇编/`-S` 确认。**延伸**：热点路径上紧凑 `switch` 通常优于一长串 `if-else if`。
> 54. **现象**：浮点对账偶发不等。**原因**：`float` 精度有限，累加产生舍入误差，`==` 严格相等几乎必然偶发失败。**解决**：① 比较改 `std::abs(total-expected) < eps`；② 更根本——金额改用**整数分**（如以"分"为单位的 `long long`）或定点/十进制类型，彻底避免二进制浮点误差。**延伸**：金融场景禁用浮点等值判断。
> 55. **现象**：`^` 是**翻转**该位，不是置位，奇数次调用置 1、偶数次又清 0。**原因**：混淆了"异或翻转"与"或置位"。**解决**：置位用 `flags |= MASK`；清位用 `flags &= ~MASK`；测试用 `flags & MASK`；翻转才用 `flags ^= MASK`。**延伸**：`~` 取反生成清位掩码是常见配套技巧。
> 56. `bool isPow2 = (n > 0) && ((n & (n - 1)) == 0);`。**原理**：2 的幂二进制只有一个 1（如 `1000`），`n-1` 把该位变 0、低位全变 1（`0111`），二者相与为 0；需额外 `n > 0` 排除 0 与负数。

## 十、补充加分题

**57.** `a <<= 8` 与 `a *= 256` 对 `int` 是否总是等价？从溢出/符号角度分析何时不等价。

**58.** 解释 `xbase = diamond ^ vip_exp` 防作弊方案的局限：若攻击者能读到内存，方案为何失效？给出一个改进方向。

**59.** （复杂度/性能分析题）对 1000 个稀疏枚举值，比较"链式 `if-else if`"与"`std::unordered_map<int, 函数>`分派"在时间复杂度、缓存局部性、常数因子上的差异，并给选型建议。

**60.** `bitset<32>` 与 `std::vector<bool>` 在内存表示、大小确定时机、位运算支持上有何区别？各适合什么场景？

> [!success]- 参考答案（第十节）
> 57. 不总是等价。数学上左移 1 位 = 乘 2，`<<8` = 乘 256。但：① 若结果**溢出** `int` 范围，二者都是 UB/实现定义，可能不同；② 对**负数** `int` 左移在 C++20 前是未定义/实现定义行为，而 `*256` 是算术运算，语义不同。安全做法：位移只对 `unsigned` 用，乘法表达数值意图。
> 58. 局限：`xbase` 本身存在内存中，攻击者读到内存就能同时改 `diamond`、`vip_exp` 并重算 `xbase`，校验形同虚设；它只能防"改了值但没改校验码"的低级修改。改进方向：校验码放**服务端**（不可信客户端不存校验逻辑）、加盐/加密、用 HMAC、关键数据服务端权威化——本质是"不信任客户端内存"。
> 59. **链式 `if-else if`**：最坏 `O(n)=1000` 次比较，但代码连续、分支预测对热点值友好、常数极小；稀疏值且热点集中时实际很快。**`unordered_map` 分派**：平均 `O(1)` 查找，但有哈希计算、指针跳转、缓存不友好（散列桶分散），常数大、有内存开销。**选型**：值少或热点集中 → `if-else`/`switch`；值多、均匀、动态可变 → `unordered_map`；编译期已知且较紧凑 → 让编译器生成跳转表的 `switch` 往往最优。
> 60. `bitset<32>`：大小**编译期**固定（模板参数），每位约 1 bit 物理内存，直接支持 `& | ^ ~ << >>` 及 `count/test/flip` 等成员函数，适合固定宽度位标志/掩码。`vector<bool>`：大小**运行期**可变，是特化的位压缩容器（非真正 `bool` 数组），支持动态增删但位运算支持弱、有代理引用的坑。选型：宽度固定且需位运算 → `bitset`；长度运行期才定且需增长 → `vector<bool>`（或考虑 `vector<char>` 避坑）。

## 十一、位运算专项

**61.** 计算下列各式（`a = 0b1010`，4 位）：`~a`、`a ^ a`、`a ^ 0`、`a & 0`、`a | 0`。

**62.** 用位运算写出三个宏/常量操作：把第 `k` 位**置 1**、**清 0**、**测试是否为 1**。

**63.** 下面代码想"取出一个 16 位数的高 8 位"，补全表达式：
```cpp
unsigned short v = 0xABCD;
unsigned hi = /* ? */;   // 期望得到 0xAB
```

**64.** 解释 `a ^ b ^ b == a` 为什么成立，并说明它和"异或加解密 `c = a ^ key`"的关系。

> [!success]- 参考答案（第十一节）
> 61. `~a = 0b0101`（每位翻转）；`a ^ a = 0b0000`（相同抵消）；`a ^ 0 = 0b1010`（与 0 异或不变）；`a & 0 = 0b0000`（与 0 相与清零）；`a | 0 = 0b1010`（与 0 相或不变）。
> 62. 置 1：`x |= (1u << k);`　清 0：`x &= ~(1u << k);`　测试：`bool on = (x >> k) & 1u;`（或 `x & (1u << k)`）。注意移位用 `unsigned` 常量 `1u` 避免符号问题。
> 63. `unsigned hi = (v >> 8) & 0xFF;`。右移 8 位把高字节挪到低位，再 `& 0xFF` 掩掉其余位，得 `0xAB`。
> 64. 因为 `^` 满足结合律且 `b ^ b = 0`、`a ^ 0 = a`，故 `a ^ b ^ b = a ^ (b ^ b) = a ^ 0 = a`。加解密正是此性质：密文 `c = a ^ key`，解密 `c ^ key = a ^ key ^ key = a`，同一个 `key` 异或两次即还原明文。

## 十二、底层汇编专项

**65.** 把下面 C++ 翻译成 `cmp + 条件跳转` 的汇编思路（伪汇编即可）：
```cpp
if (a >= b) { x = 1; } else { x = 2; }
```

**66.** 给定汇编片段，写出等价的 C++ 判断：
```asm
cmp eax, ebx
je  same
jg  greater
jl  less
```

**67.** `switch (x)` 中 `case` 为 `1,2,3,4`，编译器生成跳转表。解释 `sub eax, 1` 这一步的作用，以及 `jmp [jump_table + eax*4]` 为什么乘 4。

**68.** 为什么 `switch` 跳转表的范围检查里，对负数也能用一条无符号比较 `ja` 排除？请用 `-1` 的补码举例。

> [!success]- 参考答案（第十二节）
> 65.
> ```asm
> mov eax, [a]
> cmp eax, [b]
> jl  else_block      ; a < b（即 a>=b 不成立）跳 else
> mov [x], 1          ; if 体
> jmp end_if
> else_block:
> mov [x], 2          ; else 体
> end_if:
> ```
> 要点：用反条件 `jl` 跳过 `if` 体，`if` 体末尾 `jmp end_if` 跳过 `else`。
> 66.
> ```cpp
> if (eax == ebx) goto same;
> if (eax >  ebx) goto greater;
> if (eax <  ebx) goto less;
> ```
> `je/jg/jl` 分别对应 `==`、有符号 `>`、有符号 `<`。
> 67. `sub eax, 1` 把 `case` 值（`1..4`）归一化成数组下标（`0..3`），因为跳转表按 0 起始下标存放。乘 4 是因为示例中每个跳转表项是 32 位地址 = 4 字节，`eax*4` 才能定位到第 `eax` 个表项的字节偏移（64 位环境地址 8 字节则乘 8，重点是"下标 × 项大小"）。
> 68. `-1` 的 32 位补码是 `0xFFFFFFFF`，无符号解释为 `4294967295`，远大于上界。范围检查 `sub` 归一化后做 `cmp eax, 上界; ja default`，`ja` 是无符号比较，负数被看成极大值必然 `> 上界` 跳 `default`，正向越界也 `> 上界`，于是一条 `ja` 同时排除"负下标"和"超上界"，省掉单独的下界比较。

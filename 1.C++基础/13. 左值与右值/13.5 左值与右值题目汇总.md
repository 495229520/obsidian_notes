## 一、选择题（概念基础）

**1.** C++11 值类别体系中，`glvalue`（广义左值）等于：
- A. lvalue + prvalue　　B. lvalue + xvalue　　C. prvalue + xvalue　　D. 只有 xvalue

**2.** `rvalue`（右值）等于：
- A. lvalue + xvalue　　B. 只有 prvalue　　C. prvalue + xvalue　　D. lvalue + prvalue

**3.** 下列表达式中**是左值**的是：
- A. `10`　　B. `x + 1`　　C. 字符串字面量 `"hello"`　　D. `x++`

**4.** `std::move(x)` 这个表达式的值类别是：
- A. lvalue　　B. prvalue　　C. xvalue　　D. 不是表达式

**5.** 字面量 `10` 能被下列哪种引用绑定：
- A. 只有 `int&`　　B. 只有 `int&&`　　C. `int&` 和 `const int&`　　D. `const int&` 和 `int&&`，但 `int&` 不行

**6.** 关于 `int&& r = 10;`，正确的是：
- A. 表达式 `r` 是右值　　B. 表达式 `r` 是左值（有名字、有地址）
- C. `r` 绑定后不能被读取　　D. `10` 是左值

**7.** 模板中 `template<class T> void f(T&& arg)` 里的 `T&&` 叫：
- A. 右值引用　　B. 转发引用（万能引用）　　C. `const` 引用　　D. 左值引用

**8.** 引用折叠规则下，`int& &&` 折叠为：
- A. `int&`　　B. `int&&`　　C. `int`　　D. 编译错误

**9.** 完美转发中，保持参数原始值类别要用：
- A. `std::move`　　B. `std::forward`　　C. `static_cast`　　D. `std::ref`

**10.** 移动构造/移动赋值应标 `noexcept` 的主要原因是：
- A. 提高编译速度　　B. 否则 `std::vector` 扩容时会退回用拷贝以保证异常安全
- C. 语法强制要求　　D. 防止内存泄漏

**11.** `const int& cref = 10;` 在底层发生了什么：
- A. 直接绑定字面量 `10`　　B. 编译器创建临时对象，`cref` 绑定它并延长其生命周期
- C. 编译错误　　D. 把 `10` 拷进 `cref` 自己的存储

**12.** `std::move` 实际做的事情是：
- A. 移动对象的数据　　B. 释放对象内存　　C. 把左值转换成右值引用（不移动任何数据）　　D. 深拷贝对象

> [!success]- 参考答案（第一节）
> 1. **B**。`glvalue = lvalue + xvalue`（都"有身份/可定位"）。
> 2. **C**。`rvalue = prvalue + xvalue`（都"可被移动"）。记忆：xvalue 同时属于 glvalue 和 rvalue，是两者的交集。
> 3. **C**。字符串字面量存在静态区、是 `const char[N]` 类型的**左值**，可取地址。`10`/`x+1` 是 prvalue，`x++` 返回旧值副本是 prvalue。
> 4. **C**。`std::move(x)` 把左值转成将亡值（**xvalue**），它属于 rvalue，可被移动构造/赋值"窃取"。
> 5. **D**。`int&`（非 const 左值引用）不能绑右值；`const int&` 可绑右值（建临时对象）；`int&&` 专门绑右值。
> 6. **B**。"具名右值引用是左值"——`r` 有名字有地址，作为表达式是左值。这正是完美转发必须用 `std::forward` 的根源（见第 34、42 题）。
> 7. **B**。发生类型推导的 `T&&` 是转发引用（万能引用），能接左值也能接右值；非推导场景的 `MyString&&` 才是普通右值引用。
> 8. **A**。引用折叠口诀："**只要有 `&` 就是 `&`，只有 `&&`+`&&` 才是 `&&`**"。故 `int& &&` → `int&`。
> 9. **B**。`std::forward<T>(arg)` 按 `T` 恢复原值类别；`std::move` 是无条件转成右值。
> 10. **B**。`std::vector` 扩容时若元素的移动构造不是 `noexcept`，为保证强异常安全会**退回用拷贝**，性能大打折扣。
> 11. **B**。`const T&` 绑右值时，编译器生成一个临时对象保存该值，引用绑定它，且**临时对象生命周期延长到引用的生命周期**。
> 12. **C**。`std::move` 本质是 `static_cast<T&&>`，只改变值类别、**不搬运数据**；真正的搬运发生在移动构造/移动赋值里。

## 二、概念辨析（判断对错并说明理由）

**13.** 字符串字面量 `"hello"` 是右值。

**14.** 后置递增 `x++` 返回左值，可以对它取地址。

**15.** `std::move(obj)` 这一步就会把 `obj` 的数据搬走。

**16.** `int&& r = 10;` 之后，表达式 `r` 是右值。

**17.** `const` 左值引用不能绑定右值。

**18.** 移动构造里把源对象 `data` 置为 `nullptr` 后，源对象就变成了悬空指针。

**19.** 模板里所有的 `T&&` 都是右值引用，只能接收右值。

**20.** `decltype(x)` 和 `decltype((x))` 的结果相同。

**21.** 被移动后的对象不能再使用，碰它就是未定义行为。

> [!success]- 参考答案（第二节）
> 13. **错**。字符串字面量是**左值**（存于静态区、`const char[]` 类型、可取地址）。这是字面量里的特例——非字符串字面量（`10`/`3.14`/`true`）才是 prvalue。
> 14. **错**。`x++` 返回的是递增前的**副本（临时对象）**，是右值，不能取地址；`++x` 返回 `x` 本身的引用才是左值。
> 15. **错**。`std::move` 只是**转换值类别**（`static_cast` 到右值引用），不搬数据。只有当这个右值被传给移动构造/移动赋值时，资源才真正被窃取。
> 16. **错**。`r` 有名字有地址，作为表达式是**左值**。"右值引用"指的是 `r` 能绑定到右值，不是说 `r` 本身是右值。
> 17. **错**。`const T&` **可以**绑右值（编译器建临时对象并延长其生命周期），这正是它成为最通用只读参数的原因。
> 18. **错**。置空后是**空指针（nullptr）**，不是悬空指针。置空恰恰是为了**避免**悬空指针和 double free——源对象进入"有效但未定义"状态，可安全析构。
> 19. **错**。只有**发生类型推导**的 `T&&`（转发引用）能接左值和右值；普通函数参数 `MyString&& x` 是右值引用，只接右值。
> 20. **错**。`decltype(x)` 是 `int`（裸变量名）；`decltype((x))` 是 `int&`（带括号是左值表达式，推导出左值引用）。
> 21. **错**。被移动对象处于**"有效但未定义"**状态：可以重新赋值、可以安全析构，只是不应假设其当前值。不是不能碰，是不能依赖其值。

> [!success]- 参考答案（第三节）
> 22. 输出 `LRR`。`a` 是左值→`int&`；`20` 是 prvalue→`int&&`；`std::move(a)` 是 xvalue→`int&&`。
> 23. 输出 `1233`。`str` 非 const 左值→`T&`；`cstr` const 左值→`const T&`；`"world"` 转临时 `string` 是右值→`T&&`；`std::move(str)` 是右值→`T&&`。

> 27. 输出 `10 11`。`++x` 是左值：`++x = 10` 先让 `x` 变 6 再被赋值为 10（`x=10`）；`&(++x)` 中 `++x` 让 `x` 变 11 并返回 `x` 的引用，`p` 指向 `x`，`*p == 11`。
> 28. 输出 `8`。`5 + 3` 是右值，`const int&` 绑定时建临时对象存 `8` 并延长其生命周期，`r` 读到 `8`。
> 29. 依次输出 `拷贝构造`、`移动构造`。`(1)` 中 `s1` 是左值→拷贝构造；`(2)` 中 `std::move(s1)` 是右值→移动构造。

**35.** 用 Modern C++（Rule of Zero）重写下面这个手写五法则的类：
```cpp
class Buffer {
    int* data;
    size_t n;
public:
    Buffer(size_t n) : data(new int[n]), n(n) {}
    Buffer(const Buffer& o) : data(new int[o.n]), n(o.n) {
        std::copy(o.data, o.data + n, data);
    }
    Buffer(Buffer&& o) noexcept : data(o.data), n(o.n) { o.data = nullptr; o.n = 0; }
    ~Buffer() { delete[] data; }
    // 还需手写两个赋值运算符……
};
```

> [!success]- 参考答案（第四节）
> 30. **bug 类型**：返回局部变量引用 → **悬空引用**。`local` 在函数返回后销毁，`ref` 指向已失效内存，读取是 UB。修复：**按值返回**。
>     ```cpp
>     int dangerous() { int local = 10; return local; }   // 返回副本，安全
>     ```
> 31. **bug 类型**：右值引用不能绑定左值，**编译错误**。修复（按意图选其一）：
>     ```cpp
>     int&& r = std::move(x);   // 想转成右值
>     int&  r = x;              // 只是想取别名
>     const int& r = x;         // 只读别名
>     ```
> 32. **bug 类型**：移动构造**未置空源对象** → 新旧对象 `data` 指向同一块堆内存，析构时 **double free**，且一方先析构后另一方变悬空指针。修复：
>     ```cpp
>     MyString(MyString&& o) noexcept : data(o.data), len(o.len) {
>         o.data = nullptr; o.len = 0;   // 关键：置空源对象
>     }
>     ```
> 33. **bug 类型**：对 **const 对象 `std::move`** 失效。`std::move(s)` 得到 `const std::string&&`，移动构造形参是 `string&&` 无法绑定 const 右值，于是**静默退回调用拷贝构造**（`const string&` 能绑），没有发生移动。修复：移动的对象不要加 `const`；若必须 const 就接受这是拷贝。
> 34. **bug 类型**：完美转发漏掉 `std::forward`。`arg` 是具名变量→左值，右值实参也会走左值路径，**丢失值类别**（多一次拷贝）。修复：
>     ```cpp
>     process(std::forward<T>(arg));
>     ```
> 35. **Rule of Zero**：用能自管理资源的成员（`std::vector`）替换裸指针，则拷贝/移动/析构全部**由编译器自动正确生成**，五个特殊函数一个都不用写：
>     ```cpp
>     class Buffer {
>         std::vector<int> data;
>     public:
>         explicit Buffer(std::size_t n) : data(n) {}
>         // 拷贝、移动、析构均自动生成且正确
>     };
>     ```
>     要点：优先让资源管理下沉到 `std::vector`/`std::string`/智能指针，自己别碰 `new/delete`。

## 五、简答题

**36.** 什么是左值、右值、将亡值（xvalue）？三者在值类别体系里是什么关系？

**37.** `std::move` 到底做了什么？它会移动数据吗？

**38.** 为什么需要移动语义？它解决了什么性能问题？

**39.** 为什么 `const T&` 是最通用的只读参数形式？

**40.** 移动构造/移动赋值为什么要标 `noexcept`？不标会怎样？

**41.** 什么是完美转发？为什么单有 `T&&` 还不够、必须配 `std::forward`？

**42.** 为什么说"具名的右值引用变量本身是左值"？这带来什么后果？

> [!success]- 参考答案（第五节）
> 36. **左值（lvalue）**：有持久身份、可取地址、能放赋值号左边的对象（变量名、`arr[i]`、`*p`、`++x`、字符串字面量）。**右值（rvalue）**：临时、无持久地址的值，含 **prvalue**（字面量、算术结果、按值返回、`x++`）和 **xvalue**（将亡值）。**将亡值（xvalue）**：即将被移动的对象，由 `std::move`、按右值引用返回等产生。关系：`glvalue = lvalue + xvalue`，`rvalue = prvalue + xvalue`，xvalue 是二者交集。
> 37. `std::move` 只是把实参**无条件转换成右值引用**（`static_cast<T&&>`），本身**不搬运任何数据**。它的作用是"给编译器开绿灯"，让后续能选中移动构造/移动赋值，真正的资源窃取发生在那里。
> 38. 对持有堆资源的对象（`vector`/`string` 等），拷贝要**深拷贝**全部元素（O(n)、额外分配）。移动语义让"即将销毁的临时对象"把资源**指针直接交接**给新对象（O(1)、不分配），源对象置空。典型收益：函数按值返回大对象、容器扩容/插入临时对象时避免昂贵深拷贝。
> 39. 因为 `const T&`：① **避免拷贝**（不复制大对象）；② **接受范围最广**（左值、右值都能绑，右值会建临时对象延长生命周期）；③ **语义明确**（承诺不修改实参）。所以它是只读传参的默认选择。
> 40. STL 容器（如 `std::vector`）在**扩容搬迁元素**时，若元素移动构造是 `noexcept` 就用移动（快）；若不是，为保证**强异常安全**（搬到一半抛异常能回滚）会**退回用拷贝**（慢）。不标 `noexcept` 等于把移动优化拱手让出。
> 41. 完美转发 = 中间层接住参数后，转交给下一层时**仍保留它原本的左值/右值身份**。单有 `T&&`（转发引用）只解决"能接住左右值"；但进入函数后 `arg` 是具名变量→左值，直接转发会把右值降级成左值。`std::forward<T>(arg)` 依据推导出的 `T` **还原**原值类别，二者配合才叫"完美"。口诀：`T&&` 负责接，`std::forward` 负责按原样转出。
> 42. 因为它**有名字、有地址**——值类别的判定看"表达式"而非"声明类型"。后果：在模板/包装层里直接用这个变量名会被当左值，导致移动语义失效，所以必须用 `std::forward`（转发场景）或 `std::move`（确定要移动的场景）显式恢复右值身份。

>     std::size_t len{ 0 };
> public:
>     MyString(MyString&& o) noexcept : data(o.data), len(o.len) {
>         o.data = nullptr; o.len = 0;            // 交接所有权 + 置空源
>     }
>     MyString& operator=(MyString&& o) noexcept {
>         if (this != &o) {                        // 防自赋值
>             delete[] data;                       // 先释放自身资源
>             data = o.data; len = o.len;          // 窃取
>             o.data = nullptr; o.len = 0;         // 置空源
>         }
>         return *this;
>     }
>     ~MyString() { delete[] data; }
> };
> ```
> （教学演示用裸指针；工程上应优先 `std::string`/`std::vector` 走 Rule of Zero。）
>
> **44.**
> ```cpp
> template<class T, class... Args>
> T create(Args&&... args) {
>     return T(std::forward<Args>(args)...);   // 变长完美转发
> }
> ```
> 要点：`Args&&...` 是转发引用包，`std::forward<Args>(args)...` 保持每个参数的值类别。
>
> **45.**
> ```cpp
> // 写法一：两个重载（拷贝 / 移动各一条最优路径）
> void setName(const std::string& n) { name = n; }            // 左值：拷贝
> void setName(std::string&& n) { name = std::move(n); }      // 右值：移动
>
> // 写法二：值传递 + move（一条函数，代码少）
> void setName(std::string n) { name = std::move(n); }
> ```
> 取舍：写法一对左值/右值都走**最优路径**、零多余构造，但代码翻倍；写法二只写一份，左值多一次拷贝构造、右值多一次移动构造（通常可接受）。**热路径/大量调用**选写法一，**普通场景**选写法二。
>
> **46.** 用 `std::unique_ptr` 接管资源，析构/移动自动正确，拷贝按需自定义（或直接禁用）：
> ```cpp
> class Holder {
>     std::unique_ptr<int> p{ std::make_unique<int>(0) };
> public:
>     Holder() = default;
>     Holder(const Holder& o) : p(std::make_unique<int>(*o.p)) {}   // 需要深拷贝才写
>     Holder(Holder&&) noexcept = default;                          // 移动自动正确
>     int* get() const { return p.get(); }                         // nullptr 判断多余
> };
> ```
> 要点：`new/delete`→`make_unique`、`NULL`→`nullptr`、析构和移动交给 `unique_ptr`。
>
> **47.**
> ```cpp
> template<class T>
> void swap(T& a, T& b) noexcept {
>     T tmp = std::move(a);   // 移动，不拷贝
>     a = std::move(b);
>     b = std::move(tmp);
> }
> ```
> 为什么快：三步都是**移动**（O(1) 交接资源指针），而朴素的"`tmp=a; a=b; b=tmp;`"是三次**深拷贝**（O(n) + 多次分配）。`std::swap` 正是这样实现的。

## 七、简答深化题

**48.** 引用折叠规则是什么？转发引用 `T&&` 在分别传入左值/右值时，`T` 被推导成什么、`arg` 的类型又是什么？

**49.** `const T&` 绑定右值时，那个临时对象的生命周期遵循什么规则？什么时候会"延长"、什么时候不会救你（悬空）？

**50.** 被移动后的对象处于什么状态？为什么标准只规定"有效但未指定"，而不规定具体值？

**51.** **跨章综合题**：`std::unique_ptr` 为什么"只能移动、不能拷贝"？这与右值引用、移动语义、所有权模型有什么关系？（见 [[独享智能指针]]）

**52.** 右值引用在底层是怎么实现的？结合 `int&& e = 320 + 230;` 的汇编说明它和指针、左值引用的关系。

**53.** `std::vector::push_back` 为什么要区分 `const T&` 和 `T&&` 两个重载？`emplace_back` 又强在哪？

> [!success]- 参考答案（第七节）
> 48. 引用折叠："只要有 `&` 就折成 `&`，只有 `&&`+`&&` 才是 `&&`"（`T& &`→`T&`、`T& &&`→`T&`、`T&& &`→`T&`、`T&& &&`→`T&&`）。转发引用推导：传**左值** `int` 时 `T=int&`，`arg` 类型 `int& &&`→`int&`；传**右值** `int` 时 `T=int`，`arg` 类型 `int&&`。所以 `T` 是否带 `&` 正好记录了实参的值类别，`std::forward<T>` 据此还原。
> 49. 规则：临时对象的生命周期被**延长到该 const 引用本身的生命周期**——但仅限**直接绑定**的局部 `const T&`。不救你的情况：① 把临时对象绑给引用后**再返回这个引用**（函数结束临时即亡，返回悬空）；② 绑定的是临时对象的**子对象/经函数中转的引用**，延长不传递。一句话：生命周期延长只对"局部直接绑定"成立。
> 50. 状态：**有效但未指定（valid but unspecified）**——对象仍满足类的不变式，可安全析构、可重新赋值，但具体值未规定。原因：移动的目的是**最快地交接资源**，强行规定源对象终值（比如必须清零）会给某些类型带来**额外开销**；标准把"留什么值"的自由留给实现以换取性能。所以使用规范是：移动后只做"重新赋值"或"销毁"，不读其值。
> 51. `unique_ptr` 表达**独占所有权**：同一资源只能有一个拥有者。拷贝会产生两个指向同一资源的指针→重复释放，所以**拷贝构造/拷贝赋值被 `= delete`**；而移动构造/移动赋值保留，接受 `unique_ptr&&`，把裸指针交接给新对象并将源置 `nullptr`。因此转移所有权必须 `p2 = std::move(p1)`。这正是右值引用 + 移动语义对"独占资源"建模的范例。
> 52. 右值引用底层和左值引用一样，是**存了地址的隐藏指针**。`int&& e = 320 + 230;` 的汇编：先把结果 `550` 存入栈上临时位置 `[ebp-30h]`，再把**该临时位置的地址**存进 `e`（`[ebp-24h]`）。可见右值引用并不神秘——它给"本来匿名的临时对象"起了个有地址的名字，从而能延长其生命周期、被移动函数操作。
> 53. `push_back(const T&)` 处理左值（拷贝入容器），`push_back(T&&)` 处理右值（移动入容器，省一次深拷贝）。`emplace_back(Args&&...)` 更进一步：用**完美转发**把构造参数直接转给元素的构造函数，在容器内存里**原地构造**，连"先建临时对象再移动"这一步都省了。

## 八、概念辨析进阶

**54.** 辨析 `lvalue` / `prvalue` / `xvalue` / `glvalue`。

**55.** 辨析 `T&` / `const T&` / `T&&` / `const T&&` 的绑定能力。

**56.** 辨析 右值引用 / 转发引用（万能引用）。

**57.** 辨析 `std::move` / `std::forward`。

**58.** 辨析 空指针（`nullptr`）/ 悬空指针（dangling pointer）。

> [!success]- 参考答案（第八节）
> 54. `lvalue`：有身份、不可移动（变量名、`*p`、`++x`）。`prvalue`：无身份、可移动（字面量、算术结果、按值返回）。`xvalue`：有身份、可移动（`std::move(x)`、按右值引用返回）。`glvalue`=有身份=lvalue+xvalue；`rvalue`=可移动=prvalue+xvalue。口诀：**有没有身份**分 gl/pr，**能不能移动**分 l/r，xvalue 两头占。
> 55. `T&`：只绑非 const 左值。`const T&`：左值、右值**都能绑**（最通用）。`T&&`：只绑右值（含 xvalue）。`const T&&`：只绑右值但只读，极少用（多用于禁止移动 const 对象的特化）。口诀：要改用 `T&`，只读用 `const T&`，要移动用 `T&&`。
> 56. 二者写法都是 `&&`，区别在**有无类型推导**：函数模板里的 `T&&`（或 `auto&&`）是转发引用，能接左值/右值；写死类型的 `MyString&&` 是右值引用，只接右值。判据：`&&` 前面是**正在被推导的模板形参**才是转发引用。
> 57. `std::move`：**无条件**转成右值——"我确定要移动它"。`std::forward<T>`：**有条件**地按 `T` 还原值类别——"原来是什么我就转什么"。口诀：终点用 `move`，中转用 `forward`；`move` 别用在还要复用的对象上，`forward` 只配转发引用用。
> 58. `nullptr`：明确"不指向任何对象"，解引用前可判空、安全。悬空指针：还存着**已释放/已失效**内存的旧地址，解引用是 UB 且难以察觉。移动构造把源 `data` 置 `nullptr`，正是把"可能变悬空"的指针主动变成"安全的空指针"。

## 九、大厂面试场景题 / 八股常考

> 偏真实工程与系统/高性能岗会问的"为什么""怎么排查""怎么优化"。

**59.** 有了移动语义后，为什么函数"按值返回一个大 `vector`"不再需要担心拷贝开销？

**60.** 一个自己管理资源的类（裸指针）只写了拷贝构造、没写移动，会有什么后果？怎么从性能上发现这个问题？

**61.** `setData` 用"值传递 + `std::move`"和"重载 `const T&` / `T&&`"各有什么优劣？你在什么场景下选哪个？

**62.** 面试官问：对一个 `const` 对象调用 `std::move` 会发生什么？

**63.** `emplace_back` / `make_unique` 内部是怎么用完美转发的？如果没有完美转发会怎样？

**64.** 为什么"移动构造必须是 `noexcept`"才能让 `vector` 扩容时真正走移动？不加会发生什么？

**65.** Code review 看到 `return std::move(local);`（`local` 是函数局部变量）。这样写好不好？为什么？

> [!success]- 参考答案（第九节·上）
> 59. **现象**：按值返回大对象似乎要拷贝一份。**原因**：返回的临时对象是右值，C++ 会用**移动构造**接管它的资源（O(1)）；更进一步，编译器的 **(N)RVO / C++17 强制拷贝省略**常常连移动都省了，直接在调用方内存里构造。**解决/结论**：放心按值返回，别为"怕拷贝"去返回引用或裸指针。**延伸**：`return std::move(local)` 反而会**阻止 NRVO**（见第 65 题）。
> 60. **现象**：插入容器、按值返回时性能异常差。**原因**：缺移动构造时，所有"本可移动"的场景都退化成**深拷贝**（O(n) + 频繁分配）；`vector` 扩容也只能拷贝。**排查**：在拷贝/移动构造里打日志或断点，看热路径是否大量命中拷贝；用 profiler 看 `memcpy`/`new` 占比；检查类是否遵守"要么 Rule of Zero、要么五法则补全"。**解决**：补移动构造/赋值（`noexcept`），或改用 `std::vector`/`std::string` 走 Rule of Zero。
> 61. **优劣**：值传递+move 只写一份、维护简单，但左值入参会多一次拷贝构造、右值多一次移动构造；双重载对左右值都走最优路径、零多余构造，但代码量翻倍且易漏写。**选择**：普通业务接口用值传递+move（够好且简洁）；**高频热路径、超大对象**用双重载榨干性能。**延伸**：模板场景可用转发引用 + `forward` 合二为一。
> 62. **现象**：`std::move(constObj)` 看似要移动，实际没移动。**原因**：`std::move` 把它转成 `const T&&`，而移动构造形参是 `T&&`，**绑不上 const 右值**；重载决议**退回拷贝构造**（`const T&` 能绑）。**解决**：要移动就别让对象是 `const`。**延伸**：这说明 `std::move` 只是"请求"移动，能不能移动还看有没有匹配的非 const 移动操作。
> 63. **现象/原因**：`emplace_back(Args&&...)`、`make_unique<T>(Args&&...)` 用 `Args&&` 转发引用接住任意实参，再 `std::forward<Args>(args)...` 原样转给 `T` 的构造函数，在目标内存**原地构造**。没有完美转发，中间层会把右值实参降级成左值，导致**本可移动的变成拷贝**，还可能无法匹配只接右值的构造函数。**延伸**：完美转发是"零开销中间层"的基石。

> [!success]- 参考答案（第九节·下）
> 64. **现象**：明明写了移动构造，`vector` 扩容还是走拷贝。**原因**：扩容要把旧元素搬到新内存，若搬迁过程抛异常需能**回滚**（强异常安全）。只有移动构造声明 `noexcept`，`vector` 才敢用移动（出错也不会让容器处于半移动的坏状态）；否则它**保守地退回拷贝**。**解决**：给移动构造/赋值加 `noexcept`。**延伸**：`std::move_if_noexcept` 就是这套策略的体现。
> 65. **现象**：`return std::move(local);` 看似"帮忙移动"。**原因**：对返回局部变量，编译器本可做 **NRVO** 直接在调用方就地构造（**零**拷贝/移动）；强行 `std::move` 把表达式变成 xvalue，**禁用了 NRVO**，反而强制一次移动构造——多此一举甚至更慢。**解决**：直接 `return local;`。**延伸**：例外是"返回的是函数参数、成员、或类型需要转换"时才可能需要显式 `move`。

## 十、补充加分题

**66.** **复杂度/性能题**：对持有堆缓冲的类型，深拷贝和移动的时间复杂度各是多少？`std::vector` 的移动是 O(1) 还是 O(n)，为什么？

**67.** C++17 的"强制拷贝省略（guaranteed copy elision）"是什么？`MyString s = createString();`（`createString` 内 `return MyString("temp");`）在 C++17 下到底调用几次构造函数？

**68.** `decltype(x)` 与 `decltype((x))` 为什么不同？背后是什么值类别规则？

**69.** 结合汇编解释 `int&& e = 320 + 230;`：临时对象存哪、`e` 里存的是什么？这说明右值引用和左值引用在底层有何异同？

> [!success]- 参考答案（第十节）
> 66. 深拷贝 **O(n)**（复制 n 个元素 + 至少一次分配）；移动 **O(1)**（只交接 begin/end/capacity 几个指针，不碰元素、不分配）。所以 `std::vector` 的移动是 **O(1)**——它窃取的是堆缓冲的**指针**，元素原地不动。这也是"按值返回 vector 不慌"的底层原因。
> 67. 强制拷贝省略：当用**prvalue 初始化同类型对象**时，C++17 规定**必须**省略拷贝/移动，prvalue 直接在目标位置物化构造。对本例：`return MyString("temp")` 的 prvalue 直接构造返回对象，`s = createString()` 的 prvalue 又直接构造 `s`——全程**只调用 1 次** `MyString(const char*)`，**0 次**拷贝/移动。（C++17 前最多 2 次移动，通常被 RVO 省略。）
> 68. `decltype(x)`：对**裸标识符**，给出其声明类型 `int`。`decltype((x))`：`(x)` 是一个**表达式**，规则为——表达式是 lvalue 则结果加 `&`（`int&`）、xvalue 加 `&&`、prvalue 不加。`x` 作为表达式是左值，故 `decltype((x))` = `int&`。一句话：**多一层括号，从"声明类型"切到"表达式值类别"**。
> 69. 汇编：`320+230=550(0x226)` 先存入栈上临时槽（如 `[ebp-30h]`），再把**该槽的地址**存进 `e`（如 `[ebp-24h]`）。说明：右值引用与左值引用底层**都是存地址的隐藏指针**，机制相同；差别只在**编译期的绑定规则与重载语义**（谁能绑谁、选哪个重载），运行期表示一致。右值引用的额外价值是给匿名临时对象一个有地址的名字并延长其生命周期。

## 十一、值类别判断专项

> 本章核心技能。判断每个表达式属于 **lvalue / prvalue / xvalue**（必要时说明能否取地址、能否绑哪种引用）。

**70.** `int x = 10;` 后，判断下列各表达式的值类别：
a) `x`　b) `x + 1`　c) `++x`　d) `x++`　e) `&x`　f) `std::move(x)`

**71.** 判断下列表达式的值类别：
a) `"hello"`（字符串字面量）　b) `42`　c) `static_cast<int>(3.14)`　d) `arr[0]`　e) `*ptr`

**72.** 给定 `int& f1(int& x);` 和 `int f2(int& x);`，判断调用表达式的值类别：
a) `f1(a)`　b) `f2(a)`

**73.** 判断下列每行能否编译；若能，说明括号内表达式的值类别（`int x = 10;`）：
```cpp
int* p1 = &x;          // a
int* p2 = &(x + 1);    // b
int* p3 = &(++x);      // c
int* p4 = &(x++);      // d
```

**74.** 给定重载 `void g(const int& x);`（记 L）和 `void g(int&& x);`（记 R），`int a = 5;`，判断各调用选哪个：
a) `g(a)`　b) `g(5)`　c) `g(a + 1)`　d) `g(std::move(a))`

**75.** `template<class T> void w(T&& arg);`，`int a = 5; const int b = 5;`，判断 `T` 推导结果与 `arg` 的类型：
a) `w(a)`　b) `w(5)`　c) `w(b)`

> [!success]- 参考答案（第十一节）
> 70. a) **lvalue**（变量名）；b) **prvalue**（算术临时值）；c) **lvalue**（前置 `++` 返回 `x` 的引用）；d) **prvalue**（后置 `++` 返回旧值副本）；e) **prvalue**（`&x` 求出的地址是临时指针值）；f) **xvalue**（`std::move` 产生将亡值）。
> 71. a) **lvalue**（字符串字面量存静态区、可取地址）；b) **prvalue**；c) **prvalue**（转换到非引用类型产生临时值）；d) **lvalue**（数组下标）；e) **lvalue**（解引用结果可取地址、可赋值）。
> 72. a) **lvalue**——`f1` 返回 `int&`，可放赋值左边（`f1(a) = ...`）；b) **prvalue**——`f2` 按值返回，结果是临时 `int`。
> 73. a) **能编译**，`x` 是 lvalue；b) **编译错误**，`x+1` 是 prvalue 不能取地址；c) **能编译**，`++x` 是 lvalue；d) **编译错误**，`x++` 是 prvalue。口诀：能取地址 ⇔ 是 glvalue（lvalue/xvalue）。
> 74. a) **L**——`a` 是左值，只有 `const int&` 能绑（`int&&` 绑不了左值）；b) **R**——`5` 是 prvalue，`const int&` 和 `int&&` 都能绑，但**右值优先选 `T&&`**；c) **R**——`a+1` 是 prvalue；d) **R**——`std::move(a)` 是 xvalue（右值）。
> 75. a) `w(a)`：`a` 左值 → `T = int&`，`arg` 折叠为 `int&`；b) `w(5)`：`5` 右值 → `T = int`，`arg` 为 `int&&`；c) `w(b)`：`b` 是 const 左值 → `T = const int&`，`arg` 为 `const int&`。
